OpenProgram vs LangGraph, AutoGen, and CrewAI

FrameworkPrimary abstractionOrchestrationChoose when
OpenProgramAgent method plus an execution runtimeOrdinary control flow, model-selected tools, a shared execution DAGAn agent should author a new workflow as a reviewable function, not only select from a fixed graph or team. One runtime should provide terminal, Web, provider, tool, memory, context and multi-agent surfaces. Context should be a DAG of user, model, function and tool calls.
LangGraphGraph API with nodes and edges, or Functional API with @entrypoint and @taskExplicit state graphs or standard Python control flow, same runtimeYou need durable execution, persistence, streaming and human-in-the-loop state control. It is a low-level runtime; its overview recommends LangChain agents for prebuilt architectures.
AutoGenAgentChat agents and teams, or Core agents and runtimesAgent messages, team patterns, event-driven Core APIThe design centres on agents exchanging typed messages or team patterns. Covers teams, state, human feedback, custom agents, distributed runtimes.
CrewAIAgents, tasks, crews, flowsRole-based crews combined with event-driven flowsThe application maps to agents with roles, goals and tasks, or to structured flows that invoke crews.

Compares abstractions documented by each project, to help choose one, not to rank features. Verified against the linked documentation on 2026-08-13. An unlisted feature may still be possible through extensions; check current docs before a long-term migration.
