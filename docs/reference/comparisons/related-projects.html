Related projects

Several groups arrived independently at agents as typed Python: the docstring is the prompt, the signature is the contract.

ProjectShared ideaWhere it goes its own way
NVIDIA NOOA (Apache-2.0)Agents are Python objects; ... bodies are LLM-implemented; docstrings are prompts, annotations contractsState on self; the model writes Python into a Jupyter-style REPL (CodeAct). OpenProgram has the model choose among registered functions: a narrower action space, easier to sandbox and replay.
DSPy (MIT)A typed Signature replaces the hand-written promptOptimizes the prompt against a metric. We keep prompts fixed and readable and work on execution structure: DAG, retries, context scoping. Complementary.
Marvin (Apache-2.0), Mirascope (MIT)A decorated function's docstring and return annotation drive a structured callFocus on the single typed call. OpenProgram adds what happens across calls: shared DAG, spawn, forking, per-call context budgets.
LangGraph (MIT)Runs should be an inspectable graph with checkpointsThe graph is declared up front. Ours is recorded from the call stack: plain Python, and the DAG traces what ran. See the comparison.
smolagents (Apache-2.0)Act through code rather than rigid tool JSONCode-writing agents in a sandbox. We bind code at authoring time via Agent methods, so deterministic parts are reviewable before anything runs.
ScriptoriumReadable agent memory; Markdown notes; facts cited to source messages; MCP for Claude CodeMemory the model writes as ordinary files: open, diff, trace every fact to its message

Mischaracterized or missing? Open a PR or an issue.

Contributing
