Docs governance

Agents run one command. It fails on what a program can judge, and names the pages a change may have outdated.

Entry point

CommandDoes
python -m scripts.docs_site.check a.py docs/x.htmlNamed paths. Blocks.
… checkChanges against HEAD. Blocks in a worktree. Only reports in the shared checkout on dev.
… check --base REVA revision range. Blocks.
… check --stagedThe index, for the hook. Blocks.
… check --allEvery page, plus site-wide rules. Blocks.
--report-onlyExit 0 unless the tool itself failed
--jsonFindings and impact, for scripts
--unfilteredTurns the diff filter off: every page citing a changed file
--ack PAGE … --reason TEXTRecord that a page was checked for this change

Budget: 5 s changed, 15 s everything. Standard library and the CLI parser only: no node, no site build, no network. Exit 0: no error in scope, or --report-only. Exit 1: an error in scope. Exit 2: the tool itself failed, or a usage error such as a bad --ack.

Where it runs

PointRunsBlocksWhy
Commit in the main checkoutpre-commit, --staged, when docs, the baseline or the policy are stagedErrors on staged pagesThe author is known; with git commit -- <paths> the index excludes other sessions' files
Commit in a worktreecommit_gate.py, a PreToolUse hook in the tracked .claude/settings.json, blocks git commit and git merge.Errors in the branch~/.git-hooks cuts the .git path at its first space, so no Git hook runs here
Merge or fast-forward in the main checkoutpost-merge: --base ORIG_HEAD --report-onlyNothingRuns no pre-commit; a cherry-pick runs nothing at all, so it is caught by the next deploy report or at publish
affected_tests --runEvery changeErrors on named paths or a worktree's own changesAgents already run it
affected_tests --run, shared checkout, no pathsEvery changeNothing: reportsThe dirty tree holds other sessions' pages
refresh-dev-instance.sh--base <last deployed> --report-only, then quarantine buildNothingCommits there come from all sessions
publish-github.sh--all, before pushingEvery errorThe whole product leaves the machine; rare and deliberate

Affected pages and warnings only inform: whether a page needs rewriting takes judgement. Hooks are unversioned, so scripts/git-hooks/install.sh copies them on every deploy and publish, recording the commit beside them so an older checkout cannot downgrade them; the main checkout warns when one is stale. A hook without a venv, or exit 2, never blocks.
