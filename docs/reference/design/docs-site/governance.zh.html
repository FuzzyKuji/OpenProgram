文档治理

Agent 只跑一条命令。程序能判断的问题直接失败，并列出这次改动可能过时的页面。

入口

命令作用
python -m scripts.docs_site.check a.py docs/x.html指定路径。会阻断。
… check相对 HEAD 的改动。在 worktree 中阻断；在 dev 共享检出中只报告。
… check --base REV一段提交范围。会阻断。
… check --staged读 index，供 hook 用。会阻断。
… check --all所有页面和全站规则。会阻断。
--report-only除非工具本身失败，否则退出码为 0
--json发现项和影响，供脚本读取
--unfiltered关闭差异过滤：列出引用改动文件的每一页
--ack PAGE … --reason TEXT记录某页面已针对这次改动检查过

预算：改动模式 5 秒，全量 15 秒。只用标准库和 CLI parser：不需要 node、不构建站点、不联网。 退出码 0：范围内没有错误，或用了 --report-only。1：范围内有错误。2：工具本身失败，或用法错误，如 --ack 写错。

PROTOTYPE_PAGES清单在 governance/policy.py。新增页面要在 LOOSENED_BECAUSE 里写明原因。

代码到文档

部分规则
引用上面校验到的文件路径，或 3 层以上的目录。裸文件名只有唯一时才算。
命令、key、路由映射到来源：cli/parser.py、state/settings.py、interfaces/server/routes/。与某个 key 完全相同的代码片段算设置引用。
<meta name="covers" content="openprogram/x/ scripts/y.py">显式声明，只写在英文页，总是生效。没有任何引用的页面需要它。content="none" 声明这是不描述代码的索引或调研页。
过滤某文件被超过 3 页引用时，页面的代码词必须是改动行里的标识符才算，字符串、注释和调用关键字不算。cli/parser.py 由解析器差异决定：只算命令在改动命令路径之下的页面。state/settings.py 中，被改动块的 key 视为改动。输出会说明滤掉多少页；--unfiltered 关闭过滤。

运行位置

位置运行阻断原因
主检出提交pre-commit，--staged，暂存了 docs、基线或策略时暂存页面的错误作者明确；使用 git commit -- <paths> 时 index 不含其他会话的文件
worktree 提交commit_gate.py 作为 PreToolUse hook，配置在纳入版本管理的 .claude/settings.json 里，拦截 git commit 和 git merge。分支内的错误~/.git-hooks 在第一个空格截断 .git 路径，这里 Git hook 不运行
主检出 merge 或快进post-merge：--base ORIG_HEAD --report-only不阻断不会运行 pre-commit；cherry-pick 什么都不运行，由下次部署报告或发布时发现
affected_tests --run每次改动指定路径或 worktree 自身改动的错误Agent 本来就跑它
affected_tests --run，共享检出，未指定路径每次改动不阻断，只报告工作区里有其他会话的页面
refresh-dev-instance.sh--base <上次部署> --report-only，再以隔离模式构建不阻断这里的提交来自所有会话
publish-github.sh--all，在推送前所有错误整个产品离开本机；很少且有意为之

受影响页面和警告只提示：页面是否要重写需要判断。Hook 不进版本库，所以 scripts/git-hooks/install.sh 在每次部署和发布时复制，同时在旁边记下来源提交，旧检出不会把它们降级；主检出发现 hook 过期时会提示。Hook 找不到 venv 或工具退出码为 2 时都不阻断。
