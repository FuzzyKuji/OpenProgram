Error handling

Catch what you can handle, and leave a record of what you swallowed. A handler with no log, comment or fallback looks exactly like an undiscovered bug.

The rule

ObligationMeaning
Catch specificallyName everything the operation raises: file IO OSError; JSON ValueError; ContextVar.reset ValueError for a foreign token, RuntimeError for a spent one. Naming only part of the set turns a swallowed failure into an escaping one.
Never swallow a programmer errorAttributeError, TypeError, NameError are defects. A handler broad enough to hide one is narrowed, or logs.
Say whyEvery remaining swallow has a log line with context or a comment on why ignoring is correct; both when not obvious.
Delete pointless handlersGuarding an operation that swallows its own errors, or catching what cannot be raised.

Boundaries

A broad except Exception is legitimate where propagation would take down more than the failed operation. It still logs enough to identify the session or operation.

  • WebSocket handlers and HTTP routes: would drop the connection
  • Thread and worker entry points: would die unobserved
  • Callback invocation: caller code inside our loop
  • Optional subsystems (memory, project git, usage metering): absence degrades a feature
  • Best-effort bookkeeping the next turn re-derives

Log level

LevelWhen
errorThe user notices and must act: channel message undelivered after retries, MCP server did not start, adapter stopped for good
warningSomething was lost the user could notice: unlanded write, stale status, missing record
infoExpected degraded path in a running process: network wait, retry, model failover, reconnect
debugOptional path degraded as designed: absent subsystem, best-effort cache, working fallback; developer traces

Use exc_info=True and include the session id or equivalent.

What good handlers look like 
# A lost durable write, made visible
except OSError:
    _log.warning(
        "index.json not saved for session %s", session_id, exc_info=True)

# Narrow where a broad catch hid defects
except (ValueError, RuntimeError):
    # ContextVar.reset raises ValueError for a token minted in another
    # context and RuntimeError for one already spent. Narrowing to only
    # the first lets a cancelled turn's spent token escape and replace
    # the CancelledError.
    _log.debug("context var token already spent or foreign", exc_info=True)

# Optional subsystem, reason stated
except Exception:
    # Memory is optional: an unavailable provider degrades to no memory
    # block, never a failed turn.
    _log.debug("memory system prompt block unavailable", exc_info=True)

Scope

  • Covers all of openprogram/. tests/ and scripts/ are muted: a test swallows on purpose to assert what follows; scripts run by hand.
  • A per-file-ignores * crosses /, so openprogram/*.py mutes every module. Check new patterns against a nested file.
  • BLE001 is off: a boundary handler that logs and degrades is correct, and those go through review under Boundaries.
  • Ruff does only this gate; formatting and import order are left alone.

Logging, not print

One module logger, _log = logging.getLogger(__name__). No [module] prefix; a bracketed tag stays only when it carries data, such as [wechat:<account>]. %s arguments, not f-strings.

print is allowed for the following; outside muted paths each call says which with # noqa: T201 - <reason>.

UseExample
Command outputopenprogram cron-worker --list, a shell command the sandbox emulates, an assets.py subcommand
A stdout protocolJSON lines or a sentinel another process reads
Terminal prompt or statusQR login, OAuth URL, a foreground run saying it is online and how to stop it

T201 is muted for openprogram/interfaces/cli/**, worker commands (operations/worker/lifecycle.py, runner.py, startup_log.py, services/**), operations/self_update/**, models/providers/recording/**, **/probe_thinking.py.

Process logging

The library never configures logging. Each entry point calls configure_process_logging() from openprogram/host/process_logging.py once: one stderr handler on the root logger, format %(asctime)s %(levelname)s %(name)s: %(message)s, with httpx, httpcore, websockets, asyncio and mcp at WARNING (full output at DEBUG).

ProcessDefaultWhy
Worker (run_foreground)INFOStdout and stderr are the worker log, beside [worker +12.3s] lines
Standalone scheduler (run_forever)INFOIts terminal is its log
Foreground Server (python -m openprogram.interfaces.server)INFOSame
CLI (interfaces/cli/application.py main)WARNINGThe interactive chat shares the terminal
  • A later call in the same process moves the level and adds no handler, so a worker started through the CLI logs at INFO. The ACP server inside the CLI does this with OPENPROGRAM_ACP_LOG.
  • A root logger configured by someone else (embedding host, pytest) keeps its handlers.
  • OPENPROGRAM_LOG_LEVEL (level name, any case) overrides every process; invalid values are ignored.
