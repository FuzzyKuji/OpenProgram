依赖安全

每条公告要么在解析后的依赖图里修复，要么写明其父链。不忽略任何告警。

当前版本及原因

领域现状决定
Next.js16.4.4、eslint 9、直接的 lint 脚本保持静态导出：output: "export"，manifest 路由 dynamic = "force-static"，next build --webpack。打包路径里没有 Next 服务器。
Electron45.2.1，最低 macOS 13本地 App 验收前，打包必须替换已安装的 Electron
图片标注直接使用 Fabric 7.4.0，作为原生画布上的透明层取代 tui-image-editor 及其有漏洞的 Fabric 4 链。裁剪和旋转会压平标注；导出前仍可选择、移动、缩放和编辑文字。
React根和 Web 用 18，CLI 用 19安全升级不改变
Node>=22.12.0，npm >=10根 engines、CI 和开发环境使用同一下限
npm 传递依赖apps/web、apps/desktop、apps/cli 共用根 lockfile刷新兼容路径；移除没有修复版本的失修链（tar、form-data、postcss、extract-zip、旧 HTTP 包）
Pythonuv.lock，独立工作线同一清单、证据和门禁。Intel macOS 支持 BM25，可选 embedding wheel 在 Intel 上不可用，macOS arm64 的 embedding wheel 需要 Python 3.14 或更新。

规则

规则细节
修复版本公告的首个修复版本或之后兼容的稳定版，来自 GitHub 公告和 npm view
核对同时用 npm audit --json 和公告范围清单。GitHub 逗号分隔的范围按 semver 交集处理；解析错误即失败。包已不存在的记录也要核对。
绝不npm audit fix --force，它可能选无关的大版本。因页面静态或依赖仅开发用而忽略告警。
没有修复版本追踪每个父依赖，尽量移除整条链，否则记录父链、原因和测试过的替代
失败干净安装、审计、类型检查、构建或受影响测试失败都阻止完成，并记录命令。在最小源码改动被证明前，旧 manifest 留在 Git。
证据reports/content-security/ 下被忽略的报告，含确切公告、范围、版本和命令

边界

边界规则
解析全部经根 lockfile。只有父依赖要求时才有嵌套条目。
构建npm ci --ignore-scripts，然后工作区检查
运行导出的 Web 资源、Electron main 和 preload、提供这些资源的 Python worker。不可信输入只有经过产品校验才能到达包 CLI 和解压器。
已安装 App解析依赖不会更新 /Applications/OpenProgram.app。验收检查其实际的 process.versions.electron；源码检查不能证明。

门禁

npm ci --ignore-scripts
npm audit --json                       # 零漏洞，并做范围核对
npm run build --workspace apps/web
npm run typecheck --workspace apps/cli
npm test --workspace apps/cli
npm test --workspace apps/web
npm run check:web
npm run check:desktop
npm run check:cli
git diff --check

从干净安装开始。还要 manifest 与 lockfile 一致、工作区干净，报告区分既有源码失败和依赖引起的失败。diff 只含 manifest、lockfile、必要的兼容源码、本设计和被忽略的证据规则。
