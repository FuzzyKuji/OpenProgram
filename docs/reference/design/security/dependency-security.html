Rules

RuleDetail
Fixed versionThe advisory's first patched version or a later compatible stable release, from GitHub advisories and npm view
VerificationBoth npm audit --json and the advisory-range inventory. Comma-separated GitHub ranges are semver conjunctions; parse errors fail. Package-absent records are checked too.
Nevernpm audit fix --force, which can pick unrelated majors. Dismissing an alert because a page is static or a dependency is development-only.
No fixed releaseTrace every parent, remove the chain where possible, otherwise record parent chain, reason and tested alternative
FailureA clean install, audit, typecheck, build or affected test failure blocks completion and is recorded with its command. The old manifest stays in Git until the minimum source change is proven.
EvidenceIgnored reports under reports/content-security/, with exact advisories, ranges, versions and commands

Boundaries

BoundaryRule
ResolutionAll through the root lockfile. Nested entries only when a parent requires them.
Buildnpm ci --ignore-scripts, then workspace checks
RuntimeExported Web assets, Electron main and preload, the Python worker serving them. Untrusted input reaches package CLIs and archive extractors only through product validation.
Installed AppPackage resolution does not update /Applications/OpenProgram.app. Acceptance inspects its actual process.versions.electron; source checks do not establish it.

Gate

npm ci --ignore-scripts
npm audit --json                       # zero vulnerabilities, plus range reconciliation
npm run build --workspace apps/web
npm run typecheck --workspace apps/cli
npm test --workspace apps/cli
npm test --workspace apps/web
npm run check:web
npm run check:desktop
npm run check:cli
git diff --check

From a clean install. Also manifest and lockfile consistency, a clean worktree, and a report separating existing source failures from dependency-induced ones. The diff holds only manifests, lockfile, necessary compatibility source, this design and the ignored evidence rule.
