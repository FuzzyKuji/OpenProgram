Usage metering

Every LLM call records tokens, model and cost with its source, aggregated by model, source, session and time. The module is openprogram/models/usage/.

Three records, three questions

RecordLives inAnswersWritten by
Message columnsAssistant message historyWhat did this message cost (per-message pill)persist_assistant_message in runtime/conversation/turn_runtime/persistence.py
Compaction budgetSession meta _usageReal input tokens last turn, cache hit rate, whether to compact. Sub-microsecond readsUsageTracker.record_turn in runtime/context/usage.py
Ledger~/.openprogram/usage.db, profile-awareGlobal spend across sessions, models, sources and timerecord_message in models/usage/recorder.py

They have different consumers and lifecycles, and do not read or write each other. Session meta is a cumulative git-backed snapshot: it cannot aggregate across sessions, query by time or index per model, and a subprocess writing it would contend for the git lock.

Collection point

models/providers/streaming/stream.py wraps stream() and stream_simple(); complete_simple() runs through them. Going through it and being accounted for mean the same thing. Memory, compaction summaries, mixture_of_agents and Agent-method subprocesses use the same point with their own usage_scope.

RuleWhy
Here, not in api_registryEach provider implements its own stream_simple behind a Protocol. Collecting there means changing the Protocol or scattering wrappers. stream.py already holds the model with pricing and the final usage.
At the terminal event, before the yield, guarded by recordedagent_loop returns on the done event, suspending the generator at its yield; code after the loop never runs
Streaming is not blockedFires once, on done or error
A reply that failed is recorded tooAn attempt that reached the provider and ended without a final message may be billed. record_failed_request records the tokens its last partial reported, or one event with tokens_known false and cost unknown. The sign of reaching it is streamed content, reported tokens, or a reply silent for the idle bound; the adapter's start event is not. A refusal or a connection that failed before any content is not recorded.
Best-effortA metering failure logs and never interrupts the response. Callers that settle a budget or Goal receipt use strict event construction.

Storage

SQLite from the standard library, WAL mode for concurrent appends from subprocesses.

TableHolds
usage_eventsAppend-only events. Indexes: time, model and time, session, kind and time, job, Goal, reservation, budget scope; unique on request_id
usage_requestsGoal request receipts: prepared, started, settled, released
route_eventsFailover switches. Not usage; no aggregate reads it
probe_eventsRequests sent on OpenProgram's own behalf: the probe log. Not usage
prefix_baselinesThe last answered request on each prompt-cache lane, which the next one is compared with. Not usage

A step changing both an event and a reservation commits the event first, so a stop in between leaves exposure held and an event to recognise it by, never spend without a record.

Agent-method subprocesses
  • The subprocess writes the shared database directly, stamped with origin_pid. The ledger is the source of truth; the parent does not count again and the result pickle carries no usage.
  • process_runner.py uses spawn: the parent has loaded PyTorch, libomp and Cocoa, which SIGSEGV after fork. Spawn does not copy contextvars, so run_agentic_in_subprocess passes snapshot() as usage_ctx_snapshot and the child applies it after os.setpgrp().
  • _connect() reopens on a changed os.getpid(), because a handle is unusable across processes.
  • On SIGKILL, appended events stay and are true. A call the kill cut off is not recorded: nothing is fabricated.
