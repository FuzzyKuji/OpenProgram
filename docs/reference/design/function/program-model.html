Program model

Everything the Agent can use is a Program. A Program lists callable entries in PROGRAM_ENTRIES (optional ENTRY_OPTIONS); each becomes one tool in the shared registry. Unlisted plain functions are not recorded.

Most tools register with @function on importing openprogram.programs.tools. A tool package with PROGRAM_ENTRIES is named in registry.TOOL_PROGRAMS (only goal) and registers through its own context.

Application packages

Either form, or both in one directory:

  • Python: __init__.py with PROGRAM_ENTRIES, ENTRY_OPTIONS, optional setup(ctx).
  • Declarative: application.json, UI (index.html or ui/), optional backend.py whose operations the manifest declares.

programs/_host/ui/loader.py mount(ctx, root) mounts a declarative package, built in (manifest id is the directory name) or installed. It reads the manifest, digests the directory and registers:

  • The UI, served from the application's own directory under that digest.
  • Resource provider application.<id>.
  • One entry per operation marked agent: true, named <id>__<operation>, other than [A-Za-z0-9_-] replaced by _. Takes input (and project_id if project-scoped), runs through the worker's application service, one process per operation with manifest capability checks, and returns the finished run. Deferred, needs approval, not in DEFAULT_TOOLS. agent: false gets no entry.

Installed: recorded in ~/.openprogram/programs/catalog.json by source directory, nothing copied. Loads in the worker at start, after install, enable and disable, and when the watcher sees a change. Disabling disposes the context; a changed source is disposed and reloaded with a new digest.

Built in: a builtin-application row ({"id": "browser", "enabled": false}), read by catalog.builtin_enabled. registry.sync_builtin_application matches it on every load, so the setting holds in every process and across restarts; PATCH /api/applications/<id> applies it live. A re-enabled entry is the same tool with its toolsets and tier.

ProgramContext

The single registration interface; one per application package and plugin. Every registration records its undo; ctx.dispose() runs them newest first and restores the host. It writes into the registries the host already has.

    def word_count(text: str) -> int:

Every owner other than tool: and plugin: is an application; entries registered through its context start deferred.

The registry keeps owner → context. Loading again reuses it and records nothing twice. Unloading or hot reload (programs/_host/watcher.py) calls dispose_program(owner); a reload registers through a fresh context.

Plugins

Only a declarative package in the Claude Code, Codex, OpenCode or Hermes format: skills, slash commands, agents, hooks, MCP servers and provider directories named by a manifest. plugins/manifest.py reads them and mounts through a context owned by plugin:<name>. Hooks are shell commands subscribed through ctx.gate and ctx.on. No plugin code runs in the worker.

A manifest naming code (python, module, setup, main, tools, client, web, sidebar, a module:name hook mapping, a Hermes __init__.py) is refused at install and load: package it as an application with openprogram programs install <dir> and application.json. Plugin runtime

Resident while open in a window

The signal is the session's application bindings (programs/_host/ui/bindings.py, table resource_bindings). An open naming the session binds an instance: the App's window through POST /api/applications/<id>/open with session_id, or the Agent's call through application.<id>. release or POST /api/applications/<id>/close removes it.

Each turn TurnBindings reads open_application_ids(session_id) and installs it (_runtime.install_open_applications). split_tools_for_dispatch and tool_search read resident_now: a resident entry, a deferred entry loaded with tool_search, or a deferred entry whose application:<id> is open enters the tools array. The registered tier never changes; the copy for one request is as_resident.

User directory

One per profile, resolved by openprogram/state/program_directory.py without importing the registry. Named profiles use ~/.openprogram-<profile>/programs/.

Under ~/.openprogram/programs/Holds
<name>/Program source: Python package, application directory, or both. Names starting with . or _, symlinks and files are not scanned
catalog.jsonApplications by source directory, with settings. Sources elsewhere (such as examples/applications/) keep enabled, hidden, display_title
.runtime/data/, runs/, environments/, staging/, state.sqlite, versions/ (read only when an application's source is gone)
.removed/Set aside by openprogram programs uninstall

Files under .runtime/ and .removed/ are not source: role calls from them carry no call site.

How each kind loads
  • Package: _host/packages.py, under its directory name (a Python identifier shadowing no module). Its own Git repository; only a clean, committed checkout loads, so a passing openprogram programs check makes a change callable. Uncommitted edits keep serving the last loaded version.
  • Application: loader.mount in the worker. A directory without a catalog row is recorded on the next loader.sync (catalog.adopt_user_applications), unless it needs trust (a Python backend or files.project.write): that waits for openprogram programs install <dir> --trust. An uninstalled row is never re-recorded.
  • Harness clone (a repository with <package>/agentics/__init__.py) installed from git: recorded in program-sources.json, owned by external:<package>.

One scan (program_directory.program_dirs) serves both loaders. The watcher fingerprints the top level, the files and Git state of every package and the catalog with each enabled application's source; a change re-runs discovery.

Implementation status

Everything above is implemented. The browser core reaches browser only through the service and runs without it (browser application). Applications gained capability files.project.write. Tool names, toolsets and options are unchanged, and the Programs page keeps workflow/<name> explorer paths, used by the Web app with the owner API's /api/applications/* routes. User packages import reports from openprogram.programs._authoring.reports.

Removed: programs/workflow/ and its import path; agent_browser, browser_agent, playwright_browser, CLI /browser; openprogram workflows, openprogram apps, programs apps, programs available, gui and all install selectors; pip as a plugin source; plugin Web modules, pages and sidebar rows.
