Agent classes, Programs and tools

In OpenProgram an agent is a Python class. Subclass Agent, set the model and instructions as class attributes, and write ordinary methods: self(...) is a model call, and everything around it — branches, loops, retries, checks — is plain Python. Calling a method records it in the session's execution DAG and gives the model calls inside it the right context automatically, so no decorator or manual context object is needed. A method becomes a tool the model can call only when you register it, and a package of such classes and functions is a Program.

from openprogram import Agent

class Researcher(Agent):
    model = "configured-model"
    method_options = {"research": {"tool": True}}   # expose this method as a tool

    def research(self, question):
        text = self.prepare(question)
        answer = self(text)                          # one model call
        if "TODO" in answer:                         # a check written in code
            answer = self(f"Finish this answer: {answer}")
        return answer

    def prepare(self, text):                         # an ordinary, unrecorded helper
        return text.strip()

result = Researcher().research("A topic")

Authoring and context

Agent subclasses use ordinary methods. The framework establishes call scopes and derives Context automatically. Model configuration (model, effort, instructions, tools) belongs to Agent. Parent inheritance, named content, evaluation, and history visibility belong to Context. An Agent instance holds configuration only; it does not own a conversation, and the execution scope decides whether history continues.

The unified Agent and Context contract owns the public class API and execution lifetime. This page defines Program and tool boundaries without duplicating that contract.

Tools and entry registration

A recorded method is not automatically a tool. The class attribute method_options registers a method explicitly with tool=True, and can also set its public name, description, input form and visibility. Registered Program sources list public entries in PROGRAM_ENTRIES. Explicit metadata preserves public names and input forms.

Deterministic tools registered through function() use the same registry. Authorization applies independently of call recording and history visibility.

Skills and ordinary code

Skills supply instructions. They do not create executable entry identity by themselves. Programs supply source code and registered callable entries. Ordinary helpers preserve normal Python behavior: signatures, return values, exceptions and imports are unchanged, and helpers add no nodes to the DAG.

Method behavior

method_options also carries entry metadata, tool registration and explicit durable steps (resumable) for methods that need them. A method without options is still an ordinary recorded Agent method.

Implementation status

The Agent class, its self(...) call, method_options and automatic Context derivation are implemented in openprogram/runtime/agent/agent_class.py and agent_method.py. Verification status for the shared execution components is maintained in the central design status.
