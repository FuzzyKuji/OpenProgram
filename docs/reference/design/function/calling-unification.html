Function calling

Default on, user curated: a registered tool works with no configuration, and every layer's default is not to restrict. Tool-call results live only in run history and never enter later prompt context, so broad exposure costs no context. Loop mechanics: tool calling.

One registry

AuthoringAPI wire
@functionTool, ToolCall, ToolResultMessage
Agent method with method_options[name]["tool"] = Truetools=[...]
agent_tools(), get_agent_tool()tool_calls=[...]

The act is "function calling"; the API object stays tool. Our AgentTool and AgentToolResult add what the wire lacks: sidecar gating, sync to async, char cap. Providers serialize each one; returned tool_calls match by name and AgentTool.execute(...) runs. Managed Program packages list public entries in PROGRAM_ENTRIES. Automatic scope capture exposes nothing. Class authoring and lifetime: Agent and Context contract.

Layers 2, 2b and 6 select; 3, 4 and 5 only veto. Layers 1 to 5 mean the LLM cannot use the tool. Layer 6 lets the LLM choose what to load.

Why 2b and 5 stay separate

2b chooses a set to use; 5 removes what must not be used. A veto must hold whatever is selected: attended mode withholds ask_user_question in every folder. So the Programs page leads with 2b (pick folders) and offers 5 as a per-tool off switch. System vetoes (attended, subagent and role caps through allow and deny) are code-only and invisible.

Plugins and MCP servers

Registering is enough; there is no central allowlist. Plugin tools use _build_and_register_tool like built-ins. MCP tools register as AgentTool on connect, defer=True by default.

Agent method registration

from openprogram import Agent

class ResearchAgent(Agent):
    method_options = {
        "research": {"tool": True, "name": "research", "toolset": ["research"], "expose": "io"},
    }

    def research(self, topic: str) -> str:
        """Research a topic."""
        return self(topic)

researcher = ResearchAgent()
PROGRAM_ENTRIES = [researcher.research]
  • Method handling runs cancellation hooks, runtime injection, Context derivation, DAG entry and terminal updates, and error restoration. Options retain schema, caching, timeout, availability, approval and explicit-step recovery.
  • Construction registers only methods asking for tool exposure, in the same registry and sidecars. available_if gates registration, not the method scope.
  • The managed loader records package ownership. It adds no public decorator and no authority.

Resolution path

  1. A turn starts; TurnBindings installs the session's _loaded_deferred set, which tool_search updates and later turns keep.
  2. resolve_tools calls agent_tools(toolset=…, source=req.source, only_available=True), walking layers 2 to 5, not 6.
  3. The deferred catalog from the initial set enters the system prompt. agent_loop still receives the full list.
  4. Before each provider call, split_tools_for_dispatch keeps non-deferred and already-loaded tools for tools=[].
  5. On a ToolCall, agent_loop finds the tool in context.tools or _registry, validates arguments, and awaits execute(call_id, args, cancel, on_update).
  6. tool_search(select="cron") adds cron to _loaded_deferred; the next request carries its schema.
