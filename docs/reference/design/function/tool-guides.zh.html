工具指南

每个 schema 都随每次请求发送，长 schema 也更容易被草草读过。工具只保留短 schema，其余说明由 agent loop 送进工具结果。单入口工具靠这个机制：一个工具、几个参数，每个目标或动作的说明在首次使用时送达。Codex 的 computer use、Claude Code 的 skills 也是这种渐进披露。

声明

guides.register("self_update", [
    Guide("self_update", overview, mode="open", activates=("worktree_create",)),
    Guide("self_update.prepare", prepare_text, summary="parameters, iteration policy and verification plan",
          required_for=lambda args: args.get("action") == "prepare"),
])
字段含义
name传给 help 的点分名称，跨工具唯一
text指南，或返回指南的函数（平台差异、从代码读取的列表）
when(args)included、on_error 适用于哪些调用；lookup 是否进索引
required_for(args)指南已知前不能运行的调用
activates指南所讲的延迟工具；送达时在指南末尾加一行，列出这些工具和加载它们的 tool_search select: 调用（延迟工具）
mode送达时机用于
open工具的第一个结果每次使用都需要的内容
included匹配 when 的调用的第一个结果某个目标或平台
lookup按名称和 summary 进索引，用 help 读取带 required_for：错误代价高、参数长的动作。不带：特定情况才要的背景
on_error匹配调用的失败结果恢复建议

open、included 指南末尾附该工具适用的 lookup 指南索引。

送达

  1. _run_loop 打开视图（guides.begin_loop）。loop 之外指南不起作用：直接 Python 调用和测试看到的是普通结果。
  2. 每次模型请求前，_stream_assistant_response 记录发送的文本（guides.observe_request）。
  3. 调用判定前，required_for 指南未知时 prechecks.call_problem 返回 GUIDE_REQUIRED：普通工具错误，没有审批卡。模型读完附上的指南再调用。
  4. 调用结束时，_rewrite_tool_result（guides.attach）把应送达的指南各包在 <guide name="…"> 里，记在结果的附件（details["attachment"]）上，不放进工具自己的文字；它们在这组结果之后发出，也算在请求的文字里（工具输出）。

标记还在上一次请求文本里，或此后已送达，指南就算已知。没有台账：压缩、微压缩、worker 重启或新 agent 都会让标记消失，下一个需要它的调用会重新收到。提示词里已带标记指南的 agent 不再重复收到。

help

help(name) 是常驻工具，按名返回指南；传工具名时返回其开场指南，标记方式与送达的指南相同。无需审批，属 runtime.control 权限。未知名称会列出现有指南。在 computer_use_agent 代码里，Python 的 help、dir 可用于 cu 对象：每个 docstring 就是目标指南里该动作的那一行。
