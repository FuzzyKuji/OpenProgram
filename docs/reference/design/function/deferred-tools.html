Deferred tools

A deferred tool is registered, but its schema reaches the model only after tool_search loads it. Search is the only way to load. The loaded set is read from the request's own messages, and inside an epoch the tools array only grows at its end.

Why this design

Codex's own client sends an empty list for every failure, the one shape the backend is known to accept. Claude Code and Pi return text, but on their own wires. The model can check a name against the catalog.

Guides and applications

A guide that teaches deferred tools, and an application when it opens, end with activation_note: Tools for this: `a`, `b`. Load them with `tool_search select:a,b`. Neither loads anything; an open application's tools stay deferred.

Why this design
ComparedDoes
CodexAn explicitly mentioned app's tools stay deferred
Claude Code, PiLoading only through search
HermesOnly searchable tools can be called

One loading path changes the array one way on every provider, and opening an application no longer rereads the prefix. The cost is one cheap, recorded select: call.

EventReason given

The tools leave the registry and the catalog sends a Removed line. A loaded tool keeps its array entry; calling it returns Tool <name> is unavailable: <reason>. as an error. No tool_removal is sent.

Why this design

Codex keeps history and answers unsupported call; Anthropic advises keeping the definition and returning an ordinary error. Claude Code rewrites old references, which is a history edit. An array that never shrinks cannot fail validation or reread the prefix.

Mode and deny changes

An epoch is keyed by provider, model and first message (tool_epoch.epoch_key), so a summary or a model switch starts one. Its first request stores the withheld set with the tool snapshot.

ChangeArrayDispatch
Plan mode on or offUnchangedpermission_decision refuses
exit_plan_mode outside plan modeUnchangedRefused, PLAN_MODE_NOT_ACTIVE
Whole-tool deny rule, missing capabilityRemoved from the next epochRefused meanwhile
Structured-output submit tool appearsNew epoch record with it—
Why this design

Codex refuses at dispatch in plan mode; Claude Code refuses plan-mode calls but filters denied tools out; Anthropic advises against swapping tool lists in place. Changing the array mid-conversation fails on models that validate the tool set, and dispatch already enforces permission.

Pi and Codex use BM25; Claude Code uses fixed keyword scores. Pi's ranker spells out every rule and ports without a dependency. Every match is loaded for good, so the default stays at Claude Code's 5 rather than 8.

Old search results

A tool_search result is never shortened to a stub on any provider; tool output is not aged at all (Tool output).

Why this design

Claude Code's microcompact skips ToolSearch, and Codex never ages. The definition lives in the load record, so a stub saves little and is a history edit.
