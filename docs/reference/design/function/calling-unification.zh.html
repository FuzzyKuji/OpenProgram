函数调用

默认开启，由用户收窄：注册的工具零配置可用，每一层默认都不限制。工具调用结果只存在运行历史里，不进入后续 prompt 上下文，所以广泛暴露没有上下文成本。循环机制见工具调用。

单一注册表

编写API wire
@functionTool、ToolCall、ToolResultMessage
Agent 方法，method_options[name]["tool"] = Truetools=[...]
agent_tools()、get_agent_tool()tool_calls=[...]

动作叫“函数调用”，API 里的对象仍叫 tool。AgentTool、AgentToolResult 补上 wire 没有的东西：sidecar gating、同步转异步、字符上限。Provider 序列化每个工具；返回的 tool_calls 按名匹配并运行 AgentTool.execute(...)。受管 Program 包在 PROGRAM_ENTRIES 列出公开入口。自动作用域采集不暴露任何东西。类式编写和生命周期见 Agent 与 Context 契约。

六层 gating

层配置默认被拒绝时
1 导入available_if注册不进 _registry
2 暴露expose=False，只用于内部辅助暴露，含 plugin 和 MCP。裸 runtime.exec 拿到全部Python 可调，绝不进 tools 数组
2b 预设toolset=[...]、TOOLSETS、DEFAULT_TOOLS、命名 profile；toolset="none" 表示不要工具不强加命名子集，不是可见性门
3 会话与渠道agent_profile.toolset、unsafe_in不限制。source=None 不过滤集合收窄；渠道（telegram、wechat、plan）隐藏工具
4 列表构建check_fn、requires_env、can_use；agent_tools(only_available=True)假定可运行；只在 dispatcher 路径检查移除，LLM 不会看到调用必错的工具
5 用户与策略agent_tools(deny=, allow=)、agent_profile.disabled、tools.disabled、attended 模式不否决按名减去；attended 模式扣下 ask_user_question
6 Promptdefer=True、MCP 接线schema 随请求发送目录里只有名称和一行说明；tool_search 加载 schema

第 2、2b、6 层做选择；第 3、4、5 层只否决。第 1 到 5 层表示 LLM 用不了该工具。第 6 层让 LLM 自己选择加载什么。

为什么 2b 和 5 分开

2b 选择要用的集合；5 去掉不许用的。否决必须独立于选择：attended 模式在任何文件夹下都要扣下 ask_user_question。所以 Programs 页以 2b（挑选文件夹）为主，5 是单个工具的关闭开关。系统否决（attended，经 allow、deny 的子 agent 和角色上限）只在代码里，用户看不到。

插件与 MCP server

注册即可，没有中央 allowlist。插件工具和内置工具一样走 _build_and_register_tool。MCP 工具在连接时注册为 AgentTool，默认 defer=True。

Agent 方法注册

from openprogram import Agent

class ResearchAgent(Agent):
    method_options = {
        "research": {"tool": True, "name": "research", "toolset": ["research"], "expose": "io"},
    }

    def research(self, topic: str) -> str:
        """Research a topic."""
        return self(topic)

researcher = ResearchAgent()
PROGRAM_ENTRIES = [researcher.research]
  • 方法处理负责取消钩子、runtime 注入、Context 派生、DAG 入口与终态更新、错误恢复。选项保留 schema、缓存、超时、可用性、审批和显式步骤恢复。
  • 构造时只注册要求暴露为工具的方法，用同一注册表和 sidecar。available_if 只门控注册，不影响方法作用域。
  • 受管加载器记录包归属，不增加公开装饰器，也不扩大权限。

解析路径

  1. 一轮开始；TurnBindings 安装该会话的 _loaded_deferred 集合，tool_search 会更新它，后续轮次保留。
  2. resolve_tools 调用 agent_tools(toolset=…, source=req.source, only_available=True)，走第 2 到 5 层，不走第 6 层。
  3. 由初始集合算出的延迟目录进入系统提示。agent_loop 仍收到完整列表。
  4. 每次 provider 调用前，split_tools_for_dispatch 保留非延迟和已加载的工具作为 tools=[]。
  5. 收到 ToolCall 时，agent_loop 在 context.tools 或 _registry 查找，校验参数，await execute(call_id, args, cancel, on_update)。
  6. tool_search(select="cron") 把 cron 加入 _loaded_deferred，下一次请求带上其 schema。
