Chat-bot behaviour on channels

A chat bot is the same Agent with the same runtime, tools and memory, behind a room layer (which messages become turns) and a delivery layer (how replies leave), both in channels/. OpenClaw and Hermes are built the same way.

Room modes

ModeStarts a turnOther messagesReply reaches the room
mention (default)Mention, or reply to the botPending historyYes
alwaysEvery message—Yes
ambientEvery message—Addressed: yes. Otherwise only through chat_send.
  • A non-addressing ambient message opens with [room event], runs no ack or typing, and its final text stays in the transcript, labelled "overheard" on the web. Room events count against the flood limit.
  • The account's require_mention gives the default; /activation stores a per-group override in rooms.json. Adapters only set ChannelMessage.mentioned and strip the mention; channels/_room.py decides, the same on every platform. Direct messages are never gated.
  • chat_send(text) posts into the turn's chat, looked up by session key in channels/_active_turns.py (a session_scope: main session holds several chats). Needs only reply, is on the safe auto-allow list, is hidden from non-channel sources, at most five per turn. In an addressed turn it serves a short note before long work; the final reply is still posted.

  • Kept in memory per room with speaker fields. The next turn takes the newest 50 ahead of its message. JSON escapes newlines, so a pending message cannot forge another speaker's line.
  • Consumed entries are cleared; /new clears; a worker restart drops them. It never wakes the agent. The web folds the block at the top of the bubble.

  • Lists live in the account's access.json. A group may hold its own pair beside its activation in rooms.json; once present they replace the account's, only reset removes them, and emptying them leaves the group closed.
  • A Discord thread has its own chat id and falls back to its parent channel's lists.
  • The allowlist applies to every group, so listing a bound contact as chat is refused, and binding someone removes them from the chat lists.
  • Lists change only from the local CLI and settings page. CLI and worker both write rooms.json, under the same cross-process file lock as access.json.
  • A question from runtime.ask belongs to the person who started the turn; in a group /answer and /decline from anyone else are refused while it runs.

Loops and floods

Bot messages are dropped. A room starts at most 10 turns in a sliding minute; past that, messages fall into pending history. One message delivered twice (Slack message and app_mention) starts one turn.

Inbound mediaiLink image, voice, file and video items point at AES-128-ECB objects on Tencent's C2C CDN and carry the key. They become attachments with the key; the shared path decrypts while downloading. The CDN says application/octet-stream, so image type comes from the decrypted header.
VoiceWeChat's transcript becomes the text, with no download. Without one it is SILK, saved as voice.silk.
