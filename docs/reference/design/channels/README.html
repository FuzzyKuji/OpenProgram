Channels

A message to the bot on Telegram, Discord, Slack or personal WeChat starts a turn for the bound agent; the reply returns to the same chat. Channels run inside the background worker. No public webhook: every adapter connects outward (Telegram long-poll, Discord Gateway, Slack Socket Mode, WeChat iLink long-poll).

StepDoes
ParseAn adapter in openprogram/interfaces/channels/implementations/ parses the native event into one ChannelMessage: text, attachment metadata, quoted text.
Gatebase.Channel.handle_inbound runs the pairing gate (unknown senders get a one-hour code only the owner can approve, from the CLI or loopback Web UI), attachment download and the quoted block.
Dispatchdispatch_inbound picks the agent from bindings, computes the session key, runs the turn under a per-session lock, and broadcasts it to the Web UI and TUI.
SendOne transport module owns chunking, per-platform formatting (Telegram HTML, Slack mrkdwn, plain text for WeChat), rate-limit retry and file upload. Where edits are allowed, progress streams into one placeholder.

Scripts, jobs and agent methods can send one-shot with outbound.send(...) without a worker. Accounts, pairing and routing: openprogram channels setup, accounts, access, bindings.
