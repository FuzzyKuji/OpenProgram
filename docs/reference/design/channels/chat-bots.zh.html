渠道上的聊天机器人行为

聊天机器人就是同一个 Agent，runtime、工具和记忆都相同，只是前面有房间层（哪些消息变成回合）和投递层（回复如何发出），都在 channels/ 中。OpenClaw 和 Hermes 也是这样构建的。

OpenClaw 的组成
  • 访问：私聊配对、白名单；每群 groupPolicy 为 allowlist、open 或 disabled。
  • 提及门控：requireMention、mentionPatterns，回复机器人算提及；/activation mention|always。
  • 待处理历史：未提及消息保留（historyLimit，默认 50）供下次触发回合使用。
  • 环境房间：unmentionedInbound: "room_event" 配 visibleReplies: "message_tool"：所有消息都到 agent，最终文本保持私有，房间只听到 message 工具的内容；不显示输入状态。
  • 按群和发送者的工具策略（tools、toolsBySender）；非主会话沙箱。
  • 会话：dmScope、identityLinks、每日或空闲重置、/new、/reset。
  • 投递：分块流式（minChars、maxChars、合并、换行模式）、预览编辑、输入状态保活、ack 表情。
  • 机器人循环保护、一次性群介绍、跳过群的心跳、语音转写、双向媒体。
  • 微信：腾讯微信团队维护的插件；私聊和媒体，无群聊，iLink 二维码登录。

房间模式

模式开始回合其他消息回复到达房间
mention（默认）提及或回复机器人待处理历史是
always每条消息—是
ambient每条消息—点名时是，否则只能通过 chat_send。
  • 未点名的 ambient 消息以 [room event] 开头，不运行 ack 和输入状态，最终文本留在记录中，网页标为“overheard”。房间事件计入洪泛限制。
  • 账号的 require_mention 提供默认值；/activation 把按群覆盖写入 rooms.json。适配器只设置 ChannelMessage.mentioned 并去掉提及；决定在 channels/_room.py，各平台一致。私聊从不门控。
  • chat_send(text) 发到回合所在聊天，按会话 key 在 channels/_active_turns.py 中查找（session_scope: main 的会话含多个聊天）。只需 reply 能力，在安全自动允许列表中，对非渠道来源隐藏，每回合最多五条。点名回合中用于长任务前的简短说明；最终回复仍会发送。

循环与洪泛

机器人消息被丢弃。一个房间滑动一分钟内最多开始 10 个回合，超出的消息进入待处理历史。同一消息被投递两次（Slack message 和 app_mention）只开始一个回合。

微信

方向行为
入站媒体iLink 的图片、语音、文件、视频项指向腾讯 C2C CDN 上的 AES-128-ECB 对象并带密钥。它们变成带密钥的附件，共享路径边下载边解密。CDN 返回 application/octet-stream，图片类型取自解密后的文件头。
语音微信转写作为文本，不下载音频。没有转写时是 SILK，保存为 voice.silk。
发送文件getuploadurl，用新密钥加密，上传到 CDN，发送含下载参数和密钥的图片、视频或文件项。说明文字作为单独文本发送。使用固定到 CDN 源的 channel.wechat.cdn HTTP consumer。
限制无群聊和编辑：始终分段，不用占位
