JSON Schema 结构化输出

Runtime.exec(..., response_format=...) 是唯一的公开入口。无论供应商怎么声称，结果都严格解析，并按调用方的原始 schema 校验。普通调用仍返回 str。

模式

mode做法选用条件
native供应商的 JSON Schema 字段适配器支持、模型字段不为 False、schema 无损投影、支持当前工具
tool隐藏工具 __openprogram_submit_jsonfallback="auto"、严格工具 schema、无损、tool_choice 允许
prompt系统层放精简 schema，只做本地检查仅在显式 fallback="prompt" 时
无发送前抛 StructuredOutputUnsupportedError其他情况

非法 schema 最先失败。Model.structured_output=None 表示未知，不等于 False。有损投影会报出确切路径并禁用 native。

一次尝试

  1. 文本和工具增量带 output_attempt 进入客户端候选缓冲，不持久化。
  2. 收到供应商原始 done 后解析并校验。成功：structured_output_end，然后一个 done。流结束却没有终止事件按 incomplete 失败。
  3. 可修复的失败：structured_output_retry；客户端清空缓冲；开始新的供应商流。
  4. 预算用尽：error，没有 done，不持久化非法的助手消息。

失败处理

失败请求修复
非法 schema不发送：StructuredOutputSchemaError否
不支持或配置冲突不发送：StructuredOutputUnsupportedError否
JSON 语法、违反 schema、缺失或混合提交已发送是，最多 max_validation_retries 次
拒答、内容过滤已发送否：refusal
max_tokens、不完整、上下文长度已发送否：保留原因，不改上限
传输、限流、供应商内部错误已发送现有重试，共用预算
取消、超期已发送否：直接传播

max_validation_retries（0、1 或 2；默认 2）限制修复次数；max_retries 限制 Runtime 边界的全部供应商调用，修复两者都要满足。只有真的要修复时才发重试事件。修复提示只含失败类型和有界问题列表，只在这次 exec 内有效。

各入口

入口约定
Python返回 JsonValue；抛 StructuredOutputError，带 code、provider、model、attempts、issues
openprogram --print --json-schema PATH（- 读 stdin）stdout 是一个紧凑 UTF-8 JSON 文档。退出码 2 非法，3 不支持，4 生成或校验失败；stderr 只有错误码。

类型 
@dataclass(frozen=True)
class JsonSchemaOutput:
    schema: dict[str, Any]     # never mutated
    name: str = "response"     # ^[A-Za-z_][A-Za-z0-9_-]{0,63}$
    description: str | None = None
    strict: bool = True
    fallback: Literal["auto", "none", "prompt"] = "auto"
    max_validation_retries: Literal[0, 1, 2] = 2
    type: Literal["json_schema"] = "json_schema"

Runtime.exec(content=..., response_format={"type": "object", ...}) -> JsonValue
Runtime.exec(content=..., response_format=JsonSchemaOutput(...)) -> JsonValue
Runtime.exec(content=..., response_format=None) -> str

裸 dict 就是 schema，不是供应商 payload。Model.structured_output、StreamOptions.response_format，以及 AssistantMessage.structured_output、structured_output_mode、structured_output_attempt。原始 JSON 文本留在助手内容里供历史和审计。jsonschema>=4.23 是直接依赖。错误 code：invalid_schema、unsupported、invalid_json、validation_failed、missing_submission、mixed_submission、refusal、incomplete。

解析和限制
  • json.loads 拒绝 NaN、Infinity、Markdown 围栏、前后说明和尾部内容；不用宽松解析器，隐藏工具参数也一样。
  • validator_for(schema)，注册表禁止外部访问，错误按实例路径、schema 路径、消息排序。
  • 预检拒绝不能在 schema 内解析的 $ref、$dynamicRef、$recursiveRef 和直接引用环。允许有限递归。
  • Schema 预算：1 MiB、4096 容器节点、8192 边、深度 100；超出为 invalid_schema。
  • 最多 20 个问题，每个 500 字符。
  • 工具参数：严格导出把可选字段变成必填可空；共用规范化在副本上只还原新增的 null，再做规范校验。enum、条件和组合约束不变。
录制与回放

RECORDING_FORMAT_VERSION 为 2。请求记录规范化的 response_format；记录原始供应商事件，回放时确定性重建重试、结束和错误。每次修复都是新的供应商调用和 call_index。拒绝 v1 结构化录制；普通 v1 保持兼容。schema 做 SHA-256 哈希（键排序）用于日志、DAG 和错误；录制保留完整 schema。

会话标题使用方

conversation/turn_runtime/titles.py：TITLE_SCHEMA 为 {title: string, 1–80}，toolset="none"，max_iterations=2，fallback="prompt"，max_validation_retries=1。尽力而为：结构化错误时保留占位标题。使用方只做 Unicode 修剪和存储长度保护；日志只有固定的生命周期标签。

没有采用的做法
  • 只靠供应商 strict 并返回原文：拒答、截断和兼容端点都需要本地检查。
  • 用宽松或部分 JSON 解析修复。
  • 把每个增量解析成对象。
  • 单独的结构化供应商路径。
  • 有损 schema 改写、自动 Pydantic 类型、跨语言代码生成、增量 JSON AST。

references/pi-ai 有共用选项和严格工具 schema，但没有响应 schema。每个适配器开启能力前都要有 payload 契约测试。
