JSON Schema structured output

Runtime.exec(..., response_format=...) is the one public entry. Whatever the provider claims, the result is strictly parsed and validated against the caller's original schema. Ordinary calls still return str.

An invalid schema fails first. Model.structured_output=None means unknown, never False. A lossy projection reports its exact path and disables native.

One attempt

  1. Text and tool deltas go to a client candidate buffer, with output_attempt; nothing persists.
  2. After the provider's raw done, parse and validate. Success: structured_output_end, then one done. Stream end with no terminal fails as incomplete.
  3. Repairable failure: structured_output_retry; clients clear the buffer; a new provider stream starts.
  4. Budget gone: error, no done, no invalid assistant message persisted.

Failure handling

FailureRequestRepair
Invalid schemaNot sent: StructuredOutputSchemaErrorNo
Unsupported or conflictingNot sent: StructuredOutputUnsupportedErrorNo
JSON syntax, schema violation, missing or mixed submissionSentYes, up to max_validation_retries
Refusal, content filterSentNo: refusal
max_tokens, incomplete, context lengthSentNo: reason kept, limits unchanged
Transport, rate limit, provider internalSentExisting retry, shared budget
Cancellation, deadlineSentNo: propagates

max_validation_retries (0, 1 or 2; default 2) caps repairs; max_retries caps every provider call at the Runtime boundary, so repair needs both. Retry events fire only when a repair will really run. Repair prompts hold only the failure type and bounded issues, and last for this exec.

Plain text, no submitmissing_submission
Forced tool, none, or requested parallelNot overridden: native if possible, else unsupported

Submit is not executed and has no ToolResultMessage. Validation sits at the Agent-loop no-tool boundary; there is no separate provider path, so tools, deadlines, DAG and record/replay stay one.

A bare dict is the schema, not a provider payload. Model.structured_output, StreamOptions.response_format, and AssistantMessage.structured_output, structured_output_mode, structured_output_attempt. Raw JSON text stays in assistant content for history and audit. jsonschema>=4.23 is a direct dependency. Error code: invalid_schema, unsupported, invalid_json, validation_failed, missing_submission, mixed_submission, refusal, incomplete.

Parsing and limits
  • json.loads rejecting NaN, Infinity, Markdown fences, surrounding text and trailing content; no forgiving parser, also for hidden-tool arguments.
  • validator_for(schema), a registry with no external access, errors sorted by instance path, schema path, message.
  • Preflight rejects any $ref, $dynamicRef, $recursiveRef that does not resolve inside the schema, and direct reference cycles. Finite recursion is allowed.
  • Schema budget: 1 MiB, 4096 container nodes, 8192 edges, depth 100; over it is invalid_schema.
  • At most 20 issues, 500 characters each.
  • Tool arguments: strict export turns optional fields into required nullable ones; shared normalization restores only added nulls, on a copy, before canonical validation. Enum, conditional and combinator constraints stay.
Record and replay

RECORDING_FORMAT_VERSION is 2. Requests record normalized response_format; raw provider events are recorded, and retry, end and error are rebuilt deterministically on replay. Each repair is a new provider call and call_index. v1 structured recordings are rejected; ordinary v1 stays compatible. The schema is hashed (SHA-256, sorted keys) for logs, DAG and errors; recordings retain the whole schema.

Session title consumer

conversation/turn_runtime/titles.py: TITLE_SCHEMA is {title: string, 1–80}, toolset="none", max_iterations=2, fallback="prompt", max_validation_retries=1. Best-effort: a structured error keeps the placeholder. The consumer does only Unicode trim and storage-length protection; logs hold fixed lifecycle labels only.

What was not taken
  • Provider strict alone, with raw text returned: refusals, truncation and compatible endpoints need local checks.
  • Partial or forgiving JSON repair.
  • Parsing every delta into objects.
  • A separate structured provider path.
  • Lossy schema rewriting, automatic Pydantic types, cross-language codegen, incremental JSON AST.

references/pi-ai shares options and strict tool schemas but has no response schema. Each adapter needs a payload contract test before a capability is enabled.
