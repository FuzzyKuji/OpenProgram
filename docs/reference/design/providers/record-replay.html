Recording and replaying provider calls

Vendor modules know about neither. call_index counts every API's calls in one order, because all wrappers share one sink and one ReplayProvider.

The transform 
configure_provider_transform(transform)
  once per process; same value no-op, conflict RuntimeError
  keeps the original, never double-wraps, replaces all entries atomically
  later register_api_provider(api, original) stores transform(api, original)

record:  transform(api, original) -> RecordingProvider(original, shared_sink)
replay:  transform(api, original) -> shared_replay

In replay, original only confirms the API is registered. stream.py gets the provider first and skips credentials when requires_credentials is false. Direct constructors remain for tests: RecordingProvider(real_provider, path), ReplayProvider(path). Calls that bypass get_api_provider() must return to it; no vendor-specific cases.

File format

{"type":"header","format_version":2,"recording_id":"…","created_at":"…","redaction_version":1}
{"type":"request","call_index":0,"model":{…},"context":{…},"options":{…}}
{"type":"event","call_index":0,"event_index":0,"event":{…}}
{"type":"call_end","call_index":0,"event_count":1,"outcome":"complete"}
RuleDetail
VersionRECORDING_FORMAT_VERSION is 2. Replay accepts 1 and 2, refuses others. Version 1 cannot replay a structured response_format; request-local option fields it stored as null are dropped.
Bump whenRequired request, event or call_end fields or their meaning change. Optional header fields do not bump it; readers ignore unknown ones.
call_end.outcomecomplete, error, cancelled or abandoned; missing means complete
Old filesHeaders with only type and version stay valid; metadata comes from stat and content. Later formats get their own parser; files are never rewritten in place.
Strict reader
LevelRefused unless
FileFirst non-empty line is the only header; every line a JSON object; known version; only the four line types; not empty or truncated
CallEach request has a unique call_index consecutive from 0; events reference an open call; event_index consecutive from 0; exactly one call_end
Completionevent_count matches; no events after call_end; unknown event types fail at construction, not midway
RequestIncoming is redacted the same way, compared model, context, options; calls beyond the recording are refused

Errors are RecordingFileError(path, line, call_index, reason). list, show and activation share this parser.

Concurrent writes
  1. RecordingSink serializes and appends each line under a process-local threading.RLock.
  2. Each append opens with O_WRONLY | O_CREAT | O_APPEND, mode 0600, and takes an exclusive flock across processes.
  3. The header and next call_index are allocated under the file lock: one past the highest request index. The sink remembers how far it has read, so each call reads only the lines appended since, by any process; a file shorter than that is read again from the start.
  4. A complete UTF-8 line plus newline goes out in an os.write loop.
  5. fsync runs after call_end only; a crash leaves an incomplete call the strict parser detects.
  6. Events may interleave; call_index and event_index group them.

Recording guarantees file integrity, not scheduling. Tests that need determinism issue provider calls serially.

Differences and failures

replay mismatch at call 1, field context.messages[2].content[0].text:
recorded 'echo:hi', incoming 'echo:bye'

find_first_difference() walks dicts by sorted key and lists by index, so a pair always reports the same path. NON_DETERMINISTIC_FIELD_NAMES (timestamp, first_token_ms, first_text_ms) are skipped.
