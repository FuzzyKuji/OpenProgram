凭据连接

从不压成一个裸 key 字符串。是否 OAuth 看 kind，不看 token 前缀。一个 key 可以连别的端点：百炼的 key 存上 https://…maas.aliyuncs.com/compatible-mode/v1，同样走 openai-completions 协议，不用另建模型列表。

每种 kind 还有 base_url 和 headers，默认为空。邮箱、显示名、组织 ID 留在 Credential.metadata。

resolve_connection

Kind行为
cli_delegated读外部文件；以那个 CLI 为准
credential_process运行辅助程序，token 按 cache_seconds 复用。失败抛 AuthCredentialProcessError，解析链重新抛出，绝不换用其他层。
sso抛 AuthConfigError：保留项，没有流程实现
其他返回 auth_value

auth.usage.acquire_pooled 返回 (conn, profile, cred_id)。

线路规则

api_key  = conn.auth_value if conn else opts.api_key
base_url = (conn.base_url if conn and conn.base_url else None) or model.base_url
headers  = {**(model.headers or {}), **(conn.headers if conn else {}), **(opts.headers or {})}
is_oauth = bool(conn and conn.kind in ("oauth", "device_code"))

openai_completions、openai_responses、anthropic 相同。

旧格式与迁移

运行时只认当前结构，带 __type__ 的旧 JSON 直接报错。auth/_migrate_payload.py 原子改写每个 ~/.openprogram/auth/<provider>/<profile>.json，在首次加载 AuthStore 时运行，也可执行 openprogram providers migrate。已是当前结构的 payload 和没有 credentials 的文件（如 _rotation.json）会跳过。不用重新登录。

测试
  • resolve_connection：每种 kind；key 带或不带 base_url；实时读外部文件；辅助程序的 json 和文本解析、缓存窗口、每种失败都抛出；sso 抛出。
  • CredentialData 序列化往返，包括 data。
  • 线路规则：凭据的 base_url 优先；kind=oauth 不靠前缀就置 is_oauth。
  • 端到端：带百炼 base_url 的 key 打到百炼；官方 OpenAI key 仍走默认端点。
  • 迁移器：字段正确、无 __type__、幂等、管理文件不动。
