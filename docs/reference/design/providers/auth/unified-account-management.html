Accounts and rotation

ConceptMeaning
AccountA profile: one pool at ~/.openprogram/auth/<provider>/<profile>.json. OAuth refresh rotation allows one OAuth credential per pool, so this is the only model that covers every provider.
account_idStable ASCII key from the runtime (default, account-2, …); never changes
labelUnicode display text; renamed freely; duplicates allowed

Label of a new login: typed label, OAuth email, provider display name, then stable id. Identity comes from credential metadata, nested OAuth data or id_token claims. Older credentials derive it on read.

Request path

MechanismBehaviour
Active accountauth/account/account_selection.py: get_active_account, set_active_account, get_active_pin. acquire and the resolver default to it; chat and execute enter auth_scope. Default stays default.
Outcome reportingauth/usage.py and openai_completions.stream_simple acquire per request and report; a 429 cools the key, the outer retry rotates. No-op without a real AuthStore pool.
Conversation affinityThe stream runs in conversation_affinity(session_id); pool.pick keeps the conversation's last healthy credential if active within 1 h (AFFINITY_IDLE_MS), so vendor caches are not paid twice. A cooling or revoked credential moves it for good. Per process, at most 4096 (AFFINITY_MAX). Follows magpie (yetone/magpie, MIT).
Strategyfixed, fill_first, round_robin, random, least_used; cooldown skip in auth/pool.py; fallback in auth/credential_provider.py

Login add reuses /api/providers/{id}/login/{start,poll,submit,cancel} with an optional label; the runtime allocates the id. Multi-profile and diagnostics: routes/identity/credentials.py (/profiles, /pools, /doctor, SSE /events).
