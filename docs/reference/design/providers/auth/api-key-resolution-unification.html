API key resolution

ProviderCredential source
LLM provider with a keyAuthStore under ~/.openprogram, written by Settings or openprogram providers login <provider> --api-key
Amazon BedrockAWS credential chain; sentinel "<authenticated>", no bearer key
Google VertexGCP ADC plus project and location; same sentinel
Environment variables, config.jsonNever read for LLM keys. config.json api_keys serves only web search and TTS.

One source means the runtime, catalog and status surfaces cannot disagree, and a key saved in Settings survives a worker restart.

Calls

FunctionAnswers
resolve_provider_key(provider)Runtime path: an API-key-shaped credential or the sentinel, else None. OAuth tokens are excluded, since these wires send x-api-key or Bearer and an access token would 401.
is_configured(provider_id)A key, or a satisfied cloud chain
resolve_api_key_with_auth_store(provider_id)Model listing and probes: any bearer the AuthStore can yield, through resolve_api_key_sync
env_vars_for(provider_id)Key names as labels and identifiers; falls back to models.dev
provider_id_for_env_var(env_var)Reverse, first match in table order; None for non-LLM keys

In openprogram/models/providers/settings/env_api_keys.py, so runtime and server import it without a cycle. credentials.provider_id_for_env_var re-exports the reverse map.

Order inside resolve_api_key_sync
  1. get_credential_override, for tests or middleware
  2. CredentialProvider.acquire_sync: refreshed token or key from the pool
  3. resolve_provider_key: the cloud sentinels

None lets the caller show a login prompt or go keyless for local endpoints. AuthCredentialProcessError always propagates: a broken helper is shown by name, not replaced by a stale key.

Two name tables
TableUse
_PROVIDER_ENV_VARSPer provider, all accepted names: labels in Settings, and add_mode classification. Examples: google has three; anthropic lists ANTHROPIC_OAUTH_TOKEN first; github-copilot has three token names.
PROVIDER_ENV_VARSFlat, one name per provider, used by models/auth/adoption.py and the openprogram providers commands as the “providers with a key name” list. Excludes anthropic and copilot on purpose, so deriving it from the table above would change login flow.

Verification

tests/unit/providers/auth/test_api_key_resolution.py pins that environment names are inert, the cloud sentinels, the reverse map and key labels.
