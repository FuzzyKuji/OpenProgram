Web search

A provider's own search runs in its infrastructure and returns citations; a scraper gets a bot challenge after a handful of requests. So each request resolves search from two facts: the session's Search switch (web_search on the session run config) and whether the API provider advertises supports_web_search (_StreamFnProvider, ApiProviderSnapshot).

APIRequest toolAdvertised
openai-responses, openai-codex{"type": "web_search"}Yes
anthropic-messages{"type": "web_search_20250305", "name": "web_search"}Yes
google-generative-ai, gemini-subscription{"google_search": {}}, only in a request without function toolsNo
DeepSeek, Kimi, local models, OpenAI-compatible endpointsNoneNo

With the switch on and the capability advertised, the runtime sets the request option web_search=True and removes the local web_search tool. Otherwise the local tool stays. Gemini's generateContent rejects grounding next to function declarations (Gemini 3 combines them only on the Interactions API) and an agent request always carries function tools; a tool-free completion with web_search=True still uses grounding.
