网页搜索

Provider 自己的搜索在它的基础设施上运行并返回引用；抓取器请求几次就会遇到机器人验证。所以每个请求根据两件事决定搜索方式：会话的搜索开关（会话运行配置上的 web_search），以及 API Provider 是否声明 supports_web_search（_StreamFnProvider、ApiProviderSnapshot）。

API请求中的工具声明能力
openai-responses、openai-codex{"type": "web_search"}是
anthropic-messages{"type": "web_search_20250305", "name": "web_search"}是
google-generative-ai、gemini-subscription{"google_search": {}}，仅用于不带函数工具的请求否
DeepSeek、Kimi、本地模型、OpenAI 兼容端点无否

开关打开且声明了能力时，运行时设置请求选项 web_search=True 并移除本地 web_search 工具，否则保留本地工具。Gemini 的 generateContent 拒绝 grounding 与函数声明同时出现（Gemini 3 只在 Interactions API 上可组合），而 Agent 请求总带函数工具；不带工具的补全设 web_search=True 时仍使用 grounding。

从 Provider 条目到对话记录

阶段行为
流处理流处理器把搜索条目转成 ServerToolUse 块和 servertool_start / servertool_end 事件。
Agent 循环只转发，不执行。
客户端tool_use / tool_result，带 tool: "web_search"、provider_executed: true，input 为 {"query": ...}，result 每行一个 title — url，Provider 未报告来源时为 completed。
持久化回复块里是同样的形状，重新加载时在原位显示“Searched the web: …”。
引用url_citation（Responses）、citations（Anthropic）、groundingMetadata（Gemini）汇成 TextContent 上的 citations: [{url, title, start, end}]，随 text_end 转发并持久化，在回答下方显示为来源行。

Geminigrounding 块使用合成 id，从不重发

线上协议

内容块，openprogram/models/providers/types.py：

class ServerToolUse(BaseModel):
    type: Literal["serverToolUse"] = "serverToolUse"
    id: str                 # provider item id
    name: str               # "web_search"
    input: dict             # {"query": str}
    status: str             # "searching" | "completed" | "failed"
    results: list[dict]     # [{"title": str, "url": str}]
    raw: Any | None = None  # provider item, for replay
名称形状
文本块TextContent.citations: list[Citation] | None，Citation(url, title, start, end)
消息事件EventServerToolStart(type="servertool_start", content_index, partial)、EventServerToolEnd(type="servertool_end", content_index, server_tool: ServerToolUse, partial)
客户端事件apps/web/lib/net/ws/chat-stream.ts：text_end 时文本块上的 citations；搜索块随 transcript_update 的回复行到达
持久化块{"type": "tool", "tool": "web_search", "provider_executed": true, "input": "{\"query\": ...}", "result": ...}
