Request building

How the Context is assembled belongs upstream. Adding a provider touches only this layer and its provider.json.

Breakpoints

RuleDetail
Caller markscache_control on a content block passes through verbatim; Tool.cache_control likewise (passthrough plan)
Unmarkedapply_cache_policy (settings/cache_policy.py) marks the last tool not sent with defer_loading and the latest user message's last text block, else its last block; caller markers stay
Budgetmax_breakpoints (4), spent tools first, then messages
TTL≥ 3600 s is 1h, else the provider default of 5 min; models.prompt_cache_ttl set to 1h makes a plain cache live an hour
SystemOne string, so each provider's _build_system marks the whole block; the policy covers tools and messages
Anthropicstream_simple applies the policy before building; _get_cache_control reads the TTL map and long_ttl_endpoints
Bedrockexplicit but with its own cachePoint blocks and last-message logic, outside apply_cache_policy

The policy follows opencode's cache-policy.ts and protocols/utils/cache.ts. opencode marks a last system segment too, because its system prompt is an array. No Context-level structure is added.
