录制与回放提供商调用

厂商模块对两者都不知情。call_index 把所有 API 的调用排成一个顺序，因为所有包装共用一个 sink 和一个 ReplayProvider。

范围

边界规则
覆盖LLM 提供商的请求和事件流，跨 API，一个文件
照常真实运行Agent 循环、Runtime 重试、工具、Session、DAG
不做恢复 Session、重放工具副作用、回滚文件、定义任务步骤；录制工具、MCP、浏览器或任意 HTTP
绝不模糊匹配模型或提示词、回退到真实调用、上传或提交文件、运行中切换
严格离线只在提供商层成立。工具保留各自权限；整个进程离线要用沙箱或网络策略。
Web 界面没有；用 CLI 和设置
格式JSONL 不是稳定的公开交换格式
内容凭据脱敏不等于匿名：提示词、回复、工具结果、文件片段和个人数据都还在

变换 
configure_provider_transform(transform)
  once per process; same value no-op, conflict RuntimeError
  keeps the original, never double-wraps, replaces all entries atomically
  later register_api_provider(api, original) stores transform(api, original)

record:  transform(api, original) -> RecordingProvider(original, shared_sink)
replay:  transform(api, original) -> shared_replay

回放时 original 只用来确认 API 已注册。stream.py 先取提供商，requires_credentials 为假时跳过凭据。测试仍可直接构造：RecordingProvider(real_provider, path)、ReplayProvider(path)。绕过 get_api_provider() 的调用必须回到它；不加厂商特例。

文件格式

{"type":"header","format_version":2,"recording_id":"…","created_at":"…","redaction_version":1}
{"type":"request","call_index":0,"model":{…},"context":{…},"options":{…}}
{"type":"event","call_index":0,"event_index":0,"event":{…}}
{"type":"call_end","call_index":0,"event_count":1,"outcome":"complete"}
规则细节
版本RECORDING_FORMAT_VERSION 为 2。回放接受 1 和 2，拒绝其他。版本 1 不能回放结构化 response_format；它存成 null 的请求级选项字段会被丢弃。
何时升版本必需的 request、event、call_end 字段或语义变化时。可选 header 字段不升版本，读取方忽略未知字段。
call_end.outcomecomplete、error、cancelled 或 abandoned；缺失视为 complete
旧文件只有 type 和 version 的 header 仍有效；元数据取自 stat 和内容。后续格式用独立解析器，绝不原地改写文件。
严格读取
层级必须满足
文件首个非空行是唯一 header；每行是 JSON 对象；版本已知；只有四种行；不空、不截断
调用每个 request 的 call_index 唯一且从 0 连续；事件指向未结束的调用；event_index 从 0 连续；恰好一个 call_end
完成event_count 相符；call_end 后没有事件；未知事件类型在构造时失败，不在中途
请求传入请求同样脱敏，按 model、context、options 比较；超出录制的调用被拒绝

错误为 RecordingFileError(path, line, call_index, reason)。list、show 和激活共用这个解析器。

并发写入
  1. RecordingSink 在进程内 threading.RLock 下序列化并追加每一行。
  2. 每次追加用 O_WRONLY | O_CREAT | O_APPEND、0600 打开，并取跨进程的排他 flock。
  3. header 和下一个 call_index 在文件锁内分配：最大 request 序号加一。sink 记住读到哪里，每次只读之后追加的行，不论哪个进程写的；文件比读过的短时从头再读。
  4. 完整的 UTF-8 行加换行用 os.write 循环写出。
  5. 只在 call_end 后 fsync；崩溃留下的未完成调用由严格解析器发现。
  6. 事件可以交错；call_index 和 event_index 把它们归组。

录制保证文件完整，不保证调度顺序。需要确定性的测试应串行发起提供商调用。

权限和脱敏

对象规则
托管根get_state_dir() / "recordings"，收紧到 0700
录制目标只限托管 ID。0600，新文件用 O_EXCL，支持时用 O_NOFOLLOW，否则用目录 fd 打开并比较 lstat/fstat。绝不截断；重名失败。
回放托管文件可收紧到 0600。外部文件必须已是普通 0600 文件，否则拒绝，不 chmod。
锁文件0600
list、show、delete、prunelstat 拒绝符号链接；delete 和 prune 只动普通 .jsonl 文件，不递归
脱敏remove_secret_values() 在序列化前运行，无开关；值换成 [secret removed]
按字段名SECRET_FIELD_NAMES，不分大小写，含嵌套：authorization、proxy-authorization、api_key、apikey、api-key、x-api-key、x-goog-api-key、token、access_token、refresh_token、id_token、cookie、set-cookie、secret、client_secret、password、session_key；以及以 - 或 _ 接 token、key、secret、password 结尾的名字。token_count 保留。
按值Bearer、Basic、Bot、token、Key 方案；sk-…；URL userinfo；api_key、apikey、access_token、token 查询值
不用高熵规则：会改变普通提示词，破坏匹配
匹配回放先脱敏传入请求；录制和回放使用同一 redaction_version

差异和失败
