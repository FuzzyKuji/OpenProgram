Retry decisions for model calls

Errors take shape in two places, and both become a message with stop_reason="error" and an error_message that may be empty: an exception caught in runtime/agent/loop/driver.py, or an error event from the provider stream.

The layers together

Transport retries are counted once: AgentSession and the provider stream draw on one RecoveryState. When it runs out the message is flagged error_transport_exhausted and exec does not restart the invocation with a fresh tool context.

Messages

A caught exception becomes type_name: text, or the type alone when the text is empty, with the traceback on stderr. The final error lists each attempt's type_name: text and whether it failed permanently or after N attempts.
