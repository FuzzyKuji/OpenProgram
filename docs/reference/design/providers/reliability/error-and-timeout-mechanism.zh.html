回复的长度

对话回复没有工具交互次数和总时长限制；持续产出的流不会因为时间长被切断。用户取消始终有效。显式的 runtime.exec 期限、程序的调用轮数参数和独立 GUI、浏览器工具声明的预算不被覆盖。

空闲上限

连接还开着、回复却不再到达时，300 秒没有事件就以 StreamIdleTimeout 结束这次尝试：它是传输错误，由负责这次尝试的那一层重试，界面上显示为重试。

  • keepalive ping 和注释行不算事件。
  • 等待响应头也算静默。
  • 抛出错误前先关闭卡住的流。
  • 停止会立刻结束等待。
传输在哪里限制谁来重试
Codex 订阅，WebSocket 和 HTTPread_budget.ReadBudget，每一帧或每一行数据retry_stream
Chat Completions（DeepSeek、xAI、OpenAI 兼容）提供商自己的请求和分块循环它自己的重试循环
Gemini 订阅每次尝试的请求和数据行；它自己在两次尝试之间的等待不算静默stream._delivered
OpenAI 与 Azure Responses、Anthropic、Google、Bedrock、插件提供商stream._metered，每个事件stream._delivered

自带上限的提供商设置 bounds_own_stream_idle。

boto3 是阻塞的，所以 Bedrock 在自己的线程上读取：

  • 请求和每次事件流读取都在那里进行；每个事件交给事件循环，卡住时不会让其他会话停顿。
  • 关闭流会关掉它的套接字。botocore 自己 60 秒的读超时也作用于每次读取。
  • 在它的网络路径纳入管理之前，产品里禁用 Bedrock SDK 传输。

服务器要求的等待超过 OPENPROGRAM_RETRY_AFTER_CAP_S 时不会睡过去：Gemini 订阅立刻以限流错误失败，与 retry_stream 一致。

重发失败的回复

回复卡住，或者连接在最终事件之前断开，说明不了请求本身有问题，所以 stream._delivered 把同一个请求再发一次。对话轮次路径、AgentSession 和一次性调用都走这里。

情况处理
还没有任何内容就失败先发一个 retry 事件，再重发。Codex 和 Chat Completions 先在自己的循环里重发；它们用尽次数的失败带着标记到达，不再重发
已有推理、文字或工具调用后失败整个请求重发，已收到的部分作废，与 Codex CLI 和 Claude Code 一致。retry 事件带 restart；回复所在的行和循环里的部分消息都去掉失败那次的文字和推理，等待期间到达的引导不会把它提交进去。Codex 则保留部分回复（stop_reason="length"），本轮从它接着走
工具不会执行两次：工具只在一次回复的最终事件之后执行，失败的回复没有最终事件
正发往频道的回复已发出的段落收不回来。失败那次还没发的文字丢弃；重发的回复开头与已发内容逐字相同时跳过这段。重发的回复措辞不同时，在已发内容之后整段发出
不重发限流、过载、认证失败或请求有误（由 SDK 重试和故障切换处理）；Goal 或作业预留之下的请求；停止之后的任何请求
额度用尽失败被标记为 transport_exhausted，AgentSession 和 exec 都不再重试
用量已到达提供商、没有最终消息就结束的那次尝试会记入用量：有上报的 token 就记 token，没有就记为一次费用未知的请求。到达的依据是已流出内容、已上报 token，或静默满空闲上限；适配器的 start 事件不算。被拒绝的请求和在任何内容之前就断开的连接不记

无论尝试了几次，调用方只看到这个请求的一个 start。脱敏和故障切换两个包装层各自持有生产任务，所以停止能传到它们之下的提供商请求。

停止一次调用

机制效果
期限端到端；超出量不超过一次连接尝试。SSE 等待被压到剩余时间内。
transport_exhaustedretry_stream 标记预算用尽；exec 不再重启，原因和可重试标记如实保留
ExecInterrupt(BaseException)穿过所有 except Exception 重试层。只有最外层所有者抛出。
OPENPROGRAM_EXEC_TIMEOUT_Sexec 的进程级默认；0 为无限。不依赖信号，Python 只把信号送到主线程。
回复流式输出中停止轮次直接结束，不等 provider 关闭：正在进行的读取被取消，交给轮次的事件循环（event_stream.leave_unwinding）。限时关闭超时后同样交出，并继续运行：取消它会让 provider 被第二次取消，打断它的 socket 关闭。
轮次的事件循环关闭在单独线程里按 asyncio.run 的顺序：停止交出的读取和关闭有 2 秒自行结束（socket 关闭是一次往返），超过后被取消；接着关闭 provider 客户端，取消轮次留下的任务，关闭异步生成器，最后关闭循环
关闭过程中出现的任务被弃用的流生成器的关闭、被取消的任务留下的 socket 关闭，都运行到结束。没有任务时才关闭异步生成器，重复到不再出现新任务为止。这一段共 1 秒；到时仍在运行的被取消并写进一条警告。
回复在块中间结束最终消息里的文本和思考是内容块，而不是适配器的工作字典，在 stream._extract_final 处完成。未写完的工具调用保持适配器留下的样子。

有样本预算的评测 runner 继承 ExecInterrupt 做看门狗，遇认证错误停止，并按 LLMError.reason 计分。

未实现：同步 _call 的硬上限

Python 杀不掉线程：调用方返回后 _call 还会跑到 socket 失败，期间可能写模型调用节点或存储状态。期限、空闲上限和 SSE 预算已经约束住卡死。评测样本的子进程隔离也未实现。

LLMError 带 reason、retryable、http_status、retry_after_s、attempts、elapsed_s、had_image、provider、model、last_error_type、cause。期限到达是 TIMEOUT，不可重试。可重试错误用尽预算后仍标可重试：意思是换新预算再试，不是立刻重试。

没有裁定的异常可能显示为 UNKNOWN、不可重试；error_retryable_inferred 标记这种情况，只有这类消息保留 Runtime 的有界兜底。显式裁定、已知原因或用尽的传输预算都以其为准。

error_kind 在原因之外给出更细的稳定类别，在异常本身或它包着的异常上找：流卡住和连接被重置都是 TRANSPORT，只有前者是 stream_idle。其余是 stream_total、memory_unavailable、model_unavailable 和 auth。

等待网络

方面规则
开始传输重试耗在到不了端点的失败上（ConnectError、ConnectTimeout、ConnectionRefusedError、DNS，或由它们引起的 SDK 错误），且没有已提交的内容
动作每 5、10、20、然后 30 秒重试，发出原因为 network_wait 的 retry 事件，界面显示 “Waiting for the network”
成功继续本轮，退还这段断网消耗的重试
其他失败可重试：新预算。不可重试：抛出。
结束到 OPENPROGRAM_NETWORK_WAIT_MAX_S（1800 秒，0 关闭）或期限，标记 transport_exhausted；取消时立即结束
从不用于5xx、429、已提交的输出、单次尝试策略、恢复额度为 0
位置retry_stream（Codex）、openai-completions。Anthropic 依赖其 SDK，不等待。

策略边界上的 DNS

socket.gaierror 造成的 DNS_ERROR 以 httpx.ConnectError 抛出，提交前可走有界传输恢复。每次尝试仍解析、校验并固定地址。空或格式错误的答案、被拒的 origin 仍是策略失败。不加 DNS 回退、私有地址例外或无界重试。

嵌套 Codex 认证

Codex Runtime 默认用提供商的活跃账号，与直接对话一致；显式 profile 固定自己的账号。刷新以 CredentialProvider 为准。同步和异步调用经 AgentSession 保留最终原因、裁定和 Retry-After。OAuth token 被拒或任何显式不可重试的失败，只发一次提供商请求。
