Request repair

Every provider stream passes through it: streaming.stream._metered calls request_repair.prepared before the provider and reads its events through request_repair.repairing.

HookWhenAnswers
before_sending(model, context)Before every requestThe context with earlier lessons applied
after_refusal(model, context, refusal)An attempt ended in an error before saying anythingThe mended context, or None if unknown

REPAIRS: prefill, then body_cap. The first mended request goes again, at most MAX_RESENDS (3) times.

Stream ruleDetail
EventsNever held back; the consumer sees the reply begin once
ResendIts first start is dropped; the refusal is not passed on
After anything beyond startEvents pass through, nothing is resent
CancelRepairingStream.cancel_producer closes the current provider stream, with the same bounded wait
Refusal no repair knowsGoes on to retry and failover

The note: [An earlier image was left out: the request was over the provider's size limit.] The ¾ margin lets a conversation grow a few turns before more images go, so its prompt cache is not broken every turn.
