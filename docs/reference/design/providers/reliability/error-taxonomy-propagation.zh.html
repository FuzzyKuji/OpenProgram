错误原因传到界面

压成字符串后，限流、密钥被拒和对话过长看起来都一样，也给不出下一步。范围：对话轮的主流式错误。重试和压缩失败的字符串保持纯文本。

reason枚举可重试对话标题
rate_limitRATE_LIMIT是请求过于频繁 —— {retry_after_s} 秒后重试
authAUTHENTICATION否API key 被拒 —— 去 设置 → Providers 检查
authzAUTHORIZATION否无权限 —— 检查该模型的套餐 / 访问权限
contextCONTEXT_LENGTH否对话太长 —— 压缩或新开对话
policyCONTENT_POLICY否提供商按内容政策拦截了此请求
providerPROVIDER_INTERNAL是提供商 / 网络临时错误 —— 重试即可
transportTRANSPORT是提供商 / 网络临时错误 —— 重试即可
timeoutTIMEOUT否请求超时 —— 重试
invalidINVALID_REQUEST否只显示原始消息
unknownUNKNOWN否只显示原始消息

记忆策略错误直接设为 MEMORY_UNAVAILABLE。

API 使用方、日志和其他频道也读这个原因。自动重试策略不变，这里只暴露字段。更大范围的 except Exception 审计另行处理。

验证

密钥被拒得到 auth，致命。429 得到 rate_limit，可重试，带提示。上下文过大得到 context，致命。单元测试覆盖映射，以及 Agent 边界保留 LLMError 的原因。

端到端需要前端所选模型上可重复的失败，因为前端发送自己选的模型：过期密钥对应 auth，返回 503 的 OpenRouter :free 模型对应 provider。
