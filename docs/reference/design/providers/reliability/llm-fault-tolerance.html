Why read timeouts are generous

A reasoning stream must not carry a tight read timeout: a single timeout=120 caps the body read and fires over a buffering proxy, killing a healthy stream. Codex uses Timeout(connect=30, read=660, write=30, pool=30).

Failover

utils/failover.py and stream_with_failover try each fallback on a failover-worthy failure before content, forwarding events and suppressing the duplicate start.

Settings → System → Models, or openprogram config. OPENPROGRAM_FALLBACK_MODELS overrides it. A fallback reply records what was skipped in AssistantMessage.failover. Each switch also goes to the route_events table the routing overview reads.
