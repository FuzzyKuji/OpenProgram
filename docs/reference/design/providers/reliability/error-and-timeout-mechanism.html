Length of a reply

Chat replies have no limit on tool interactions or total time; a stream that keeps producing is never cut for running long. User cancellation always applies. Explicit runtime.exec deadlines, program call-round parameters and declared budgets of standalone GUI or browser tools are not overridden.

Stopping a call

MechanismEffect
DeadlineEnd to end; overrun bounded by one connect attempt. SSE waits are clamped to what remains.
transport_exhaustedretry_stream marks a spent budget; exec does not restart it, and keeps reason and retryable honest
ExecInterrupt(BaseException)Passes every except Exception retry layer. Only the outermost owner raises it.
OPENPROGRAM_EXEC_TIMEOUT_SProcess default for exec; 0 is unbounded. Needs no signals, which Python delivers only to the main thread.

A benchmark runner with a sample budget subclasses ExecInterrupt for its watchdog, stops on authentication errors and scores by LLMError.reason.

Not built: a hard limit on a synchronous _call

Python cannot kill a thread: the caller would return while _call runs on until its socket fails, possibly writing model-call nodes or store state. The deadline and SSE budgets already bound stalls. Subprocess isolation for benchmark samples is also not built.

LLMError carries reason, retryable, http_status, retry_after_s, attempts, elapsed_s, had_image, provider, model, last_error_type, cause. A deadline hit is TIMEOUT, never retryable. A spent budget of a retryable error stays retryable: retry with a new budget, not at once.

An exception with no verdict may show as UNKNOWN, non-retryable; error_retryable_inferred marks that, and only such messages keep Runtime's bounded fallback. An explicit verdict, known reason or spent transport budget is authoritative.

One RecoveryState per invocation. A dropped connection never spends a repair. A request that succeeds refunds its transport retries. An explicit limit of 0 disables both.

DNS at the policy boundary

A DNS_ERROR from socket.gaierror is raised as httpx.ConnectError, so bounded transport recovery applies before anything is committed. Every attempt still resolves, validates and pins. Empty or malformed answers and denied origins stay policy failures. No DNS fallback, private-address exception or unbounded retry.

Nested Codex authentication

Codex Runtime uses the provider's active account, as direct chat does; an explicit profile pins its own. CredentialProvider refresh is authoritative. Synchronous and asynchronous calls keep the terminal reason, verdict and Retry-After through AgentSession. A rejected OAuth token, or any explicit non-retryable failure, makes exactly one provider request.
