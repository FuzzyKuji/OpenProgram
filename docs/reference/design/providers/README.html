Providers

AspectCurrent design
VendorsOne adapter directory per vendor under openprogram/models/providers/adapters/, with a provider.json declaring models, wire API and login methods. Anthropic, OpenAI, Google Gemini, Amazon Bedrock, Azure OpenAI, xAI, DeepSeek, Mistral, Groq, OpenRouter, GitHub Copilot and others, plus local Ollama, LM Studio, vLLM and llama.cpp.
RequestThe runtime hands over a ready Context (system, messages, tools). The adapter translates it to the wire request and applies that vendor's prompt caching. Nothing above knows vendor formats.
AccountsCredentials per (provider, account) pool, from API keys or subscription OAuth. One account is active; rotation and failover can be switched on.
FailuresEvery error maps to one taxonomy, is retried or failed over by class, bounded by timeouts, and reaches the UI as a structured error.
CatalogFrom provider.json, subscription catalogs and models.dev. Thinking effort and the Fast tier are declared per provider.
Manageopenprogram providers (login, list, use, status, doctor, accounts), or Settings → Providers
