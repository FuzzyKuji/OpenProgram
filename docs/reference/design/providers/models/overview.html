Model catalog

Selectable in chat equals enabled equals resolvable: there is one list. No big files, nothing stale, and the package directory stays read-only.

Providers with no directory work through models.dev. catalog/enabled_models.py is the registry, settings/storage.py persists config, settings/thinking_spec.py holds thinking, models/listing/ is what interfaces read. Nothing else is named a catalog.

Every field optional. If a machine can obtain a field, a human does not write it, so there is no model list.

Browse

Provider list: provider.json providers plus the models.dev index, with names and status only. Model list: queried for one provider, by _browse_models_with_error: the official source when credentialed, models.dev filling gaps or standing in, else empty.

A provider that departs from standard ships list_models.py exposing fetch(provider_id, timeout); _load_fetcher imports it by directory, no central edit. Success: list[dict] with id and name. Failure: {"error": …}. fetch_and_normalize is the one normalisation point.

Ordinary results use a short memory cache. Subscription catalogues also keep an atomic last-known-good copy: a failed request can show stale rows, but only a non-empty official catalogue can retire models.

A failover or agent reference to a non-enabled model is a configuration error pointing at Settings. Old sessions keep their history but cannot continue on a deleted model.

An unknown id is refused with the nearest ones (catalog/suggestions.py): "Unknown model 'openai-codex':'gpt6 sol'; did you mean openai-codex:gpt-6.1-sol, …?". Names compare by words: display-name word 4, id word 3; a version or provider id counts only beside those. Follows magpie (yetone/magpie, MIT).

Invariants

  1. The only persisted model data is enabled specs in config, plus the subscription last-known-good copy.
  2. Ordinary browsing is never written to a file.
  3. Human data in git, program data in user config.
  4. provider.json has only what machines cannot obtain.
  5. openprogram.models.providers never imports openprogram.interfaces.server; the listing imports providers, never the reverse.
  6. <prefix>/<id>, alias fallback and key_prefix are preserved; the registry stays one mutable dict.
  7. One each: fetch_and_normalize (row shape), _upsert_spec_row with _normalize_spec_row (into config), _build_model_from_row (into Model).
What a change must preserve
  • A config row resolves through get_model to the same Model for every provider.
  • google-gemini-cli/* and gemini-subscription/* are distinct keys; rows carry their own.
  • cost, multimodal input, headers (copilot) and compat travel in the spec.
  • Multi-wire providers need one exec per (api, base_url, headers, compat).
  • test_provider_wire_invariants.py and test_model_fetch_routing.py stay green.
