Levels

ThinkingLevel = "minimal" | "low" | "medium" | "high" | "xhigh" | "max"

Plus off. Framework names, unrelated to any API's. The picker shows only what the model supports.

From picker to request

  1. get_thinking_config_for_model (interfaces/server/thinking_effort.py) builds the options from the model's thinking_levels.
  2. _normalize_thinking (runtime/conversation/session_config.py) checks the choice against VALID_THINKING; it is stored per session.
  3. reasoning_from_config hands it to the turn as SimpleStreamOptions.reasoning.
  4. The provider's stream_simple() calls translate_reasoning(provider, model, level) and writes the answer into its request field, for example {"output_config": {"effort": "high"}}.

Which levels a model shows

list_models_for_provider() in models/listing/listing.py takes the first that answers. The picker and list_enabled_models read through it.

A model with reasoning=false has no levels and no picker.

Level to API value

thinking_spec.translate_reasoning answers the first match:

CaseAnswer
wire_format missing or noneNone
Model override with an empty mapNone: reasons, but no effort parameter is sent
Level in the override's mapthat value
Provider map's value for the level is in the override's valuesthat value, so Anthropic's minimal becomes low
Otherwise under an overridethe default effort if the map has it, else the map's first value
effort_stringprovider effort_map, else default_effort
budget_tokensprovider budget_map, else 8192

The framework passes depth and lets the API choose token use. Gemini and older Anthropic models need a count, hence budget_map.

How Fetch uses probes
  • Each provider folder may have a probe_thinking.py exposing probe().
  • During enrichment, models/listing/fetchers/__init__.py calls it through _load_probe when an entry has no reasoning.
  • A provider without a probe, or a probe that fails, does not affect Fetch.
  • Probes are read-only. model_overrides is edited by hand.
