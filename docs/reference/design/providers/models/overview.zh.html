模型目录

聊天可选 = 已启用 = 后端能解析：只有一份列表。没有大文件，不会过期，包目录保持只读。

谁写什么

作者位置内容
人，在 git 里providers/adapters/<p>/provider.json，专用协议另有 <p>.py端点、思考、缓存、覆盖项
程序config.json → providers.<p>.models已启用规格、key、用户状态
网络models.dev、官方 /v1/models只用于浏览

没有目录的供应商通过 models.dev 使用。catalog/enabled_models.py 是注册表，settings/storage.py 持久化配置，settings/thinking_spec.py 管思考，models/listing/ 是各界面读取的层。其他东西不叫 catalog。

provider.json

每个字段都可选。机器能拿到的字段，人不写，所以没有模型列表。

字段作用默认
endpoints具名的 api 和 base_url 组models.dev base_url，OpenAI 兼容
thinkingwire_format、强度映射、每模型档位：思考强度low、medium、high
cache提示缓存无
model_overrides每模型 headers、compat、endpoint、key_prefix；启用时并入规格无

目录用下划线（amazon_bedrock/），id 保留连字符。同一服务两种协议是一个供应商的两个端点。

浏览

供应商列表：有 provider.json 的供应商加 models.dev 索引，只有名字和状态。模型列表：针对单个供应商，由 _browse_models_with_error 查询：有凭据时用官方来源，models.dev 补全或顶替，否则为空。

来源形态拉取器
标准 /v1/modelslisting/fetchers/openai_compat.py
Anthropic，带每模型能力adapters/anthropic/list_models.py
账号级私有adapters/openai_codex/list_models.py、xai_subscription/list_models.py
厂商专用google（query key）、amazon_bedrock（SigV4）、github_copilot（session bearer）、deepseek（只有 id，后补全）

接口不标准的供应商在目录里放 list_models.py，暴露 fetch(provider_id, timeout)；_load_fetcher 按目录名导入，不用集中修改。成功：带 id 和 name 的 list[dict]。失败：{"error": …}。fetch_and_normalize 是唯一的规范化点。

普通结果用短内存缓存。订阅目录另存原子的最后完好副本：请求失败时可显示过期行，但只有非空的官方目录才能退役模型。

启用、禁用、刷新

操作效果
启用（toggle_model）浏览行、覆盖项、端点的 api 和 base_url、推导的思考档位写入 providers.<p>.models；注册表重载
禁用删除该行；手动行保留并置 enabled: false。订阅供应商把 id 记入 disabled_models。
刷新重新浏览已启用模型并覆盖规格
手动添加同一列表，source: "manual"
订阅目录登录后、worker 启动且已过期时、每 6 小时、手动刷新：新 id 启用，变化更新，移除的退役，已禁用的保持。发生变化时广播 provider_models_changed；网页和桌面端重读，重连的客户端也一样。

使用

读取方来源
后端ENABLED_MODELS，键 <prefix>/<id>，经 get_model、get_providers、get_models；未命中时查别名
GET /api/providers/list供应商列表
GET /api/providers/{name}/models该供应商已缓存的浏览结果和启用标记；POST …/fetch-models 立即查询
GET /api/models/enabled聊天选择器：ENABLED_MODELS 原样
interfaces/server/thinking_effort.py来自已启用行的档位

故障转移或代理引用未启用的模型是配置错误，提示指向设置页。旧会话保留历史，但不能继续用已删除的模型。

未知 id 会被拒绝并给出最接近的（catalog/suggestions.py）："Unknown model 'openai-codex':'gpt6 sol'; did you mean openai-codex:gpt-6.1-sol, …?"。名称按词比较：显示名的词 4 分，id 的词 3 分；版本号和供应商 id 只有挨着这些词才计分。沿用 magpie（yetone/magpie，MIT）。

不变量

  1. 持久化的模型数据只有配置里的已启用规格，以及订阅目录的最后完好副本。
  2. 普通浏览结果不写文件。
  3. 人写的数据在 git，程序写的数据在用户配置。
  4. provider.json 只放机器拿不到的内容。
  5. openprogram.models.providers 不导入 openprogram.interfaces.server；listing 导入 providers，反之不行。
  6. 保留 <prefix>/<id>、别名回退和 key_prefix；注册表始终是一个可变 dict。
  7. 各只有一处：fetch_and_normalize（行形状）、_upsert_spec_row 和 _normalize_spec_row（进配置）、_build_model_from_row（成 Model）。
改动必须保持的
  • 每个供应商的配置行经 get_model 解析出相同的 Model。
  • google-gemini-cli/* 和 gemini-subscription/* 是不同的键，行里各带自己的。
  • cost、多模态 input、headers（copilot 依赖）和 compat 都随规格保存。
  • 多线路供应商，每种 (api, base_url, headers, compat) 各验证一次。
  • test_provider_wire_invariants.py 和 test_model_fetch_routing.py 保持通过。
