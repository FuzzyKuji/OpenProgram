Responses reasoning replay

SDK output objects can serialize absent optional fields as null, and a compatible endpoint answers HTTP 422 to content: null on reuse. convert_responses_messages, shared by all Responses adapters, handles it at the outgoing boundary.

ItemAt conversion
Null content, encrypted_content, statusOmitted from reasoning items
Non-null values, summary arrays, opaque encrypted contentPreserved
Server-assigned IDs, cross-model signaturesExisting handling unchanged
Stored historyNever rewritten; byte-for-byte unchanged
Later turnsThe reply stores each reasoning item whole, summary or not, as its thinking block's signature, and text under the message id the provider gave it; the next turn, a retry and a turn resumed from its journal send them again to the same model, so the next request starts with the bytes of the last one; another model gets no earlier reasoning (Rendering)
Asking for itEvery request of a reasoning model sends include: ["reasoning.encrypted_content"], whatever the effort (not on xai-subscription; on Azure, whose requests are stored, only with a reasoning field). With store: false nothing else brings the reasoning back to the next round; Codex asks the same way
PayloadsNever decrypted
Permissions, failed external actionsNot changed, not retried

No new queue, provider fallback or retry policy. The installed OpenAI SDK ResponseReasoningItem declares these fields optional; its output serialization differs from input requirements.
