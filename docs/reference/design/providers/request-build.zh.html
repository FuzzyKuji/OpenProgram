缓存

模式机制声明者
explicit请求里放断点（cache_control、cachePoint）anthropic、amazon_bedrock
auto自动前缀缓存，可选 prompt_cache_keyopenai_responses
out_of_band用单独 API 存缓存；只读命中统计代码认识此模式，目前没有提供商声明
none不做其余提供商，默认

各提供商在 provider.json 的 cache 键下声明；独立的 cache.json 仍能加载，但有弃用警告。settings/cache_spec.py：get_cache_spec、cache_mode、ttl_for_retention、cache_key_param、with_lifetime_setting。

断点

规则细节
调用方标记内容块上的 cache_control 原样透传；Tool.cache_control 同样（透传方案）
未标记apply_cache_policy（settings/cache_policy.py）标记最后一个工具和最新用户消息的最后文本块，否则其最后一块；调用方的标记保留
预算max_breakpoints（4），先给工具，再给消息
TTL≥ 3600 秒 为 1h，否则提供商默认 5 分钟；models.prompt_cache_ttl 设为 1h 时普通缓存活一小时
system单个字符串，由各提供商的 _build_system 标记整块；策略只管工具和消息
Anthropicstream_simple 构建前应用策略；_get_cache_control 读 TTL 映射和 long_ttl_endpoints
Bedrockexplicit，但有自己的 cachePoint 块和最后消息逻辑，不走 apply_cache_policy

策略来自 opencode 的 cache-policy.ts 和 protocols/utils/cache.ts。opencode 的 system 是数组，还能标记最后一段。这里不新增 Context 级结构。
