Auto-Compact 和 Reactive

Auto-Compact 就是压缩里的流水线。/compact [tokens] 指定保留多少最近 token。Mid-turn 和 Reactive 在 agent 循环里运行（超长恢复），作用于该轮所在的分支；Stop 会结束摘要请求。

Context Collapse（设计）
  • 触发：仍超，约 90%；95% 阻塞。
  • 每段 5–10 轮，各摘要约 100–300 token；LLM 调用数等于段数（30 轮 3 段：3 次）。
  • 原文通过读时投影留在 collapse store。

滚动摘要

压缩之外的约束：

  • 始终保留最新一个完整用户轮次，默认保留最新两个；token 预算可能允许少于二十条顶层消息。
  • 已发布的汇报也是边界，因此连续多条汇报之间即使没有用户消息也能折叠；只保留放得下的尾部。
  • 大的已完成工具轮次不能让压缩失效，因此切点移到下一个完整用户边界。活跃用户轮次绝不拆分，其工具证据不进摘要就不丢弃。
  • 摘要输入和 covers_ids 描述同一范围。
  • 估算包括摘要标记和工具结果。完成事件报告两个 token 数和摘要是否生效。
  • 历史上错误的摘要不重写；不迁移、不删除。
  • 会话图的压缩范围用同一消息快照，加载期间重复压缩也一致。
验收
  • 十六条顶层消息含大工具结果时，覆盖完整的旧轮次，上下文缩小。
  • 摘要收到每个被替换的用户请求和可见工具结果；最近轮次不变。
  • 等长或更长的摘要、取消、provider 错误和调用期间的编辑都不写入。
  • 重复压缩、切分支、占用统计和最终请求的渲染一致。

请求检查点的范围

规则：请求检查点。此外：

  • 在消息转换、记忆注入和实际工具解析之后测量；每次发送和回退模型都重查。
  • 缓存属于当前 AgentContext，不跨函数视图。
  • 服务不能持久压缩的调用。不取代 DAG 摘要，也不保证语义无损或与 provider 计数完全一致。

请求检查点

阶段行为边界
预算计入系统提示、工具、响应 schema、输出预留、历史回退模型重新计算
检查点较早的完整纯文本前缀变成任务摘要不拆工具组，不丢多模态或未解决内容
摘要请求全部源文本按预算分块，滚动摘要取消、错误和预算耗尽时保留原文
继续只发送验证过的更小请求原始消息和 DAG 节点不变

改编自 Codex 本地压缩，它保留用户消息并替换执行历史。OpenProgram 不复制 Rust 源码、不截断用户指令、不采用远程加密压缩，也不取代 DAG。检查点文本是助手数据，绝不是系统指令。

验收
  • 长助手文本和工具参数超过模型窗口后，AgentLoop 能继续。
  • 每个保留的工具调用都有结果；最新执行和用户消息完全一致。
  • 摘要调用不超窗口、覆盖全部源文本，溢出时恢复且不丢输入。
  • 取消、前缀变化、切模型和非文本证据不复用不兼容的摘要。
