Auto-Compact and Reactive

Auto-Compact is the pipeline in Compaction. /compact [tokens] takes how many recent tokens to keep. Reactive: context/compaction/reactive.py; stops if every attempt fails.

Context Collapse (design)
  • Trigger: still over, about 90%; blocking at 95%.
  • 5–10 turns per segment, each summarized in about 100–300 tokens; LLM calls equal segments (30 turns in 3 segments: 3 calls).
  • Originals stay in a collapse store through read-time projection.

Rolling summary

Beyond Compaction:

  • Always retain the latest complete user turn, and by default the latest two; the token budget may allow fewer than twenty top-level messages.
  • A posted report is a boundary too, so a run of reports can be folded even with no user message between them; only the tail that fits stays.
  • A large completed tool-heavy turn must not make compaction ineffective, so the cut moves to the next complete user boundary. An active user turn is never split, and its tool evidence is not discarded without entering the summary.
  • Summary input and covers_ids describe the same range.
  • Estimates include summary markers and tool results. The completion event reports both token counts and whether a summary was applied.
  • Historical incorrect summaries are not rewritten; nothing is migrated or deleted.
  • Session-graph compaction scope uses the same message snapshot, so a repeat during loading stays consistent.
Acceptance
  • With large tool results among sixteen top-level messages, coverage includes complete older turns and context shrinks.
  • The summary receives every replaced user request and visible tool result; recent turns are unchanged.
  • Equal or longer summaries, cancellation, provider errors and edits during the call write nothing.
  • Repeated compaction, branch switching, occupancy statistics and final requests render consistently.

Request compaction

Rules: Compaction inside one user message. Beyond those:

  • Measured after message conversion, memory injection and actual-tool resolution; rechecked on every send and for fallback models.
  • Older results first; the latest tool group is retained, though a completed latest group may be processed when necessary.
  • Cache belongs to the current AgentContext and never spans function views.
  • Scope is tool accumulation within one turn. It does not replace DAG summaries or promise lossless semantics or exact agreement with provider counts.

Adapted from Codex local compaction, which keeps user messages and replaces execution history. OpenProgram copies no Rust source, truncates no user instructions, adopts no remote encrypted compaction and keeps the DAG. Summary text remains assistant data, never system instructions.

Acceptance
  • AgentLoop continues after long assistant text and tool arguments exceed a model window.
  • Every retained tool call has its result; the latest execution and user messages are exact.
  • Summary calls fit the window, cover the full source and recover from provider overflow without dropping input.
  • Cancellation, changed prefixes, model switches and non-text evidence do not reuse incompatible summaries.
  • Open: installed-App acceptance.
