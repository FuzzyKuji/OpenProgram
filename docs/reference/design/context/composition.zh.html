组成

规则加注册表：功能自己注册成分，新增功能不改框架。前提：模型是程序里的一个零件，要知道自己的处境，只看该看的历史。

分层沿用 Hermes 的 stable、context、volatile。Hermes 靠写死的 if 链到达各层，只有两个注册点；这里所有成分都是注册项。

这是缓存视角。模型收到的是连续文本，没有分层或断点字样。

判据：本次调用结束后信息流向哪

层规则内容
L0 系统级始终携带，整个会话不变身份、指令、工具
L1 会话级留给后续，前缀稳定项目块、记忆、历史
L2 任务级只属于本次输入、本次片段

L2 必须在 L1 历史之后：放在前面，每次都变的文本会让其后庞大的稳定前缀失效。

注册

@dataclass
class ContextComponent:
    name: str
    layer: Literal["L0", "L1", "L2"]
    order: int                          # 越稳定越小
    build: Callable[[Any], str | None]  # "" / None = 本次没有
    condition: Callable[[Any], bool]    # 默认恒真

每层：收集、按 order 排序、去掉条件为假的、构建、拼接。不用的功能没有代价。

AGENTS.md 和主提示词
  • 只有一个文件名，按目录分层，每个文件放在 <agents_md path applies_to> 中，最通用的在前，近的优先。全局是 <state>/AGENTS.md；项目根是工作目录最近的含 .git 的祖先，否则只有工作目录本身。
  • 工作目录：本轮绑定的 worktree 或项目文件夹，否则默认工作目录。
  • 之后才到达的文件，追加到第一个涉及它的 read、write 或 edit 结果上，每会话一次（agent_loop._attach_nested_agents_md），前缀保持稳定。

  • 没有按智能体的人设文件。指令是 system_prompt，关于用户的了解在记忆的 Core。Worker 启动时退役 agents/<id>/workspace/：未动过的种子删除，改过的追加到 system_prompt 并移到 workspace/.retired/。
  • 主提示词整文件读取；模型需要不同引导时用自己的主提示词，不追加片段。
  • 已加载工具不在文本里重复，加载新工具不改变提示。
  • App 聊天的渠道行指向 guides/a2ui.md，不再每轮携带 2 KB 目录。

设计：调用树和处境

L1 历史作为 DAG 的一条活动路径，渲染成带输入输出的 YAML 树。只在末尾增长和释放，前缀保持缓存，大小取决于调用深度而非调用总数。

被调用者会再调模型？树中
Agentic 函数会进入，按同一规则递归
普通函数或工具不会折叠
推理本身—不进树，其输出就是函数的输出

结构便宜，完成的子树保留 function 行；输入输出昂贵，完成后释放（status: done），子树根保留关键产出。结构和历史是一块：拆开的话，变化的结构块永远命中不了缓存。

处境块和输出契约 
<situation>
You are running INSIDE the agentic function `{fn_name}`.
Job: {fn_doc}
Call path: {call_path}
Position: {program_position}
Your output: {output_contract}

The tool list may include `{fn_name}` itself — do NOT call it (re-entering
causes infinite recursion). Use lower-level tools to do the work directly.
</situation>
字段来源和示例
fn_name帧节点名
fn_doc文档字符串首句，帧节点元数据
call_path沿 caller 链：paper_agent → _pick_stage → literature → seed_surveys
program_position调用方传入，可选：step 1 of the literature stage, next → extract_framework
output_contract可选。解析成决策：输出一个符合菜单的 JSON 对象。交付物：成为给 {consumer} 的 {artifact}。传递：作为 {param} 给 {next_fn}

成对标签，内容里的 # 或代码不会被当成分隔符。作为本次用户消息的第一个文本块，其后是预取、输入和输出 schema。

调用树格式，逐步示例

YAML：模型熟悉、省令牌、靠缩进表示层级、多行值用 | 块。字段：function、input、output、status（running 或 done）、children。

运行 _lit_decide，树到第 3 层；之后 L0 不变：

<call_tree>
- function: paper_agent
  input: "expand LLM-as-Code into an AAAI long paper"
  children:
    - function: _pick_stage
      output: "go to literature"
    - function: literature
      input: "LLM-as-Code → AAAI"
      status: running
      children:
        - function: _lit_decide
          status: running          # 你在这里
</call_tree>

运行 seed_surveys：_lit_decide 折叠成输出；arxiv_search 等普通工具不进树：

        - function: _lit_decide
          output: "next step seed_surveys"
        - function: seed_surveys
          status: running          # 你在这里
          input: "query: LLM agent frameworks surveys …"

第二次 _pick_stage：literature 完成，保留结构，释放输入输出：

    - function: literature
      output: "framework{name, 4 branches}"
      children:
        - {function: _lit_decide, status: done}
        - {function: seed_surveys, status: done}
        - {function: extract_framework, status: done}
    - function: _pick_stage
      status: running              # 你在这里

check_novelty 是嵌在 idea 里的 agentic 函数，递归到第 5 层：

    - function: idea
      status: running
      children:
        - function: generate_ideas
          status: running
          children:
            - function: check_novelty
              status: running      # 你在这里
