记忆的自我认知

被问到记忆如何工作时，上下文里没有答案的智能体会搜索磁盘，描述它碰到的别的框架。本页讲每一轮告诉模型什么。记忆子系统本身见记忆概览。

记忆块

fence_memory 用 <memory-context> 和一句说明包裹两条路径，这句话的目的是不让召回的事实被当成新请求。

路径内容位置
常驻各层 MEMORY.md：先导航后核心，由通用到具体（LocalMemoryBackend.system_prompt）系统提示，L1 order 30
每轮召回本轮搜索结果（search）当前用户消息内的前缀

包裹不是幂等的：sanitize_context 会连内容删掉整个 <memory-context> 块，包两次得到空块。身份说明只能替换开场句，不能再加一层。

静默失败

层失败时
_core_block、system_promptOSError：空字符串，与文件没内容相同
ScopedBackend._read任何异常：空字符串
_build_memory任何异常：空字符串
assemble_sections跳过失败的成分，丢弃空字符串
build_system_prompt退回智能体的内联提示

在 required 策略下这些情况抛 MemoryPolicyError 并结束本轮。否则 require_or_empty 记录 MEMORY_UNAVAILABLE 并发出 memory.degraded，模型看不到。

状态模型看到应得出
memory.backend = none什么都没有无需提及，用户的决定
工作区为空什么都没有还没有记录，正常
读取失败什么都没有暂不可用，绝不是“用户没告诉过我”

工具和失败处理细节
  • openclaw 的记忆插件占默认插槽；工具描述要求必须先召回，并要求把 disabled=true 告诉用户。检索失败返回 disabled、unavailable、警告和建议操作。启动模板声明空工作区是正常的。
  • hermes 没有 list 动作，每次写入都返回完整列表。
  • codex-cli 有 List、Read、Search、AddAdHocNote，受 Feature::MemoryTool（关）和 memories.dedicated_tools 控制。
  • OpenProgram 的记忆写入器用 setting_sources=[] 运行 Claude Code SDK，宿主的 CLAUDE.md 进不去（state/memory/agent_runtime/claude_code.py）。读记忆的智能体没有对应的说明。
