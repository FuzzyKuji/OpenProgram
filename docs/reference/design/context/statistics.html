Accounting rules

One snapshot per response

  1. Read the current branch: compacted rendered history, latest system prompt, frozen tool set.
  2. Categorize locally: message structure, tool schemas, Skills, Memory. Subtract nested items from their parents.
  3. Calibrate: combine the latest provider total for the same HEAD and compute the uncategorized difference.

The breakdown is computed once per API response. Rereading the dynamic tool registry within it would let the categories and estimated describe different moments.

Calculation

classified = system_other + skills + memory + tools + mcp + deferred + messages
other = max(0, provider_total - classified)
displayed_used = provider_total if measured else classified
free = max(0, window - displayed_used)

Measured input tokens win; local estimates are used only without a measurement. When local estimates exceed the measurement, the provider total stays and displayed categories scale down proportionally. The response keeps raw estimates and the calibration factor. The difference is never negative.

Acceptance

  • estimated and the raw category total come from the same calculation.
  • Displayed categories sum to total_used when measured, input_used when estimated.
  • A branch switch or graph change never reuses the old HEAD's measurement.
  • A model switch applies its context window at once and replaces the old measurement with a fresh estimate; the next completed request supplies a new measurement.
  • App and Web read the same /api/sessions/{id}/context and do not estimate on their own.
