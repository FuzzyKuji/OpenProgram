Overview

Each call renders a selection of the session's execution DAG into a Context (system, messages, tools): the branch it continues, old tool output shortened, the oldest turns replaced by one summary once the window fills. This layer decides what to feed; the provider layer decides how to send it.

The DAG render is the only pipeline. A render failure fails the turn visibly. Auxiliary calls (summarization, memory sleep, branch summary, mixture-of-agents) bypass engine.prepare and build a minimal Context: a system prompt and one user message, no tools.

What engine.prepare does

process_user_turn (openprogram/runtime/conversation/turn_runtime/) calls openprogram/runtime/context/engine.py:

  1. Scan references: tool_use ids cited later.
  2. Resolve the head, then render_context, then render_dag_messages.
  3. Take the system prompt the caller assembled (identity, AGENTS.md chain, skills, tools).
  4. Compute the token budget: system, history, tools, output reserve.
  5. Reconcile usage: the last provider measurement plus a local estimate of what was added since.
  6. Return TurnPrep.

Storage: the DAG

A git-backed, append-only session store (openprogram/state/store/session/). No rule rewrites a node. Each turn is a commit and predecessor is what it responds to.

OperationEffect
New messageNode under HEAD; HEAD advances
RetrySibling with the same content
EditSibling with different content

Copy conversationNew session holding the history up to HEAD

Edit, retry and checkout are refused while an agent runs, so the active tree never hangs on a stale node. The workdir does not roll back with checkout.

Rendering, aging, compaction

StageRule
Selectionrender_context walks the predecessor chain from the head and admits each turn's call subtree through the frame and expose rules. It writes nothing. render_dag_messages turns a tool call into a ToolCall and ToolResult pair inside its assistant message, a direct function call into a text pair.
AgingThe last TAIL_TURNS assistant turns keep tool output in full; older results become a short [aged] stub. Each model call records a render_manifest (policy version, aging boundary, spilled nodes). Oversized nodes spill to disk when written.
CompactionAt context.auto_compact_percent (default 80), on /compact, or when the provider rejects a request as too long, engine.compact summarizes the oldest whole turns into one context/summary whose covers_ids lists them. A branch containing the whole covered segment renders summary and kept tail; any other renders raw. The summary must be non-empty and strictly smaller. Compaction

Tool aging

Whole-segment summaries lose which tools ran; without per-item aging the model repeats calls and claims files it never checked. Code: openprogram/runtime/context/tool_aging/, aging.py, render.py.

SettingEffect

Attach and merge

One mechanism: an attach pointer, a node with function="attach" hanging off a user turn as a side child. It renders as text between [Attached from "label"] and [End of attached content].

UseBehaviour
AttachPassive: staged, read on the next model call
Sub-agent reportPointer holding the task, final reply and the read_conversation(session_id, head_id) address of the transcript. A synchronous spawn returns the reply in its agent tool result.
Mergeprocess_merge_turn() writes one pointer per peer after the target head, plus an instruction, and runs a normal turn. A base peer stays verbatim; others may be summarized. Merged heads are marked and a multi-parent context commit records the lineage.

What re-estimates, and the window

server.refresh_context_stats re-estimates and broadcasts when the next request would change:

ChangeSite, under openprogram/interfaces/server/
Compaction mid-turnws_actions/chat/context_usage.py
Model switchroutes/execution/runtime.py, ws_actions/runtime.py
Branch checkout, deletews_actions/branch.py
Sibling checkoutroutes/chat_branches.py
  • A measurement belongs to its branch; another head is re-estimated.
  • Occupancy uses the last measured request, never the sum of a turn's requests. Empty terminal events keep the last measurement. With none, the UI uses a local estimate. Usage and calibration in the older cumulative format are invalidated; cumulative billing totals are unchanged.
  • Window: get_model(provider, model) and real_context_window(), splitting provider:model on the colon (server._resolve_context_window). The session's picker override beats its persisted model.
  • The WebSocket chat runner records each request's prompt size as it finishes, so ring and panel update between tool calls. At turn end it refreshes the branch head and persists the final measurement.
  • Session loading recovers a newer provider usage record from an older turn that never broadcast, unless a later session edit superseded it.
