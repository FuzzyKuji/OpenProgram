Compaction

A session has at most one active summary. Compacting again feeds the previous summary to the summarizer and replaces it. extra_meta._last_summary_id names the active one, _last_summary_text carries its text for chaining; older nodes stay on disk as inert relics. The capsule that draws a summary: DAG rendering §9.

  • Append-only. One node written, nothing mutated: no cloned tail, no edge rewrites, no head movement. Ignoring the summary reconstructs the original view.
  • Ids, not seq intervals. Sibling branches interleave seqs, so an interval would drag in dead forks and change with HEAD.
  • covers_ids is a contiguous segment of real turns. It never names a summary: re-compaction extends the old segment by the new turns.

Rendering rule

render_context in context/nodes.py decides what the model reads, for chat and runtime.exec. Let S be the active summary and L its covers_ids. From head H: if every node of L is on H's predecessor spine, drop L and admit S at its position; otherwise render the spine raw.

CaseResult
Compacted branch[ROOT, S, kept tail…]
Fork without the whole segment (retry inside it, dead sibling)Raw; does not inherit a summary of turns it never had
Any checkout, any timeDeterministic from data; nothing depends on where HEAD was
Superseded summariesNever elide anything

The DAG capsule folds by the same rule over the same covers_ids.

Pipeline

/compact (trigger_compaction), auto-compact (budget at context.auto_compact_percent, default 80%, before a turn) and reactive compact (provider overflow) all run engine.compact:

  1. Freeze the rendered input. compaction.view.load_compaction_view uses render_context and render_dag_messages, with tool results, expose, spill references and the aging boundary. Top-level turns define coverage; visible child calls count toward input and budgets.
  2. Select whole turns. Retain 10% of the window, bounded to 8,000–40,000 tokens (an explicit override wins). Prefer at least four conversational messages at a user boundary; a posted report is a boundary too. Below target: no-op. If the last two turns exceed the target, the cut can advance to the latest user boundary. That latest turn stays intact unless only reports follow it.
  3. Summarize the whole covered prefix: every replaced turn, the initial request, any applicable previous summary, rendered child calls. Other branches' caches are not injected. Non-text media becomes a reference notice. Requests the user cancelled or replaced are marked so; what the assistant or a tool said stays attributed, not stated as fact.
  4. Validate before writing. Reject empty, failed, cancelled, oversized or non-reducing summaries; a candidate is rendered in memory with the same aging boundary and must be strictly smaller. Recheck the head and rendered nodes after the model call; a change is a retryable no-op, and other branches do not count. Provider failure keeps the history, with no lossy structural fallback.
  5. Persist and report. One node; covers_ids expands any previous summary to real turn ids. Coverage count and before and after estimates use the context panel's renderer. No-ops write nothing and do not count.

The context display uses provider input usage. Each request also records a local estimate of the same messages, so a later graph edit scales its estimate by the measured ratio, labelled as an estimate until the next report. Legacy usage with no matched estimate does not calibrate.

Automatic compaction that keeps failing

Each failed try still pays for the whole conversation. After FAILS_MOST (3) failures in a row of one conversation on one model, each within HELD_FOR_S (5 minutes) of the last, automatic compaction waits five minutes from the last failure, then tries once (runtime/context/compaction/hold.py, consulted by DefaultContextEngine.compact).

  • Failures: summarizer error (a 429, for example), empty summary with an error, over the render budget, no reduction.
  • Not failures: cancellation, changed source.
  • A summary that installs clears the count. /compact always goes.
  • Follows magpie's compaction guard (yetone/magpie, MIT).

Graph contract

  • The active summary row carries covers_ids: metadata.covers_ids, extended with covered turns' caller subtrees, minus ids no longer present.
  • Superseded rows carry superseded_summary: true and no covers_ids.
  • The builder does no seq arithmetic or head-dependent filtering.
Compaction inside one user message

Before every AgentLoop provider request, including tool continuations and function-local llm() and agent(), the runtime budgets converted messages, actual tools, system prompt, output cap and a safety margin. This view belongs to the request: execution messages and the DAG stay intact, and no summary node is created.

StepRule
Output capUnspecified: the smallest of model capability, 16,384 and a quarter of the window, used for budgeting and dispatch alike. Explicit caps are never reduced
Tool resultsText-only results of complete tool groups are summarized without waiting for a user message. User messages, tool arguments, result ids, error flags and multimodal content are unchanged
CheckpointStill over: older complete text-only history becomes a task summary. All user messages and the latest assistant segment stay verbatim. Incomplete tool groups, multimodal input and signed reasoning are not eligible
ReuseWithin the invocation, matching original content and model settings; checkpoints also need an unchanged source prefix

Over budgetLocal estimates only. Protected content that cannot fit fails explicitly; a request estimated over budget is not sent
Choosing the share from the user's own calls

Compacting sooner reads less per call but pays for more summaries and rework. context.auto_compact_percent (Settings → System → Models → Summarize long conversations at, 50–95, read at each decision) is advised by GET /api/usage/tuning?days=30 (runtime/context/tuning.py), replaying every share from 50% to 95% on the period's chat, exec and subagent calls, per model. Follows magpie's tune (yetone/magpie, MIT).

  • Calls replay in order, each prompt growing as it really grew, with recorded compactions (a drop to under 60% of a prompt of at least 20K) removed.
  • Past the threshold (the share of the window less the reply reserve), a compaction reads the whole prompt and writes a summary as long as those seen (or 10K over the start when none were). The next call writes it to cache; later ones read back what recorded compactions were followed by (at least 10K until five were seen).
  • Tokens are weighed against plain input with catalog prices or the vendor's usual ratios.
  • Shares leaving less than half a summary, or twenty calls' growth, of room are not tried. Of those within 1% of the cheapest, the largest is advised, only if it saves at least 3% over the current one. Fewer than 50 calls: no advice.
  • The same endpoint advises models.prompt_cache_ttl (5m or 1h) for Anthropic API and Bedrock calls: hour-long writes cost twice input, and a call after expiry writes its whole prompt again. The setting lengthens only a plain cache (with_lifetime_setting in providers/settings/cache_spec.py).
Other compaction schemes

A single rolling summary matches Claude Code, Codex CLI and Gemini CLI and keeps the cache prefix stable. It is policy, not storage: schemes differ only in which summaries are active and how the renderer substitutes them, so switching migrates no data.

SchemeChange
Segmented (several live)N nodes over disjoint segments; the rule applies per summary; an active set replaces _last_summary_id
Nestedcovers_ids admits summary ids; substitution is recursive
External memorySame node; the renderer stops inlining it

Any future context still keeps two contracts. The DAG is the ledger, not the context: context is a deterministic view over append-only nodes, and existing deviations (render_range, expose, attach and merge, memory prefetch) are data, not hidden state. Provenance is mandatory: the ids that entered a prompt are stamped on the call as reads, for replay, audit and per-node marking.

A summary is the first view node: one standing in for other content. Retrieved memory, injected documents and cross-session references generalize it, with the capsule as the generic treatment. No view-composition framework is built ahead of a second scheme.
