The memory block

fence_memory wraps both paths in <memory-context> with one note, written so recalled facts do not read as new requests.

PathContentLands in
ResidentEach layer's MEMORY.md: map, then core, general to specific (LocalMemoryBackend.system_prompt)System prompt, L1 order 30

Fencing is not idempotent: sanitize_context removes a whole <memory-context> block, body included, so fencing twice returns an empty fence. Identity must replace the opening sentence, never add a wrapper.

Tools and failure handling in detail
  • openclaw's memory plugin is the default slot; its tool description makes recall mandatory and requires surfacing disabled=true to the user. Failed retrieval returns disabled, unavailable, a warning and an action. An empty workspace is declared normal in its bootstrap template.
  • hermes has no list action; every write returns the full list.
  • codex-cli has List, Read, Search and AddAdHocNote behind Feature::MemoryTool (off) and memories.dedicated_tools.
  • OpenProgram's memory writer runs the Claude Code SDK with setting_sources=[], so the host's CLAUDE.md never reaches it (state/memory/agent_runtime/claude_code.py). The reading agent has no equivalent statement.
