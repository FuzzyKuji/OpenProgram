Composition

Rules plus a registry: features register components, and adding one does not change the framework. Premise: the model is one part inside a program, told its situation and shown only the history it should see.

Layers follow Hermes's stable, context and volatile split. Hermes reaches them through a hard-wired if chain with two registration points; here every component is a registration.

A cache view. The model receives continuous text with no layer or breakpoint wording.

The criterion: where the information flows after this call

LayerRuleContent
L0 systemAlways carried; unchanged all sessionIdentity, instructions, tools
L1 sessionKept for what follows; stable prefixProject blocks, memory, history
L2 taskThis call onlyInput, per-call sections

L2 must follow L1 history: placed before it, per-call text would invalidate the large stable prefix behind it.

Registration

@dataclass
class ContextComponent:
    name: str
    layer: Literal["L0", "L1", "L2"]
    order: int                          # more stable = smaller
    build: Callable[[Any], str | None]  # "" / None = absent this time
    condition: Callable[[Any], bool]    # default: always

Each layer: collect, sort by order, drop false conditions, build, join. Unused features cost nothing.

AGENTS.md and the base prompt
  • One file name, layered by directory, each file in <agents_md path applies_to>, most general first so the closer file wins. Global is <state>/AGENTS.md; project root is the nearest ancestor of the working directory holding .git, else the working directory alone.
  • Working directory: the turn's bound worktree or project folder, else the default workdir.
  • A file reached later is appended to the first read, write or edit result touching it, once per session (agent_loop._attach_nested_agents_md), keeping the prefix stable.
  • detect_injection_patterns flags files and does not drop them.
  • No per-agent persona files. Instructions are system_prompt; what is learned about the user lives in Memory's Core. Worker startup retires agents/<id>/workspace/: untouched seeds deleted, edited ones appended to system_prompt and moved to workspace/.retired/.
  • One base prompt read whole; a model needing other steering gets its own base prompt, not an appended snippet.
  • Loaded tools are not repeated in text, so loading another does not change the prompt.
  • App chat's channel line points at guides/a2ui.md instead of carrying the 2 KB catalog every turn.

L2

build_system_prompt assembles L0 and L1 only. Programs add L2 with ctx.context(name, build, layer="L2"), registered as <owner>:<name>. build_turn_sections(agent, turn, channel=, tools=) builds them; builders read turn_inputs(); the conversation's own turn sends the text beside its message as the pages section; another turn (a verification, a check-in) appends it to its system prompt after the goal instructions.

A resumed checkpoint keeps its saved prompt.

Everything below rides in front of the turn's user message, in this order, stored on the user node as its turn_context list (context.turn_context). Later requests render the same bytes from it. The code that builds a request passes its audience to the render.

Designed: the call tree and situation

L1 history as one active path of the DAG, rendered as a YAML tree carrying input and output. It grows and releases only at the tail, so the prefix stays cached and size follows call depth, not total calls.

Called thingCalls the model again?In the tree
Agentic functionYesEnters; recurses by this same rule
Plain function or toolNoCollapsed
The inference itself—Not in the tree; its output is the function's output

Structure is cheap, so a finished subtree keeps its function lines; input and output are expensive, so they are released (status: done), and the subtree root keeps its key output. Structure and history stay one block: split, the changing structure block would never hit the cache.

Situation block and output contract 
<situation>
You are running INSIDE the agentic function `{fn_name}`.
Job: {fn_doc}
Call path: {call_path}
Position: {program_position}
Your output: {output_contract}

The tool list may include `{fn_name}` itself — do NOT call it (re-entering
causes infinite recursion). Use lower-level tools to do the work directly.
</situation>
FieldSource and example
fn_nameFrame node name
fn_docFirst docstring sentence, frame node metadata
call_pathAlong the caller chain: paper_agent → _pick_stage → literature → seed_surveys
program_positionPassed by the caller, optional: step 1 of the literature stage, next → extract_framework
output_contractOptional. Parsed into a decision: emit one JSON object matching the menu. Deliverable: becomes {artifact} for {consumer}. Passed on: goes to {next_fn} as {param}

Paired tags, so # or code in the content cannot be read as a delimiter. Inserted as the first text block of the call's user message, followed by prefetch, input and any output schema.

Call tree format, step by step

YAML: familiar, cheap, hierarchical by indent, multi-line values in | blocks. Fields: function, input, output, status (running or done), children.

Running _lit_decide, tree at level 3; L0 unchanged afterward:

<call_tree>
- function: paper_agent
  input: "expand LLM-as-Code into an AAAI long paper"
  children:
    - function: _pick_stage
      output: "go to literature"
    - function: literature
      input: "LLM-as-Code → AAAI"
      status: running
      children:
        - function: _lit_decide
          status: running          # you are here
</call_tree>

Running seed_surveys: _lit_decide collapses to its output; arxiv_search and other plain tools stay out:

        - function: _lit_decide
          output: "next step seed_surveys"
        - function: seed_surveys
          status: running          # you are here
          input: "query: LLM agent frameworks surveys …"

Second _pick_stage: literature finished, structure kept, input and output released:

    - function: literature
      output: "framework{name, 4 branches}"
      children:
        - {function: _lit_decide, status: done}
        - {function: seed_surveys, status: done}
        - {function: extract_framework, status: done}
    - function: _pick_stage
      status: running              # you are here

check_novelty, an agentic function nested in idea, recurses to level 5:

    - function: idea
      status: running
      children:
        - function: generate_ideas
