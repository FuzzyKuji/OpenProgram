占用与压缩

圆环、面板和压缩报告读同一视图：下一轮模型收到的内容。压缩不移动 HEAD，所以 HEAD 不变不代表图不变。

一个度量

rendered_history 是当前有效摘要加未覆盖的尾部。

使用方视图规则
session_stats.compute_breakdownrendered_history唯一度量。按折叠后的消息计数，含 thinking 和工具块
engine.compactestimate_total_used压缩前后各一次，写入 compaction_finished
refresh_context_stats分项和总量递增 _context_rev，依据改为 estimated。手动或自动压缩后运行
GET /api/sessions/{id}/context当前快照仅图未变时复用
session_context_stats上次请求仅 HEAD 和 _context_rev 都未变时复用
_get_messages、get_branch未折叠分支聊天历史。占用计算不用它

缓存只按 HEAD 取键时的症状：/compact 报告 40.7k，面板仍显示 Messages 125k。摘要已存，快照是旧的。

压缩结果

  1. 准备：从渲染历史构建提示，计算 budget_pct。
  2. 达 80% 压缩：模型写摘要，追加摘要节点。
  3. 再次准备：本次请求读摘要和尾部。
结果条件事件
开始决定调用摘要模型compaction_started
成功摘要已存，summarised_count > 0compaction_finished
无可压缩消息少于 4 条，切点不超过受保护的开头，自动重试被暂缓，或摘要未覆盖任何内容compaction_finished 带 no_op: true。调用模型前已知时，不发开始事件，不发请求
失败摘要调用或流程异常；或保留历史并给出原因：摘要过长、未缩小、已取消、上下文已变、范围无效、插入无结果compaction_failed；保留历史时同时带 no_op: true

触发：/compact 或面板按钮；请求前预算达 80%；从 413 或 prompt_too_long 恢复。一个会话最多一个活动摘要。insert_summary_node 保留旧轮次。

圆环和面板

状态显示
正常中性轨道，弧线按比例着色。没有建议边框或建议状态。点击打开面板
压缩中分支正在运行的是 compact 操作，或处在压缩阶段的轮次时（isCompacting，从 compaction_started 到结束或失败）：圆环忙碌，面板按钮禁用
压缩对话面板行发送 {action:"compact", session_id}，与 /compact 同一 WebSocket 路径。无会话或压缩中时禁用。刚压缩完仍可点，服务端回答没有可压缩的内容

系统消息

自动和手动压缩共用 chat-handlers.ts 的同一分支。消息为双语。

事件文案
开始不加消息：运行条显示“正在压缩上下文…”
结束上下文已压缩：盖住 N 条旧消息。对话事件位：此处压缩了上下文：盖住 N 条，本地估算 X → Y tokens。只在含有整段被盖住消息的分支上显示；从这段中间分出的分支没有被压缩过
失败上下文压缩失败[：错误]
结束且 no_op上下文保持不变，本次没有应用更小的摘要

验收

  • 成功后，圆环和面板总量下降，并与 compaction_finished.tokens_after 一致。
  • 重复压缩不调用摘要模型，报告无可压缩，绝不显示“盖住 0 条，X → X”。
  • 任何占用下都没有建议边框。
  • 压缩期间圆环忙碌、按钮禁用，完成后恢复。
