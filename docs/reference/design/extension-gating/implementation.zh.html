门控实现

门控点

每个门控都在模型即将看到扩展的位置运行。

扩展何时看到门控拒绝时
技能/skill X 注入 SKILL.mdinterfaces/server/ws_actions/chat/turn_skill.py 的 _skill_gate_error，调用 gate()skill_blocked，“Skill blocked: 原因”；不展开正文
工具resolve_tools() 构建本轮工具runtime/conversation/model_tools.py被过滤
MCP同一流程，名称为 <server>__<tool>resolve_tools 内部的 _apply_profile_gates，作用于每条返回路径按服务过滤。缺少 required 时抛 RequiredMcpUnavailable

没有更早的统一入口：技能是带分类的对象，工具是裸名称，MCP 工具是带命名空间的名称。不同的只是输入形状。

共享函数

openprogram/extensions/gating.py：纯函数，任何层都可导入。

函数返回
match_any(name, patterns)是否有 fnmatchcase 模式匹配；空模式为假
gate(*, name, category="", disabled=(), allowed=(), categories=())通过时 None，否则为原因字符串
check_required(installed, required)没有任何匹配的 required 模式

Schema

runtime/agent_registry/manager.py 的 AgentSpec。每个块都是普通 dict。

块默认
skills{"disabled": [], "allowed": [], "categories": []}
tools{"mode": "automatic"}
mcp{"disabled": [], "allowed": [], "required": []}

resolve_tools

每轮 override 优先于 profile.tools。

输入结果
Noneagent_tools(source=…, only_available=True)
[]、mode: none无工具
mode: automatic，或没有 enabled、toolset、preset、allowed 的字典全量工具减去 disabled
mode: selected 或 preset这些名称减去 disabled；有延迟工具时加入 tool_search
enabled 列表恰好这些名称；优先于 allowed
toolset该集合，按两个模式列表过滤
其他字典DEFAULT_TOOLS，按两个模式列表过滤
名称列表恰好这些，除非含 tool_search，否则都常驻

配置的 MCP 门控作用于每条路径，包括每轮名称列表。web_search 由自己的布尔值单独叠加。required 在过滤之后、调用供应商之前检查。

兼容性

skills、tools、mcp 必须是对象。AgentSpec.from_dict 用 dict() 处理它们，因此 skills: ["pdf", "drawio"] 这类旧列表在加载时抛 ValueError，不会迁移。只含空列表的 tools 字典视为 automatic。

测试

没有专门的单元测试：match_any 只是 fnmatchcase 加遍历。openprogram doctor 检查技能能否加载和 MCP 配置能否读取，不检查门控。语义偏离 fnmatchcase（如支持 **）时再加测试。
