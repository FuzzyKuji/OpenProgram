Claude Code

Each type has its own list field, of exact names: easy to read, verbose for broad cases.

Agent fieldMeaning
toolsAllowlist
disallowedToolsDenylist
skillsPreloaded
mcpServersA reference or an inline definition, so an agent can bring its own MCP config
hooksSession-scoped per agent. OpenProgram's plugin hooks in openprogram/extensions/plugins/hooks.py have no per-agent scope
permissionModeThe agent's permission mode

opencode

One permission ruleset per agent: {pattern, action: allow | deny} rules glob-matched against keys such as tools:bash, mcp:slack/*. First match wins.

  • A new type is a namespace prefix with no schema change.
  • One rule can do the work of several ({pattern: "mcp:*", action: "deny"}).
  • Trade-off: users learn a pattern grammar.

hermes

Platform-adapter focused (Discord, Slack, ntfy, …). Each adapter's plugin.yaml sets what it may do on the network, at channel level, with no agent-profile equivalent. Nothing adopted here.

Design rationale

A Claude Code skeleton with opencode wildcards. Per-type fields read as what they do, and allowed, categories and required extend the existing struct mechanically. fnmatch removes pure-list verbosity with one helper, and exact names keep working. A single ruleset would be a pure refactor (not built). A meaningfully different model in a future framework reopens this.
