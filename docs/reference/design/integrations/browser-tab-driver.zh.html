浏览器标签页驱动

  • 浏览器应用的 tabs.py 为 browser 目标驱动 App 的内置标签页。
  • 内置标签页只有这一种操作方式：模型、程序的网页标签命令和页面资源都经过它。
  • 一次调用指明标签页和元素；page context token、会话、frame、租约和修订号校验都不存在。

标签页

项
身份一个标签页就是渲染进程列出的 (window_id, tab_id)（surface_context.capture_pages_for_listing，带上每个标签页的 CDP target_id）。
Id驱动给它起名为 t 加上 window_id 与 tab_id 的 SHA-1 的前四个 base32 字母（冲突时多取一个），所以每个进程——worker 和 fork 出的工作流子进程一样——在每个轮次、每个对话、每个子 agent 里都给同一个标签页同一个 id，按任何顺序重新列出也不会改名。
移动的标签页移到另一个窗口的标签页保留它的 id：列出的标签页的 target_id 属于某个已知标签页时，就接管那个标签页。
变化的目标target_id 变了的标签页（App 重启过）会忘掉它的 ref、文档基线和截图。
绑定每次列出都会重新绑定每个页面，所以新绑定替换旧绑定时旧绑定会被释放。
默认标签页不带 tab 的动作发往其 agent 最近用过的标签页（见下），否则发往获得焦点的标签页，再否则发往唯一可见的标签页。
open、close、screenshotopen 请渲染进程新开一个后台标签页（surface_context.open_page）并把它设为当前标签页；close 和 screenshot 经过标签页的绑定（request_close_tab、request_bound_screenshot），绑定过期时重新列出一次即可续上。
归属agent 打开的标签页记在 browser_tabs_opened 里（重启后仍保留），带着它的对话，以及 opened_in 里打开它的那次执行。tabs 列出本对话的标签页和当前页，tabs(all=true) 列出其余的。工具说明要求模型复用已开的页面、用完关闭。归档或删除对话时，关闭它打开的所有标签页（close_conversation_tabs）。用户自己的标签页从不关闭。
运行的标签页定时运行或检查轮次结束时，关闭这次运行打开的标签页，不论它怎么结束：完成、失败、被停止或被打断（close_run_tabs，在执行结算时以及后台服务得知定时运行结束时调用）。这类运行从干净状态开始、以答案结束，它打开的东西对下一次没有用。只有它们会被记在标签页的记录上（opened_in）。
谁等关闭完成在后台服务里，运行的结束不等它关完。定时运行自己的进程在退出前关闭并等它完成，因为线程会被进程退出打断。进程被杀的运行，后台服务一看到进程没了就把它结束，标签页随之关闭。
上限一个对话最多留着它的 agent 打开的 TABS_PER_CONVERSATION（8）个标签页：多开出一个之后，关掉最久没用的那个（_keep_within_limit），并在结果的 note 里说明。新开的和用户面前的标签页不动；只算这一轮列得出的标签页；整理失败不会让打开失败。反复开页面的东西因此有了上限，比如监控或跑上几天的 Goal。

连接

项
所有者线程Playwright 的同步 API 属于单个线程，所以由一个所有者线程持有到 App 的连接（对 desktop_app_ws_url 调用 attach_to_app），并执行所有页面调用；调用方带着自己的上下文变量等待它。
不改动 AppPlaywright 把接管的页面当成测试浏览器：每个页面（包括 App 自己的窗口）都被告知系统是浅色、页面有焦点，下载也改到 Playwright 的目录。attach_to_app 以 no_defaults 连接，这些都不会作用到 App。它是唯一调用 connect_over_cdp 的地方，由契约测试保证。
焦点后台页面不触发焦点事件，所以驱动对自己操作的每个标签页打开焦点模拟，其他页面不动。
查找页面页面通过 Target.getTargetInfo 与标签页的 target_id 匹配来找到。
重连一个连接不一定能得知 App 在它之后打开的标签页，所以找不到目标时驱动会重新连接再找一次；断开的连接在下一次调用时重连。
记录第一次接上页面监听时，驱动开始记录它的控制台、页面错误和请求（各保留最近 300 条），并统计文档导航次数和进行中的 fetch/XHR 请求。
没有 App 窗口没有可以开标签页的 App 窗口时（open_page 返回 desktop_unavailable：App 已关闭，或这个进程连不到它），open 启动驱动自己的无窗口浏览器（host/resources/background_browser.py：运行时自带的 Chromium，否则把已安装的 Chrome 或 Edge 当程序启动，用全新的配置）。
自有浏览器的标签页窗口 id 是 background；id、动作、锁和归属记录都相同；没有预览，也没有 App 的登录状态，open 的结果会说明。它们只活在打开它们的进程里，和 App 连接共用一个 Playwright：最后一个标签页关闭、闲置超过 OWN_IDLE_SECONDS（30 分钟）或进程结束时浏览器随之关闭。App 没在运行时列表不等待；App 在运行却不应答时照常报错。

多个 agent

项
不做租约同一对话的 agent 共用会话 id，子 agent 可以并行运行，所以标签页被一个 agent 占用的时间不超过一个动作或一组动作：跨轮次持有租约会让对话拒绝自己的轮次，正是跨轮次持有的租约和它的交接造成的。
锁每个 Tab 有一把锁。
持锁范围动作在第一次页面调用前拿到它，并一直持有到等待结束、结果读出，所以别的 agent 的输入不会落在一个动作和它报告的状态之间。
动作列表一组动作（targets/browser.run 带多个步骤，在 tabs.batch() 里）持有它拿到的所有锁直到结束，所以一组动作里填写的表单不会被插入。
等待等锁时轮询并检查取消，超过 TAB_WAIT_SECONDS（60 秒）以 tab_busy 失败；两组动作互相等对方的标签页时也这样结束，而不会死锁。
Agent一次调用代表的 agent 是 <session>/<execution>（_VIEWER 上下文变量，随调用带进所有者线程）。
当前标签页每个 agent 记住自己的当前标签页；还没有的 agent 从它所在对话最近用过的标签页开始。
快照快照按 agent 跟踪（track = openprogram:<agent>，以及每个 agent 自己的文档基线），所以一个 agent 看到的变化涵盖它上次查看之后的一切，包括其他 agent 做的。
写入记录每个标签页记录写操作及其执行者；自本 agent 上次结果以来有别的 agent 操作过该标签页时，结果会附上 note。
所有者线程只有单个页面调用在所有者线程上执行。
轮询wait 和动作后的等待在调用方线程上轮询，每次只占用所有者线程很短的时间（_shows、_activity、_loaded），所以一个 agent 的等待不会挡住另一个 agent 在另一个标签页上的点击。

写操作只发送一次

项
重试只有 _page 在任何输入之前抛出的 tab_gone 会让驱动重新列出标签页并再试一次。
失败的动作在 Playwright 可能已经发出输入之后失败的动作算作一次写操作；超时时错误会说明它可能已经生效，并附上页面当前状态；动作期间标签页关闭为 tab_closed。
成功之后动作成功之后，等待或读取页面时的任何失败都作为带 note 的成功结果返回，绝不成为调用方会重试的错误。
closeclose 把渲染进程的响应超时视为 close_uncertain，把过期绑定视为 tab_gone（什么都没发出），其他失败视为 close_failed。
evaluateevaluate 算作写操作。

动作打开的标签页

连接会发现目标（Target.setDiscoverTargets）并为每个新页面目标计数。动作期间计数变化时，驱动列出标签页，结果的 opened 给出 opener_tab_id 是被操作标签页或未知的新标签页。agent 的当前标签页保持不变。

坐标

项
记录截图按 agent 记下 CSS 像素与图像像素之比、标签页最后一次写操作、URL、滚动位置和图像本身。
点击按 x,y 点击需要该 agent 的截图；截图之后页面跳转过或滚动过时，以 screenshot_stale 失败。
落点检查如果此后 Agent 写过该标签，驱动重新截图，比较两张图中点周围 64 CSS px 的方块（macOS 用 Core Graphics 解码，Windows 和 Linux 用驱动自带的 PNG 读取器；最多 6% 的像素可在单通道相差超过 32，容纳光标和抗锯齿）。
判定该点仍显示截图所示内容时点击继续，所以在别处打字或无效按键不需要新截图。不一致或无法比较像素时拒绝。
拒绝方式拒绝时附上新截图并记为该 agent 的截图，下一次 x,y 不用再额外调用。

预览跟随

项
跟随规则对话的页面预览跟随驱动报告的操作：前端只跟随实时的 browser.resource 事件，且其中的 last_operation 是新的、阶段为 dispatched 或 acknowledged，快照从不触发跟随。
写动作每个写动作（read、console、network、wait、screenshot、tabs 和 close 以外的动作）先为当前 execution 保留标签页的资源行（publish_bound_page），再带 follow 报告 dispatched（pages.report_browser_operation），在输入发出之前记下操作，并把资源的控制状态设为 active。
动作之后动作之后以同一个操作 id 报告 acknowledged，或带原因码报告 failed；失败的报告不会再设置控制状态。
操作中状态页面只在设置它的 execution 运行期间显示为操作中：那个 execution 结束后，资源投影会把 active 投成 idle。
标记点点击的结果带标记点：点击前，_aim 把元素滚动到视口内并记下其包围盒的中心，按 x,y 点击时记下换算出的 CSS 坐标，同时记下视口的 innerWidth 和 innerHeight；sanitize_operation 把它们变成 point，以视口尺寸作 width 和 height，由 browser-marker-geometry 映射到截图上。
读动作读取（read、console、network、wait、screenshot）报告一个不带 follow 的 acknowledged 操作，所以预览会跟随，页面却不会被标为操作中；open 在发布新标签页之后为它报告同样的操作，使它成为被跟随的标签页。
列表步骤一组动作的每一步各自报告。
上报报告从不让动作失败：出错只在 debug 级别记日志。

工作流子进程

项
驱动fork 出的子进程丢弃父进程的驱动（os.register_at_fork），因为它的所有者线程和连接属于父进程，然后启动自己的驱动。
渲染进程调用它的渲染进程调用（capture_pages_for_listing、open_page、request_close_tab、request_bound_screenshot）经过父进程的 webtab 桥，桥把它们限制在发起的窗口内、只认可它发出的绑定，并在子进程结束时关闭子进程打开的标签页。
操作上报子进程不持有 App 连接，所以它的操作报告也交给 worker：pages.forward_operations_to_parent 把每个报告作为 __op_browser_operation__ 放进子进程的事件队列，worker 用 report_forwarded_operation 报告它，只保留操作本身的字段，没有指明 execution 时用它启动的那个。
锁标签页锁和写记录是按进程的，所以子进程和 worker 在同一个标签页上会在单次页面调用的粒度上交错。

访问与取消。 本轮的页面关闭了 agent 访问（preview_status 为 disabled）时，内置浏览器的所有动作都以 page_access_disabled 被拒绝。等锁、wait、动作后的等待和一组动作的每一步都会检查取消。
