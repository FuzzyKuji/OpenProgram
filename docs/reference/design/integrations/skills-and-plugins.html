Skills and plugins

KindWhat it is
SkillA directory with SKILL.md and optional references/, templates/. The description is listed in the system prompt; the skill tool loads the body
PluginA manifest contributing skills, commands, agents, hooks, MCP servers and provider directories. Carries no code, so enabling one runs nothing in the worker

Managed on the Abilities pages and with openprogram skills, openprogram plugins. Mounting: Plugin runtime.

Skills

---
name: my-skill
description: One-line trigger description
category: devops              # hermes-style grouping
optional: false               # replaces hermes optional-skills directory
allowed-tools: [Read, Edit]   # claude-code: restrict usable tools
triggers:                     # OpenProgram extension
  keywords: ["deploy", "ci"]
  file_patterns: ["*.yml"]
  slash: "/deploy"
version: 1.0.0
author: ...
---
Precedence, lowest firstLocation
Remote cache~/.openprogram/cache/skills/<name>/, pulled from a remote index
PluginContributed by enabled plugins
User~/.openprogram/skills/<name>/
Project<project>/skills/<name>/

A later source overrides on conflict. The name is the path relative to the source root (anthropic-skills/docx), so a collision means one skill from two sources.

A manifest naming code is refused; code that adds tools or a UI is an application. With no code in the worker there is no in-process or RPC mode.
