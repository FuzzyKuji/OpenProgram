Chat rendering

While a live assistant reply or its runtime card exists, Web Use tree updates do not reload the transcript, so message identity, streaming, scroll and message actions survive. A standalone run with no persisted card may hydrate once.

Claude Code's visual click path, for comparison
  1. computer(screenshot, tabId) reaches the claude-in-chrome MCP tools, then the Native Messaging host and Chrome extension service worker.
  2. The worker calls Page.captureScreenshot on the tab and returns PNG and viewport metadata the same way.
  3. computer(left_click, [x,y], tabId) follows the same route.
  4. The worker validates tab, permissions and coordinate mapping, and may pause for user authorization.
  5. UPDATE_PHANTOM_CURSOR moves the on-page cursor, a visual cue only.
  6. Input.dispatchMouseEvent sends moved, pressed, released through CDP, without moving the system mouse.

From the locally inspected Claude Code 2.1.227 and Chrome extension 1.0.85 packages; not a stable interface. Clicking by page ref needs no screenshot. Claude Code browser documentation, Playwright MCP.

Test coverage

Component tests cover both MCP adapters for namespace collisions, reobservation revocation, cross-session and stale references, and permission rejection. Real Chromium integration tests cover file selection and independent verification without personal documents or live websites.
