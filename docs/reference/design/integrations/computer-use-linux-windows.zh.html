Linux 与 Windows 后端

Linux 后端

LinuxComputer 保持 MacComputer 的接口，工具、服务端的应用查询和测试都通过 backends.backend() 驱动任一后端。它只在 X11 会话里运行：Wayland 下任何客户端都不能读取别的客户端的画面或向其注入输入，support() 会如实说明。

项
应用AT-SPI 桌面下拥有窗口的子节点，加上所属进程不接入无障碍总线的顶层 X 窗口。X 窗口的所属进程取 _NET_WM_PID；Xt、Motif 客户端不设置它时，取名称或可执行文件名以窗口 WM_CLASS 实例名开头的最新进程。
应用身份每个应用按可执行文件或名称匹配桌面条目（Gio.AppInfo），由此得到标识（org.gnome.Calculator）、显示名，以及在 hicolor 主题里查到的图标。启动通过 Gio.DesktopAppInfo.launch，之后既等窗口也等应用的 AT-SPI 根节点，因为 GTK 4 应用在窗口映射之后才加入总线。
窗口顶层窗口取窗口管理器的 _NET_CLIENT_LIST（用 xprop 读取），这样排除了 GTK 10×10 的 client-leader 窗口；没有客户端列表时，跳过 10×10 及更小的窗口。AT-SPI 的 frame 先按标题、再按尺寸与 X 窗口配对。不在已映射集合里的窗口报告为最小化；show_window 重新映射它。
树角色是 AT-SPI 角色名（push button、text、check box），role_name 原样打印。子树在屏幕上时才读：GTK 3 设置 SHOWING，GTK 4 在窗口以下只设置 VISIBLE，所以窗口的子节点只要有一个报告 SHOWING 就按 SHOWING 遍历，否则按 VISIBLE。未展开组合框的弹出项和 GTK 的提示窗口跳过。
树的过滤无名的 filler、panel、section 是透明的。GTK 4 用类名给无名控件命名（AdwGizmo、GtkMenuButton），这类名字不当作标签。
标志标志来自状态（CHECKED 或 PRESSED、FOCUSED、SELECTED、EXPANDED、非 ENABLED/SENSITIVE），settable 来自 EditableText 或 Value，secure 来自 password text 角色。次要动作是元素的 Action 名称中除 click、press、activate、toggle、jump、open、select 以外的部分。
后台的元素动作点击执行元素的主动作；set_value 用 EditableText.set_text_contents、Value.set_current_value，复选框状态不一致时执行切换；type_text 和 paste 用 EditableText.insert_text（UTF-8 字节长度）在光标处插入并替换选区，换行执行输入框的 activate 动作；对输入框 press_key Return 执行 activate
选区、滚动、菜单select_text 用 Text.set_selection 或光标偏移（字符偏移，不是 UTF-16）；copy 读取 Text.get_selection，不经过剪贴板；按元素 scroll 把最近的滚动条的 Value 每页移动其长度的 90%；menu 遍历窗口的 menu bar 并执行叶子项的动作。
焦点Component.grab_focus 会让 GTK 把窗口提到前台，所以凡是必须移动焦点的地方，都会把焦点还给原先活动的窗口。
前台输入GTK 和 Qt 通过 XInput 2 读取指针和按键，会忽略用 XSendEvent 发给未聚焦窗口的核心事件，所以按坐标点击、拖拽、滚轮、悬停和按键都通过 XTEST 发送：先激活窗口（windowactivate；没有 EWMH 窗口管理器时用 windowraise 加 windowfocus），执行输入，再恢复指针位置、原先排在它上面的窗口和原先活动的窗口；hover 让指针留在原处。
组合键组合键用 xdotool 名称，cmd、command、meta、win 映射为 super，option 映射为 alt。
截图对外部 X 窗口调用 Gdk.pixbuf_get_from_window，得到窗口自身按 X 分辨率的像素，长边缩到 1568 像素以内；最小化的窗口没有截图。截图像素通过 xdotool getwindowgeometry 给出的窗口位置换算为屏幕像素，与 AT-SPI 屏幕坐标用的是同一个参照系。
OCR稀疏窗口（以及 find 的回退）用 tesseract --psm 11 tsv，语言取 eng、chi_sim、chi_tra、jpn、kor 中已安装的；置信度 30 以上的词拼成行。Linux 上不检测轮廓形状。
音频pactl list sink-inputs 给出每个音频流的 application.process.id；录音器轮询，直到出现该应用或其任一子孙进程的音频流（每次轮询都重新读取子孙进程，因为播放器通常是开始录音之后才启动的子进程），然后用 parec --monitor-stream=<index> 以 16 kHz 单声道浮点读取。读取持续到 parec 结束，所以停止时它还缓冲着的样本也会保留。
音频延迟PipeWire 下四分之一秒内就收到第一批样本；PulseAudio 的定时调度下，对一个音频流的首次监听会晚 1.2–1.7 秒开始，这段会丢失。
拒绝password text 元素、Seahorse、KWallet、gcr 弹窗、polkit 代理以及 OpenProgram 自身的条目。
项
应用指南app 指南在发送时按 Linux 改写（targets/app.py 的 _LINUX_GUIDE）：哪些步骤会把窗口切到前台、纯文本 paste、不经剪贴板的 copy、Linux 上的拒绝列表。
应用列表回复computer_use_apps 的 WebSocket 回复带上 worker 的 platform；在 Linux 上，审批卡片对按坐标输入、拖拽、悬停和回车以外的按键（needsForeground）说明这一步会把窗口切到前台。

Windows 后端

WindowsComputer 保持同一个接口。进程设为按显示器感知 DPI（SetProcessDpiAwarenessContext(-4)），所以窗口框、UI Automation 的边界和输入坐标都是物理屏幕像素。它调用的每个 Win32 函数都声明了 restype 和 argtypes，64 位句柄不会被截断。

项
应用EnumWindows 给出的可见、无所有者、非工具窗口且有标题的顶层窗口，按进程分组。UWP 外框（ApplicationFrameWindow）属于 ApplicationFrameHost，它的应用是子窗口 Windows.UI.Core.CoreWindow 所在的进程。已安装应用来自 Get-StartApps（桌面应用和应用商店应用都在，缓存一分钟）；运行中的进程按可执行文件或名称对应到一行，启动时运行 explorer.exe shell:AppsFolder\<AppID>，再等新窗口出现。
树对窗口调用 IUIAutomation.ElementFromHandle，用控件视图遍历器遍历；屏幕外的子树跳过，菜单项除外。角色是控件类型（50000–50040）的小写名称（button、edit、check box）。没有名字、没有动作的 pane、group 和 custom 是透明的。
标志标志来自模式：Toggle 状态、IsEnabled、HasKeyboardFocus、SelectionItem、ExpandCollapse、可写的 Value 或 RangeValue（settable）、IsPassword（secure）。值取自 RangeValue、Value 或 Text 模式的文档范围。次要动作是 expand、collapse、scroll、select，以及 LegacyIAccessible 里不是 press、click、invoke、jump 的默认动作。
后台元素动作点击依次尝试 Invoke、Toggle、SelectionItem.Select、ExpandCollapse 和 LegacyIAccessible.DoDefaultAction，对输入框则是聚焦；set_value 用 Toggle、RangeValue、Value 或 LegacyIAccessible；select_text 按字符移动 Text 模式的范围；copy 读取 Text 模式的选区；按元素 scroll 用最近的 Scroll 模式按大步滚动；menu 遍历传统 HMENU（GetMenu）并投递 WM_COMMAND，或展开并调用 UI Automation 菜单项。
投递输入按坐标的点击、拖拽、滚轮和悬停，以鼠标消息投递给该点下最深的子窗口（ChildWindowFromPointEx），用它的客户区坐标；第二次点击是 WM_LBUTTONDBLCLK。不带命名修饰键的按键，以 WM_KEYDOWN/WM_CHAR/WM_KEYUP 发给该线程的焦点窗口（GetGUIThreadInfo）；type_text 每个 UTF-16 单元投递一个 WM_CHAR。向传统 edit 或 rich edit 控件 paste 时发送 WM_PASTE。
前台输入快捷键读的是 GetKeyState，投递消息改变不了它；UWP 外框、Chromium 和 Firefox 窗口读取原始输入。所以带修饰键的组合键、对这些窗口类的指针输入，以及其他情况下的 paste，都在 _Forward 里用 SendInput：它先接入前台线程的输入队列（AttachThreadInput）以便调用 SetForegroundWindow，执行输入，再把光标、原来的前台窗口，以及该窗口在原先上方窗口之下的位置还回去。
截图PrintWindow 加 PW_RENDERFULLCONTENT 把窗口（无论是否被挡住）画进一张外框大小的位图；从中裁出可见框（DWMWA_EXTENDED_FRAME_BOUNDS），用 HALFTONE 模式的 StretchBlt 缩到长边 1568 像素，再由 GetDIBits 取出 BGRA 行，png_encode 不借助任何图像库写成 PNG。最小化的窗口没有截图；show_window 用 SW_SHOWNOACTIVATE 还原它。
剪贴板paste 写入 CF_UNICODETEXT，md 和 html 还写入 "HTML Format"（头部偏移由 cf_html 计算），之后恢复原来的文字。
OCR与 Linux 相同，装了 tesseract 时使用。
音频对 VAD\Process_Loopback 调用 ActivateAudioInterfaceAsync，参数为 PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE，得到一个 IAudioClient，以共享回环模式初始化并自动转换为 16 kHz 单声道 float，在独立的 COM 线程上由事件驱动经 IAudioCaptureClient 读取。完成回调是 agile COM 对象，因为 Windows 在工作线程上调用它。
拒绝IsPassword 元素、CredentialUIBroker、consent（UAC）、LogonUI、LockApp、credwiz、keymgr 和 OpenProgram。
应用指南和卡片app 指南在发送时按 Windows 改写（_WINDOWS_GUIDE）；对组合键和粘贴（needsForeground(args, "windows")），审批卡片说明这一步会把窗口切到前台。

与 cua-driver 的关系

项
cua-drivercua-driver（trycua/cua，MIT）是和这些后端最接近的开源驱动：一个 Rust 运行时覆盖 macOS、Windows 和 Linux，可以通过 MCP（cua-driver mcp）调用，也可以用它的 Python SDK（cua_driver，UniFFI 封装的原生库）在进程内调用。
立场这些后端保留自己的代码，从它那里借鉴做法，而不是把它嵌进来：
项
送达macOS 的后台投递已经采用它的配方（macOS 投递），嵌入它不会改变点击送达的方式。
速度进程内 SDK 加载约 0.8 秒，窗口和 App 列表响应不到 10 毫秒，速度不是障碍。
体积与变动代价是体积和变动：macOS wheel 含 64 MB 库和 82 MB 可执行文件，该包在 0.x 经历了 40 多个小版本。
光标与遥测进程内运行时在 macOS 上不绘制 Agent 光标，且除非关闭否则发送产品遥测。
驱动之上这些后端调过的行为（稳定序号、找回被替换的元素、应用正忙、等待稳定、窗口标识、拒绝）在驱动之上，换不换都还是我们自己的。

cua-driver 能覆盖这些后端做不到的场景时，它是首选：Linux 后端拒绝 Wayland 会话，而 cua-driver 能在 Wayland 下驱动 Sway、niri、GNOME 和 KDE。把它用作 Wayland 下的 Linux 后端是计划中的采用方式（见实现状态）。

实现状态

状态范围
已实现Linux（X11）后端。测试在 Debian 12 容器里进行，环境是 Xvfb、Openbox、AT-SPI 总线和 PipeWire，对象是一个 GTK 3 窗口（菜单栏、输入框、密码框、复选框、滑块、带滚动的文本视图、绘图区、一个由子进程放声音的按钮）、GNOME 计算器（GTK 4 加 libadwaita，从桌面条目启动，靠元素点击算出 7×6）以及 ImageMagick 的 display（不接入 AT-SPI 的 Xt 客户端，靠 OCR 读取）。与主机无关的部分有单元测试。
已实现、尚未在 Windows 上运行上文所述的 Windows 后端。构建它的 macOS 机器没有 Windows 客户机，所以只有与主机无关的部分（PNG 编码、按键映射、HTML 剪贴板内容、开始菜单解析、控件类型表、拒绝列表、录音格式）有单元测试。
未实现经 Responses 和 Anthropic API 的音频输入（这两个接口的模型不收音频）；把窗口从另一个桌面空间移过来，以及用按键向它输入（macOS 投递）；从轮廓直接认出图标的名字（模型看截图分辨）。
