Computer use interface

Agent cursor

Item
Step pointBefore a step that names an element or a point, MacComputer.act computes where it lands (the element's centre from its AXPosition and AXSize, or the screenshot point mapped through the window origin and scale) and calls native_window.note_action_point, then waits CUE_LEAD_SECONDS (0.15 s) so the cursor arrives first.
Coordinate spaceThe point is in screen points with the origin at the top left of the main display, the space Electron also uses.
FrameThe worker broadcasts it as a native.action frame (session_id, x, y, sequence, at, action, app_name); an agentic subprocess forwards it through the same parent channel as operated windows (kind: "action").
Web clientIn the web client native-window-store.ts hands the frame to openprogramDesktop.nativeActionCue unless Show actions is off.
DrawingThe desktop main process (main/worker/agent-control.js) draws it in the conversation's control overlay: the cursor glides there and stays.
DeduplicationEvery App window receives the frame, so the main process drops a step it has already shown by session_id, sequence and at.
PlatformsLinux and Windows do not emit points yet.

Window marker

Item
MarkerThe operated window carries the macOS screen-sharing marker, as under Codex Computer Use: a badge over its title-bar buttons and the sharing icon in the menu bar. macOS draws both for any window under a live ScreenCaptureKit stream, so window_watch.WindowWatch keeps one open on it.
TouchMacComputer touches it with the window id, the app's name and the frame of its title-bar buttons (read through Accessibility) on every act and every get_state that names a window.
StreamThe stream filters to that one window (SCContentFilter.initWithDesktopIndependentWindow), asks for a 2x2 frame at one frame a second and attaches no output, so nothing is recorded.
ReleaseEach session watches at most one window: moving to another window releases the previous one, and a window with no step for IDLE_SECONDS (20 s) is released by a sweep timer.
FailureOpening the stream runs on its own thread and its failures are ignored, so a step never waits on or fails because of the marker.
Item
Place reportWhile a window is watched, a second thread reports its place every REPORT_SECONDS (0.12 s) when it changed: window_place reads the on-screen window list for the window's frame and the windows in front of it within GLOW_MARGIN (32 pt), leaving out windows titled OVERLAY_TITLE (the App's own overlays).
Control frameThe report goes through native_window.note_control with the owner captured when the window was touched, as a native.control frame (session_id, window_id, active, app_name, frame, buttons, occluders); a subprocess forwards it as kind: "control".
EndReleasing the window sends active: false.
Web client The web client passes reports to openprogramDesktop.nativeControl while Show actions is on, and always passes the end.
Overlay windowThe desktop main process keeps one transparent, click-through, unfocusable window per conversation over the window plus the margin and loads /menu-overlay/agent-control, which draws the inward glow, the accent lights over the buttons and the cursor.
StackingThe overlay sits in the window stack directly above the controlled window (moveAbove with its window id, ordered again on every report because the stack changes whenever the user switches apps), so a window in front of the controlled one also covers the overlay; only when the window server refuses that order does it float above all windows.
Covering windowsEither way covering windows are cut out of the glow and lights, and the cursor hides while its point lies under one.
LookIts look is set in Agent control overlay.

Web presentation

Item
Reading a calllib/computer-use/computer-use-agent-call.ts reads a computer_use_agent call: appStepArgs turns an app call into the flat step the app renderers take ({action, app, …}; several steps become a batch and code its own action), and screenStep names a browser or VM call's action.
App stepstool-presentation.ts renders app steps with the monitor icon and the system tone; the title names the action and the application ("Clicked in Calculator"), the target line shows the key, text, action name or window where one is given.
Other callsBrowser calls show the action and URL, VM calls the action, and code "Ran code in <app>". A conversation recorded while the tool could pass a task on shows that call as "Handed to a new agent" with the brief's first line.
Approval cardThe approval card's scope buttons add "Allow this conversation" between once and always, and the answer summary prints "Allowed for this conversation".
Old callsCalls recorded by the earlier tools (computer_use, web_use, gui_agent) keep their renderers so old conversations read.

Interface work

Item
Card headerThe approval card for an app call (computer-use-approval.tsx) leads with the application itself: its icon, display name and bundle id come from the computer_use_apps WebSocket action, which calls the backend's app_info and launches nothing, and the web caches them per name (lib/net/computer-use-apps.ts).
Card bodyBelow it a chip names the step in words (computer-use-step.ts), two lines state that the step runs in the background (or, for audio, that only that application's sound is recorded) and what the offered scopes cover, and the arguments without empty values fold into "Execution details".
Item
SectionThe project's Settings tab has a Computer use section (computer-use-apps-section.tsx) between the default settings and the permission rules.
RowsIt lists the project's computer_use_agent(<app>) allow rules (and those saved as computer_use(<app>)) as one row per application with icon, name, bundle id and a remove control, and the generic rule list leaves those rules out.
RemovingRemoving a row removes the rule.
Conversation grantsConversation-scoped grants are session rules that end with their conversation, so the section does not list them.

The person points the agent at things the way Codex lets them:

Item
Comment and regionIn a web tab, Comment on the page… picks one element and adds its selector, text and the comment to the draft; Screenshot a region… lets them drag a rectangle and adds those pixels as a PNG attachment.
Isolated worldBoth run in one isolated world (PICKER_WORLD in apps/desktop/main/web-views/web-views.js) that shares a cancel hook, so one mode ends the other.
Region overlayThe region overlay is removed and two frames are painted before capturePage takes the rectangle, scaled by the page zoom.
DeliveryThe file reaches the target conversation through lib/chat/composer-inbox.ts: the composer showing that conversation takes it as a dropped file, and it waits there until one does.
@ menuThe composer's @ menu lists open web tabs and running apps above the files (attach/mention/mention-sources.ts). A tab is written as a markdown link to its address and an app as its name and bundle id, so "this tab" resolves without the model guessing. Running apps come from computer_use_apps with running: true, which lists regular apps other than the refused ones and is kept for ten seconds in the page.
