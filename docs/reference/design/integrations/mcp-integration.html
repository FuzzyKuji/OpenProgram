MCP client integration

OpenProgram as MCP client: each tool of a server in mcp_servers.json becomes an ordinary AgentTool named {server}__{tool}. Exposing OpenProgram's own tools is the opposite direction: MCP server.

Call path

  • Awaited on the worker's event loop. A session-expired call reconnects and retries once.
  • Only the model starts these calls. programs run and the /programs page are for local functions.

Configuration

<state_dir>/mcp_servers.json, following the profile through paths.get_state_dir. A missing or unparsable file logs one warning; the worker starts with no servers.

{
  "servers": {
    "drawio": {
      "type": "local",
      "command": ["npx", "-y", "@drawio/mcp"],
      "env": {},
      "enabled": true,
      "timeout_seconds": 60
    }
  }
}

Credentials

Every value in env and headers is a secret, since any entry can hold one, alongside the bearer token and OAuth client secret.

PATCH /api/mcp/servers/{name}Effect
Name or whole field absentPreserve
Name with a valueReplace
Name with an empty stringDelete

Same rule for auth.token and auth.client_secret. Changing auth.kind drops the other kind's secret. The Web UI opens secret inputs empty and lists stored names only.

Startup and readiness

Successful connectionNamespaced tools and prompts become available
Shutdown during startupStartup cancelled and drained; clients, supervisors, callback resources and registrations released; no late registration
Owner deletes or disables a queued serverStays absent or disabled; no new process or tools; a management replacement wins over the startup snapshot
Owned OAuth callback cancelledSocket, thread and waiter released, no false code; normal code and state validation intact
Rules behind this
  • The server lifespan runs load_mcp_servers() as a managed background task; servers connect in order with their configured timeouts.
  • Each client is published in the registry before its connection is awaited: ready=false, no tools. The masked management API stays available.
  • Each queued server reads the current persisted configuration when reached.
  • Connecting lazily on first tool use is not done. Waiting for every connection is not done, since authentication may outlast the health deadline. Neither is another worker, changed owner timeouts, suppressed auth errors or a pending client marked ready.

Mechanisms

Tool names

adapter.namespace_tool_name(server, tool) replaces characters outside [A-Za-z0-9_-] with _ and truncates to 64, OpenAI's limit, keeping the tool suffix. Double underscore because OpenAI's name pattern rejects opencode's colon. On a collision the last registered wins.

Persistent connection and supervisor task

MCP is a long-lived bidirectional connection and the SDK exposes it as nested context managers. A supervisor asyncio.Task holds them open.

async def _supervisor(self):
    async with stdio_client(params) as (r, w):
        async with ClientSession(r, w) as session:
            await session.initialize()
            result = await session.list_tools()
            self._session = session
            self.tools = list(result.tools)
            self._ready.set()
            await self._shutdown.wait()
  • start() creates the task and waits on _ready; call_tool() reuses _session; stop() sets _shutdown and the subprocess closes.
  • A startup failure also sets _ready and records error; the manager skips registration and logs one line.
OAuth
  • Delegated to the SDK's OAuthClientProvider through PersistentOAuthProvider.
  • Persisted across restarts: tokens with absolute expires_at; the dynamic client registration, whose loopback port is reused so re-auth presents a registered redirect_uri; the discovered server metadata, so a cold-start refresh reaches the real token endpoint.
  • An expired token renews in the background. Browser consent runs only on first auth or a rejected refresh, surfaced as error_kind="needs_reauth".
  • The browser opens for consent only when someone connects the server, from the App or the CLI. When the worker connects its servers by itself, at startup or on its own reconnects (oauth_flow.unattended), the link stays in /api/mcp/auth/pending and no browser comes in front of what the user is doing.
