发现和执行各自计算 白名单 ∩ 实时注册表 ∩ paired 能力。身份限制最先生效：source=mcp 时，高风险工具、进程和 worktree 工具、根目录外写入一律拒绝，任何提问都不等待回答。

认证和传输

方面规则
令牌openprogram mcp token create 原子写入 <state_dir>/mcp_server_token（0600）并只打印一次。serve 从不生成令牌
校验openprogram mcp serve 在读取任何消息前，以恒定时间比较 OPENPROGRAM_MCP_TOKEN 和文件。没有关闭开关
失败非零退出，stdout 为空，stderr 固定为 Error: MCP server authentication failed
保密令牌不进入 JSON-RPC、日志、错误或会话内容
客户端身份凭据 SHA-256 的前 16 个小写十六进制字符。initialize.clientInfo 既不读取也不记录
权限固定 paired，绝不是 owner，和 Web owner 令牌相互独立
传输只有 stdio，继承启动进程的信任边界
协议锁定 mcp 1.30.0，协议 2025-11-25；由 SDK 协商版本，没有自定义握手字段
Streamable HTTP以后单独设计：需要 OAuth、Origin 校验和部署生命周期

权限决策和取消的内部机制
部分规则
权限顺序permission_decision：身份限制，然后所有者规则（deny、plan 只读限制、ask、外发暂扣、allow），最后模式。默认模式 bypass；子智能体沿用父级模式。见权限决策
工具包装wrap_with_approval 返回 execute 已加关卡的工具副本，外部调用方无法绕过
CancelToken每轮一个，绝不按会话（runtime/execution/run_control/tokens.py）。一轮结束后到达的停止不影响下一轮
全局钩子add_pre_invocation_hook、set_cancellation_check：每个 Agent 方法入口和每次 Runtime.exec 都会中止
统一入口只接受规范的 execution_id，先持久化意图，再唤醒所有者和待答提问。ACP、MCP、Channels、Web 共用一个 Control Service
is_errorAgentToolResult 和 AgentEventToolEnd 的一等字段；Runtime、审批、Agent 循环、MCP 转换和缓存判定都读取它。details 只放 reason_code、denied、timeout 等诊断。details["is_error"] 只是输入兼容桥

协议做法

主题同类做法
推送审批codex：执行和补丁审批用 elicitation/create，自定义字段 threadId、codex_elicitation、codex_mcp_tool_call_id、codex_event_id，返回 ReviewDecision。延迟低，要客户端支持 elicitation；载荷缺少 ElicitResult 的 action 和 content
拉取审批openclaw、hermes：permissions_list_open 和 permissions_respond，allow-once、allow-always、deny。通用客户端可用，代价是多一次往返和轮询。openclaw 还经 claude/channel/permission 推送
取消codex 在活动轮次注册表中查找轮次，tasks/cancel 报不支持。openclaw 把 extra.signal 传入 callTool。hermes 没有取消
进度codex 只记录 notifications/progress。调研的框架都不对外发标准进度
错误工具失败都返回 {isError: true, content:[text]}，协议失败用 JSON-RPC 错误。OpenProgram 采用这一区分
排除weclaw 的无认证发送和无条件批准 session/request_permission；opencode 未设 OPENCODE_SERVER_PASSWORD 时的无认证 serve

不在范围内

项目状态原因
ACP stdio 服务端已有，不扩展：openprogram acp、openprogram/interfaces/acp/server.py所有者权限和交互式权限语义；MCP 令牌、白名单、工具不并入
入站 webhook未实现到达时无所有者在场，和 cron 一样需要注册时固定的任务能力。最低控制（来自 hermes）：启动时校验的按路由 HMAC 密钥、限流、幂等缓存、读取前检查正文大小
客户端 SDK未实现标准 MCP SDK 就是客户端库。真实集成证明这些工具太粗时才需要专用 SDK；只有两条路由有固定形状断言
HTTP、SSE、OAuth、Web 路由、放宽 SDK 范围未实现对外接口保持带认证的 stdio 和这些工具
