Three gates on every tool_call

Discovery and execution each compute allowlist ∩ live registry ∩ paired capability. Identity limits come first: for source=mcp, risky tools, process and worktree tools, and out-of-root writes are always denied, and no question waits for an answer.

OwnerAuthMiddleware enforces Host and Origin, cookie or Bearer credentials, CSRF, no-store, and WebSocket authentication before accept, then grants full owner authority. Protocol approaches

TopicPeers
Push approvalcodex: elicitation/create for exec and patch, custom fields threadId, codex_elicitation, codex_mcp_tool_call_id, codex_event_id, returning ReviewDecision. Low latency, needs client elicitation; its payload lacks ElicitResult action and content
Pull approvalopenclaw, hermes: permissions_list_open and permissions_respond, allow-once, allow-always, deny. Works with generic clients, at a round trip and polling cost. openclaw also pushes through claude/channel/permission
Cancellationcodex looks up the turn in its active-turn registry, and tasks/cancel reports unsupported. openclaw passes extra.signal into callTool. hermes has none
Progresscodex only logs notifications/progress. No surveyed framework emits standard progress
ErrorsAll return {isError: true, content:[text]} for tool failure and JSON-RPC errors for protocol failure. OpenProgram adopts this
Excludedweclaw's unauthenticated send and unconditional session/request_permission approval; opencode's unauthenticated serve when OPENCODE_SERVER_PASSWORD is unset
