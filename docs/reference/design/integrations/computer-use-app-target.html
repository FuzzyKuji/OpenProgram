Application target

Shape

computer_use_agent(target="app", action, args={app, element_index | x,y, …})

Actions come in three groups:

Item
Readinglist_apps, list_windows, get_app_state (include = all / tree / screenshot, window or window_id), zoom (a region of the last screenshot at full pixel density), find (text and role search over the last tree).
Acting, Codex's target API: click (button, count, held modifiers, hold duration), type_text, press_key, set_value, scroll (pages or pixels), drag, perform_secondary_action, select_text, paste; and from the Claude app's app_* set: copy, focus, menu, show_window; and open_file (macOS).
Several steps(actions): up to 20 acting steps on one app, in order, stopping at the first error; one settle and one state at the end. A final get_app_state step chooses what that state is: the tree alone, the full tree, or another window.

Results and the tree

Only list_apps needs no grant. A step in actions cannot name a different app, because the grant the call carries names only the call's app.

Item
Acting resultEvery acting call returns Done: <summary> followed by the Accessibility tree diff against the state the model last saw: - line for elements that vanished, + index line for new or changed ones.
Whole treeWhen more than half the lines (and at least twelve) changed, the whole tree is returned instead, because a diff of a rebuilt view is longer than the view.
Full treeget_app_state(full=true) returns the full tree on demand.
RenderingThe tree is capped at 1500 nodes and rendered one element per line: index, role (AXTextField → text field, with the subrole in parentheses), label, value, placeholder, flags (focused, selected, checked, disabled, secure, settable …) and the element's secondary actions other than the primary press.
Bidirectional marksBidirectional marks some apps wrap numbers in are dropped from the rendering and from find.

The tree covers the window, the menus, popovers and dialogs beside it, and the menu bar with only open menus expanded. Closed menus are read by the menu action, so every read covers the same ground and a diff never shows a whole menu bar appearing or vanishing.

Results that changed nothing are marked: menu listings, copy and an already-visible show_window return a Report, and the tool returns it without settling or reading the state again.

Stable indices

Item
Basistree.number gives indices against the window's previous Snapshot (its index-free lines, their indices, and the next unused index).
Equal lineA line that is equal keeps its index.
Changed blockWithin a block of changed lines, a line with the same depth, role and label as an earlier one is that element with a new value or state and keeps its index wherever the block moved it, so lines added above it do not take its place; what is left pairs in place when depth and role hold (a renamed button).
New lineAny other new line takes the next unused index, and indices freed by removed elements are never reused.
GuaranteeThe model's earlier indices therefore never point at a different element after an insertion above them, which Codex's positional numbering does not guarantee.

Replaced elements

Item
CauseApps, web pages above all, rebuild their accessibility elements while the window still shows the same controls, on their own or after another agent's step.
Dead elementThe element the backend kept from the last read is then dead although its line is still there.
Detection_element in each backend detects that, reads the same window again and matches it with tree.rebind: the fresh tree is numbered against what the model last saw, and the index is taken while its line reads the same, or keeps its depth, role and name (label or placeholder).
StepThe step then runs on the live element.
Still failsAn unnamed control that changed, a line that is gone and a window that closed still fail with "element N no longer exists", before any input.
Last viewThe model's last view (WindowState.snapshot) is kept through the repair, so the state returned after the step reports everything that changed since that view.

One agent at a time

Item
ScopeAgents of one conversation (the main turn and the agents it starts) each keep their own reading of a window, and the window is one.
Holdtargets/app.py holds the application for the length of a call: a single action with its settle and state, a list of actions, or a get_app_state.
WaitingAnother agent's call on that application waits, polling with cancellation checks, and after APP_WAIT_SECONDS (60 s) fails with nothing sent (action_dispatched: false).
IdentityThe application is the backend's identity for it where it has one (app_key, the bundle id on macOS, so a name, a bundle id and a path are one application), else the name as written.
Other agentsEach application records its acting calls with the agent that made them; a result starts with a note when another agent acted since this agent's last result, and the changes it lists include theirs.
No holdRead-only calls take no hold: list_apps, list_windows, zoom, find.
Code stepsCode steps hold the application one step at a time.

Settling

After an action the tool polls a cheap fingerprint of the first 400 elements every 0.2 seconds, starting after 0.3 seconds, and stops when two fingerprints agree, after 1.5 seconds, or after 5 seconds while a busy indicator or an unfinished progress indicator is present — Codex's "about a second, up to five while loading".

Menu bar

Item
Pathmenu walks AXMenuBar by title, case-insensitively and ignoring a trailing … or ....
ListingA path that ends at a submenu lists its items with shortcut glyphs (⌃⌥⇧⌘ from AXMenuItemCmdModifiers), [checked] and [disabled]; a leaf is pressed with AXPress.
Side effectReading the menu tree through Accessibility opens nothing on screen.
copycopy presses the app's own menu item whose shortcut is ⌘C, found by shortcut rather than by its localized title, and falls back to posting ⌘C; when that item exists but is disabled (nothing selected, or focus on a control) it reports so at once.
PasteboardOtherwise it waits for the pasteboard change count, reads the string, and restores the previous pasteboard.
Item
No prior statecopy, press_key, type_text and paste without an element_index act on the app's current focus and need no earlier get_app_state; menu, show_window and wait never need one.
hover and waitFrom Claude's computer-use tool come hover (three mouseMoved events posted to the process, approaching the point, then a 0.8-second rest; the real cursor stays put) and wait (up to 10 seconds, cancellable, followed by the usual settle and tree diff).
focusfocus sets AXFocused and waits up to half a second for the app to report it, since apps apply focus on a later run-loop turn.
Item
ScreenshotThe screenshot is the window's own image captured through ScreenCaptureKit, scaled so the long side is at most 1568 pixels; coordinates the model sends are pixels of that image.
CoordinatesA step maps them to screen points with the scale that produced the image (2 on a Retina display, less when a large window was captured smaller) and the window's origin as the window server reports it at that moment (screen_point, after _follow_window), so a window the user moved since the read is still hit where the model pointed.

Text on the screenshot

Item
Sparse windowA window whose own walk yields fewer than 12 elements (frame, title bar buttons and little else) is drawn without Accessibility.
RecognitionFor such a window every full or screenshot-only read also runs Vision's accurate text recognizer on the screenshot it just took and lists each line as "text" at (cx, cy), WxH in screenshot pixels, top to bottom and left to right, at most 150 lines.
LanguagesThe first recognition language picks Vision's model, so the languages are a hint (the user's preferred languages, then Chinese, Japanese, Korean and English) and language detection chooses per image.
find fallbackfind with text falls back to these lines when no element matches; for a window that was not sparse it captures and reads the window once at the same scale, so the positions stay valid for actions.
Not in the treeOCR text has no indices and is not part of the tree diff: it is evidence for coordinate actions, and a failure of the recognizer leaves the read without it.
ShapesThe same reads list icons and controls without text (ocr.detect_shapes): Vision's contour detector runs twice, once for dark marks on a light window and once for light on dark, at most 1024 pixels on the long side.
Merging and droppingTop-level outlines within 3 points of each other merge into one shape, and a shape is dropped when it covers a recognized line of two or more characters, is under 8 points on its short side, over 80 points on its long side, more than 4:1, or touches the screenshot's edge (the window's rounded corners and border).
One characterA one-character line does not rule a shape out, because the recognizer often reads an icon as a glyph.
OrderShapes the two passes both find are kept once, and the list is sorted in 16-point rows, left to right, at most 60.
No nameA shape carries no name: the model reads the screenshot to tell a gear from a trash can.

Audio

Item
CodexCodex records computer audio with start_audio_recording / stop_audio_recording (60 seconds by default, 300 at most) and hands the clip to the model as audio input.
KeptOpenProgram keeps the two actions and their limits.
ClipThe clip becomes a WAV on disk plus a transcript from the Settings → Voice engine, which every model can read.
Content blockToolReturn.audio also carries the WAV as an AudioContent block.
Audio inputWhen the model lists audio among its inputs, the Gemini converter passes it as inline audio and the Chat Completions converter as input_audio, each in a user turn after the run of tool results, which must stay together.
Chat CompletionsThat Chat Completions turn also carries the run's screenshots for vision models, since a tool message holds only text.
Other convertersThe Responses and Anthropic converters skip audio blocks, and tool-result media is not written to the conversation history, so the clip costs nothing for models that cannot hear it.
Captureaudio.py opens an SCStream whose filter is the display with only the target application included, asks for 16 kHz mono float samples, excludes the OpenProgram process, and attaches only an audio output: the 2×2, one-frame-a-second video side is never consumed.
LimitSamples past the limit are dropped and a timer stops the stream half a second after it, so a forgotten recording releases the capture.
StorageOne recording runs per conversation; it is converted to 16-bit PCM on stop and saved under the state directory, keeping the newest 20.
ApprovalThe action keeps the per-application approval: only the named app's sound is in the clip.
SilenceA clip whose peak stays under 1e-4 is reported silent and not transcribed.
No windowAn application without a window has no SCRunningApplication and cannot be recorded.
