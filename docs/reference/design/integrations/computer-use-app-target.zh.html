应用目标

形态

computer_use_agent(target="app", action, args={app, element_index | x,y, …})

动作分三组：

项
读取list_apps、list_windows、get_app_state（include = all / tree / screenshot，window 或 window_id）、zoom（以完整像素密度查看上一张截图的一块区域）、find（在上一棵树里按文字和角色查找）。
执行，即 Codex 的目标 API：click（按钮、次数、按住的修饰键、按住时长）、type_text、press_key、set_value、scroll（按页或按像素）、drag、perform_secondary_action、select_text、paste；以及来自 Claude App app_* 一组的 copy、focus、menu、show_window；还有 open_file（macOS）。
多个步骤（actions）：对同一个应用按顺序执行至多 20 个执行类步骤，遇到第一个错误即停止；最后只等待稳定一次、只返回一次状态。

结果与元素树

只有 list_apps 不需要授权。actions 里的步骤不能指定别的应用，因为这次调用携带的授权只点名调用本身的应用。

项
动作结果每个执行动作的调用返回 Done: <摘要>，后面跟 Accessibility 树相对模型上次所见状态的 diff：- 行 是消失的元素，+ 序号 行 是新增或变化的。
整棵树变化行数超过一半（且至少十二行）时改为返回整棵树，因为重建后视图的 diff 比视图本身还长。
完整树get_app_state(full=true) 按需返回全树。
渲染树上限 1500 个节点，每元素一行：序号、角色（AXTextField → text field，子角色放括号里）、标签、值、占位符、标记（focused、selected、checked、disabled、secure、settable……）以及除主按压之外的次级动作。
双向标记有些应用给数字包上的双向文字标记会从渲染和 find 中去掉。

树覆盖窗口、它旁边的菜单、弹出框和对话框，以及只展开已打开菜单的菜单栏。未打开的菜单由 menu 动作读取，所以每次读取的范围一致，diff 里不会出现整条菜单栏凭空出现或消失。

没有改变任何东西的结果会被标记：menu 的列表、copy 和窗口本已可见时的 show_window 返回 Report，工具直接返回它，不等待稳定，也不再读取状态。

稳定序号

项
依据tree.number 参照窗口上一次的 Snapshot（不含序号的各行、它们的序号和下一个未用序号）分配序号。
相同的行相同的行保留原序号。
变化的块在一块变化的行里，深度、角色和标签都与先前某行相同的行，就是那个元素换了值或状态，不论这一块把它挪到哪里都保留原序号，所以它上方新增的行不会占它的位置；剩下的行在深度和角色不变时按原位配对（按钮改名）。
新行其他新行取下一个未用序号，被移除元素释放的序号永不复用。
保证因此模型先前拿到的序号在其上方插入新元素后也不会指向别的元素——Codex 按位置编号做不到这一点。

被替换的元素

项
原因应用（尤其是网页）会在窗口显示的控件不变的情况下重建自己的辅助功能元素，可能是自己重绘，也可能是另一个 agent 的操作引起的。
失效元素后端从上次读取留下的元素这时已经失效，而它那一行还在。
检测各后端的 _element 发现这种情况后重新读取同一个窗口，用 tree.rebind 对上：新树参照模型上次看到的内容编号，只要该序号的那一行读起来没变，或者深度、角色和名字（标签或占位符）没变，就采用它，步骤在活的元素上执行。
执行然后步骤在活元素上运行。
仍然失败没有名字又变了的控件、已经消失的行、已经关闭的窗口，仍然在任何输入之前以 “element N no longer exists” 失败。
最后视图修复过程中保留模型上次的视图（WindowState.snapshot），所以步骤之后返回的状态仍然报告自那次视图以来的全部变化。

同一时间只有一个 agent

项
范围同一对话里的 agent（主回合和它启动的 agent）各自保存对窗口的读取，而窗口只有一个。
占用targets/app.py 在一次调用期间占住这个应用：单个动作连同它的等待稳定和状态、一串动作，或一次 get_app_state。
等待别的 agent 对这个应用的调用会等待，等待时轮询并检查取消，超过 APP_WAIT_SECONDS（60 秒）则失败且不发送任何输入（action_dispatched: false）。
身份应用以后端给它的身份为准（app_key，macOS 上是 bundle id，所以名字、bundle id 和路径指的是同一个应用），没有时用写下的名字。
其他 agent每个应用记录对它的操作类调用以及是哪个 agent 做的；自这个 agent 上次的结果以来有别的 agent 操作过时，结果开头会注明，它列出的变化包含对方的改动。
不占用list_apps、list_windows、zoom 和 find 不占用。
代码步骤代码里的步骤每一步占用一次。

等待稳定

动作之后，工具从 0.3 秒起每 0.2 秒对前 400 个元素取一次轻量指纹，两次指纹一致即停止；最多 1.5 秒，存在忙碌指示器或未完成的进度指示器时最多 5 秒——对应 Codex 的"约一秒，加载时最多五秒"。

菜单栏

项
路径menu 按标题遍历 AXMenuBar，不分大小写，忽略末尾的 … 或 ...。
列出路径停在子菜单时列出其菜单项，带快捷键符号（由 AXMenuItemCmdModifiers 得到 ⌃⌥⇧⌘）、[checked] 和 [disabled]；末端项用 AXPress 按下。
副作用经 Accessibility 读菜单树不会在屏幕上打开任何东西。
copycopy 按下应用自己快捷键为 ⌘C 的菜单项——按快捷键而非本地化标题查找——找不到时退回发送 ⌘C；该菜单项存在但被禁用（没有选区，或焦点在控件上）时立即如实报告。
剪贴板否则它等待粘贴板的 change count 变化，读出字符串，再恢复先前的粘贴板。
项
无需先读状态不带 element_index 的 copy、press_key、type_text 和 paste 作用于应用当前的焦点，不需要先 get_app_state；menu、show_window 和 wait 从不需要。
hover 和 wait来自 Claude computer-use 工具的有 hover（向进程投递三个逐步接近目标点的 mouseMoved 事件，再停留 0.8 秒；真实光标不动）和 wait（最多 10 秒，可取消，之后照常等待稳定并返回树 diff）。
focusfocus 设置 AXFocused 并最多等半秒让应用报告它，因为应用会在之后的 run loop 轮次才应用焦点。
项
截图截图是经 ScreenCaptureKit 抓取的窗口自身图像，缩放到长边至多 1568 像素；模型发来的坐标是这张图上的像素。
坐标每一步用生成截图的比例（Retina 屏为 2，大窗口按更小比例抓取时更小）和窗口服务器此刻报告的窗口原点把它换算成屏幕点（先 _follow_window，再 screen_point），所以用户在读取之后移动过窗口，点击仍落在模型指的位置。

截图上的文字

项
稀疏窗口窗口自身遍历出的元素少于 12 个（窗框、标题栏按钮之外几乎没有）时，说明它绕开了辅助功能自行绘制。
识别对这样的窗口，每次完整读取或仅截图读取都会对刚拍下的截图运行 Vision 的精确文字识别，把每行列成 "text" at (cx, cy), WxH，单位是截图像素，按从上到下、从左到右排列，最多 150 行。
语言识别语言列表的第一项决定 Vision 用哪个模型，所以语言只作提示（用户首选语言，然后是中文、日文、韩文和英文），由语言检测按每张图选择。
find 回退find 带 text 时，若没有元素匹配就退回到这些文字行；对不稀疏的窗口，它会以相同比例重新抓取并识别一次，因此位置对动作仍然有效。
不进树OCR 文字没有序号，也不进入树的 diff：它是坐标动作的依据，识别器失败时读取结果里就不带它。
形状同样的读取还会列出不带文字的图标和控件（ocr.detect_shapes）：Vision 的轮廓检测跑两遍，一遍找浅色窗口上的深色图形，一遍找深色上的浅色，长边最多 1024 像素。
合并与丢弃相距 3 点以内的顶层轮廓合并成一个形状；形状盖住两个字符以上的识别文字行、短边小于 8 点、长边大于 80 点、长宽比超过 4:1，或贴着截图边缘（窗口的圆角和边框）时丢弃。
单字符单字符的文字行不排除形状，因为识别器常把图标读成一个字。
顺序两遍都找到的形状只保留一次，按 16 点一行、从左到右排序，最多 60 个。
无名称形状没有名字：模型对照截图分辨齿轮和垃圾桶。

音频

项
CodexCodex 用 start_audio_recording / stop_audio_recording 录电脑声音（默认 60 秒，最多 300 秒），并把录音作为音频输入交给模型。
保留OpenProgram 保留这两个动作及其上限。
片段录音落成磁盘上的 WAV，再加上设置 → 语音引擎给出的转写文字，任何模型都能读。
内容块ToolReturn.audio 还把 WAV 作为 AudioContent 块带上。
音频输入模型的输入模态里有 audio 时，Gemini 转换器把它作为内联音频、Chat Completions 转换器把它作为 input_audio，放在那组工具结果之后的用户轮里（工具结果必须连在一起）。
Chat Completions由于 tool 消息只能放文字，Chat Completions 的这个用户轮也为视觉模型带上那组结果里的截图。
其他转换器Responses 和 Anthropic 转换器跳过音频块，工具结果里的媒体也不写进对话历史，所以对听不了音频的模型没有额外开销。
采集audio.py 打开一个 SCStream，过滤器是只包含目标应用的显示器，要求 16 kHz 单声道 float 采样，排除 OpenProgram 自身进程，并只挂音频输出：2×2、每秒一帧的视频那一侧从不被消费。
上限超过上限的采样被丢弃，计时器在上限后半秒停掉流，所以忘了停止的录音也会释放采集。
存储每个对话同时只有一段录音；停止时转成 16 位 PCM 并保存在状态目录下，保留最新的 20 个。
审批这个动作沿用按应用的审批：录音里只有所指定应用的声音。
静音峰值始终低于 1e-4 的录音报告为静音，不做转写。
无窗口没有窗口的应用没有 SCRunningApplication，无法录音。
