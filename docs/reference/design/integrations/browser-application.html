Browser application

The built-in browser is the application openprogram/programs/applications/browser/. The core never imports it: the application's setup(ctx) provides the service browser, and every core caller looks it up with _services.lookup("browser") and runs without a browser when the lookup returns None.

ModuleRole
__init__.pysetup: provides the service and registers the L2 context section pages. The application registers no tool
service.pyBrowserService, the service's members (below)
pages.pyBrowserResourceStore, per-conversation Page projections, resource control, human page input
tabs.pythe tab driver for computer_use_agent(target="browser")
extension.pythe user's Chrome or Edge through the Playwright Extension
page_actions.py, file_inputs.pyargument parsing and page scripts the two above share; the approved local file an upload sends
app_endpoint.py, privacy.pythe App's CDP endpoint; password-value redaction
prompt.pythe open-Pages section of a call's prompt

The Agent operates the browser with one tool, computer_use_agent(target="browser"): the App's tabs through the tab driver, the user's Chrome or Edge through the extension. Its actions are in Browser tab actions.

The service's members are pages, tabs, chrome, extension, user_browser_names, open_tab(url), authorized_page(arguments, window_id) and browser_of().

A Program's web tabs

Item
Opentabs.openWebTab of the framework interface calls open_tab(url): the tab opens in the background for the running conversation, as open of the browser target does.
ActA native presentation command on a web tab names it with arguments.tab, the tab's id from tabs (omitted: the tab the conversation used last). authorized_page checks it against the App's current window and binding and sends the App its own tab id.
AuthorityBoth need what computer_use_agent needs: a turn that may not use the screen tool may not reach a web tab this way either.
