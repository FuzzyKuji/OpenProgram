Browser application

The built-in browser is the application openprogram/programs/applications/browser/. The core never imports it: the application's setup(ctx) provides the service browser, and every core caller looks it up with _services.lookup("browser") and runs without a browser when the lookup returns None.

The web_use runtime

web_use is the application's one registered entry. Programs and MCP clients call it directly; the browser target of computer_use_agent uses the tab driver instead.

Names. Agents and MCP see one tool, web_use; sessions are web_session_id in a WebUseSessionRegistry. The HTTP route is /api/web-use; /api/computer-use remains a hidden compatibility route on the same handler, kept out of OpenAPI, and old computer_session_id request fields are converted to the new ones.

Five commands

CommandWhat it does
list_pageslists the Pages of every registered OpenProgram window, each with a single-use page_context_token
observeselects a Page by token, opens a WebSession and returns bounded text, ARIA and element refs
actperforms one navigate, click, type, press, scroll, hover or select against the latest expected_frame_id
verifyruns a Runtime assertion (text_contains, title_contains, url_contains and so on); a model's claim of completion never makes a result succeeded
closecloses the observed Page's tab and releases its WebSession, Page binding and held capabilities
 
web_use({ command: "list_pages" })
web_use({ command: "observe", page_context_token: "pct_…", arguments: { detail: "interactive" } })
web_use({ command: "act", web_session_id: "cs_…", arguments: { action: "click", expected_frame_id: "f_…", ref: "e1" } })
web_use({ command: "verify", web_session_id: "cs_…", arguments: { action: "verify", expected_frame_id: "f_…", assertion: "text_contains", value: "Saved" } })
web_use({ command: "close", web_session_id: "cs_…" })

Page inventory

Item
Replylist_pages returns windows[], one snapshot per registered window with its window_id, inventory_revision, active_tab_entry_id, focused_page and tab_entries, and a flattened pages list.
Tab entryA tab entry is one item in the top tab bar: single holds one Page, split two ordered panes (tab:<tab_id> and group:<CenterTabGroup.id>).
PageEach Page carries its window_id, tab_id, tab_entry_id, placement, title, origin, visible, focused, an optional opener_tab_id and its token.
Pane orderPane order follows the rendered order; left and right derive from actual geometry and are never Page identity.
Inventory revisionGrouping, reordering or resizing increments inventory_revision without changing a Page.
PopupA popup becomes its own tab and Page with opener_tab_id; it never rebinds the opener's session, and the caller picks it up on the next list_pages.
No Desktop windowWhen no Desktop window is registered, as after a worker or App restart, discovery waits up to DESKTOP_RECONNECT_WAIT_SECONDS (20 s) and then returns desktop_unavailable with retry_command=list_pages.

Binding and revisions

Item
TokenA token binds the caller's owner, the window, the exact CDP target and the server's page and access revisions; missing, replayed, cross-owner or replaced-target tokens are refused before any backend call.
Geometry revisionEach visible web tab also carries a renderer-owned geometry_revision that changes with its in-App bounds or visibility (not with focus, and not with macOS stacking, occlusion or minimization).
ComparisonThe WebSession stores all three revisions, the worker compares page and access, and the exact renderer compares geometry before native activation; any mismatch returns page_context_stale without touching the backend.
LeaseWrites to one Page hold an exclusive lease; different Pages run concurrently.
Background PagesBackground Pages resolve their target directly, with no tab switch, window focus, bringToFront() or OS input.
LocationThe inventory, WebSession registry and renderer WebSocket registry run in the worker's main process; a workflow subprocess reaches the same WebSession through the parent bridge, which forwards revisions unchanged.

Owners and cleanup

Item
OwnerA chat turn's owner is its session and assistant turn.
ReleaseNormal return, retry, cancellation and exceptions release every WebSession, Page lease and binding the owner holds, whether or not the model called close.
DisconnectA disconnected owner WebSocket revokes all its bindings at once.
closeExplicit close checks the owner and live binding, asks the App to close the tab and then releases the session; a foreign owner closes nothing.

Tokens and recovery

Item
Reuseact or verify with a token and no live web_session_id reuses the WebSession that token opened; with an unused token the runtime first observes read-only, and navigate, screenshot, wait and ref-free verify continue on that frame, while ref or coordinate actions return the observation with action_performed=false.
MemoryThe registry remembers, bounded and in memory, the tabs of WebSessions that ended and of tokens that expired.
HintsA later page_context_not_found, page_context_consumed or web_session_not_found from the same owner scope carries recovery_tab_id, recovery_window_id and recovery_command=observe; the agent tool then observes that tab with a fresh token and returns recovered_page=true, previous_action_replayed=false.
ReplayNothing is replayed.
Next callEvery recoverable failure names exactly one next call.

Backends

Item
Choiceobserve picks one of three backends and freezes it for the WebSession: playwright_mcp (default, pinned @playwright/mcp), chrome_devtools_mcp (pinned chrome-devtools-mcp) or open_claude_chrome (OpenProgram's own Electron/CDP controller that follows the Open Claude in Chrome tool contract, with no extension or native host).
MismatchA later request for another backend returns backend_mismatch; failures, timeouts and stale frames never fall back to another backend, so one action writes at most once.
ProcessEach official-MCP WebSession owns a private MCP process started with npx --prefer-offline, bound to the exact target with tab selection disabled.
RestartIf that process stops, the next observe restarts it read-only; act never writes through a restarted process and returns computer_use_backend_unavailable with observe_required=true.
ParityAll three run one parity matrix through WebUseSessionRegistry.execute(): the same results, frame invalidation, reason codes and verification semantics.

Frames and failures

Item
After a writeEvery successful write invalidates the frame and sets observe_required=true.
FailuresMissing arguments return invalid_arguments with the complete missing_arguments list and leave a valid observation in place; an old frame returns stale_observation; an unknown action returns unsupported_action; a backend error returns backend_action_failed.
Reason codesReason codes (page_context_stale, page_access_disabled, target_lost, page_in_use, ref_not_found, timeout, cancelled among them) come from the runtime; backend text never overrides them.

Cost

Item
ObservationObservation is DOM and ARIA first: URL, title, text, snapshot and refs, without screenshots.
Screenshotscreenshot returns one current-viewport PNG, taken from the exact Page's CDP session, for canvas pages or failed semantic location.
Image lifetimeThe image goes only to the next provider request; tool text, the DAG and final results keep only frame_id, the viewport and image_attached, and normal return, provider errors, timeouts and cancellation all clear the image and revoke coordinate permission.
Not runNo OCR, object detection, crop and zoom, visual memory or workflow replay runs.
Page contentPage content is untrusted data that cannot change targets or permissions.

Agent cursor

Item
CursorDuring an agent click, all three backends arm a capture listener in the exact Page only; a real pointer event shows a text-free, aria-hidden, pointer-events: none cursor and ripple at the viewport point, which then fades.
IsolationUser clicks, other Pages and the OS mouse are untouched, and a feedback failure never changes the click's result.
