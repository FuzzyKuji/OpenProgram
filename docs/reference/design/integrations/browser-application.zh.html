浏览器应用

内置浏览器是应用 openprogram/programs/applications/browser/。核心从不 import 它：应用的 setup(ctx) 提供服务 browser，核心里每个调用方都用 _services.lookup("browser") 查找它，查找返回 None 时就在没有浏览器的情况下运行。

模块作用
__init__.pyPROGRAM_ENTRIES（web_use）和 setup：提供服务，注册 L2 上下文段 pages 和资源 provider web
service.pyBrowserService，即服务的成员（见下）
pages.pyBrowserResourceStore、按对话的 Page 投影、资源控制、人的页面输入
tabs.pycomputer_use_agent(target="browser") 的标签页驱动
extension.py经 Playwright Extension 操作用户的 Chrome 或 Edge
chrome.py、privacy.pyopenprogram browser 维护的 Chrome 引导；隐私过滤
contract.pyagent 和 MCP 共用的 web_use 参数契约
prompt.py一次调用的 prompt 里关于已打开 Page 的段落
resource.py资源 provider web，以及原生展示命令用的 Page 租约
web_use/web_use 运行时：页面控制器、会话及其注册表、恢复、精确页面 MCP 后端
engine/页面控制器驱动的 Playwright 动作引擎

服务的成员是 pages、tabs、chrome、extension、user_browser_names、web_use_parameters()、normalize_web_use_arguments()、execute_direct_web_use(arguments, owner_id=)、registry()、release_owner()、park_owner()、authorized_page() 和 browser_of()。

调用方无服务时
调用提示词没有 Pages 部分；该轮没有 web_use
web_use 参数校验失败，提示 “the browser is not enabled”
MCP不列出 web_use 并拒绝其调用
/api/web-use返回 browser_not_enabled
进程路由不列浏览器资源；浏览器控制返回 404
Web 标签桥跳过 Page 记录
computer_use_agent(target="browser")报告目标不可用；桌面目标继续工作
权限策略看不到用户浏览器

web_use 运行时

web_use 是这个应用唯一注册的入口。程序和 MCP 客户端直接调用它；computer_use_agent 的 browser 目标则改用标签页驱动。

名字。 agent 和 MCP 只看到一个工具 web_use；会话是 WebUseSessionRegistry 里的 web_session_id。HTTP 路由是 /api/web-use；/api/computer-use 作为隐藏的兼容路由保留，共用同一个处理函数，不出现在 OpenAPI 里，旧的 computer_session_id 请求字段会被换成新字段。

五个命令

命令作用
list_pages列出所有已注册 OpenProgram 窗口的 Page，每个 Page 带一个一次性的 page_context_token
observe按 token 选中 Page、打开 WebSession，返回有界的文本、ARIA 和元素 ref
act针对最新的 expected_frame_id 执行一次 navigate、click、type、press、scroll、hover 或 select
verify执行运行时断言（text_contains、title_contains、url_contains 等）；模型声称完成永远不会让结果变成 succeeded
close关闭所观察 Page 的标签页，释放它的 WebSession、Page 绑定和持有的能力
 
web_use({ command: "list_pages" })
web_use({ command: "observe", page_context_token: "pct_…", arguments: { detail: "interactive" } })
web_use({ command: "act", web_session_id: "cs_…", arguments: { action: "click", expected_frame_id: "f_…", ref: "e1" } })
web_use({ command: "verify", web_session_id: "cs_…", arguments: { action: "verify", expected_frame_id: "f_…", assertion: "text_contains", value: "Saved" } })
web_use({ command: "close", web_session_id: "cs_…" })

Page 清单

项
回复list_pages 返回 windows[]（每个已注册窗口一份快照，含 window_id、inventory_revision、active_tab_entry_id、focused_page 和 tab_entries）以及展平的 pages 列表。
标签条目tab entry 是顶部标签栏里的一项：single 含一个 Page，split 含两个有序 pane（tab:<tab_id> 与 group:<CenterTabGroup.id>）。
Page每个 Page 带 window_id、tab_id、tab_entry_id、placement、标题、origin、visible、focused、可选的 opener_tab_id 和它的 token。
窗格顺序pane 顺序跟随实际渲染顺序；左右由实际几何推出，从不是 Page 身份。
清单修订号分组、重排或调整大小会递增 inventory_revision，不改变 Page。
弹窗弹窗成为独立的标签页和 Page，带 opener_tab_id；它从不重绑 opener 的会话，调用方在下一次 list_pages 时发现它。
无 Desktop 窗口没有已注册的 Desktop 窗口时（例如 worker 或 App 重启后），发现过程最多等待 DESKTOP_RECONNECT_WAIT_SECONDS（20 秒），然后返回 desktop_unavailable 和 retry_command=list_pages。

绑定与修订号

项
Tokentoken 绑定调用方 owner、窗口、精确的 CDP target 以及服务端的 page 与 access 修订号；缺失、重放、跨 owner 或 target 已替换的 token 在调用任何后端之前就被拒绝。
几何修订号每个可见的网页标签页还带一个由 renderer 维护的 geometry_revision，随它在 App 内的边界或可见性变化（不随焦点变化，也不随 macOS 的层叠、遮挡或最小化变化）。
比较WebSession 保存这三个修订号，worker 比较 page 与 access，精确的 renderer 在原生激活前比较 geometry；任何不一致都返回 page_context_stale，不触碰后端。
租约对同一 Page 的写入持有独占租约；不同 Page 可以并发。
后台 Page后台 Page 直接解析 target，不切换标签页、不聚焦窗口、不调用 bringToFront()、不产生 OS 输入。
位置清单、WebSession 注册表和 renderer WebSocket 注册表运行在 worker 主进程；workflow 子进程经父进程桥访问同一个 WebSession，修订号原样转发。

Owner 与清理

项
Owner对话 turn 的 owner 是它的会话和 assistant turn。
释放正常返回、重试、取消和异常都会释放该 owner 持有的所有 WebSession、Page 租约和绑定，无论模型有没有调用 close。
断开owner 的 WebSocket 断开会立即撤销它的所有绑定。
close显式 close 先检查 owner 和存活绑定，请 App 关闭标签页，再释放会话；别的 owner 什么也关不掉。

Token 与恢复

项
复用带 token 而没有存活 web_session_id 的 act 或 verify 复用该 token 打开过的 WebSession；token 未用过时，运行时先做一次只读 observe，navigate、screenshot、wait 和不带 ref 的 verify 在这个 frame 上继续，而 ref 或坐标动作返回观察结果和 action_performed=false。
记忆注册表在内存里有界地记住已结束 WebSession 的标签页和已过期 token 的标签页。
提示之后同一 owner 范围里出现的 page_context_not_found、page_context_consumed 或 web_session_not_found 会带上 recovery_tab_id、recovery_window_id 和 recovery_command=observe；agent 工具随后用新 token 观察那个标签页，返回 recovered_page=true、previous_action_replayed=false。
重放不重放任何操作。
下一次调用每个可恢复的失败都恰好指明下一步调用。

后端

项
选择observe 从三个后端中选一个，并在该 WebSession 内固定：playwright_mcp（默认，固定版本的 @playwright/mcp）、chrome_devtools_mcp（固定版本的 chrome-devtools-mcp）或 open_claude_chrome（OpenProgram 自己的 Electron/CDP 控制器，遵循 Open Claude in Chrome 的工具契约，不运行扩展或 native host）。
不匹配之后请求别的后端返回 backend_mismatch；失败、超时和过期 frame 从不回退到另一个后端，因此一个动作最多写一次。
进程每个官方 MCP 的 WebSession 拥有一个用 npx --prefer-offline 启动的私有 MCP 进程，绑定到精确 target，禁用标签页选择。
重启这个进程停止后，下一次 observe 以只读方式重启它；act 从不经重启过的进程写入，而是返回 computer_use_backend_unavailable 和 observe_required=true。
一致性三个后端经 WebUseSessionRegistry.execute() 跑同一张一致性矩阵：结果、frame 失效、reason code 与验证语义都相同。

Frame 与失败

项
写之后每次成功写入都会让 frame 失效并设置 observe_required=true。
失败缺参数返回 invalid_arguments 和完整的 missing_arguments，保留仍有效的观察；旧 frame 返回 stale_observation；未知动作返回 unsupported_action；后端错误返回 backend_action_failed。
原因码reason code（包括 page_context_stale、page_access_disabled、target_lost、page_in_use、ref_not_found、timeout、cancelled）由运行时产生，后端文本从不覆盖它们。

成本

项
观察观察以 DOM 和 ARIA 为先：URL、标题、文本、快照和 ref，不截图。
截图screenshot 从精确 Page 的 CDP 会话取一张当前视口 PNG，用于 canvas 页面或语义定位失败时。
图片生命周期图像只进入下一次 provider 请求；工具文本、DAG 和最终结果只保留 frame_id、视口和 image_attached，正常返回、provider 错误、超时和取消都会清除图像并撤销坐标权限。
不运行不运行 OCR、目标检测、裁剪放大、视觉记忆或 workflow 回放。
页面内容页面内容是不可信数据，不能改变目标或权限。

Agent 光标

项
光标agent 点击期间，三个后端只在精确 Page 里挂一个捕获监听；真实的指针事件会在视口坐标处显示一个无文字、aria-hidden、pointer-events: none 的光标和波纹，随后淡出。
隔离用户点击、其他 Page 和 OS 鼠标不受影响，反馈失败也不会改变点击结果。
