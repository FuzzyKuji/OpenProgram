浏览器标签页动作

读取

项
快照read 返回 Playwright 的 AI 快照：ARIA 树，每个元素带一个 ref（e12，框架内为 f1e3）。
Playwright 版本Playwright 1.60 以 Frame.ariaSnapshot(mode="ai", track) 提供它，返回一段文本：同一文档已有被跟踪的快照时是增量；更早的版本以 Page.snapshotForAI 提供，两者一并返回。
全量或增量文档是新的或需要整页时，驱动请求整页，否则只请求变化。
标记变化的行标为 <changed>，[unchanged] 代表已经发送过的部分。
限制两者都会遮盖密码字段的值，整页截断在 40,000 字符。

ref

项
生命周期Playwright 按最近一次快照解析 aria-ref=<ref>，只要元素还在，它的 ref 就不变，所以 ref 能跨任意多个动作和轮次。
保留驱动从快照里记下每个 ref 的角色和名称。
查找解析不到的 ref 按这对角色和名称重新查找，直接用 role 和 name 指定的元素也这样找。
失败仍然找不到时，动作以 element_gone 失败，并附上页面的当前状态。

操作

项
输入点击、悬停、按键、输入（fill，或 clear: false 时用 insert_text）、select_option、drag_to 和 set_input_files 都是 Playwright 自己的可信输入。
后台标签页它们送达后台标签页时不会把它调到前台，这一点在 App 上核实过：后台标签页收到的指针、鼠标和点击事件都是 isTrusted。
滚动和粘贴滚动用 page_actions.SCROLL_SCRIPT，paste 用 PASTE_SCRIPT。
坐标按 x、y 点击时，用截图时测得的比例把截图像素换算成 CSS 像素，前提是截图仍然有效（坐标）。
光标点击前会激活 App 的 agent 光标并把它放到元素上。
导航动作之后，驱动最多等 0.3 秒看是否开始导航。
加载开始了就等 domcontentloaded。
请求之后再最多等 2 秒，让动作发起的 fetch/XHR 请求完成。
返回然后返回变化；URL 变了或文档是新的时，返回整页。
异常异常会变成带原因码和页面当前状态的结果，从不以原始错误返回。

审批。 App 的标签页不需要审批：打开或跳转到任何网站、在上面操作、在里面运行脚本都不询问。upload 在会询问的模式下询问，代码模式的校验器拒绝它；只读动作（tabs、read、wait、screenshot、console、network）对代理标记为读取。

文件上传

项
隐藏的输入框页面很少直接显示文件框：它常以 display: none 藏在样式化的上传按钮后面，大纲里只有按钮；有的页面在点按钮时才创建文件框。
做法所以驱动像人一样上传，做法与 Playwright MCP 相同。
监听器每个写动作执行期间页面上都挂着 filechooser 监听（_catch_choosers），Chromium 因此把文件选择交给驱动，而不在用户屏幕上弹出窗口；动作稳定后监听移除，用户自己点击时照常弹出窗口。
捕获的选择器这样拦下的选择器保存在标签页上，结果带 file_chooser（multiple、accept）；不带 ref 的 upload(path) 回应它，路径有误时它继续等待，其他写动作会丢弃它。
一步形式upload(ref, path) 是一步完成的形式。
设置或点击ref 是文件框或它的标签时（FILE_INPUT_SCRIPT），文件直接设到这个文件框上，隐藏与否都可以；其他元素在 expect_file_chooser 中点击，由它打开的选择器接收文件，3 秒内没打开则报 no_file_chooser。
不猜测驱动从不猜测按钮附近的文件框：页面上另有一个隐藏文件框时，文件会进错字段却报告成功，这也是 Codex 只通过选择器提供上传的原因。
原因页面可能卡在上一次上传里，也可能在 await 之后才打开文件框，那时点击带来的用户激活已经用掉了。
报错所以错误里会写出按钮当前显示的文字以及它是否被禁用（ELEMENT_STATE_SCRIPT），并给页面上所有可用的文件框编号列出（FILE_FIELDS_SCRIPT）。
条目每一项写明 id 或 name、accept、multiple、它所在的文字，以及它是不是按钮所在区域里唯一的一个。
选择模型用 upload(field=n, path) 选定一个，文件直接设到那个文件框上（Tab.file_fields）。
丢弃其他写动作或换页都会丢弃这份列表，用户自己的浏览器不支持 field。
文本结果文本结果会写明拦下的选择器及其 accept，模型据此知道要回应它。
用户的浏览器用户的 Chrome 或 Edge 通过 Playwright MCP 自己的文件选择状态遵循同一模型：带 ref 的 upload 先点击它，不带 ref 时回应上一次点击打开的选择器。
拖放区完全没有文件框的拖放区不在覆盖范围内。

evaluate

项
能读到什么evaluate 能读到已登录页面持有的一切，包括快照遮盖掉的内容。
授权它是操作浏览器的一部分：在内置浏览器里随 Page 授权运行，在用户的 Chrome 或 Edge 里随那个浏览器的授权运行（computer_use_agent(browser:chrome)）。
标记page_script 标出带 evaluate 步骤（单步或在 actions 里）的 computer_use_agent 浏览器调用，以及 web_use 的 evaluate；策略只用这个标记做一件事：这一轮由所有者以外的人发起时拒绝这类调用（IDENTITY_PAGE_SCRIPT：外部 MCP 客户端、别人设置的 agent 或定时任务）。
代码模式代码模式的校验器对代码调用里的 evaluate 步骤用同一个判断（identity.unattended）。
卡片询问带脚本的调用时，卡片完整展示参数。
脱敏结果经过同样的密码遮盖。
写法函数脚本直接调用；其他脚本像控制台那样运行：先当表达式解析，不行就当多条语句（最后一条的值是结果），再不行（有 await 时）当 async 函数体（return 的值是结果），所以只运行一次；返回的 Promise 最多等 30 秒（SCRIPT_SECONDS）。
错误脚本抛错时以 script_error 失败，带页面自己的错误信息。
上限脚本上限 8000 字符，结果上限 20,000 字符。
