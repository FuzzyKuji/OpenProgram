computer_use_agent

形态

computer_use_agent(target, action?, args?, actions?, code?, timeout?)
参数含义
targetapp、browser 或 vm，以本轮开始时本机能提供的为准；到不了的目标不在 schema 里，仍然点名它的调用会回答如何配置
action、args一个步骤及其参数；省略时打开该目标
actions同一目标上至多 20 个 {action, args} 步骤，遇到第一个错误即停止；状态只返回一次
code在隔离解释器里运行的 Python（见“代码”）；只在沙箱能运行的系统（macOS）上出现在 schema 里
timeout代码调用可运行的秒数，至多 120（默认 60）；随 code 一起出现
schema 如何生成
  • 描述和 schema 在每轮解析工具时构建（tool.describe，经 function() 的 describe 钩子和 current_tool），因此只列出宿主具备的内容：
    • app：平台后端可加载时
    • browser：浏览器应用启用时
    • vm：设置了 computer_use.vm_url 后
    • 用户的 Chrome 或 Edge：仅在安装了 Playwright Extension 时（extension.installed 查找浏览器数据目录中的 <profile>/Extensions/<id>，绝不碰浏览器）
    • code：仅在沙箱运行时
  • 没有扩展时，浏览器那一行写明：用户 Chrome 或 Edge 里的页面按应用窗口来操作。
  • 因此模型不会靠一次拒绝才知道某个目标不存在。
  • 一个目标都没有时，check_fn 隐藏这个工具。

action、actions 和 code 互斥。参数由目标校验，出错时指出正确写法，因为 schema 不列出每个动作的参数。

项
指南每个目标有一份指南（guides/<target>.md；app 指南按 macOS、Linux、Windows 改写）：它的动作、参数和结果长什么样。
送达tool.py 把它们注册为随结果附带的工具指南：computer_use_agent.<target> 附在第一次操作该目标的调用结果里，computer_use_agent.code 附在第一次操作任意目标的调用结果里（只在代码能运行的系统上），所以模型在发出代码之前已经读过代码怎么用。
不等待没有任何调用要等指南：在两份指南都还没见过时就发来代码的调用照常执行，指南随它的结果一起回来。
已知指南指南是否已知取决于 agent loop 最近一次发出的请求，所以上下文压缩、工具结果被清理和 worker 重启都会让指南重新送达；另一个 agent 写的提示里带着的指南，是包在发言者的 JSON 信封里送到模型的，所以 guides.known 也认引号被转义后的标记。
按需获取action: "guide" 和 help("computer_use_agent.<target>") 按需返回它们。
项
动作app 的动作就是应用目标的动作，参数相同；browser 的动作是标签页驱动的动作（tabs、open、read、click、type……，见浏览器目标：标签页驱动）。
先选浏览器与 Codex 一样，先选浏览器，动作不随浏览器改变。
按次生成指南浏览器指南每次送达时按同一项检查生成：只列出装了扩展的用户浏览器，一个都没有时指明其中的页面用 app 目标操作。
无扩展点名了没装扩展的浏览器的调用会立刻得到这条建议，不询问审批，也不启动服务器。
服务进程对装了扩展的，targets/browser.py 把每一步交给浏览器应用的 extension.py，它通过自己的 MCP 客户端运行固定版本的 @playwright/mcp --extension --browser chrome|msedge，每个会话、每个浏览器一个服务器，在调用之间保持。
连接服务器在该浏览器里打开带有其中继地址的 chrome-extension://<id>/connect.html，Playwright Extension 回连，并为用户共享的标签页中继 CDP；设置了 computer_use.chrome_extension_token 时，服务器传入 PLAYWRIGHT_MCP_EXTENSION_TOKEN，扩展不再询问直接连接。
动作映射tabs、read（tab 为序号时会选中那个标签页）、open、close、screenshot、upload、evaluate 和日志映射到服务器的标签页、快照、截图、文件、evaluate 和日志工具；所有元素和指针动作都经过 OfficialMCPPageBackend._action_call，即 playwright_mcp 后端对 App Page 使用的同一套翻译。
refref 是服务器快照里的 ref。
代码模式代码模式下，代码调用在 args.browser 里点名用户的浏览器时，cu.browser 操作的就是它。

代码
项
解释器code 在 computer_use_agent/sandbox/runner.py 的常驻沙箱解释器里运行（macOS 上用 seatbelt，没有文件、网络和进程权限）。
命名空间命名空间里有 cu.app、cu.browser 和 cu.vm；await cu.app.click(app="Numbers", element_index=3) 就是带这些参数的结构化步骤 click，由宿主经同样的目标代码和检查派发，每一步一条 effect 回执（computer_use_agent/sandbox/broker.py）。
文档字符串前导代码把每个动作在指南里的那一行作为对应 cu 方法的 docstring，所以解释器里可以用 dir(cu.app) 和 help(cu.app.click)。
参数说明code 参数自己的说明里为每个可用目标给出一条这样的调用，所以模型即使已经看不到代码指南，写出来的也是 cu.browser.click(...)，而不是光秃秃的 click(...)。
项
屏幕代码调用操作的是它点名的那块屏幕：app 是 args.app；browser 是 args.browser 指定的浏览器（不写就是内置浏览器）。
授权这次调用的授权覆盖这块屏幕，所以 code._validator 拒绝点名别的应用或别的浏览器的步骤，目标提供的其余动作一律放行，包括页面脚本和打开网站。
上传在代码里被拒绝：从内置浏览器上传文件会把本地文件发出去，要作为单独的动作来做。
页面脚本没有人看着这一轮时页面脚本不运行，从代码里发起和作为动作发起一样：code.run 在调用开始时从这一轮的请求里读到这一点。
项
生命周期一个解释器服务一次执行尝试，所以变量在本轮剩余时间里保留；失败或超时后解释器会被替换。
持有方式解释器按对话和执行保存，app 目标的窗口状态按对话和 Job 保存（tool.operator，取自调用所在的 Job）。
共用键对话自身的轮次共用一个键，所以一轮操作的是上一轮读取的窗口。对话启动的 Agent 作为独立 Job 运行，它的读取和代码绝不替换主轮次或其他 Agent 正在操作的内容。
项
限制每次调用最多运行 120 秒、100 步。
打印文本打印的文字保留到 256 KB，超出部分丢弃，并在结果里注明；步骤返回给代码的内容不计入这个额度。
未发出在输入到达应用之前就停下的步骤（NotDispatched：元素已不存在、元素被隐藏、找不到应用）返回 action_dispatched: false，代理把它记为未提交。
输入后失败输入可能已经发出之后才失败的步骤，在代码里抛出带目标报错信息的异常，它之前的步骤保持已执行。
超时超时或解释器停止的调用以错误结果返回：已执行的步骤保持已执行，正在执行的那一步可能生效也可能没生效，下一次代码调用会启动新的解释器，不带这次的变量。
未关闭的回执调用返回时，代理把结果一直未知的步骤的回执关闭（GuiBroker.settle，回执状态 unknown）：告诉模型的是调用结果，不会有悬着的回执留到调用之后。
平台代码模式需要 macOS 沙箱；在其他系统上代码调用会报告沙箱不可用。
谁来操作
项目
调用方调用工具的 agent 自己操作屏幕，把任务做完。工具没有把任务交给另一个 agent 的参数，所以失败的步骤在原地重试。
长任务code 在一次调用里运行多步，只返回它打印的内容，中间画面不进入对话。
多块屏幕同时操作几块互不相干的屏幕走 agent 工具；基础指令只在用户或项目说明要求子 agent 时才允许它。每个 agent 有自己的窗口状态、元素序号和代码解释器。
时限这个工具没有总时限：每个动作自有上限，代码到自己的超时就停。
工具模块
模块作用
openprogram/programs/tools/computer_use/computer_use_agent/tool.py注册的工具：schema、目标清单、路由、指南注册、审批原因
…/computer_use_agent/guides/各目标的指南
…/computer_use_agent/targets/app.py基于 openprogram/programs/tools/computer_use/computer_use_agent/desktop/ 的应用动作
…/computer_use_agent/targets/browser.py浏览器动作：标签页驱动（browser 服务的 tabs），或用户的浏览器（它的 extension）

…/computer_use_agent/code.py基于 computer_use_agent/sandbox/runner.py 和 sandbox/broker.py 的代码模式

没有单独的“规划 → 决策 → 执行 → 验证”循环：长任务由调用工具的 agent 自己做完，多步操作用一次代码调用。
