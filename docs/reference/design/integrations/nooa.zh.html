直接调用、Agent 类和自动 DAG 上下文

名称定义
Agent可复用的模型配置，不拥有默认对话
Context父级、命名内容、动态提供者、历史可见性。由框架构造，应用无需手建
原样复用Runtime、AgentSpec、工具策略、执行控制、Session DAG

用法

from openprogram import agent
answer = agent("Analyze this paper", model="configured-model")

使用当前执行会话，没有时开一次独立执行。

from openprogram import Agent
bot = Agent(model="configured-model")
first = bot("Investigate this topic")
second = bot(first)

复用配置，不复用历史：连续性由执行作用域决定，独立的顶层调用互不共享。

class Researcher(Agent):
    model = "configured-model"
    def research(self, question):
        text = self.prepare(question)
        return self(text)
    def prepare(self, text):
        return text.strip()
result = Researcher().research("A topic")

方法上不用装饰器。research 是入口，prepare 是不记录的辅助方法。

入口规则
agent()、Agent.__call__同步。两者委托同一个内部执行函数
await bot.arun(...)、await agent_async(...)用于活动事件循环内的调用
构造只解析配置：不发模型请求，不建持久会话。首次执行时才解析会话
全局状态没有保存历史的进程级默认 Bot

Context 生命周期

触发规则
Program 或顶层入口建立作用域并绑定 Context；继承环境会话和显式分支
函数或方法入口按祖先和可见性规则派生作用域，不复制历史
每次模型请求前解析 DAG 来源、实例内容、动态内容、调用覆盖；选择、去重、预算
模型返回更新执行状态，后续构造按规则可见
返回、错误、取消恢复父级。已完成的交互遵循 expose 和 render_range，子上下文不无条件合并
顶层退出解绑任务本地状态，关闭自有资源
关系决定
调用祖先继承和可见性
前驱对话顺序
每次 Agent 执行拥有自己的 DAG。记录用户消息、模型请求、直接派发的工具；普通辅助函数不产生持久节点
调用另一个 Agent独立 DAG；父级保存结果和 child_session_id
权限、取消、文件检查点留在发起执行，和图归属无关

Context 是运行时构造对象；中间值不要求完整复制或持久化。会话持久化和 Trace 导出另行处理。

统一的 Context 模型

parent Context + Agent configuration + call content
    → derive current Context
    → evaluate named content and select visible DAG interactions
    → apply existing budget and compaction
    → Runtime.exec model request
部分行为
父级子级继承当前 Context；退出作用域恢复父级
内容命名的指令和业务数据。子级可覆盖名字而不改父级。实例绑定就是这种内容，在调用派生 Context 时加入
求值Python 提供者接收当前 Context，在构造请求时运行。不求值表达式字符串
可见性Session DAG 规则按分支、调用作用域、expose、render_range 选择交互
  • 历史选择和内容替换是两件事。文本相同不代表同一次交互；选中的 DAG 身份在实际请求时记录。
  • 没有第二个历史数据库或 provider 运行时。工具授权和历史可见性相互独立。
API行为
Context.current()当前绑定
Context.derive()子 Context
bind()发布任务上下文和显式 writer，拒绝冲突的环境 writer，退出时恢复
Context(store=writer, head_id=None)为重复调用绑定现有 SessionNodeWriter：把 NOOA 式实例事件生命周期变成显式绑定。head_id 选分支末端，默认会话 head。store 归调用方所有

普通函数捕获

def research(question):
    data = prepare(question)
    return analyze(data)
def prepare(question):
    return question.strip()
def analyze(data):
    return agent(data)
代码处理
已注册的 Program 源码托管加载器保留 Runtime 注入和入口适配；辅助函数用轻量作用域，不逐次持久化
Agent 方法，包括 _ 辅助方法自动作用域；不追加 DAG 节点，也不成为工具。实例、静态、类方法遵循 Agent 归属
宿主文件、依赖包、lambda、动态生成代码、无源码不捕获。agent() 仍可用；Python 祖先不持久化
全部签名、返回值、异常、导入保持 Python 语义。入口注册和工具暴露保持显式。创建生成器不产生已完成的调用记录

配置和权限

设置归属
model、effort、instructions、tools调用覆盖 → 实例 → 类默认 → 环境会话 → 产品默认。省略和显式空值不同
expose、render_range沿用默认；由 method_options 或显式元数据设置
工具可见性、审批和 DAG 可见性分开。内层配置不能扩大外层权限
AgentSpec、会话保存的 Bot 复用 AgentSpec。Python 对象不产生侧栏 Bot 或日程

默认构造需要模型交互和调用关系，不需要普通参数或局部变量。显式内容有界；self 用身份或类型表示；方法名按模块和类限定。调用记录不等于批准任意 Python 副作用，它们仍受沙箱约束。

并发和失败

  • 当前 Context、调用身份和生效配置按任务绑定，退出时恢复。继承不复制历史或可变分支配置。允许嵌套重入。
  • 共享 Agent 配置不代表共享历史。可变实例内容和共享会话需要定义同步规则。
  • 错误、超时、取消恢复父级并保留已完成交互。恢复依靠安全点和显式步骤，从不恢复任意 Python 栈。独立调用复用权限上下文和非交互审批规则。
  • 没有外层执行时，入口自行持有环境并在退出时释放。
  • 可恢复函数在调用和续跑间使用同一个持久节点 ID；provider 工具调用身份留在节点元数据里。

没有函数装饰器

  • 已移除的公开装饰器没有适配层，也没有替代品。Agent.method_options 保留输入元数据、Runtime 注入、注册和 schema、可用性、权限、可见性、重试、执行控制和显式步骤恢复。
  • 托管源码声明 PROGRAM_ENTRIES 和 __agent_options__。方法带 _is_agent_method 标记。已存储的节点 schema 和历史仍可读。
  • 第一方工作流、生成的程序、扫描器和分发器都用普通 Agent 类。
  • Harness 包在各自仓库迁移，保留 agentics 路径；运行时不捆绑。六个本地发布的工作流已隔离迁移，这不算上游发布。
行为测试宿主和取消显示
  • 宿主在 OS 沙箱之前初始化标准 SessionStore。运行器通过 Context 绑定 SessionNodeWriter，Agent 调用复用它。候选测试不能启动进程、写源码快照、读宿主密钥或联网。
  • 取消关闭规范执行；未决的外部副作用仍可查看。
  • 节点或存储不可用时，助手投影经持久 DAG outbox 重试。显示失败不会否定已生效的取消。
  • 取消暂停的续跑错误时，错误显示换成已取消，清除错误元数据，保留内容。
  • 资源释放观察者的失败对控制调用方可见。正常完成的 Job 保留带结果的投影所有者；在它提供结果和错误字段前，取消通知不发布其他终态 Job 行。
验收
场景可观察结果
非模型父级research → prepare、analyze → agent 作用域正确；模型输入、输出、失败可归属
继承和求值父级继承、实例块、每次请求刷新动态值、覆盖顺序、去重且保留不同的重复交互
等价性相同 DAG、分支、策略下新旧入口历史相同；在实际请求时记录出处
会话生命周期构造无副作用；无关任务中的同一实例相互隔离；同一任务中的不同 Agent 共享允许的上下文；现有会话需显式延续
预算和压缩沿用压缩并保留出处；摘要用量计量；失败不丢历史
并发和资源兄弟隔离、共享实例状态有显式策略、重入、恢复父级、只清理自有资源
加载和身份只捕获授权源码；递归和导入别名保留记录；同名方法不冲突；元数据不重复节点
策略和显示记录不暴露工具；副作用前拒绝；独立入口执行策略；默认 App 显示函数、模型、工具调用和终态

还覆盖对话投影、Goal 生命周期、取消、恢复和随产品发布的 Program。记录保留 DAG 关系，不改变内容、归属或权限。检查只取最小受影响集合。

和 NOOA 的关系

领域选择
类和方法采用类声明、普通调用、框架托管方法
Context 建模采用基于类的实例内容、动态解析、作用域覆盖；增加 DAG 来源。生效上下文归执行作用域
历史过滤NOOA 按 call_id 过滤并支持嵌套策略继承。OpenProgram 保留 DAG 分支和帧规则
Trace 和模型上下文NOOA 分离事件和 trace。OpenProgram 保持一个 DAG，分显示视图和输入视图
不采用逐函数手建上下文、进程级历史、整解释器追踪、第二个 provider 或事件数据库
