操控电脑的界面

Agent 光标

项
步骤落点在一个点名元素或坐标的步骤执行前，MacComputer.act 先算出它落在哪里（元素的中心取自它的 AXPosition 和 AXSize，截图坐标则按窗口原点和缩放换算），调用 native_window.note_action_point，再等待 CUE_LEAD_SECONDS（0.15 秒），让光标先到。
坐标系这个点以屏幕点为单位、原点在主显示器左上角，与 Electron 的坐标空间相同。
帧worker 把它作为 native.action 帧广播（session_id、x、y、sequence、at、action、app_name）；agentic 子进程通过与被操作窗口相同的父进程通道转发（kind: "action"）。
Web 客户端Web 客户端里 native-window-store.ts 在显示操作没有关闭时把帧交给 openprogramDesktop.nativeActionCue。
绘制桌面主进程（main/worker/agent-control.js）把它画进这个对话的控制提示层：光标滑过去并停在那里。
去重每个 App 窗口都会收到这一帧，所以主进程按 session_id、sequence 和 at 丢掉已显示过的步骤。
平台Linux 和 Windows 还不发出这些点。

窗口标识

项
标识被操作的窗口带有 macOS 的屏幕共享标识，与 Codex Computer Use 下一样：标题栏按钮上的徽标和菜单栏的共享图标。macOS 会给任何处在 ScreenCaptureKit 实时流下的窗口画这两样，所以 window_watch.WindowWatch 在它上面保持一个流。
触碰MacComputer 在每次 act 和每次指明窗口的 get_state 时，用窗口 id、应用名和标题栏按钮的位置（通过辅助功能读取）触碰它。
流流只过滤这一个窗口（SCContentFilter.initWithDesktopIndependentWindow），请求每秒一帧的 2x2 画面且不挂任何输出，因此不录下任何内容。
释放每个会话最多监视一个窗口：转到另一个窗口会释放前一个，IDLE_SECONDS（20 秒）内没有步骤的窗口由清理定时器释放。
失败打开流在单独线程上进行，失败被忽略，所以步骤不会因标识而等待或失败。
项
位置上报窗口被监视期间，另一个线程每 REPORT_SECONDS（0.12 秒）在有变化时上报它的位置：window_place 读取屏幕窗口列表，得到窗口的位置和 GLOW_MARGIN（32pt）范围内挡在它前面的窗口，标题为 OVERLAY_TITLE 的窗口（App 自己的提示层）不计入。
控制帧上报经 native_window.note_control 发出，归属取触碰窗口时记下的对话，帧类型为 native.control（session_id、window_id、active、app_name、frame、buttons、occluders）；子进程以 kind: "control" 转发。
结束释放窗口时发出 active: false。
Web 客户端Web 客户端在显示操作打开时把上报交给 openprogramDesktop.nativeControl，控制结束的上报总会交过去。
覆盖窗口桌面主进程为每个对话在窗口加边距的范围上放一个透明、点击穿透、不可聚焦的窗口，加载 /menu-overlay/agent-control，画出向内发光、按钮上的强调色红绿灯和光标。
层级提示层在窗口层叠里紧贴在被控窗口之上（用窗口 id 调 moveAbove，每次上报都重新排一次，因为用户切换应用时层叠会变），所以挡在被控窗口前面的窗口也会挡住提示层；只有窗口服务器拒绝这样排序时，它才浮在所有窗口之上。
遮挡窗口两种情况下发光和红绿灯都会挖掉挡在前面的窗口，光标的落点在这些窗口下面时光标隐藏。
外观外观见 Agent 控制提示层。

Web 展示

项
读取调用lib/computer-use/computer-use-agent-call.ts 解读 computer_use_agent 调用：appStepArgs 把 app 调用变成应用渲染器接受的扁平步骤（{action, app, …}；多个步骤成为 batch，代码自成一个动作），screenStep 给出浏览器或虚拟机调用的动作。
应用步骤tool-presentation.ts 用显示器图标和 system 色调渲染 app 步骤；标题写动作和应用（"在 Calculator 中点击"），目标行在给了按键、文本、动作名或窗口时显示它们。
其他调用浏览器调用显示动作和 URL，虚拟机调用显示动作，代码显示"在 <app> 中运行代码"。工具还能把任务交出去时录下的对话，把那种调用显示为"交给新代理"及简报首行。
审批卡片审批卡片的范围按钮在"允许一次"和"始终允许"之间加入"允许此对话"，答案摘要打印"允许此对话"。
旧调用早先工具（computer_use、web_use、gui_agent）记录的调用保留各自的渲染器，旧对话照常可读。

界面工作

项
卡片头部app 调用的审批卡片（computer-use-approval.tsx）先展示应用本身：图标、显示名和 bundle id 来自 computer_use_apps WebSocket 动作，它调用后端的 app_info，不启动任何东西，Web 按名字缓存结果（lib/net/computer-use-apps.ts）。
卡片正文其下一个标签用文字说明这一步（computer-use-step.ts），两行分别说明这一步在后台进行（录音则说明只录该应用的声音）以及可选范围的含义，去掉空值的参数折叠在"查看执行详情"里。
项
设置分区项目设置页在默认设置和权限规则之间有一个"操控电脑"分区（computer-use-apps-section.tsx）。
行它把项目的 computer_use_agent(<app>) 允许规则（以及以 computer_use(<app>) 保存的规则）列成每个应用一行，带图标、名字、bundle id 和移除按钮，通用规则列表不再重复这些规则。
移除移除一行即删除该规则。
对话级授权对话级授权是随对话结束的会话规则，所以这里不列出。

实现状态

状态范围
已实现网页标签里的元素评论和区域截图；对已打开标签页和正在运行应用的 @ 提及。
macOS 上已实现桌面应用上的控制提示层（向内发光、强调色红绿灯和 agent 光标），窗口位置帧、步骤坐标帧和桌面提示层窗口有单元测试。未实现：Linux 和 Windows 后端不上报窗口位置和步骤坐标，那里不会显示提示层。
macOS 上已实现窗口标识，监视、切换和空闲释放有单元测试。Linux 和 Windows 上未实现。
