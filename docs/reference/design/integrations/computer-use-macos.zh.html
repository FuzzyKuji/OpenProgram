元素动作元素动作走 Accessibility：AXPress / AXConfirm / AXPick，然后 AXSelected，然后聚焦，最后才在元素中心做一次指针点击；右键用 AXShowMenu；set_value 用 AXValue；select_text 用 AXSelectedTextRange（UTF-16 偏移）；scroll 先用翻页动作，再用滚动条的值，再用滚轮事件。

真实指针事件必须真实的指针事件（坐标点击、拖动、滚轮）按开源 cua-driver 确立的做法发送：
  1. 向目标进程序列号发送一条聚焦但不置顶的记录。
  2. 一个 mouseMoved 预备事件。
  3. 事件本身，带点击状态、按钮、subtype 3、目标 pid、窗口 id 和点击组。

键盘键盘事件附带 SLSEventAuthenticationMessage 以便接收进程接受；没有 SkyLight 时回退到 CGEventPostToPid。
效果结果是应用把这次点击当成用户点击来处理，而真实光标留在原地、前台应用不变。

应用处理 mouse-down 时 AppKit 仍会把被点的窗口排到同层最前，所以坐标点击和拖拽之前先记下压在目标上方且与之重叠的其他应用窗口（前台应用自己的窗口除外），结束后按从深到浅的顺序对它们 AXRaise，窗口叠放顺序因此还原。

应用正忙

项
串行处理macOS 应用一次处理一个辅助功能请求，按顺序处理，做完才回应。
超时错误处理时间超过消息超时的请求会返回 kAXErrorCannotComplete，而应用其实已经收到一次并且正在执行：保存要几秒的按钮、运行模态对话框的命令、保持打开的菜单都是这样。
实测在 macOS 15 上实测：在超时内处理完的按压返回 0；更久的在超时（默认 1.5 秒）后返回这个错误，并且恰好送达一次；处理期间应用被占住，所有读取也同样失败，包括 AXWindows，于是应用读起来像没有窗口。
超时作用域设在某个元素上的超时只对那个元素生效。
项
发送MacComputer._taken 发送每个会改变应用的请求（_perform、_set），并在元素上设置 ACTION_TIMEOUT（1 秒）。
算作已接收等满这段时间后的 kAXErrorCannotComplete 算作已被接收，所以这一步按已执行汇报，不会再退回去用指针点击或键入按键，否则会做两次；立刻返回的同一个错误码表示请求根本没能发出，仍算失败。
探测_answers 用 ANSWER_TIMEOUT（0.5 秒）向应用元素询问它的角色，只有这次询问没有得到回应时才为假。
等待_await_answer 重复询问，最多 UNANSWERED_MAX（10 秒），之后抛出 NotAnswering（属于 NotDispatched）。
顺序请求按顺序得到回应，所以回应到来时，应用已经做完之前发给它的步骤，或者正在运行那一步打开的对话框或菜单。
项
等待时机get_state、list_windows 和 act 在向应用询问任何东西之前都这样等待，等待在后端的锁之外；settle 在读取窗口之前等待；wait 从不等待，模型可以用它让应用做完。
沉默的步骤targets/app.py 把应用一直没有回应的步骤按已完成返回，不带状态，并写明不要重复。
被拒绝的步骤因为应用没有回应而被拒绝的步骤什么都没有发出（action_dispatched: false）；一串步骤里，它之前的步骤保持已执行，不再等第二次。
其他失败步骤已发出之后读取状态的其他失败（应用退出、屏幕锁定）写在这一步的 Done 之后，绝不会被报成没有发生。
