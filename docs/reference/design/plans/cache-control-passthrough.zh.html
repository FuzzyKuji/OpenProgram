cache_control 透传

调用方有一段固定的长规则加动态尾部，想把断点放在规则之后。调用方的 cache_control 是不透明字典，例如 {"type": "ephemeral"}，可带 ttl，不解析直接交给 Anthropic。只针对 anthropic 类：原生 API 和任何 anthropic-messages 接口。OpenAI、codex 类用自动前缀缓存。

层位置做什么
内容类型models/providers/types.pyTextContent、ImageContent 带 cache_control: dict | None。视频、音频没有。
上下文runtime/agent/runtime/ 的 _build_pi_context把每个 content 块的标记复制到对象上。role == "system" 的块变成 system_text，没有逐块断点。
缓存策略models/providers/settings/cache_policy.pyapply_cache_policy 给最后一个工具、最新用户消息的最后文本块各加一个标记。不动调用方标记，已有标记的消息跳过。
请求体adapters/anthropic/anthropic.py 的 _build_messages把标记写入块字典，只针对 list 内容的 UserMessage。自动的最后一块断点也会落在结尾的工具结果批上。

没有标记时，请求体与没有该字段时逐字节相同。

自动断点与调用方断点

_mark_final_message 把自动断点放在请求的最后一块：一轮对话的第一次请求是用户消息，之后每次是那批工具结果，所以每次请求都能从缓存读到整段历史。

这条消息里任一块有标记，就不加自动断点。否则会多占一个名额，并把缓存边界钉在变化内容之后。

1h 断点不会排在 5m 断点之后，否则 Anthropic 拒绝请求：策略层只在系统断点带 1h 时才用它；一旦出现 5m 断点（包括调用方自己标的），之后的断点都改成 5m。

调用方要遵守的边界

边界效果
最小前缀标记前不足 1024 token（Haiku 2048）时 Anthropic 静默忽略：cache_read 一直是 0，不是透传的问题
每请求四个断点第五个返回 400。系统块、最后工具、最新用户消息、最后一块可能已占满。调用方标记使总数超过四个时，先去掉最早的消息断点，最后一块保留自己的断点
代理剥掉 cache_control 的代理会让 cache_read 保持 0。发送两次相同固定前缀，检查第二次 cache_read > 0
其他 provider块构造只读 .text、.data；两处 model_dump() 导出的是选项而非内容，字段不会泄漏。TextContent.model_dump() 可往返，持久化不受影响

调用方的工作

把固定规则放进第一个文本块并标记。OpenAI、codex 只需把稳定前缀放在最前。
