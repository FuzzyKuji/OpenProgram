Credential connection unification

One CredentialData replaces six payload classes. One resolve_connection() gives the wire layer everything a request needs, so a key can carry its own base URL. Design source: credential connection unification.

@dataclass
class CredentialData:
    kind: str
    auth_value: str = ""            # what to send
    base_url: str = ""
    headers: dict = field(default_factory=dict)
    data: dict = field(default_factory=dict)   # refresh tokens, file paths, flow ids

@dataclass
class ResolvedConnection:
    kind: str
    auth_value: str
    base_url: str | None
    headers: dict

Stored flat as {kind, auth_value, base_url, headers, data}, with no __type__. _payload_from_dict accepts only this. Credential.metadata and display information stay on Credential.

Resolution

Credentialresolve_connection returns
cli_delegatedReads its external file now, so the token is the freshest on disk
credential_processRuns its helper, cached for cache_seconds; a failing helper raises AuthCredentialProcessError rather than letting another credential stand in
ssoRaises AuthConfigError: no login flow implements it
No auth valueNone, and the caller falls back
Unsupported provider; Anthropic oauth, device_code or cli_delegated; any sk-ant-oat valueNone. Anthropic needs an API key

An empty base_url becomes None, separating "no endpoint" from "this endpoint". acquire_pooled(provider_id, account_id=None) returns (ResolvedConnection, str, str) | None. _extract_token remains as a thin reader over it.

At the wire layer the credential wins and the catalogue fills gaps:

base_url = (conn.base_url if conn and conn.base_url else None) or model.base_url
headers  = {**(opts.headers or {}), **(conn.headers if conn else {})}

OAuth detection reads conn.kind, not the token string.
