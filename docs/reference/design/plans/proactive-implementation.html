Wiring the proactive layer into the code

The design is in Proactive layer and wins on any conflict. openprogram/runtime/events/bus.py is the event layer; taps sit in the source files that already know when something happened. Event has three core fields plus open metadata, so turn and session travel there and a source with no turn invents none.

The gate query does not read permission_mode, so it also applies to sub-agent turns in any mode (invariants, execution model).

Prepare

Designed to use JobRunner.spawn_job with an allowlist excluding bash, write and network tools, in a separate pool of 1–2, preemptible by user tasks, yielding on 429. Today the engine emits proactive.prepare_requested and proactive.inject events; nothing yet spawns the task or lands the steering message.

Known gap

@function tool execution writes no DAG node; only Agent methods do. The DAG is therefore incomplete as a causal record, and audit relies on the full event set in events.jsonl instead.

Checking a wiring change

py_compile, relevant unit tests, the documented local refresh, healthy /healthz, one real message through the Web UI (npm --prefix apps/web run build first for frontend changes). For ordering, run a turn with a tool call and read the session's events.jsonl:

user.prompt_submitted → model.response_started → tool.before → tool.after → model.response_completed

Each entry carries session and turn in metadata.
