The cursor after a fork

FrameworkCursor scope after a forkPrefix extracted again
codex-cliNew thread_id, the cursor table's primary keyYes, all of it; only Phase 2 consolidation merges semantically
claude-codeUndocumented—
openclawNew session, flush markers cleared on purposeYes; comments prefer repetition to omission from equal hashes
opencodeNew ids; tail_start_id translated through a lookup tableNo
hermes-agentNew session; index advanced by hand to the copied lengthNo. Compaction-created sessions reset to 0 because they start empty.
pi-monoNo cursor needed: walk leaf to nearest common ancestorNo; traversal excludes it
OpenProgramUnchanged; markers read back from the current tipNo
pi-ai, weclawNo forks; weclaw's /new clears the session—

Index and timestamp cursors need one line per scope, so they change scope at a fork, and that works because their forks copy content. Our forks copy nothing, so we record identities. pi-mono's alternative needs a comparison branch for every traversal; memory asks what is unwritten in the session and has no second branch to compare.

Lessons on trimming
LessonFor us
Line counts cannot limit long linesNot adopted: another write-path gate would still exclude stable facts. Ours counts tokens at rendering.
Trim by ownership, not ageNot adopted: it matters when the file is the sole copy. Our block is derived, so omission destroys nothing.
Limit all relevant contentcodex omits global AGENTS.md; claude-code stops a CLAUDE.md only at 4 MiB
Disclose truncationcodex only logs it, so user and model never know. Ours reports it.
