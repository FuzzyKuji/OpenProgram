阅读、编辑与历史

操作行为
打开主题或 Core 源记录显示渲染后的 Markdown，带脚注和链接。控件：预览、编辑、历史。
编辑源文本。没有保存按钮。
保存每次编辑立即进本地草稿存储，并经按文件串行的写入器提交。较旧的响应不会把更新的输入标成已保存。
撤销、重做按单次编辑，跨自动保存有效
历史最新在前，每次 50 条，带本地日期时间和提交说明。更早的按需加载。
选中一个版本相对父提交增删的行
恢复此版本先提交当前状态，再用所选文档新建一个提交。历史保留。

Git 检查点

手动编辑按五分钟合成检查点。第一次编辑先提交 memory: before manual editing 并记下持久的截止时间，界面之外写入的编辑前状态也不会丢。服务端任务每 15 秒检查截止时间并提交 memory: manual editing checkpoint，页面关了也照常。重启后恢复未到期的截止时间。

数据与失败处理

情形行为
写入路径分阶段写入：校验引用、重建派生视图、提交 Git 历史，Markdown 渲染不变。源校验不变。
过期编辑在写锁内比较提交的 base_content；不一致则拒绝，保留草稿并显示错误。
规范化响应返回规范化后实际保存的文本，因为规范化可能改动源文本。
显示的状态行内只显示错误和 Git 警告；没有“保存中”或“已保存”提示。
切换、刷新草稿保留在本地。
访问需所有者授权的端点读取有界的 Git 历史，仅限主题 Markdown。路径和版本输入不能逃出 Memory；版本必须是完整提交 id。
