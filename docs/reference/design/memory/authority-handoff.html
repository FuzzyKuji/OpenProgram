Unpaired is no third tier and no reply-only state: the message is never rendered into model context, which removes that injection surface.

The gate

authority_tier is one enum on the request boundary, beside principal_id, speaker_kind, speaker_id, speaker_display and interaction. A request carries no capability list a caller could mint.

Trust in memory

Memory cites chat messages, so trust is a question about the cited message. Pairing is the trust decision: owner and paired turns carry memory.source.append, enter distillation alike and are attributed by speaker. No second gate.

  • Unpaired text enters neither memory nor context. interfaces/channels/base.py checks access before dispatch, so the message never becomes a turn and has nothing to cite or recall.
  • A new citation is checked when its edit commits: the message exists in the session store, is a person's or the assistant's words, and its speaker holds memory.source.append. A paired edit may cite only its own conversation.
  • A paired memory_update may only create or byte-append. Rewriting or deleting takes a persisted owner turn.

The memory writer

Follows the default chat Agent's provider, model and credentials; memory.writer.model overrides it, live, from Web settings. Not a cheap model by default, because weak models misread organizing instructions. Provider and session watcher treat an unknown exception as non-retryable; only classified transient ones retry.

Read scoping: stamp on write, filter on read

Designed, not built (see status). Visibility is decided once at write time and stored on the content. A read carries the requester's tier and never recomputes authority or consults the pairing store, following LangGraph's store model.
