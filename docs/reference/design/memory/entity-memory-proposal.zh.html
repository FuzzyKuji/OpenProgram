基于 Git 的实体记忆

暂缓的提案。实体记忆是对实际发生之事的不可变记录，可逐步追溯：Session-Git 存“说了什么”，Project-Git 存“改了什么”。当前生效的 Memory 是 概览 里的 Source、Topic、Core 工作区；当前持久化见 会话存储。

提案现状
会话记录每个对话一个 Git 仓库，每轮一个提交没有仓库。<state>/projects/<project-id>/chats/<session-id>/main.jsonl；commit_turn 让会话字段持久化。
有效会话meta.json 存在且可解析main.jsonl 或 agents/ 存在
位置索引locations.json存储根下的 .chats-locations.json，旁边是 .chats-index.json
Agent 文件历史提交进用户的仓库影子 Git，位于 ~/.openprogram/shadow-git/<project-hash>/，不碰用户的 .git。Project-Git 自动提交已有代码，但已弃用，默认关闭。
工作区有改动Agent 开始前不干净就跳过每轮开始记下已改动路径；这些改动仍在时拒绝提交，并发 project_commit_skipped 提示
项目注册表、面板、聊天指示见下文已实现：projects.json、WS list_projects 和 create_project、侧栏 Projects
回放界面、会话 Git 的 WS 动作、回填见下文未实现

Session-Git 生命周期

阶段提案
创建第一条消息时惰性创建（SessionStore._open(id, create_if_missing=True)）：git init，写 meta.json，建 history/、context/、workdir/。指定工作目录则绑定真实项目，仓库放在项目内；否则 project_id="default"，放在主目录根下。
有效性目录存在且 meta.json 能解析为 JSON。其余（测试残留、无关目录、损坏）静默跳过。
发现扫描每个 <state>/projects/<project_id>/chats/ 加位置索引；合并、去重，按 updated_at 降序。侧栏和 Chats 页用同一规则。
写append_message 同步写 history/NNNN-<role>-<id>.json 并更新内存索引；commit_turn 在轮末提交一次。
读get_branch(session_id, head_id) 沿 parent_id 得到消息列表；get_nodes 返回原始 Call 对象；session_commits 返回按轮的日志。
分支、重试DAG 重试对应 git 分支 retry-<assistant_id>；切换 DAG head 对应 git checkout。
元数据、绑定update_session(session_id, title=..., project_id=...) 写 meta.json 和索引。绑定记在 project_id。
缓存SessionLog 和 SessionMemoryIndex 的内存 LRU，上限 256（OPENPROGRAM_SESSION_CACHE_CAP），淘汰后从磁盘重建；每会话一把锁加一把存储锁。
删除delete_session：移出缓存，关闭运行时，删除整个目录（含 .git/）和位置条目。入口是侧栏菜单；Chats 页右键待加。Provenance 指针悬空，查询时跳过，虚拟层无需清理。
垃圾回收没有 meta.json：跳过。空且标题是默认值：列出。长期不活跃：不自动删除；回收空间的策略属于用户配置，不在存储层。

dispatcher.process_user_turn() 返回 TurnResult 时提交一次：1 条用户消息、1 条助手消息、N 个工具结果。

turn <N>: <first 60 chars of user msg>

assistant: <first 80 chars of reply>
tools: read, grep × 3, list

回放

控件动作
prevgit checkout HEAD~1，回放界面
next沿 reflog 反向走
view full history时间线，每提交一行；点击看消息内容
WSgit_history(session_id)、git_checkout(session_id, commit_sha)。dispatcher 在该提交上继续下一条消息。

双写

dispatcher 写 DAG。一轮结束后，节点在后台线程序列化进仓库，因为一次提交要约 100 到 500 毫秒。每会话一个仓库、提交串行，冲突很少；文件锁兜底。启动时，没有仓库的会话按 seq 逐轮回填一次。

Project-Git 生命周期

阶段提案
创建绑定目录时 resolve_project(path, name)：复用 .git/ 或 git init，登记到 projects.json。
自动提交轮末，绑定会话的 Agent 改了文件就提交，用 Agent 的 user.name 与用户提交区分。用户同时编辑时，开始时干净并不能证明归属，所以必须识别 Agent 自己的改动。
读ProjectGit.log(limit)；溯源层用 project_commits(project_id)。
解绑只移除登记。用户的 .git/ 保留；会话的 project_id 作为历史指针保留；会话仓库留在项目内。
 
git commit -c user.name="agent (<model> via OpenProgram)"
           -m "[agent <session_id>] turn <N>: <user msg first 60 chars>"
已实现的自动提交，默认关闭
项目行为
开启config.json 的 project_auto_commit 或 OPENPROGRAM_PROJECT_AUTOCOMMIT=1
提交说明[agent <会话 id 前 8 位>] <用户消息首行前 60 字符>
不是仓库每轮开始时，先为现有文件做基线提交，让 Agent 提交是真实差异。若 node_modules、.venv 这类依赖或构建目录会撑大它，则拒绝并提示。
有活动 worktree让路；worktree 有自己的合并和丢弃流程。
主目录项目不做任何事；它没有绑定目录。

项目元数据与展示

会话可以没有项目。有项目时，Agent 的文件提交落在项目仓库，会话元数据带 project_id。

Project: id, name, workdir, sessions, status (active | paused | done), created_at
位置内容
左侧栏 Projects 区名称、会话数、状态、New Project
项目页名称、工作目录、会话、提交历史、抽象记忆入口
新建项目选目录，命名，创建或复用仓库，可选关联当前会话
聊天顶部项目名和缩写的工作目录，链接到项目页

关键不变量

  • DAG 是事实来源，Git 是镜像。Git 失败不影响 DAG。有提交而 DAG 没写是脏数据。
  • Session-Git 每轮一个提交，不按消息。
  • Agent 不污染用户工作区：用户有未提交改动时跳过提交。
  • 回放是只读视图；checkout 后发新消息，从该提交在 DAG 上分叉。
  • 抽象记忆建在实体记忆之上，反之不成立。

项目注册表的安全（已实现）

worker、CLI 和 Agent 子进程都写 projects.json。

情形处理
读改写全程持有跨进程锁 <state>/projects/.locks/.projects-registry.lock
发布写唯一的临时文件再改名；读者看到的要么是完整旧文件，要么是完整新文件
读取出错抛出异常，因为空结果会被写回，抹掉所有绑定
不是 JSON 对象移到 projects.json.unreadable-<time>-<id>；注册表从空开始

风险

风险缓解
异步提交失败无人察觉后台重试；启动时比较 DAG seq 和提交数，不符则回填
工作目录不是仓库Agent 第一次提交时 git init；已有则复用
多个会话改同一项目文件锁串行化项目提交；最坏情况是排队
回到第 5 轮发新消息分叉而不是覆盖：即 DAG 的重试，映射为 Git 分支

关系

对象关系
提交链不冲突。DAG 节点镜像为 Git 提交，是实际发生的历史。ContextCommit 链是 LLM 看到的，派生且可重算，不进 Git；需要时可单独导出。
抽象记忆实体记忆是其唯一来源。蒸馏读取 Session-Git 节点和 Project-Git 提交，写入时间线和图。每条记忆带一个指回的 Provenance；见 虚拟记忆。
外部工具本提案暴露 Git 日志和差异历史。与其他工具的功能对比须先核实，才能影响实现。

会话标题（已实现）

优先级规则
1. 用户命名/rename 或界面。不会被覆盖。“生成名称”会解除锁定，之后仍可自动改进。
2. 模型标题后台调用，3 到 7 个词，句首大写，与对话同语言，最多 80 字符，走结构化输出。在第 1、6、16、40 轮运行；以寒暄开场的对话在第 2、3 轮也运行。输入是当前分支的摘录，最多 1000 字符。失败只记日志。重新命名只替换它开始时的标题；侧栏经 session_updated 更新。
3. 摘录第一轮立即设置：首条用户消息的第一行，50 字符，模型工作时侧栏也不会空。
4. 预览列表时，没有可用标题的会话显示首条用户消息的预览。

所有有效会话都列出，没有空占位过滤。

提议的构建顺序
  1. Session-Git：openprogram/state/memory/session_git/（init、commit、log、checkout），dispatcher.process_user_turn 结束时的后台提交，回填脚本，WS git_session_log 和 git_session_checkout。
  2. 项目模式与界面：注册表，会话元数据的 project_id，WS list_projects、create_project、add_session_to_project，侧栏 Projects。
  3. Project-Git 自动提交：绑定会话的轮后钩子，干净则提交，有改动则警告，加警告横幅。
  4. 回放界面：聊天顶部的 prev、next，时间线视图，调用 checkout 的 WS 动作。
  5. 数据迁移：回填现有会话；把现有 Git 项目导入为 Projects。
