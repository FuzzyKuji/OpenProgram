Checking each write

memory.writer.verify (default off) tests each committed batch, because a fact can land where nobody would look. At least three model calls, three more for a repair.

StepDoes
1. ProbeThe model picks one fact: JSON question, expected answer, chat references; a reference outside the batch is rejected
2. RetrieveA fresh run answers from a throwaway copy without the runtime directory
3. JudgeThe model compares answer and expected
4. RepairOn a mismatch, a run reorganizes the real workspace through the ordinary transaction, given question, answer and failed trace; 2 and 3 run once more
Outcomes
passed, repaired, unrepaired, error, in .scriptorium/verification.jsonl (latest 500) and verification under openprogram memory status
Never
Fails its write
Structured replies

output_schema is a writer-runtime contract: OpenProgramAgent adds the schema to the system prompt and reads one JSON object from the reply, bare, fenced or in a sentence, checking required fields and JSON types. A missing or malformed reply gets three attempts in all.

Failure modes

Failure modes
FailureEffect
No writer processDeferred and retried; the conversation is safe in the session store
Model unreachable mid-writeTurn rolled back whole, nodes unmarked, same turns retried
Lock heldBackground write waits one second, writes nothing and says so; the next turn retries
Redone turn fails tooNothing installed, nodes unmarked
Hand edit through OpenProgram breaks the formatNever installed; committed file untouched, rejected text kept for a retry
Nothing worth keepingA run with no failed edit marks its batch; one whose edits kept failing marks nothing
A later pass could finish (held lock, unreachable model)WriteFailure, retryable: the watcher leaves the session unmarked and tries again; shown only on the Memory page
No later pass could (content refused)WriteFailure, not retryable: marked handled, memory.ingest_ended with ok: false, and memory_writer_failed to open clients, once per streak or change of reason

Failures persist in writer-status.json. Hooks swallow and log their own failures, so memory never takes a conversation down. With nothing owed, including below the threshold, write returns nothing.
