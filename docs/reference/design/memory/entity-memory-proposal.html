Entity memory on Git

Deferred proposal. Entity memory is an immutable record of what happened, traceable step by step: Session-Git stores what was said, Project-Git what was changed. The active Memory is the Source, Topic and Core workspace in Overview; current persistence is in Session storage.

Session-Git lifecycle

StageProposal
CreateLazily on the first message (SessionStore._open(id, create_if_missing=True)): git init, write meta.json, create history/, context/, workdir/. A working directory binds the real project and places the repository inside it; otherwise project_id="default" at the home root.
ValidityDirectory exists and meta.json parses as JSON. Anything else (test leftovers, unrelated directories, corruption) is skipped silently.
DiscoveryScan every <state>/projects/<project_id>/chats/ plus the location index; merge, deduplicate, sort by updated_at descending. Sidebar and Chats page share the rule.
Writeappend_message writes history/NNNN-<role>-<id>.json synchronously and updates the in-memory index; commit_turn commits once at turn end.
Readget_branch(session_id, head_id) walks parent_id to a message list; get_nodes returns raw Call objects; session_commits returns the turn-level log.
Branch, retryDAG retry is git branch retry-<assistant_id>; switching DAG head is git checkout.
Metadata, bindingupdate_session(session_id, title=..., project_id=...) writes meta.json and the index. project_id holds the binding.
CacheIn-memory LRU of SessionLog and SessionMemoryIndex, cap 256 (OPENPROGRAM_SESSION_CACHE_CAP), rebuilt from disk after eviction; per-session lock plus store lock.
Deletedelete_session: drop from cache, close the runtime, remove the directory including .git/ and any location entry. Sidebar menu; Chats page right-click not yet. Provenance pointers dangle and are skipped on query, so the virtual layer needs no cleanup.
Garbage collectionWithout meta.json: skipped. Empty with a default title: listed. Long-inactive: never deleted automatically; any space policy belongs to user configuration, not the store.

Dual write

The dispatcher writes the DAG. After a turn, its nodes are serialized to the repository on a background thread, because a commit takes about 100 to 500 ms. One repository per session and serial commits make conflicts rare; a file lock is the fallback. On startup, sessions without a repository are backfilled once, turn by turn in seq order.

Project-Git lifecycle

StageProposal
Createresolve_project(path, name) when a directory is bound: reuse .git/ or git init, register in projects.json.
Auto-commitAt turn end for a bound session whose agent changed files, committed under an agent user.name so it differs from the user's commits. A clean start alone does not prove ownership when the user edits concurrently, so agent-owned changes must be identified.
ReadProjectGit.log(limit); project_commits(project_id) for the provenance layer.
UnbindRemoves the registration only. The user's .git/ stays; the session's project_id stays as a historical pointer; the session repository stays in the project.

Key invariants

  • The DAG is the source of truth; Git is the mirror. A Git failure does not affect the DAG. A commit without a DAG write is dirty data.
  • One Session-Git commit per turn, not per message.
  • The agent never pollutes the user's working tree: with uncommitted user changes, it skips the commit.
  • Replay is a read-only view; a new message after checkout forks the DAG from that commit.
  • Abstract memory builds on entity memory, never the reverse.

Risks

RiskMitigation
Async commit fails unseenBackground retry; on startup compare DAG seq with commit count and backfill on mismatch
Workdir is not a repositorygit init on the agent's first commit; reuse an existing one
Several sessions edit one projectFile lock serializes project commits; at worst a queue
Going back to turn 5 and sending a messageFork, not overwrite: the DAG's retry, mapped to a Git branch

Relationships

WithRelationship
Commit chainNo conflict. DAG nodes mirror to Git commits, the history that happened. The ContextCommit chain, what the LLM saw, stays out of Git as derived and recomputable; a commit may be exported on request.
Abstract memoryEntity memory is its single source. Distillation reads Session-Git nodes and Project-Git commits into the timeline and graph. Each memory carries a Provenance pointer back; see Virtual memory.
External toolsThis proposal exposes Git log and diff history. Any feature comparison with another tool must be verified before it informs implementation.

Session titles (built)

PriorityRule
1. Typed name/rename or the UI. Never overwritten. "Generate a name" clears the lock, so later retitles can still improve it.
2. Model titleBackground call for 3 to 7 words, sentence case, in the conversation's language, up to 80 characters, through structured output. Runs at turns 1, 6, 16 and 40, and at 2 and 3 after a small-talk opener. Input is an excerpt of the current branch, at most 1000 characters. Failures are logged only. A retitle replaces only the title it started from; the sidebar updates through session_updated.
3. ExcerptSet immediately at the first turn: first line of the first user message, 50 characters, so the sidebar is never empty while the model works.
4. PreviewAt listing time, a session with no usable title shows a preview of its first user message.

All valid sessions are listed; there is no empty-placeholder filter.

Proposed build order
  1. Session-Git: openprogram/state/memory/session_git/ (init, commit, log, checkout), a background commit at the end of dispatcher.process_user_turn, a backfill script, WS git_session_log and git_session_checkout.
  2. Project schema and UI: registry, project_id in session metadata, WS list_projects, create_project, add_session_to_project, Projects in the sidebar.
  3. Project-Git auto-commit: post-turn hook for bound sessions, commit when clean, warn when dirty, a warning banner.
  4. Replay UI: prev and next at the top of chat, timeline view, WS action calling checkout.
  5. Data migration: backfill existing sessions; import existing Git projects as Projects.
