为什么做成派生，为什么是预算而不是拒绝写入的上限
问题影响
块 ID编辑前存在的块 ID 必须都留下，否则事务以 block ID must not be removed 失败。裁掉持有唯一 ID 的文件过不了这关。渲染出的 ID 永远是 topics/ 里某个 ID 的副本。
拒绝式上限一次超限就回滚整个事务，连 Topic 改动一起；此后每条稳定事实都被劝走，core 区冻结。
一种文件topics/core.md 遵守 Topic 契约。validate_writable_path 拒绝写 topics/**/*.md 之外的路径，错误码 READ_ONLY_PATH。
旧的根目录 core.mdpromote_legacy_core 把它一次性移进 topics/。
重整重整提示词要求 topics/core.md 只留对多数交互有用的事实；超出预算不是留下一段的理由。按大小拆分时跳过这个文件。

离开的分支

空闲监视器的强制写入调用 list_branches，跳过已归档分支，再对每个分支端点调用 get_branch(session_id, tip)。已写标记覆盖共享前缀。每轮结束后的写入只走 head。

为什么不要 pi-mono 的摘要节点（branch-summarization.ts）
要点理由
去处pi-mono 只有会话 JSONL 和 AGENTS.md，摘要是被放弃内容唯一的去处。这里事实归 Topic 文件；DAG 上的节点没有脚注和块 ID，检索不到。
又多一处context/summary 的压缩摘要已挂在 DAG 上，服务上下文窗口。再加一种就多一个要找的地方。
没有离开事件head 移动和切换分支都不是事件。写 head 的地方分散在 set_head、append_message、SessionNodeWriter.append、update_session 和回退，SessionMemoryIndex.set_head 直接丢弃旧值。照抄要新增事件并保留旧 head，而这件事放到会话结束时一样管用。
主动放弃不用猜：回退把片段标为 rewound，节点留在图里，离开对话路径。
空闲条件should_incremental_write 在有待写内容且最后一条消息超过一小时时也会触发，离开的分支都满足。非 head 分支先查 token 阈值，所以一轮的重试被跳过。

游标兜底

项行为
claude-code游标是消息 UUID。消息不见了就全部当没写过，因为返回零条会让这个会话的抽取就此停止。
这里的规则账读不出来就是什么都没写，绝不抛出让写入永远卡住的异常。重写一批的代价有限，事务会合并陈述同一事实的段落。
节点标记已写状态是会话节点上的标记（memory_written_scriptorium），没有会读不出来的游标文件。缺标记只造成重复工作。
runtime.json缺失、解析失败或结构不对：RuntimeStateStore.load 返回空状态。这个文件计入工作区版本，恢复的内容不会配上更新的状态。
升级另一种一次性情形，取舍相同：见已写标记。
