Authority landscape

Local interfaces and channels such as Telegram and Discord share one Agent and memory workspace. The design holds the rules.

An unpaired direct message gets an eight-character code, once an hour. An unpaired group message is ignored. Renaming to impersonate the owner does nothing.

Order after a message arrives

  1. Channel ingress. Speaker ID and display name come from platform metadata, never message text.
  2. Pairing. The stable ID is looked up; unpaired messages stop here. Approval comes only from the local CLI or a loopback Web request.
  3. Attribution. speaker_*, the owner principal and authority_tier persist as separate fields.
  4. Capability. _gated_execute checks the fixed table; rules and bypass cannot skip it.
  5. Execution or memory. Paired changes through memory_update are limited by workspace enforcement to create or byte-append.
