Trimming resident content

The resident section is the core of MEMORY.md, rendered from topics/core.md.

openclawOpenProgram
Who writesAutomatic promotion and hand edits, in one fileWriters and people edit topics/core.md; the Runtime renders the section
Limit10000 charactersRender budget core_max_tokens, 2000
When fullRemoves oldest automatic paragraphs, keeps hand-written ones (memory-budget.ts)Renders in file order until the next paragraph does not fit; a heading left with nothing under it goes too
Removal destroys contentYes, so ownership must be trackedNo: the rest stays in the source, indexed and citing its evidence
RunsDuring writesAfter each write, with timeline/, recent_events.jsonl and relations.json
ReportsRemoved dates, to the callerRendered tokens and left-out block IDs, on last_core_block

To keep a paragraph resident, move it earlier in the file. No marker exists for this.

Why a derived section, and a budget rather than a limit that rejects
ConcernEffect
Block IDsEvery block ID present before an edit must survive it, or the transaction fails with block ID must not be removed. Trimming a file that holds the only copy of an ID cannot pass. Rendered IDs are always a copy of an ID in topics/.
A rejecting limitOne overflow would roll back the whole transaction, Topic changes included, and every later stable fact would be sent elsewhere, leaving the section frozen.
One file kindtopics/core.md follows the Topic contract. validate_writable_path refuses edits outside topics/**/*.md with READ_ONLY_PATH.
Old root core.mdpromote_legacy_core moves it into topics/ once.
ReorganizationThe organize prompt keeps topics/core.md to facts useful across most interactions; being past the budget is no reason to keep a paragraph. Size-based splitting skips this file.

Reporting whether anything changed

Reorganization rests on model judgment, and a model that finds nothing to do does nothing. reorganize returns changed_files beside topics, the count of files examined, so an empty list is visible.

Departed branches

The idle watcher's forced write calls list_branches, skips archived branches, then get_branch(session_id, tip) for each. Written markers cover shared prefixes. Post-turn writes follow the head only.

Why not pi-mono's summary node (branch-summarization.ts)
PointReason
Destinationpi-mono has only session JSONL and AGENTS.md, so a summary is the only place abandoned statements can go. Here facts belong in Topic files; a node on the DAG has no footnotes or block IDs and cannot be retrieved.
Another locationCompaction summaries in context/summary already attach to the DAG, for the context window. A second kind is one more place to look.
No leave eventNeither head movement nor branch switching is an event. Head writes are spread across set_head, append_message, SessionNodeWriter.append, update_session and rewind, and SessionMemoryIndex.set_head discards the old value. Copying pi-mono would add an event and retain the old head for work that serves equally well at session end.
Deliberate abandonmentNeeds no inference: rewinding marks a segment rewound; its nodes stay in the graph and leave the conversation path.
Idle ruleshould_incremental_write also fires when anything is pending and the last message is an hour old, which every left branch satisfies. Non-head branches check the token threshold first, so one-turn retries are skipped.

Cursor fallback

ItemBehaviour
claude-codeThe cursor is a message UUID. If that message is gone, everything counts as unwritten, because returning zero messages would end extraction for the session.
Rule hereUnreadable accounting means nothing was written, never an exception that blocks writing for good. Rewriting a batch is bounded, and transactions merge paragraphs stating the same fact.
Node markersWritten state is a marker on session nodes (memory_written_scriptorium), so no cursor file can go unreadable. A missing marker causes repeated work.
runtime.jsonMissing, unparsable or the wrong shape: RuntimeStateStore.load returns empty state. The file counts toward the workspace revision, so restored content does not pair with newer state.
UpgradesA separate, one-time case with the same tradeoff: see written markers.
