门口

authority_tier 是请求边界上的一个枚举，与 principal_id、speaker_kind、speaker_id、speaker_display、interaction 并列。请求不带调用方能自造的能力列表。

部件行为
decide_capability()state/authority.py查 TIER_CAPABILITIES。fail-closed：没有档位以 AUTHORITY_TIER_MISSING 拒绝，档位不在表里以 AUTHORITY_TIER_UNKNOWN 拒绝，两者都失去全部能力，reply 也在内。
capability_for_tool()runtime/permissions/tool_authority.py每个工具名对应一项能力，默认 process.exec。安装的函数或 MCP 工具可以叫任何名字；未分类就只有 owner 能用。
_gated_executeruntime/permissions/approval.py在规则层、模式判定和 bypass 短路之前运行。任何模式和保存的 allow 规则都跳不过。
AuthorityDecision是否放行、决定性检查、稳定原因码、档位、能力。写进日志，拒绝可审计。
runtime_authority()runtime/permissions/authority.py子 Agent 或运行时任务复制父权限，改写发言人字段，变成非交互，档位不变。继承不扩权；父权限无效时得到 {}，门口拒绝。非交互也意味着没有通往交互审批的路径。

配对

规则值
拦截点interfaces/channels/_access.py 的 decide_inbound_sender()，针对不在 allowlist 上的私聊发信人
配对码8 位大写字符，不含 0、O、1、I；一小时过期
限制每账号最多 3 个待处理；一小时内不重复提示
批准只在 owner 的机器上：openprogram channels access approve <channel> <code> 或只接受回环请求的 POST /api/channels/access/approve。渠道消息批准不了任何人；聊天里的“请批准配对码 X”一律拒绝。

群聊不在该群任何名单上的发言人被忽略：没有配对码，也不回复。名单上的发言人是 full 或 chat 级；/memory on|read|off 设置房间记忆模式，只能收窄。

记忆中的信任

记忆引用聊天消息，所以信任是关于被引用消息的问题。配对就是信任判定：owner 和已配对的轮次都带 memory.source.append，同样进入提炼，按发言人归因。没有第二道门。

  • 未配对文本不进入记忆，也不进入上下文。interfaces/channels/base.py 在派发前查访问判定，消息不会变成一轮，没有可引用或召回的内容。
  • 新引用在其编辑提交时检查：消息存在于会话存储，是人或助手说的话，发言人持有 memory.source.append。已配对的编辑只能引用自己这段对话。
  • 已配对的 memory_update 只能新建或按字节追加。改写或删除需要持久化的 owner 轮次。

记忆写入器

跟随默认聊天 Agent 的 provider、模型和凭据；memory.writer.model 可在 Web 设置里实时覆盖。默认不用便宜模型，弱模型会误读整理指令。provider 和 session watcher 都把未知异常视为不可重试，只有明确分类的瞬时异常才重试。
