Knowing which turns memory has written

A session is a DAG: re-asking, retrying and spawning fork it. Every branch belongs in memory; a shared prefix belongs there once. The record of what is written is a mark on the turn's own node.

The idle allowance in should_incremental_write does not apply to abandoned tips: their last message is old by definition and every retry would pass. Rewound turns never arrive; get_branch filters them.

The absence of an error is not a product. Measured: twenty turns on one rejected edit, a successful return, a one-byte topic file.

  1. Install the topic files in a transaction, whole or not at all. Footnotes link the chat messages, so no evidence is copied.
  2. Mark the batch. A crash between the two is a redo; the reverse order would lose turns silently.

Lost marks and bad bookkeeping

Reprocess rather than go silent. An unreadable runtime.json loads as an empty state. A walk that meets no mark offers the whole branch; the writer sees existing topic files, so a known fact is left or merged.

The legacy cursors field is ignored and nothing seeds marks from it: its ordinal is the value forks corrupted. An upgraded session costs one larger write.

Why a mark

Why not a position cursor

One ordinal per session, compared against a row's position in the flattened branch. An ordinal describes the flattening, not the message: the same message gets two numbers on two lines, different messages at one depth share a number, and rewind or compaction shifts every later row. It also counts rows memory skips, so the figures below are measurements.

The long case is worse: a fragment starting mid-conversation, reported as success. A monotonic counter cannot go back to a fork point, and a counter and a branching conversation are different shapes.

  • The set is more exact: the walk assumes marks form a prefix, which holds because batches are oldest-first but is not checked.
  • Its cost decides it: sessions already record per node where a turn came from and whether rewind retired it.
  • A marker node pointing at the turn (pi-mono's shape) would put a node in the graph per batch for every reader to skip.

  • Nobody puts the record on the turn. openclaw's promotedAt comes closest, on a derived record.
  • Two shapes are in use: coarsen the unit until branching stops mattering (codex-cli, openclaw, hermes-agent), or derive the delta from the tree (pi-mono). Coarsening gives up writing from a live session.
  • Their fork failure is duplication, which nightly reorganize can merge. A position cursor's is omission, which nothing recovers.
  • Taken: reprocess rather than go silent. A lost position counts everything again, because counting nothing would stop extraction for good.
