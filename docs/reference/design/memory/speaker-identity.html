Speaker identity

Several people can share one agent and one memory workspace. Each turn carries its speaker in trusted fields; the body stays as sent.

A session row holds one peer, so identity goes on every message. Routing: openprogram/interfaces/channels/_session_routing.py. Its session_scope values derive from openclaw's dmScope.

How identity travels

One call site covers every channel: channels/base.py is the only caller of dispatch_inbound. peer_id stays the routing target, the group in a group chat. Label: display (id), or whichever half exists, else the role.

JSON encoding escapes LF, CR, quotes and backslashes; the renderer also escapes U+2028 and U+2029. Decoding recovers the exact body. Older stored turns may begin [Bo (4402)]; that text is body too.

Design choices

QuestionChoiceBecause
Identity in the body or in fields?Fields onlyThe body can be forged, and parsing a label back from content would make the forgery a filter key. The live agent reads the envelope (speaker_kind, speaker_id, speaker_display, content), so the Web transcript shows what the sender typed.
Stable id in the label?Yes, as in openclawName alone: a rename makes two people, a shared name merges two.
Direct messages too?Every channel messagesession_scope: main puts direct peers in one session, and the scope is resolved below base.py.
Clean display names?Yes; no escaping systemnormalize_identity_header_part: collapse whitespace, drop non-printable characters, [ ] to ( ), : to its full-width form, cap at 64 characters. Same rules as openclaw, plus the colon and control characters.
Clean the body?NeverRewriting [ at line heads breaks Markdown links, lists, logs and pasted code. No rule separates [2026-08-09] INFO ready from a forged label.
How does a body reach the writer?Separate JSON fieldsFields hold ref, speaker, content apart; no handwritten headers, XML or fences. openclaw's rule for enclosures (the content cannot close them) holds here by construction.
Strip anything from history?NothingThe body carries no added label, and there is no per-turn metadata block.
Memory per person?No: one shared workspaceIdentity is attribution, not access control; a team bot lets others use what one person told it. A person is a page in topics/people/, where a rename or second channel is reconciled. Separate memory means a separate instance (openprogram --profile <name>).

Asking about a person

QuestionAnswered by
What is known about Ada?memory_search with path_prefix=topics/people/

Topic paragraphs are the writer's prose, which nobody said, so memory has no speaker filter and keeps no copy of chat bodies.

Implementation status

StatusItems
SpeakersImplemented. Trusted transport, ChatTurn.speaker_label, JSONL writer input, footnotes to chat messages. Local Web and CLI turns persist owner/local; older nodes without trusted fields stay speakerless.
AuthorityImplemented. Speaker, instance owner and tier are stored apart; the owner principal owner/install/<16 hex> comes only from owner.json in the state directory; an embedded run has its own per-process one. Tiers: owner (all capabilities) and paired (reply, memory.read, memory.source.append, runtime.wait). Tool calls are checked by decide_tool_authority. Continuations, Tasks, inbox, subagents and subprocesses can only inherit a tier. Unpaired messages never enter the agent and are not recorded. Paired memory_update may only create or append.
Memory writingImplemented. Branch-aware written markers; the writer uses the default agent's model and credentials, or memory.writer.model. memory.backend=none disables injection, recall, writing, organizing and memory threads, and rejects CLI memory verbs and /api/memory/*. Tools, CLI and Web report last success, failure code from a closed enum, retryability and pending count.
Not yetHold queue for over-tier requests. Read filtering by requester tier is partial.
