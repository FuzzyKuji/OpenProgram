实体记忆（提议）Session-Git，每会话一个仓库、每轮一次提交；Project-Git，智能体编辑时自动提交。原始、不可变、完整暂缓
抽象记忆（提议）Timeline、Graph、不超过 2 KB 的 Core.md，由实体经五阶段带出处蒸馏。召回只注入这一层，模型用工具回溯Graph 视图和实体召回暂缓

记忆是 Markdown 工作区。提议的层不是事实来源，写入器也不依赖它们。

原则

原则含义
带出处Topic 链接到 Source 帧。实体层还会增加 (project, session, commit, timestamp)
双时间每条记忆记录 event_time 和 ingestion_time，支持时间回溯查询和矛盾检测
限定范围的召回Runtime 注入活动 Core，并提供 Source 和 Topic 上的记忆工具。Git 导航只是提议
Git 原生只限提议的实体层

实现状态

领域状态
权限出处SessionDB 写入器和 memory_update 都从持久化的轮次权限构建，绝不取自载荷。没有出处的 Source 按失败关闭
自动写入器读取 SessionDB 分支，在来源节点记录处理结果，默认用聊天 provider 和模型（可由 memory.writer.model 覆盖），经分阶段事务安装
接口记忆工具、CLI、Web UI、写入器状态、一次性可信 Source 回填、memory.backend=none 保护、从 SessionDB 到 watcher 状态的组合测试
引用新的 Topic 引用必须解析到本事务证据中的 trusted Source 帧，因此任何工具路径都不能引用 pending Source
失败状态文件、CLI、工具、API、Web UI 共用一个封闭的 MemoryWriteFailureCode 分类。空闲 watcher 在跨进程锁下持久化每个结果。未配对群归档有速率和存储上限
读取过滤memory.read 是独立能力，读路径接收调用方层级，依赖 pending 证据的块不进入召回和 Core
仅设计按层级隐去块内容、hold-and-approve 请求、分支语义出处、跨会话 spawn 关系、实体 Git 层、Graph 视图、事件驱动的写入器通知
