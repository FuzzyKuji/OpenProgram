用量计量

每次 LLM 调用都记录 token、模型、费用和来源，可按模型、来源、会话和时间聚合。模块是 openprogram/models/usage/。

三份记录，三个问题

记录位置回答写入者
消息列助手消息历史这条消息花了多少（每条消息的小标签）runtime/conversation/turn_runtime/persistence.py 的 persist_assistant_message
压缩预算会话 meta 的 _usage上一轮真实输入 token、缓存命中率、是否压缩；亚微秒读取runtime/context/usage.py 的 UsageTracker.record_turn
账本~/.openprogram/usage.db，随 profile跨会话、模型、来源和时间的总花费models/usage/recorder.py 的 record_message

三者消费者和生命周期不同，互不读写。会话 meta 是基于 git 的累计快照：不能跨会话聚合、按时间查询或按模型索引，子进程写它还会争抢 git 锁。

采集点

models/providers/streaming/stream.py 包住 stream() 和 stream_simple()，complete_simple() 也经过它们。经过这里和被记账是同一件事。记忆、压缩摘要、mixture_of_agents 和 Agent 方法子进程都走同一点，各自带 usage_scope。

规则原因
在这里，不在 api_registry每个 provider 在 Protocol 后面各有 stream_simple，在那里采集要改 Protocol 或到处包装。stream.py 已经拿着带价格的模型和最终 usage。
在终止事件、yield 之前，由 recorded 保护agent_loop 收到 done 就返回，生成器停在 yield，循环之后的代码永远不执行
不阻塞流式只在 done 或 error 上触发一次
失败的回复也记录已到达提供商、没有最终消息就结束的那次尝试可能被计费。record_failed_request 记下它最后一个部分消息上报的 token；没有上报时记一条 tokens_known 为 false、费用为 unknown 的事件。到达的依据是已流出内容、已上报 token，或回复静默满空闲上限；适配器的 start 事件不算。被拒绝的请求和在任何内容之前就断开的连接不记录。
尽力而为计量失败只记日志，绝不打断回复。结算预算或 Goal 回执的调用方使用严格的事件构造。
不新增定价providers/catalog/models.py 的 calculate_cost

UsageEvent

每次调用一行冻结记录。SCHEMA_VERSION 为 2。

分组字段
身份event_id（uuid；INSERT OR IGNORE 让重试幂等）、ts
归属session_id、parent_session_id、agent_id、call_kind、call_label、origin_pid
预算job_id、budget_scope_id、reservation_id、request_id、goal_id、goal_revision、goal_session_id、execution_id
模型provider、api、model_id
tokeninput_tokens、output_tokens、cache_read_tokens、cache_write_tokens、total_tokens（不小于四项之和；汇总按各项相加，缓存 token 一定计入）；tokens_known 区分未上报和零
费用，美元，扁平便于 SUMcost_input、cost_output、cost_cache_read、cost_cache_write、cost_total、cost_source（model_catalog、configured、provider_reported、unknown）
延迟first_token_ms 到首个任意内容；first_text_ms 到首段可见文本。在 streaming/first_token.py 测量，随 Usage 携带，没有则为 None。参考 magpie 的 TTFT（yetone/magpie，MIT）。
提示缓存prefix_hash、break_at、break_cause、expected：请求的缓存前缀在哪里断开、为什么（提示缓存前缀）
来源token_source（provider_usage、anthropic_count_api、estimate），面板可标记估算值；schema_version

call_kind 是字符串，新增调用方无需改这里：chat、exec、compaction、summarize、memory、subagent、tool、title、prediction、permission、direct（默认）。

存储

标准库 SQLite，WAL 模式支持子进程并发追加。

表内容
usage_events只追加事件。索引：时间、模型加时间、会话、类型加时间、job、Goal、预留、预算范围；request_id 唯一
usage_requestsGoal 请求回执：prepared、started、settled、released
route_events故障切换。不是用量，聚合不读
probe_eventsOpenProgram 为自身发出的请求：探测日志。不是用量
prefix_baselines每个提示缓存通道上一次得到回复的请求，下一次请求与它比较。不是用量

同时改事件和预留的步骤先提交事件，中途停止时敞口仍被占住，并有事件可供识别，绝不会有花费却无记录。

Agent 方法子进程
  • 子进程直接写共享数据库，带 origin_pid。账本是事实来源，父进程不重复计数，结果 pickle 不带用量。
  • process_runner.py 用 spawn：父进程已加载 PyTorch、libomp 和 Cocoa，fork 后会 SIGSEGV。spawn 不复制 contextvar，所以 run_agentic_in_subprocess 把 snapshot() 作为 usage_ctx_snapshot 传入，子进程在 os.setpgrp() 后应用。
  • _connect() 发现 os.getpid() 变化就重新打开，因为句柄不能跨进程使用。
  • SIGKILL 时已追加的事件保留且为真。被杀掉打断的调用不记录：绝不捏造。
