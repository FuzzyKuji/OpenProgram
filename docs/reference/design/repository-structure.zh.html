仓库结构

OpenProgram/
  apps/
    web/         Next.js Web application
    desktop/     Electron desktop application
    cli/         Ink terminal client
  openprogram/   Agent core, Python SDK and the Python interfaces
    interfaces/server/  FastAPI, HTTP, WebSocket, authentication, static hosting
    interfaces/cli/     Python CLI: parser, dispatch, Rich fallback, setup
  tests/         Python tests: layer / product domain
  docs/          User documentation and design records
  scripts/       Development, validation and release tools
  references/    Reference implementation snapshots
  website/       Official website source
  pyproject.toml Single Python aggregate-project configuration
  uv.lock        Sole Python lockfile
  package.json   npm workspace entry
  package-lock.json  Sole npm workspace lockfile

原则

原则含义
核心与应用分离核心领域绝不依赖应用。核心没有兼容命名空间：Server 和 CLI 模块以 openprogram.interfaces.server.*、openprogram.interfaces.cli.* 导入。
沿可验证的边界拆分只有具备独立输入、输出和测试入口的代码才移动。仅因文件长而引入 mixin、manager 或 facade 不算拆分。
公开接口稳定CLI 命令、HTTP/WS 协议、端口、用户数据目录、必要的 Python 导入。每个应用单独移动、验证、提交。
设计与实现记录分开本页是长期结构；仓库结构实现记录位置、兼容和验证。历史看 Git。

Python 核心与打包

方面规则
核心顶层只放能独立解释的领域：runtime/、programs/、models/、state/、host/、extensions/、operations/、interfaces/。子能力放在所属领域内，如 Context 的 Git DAG 在 runtime/context/git/。
Serverroutes/、ws_actions/、server_runtime/ 和顶层模块；openprogram.interfaces.server.server 组装应用。每个模块只有一个名字、一份状态。
CLIapps/cli/ 只有 Ink 客户端（src/、tests/、package.json）。openprogram.interfaces.cli 从 application.py 重新导出 main 和 build_parser。
分发一个用户可安装的 openprogram wheel，含核心、Server 和 Python CLI，由包发现找到，wheel、可编辑安装和检出共用一种布局。不建无成员的 [tool.uv.workspace]，不拆三个公开发行包。
packages/不创建。只有第二个共享包具备稳定公开入口且至少两个使用方时才重新考虑。
Profile 状态工具配置、收藏等写入 ~/.openprogram[-profile]/，绝不作为源码或 wheel 种子。兼容读取只查旧的 openprogram/webui/ 位置，一次性复制到 profile 状态，绝不依赖 Server 模块路径。
Skills不随安装分发；内置工作流由 Programs 提供。openprogram/extensions/skills/ 只负责从远端缓存、插件、~/.openprogram/skills/ 和 <cwd>/skills/ 加载兼容 AgentSkills 的技能。没有 skills_bundled/ 或隐藏副本。
测试tests/<layer>/<product-domain>/test_*.py，按实际最强依赖选层；见测试体系。
不算结构__pycache__/、.DS_Store、构建产物和 Finder 冲突副本保持忽略。用户安装的 programs/packages/ 检出是产品数据，重组时保留。

Node 工作区与脚本

方面规则
React 版本Web 固定 React 18，Ink CLI 固定 React 19。npm 提升可能让共享 peer 互相影响，所以私有根包声明精确的 React 18、react-reconciler 0.29 和类型版本作为布局约束。CLI 的 React 19 和 react-reconciler 0.33 留在自己的工作区；它不使用从根解析 React 的第三方 hook 包。
脚本归属单个应用放 apps/<name>/scripts/，跨应用开发和验证放 scripts/，运行时、安装器和发布放 scripts/release/。
公开安装器scripts/install-release.sh 是兼容入口。完整检出时运行 scripts/release/install-release.sh；单独下载时，从同一受验证仓库和不可变 tag 取该文件到临时文件后运行。
固定路径scripts/install.sh、scripts/install.ps1、scripts/refresh-local-app.sh、scripts/promote_stable.sh。本地刷新复用 scripts/release/ 的暂存和版本校验工具。
根目录文件只有两种生态的入口文件和 lockfile、项目元数据、入口文档。.github/ 是仓库基础设施。

大文件

文件状态规则
apps/desktop/main.js组合根，约 2000 行；纯逻辑在 main/windows/menu-geometry.js、main/worker/worker-recovery-state.js、main/web-views/tab-transfer-validation.jsHTTP 探测、进程和窗口生命周期、原生 WebView 归属、传输协调和菜单托管，都要有执行级验收才移动
apps/web/lib/desktop/desktop-bridge.ts小的聚合入口；状态、恢复、传输、菜单、事件和表面在 bridge/；类型在 desktop-bridge-types.ts 和 desktop-transfer-types.ts保留聚合入口
运行时状态机模块不变量集中不按长度拆；只因职责可独立验证或存在重复实现才拆。不引入 mixin 层。
大型 Web 和 Desktop 检查脚本夹具、场景和结构断言混在一起先提取共享夹具和可独立执行的场景；保留命令入口；不为缩短文件引入测试框架

文档

类别位置
用户文档start/ install/ capabilities/ interfaces/ models/ integrations/ server/ reference/；进入公开导航和搜索
当前设计reference/design/，按产品领域；UI 文档分为基础、对话编辑、浏览器标签、设置/目录和工作区

README根目录：产品。openprogram/README.md：核心 SDK。openprogram/interfaces/server/、apps/web/、apps/desktop/、apps/cli/：各入口当前的职责、依赖方向和验证命令。

取舍

选项结果原因
根目录 openprogram/ 核心加 apps/采用核心仍是顶层项目入口；非 Python 客户端在 apps/ 下一目了然
只移动的应用迁移采用先改路径、构建、导入和脚本，之后再拆，避免同时改行为
用导航分组组织文档采用批量移动会破坏旧链接
把 openprogram/ 改名为 backend拒绝它是 Agent 核心和 SDK；Server 只是一个应用入口
Server 留在 openprogram/webui/拒绝混杂服务器代码、旧静态 UI、构建产物和 Web 命名
按固定行数拆分拒绝行数不等于职责，容易产生只转发的模块
依赖注入框架拒绝模块函数和显式参数足以保持边界
一次提交移动所有应用拒绝无法评审

必须保持的事实

分层

边界规则
核心包interfaces/ 之外的 openprogram/ 没有 FastAPI 路由或 WebSocket 处理器；没有前端或 Electron 源码，没有持久化的前端构建产物。
接口openprogram/interfaces/server、apps/web、apps/desktop、apps/cli 各有自己的入口、README、测试和构建命令。
CLIopenprogram.interfaces.cli.main 和 build_parser 保持可导入，完整命令树、控制台脚本和 TUI 不变。
端口默认端口 18100；一个 Worker 提供 API、WebSocket 和 Web 静态文件，没有双端口 Next.js Server。
Web 与 Electron浏览器和 Electron 加载同一 Web 应用；Electron 专属能力只经 preload/IPC。
Agent HarnessAgent Harness 导入 openprogram 时不依赖 Server、Web 或 Desktop。

构建与状态

  • 没有旧静态 UI 和旧双端口实现；核心没有 Server 或 CLI 兼容命名空间。
  • 前端构建产物只进被忽略的构建或暂存目录和最终发行物。
  • 可变 profile 状态不在源码树和 wheel 中；旧的包内 JSON 只作升级输入，不被跟踪。

文档与仓库

边界规则
发布的文档docs/ 下除构建输出和纯静态目录外都发布；工程记录在 docs/reference/design/；所有公开链接有效。
设计导航设计导航按产品能力分组；源文件路径不变。
顶层目录Git 跟踪的顶层目录在结构契约中声明。开发脚本不放根目录；没有实现的源码检出模块入口由契约单独列出。
源码根路径README、技能和安装说明不提已删除的源码根路径；根目录没有 web/、desktop/、cli/。
包 README顶层 Python 包目录 README 与 __init__.py docstring 同步。
结构批次每批结构改动单独提交，通过直接受影响的测试后再做规格和质量复审。
