测试体系

运行依赖决定层级；产品领域跟随 openprogram/ 的模块名。一个测试符合多个层级时取依赖最强的。每个生产缺陷在最低公共边界有一个回归测试。

深度最多到层级和产品领域；层级根下没有受跟踪的测试。Marker 只描述能力：slow、browser、sandbox、live、macos。严格 marker、严格配置、严格 xfail；默认 -m 'not live and not browser'；单个测试超过 120 秒失败。

隔离

  • 仓库契约只读 Git 受跟踪文件，所以干净检出和含忽略文件或嵌套仓库的检出结果相同。通用扫描器的根由调用方提供。
  • 顶层 conftest.py 只保留防止访问真实用户状态的隔离；领域 fixture 留在本地。临时 HOME 确定性清理。
  • 并发结果用 Event、Condition 或带截止时间的等待。
  • 测试不替换全局线程类，也不创建真实线程或线程池。生产模块内的后台资源在 teardown 时 join 或关闭。
Unit 守卫
  • 结构契约检测直接和别名的资源导入、直接的 sleep 导入和线程类替换。
  • Autouse 运行时守卫拦截测试代码里的线程创建、线程池构造和固定等待。
  • 只允许模块限定的 asyncio.sleep(0)（位置或关键字参数）作为调度让出。
  • 合并轮次测试自有临时 SessionStore。fixture 构造后立即注册关闭，任何结果都会在守卫运行前排空索引写入并 join 定时器。
  • 历史页对象用本地名 historyWindow，让浏览器 window 的源码检查不产生歧义。
  • 本地刷新的测试仓库包含真实的 ASAR 权限恢复 helper，版本变更拒绝在 staging 之后运行。

日常改动只跑 scripts/testing/affected_tests.py。全量就是下面这些任务，在 CI workflow 里，发布前手动启动。

验收

  • 没有未处理线程警告（警告即错误）；固定 worker 连续三次无 worker 崩溃。
  • 必需的 Python 套件零失败；已知缺陷不能留在完成状态。
  • 无前端产物的 component 行为和带构建 CSP 的 e2e 行为分别验证。
  • 迁移时记录测试数、skip 和 xfail 的变化。
  • npm 风险按工作区审计，只用兼容升级，绝不 npm audit fix --force。
  • 顶层契约阻止根目录开发脚本、未声明目录和已删源码路径回到指南。
修改测试体系

一次一批：经公共或共享边界复现，修最小的共同原因，跑受影响测试，通过独立规格和质量评审，提交。不实现 Python 控制流解释器，也不按行数拆测试。
