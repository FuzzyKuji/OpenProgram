Test system

Runtime dependencies decide the level; product domains follow module names in openprogram/. When a test fits several levels, the strongest dependency wins. Each production defect gets one regression test through the lowest public boundary.

At most level and product-domain depth; no tracked test directly at a level root. Markers describe capabilities only: slow, browser, sandbox, live, macos. Strict markers, strict config, strict xfail; -m 'not live and not browser' by default; one test over 120 s fails.

Isolation

  • Repository contracts read only Git-tracked files, so clean checkouts and ones with ignored or nested repositories give identical results. Callers supply roots to generic scanners.
  • Top-level conftest.py keeps only what prevents access to real user state; domain fixtures stay local. Temporary HOME has deterministic cleanup.
  • Concurrent results use Event, Condition or deadline-based waits.
  • Tests do not replace global thread classes or create real threads or pools. Background resources in production modules are joined or closed at teardown.
Unit guards
  • Structural contracts detect direct and aliased resource imports, direct sleep imports and thread-class replacement.
  • Autouse runtime guards intercept thread creation, pool construction and fixed waits in test code.
  • Only module-qualified asyncio.sleep(0), positional or keyword, is allowed as a scheduling yield.
  • Merge-turn tests own their temporary SessionStore. The fixture registers close right after construction, so every outcome drains index writes and joins timers before the guard runs.
  • History-page objects use the local name historyWindow, keeping source checks for browser window unambiguous.
  • Local-refresh test repositories include the real ASAR permission-restoration helper, so version-change rejection runs after staging.

Acceptance

  • No unhandled-thread warnings (they are errors); three consecutive fixed-worker runs with no worker crash.
  • Required Python suites have zero failures; known defects cannot stay in a completed state.
  • Component behaviour without frontend artifacts and e2e behaviour with built CSP are verified separately.
  • Test-count, skip and xfail changes are recorded across migrations.
  • npm risks are audited per workspace with compatible upgrades only, never npm audit fix --force.
  • Top-level contracts stop root development scripts, undeclared directories and deleted source paths returning to guides.
Changing the test system

One batch at a time: reproduce through a public or shared boundary, fix the minimum shared cause, run affected tests, pass independent specification and quality review, commit. Do not implement a Python control-flow interpreter or split tests by line count.
