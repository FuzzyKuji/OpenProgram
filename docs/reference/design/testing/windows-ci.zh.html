Windows CI 完成

原生 x64 和 ARM64 作业用四个 worker 运行平台契约和完整单元测试。被阻塞的诊断进程和普通失败的测试都必须输出详情并以失败退出。

关注点规则
过长的测试 ID大型参数化载荷使用显式的短 ID：pytest 把节点 ID 写入 PYTEST_CURRENT_TEST，Windows 环境变量值上限低于 32767 字符。载荷字节不变。
POSIX 断言权限位检查只在 POSIX 上运行；目录往返测试在 Windows 上照常运行
输出Python 不缓冲；单元测试结果带测试名；成功和失败都上传完整输出和 traceback 文件
挂起进程级 traceback 截止时间取代 pytest faulthandler 插件，并覆盖报告和退出；步骤和作业都有时限
失败的测试保持非零退出码；不删除测试，也不当作通过
截止时间同步截止时间是看门狗，不是性能断言
Fixture 归属和文档读取
范围规则
文档发布打开时按设备和 inode 绑定文件身份，并在描述符和路径两套 stat API 内分别比较元数据稳定性，因为 Windows 的时间戳表示可能不同。任一 API 内发生变化或内容版本不匹配，都拒绝发布并保留原始字节。
文档路由 fixture隔离 HOME 和 USERPROFILE，用原始路径函数解析状态，使惰性导入跟随当前环境
历史归属 fixture构造后立即注册 SessionStore.close；关闭时在生产线程收尾守卫运行前取消并合并延迟的索引写入线程
跟踪派发 fixture保留 JobRunner，获取后立即注册清理；先请求不等待的单例关闭，再合并 dispatcher、reconciler 和 budget 线程，最后关闭 SessionStore
子进程事件清理断言回调阻塞时结果已返回，然后释放并合并回调线程；准备和主机调度时间不算延迟
