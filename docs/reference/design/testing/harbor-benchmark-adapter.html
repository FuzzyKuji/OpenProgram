Harbor benchmark adapter

Harbor datasets such as FrontierHarness Eval score a coding agent inside each task's container. scripts/benchmarks/harbor_agent/agent.py makes OpenProgram one of those agents: it installs the CLI in the container, runs the instruction with openprogram --print, and hands Harbor the run's tokens and cost. The openprogram package never imports it, and Harbor is not an OpenProgram dependency.

ConcernRule
Code under testA wheel built from one commit and uploaded, or a published Git ref; exactly one. A Git ref must arrive as a string: Harbor reads --ak values as JSON, and a commit id that reads as a number is refused rather than rewritten
InstallAs root, by a pinned uv, on a uv-managed Python 3.12 apart from the task's own; readable by any agent user. Every dependency is held to the commit's uv.lock by a required constraints file, so every trial runs the same code; the installed versions go into the trial's logs. curl is installed only when the image lacks it. A bundle of the same install, packed once per commit, is unpacked instead on an x86_64 glibc image: seconds, no network
KeyHarbor resolves it for -m (or --api-key-name) from the host; it reaches only the run command, under the provider's own variable (OPENAI_API_KEY; --ak key_env= names another). Nothing logs in or is stored. A missing key stops the job before any trial starts. A credential found in the state when the run ends is deleted
Model-m is OpenProgram's provider/id; --ak provider= renames the provider when Harbor and OpenProgram differ
RunAs the task's agent user, in the image's working directory. The instruction reaches --print=- on stdin, never as a flag; stdout (events) and stderr go to separate files. No tool-round limit; approvals refused; core files off, so a process that aborts leaves nothing in the graded directory
Run noteBeside the instruction, every request tells the model that no one is watching and it must carry the task to the end, sent once and with the same bytes every round so the provider's cache keeps matching. Shell commands read /proc on Linux, so an image without ps runs them
RequestThe product's own: system prompt with the working directory and shell, and the tool list in the next row. The first user message carries the date and the run note in front of the instruction; a container's fresh home has no memory, so no memory map is sent. The date is the only part that differs between runs on different days
ToolsThe product's default 27 loaded: files and shell (bash, read, write, edit, apply_patch, glob, grep), background jobs, sub-agents and goals, todos and reminders, four MCP tools, tool_search, and on a macOS host computer_use_agent. 31 more (web_fetch and web_search among them) wait behind tool_search. Sub-agents, goals and reminders count in the score and the cost. --no-web drops every web tool and provider search. Captured on a macOS host; a Linux container's list is not yet checked
Workspace--no-project-binding: nothing is written into the graded working directory, so there is no marker to clean up
FailureA non-zero exit, a missing usage summary, or one that is not completed with at least one model request fails the trial. The error's type comes from the usage summary alone, never from the run's output, which holds the model's text. A run the provider ended, before its turn or after OpenProgram's own retries in it, is reported by its cause (authentication, rate limit, server, network, unknown model), and a turn that ended on a stream idle bound as a stalled response, in whatever words the provider's reader names it. The classification --print records where it caught the exception (error_kind, error_reason) is looked up first; a build that records none, or a dropped connection the reason does not tell from a stall, is read from the error's wording. Every other failure is the plain non-zero exit, the agent's
TimeoutWhen Harbor's agent timeout ends the run, OpenProgram gets SIGTERM: it cancels the turn, waits up to 30 seconds for it to stop (2 seconds from the cancel once a second signal comes), writes the usage summary and the transcript, and exits 143, whenever a further signal lands
FinishAfter every run, whatever ended it (success, failure, Harbor's timeout after the stop): OpenProgram's state in the agent's home is copied to agent/openprogram-state/ of the trial without auth/ and cache/, then the credential is deleted; a named profile's state goes to openprogram-state-<profile>/ the same way. The step fails when any credential is left. It runs as the agent user, whose home holds the state; a failure is logged and never replaces the run's own outcome
RebuildThen, when the run left no transcript (killed outright, or out of memory), openprogram transcript builds it from the state the run left, with the code --transcript-file runs. A transcript already there is kept. The order is fixed: stop, copy the state and delete any credential, rebuild
ExitNo model request beside the turn (a title, a branch name, topic sorting), and no hand-off to memory, which past its threshold is a model run; the next worker's idle pass writes the conversation into memory.
Leaving after a stopThe command waits on an event the turn sets, not on its thread: on Python 3.12 a signal during Thread.join marks a running thread stopped. A turn still busy when the wait ends has the commands it was waiting on stopped, since each runs under a supervisor that outlives the process; the process then leaves without the interpreter's shutdown
Further signalsOnly the first is raised; its handler holds the rest. A signal noted while the run stops leaves once the files are written, one while the interpreter joins its threads leaves at once, and from the exit callbacks on they are ignored, so the status stays the first signal's (143 for SIGTERM)
Evidence--transcript-file writes the turn as stored, one JSON line per record: each model request with its time and tokens, the reasoning, reply text, tool calls with full arguments, and each tool result with its time; nothing scrubbed. On the host it becomes Harbor's trajectory.json (ATIF), one step per request, for harbor view
Killed outrightA process killed outright writes neither file; its transcript is rebuilt from the state (see Rebuild), and its state copy holds the session log with the turn's journal and the usage ledger with each request's tokens
Tool resultsEach result comes from the turn's journal in the session log; one the journal lacks falls back to the store's 4,000-character preview, with complete false
Result sizeThe output is the result as the model read it: at most the model's tool-output weight (10,000 by default, a CJK character weighing 1 and any other 0.25) or 30% of its window, the whole text in a file the model pages with read; the shell tool keeps the end of a long output and says how many bytes it dropped
NetworkThe provider's public API host from Harbor's registry is reported, so an allowlisted task opens it

The full run

scripts/benchmarks/frontier_eval.py runs a target: a file in scripts/benchmarks/targets/ holding the whole method of one evaluation, each part with where it was published. Comparability comes from a control harness in the same job, not from published numbers taken under other conditions.

TargetTasks × attemptsModel, effortControl

  • Job: OpenProgram and Harbor's own adapter for the control harness at its pinned version, given the target's reasoning effort, on the same tasks, model and network. Harbor 0.25.0, the target's retry policy (applied by the launcher), which rate it publishes, the environments it counts as comparable (Runta) and its prices are all in the file.
  • Time limits: each task's own agent timeout, 600 to 1,800 seconds for the 21 tasks, as in FrontierHarness. Its runner also limits one task's whole harbor run -r 2, retries included, to 5,400 seconds. Harbor has no such limit, so the summary counts the kept trials that ran longer; deleted retries' time is missing from it.
  • Departures: another model, fewer attempts, a subset of tasks, a timeout cap, an agent environment variable, no control, a non-comparable environment or another Harbor version are each written into the run's record with methodology_comparable: false.
  • Effort: both agents get the target's reasoning effort, OpenProgram through --print --effort; --effort on the launcher sets another for both, a departure. A build whose --print takes no --effort runs at its Agent's default, a departure too.
  • Web: the target's disable_web_search (false in every target, as in the published runs) goes to both agents alike when true, and is written into the run's record.
  • Pilot: run --pilot runs the target's eight pilot tasks, a recorded departure. They are fixed from FrontierHarness v1's per-task pass share in three tiers: hard (0.2 or less) kv-store-grpc, dna-insert, extract-elf; medium (0.3 to 0.5) chess-best-move, gcode-to-text; easy (0.8 or more) regex-log, sanitize-git-repo, build-cython-ext.
  • Check: Docker, the Harbor version found, the key, free disk.
  • Build: a wheel and constraints from one commit by git archive, so an unpublished commit works; the bundle for local Docker. Before uv build the commit and build time are written into the source as openprogram/_build_info.py, so the installed --version and every run header name the commit without the launcher's record beside them.
  • Retries: Harbor retries nothing (max_retries: 0). After it exits, the launcher runs up to the target's max_retries rounds. Each moves the trials Harbor's RetryConfig would retry, and failed verifier setups, to jobs/<job>.retried/<trial>/<n>/ with a ledger line, then runs harbor job resume.
  • Retry folder: beside the job, because resume deletes any folder in it without a result.json. No round starts once the budget is spent or the job was stopped.
  • Budget: stops the job once every attempt so far costs that much. Each OpenProgram attempt appends its cost to a ledger beside the job, and every attempt set aside, of either agent, has its line there with the reason.
  • Dropped attempts: --rerun-infra writes each one to the ledger with its reason, keyed by trial name and start time, so a control trial rerun under the same name keeps both costs.
  • Resume: refused when the wheel, the bundle or the target changed. --rerun-infra moves the trials counted as infrastructure or cancelled aside and runs them again; the retry rounds go on from where they stopped.
  • Summary: each trial passed, agent failure, infrastructure or cancelled.
    • Per agent: pass rate over passes and agent failures; FrontierHarness's first valid attempt per task; which of these the target publishes.
    • First-attempt pass rate: a trial does not count when an earlier attempt ended for the agent's own reason; a retry for the provider, network or container does not count against it. Both agents in a job the launcher retried; OpenProgram only in an older job, where Harbor retried and deleted the control's attempts.
    • Also per agent: retries and their kinds; cost of every attempt as reported, and the retried attempts' share; cost at the target's prices; cost per pass over the kept trials at those prices, the same attempts for both agents; container hours; trials over the wall-clock limit.
    • Paired with the control: the n-th scored attempt of each on a task form a pair; McNemar's exact test on the pairs where only one passed; the smallest gap that many pairs can show at 5% and 80% power. Attempts on one task are not independent, so both read optimistic when tasks are few.
  • Infrastructure needs evidence: an infrastructure error type, a provider or network cause in the usage summary (said to be before the turn or in it), a verifier whose own setup failed before any test ran, or a verifier that never started. A verifier timeout after the tests ran counts against the agent.

What it does not do

  • No cost cap inside the agent (--max-budget-usd): a task that fails because its money ran out is a result the cap made, not the harness. Codex has none and FrontierHarness caps only wall time; Harbor leaves Claude Code's and mini-SWE-agent's caps off by default. Spend is bounded outside the agent, by the launcher's ledger and SIGINT.
  • No second, live transcript: the journal and the ledgers are already written record by record; the transcript is derived from them, once, on exit or afterwards.

Commands for an oracle smoke, one task and a full run, on local Docker and on Runta: scripts/benchmarks/harbor_agent/README.md.

Why this design

TopicFollowsWhy
Encrypted reasoning always asked forCodex (OpenCode alike)With store: false the server keeps no reasoning: a reasoning model still reasons and bills without the request asking for it back, and the next tool round loses it. Codex asks every time; Pi only with an effort. include is a top-level parameter, so earlier prefix bytes and the cache are unchanged
Off is effort: "none"Pi (the bytes Codex sends)No reasoning field leaves the server reasoning at its default, which is not what turning thinking off says. Pi sends its map's off value, and nothing where a model maps off to nothing; models older than none (o-series, gpt-5 to gpt-5-pro) do that here
Key in the run's environmentHarbor's Codex and Claude Code adaptersBoth pass the key as the provider's variable of one process; a login step wrote a credential that then had to be found and deleted
Launcher retriesFrontierHarnessIt archives an attempt before retrying and never replaces a valid one. Harbor deletes a trial's folder before its own retry, so the control's earlier attempts were lost and its first-attempt rate could not be counted. Harbor's trial hook would need a Python entry point instead of harbor run
Transcript from stateCodex and Claude Code adaptersBoth write their session record by record and derive the trajectory afterwards. One path means a killed run's transcript is the one a finished run writes; a live second copy could disagree with it
Commit in the buildClaude CodeIt injects its version and build time at build time. A trial folder read on its own has no launcher record beside it; a source checkout is unchanged
--no-webHarbor (its Codex and Claude Code adapters)Both declare native web tools and turn them off on disable_web_search. One switch for both sides allows a run with web off; the default stays on, as published
Pilot tasksFrontierHarness's own per-task dataFive of the earlier eight passed every v1 trial and showed neither the cost tail nor a gap; hard tasks show timeouts and the tail, so each tier is there. Its smoke task regex-log is among them
No cost cap in the agentCodex, FrontierHarnessSee What it does not do
