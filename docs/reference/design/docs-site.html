Reading and visual design

New pages are HTML documents on one foundation: neutrals with a single blue accent, light and dark. Prototype pages work through --bg, --bg-code, --tx, --tx-soft, --acc and --bd, aliases of the foundation tokens. An article never repeats a fixed light-only palette.

  • A page starts from its question, reader, scope and implementation boundary; public entry and data flow come before detail; remaining work closes the page.
  • Stable heading id values feed the page navigation.
  • Diagrams have an accessible title and description. Native disclosure holds detailed evidence. Keyboard focus, reduced motion and phone reading are part of acceptance.
  • Wide tables stay in keyboard-accessible horizontal scroll regions at a readable column width. Standalone HTML also gets diagram scroll regions and an opaque fallback canvas when it defines no background. These helpers do not certify the implementation a page describes.

Design information architecture

Three levels: area, module, page. Seven areas: architecture, agents and workflows, context and memory, interfaces, models and external connections, security and engineering, supporting material. The landing page uses the same seven. Architecture lists entry pages directly.

  • Each page belongs to one module. Loading or navigating to a page expands its ancestors.
  • Filtering matches page and category names, keeps matching ancestors open; clearing restores the prior state at every level. Native details and summary give keyboard operation.
  • New pages appear in an Uncategorized area.
  • Both languages share hierarchy, order and output mapping.
  • Prototypes, implementation records and research stay distinct under Supporting material and do not imply implemented behavior.

Canonical documents and stable URLs

  • One topic, one maintained source. A merge keeps unique diagrams, constraints, status and evidence, and every retired heading as an anchor. Rationale and model-selection analysis sit beside the design contract; usage guides and API references stay separate.
  • Filenames are descriptive lowercase hyphenated words, with no dates, TODO or PROBLEM prefixes. Deferred proposals state it in the title.
  • Inside a subsystem directory, names and titles omit the subsystem: context/statistics.html, memory/editor.html, runtime/dag/layout.html. Established terms stay when dropping a word changes meaning. A diagram qualifier is used when a text page already owns the shorter name.

Documentation completeness

The repository README, with a Chinese counterpart of the same structure, introduces the project, verified entry commands, examples and citation. The docs homepage directs to the nine tabs rather than repeating it. Reference overviews link to task guides and generated details.

Reference generation emits English and Chinese pairs from the same argparse tree, settings schema and provider manifests; names, flags, keys, defaults and protocol values stay exact.

  • A source-string catalogue (reference_zh.json) supplies Chinese; a missing translation fails generation.
  • Both languages traverse every command depth with the same options, and write only when content changes. Removed command pages go in both.
  • Reads schema defaults, never user configuration; no credentials.
  • Generators finish before discovery; failure aborts the build.

Acceptance: all reference pairs, recursive option parity, missing-translation failure, idempotence, stale-page removal, homepage language links, short names, links, language checks, visible language switching on the default local instance.

Heading hierarchy

  • A page with no on-page contents hides the empty column and gives it to the article; the fullscreen control stays at the right edge; SPA navigation updates this.
  • Nested lists cover h2 through h6. Each heading belongs to the nearest preceding shallower heading; skipped levels make no empty groups. Order, labels and anchors are unchanged.
  • Each group has its own indented dashed guide. The selected heading and ancestor path get group-owned indicators; no line spans unrelated depths. Neutral child guides show structure before a child is selected.
  • Headings with children use the sidebar's details/summary chevron, which toggles only that subtree; the link still navigates. Leaves have no chevron and keep curved guide endpoints. Groups start expanded and scrolling respects user collapse; a collapsed active descendant marks its parent path, tracking the nearest visible ancestor. No row boxes on hover or selection.
  • Endpoints use actual wrapped rows. Previews stay within the sibling group. One aria-current location. Resize and SPA changes recompute geometry and dispose old observers.

Acceptance: multiple parent groups, skipped levels, deep headings, wrapped rows, active ancestors, hover, resizing, SPA navigation.
