Framework overview

Subsystems are decoupled by one process-wide event bus: the dispatcher, agent loop, tool execution, storage and collaboration never call each other's UI or broadcast logic. They emit; whoever cares subscribes.

LaneBehaviour
Asynchronous observationEventBus: nobody can stop what is happening
Synchronous consultationtool_gate: the one place that can stop a tool

One turn

Entry
ChatAgent().run_turn (production), which reaches _process_turn_once in runtime/conversation/turn_runtime/__init__.py. process_user_turn is a compatibility entry. Synchronous so channel worker threads can call it; starts its own asyncio loop and returns TurnResult
User message
A DAG Call node with caller=ROOT, written before the run so a crash leaves a record. Emits chat_ack and user_message for the UI
Turn binding
TurnBindings sets _current_turn_id, read by every coroutine in the turn (tools, Agent methods, send_message) and routing file backups and sub-branch anchors; and _store, a SessionNodeWriter for the same DAG. Assistant id is user_msg_id + "_reply". Reset on success, exception and early return
Finish
Emits chat_response, returns TurnResult

Single-turn and multi-turn differ only in chain length. Writing a fork means pointing a user node's caller away from the active tail (set_head moves the UI pointer), or a new root through the agent tool.

Before the model call

  1. run_loop_blocking calls ContextEngine.prepare(...): DAG history rendered into LLM messages (TurnPrep).
  2. If should_auto_compact(prep): compact (LLM summarization into a durable node); then prepare again.
  3. The prompt is added once per loop, so the prompt-cache prefix stays intact.
  4. agent_loop([prompt], context, config, ...).

Core loop

  1. Push AgentEventTurnStart.
  2. _stream_assistant_response calls the model.
  3. Extract ToolCalls; _execute_tool_calls runs them; results are appended to the context.
  4. Push AgentEventTurnEnd. Stop when there are no tools, steering or follow-up.

Chat turns have no iteration cap. runtime.exec passes max_iterations=20.

Finish

Failure
The error folds into the placeholder row or a standalone error node; head_id moves to the failed turn
Success
persist_assistant_message, then finalize_turn: head and token update; ContextCommit output backfill; after_turn feeds provider usage back; shadow Git turn commit and project auto-commit (commit_turn_changes); auto-title, usage, snapshot eviction; session status
DAG
User node, assistant placeholder, tool results and Agent method nodes all reach one SessionNodeWriter. commit_turn makes session fields durable: append-only, no mutable mirror file, so concurrent agents never collide

Storage

Log
One append-only log per session; _open(sid) returns (SessionLog, SessionMemoryIndex), LRU cached, index rebuildable from the log
Branch
(session, head). get_branch(sid[, head]) walks predecessor and caller; set_head moves one UI pointer in meta. Forks are separate chains and never contaminate
Commit
commit_turn(sid, msg) at turn boundary. Events: sessions.listed, branches.listed

Event layer

Bus
EventBus.subscribe(handler, types=...), legacy on, process singleton get_event_bus()
Gate
register_tool_gate, decide_tool_gate: strictest wins, fails open, must be fast (no LLM or slow IO)
Questions
QuestionRegistry: process-wide pending table, claim-once, thread-safe

Context engine

Aging
While rendering, tool results outside the recent tail collapse to one-line stubs. DAG nodes are untouched
Context commits

Agent run

EventStream
Async-iterable plus a terminal value; provider dict events become typed
LoopDriver
prompt, follow_up (append at wrap-up)
Static admission
gate(name, disabled, allowed, categories): fnmatch, in that order. agent.json declares who may use what; separate from tool_gate
Subagents
run_agent_turn(sid, prompt, agent_id, ...) durably admits one turn with source="agent_spawn", inherits the parent's permission mode and rules, and waits for its Job. Returns AgentTurnResult (head_id is the new tip); label names the branch

Collaboration

to
SID:HEAD (one more turn from that head) or a branch name. Creating branches is the agent tool's job; to="new" is rejected with a redirect
Parent anchor
_resolve_parent reads session and turn ContextVars and falls back to the session head when the turn id is missing: worker-thread ContextVars are unreliable, which is also why subagent.started and .ended pass the session explicitly
Delivery
Always asynchronous through the Job runner (run_agent_turn_async). On completion it writes an attach pointer and dispatches a follow-up to the initiator. The caller's model reads it as a user-role report (_attach_report): name, task, final reply and read_conversation(session_id, head_id). A synchronous spawn adds nothing: the agent result already has reply and SID:HEAD
Guards
agent.max_messages (0, off by default; children inherit count + 1; A↔B round trips count); a turn cannot message itself; target session must exist; tool.before applies
In chat
Sender shows the tool's own row ("Sent to …"); the receiving branch draws one row named after the sender, from [message from SID:HEAD (sender)]
