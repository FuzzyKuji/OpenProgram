Theme system

CSS custom properties are the only runtime mechanism. Every built-in theme provides the same token set, and components never branch on a theme name.

From setting to component

  1. Select. Appearance: Mode (Auto, Light, Dark), theme pack, accent colour, CSS overlay. Font options come from font-pref.ts.
  2. Persist. Schema 3: agentic_theme_style + agentic_theme_mode; agentic_theme_accent; agentic_custom_css_enabled; agentic_tabrow_color. Fonts also keep a cookie for the first frame.
  3. Apply. The first-frame script and hook set data-theme, data-custom-css, accent tokens and --font-sans.
  4. Resolve. The pack's token file. Accent overrides three tokens; the overlay sits on top.
  5. Consume. The Tailwind bridge, CSS modules and desktop overlays read tokens.

Entry points: apps/web/lib/prefs/appearance/theme-pref.ts, apps/web/app/globals.css, apps/web/app/styles/themes/.

Token contract

Theme files give values, components define use, and one purpose has one token name in every theme.

Focus, active tab, pages in the centre card
AspectRule
Text entry, native selectOne existing border in the accent colour on focus: no outline, offset ring, box-shadow or size change. Search and composer wrappers own the border; their inner editor has none. Navigation, checkboxes, radios, sliders and embedded third-party surfaces keep their own keyboard focus.
Active desktop tabIn dark mode --tab-active-bg mixes the content background with 12% white, for ordinary tabs and split groups, stable on hover. Light mode and browser tabs use the content background.
Pages in the centre cardThe shell marks non-chat routes (.page-col) and panes ([data-page-surface]). A theme may restate --bg-secondary, --bg-tertiary and their derivatives for those scopes: beige-light uses #fbfaf8 and #f3f1ec, so pages read like the chat while the frame, rails and chat pane keep theme values.
Desktop windowAll theme ids pass unchanged to overlays; the window background is the pack's --bg-primary even with an accent override.
Diagnosing intermittent theme switches
AspectBehaviour
Desktop source of truthA complete valid theme-prefs.json from the main UI. Legacy browser-storage migration runs only when the file is missing or its mode or style is invalid. Raw browser-database scans cannot find the latest record, so they never override it or restore a cleared accent.
After loadThe web page's localStorage is the authority and syncs the desktop cache
Event logtheme-events.json under desktop userData, at most 64 records: message sends, first-screen init, settings changes, system colour events, cross-window sync, HTML attribute changes
Log contentsTimestamps, fixed event names, theme enums, system light or dark. No chat content, URLs, CSS or user paths. Write failures do not affect rendering.
LimitThe log identifies a switch's source; it does not establish that an unknown trigger is fixed

OptionUseWhy, and what it lacks

Implementation status

Implemented: Mode × theme pack × accent × overlay, with THEME_STYLE_PAIRS as the light and dark matrix. Stored custom and custom-light migrate to beige, and saved CSS turns the overlay on. Composer, provider icons and DAG use role tokens only. Desktop first-paint details: Desktop chrome.
