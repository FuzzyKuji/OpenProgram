主题系统

CSS 自定义属性是唯一的运行时机制。每个内置主题提供同一套令牌，组件不按主题名分支。

涵盖不涉及
设置里的外观和字体组件尺寸、布局、交互
首帧、React 水合、系统配色变化已保存的用户 CSS 覆盖层（除选择器迁移外不自动改写）
主窗口、桌面浮层、新窗口业务逻辑
表面、文字、边框、状态、焦点、输入框、DAG语法高亮、网站内容

从设置到组件

  1. 选择。外观：模式（自动、浅色、深色）、主题包、强调色、CSS 覆盖层。字体选项来自 font-pref.ts。
  2. 保存。Schema 3：agentic_theme_style + agentic_theme_mode；agentic_theme_accent；agentic_custom_css_enabled；agentic_tabrow_color。字体另存 cookie 供首帧使用。
  3. 应用。首帧脚本和 hook 设置 data-theme、data-custom-css、强调色令牌和 --font-sans。
  4. 解析。主题包的令牌文件。强调色覆盖三个令牌；覆盖层叠在最上面。
  5. 使用。Tailwind 桥接、CSS 模块和桌面浮层都读令牌。

入口：apps/web/lib/prefs/appearance/theme-pref.ts、apps/web/app/globals.css、apps/web/app/styles/themes/。

焦点、活动标签、中间卡片里的页面
方面规则
文本输入、原生 select聚焦时现有边框变强调色：不加 outline、偏移环或 box-shadow，尺寸不变。搜索框和输入框由外层持有边框，内部编辑区无边框。导航、复选框、单选、滑块和嵌入的第三方界面保留各自的键盘焦点样式。
桌面活动标签深色模式下 --tab-active-bg 为内容背景混 12% 白色，普通标签和分屏组共用，悬停不变。浅色模式和浏览器标签用内容背景。
中间卡片里的页面外壳标记非聊天路由（.page-col）和窗格（[data-page-surface]）。主题可在这些范围内重设 --bg-secondary、--bg-tertiary 及派生令牌：beige-light 用 #fbfaf8 和 #f3f1ec，页面观感与聊天一致，窗口框架、侧栏和聊天窗格仍用主题值。
桌面窗口所有主题 id 原样传给浮层；有强调色覆盖时窗口背景仍是主题包的 --bg-primary。
排查偶发的主题切换
方面行为
桌面端依据主界面保存的完整有效 theme-prefs.json。只有文件缺失或 mode、style 无效时才做旧浏览器存储迁移。直接扫描浏览器数据库找不出最新记录，不得覆盖它，也不得恢复已清除的强调色。
加载后以网页自己的 localStorage 为准，并同步桌面缓存
事件日志桌面 userData 下的 theme-events.json，最多 64 条：消息发送、首屏初始化、设置变更、系统配色事件、跨窗口同步、HTML 属性变化
日志内容时间戳、固定事件名、主题枚举、系统明暗。不含聊天内容、URL、CSS 和用户路径。写入失败不影响渲染。
局限日志用于定位来源，不代表未知触发源已修复
方案对比
方案结论原因与不足
CSS 自定义属性 + data-theme采用原生层叠覆盖 Web、CSS 模块、Tailwind 任意值和同源浮层。查不出缺失令牌，因此加静态检查。
Tailwind @theme仅作桥接把令牌暴露为工具类，不另存一份取值。不能生成 import，由脚本对齐主题文件和 TS id。
JS 主题对象、Context否决取值重复；覆盖不到原生 CSS、首帧和 Electron 浮层
组件级 [data-theme] 分支否决每加一个主题都会漏改
light-dark()否决只能表达明暗，表达不了具名主题包

依据：CSS Custom Properties Level 1、CSS Color Adjustment color-scheme。
