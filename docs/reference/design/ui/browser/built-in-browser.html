Built-in browser

Pages render in Electron WebContentsViews on their own persist:webtabs profile, sharing no cookies or storage with the App. The Agent works on the same pages through the browser target of computer_use_agent: the user watches and can take over, and pages a session opens appear in that session's Resources.

Page behaviour

BehaviourRule
LoadingReload becomes an accented Lucide X named Stop loading, over a thin indeterminate bar below the toolbar with no percentage and no height change. Static with reduced motion. Completion, failure and cancellation restore Reload.
Unsaved pagesA blocked reload or navigation (will-prevent-unload) shows a native dialog on the owning window. Stay on page is the default and cancel; Leave page permits only that operation. Missing owner, destruction or dialog failure keeps the page. A page that is not on screen in the focused window leaves without the dialog, since nobody is there to answer and the dialog would come in front of what the user is doing. Tab close and App shutdown are outside this rule.
Tab iconsFavicon when it decodes to visible pixels, else the animated Lucide browser icon. Main reads bytes through the page session: HTTP(S) and image data, 256 KiB, five seconds, returned as data URLs so the renderer can detect fully transparent icons. Navigation and destruction cancel reads; stale results cannot land. Snapshots carry the favicon; history keeps the original URL.
Find, Zoom, PrintTarget only the requesting window's exact WebTab. Find has previous, next, count and close, which clears selection. ⌘/Ctrl+F, ⌘/Ctrl++/-/0 and ⌘/Ctrl+P match the menu. An older shell lacking the IPC disables the action.
PrintSystem printing first; on failure or with no destination, the owning window's Save PDF dialog. Cancelling writes nothing; a successful print makes no PDF. The PDF is written to a unique temporary file, then replaces the target; failure keeps existing files.

  • Web-only mode: import is not offered

Agents on these pages

TopicRule
Session pagesGrouped by session and collapsed in the session resources panel (Session resources). Records keep session ownership and pin state; manual pages and explicit splits stay top-level.
PausingClicks, scrolling, keys, navigation and closing a page never pause an Agent, from a user or automation, including automation of OpenProgram. Only conversation controls pause or cancel. Browser resources keep no separate write prohibition; dispatch guards, ownership checks and current-frame validation stay.
Lost targetThe session is discarded and the tool returns recovery information with the last URL. Recovery observes a new page at that exact URL, never replays a mutation or picks another tab. Missing authentication or unsaved state is reported.
ShutdownScreenshots keep their ToolReturn images and structured errors. A live server never submits to a closed default executor; recovery respects cancellation and unresolved external effects.
Browser step execution and caller context
  • The workflow owns the observe, action and verify loop. Each planner request sets stop_after_tool_round: the shared Agent loop runs one validated, permission-checked tool round, keeps its receipts and returns without another model response. Default Agent calls continue to final output.
  • Independent of the safety limit max_iterations. Exhausting a limit is non-retryable, so completed actions cannot replay. A structured final-output contract cannot be combined with this early return.
  • Every BrowserPageController submission to its Playwright owner thread, including cleanup and final verification, carries the current ContextVars, copied per submission. Page isolation, binding validation, permissions and operation leases stay authoritative.
  • A legacy browser task uses an explicitly bound current Page without reloading for a URL hint. A stale explicit binding fails rather than opening a replacement. With no explicit Page, URL and open behaviour are unchanged.
File selection and planner failures
  • The planner uploads with an approved local path and a fresh file-input ref, under sandbox reads, approval, Page ownership, cancellation and step limits. MCP-backed planners use the same controller.
  • File inputs expose type and selected names, never bytes or local paths. Selecting is separate from server acceptance: file_selected checks the exact current input and final evidence is rechecked.
  • Verification uses value, not typing text. Invalid calls return an actionable error; three consecutive failures on an unchanged frame stop with the concrete error. A planner can stop with a blocker, which never grants success. Operation counts are Page mutations, not model requests.

How web tabs present themselves

As a current Chromium browser, consistently across headers and script. Nothing claims to be another browser.

PartBehaviour
User-Agentwebtab-user-agent.js drops only the App's token and keeps Electron/x with the full Chrome version: claiming plain Chrome while navigator.userAgentData lacks Google Chrome reads as forged and sticks in Cloudflare's challenge
Clearance cookiescf_clearance, __cf_bm and cf_chl_* hold only for the User-Agent that earned them. When it differs from webtab-user-agent.json, the App removes them before any tab loads; other cookies stay.
Client HintsElectron sends no Sec-CH-UA. webtab-client-hints.js reads getHighEntropyValues() once from a loopback page, then sends Sec-CH-UA, -Mobile and -Platform to secure origins and the high-entropy hints an origin names in Accept-CH
Permissionswebtab-permissions.js allows what Chrome allows silently (fullscreen, pointer lock, clipboard writes, external protocols), asks in a native dialog on the tab's window for camera, microphone, location, notifications and similar, denies the rest. Answers are kept per origin in webtab-permissions.json; clearing web tab cookies forgets them. An undecided permission reads denied, since Electron's check handler is yes or no.
Permission asked by an unwatched pageA request from a page that is not on screen in the focused window is refused that once and not kept, so the user is asked when they open the page.
EngineThe Electron in apps/desktop/package.json tracks Chrome stable (Electron 45 is Chromium 156); installed Apps take it as in Stable and development instances
Not patchedwindow.chrome is empty and there is no Widevine. Pages needing full Chrome are a separate design: the Agent working in the user's own Chrome.
