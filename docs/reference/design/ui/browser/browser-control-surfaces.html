Browser actions and task controls

The pinned Playwright response renderer is guarded against an empty tab-header list after snapshot capture. Detach or close during that asynchronous read must not dereference a missing header. When a response has no attached page, only snapshot reads are retried, at most three times; navigation, form input and submission are never replayed. Reconnection to a different URL is not accepted as recovery. The Agent receives an observation-required result and the remaining batch stops.

When an extension action loses its reference, or its connection closes, read a fresh snapshot of the same URL before returning control to the Agent. A recovered observation stops the remaining batch. Completed steps are retained; no input or submission is replayed. Missing references mean no dispatch; a closed connection leaves the action outcome unknown and requires inspection. A failed snapshot or a different page remains an error.

Opening a URL in the user's Chrome or Edge creates a normal working tab. Opening a new working tab is the product's policy; the extension connection page itself can also navigate and is not inherently unusable.

Input and capture mapping
  • Renderer bounds convert to native DIP before scaling. Native input uses Chromium's emulated-view mapping.
  • Observations and screenshots stay in CSS coordinates. The exact native Page reports input_scale through the owner-checked binding reply; coordinate clicks and pointer moves multiply by it before CDP. Wheel deltas and window.scrollBy stay in CSS units.
  • MCP reference namespaces stay upstream: scaled reference clicks evaluate the existing click script there; hover uses a temporary exact-element marker, frame-aware Playwright bounds and a native pointer move.
  • Action markers share the viewport and scale. Owner checks and deferred transfer restoration stay.
  • Agent screenshots use a fixed CSS-resolution CDP capture with temporary device metrics and DPR compensation. Concurrent captures share one result. Cleanup removes the override and restores native geometry, as does final debugger detach. A resize, navigation, ownership change or preview exit invalidates an in-flight result.
  • A capture keeps its owned native view and navigation generation. Start or commit in any frame, same-document and same-URL reload included, invalidates pending captures; a failed navigation never restores an earlier generation. Position-only moves keep native captures; dynamic DOM updates do not count as generations.
Movement cost and gestures
  • Position-only moves update bounds without touching emulation or zoom. Identical geometry issues nothing. Scale changes only with native dimensions; navigation and debugger detach restore emulation. Renderer reports share one rounded geometry, UI zoom included.
  • Root scrollbar tracks are hidden by a reversible author-origin stylesheet; wheel, keyboard and nested scrolling work. Leaving preview removes it, including when insertion overlaps navigation or exit.
  • While a drag or resize is held, one decoded bitmap moves and scales in the renderer; native bounds and emulation stay fixed, and page animations look frozen. On release the hidden page gets the final bounds once, a capture waits for its painted surface, and live interaction resumes.
  • Presentation captures use capturePage, never CDP or a loop. An invalidated or timed-out capture cannot hide or restore a replaced preview.

Dispatch cancellation

A browser action checks the task's cancellation while it waits for its tab and while it waits for the page to settle; a list of actions checks again before each one. A cancelled pending action sends nothing. A dispatched action is neither undone nor repeated.

Acceptance

  • Hiding keeps the page; Resources reopens it; the More item sends no execution-control requests.
  • innerWidth stays 1920 across resizes below and above 480 pixels. Native clicks, Agent clicks, markers, scrolling and fresh screenshots agree at two sizes; UI zoom, navigation, tab restoration and transfer cleanup hold.
  • Sixty moves and repeated identical bounds cause zero emulation resets; one reset per changed scale; forced restoration and stylesheet lifecycle hold; dragging and scrolling stay continuous.
