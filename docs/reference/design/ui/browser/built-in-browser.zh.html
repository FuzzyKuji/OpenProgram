OpenProgram · UI 设计规范

内置浏览器、资料导入与新建 Pane

OpenProgram 在桌面 App 里自带一个浏览器。网页渲染在 Electron WebContentsView 中，使用独立的 persist:webtabs profile，不与 App 本身共享 cookie 或存储。用户可以从 Chrome 或 Edge 导入书签、历史和密码，并像普通浏览器一样使用书签、History 和下载。Agent 通过 computer_use_agent 的 browser 目标操作同一批网页：用户看着它操作，随时可以接手；会话打开的网页显示在该会话的 Resources 里。新建 Pane 只负责选择内容类型；进入 Browser 后才显示网页导航、书签、History 和资料导入。浏览器工具栏只处理当前网页和浏览资料，窗口菜单处理 OpenProgram 与 Pane，两个设置入口打开同一个 Settings 页面。

01

产品决策

当前问题来自内容入口、浏览器主页和资料管理共用一个页面。设计先分离职责，再定义每个页面出现的控件。

书签图标和栏位

网站书签复用标签页 favicon 渲染：已保存图片、网站自身 /favicon.ico、Lucide 浏览器默认图标，依次回退。仅接受 HTTP(S) 和图片数据，不发送 referrer，不使用第三方 favicon 服务。新书签保存当前网页图标，再次查看相同 URL 时更新已保存图标，加载时空图标不清除原值。书签栏保持原高度，依次显示书签栏内容、双箭头溢出入口、分隔线和最右侧“所有书签”。所有书签打开现有管理页，其他书签和移动端书签保持原层级。文件夹继续显示文件夹图标。验收覆盖导入书签、图标失败和更新、溢出导航以及管理入口。参考 Chrome 官方书签帮助。

加载反馈

原生网页加载时，刷新按钮切换为强调色的 Lucide X，标注“停止加载”；工具栏下方显示细条形的不定进度指示，不改变工具栏高度。停止按钮取消加载；完成、失败或取消后隐藏指示并恢复刷新。指示使用原生加载事件，不显示虚构百分比；减少动态效果模式下保持静态。

刷新时确认未保存的网页内容

网页使用 beforeunload 阻止刷新或导航时，在其当前所属窗口显示原生确认框。默认按钮和取消操作都是留在页面；选择离开页面后，仅允许当前被阻止的操作继续。页面失去所属窗口、已经销毁或对话框失败时保持页面。普通刷新不额外确认。使用 Electron 的 will-prevent-unload 事件；本次不修改标签关闭和 App 退出策略。

网页标签始终显示可见图标

普通标签和分栏成员优先显示网站 favicon；加载中、加载失败或解码后完全透明时，显示已有的动态 Lucide 浏览器图标。桌面主进程使用页面所属 session 读取图标，只允许 HTTP(S) 和图片 data URL，限制为 256 KiB 和五秒；以图片 data URL 传给渲染端，支持检测透明像素。导航和销毁取消读取，过期结果不能覆盖当前页面。重新打开保留的页面时，状态快照带上当前 favicon。历史记录保存网站原始图标 URL。

New pane 只做选择

空白 Pane 只显示 Files、New chat、Browser、Terminal。地址栏、快捷网站、Bookmarks 和 History 不出现在这里。

四个入口使用同级彩色识别

Files、New chat、Browser、Terminal 都使用相同尺寸的圆角图标容器和 Lucide 线性图标；Files 使用蓝色、New chat 使用绿色、Browser 保留橙紫色、Terminal 使用紫色。颜色只帮助识别内容类型，不改变卡片层级、交互状态或可访问名称，也不引入品牌 Logo、外部素材和额外动画。

Browser home 复用完整 Browser chrome

选择 Browser 后原位进入浏览器主页；主页与实际网页使用同一套地址栏和书签栏结构。主页中无当前网页语义的 Back、Forward、Reload、Home、Bookmark 和外部打开保持可见但禁用，地址输入、Bookmarks、Import 和 Browser ⋯ 可用。

页面决定导航还是 popup

普通链接、表单提交、脚本赋值和同文档导航继续由当前 WebContentsView 提交，并只更新当前 WebTab 的 URL、标题和 History；不得新建标签。只有页面明确请求新浏览上下文（target="_blank" 或 window.open）时，main 进程才把经过校验的 HTTP(S) URL 转换为一个具有独立 id 的 WebTab。新 WebTab 立即成为活动标签；当前已经位于 /chat 或 /s/<id> 时不得再推送 /chat，避免会话路由同步覆盖 popup 的活动状态。

网页右键菜单绑定命中内容

原生网页区域直接使用 Electron context-menu 命中参数。HTTP(S) 链接显示 Open Link in New Tab 和 Copy Link Address；可编辑内容显示 Undo、Redo、Cut、Copy、Paste 和 Select All；普通页面显示 Back、Forward 和 Reload。Open Link in New Tab 复用同一 popup 入口，因此与页面自己的 window.open 具有相同的 URL 校验、唯一标签和立即激活语义。菜单动作只作用于产生该菜单且仍由同一窗口拥有的 WebTab。

悬浮网页预览属于发起会话

Agent 在聊天中打开的悬浮网页预览记录创建时的 session tab。它只在该会话作为当前中心内容时显示；切换到其他聊天、普通 Browser tab 或非聊天页面时，renderer 必须从原生可见集合移除该 WebTab 并恢复用户网页缩放。返回原会话时复用同一 WebTab、URL、滚动和表单状态，不重新加载。用户关闭预览后，恢复入口也只出现在所属会话。

书签分为保存与管理

地址栏右侧的星标只保存或移除当前页；相邻的 Bookmarks 按钮打开完整书签页。Browser home 只显示用户维护的快捷网站，不展开全部书签。

Bookmarks manager 采用 Chrome 式两栏结构

完整书签页顶部固定页面标题、搜索框和页级菜单；左栏只显示可折叠的文件夹树并高亮当前目录，右栏只显示当前目录的直接子项。书签行使用 favicon、标题和单一 ⋮ 菜单，文件夹行进入对应目录；不再把整棵树、URL 和编辑/删除按钮同时铺在一个列表里。左右列表行统一为 36px，搜索框沿用全局 30px 控件高度，行内图标按钮为 28px，页头为 52px；右侧列表的首屏内边距为 16px。Pane 变窄时目录树移到内容列表上方，不能直接消失。

书签栏默认显示

Browser home 和实际网页默认在地址栏下方显示同一行书签。用户可以从 Browser ⋯ 或 Settings 关闭；窄分屏临时隐藏该行，仍可通过 Browser ⋯ 中的 Bookmarks 访问全部内容。

书签栏显示来源目录的内容

Chromium 的 Bookmarks bar 是书签栏容器，不作为普通文件夹按钮显示。该容器的直接子项按原顺序进入栏内；Other bookmarks 和 Mobile bookmarks 保留在“所有书签”管理页中；栏位右侧依次是溢出入口、分隔线和“所有书签”。普通根级书签继续作为栏内项目。进入溢出菜单的项目不能在可见栏内保留被裁切的半个按钮；最后一个可见按钮必须完整显示背景和两侧圆角。

书签菜单保留 Chrome 式层级

单行书签栏不出现水平滚动条；被宽度截断的项目由右侧溢出入口列出。菜单固定为 280px 宽，过长标题使用省略号；文件夹行在既有 14px 图标位显示 Folder 图标，并以右箭头进入下一级菜单，不把完整路径拼进一行。网站行显示书签 favicon；导入数据未包含 favicon 时按 URL 获取，加载失败时显示共用的浏览器默认图标，不能留下无内容的空白位。桌面 App 中鼠标悬停书签栏文件夹立即打开该文件夹，横向移到相邻文件夹时菜单随目标切换，不设置额外等待时间。连续切换文件夹时复用同一个菜单视图，只替换菜单数据，不能反复重建视图并重新解码已经显示过的 favicon。菜单的原生覆盖层从书签栏下缘开始，不能遮挡书签栏按钮的鼠标命中区域。每一级菜单高度受当前窗口约束，并支持鼠标、触控板与键盘操作。

设置只有一个数据源

窗口菜单的 Settings 打开 OpenProgram 设置；Browser 的 ⋯ 直接打开其中的 Browser 分区。工具栏不增加常驻齿轮，也不实现第二套浏览器设置存储。

分屏属于 Pane

分屏、退出分屏和 Pane 排列适用于 Files、Chat、Browser、Terminal，不属于当前网页动作。它们放在 Tab/Pane 控件或 Tab 上下文菜单，不出现在浏览器工具栏。

导入保留来源结构

Chromium 的 bookmark bar、other bookmarks 以及嵌套文件夹按原有层级和顺序进入 OpenProgram bookmark tree；导入不得把书签压平成主页下方的独立条目。

菜单分别绑定触发按钮

浏览器 ⋯ 和窗口 ⋯ 都使用各自触发按钮的实际屏幕矩形定位，菜单右边缘与按钮右边缘对齐，垂直间距为 4px；二者不能共用位置或内容。

菜单行带图标，勾选在行尾

浏览器 ⋯ 菜单的每一行都以 Solar Bold Duotone 平面图标开头，和侧栏文件夹同一系列。桌面覆盖层是另一个文档，所以打开方只传图标名（glyph，即 Solar 图标名），由覆盖层用 MenuIcon 绘制；Web 后备菜单渲染同一个 MenuRow。“显示书签栏”这类可勾选行保留图标，勾选显示在行尾、按键标签之后，和应用里其他菜单一致；未勾选的行留空这一列，标签保持对齐。

工具栏提示始终在工具栏上方

桌面 App 中工具栏下方的网页是原生视图，会盖住画在它上面的内容，所以工具栏提示始终在按钮上方打开，不会翻到下方。提示保持一行，过长的标签（例如“浮动到”里的会话标题）截断，以放进工具栏上方的空间。

History 使用紧凑行

记录按本地日期分组，每行只显示时间、favicon、标题、域名和操作；完整 URL 不再单独占用第二行。

导入必须显式触发

来源浏览器、profile 和数据类型分别确认。OpenProgram 不读取或修改用户正在使用的源 profile。

04

参考行为与取舍

参考产品用于确认可见行为，平台文档用于确认可实现边界。OpenProgram 不复制完整 Chromium importer。

Content hierarchy

Codex 的 Pane 入口

Files、New chat、Browser、Terminal 作为一级内容类型；浏览器控件只在 Browser 内显示。

采用
Browser profile

独立浏览状态

内置浏览器保持自己的 profile。需要既有资料时，由用户明确发起导入。

修改后采用
Bookmark access

Chrome 的分层入口

星标保存当前页；书签栏可开关；完整管理器独立存在。OpenProgram 保留三层，但针对分屏定义更严格的收缩规则。

修改后采用
Settings ownership

OpenAI 的 App Settings

内置浏览器保持独立状态，Cookies 与历史清理归桌面 App Settings。OpenProgram 增加 Browser ⋯ 深链，但不复制设置存储。

修改后采用
Page intent

Chrome 的导航与 popup 区分

当前浏览上下文中的导航原位提交；页面明确请求新浏览上下文时创建并激活新标签。OpenProgram 保留这一区分，但把 native popup 转换为受中心标签状态管理的 WebTab。

修改后采用
Page menu

Electron 原生 context menu

webContents 提供链接、选择区、编辑状态和 frame 命中参数；Menu.popup 提供当前 OS 的原生菜单。OpenProgram 采用有限动作集，不暴露 DevTools 或任意协议打开。

修改后采用
Importer

Chromium C++ importer

组件不作为 Electron JavaScript API 暴露，且不提供通用 Cookies import 实现。

不复制
  • OpenAI 内置浏览器说明：确认独立浏览状态、外部浏览器边界，以及 Cookies 和 History 由桌面 App Settings 清理。
  • Chrome 书签说明：确认地址栏右侧保存当前页、书签栏可开关、完整 Bookmark manager 独立存在。
  • Chrome 导入设置：确认按数据类型选择以及 Imported Bookmarks 的合并行为。
  • Chromium 用户数据目录：确认 History、Bookmarks、Cookies 的 profile 存储位置。
  • Chromium user_data_importer：确认原生导入组件的能力与 Electron 暴露边界。
  • Electron session 与 Cookies：确认持久化 partition 和逐条 Cookie 写入接口。
  • Electron webContents 与 renderer window.open：确认 setWindowOpenHandler 接收已解析 popup URL，context-menu 提供链接、选择区和编辑命中参数。
  • Electron Menu：确认 Menu.buildFromTemplate 和绑定所属 BaseWindow 的 menu.popup 是 main 进程的原生上下文菜单入口。
05

导入架构与数据流

renderer 只传递 main 进程签发的 opaque source/profile id。文件路径、源浏览器可执行路径和 Cookie 值都不能通过 renderer 自由指定。

一般资料路径Cookie 敏感路径

历史记录

  • 读取 Chromium History SQLite 副本
  • 只接受 http/https
  • 按 URL + visitedAt 去重
  • 错误时保留现有记录

书签

  • 解析 Chromium Bookmarks JSON
  • 保留根目录、嵌套文件夹与同级顺序
  • 同 URL 不重复添加并删除空文件夹
  • 只在 Bookmarks 页面展示和管理

Cookies

  • 禁止直接复制 Cookie 数据库
  • 由源浏览器临时进程解密
  • 逐条校验后写入 partition
  • 任何日志都不记录值

网页导航、popup 与右键动作流

target="_blank" / window.opensetWindowOpenHandler 拒绝 native 子窗口；仅将有效 HTTP(S) URL 和 opener id 发给拥有该 View 的窗口。openPopupWebTab 创建唯一 id 并立即设为 active；已在聊天 surface 时保持当前 route。

06

信任边界与失败行为

网页内容、renderer 与 main 进程之间只传递完成动作所需的有界状态；资料导入不是 profile 迁移，只复制用户明确选择的数据。

浏览器操作遵循任务执行状态

点击、滚动、键盘输入、导航和关闭页面都不会暂停 Agent。用户输入和自动化同样适用，包括对 OpenProgram 本身的自动化。只有会话执行控件能暂停或取消任务，浏览器资源不维护独立的写入禁令。执行派发守卫、归属检查和当前 frame 验证保持不变。

目标消失时丢弃其 session，工具返回包含最后 URL 的可操作恢复信息。恢复方式是观察在该精确 URL 新打开的页面，绝不重放修改操作或选择无关标签。Agent 用新观察继续任务；缺少认证或未保存状态时如实报告，不虚构恢复。

浏览器截图保留 ToolReturn 图像与结构化错误。执行器关闭后，存活服务器不会继续向已关闭的默认执行器提交工作；恢复遵守任务取消与未决外部效果限制。

图标和书签菜单生命周期

每个桌面窗口保留一个已分离的书签级联菜单视图。再次打开时重新挂载并更新菜单数据，不加载新文档。普通菜单保持原来的关闭行为。窗口清理销毁可见与缓存视图；已分离视图不能发送菜单操作。

渲染进程共用图标缓存，同一来源的并发请求合并，成功解码的32像素绘制结果保留30分钟，失败结果保留5分钟，最多256项。组件直接绘制缓存结果，不重新请求图片；来源变化使用新的缓存项。加载超时为5秒，不发送Referer，不使用第三方图标服务。跨域图片只绘制，不读取像素；可以读取且完全透明的图片仍使用回退图标。App重启后可以通过浏览器缓存重新加载，不新增持久化图标数据库。

网页标签如何报出自己的身份

网页标签像当前版本的 Chromium 浏览器那样报身份，请求头和页面脚本一致；网站要用设备之前先询问。不冒充任何其他浏览器：品牌信息就是这个 Chromium 自己报给脚本的那些。

  • User-Agent。webtab-user-agent.js 只去掉 App 自己的标记，保留 Electron/x 和完整的 Chrome 版本号。User-Agent 自称普通 Chrome、而 navigator.userAgentData 只有 Chromium 没有 Google Chrome，这种不一致会被当成伪造：Cloudflare 会把这样的访问者一直留在验证页，同一页面保留 Electron/x 时直接通过。Cloudflare 的通行 cookie（cf_clearance、__cf_bm、cf_chl_*）只对取得它的那个 User-Agent 有效，所以网页标签的 User-Agent 和 webtab-user-agent.json 记下的不同时（换了 Electron，或这里改了），App 在任何标签加载前删掉它们；其他 cookie 不动。
  • Client Hints。Electron 不发 Sec-CH-UA 请求头，但页面里能读到 navigator.userAgentData。webtab-client-hints.js 从一个回环页面读一次本 session 自己的 getHighEntropyValues()，之后对安全源发送 Sec-CH-UA、-Mobile、-Platform，并按来源在 Accept-CH 里声明的内容发送高熵提示。
  • 权限。没有处理器时 Electron 放行所有权限。webtab-permissions.js 对 Chrome 默认放行的（全屏、指针锁定、剪贴板写入、外部协议）直接允许；摄像头、麦克风、定位、通知等在标签所在窗口上用原生对话框询问；其余一律拒绝。回答按来源保存在 webtab-permissions.json，清除网页标签 cookie 时一并清掉。未决定的权限读出来是 denied 而不是 Chrome 的 prompt，因为 Electron 的检查处理器只能回答是或否。
  • 内核。apps/desktop/package.json 固定的 Electron 跟随 Chrome 稳定版（Electron 45 对应 Chromium 156）；已安装的 App 按开发版实例文档说的方式换上它。

Electron 本身和 Chrome 仍有差异：window.chrome 是空的，没有 Widevine。这些不打补丁伪装。需要完整 Chrome 的网页另作设计（让 agent 在用户自己的 Chrome 里操作）。

浏览器单步执行与调用上下文

浏览器工作流负责外层观察、动作和验证循环。每次规划请求启用stop_after_tool_round：共用Agent循环按原有参数校验、权限检查执行工具轮次，保留结果，然后返回工作流，不再请求下一条模型回复。它与安全上限max_iterations分开。默认Agent仍持续执行到最终输出。安全上限耗尽不可作为传输错误重试，避免重复已执行动作。要求最终结构化输出时不能同时启用此提前返回。

BrowserPageController向Playwright所属线程提交的每个操作均传递当前ContextVars，包括清理和最终验证。每次提交独立复制上下文，不把某次权限永久保存在控制器中；其他会话不能继承权限。页面隔离、绑定校验、权限审批和操作租约保持有效。

旧浏览器任务在存在明确绑定的当前Page时复用它，任务同时携带URL提示不会触发重载。明确绑定失效时返回失败，不另开替代页面。没有明确Page时保留原有URL打开行为。

验收通过公开浏览器任务、模拟模型和真实Runtime/Agent循环验证：一个动作仅执行一次，下一次请求验证，无迭代错误和重放，控制器关闭时保持同一会话身份。默认安全上限仍失败且不重放，明确当前Page复用且不打开或导航。实现证据：独立功能审查和质量审查通过。真实Runtime浏览器回归覆盖单次动作后验证、显式禁止规则、清理身份保留和失效绑定拒绝。Agent循环回归覆盖同步与异步选项传递、最终输出约束冲突，以及安全上限耗尽不可重试且工具只执行一次。

文件选择与规划失败

规划器通过明确的upload动作、已批准的本地路径和最新文件输入框ref选择文件。动作仍受沙箱读取规则、权限审批、页面所有权、取消和步数上限约束。文件输入框只暴露类型和所选文件名，不暴露内容或本地路径。选中文件与服务器接受分别验证；file_selected检查当前指定输入框，最终证据再次核验。MCP规划器在原有页面控制器中执行文件选择，不切换后端所有权。

验证内容填写value，text用于输入文字。无效参数返回明确原因；同一页面连续三次失败后停止，保留具体错误。规划器可以用stop报告阻碍，但不能因此成功。纠正参数后成功的调用正常继续。实际操作步数仍统计页面修改，不统计模型请求。

验收使用真实Runtime规划调用和测试专属无界面Chromium文件输入框，覆盖错误纠正、重复无效验证、停止、文件选择和读取、显式禁止、过期ref、沙箱读取、取消及独立服务器反馈验证。不上传用户私有文件，不操作实际注册。实现证据：独立规格与质量审查通过。回归覆盖两条 Runtime 规划路径、真实 Chromium 文件选择、服务器确认，以及读取后取消且不发送文件。

主页快捷方式编辑器

主页的“添加”图标切换紧凑的非模态浮层，浮层以该图标为定位点。编辑器复用 Popover、Input 和 Button，使用已配置的界面字体、主题表面和焦点颜色。名称和地址采用纵向排列的可见标签，适应窄分栏；名称可留空。

取消、关闭、Escape、外部交互或再次点击“添加”均关闭编辑器并清空草稿。键盘关闭后焦点返回“添加”。定位点被隐藏或移除时，面板也隐藏。每个主页管理自己的编辑器，不添加全局关闭监听器或应用级状态。

在任一输入框按 Enter 可提交，输入法组字期间除外。地址为空时禁用提交。保存沿用既有地址规范化、快捷方式存储和去重行为，随后清空并关闭编辑器。
