Page loading performance

The shared shell loads on every application page. Startup code, repeated catalog work and provider selection rendering are optimized without changing authentication, route history or model capabilities.

Not end-to-end click timings. In the baseline all fourteen DiceBear styles entered the initial graph (two avatar chunks, about 270 KB gzip), the native Provider list request took 1138 ms, and a Python profile counted 1.318 s of cumulative enumeration. Session-long resource counts include three-second polling and are not cold-start timings.

Design

AreaRule
AvatarsOptional styles load by explicit dynamic import (React lazy loading); the default shapes style stays synchronous. In-flight loads are shared; a failed import can retry. Results arriving after unmount or a configuration change are ignored.
SVG cacheModule-level reuse, bounded (128 entries, 512K characters). Upload and letter modes generate no DiceBear SVG.
Provider rowsReact memo with stable callbacks; a selection change does not regenerate unchanged icons.
CatalogOne credential-presence snapshot per request. It never crosses requests or becomes an authentication decision cache.
Settings readsA successful read seeds the first Provider catalog view only while fresh. Mutations invalidate it.

Must stay true

  • Unsupported providers stay unsupported. Local provider identity, aliases, account presence, CLI fallbacks and env or cloud credential semantics do not change.
  • Metrics never expose credential values.
  • Cache expiry, failed requests and loading placeholders never show another provider as the selected route.
  • Upload, letter, all generated styles, Thumbs background and SVG ID isolation remain.
Acceptance
  • Public Avatar import loads only the default style; chosen styles load once; all fourteen stay selectable.
  • Identical avatars reuse markup within the bounded cache.
  • Catalog list tests prove one enumeration per request and immediate changes on the next request.
  • Selection updates render only affected rows; warm catalog revisits show cached rows at once.
  • Production entry bytes and same-machine catalog timings are compared with the baseline.
  • Chat, Agents, Abilities, General and Provider navigation are checked in the installed default App.
