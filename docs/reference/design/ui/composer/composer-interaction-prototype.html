Optional question_title and option_descriptions supply the row layout. Only explicit string entries render; inherited object properties are not metadata and do not restrict labels. Plain answers and prompts remain for other clients. Multiple pending requests are separate keyed panels.

Discussion

AspectRule
WhereOrdinary questions: Chat about this. Approvals have only Allow once and Deny.
FieldInline in the card; heading names discussion; 96px minimum; shared Textarea. The original question stays read-only, without duplicate answer controls. Progress is hidden.
Open, cancelSend nothing; the wait stays unresolved

During submissionCompeting approval controls are blocked. Unknown delivery keeps the command and feedback for retry. Switching conversations cannot retarget it.
IdentitySession and wait jointly identify the request; feedback, command id and delivery state survive remounts

Like the Claude Agent SDK and OpenCode, feedback attaches to the original call. OpenProgram synthesizes no first-person rejection and does not treat questions as tool permissions.

Typography and alignment

Text
Application sans-serif at the base token, line height 1.5, no shrink at desktop breakpoints. Prompts and field headings 600; values, hints and placeholders 400.
Code
Commands and JSON: shared OperationCode, monospace, language label sized as the first code line, secondary background, inset 1px theme border, copy icon on the first line. No separate toolbar.
Copy
Success only after clipboard acknowledgment; failure is announced
Edges
Headings, body and editor border share one left edge, 12px inside the container. No negative margins.
Actions
A non-shrinking sibling of the scrolling body, anchored to the bottom through height transitions and overflow
Command details
Native disclosure, 12px gap; the working directory appears only in the JSON arguments. Sandbox escalation explanations stay visible.

Keyboard ownership

FeatureRule
History recallKeeps the exact draft; Down after the newest restores it. Editing recalled text starts a new cycle. State is scoped to the composer owner, so another split pane does not reset it. Selection, modifier arrows, IME, file and slash menus keep precedence.
File mention resultsBound to the token location and query. A changed query invalidates them; a late response cannot restore them after Escape, replacement or unmount. Escape dismisses until the token changes.
Mention pendingEnter and Tab keep the draft and neither select nor send. Escape works. IME and Shift+Enter keep editing. No timeout or retry.
Mention empty or failedEnter sends; Tab moves focus
Rejected send intentThe owner reservation keeps the unsent body even when only attachments or settings differ, across focused and bound composers. An accepted frame keeps its payload; success clears only matching text. The reservation token is released in finally.
Long-lived approvals
ItemRule
ExpiryHuman tool approvals have no default expiry. The durable wait keeps the exact operation and file fingerprints; the safe-point handoff ends the attempt and frees the slot. Explicit deadlines remain for other waits.
ResumeResume loads the checkpoint and reuses the saved system prompt and browser-tool selection. Model, tool implementation, permissions and location are validated; live Page access is checked per call. An incompatible continuation reports that execution did not resume.
Clearing errorsOnce recovery reaches running or completed, prior continuation error metadata is cleared. Replay repairs a completed message without rerunning.
CancellationCancellation and terminal events remove pending decisions, including after reconnect. Expired requests stay expired. Job recovery handles only Job admissions. An operation that paused again does not retry on its old answer.
File approvalsFile edit, write and patch approvals bind paths and contents, checked before dispatch and before mutation. Changed or missing targets are not written; the agent gets a non-executed result and must re-read. Opaque shell commands cannot claim this guarantee.
Declined or expiredA terminal declined or expired wait projects an outcome into its assistant node through the durable DAG outbox, with no execution or new turn; replay does not duplicate it.
Terminal releaseA terminal execution releases the active conversation's composer, unless a newer execution is active; the reply's terminal row arrives as a transcript update, with no reload. A continuation opening another approval publishes it on the shared WebSocket stream.
PeersClaude Agent SDK indefinite canUseTool waits, OpenCode permission/next.ts, Codex tools/approvals.rs.

Acceptance
  • Discussion: empty field with context; cancel keeps the request; sending declines and returns feedback in the turn with no extra message; Deny alone adds none; pending submission cannot approve; retries keep one command.
  • Questions, on real Composer and QuestionMode: Back, Next, Submit order, digits, custom and multiple answers, remounts, narrow and short views, collapse, session isolation, uncertain retry, receipts.
  • Mentions, on the real hook and menu: changed-query Enter cannot select old results; Escape survives a delayed response; failed and empty fallbacks; pending input and IME do not submit; disposal suppresses late work.
