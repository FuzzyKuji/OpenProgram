Git folder pills

A working folder inside a Git checkout gets a git half in its pill in the environment row: which branch, what changed, and the few Git actions a chat needs.

Which folders

FolderGit half
Main project folderYes, for a real project. Not the default home-folder project: that repository is OpenProgram's storage.
Each additional working folderYes
Outside a Git checkoutNone
Two folders in one checkoutOne git half: project first, then list order (git-chip-registry.ts). Separate worktrees have separate roots and keep their own.

Freshness

Nothing polls. A pill reads on mount and folder change, when its menu opens (the only read that lists branches and looks up the PR), when a turn ends, on window focus, on project change, and after a mutation on the same checkout (op:git-changed).

Backend

openprogram/state/worktree/folder_git.py holds the logic; ws_actions/folder_git.py moves it off the event loop. Every reply echoes path.

GIT_OPTIONAL_LOCKS=0 keeps status from contending with the user's git. GIT_TERMINAL_PROMPT=0 makes a push needing credentials fail, not hang.
