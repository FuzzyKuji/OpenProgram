输入框本地路径

桥封装 Electron 的 webUtils.getPathForFile，是渲染进程获取原生路径的唯一来源；渲染进程没有 Node 文件系统权限。每个 File 在任何读取前查询一次。

按项目

项目结果
有字节的文档沿用上传和预览。标记用原始路径；后端可另存会话副本。
图片多模态载荷加一个原始路径标记。派发给提供商前从附件元数据移除 source_path。
文件夹或不可读项没有字节的有效路径引用，不标“太大，未发送”
剪贴板 blob、普通浏览器文件没有原生路径：沿用上传和生成的会话路径

标记

@json
原始路径的 JSON 字符串，给 Agent。保留方括号、引号、反斜杠和尾部空格。读取方兼容旧的无引号标记。
@previewjson
不可变的会话副本路径，给 UI。没有它的旧消息仍可读。原始文件端点不把源路径的父目录加入可读根。
source_path
在每个上传附件上。只有该附件的确切源路径存在时，后端才保留前端标记，同名上传因此不混淆。

项目与附加文件夹

控件行为
项目 chip草稿的主工作目录。首个已提交轮次后只读：cwd、权限基线和会话仓库位置已固定。
文件夹加号附加工作目录；会话中可编辑。没有会话时按草稿待选项目确定主项目，不把它列为选项。
选择已有项目只更新草稿。新文件夹创建或解析项目并选中结果。
后端不可用以已连接后端的回复为准；控件保持原状态
边界与否决方案

不涉及：附件卡片样式、目录遍历、浏览器递归上传、文件系统扫描、新 IPC 处理器、上传大小、Programs UI、依赖。

否决：旧的 File.path；渲染进程开启 Node 集成；可读文件只发路径；在普通浏览器捏造相对路径；枚举拖入的目录。

验收
  • Preload 对同一 File 返回确切路径；能处理桥缺失、空结果和异常。
  • 文档、图片、不可读文件夹的标记含完整路径；带括号的文件名显示安全。
  • 含 ]、引号、尾部空格的路径在两个解析器间往返不变。
  • 无路径附件保持原标记；同名和混合来源附件不混淆；持久化不重复已带路径的附件。

实现状态

已实现。Preload 边界在 VM 中用同一 File 对象验证，没有做真实窗口拖动。
