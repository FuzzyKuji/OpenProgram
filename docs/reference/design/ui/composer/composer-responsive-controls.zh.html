输入框响应式控件

每一行按自己测量到的宽度响应，没有固定断点：同样宽度下，聊天和 DAG 页面的控件不同。菜单、值、键盘、提示和无障碍名称都不变。

环境行

级别显示
0全部
1名称限制在约 12 个字符并加省略号；Local chip 只留图标
2隐藏分支名：分支图标和 diff 徽标
3（data-compact）隐藏所有标签（状态、界面、项目、目录、DAG Fit、缩放百分比、Legend）；diff 徽标变成半绿半红的圆点

use-compact-environment-row.ts 关闭过渡（data-measuring）逐级布局，再动画到第一个放得下 clientWidth 的 data-squeeze 级别。它把 auto margin 归零后测最后一个 chip 的右边缘：这个 margin 让 scrollWidth 总是填满整行。回到更宽松的级别需要 12px 余量。分栏用同一逻辑。

方面规则
测量use-compact-controls-row.ts 在 .composer-bottom-row 旁放一份隐藏的 max-content 副本，累加各簇和间距，绘制前移除

为什么用副本不切换真实的行：它的 Button 对所有属性做过渡，仍会报告紧凑宽度

规则

  • 单行，不换行；不隐藏控件。输入框高度和 splitRatio 不变。
  • 标签不参与 flex 收缩。受限名称以省略号结尾。同一条过渡规则，不用 display:none。
  • 图标按钮保持大小、顺序和操作；聊天和执行用不同图标；深度图标颜色表示档位。
  • 原生 ResizeObserver 和 MutationObserver；不改模型、权限和深度状态。

方案对比
方案结果
容器查询只用于上下文环标签和深度卡片宽度：行的需求不只取决于宽度
无障碍名称复用提示、触发器和标签；视觉隐藏保留 DOM 语义
横向滚动只作为极窄宽度的回退
换成两行否决：改变输入框高度和记录底部间距
验收
  1. 溢出时经 data-squeeze 收缩到 data-compact，没有固定宽度特例或标签 flex-shrink:1。
  2. 所有标签共用一条动画规则。
  3. 分栏拖过阈值后，右侧设置和左侧权限、更多都可见且不重叠。
  4. 权限、聊天模型、执行模型和深度图标都能打开各自菜单。
  5. 变宽后所有标签恢复；重新选分栏、切换聊天和 DAG、刷新后依然如此。
  6. 底部控件静止时有不透明表面，边框 0，无阴影；悬停或打开时背景更强。
  7. 重新打开的上下文统计来自缓存；后台完成后更新缓存和圆环。
  8. 缓存按会话和分支隔离；过期请求取消；刷新失败保留缓存；32 项淘汰。
