Slash commands and context compaction

Slash commands

When input starts with / and has no space, the menu expands upward; a space closes it over 380ms. Enter runs a registered first word, otherwise sends chat. A menu that is closing does not intercept Enter. Skills, plugins and user commands come from /api/commands; built-ins win dispatch.

Optional arguments (only […]) run at once. Without a session, session commands keep the input and warn "Start a conversation first".

Known small issues
  • A registry item also named compact shows twice in the menu; dispatch still picks the built-in.
  • Jump to latest may overlap the menu position.

What compaction sends

One rolling summary. Further compaction combines the old summary and more turns into a new one.

[System prompt] [Current summary] [Recent uncompacted turns] [New user message]

All of them use compaction_started, compaction_finished and compaction_failed. The start shows in the run indicator. A /compact adds a system message when it ends; a stopped one reads “Compaction stopped; context unchanged.” A turn's own compaction that fails says nothing: the history is as it was and a later request tries again.

Steps

  1. Read rendered history from SessionDB: the summary and remaining turns. Text already covered is not reread.
  2. Threshold. Fewer than four messages: stop; the manual path explains. Already summary plus tail with no valid cut: nothing to compact, no model call.
  3. Summarize with a separate model call. Default tail: 10% of the window, clamped to 8k–40k tokens, at least four non-empty messages. /compact 2000 overrides.
  4. Persist a summary_* node (role=llm, name=context/summary, sent as a user message that says it is a summary); covers_ids marks the range. Old turns stay and HEAD does not move.
  5. Graph. The DAG shows a capsule. A chain has one summary in effect, the one covering furthest; an older one is superseded and stops rendering (Compaction).
