思考面板里的 Fast

展开的思考面板标题行依次是思考深度标题、靠右的 Gauge 按钮和帮助提示。没有单独的速度胶囊或菜单项，收起的深度控件只显示深度标签。思考深度保持独立。

连接

连接能力请求
xAI API，Grok 4.6只对 https://api.x.ai/v1 上的 grok-4.6 支持，绝不按名称前缀Fast：service_tier: priority。Standard：default。
Grok 订阅，Grok 4.6CLI chat proxy 接受相同取值。其他订阅模型保持未知。相同
自定义网关不凭模型名继承。连接配置可以声明支持；显式 false 优先。仅在支持时使用配置的适配器映射
Codex、Claude沿用现有证据来源；UI 与派发用同一能力结果沿用现有 priority 或 speed 加 beta 映射

由 openprogram/models/providers/settings/fast.py 的 fast_capability() 解析：supported、unsupported 或 unknown，并带来源。chat.fast 是兼容投影。优先级：官方账户数据、连接配置、静态声明、目录；网络失败不清除有效的缓存声明。

行为

方面规则
默认Standard。按对话分支保存，切换和发送时都会写入，并按连接/模型保存。没见过的连接从 Standard 开始，换模型不会开启付费档位。
关闭显式发送 Standard，覆盖 Agent 的 priority 默认值。省略字段会继承它。
生效范围下一次提交的轮次。排队消息保留自己的设置；运行中的请求不变。
授权后端按轮次实际的提供商和模型解析，派发前再校验。其他执行模型解析自己的能力。
未验证的连接可见、可聚焦、不可用的控件，附说明。不支持与未知是两种状态；不说成模型没有 Fast。
没有深度滑轨同一弹层，有速度控件，无滑轨
面板打开时隐藏“跳到最新”，避免叠放。切换后面板不关，滑轨不动。

参考与否决方案

采用：xAI 的请求档位与实际档位分离，走 OpenProgram 现有的 OpenAI 兼容 xAI 适配器。否决：全局按 Grok 名称前缀覆盖、用降低推理代替 Fast、固定速度倍率。

验收
  • 能力：xAI API 和 Grok 4.6 订阅与未知订阅模型分开；切换连接更新原因；目录失败保留已知支持。
  • 输入框：键盘和指针都能选择速度，重载后保留，换模型从 Standard 开始，窄布局可用。
  • 派发：只有所选的受支持连接发送 priority；排队设置稳定；推理参数不变。
  • 响应：合成的 priority、default、缺失、错误、取消响应状态准确，没有重复请求或捏造的价格。

实现状态

仪表、能力、请求偏好、保存响应档位和 xAI 实际费用已实现。真实付费调用不在自动验证范围内。
