交互反馈

点击启动的操作只要超过约 100ms，界面就立即有可见变化。

三个层次

层次行为
0ms 乐观状态任何网络 I/O 之前，客户端显示过渡状态：加载卡片、高亮目标、正在停止、待处理消息。以有类型的本地行、服务端行上的覆盖层或标志写入 session store，从不改写服务端行。
服务端快速确认0ms 的行是带本次发送 clientRequestId 的有类型本地行。服务端把同一个 id 存在用户节点或函数运行预先创建的节点上，所以第一个带这个 id 的读取或 turn_upsert，无论哪个先到，都原位替换本地行，不闪烁。发给还没有该聊天视图的 socket 的确认，把这次读取作为 first_read 带上。
流式更新编号的 transcript_update 变化填充行（树、步骤、状态），文字帧按偏移追加文字；终态 row_upsert 收尾。先于服务端显示的字段是覆盖层，在约定事件发生时结束：终态、下一次读取、服务端给出相同值、行离开，或请求失败。
失败回滚（必需）真实数据替换状态，或超时恢复并显示错误提示：控制操作为 10s，OPTIMISTIC_TIMEOUT_MS。

共享辅助函数

apps/web/lib/runtime-bridge/optimistic-action.ts 中的 optimisticAction({apply, settled, revert, onTimeoutMessage})。

参数作用
apply设置 0ms 状态
settled()真实数据替代后为 true：消息已从 store 移除、树已重新填充、branch.active 已切换
revert超时且 settled() 仍为 false 时运行，并显示提示

用于确认路径是 load_session 重载的界面（重试、版本切换）。纯本地短暂状态（停止、fn-form 占位、分支切换）内联这一模式。

各界面的行为

界面点击后的前 100ms
聊天发送欢迎页 0ms 隐藏；socket 接下发送后，用户消息作为待处理的本地行加入，约一次往返后 chat_ack 给它服务端 id；回复随服务端的轮次到达
停止按钮0ms 清除 runningTask，在回复上设置已取消的覆盖层并保留已流出的文本；同时处理发送队列
函数调用重试0ms 卡片变为加载状态并显示运行中，切换器变为 N+1/N+1；重载后填充；10s 回滚
fn-form 或欢迎页提交0ms 以本地行插入待处理运行卡片；带其请求 id 的读取替换它；POST 失败则移除并提示
Runtime < N/M > 切换器0ms 当前卡片变为加载状态并显示目标同级索引；重载替换内容；10s 回滚
聊天消息 < N/M > 切换器0ms 标签更新到目标；重载填充；失败时恢复标签并提示
分支面板切换0ms 高亮所点的行；真实 branch.active 替换；10s 自行清除
聊天重试、编辑、分支、回退setBusy(true) 使按钮变暗，setRunActive 禁用编辑和重试
侧栏切换会话router.push；路由切换时渲染缓存消息
启用或禁用模型、工具、开关立即更新本地 store

新的乐观状态使用 store 的既有机制：类型化的本地变更（applyLocalChange）和覆盖层、siblingIndex、setRunningTaskFor。不建并行状态。
