Resources and operation preview

Resources lists every target a conversation uses, by type. One chat preview follows the target the viewed branch operated on last. Agent-opened Pages stay in the background and add no top tabs.

Related: Session resources, Resource panel and preview interaction, Browser control surfaces, Agent control overlay.

Resources has no Pin control and no search field. Explicitly pinned or user-opened top pages remain ordinary views; migration does not close them.

Following

Scope
At most one preview per App window. Preferences belong to the viewed conversation and branch, and resource selection never changes that branch.
Trigger
Only host-admitted operation events in that branch, including observe. Opening a resource, status polling or a screenshot does not switch.
Auto preview
The More checkbox Automatically show the page the Agent is using turns it on and returns to the latest admitted operation. A clicked target stays until the next operated Page replaces it.
Fixed preview
Checkbox off: the current Page stays. The Agent continues and cannot replace it. Not persisted across reloads.
Child agents
A parent follows its own and its child executions in host dispatch order, naming the active agent. A child window follows only its branch.
Changing branch
Restores that branch's preference; a new one follows its latest target, its unavailable state, or an empty state. Other branches keep running but cannot replace the preview.
Closed target
Clears Operating and shows unavailable or last frame until a newer admitted operation or a new selection. It never falls back to an older resource.
Other branch's resource
Inspecting neither checks that branch out nor grants write access.
Native windows and terminals
  • A function result naming target (window_id, pid, app_name) moves the preview to that app.
  • The worker keeps only the latest window and screenshot per conversation, in memory, broadcasts native.window and serves /api/session/{id}/native-window/frame.
  • A GUI step inside an agentic subprocess forwards the window to the worker, which attributes it to the owning conversation.
  • The preview shows what the Agent last saw, not a live view.
  • A terminal moves the preview when it starts running or receives input; the preview mirrors its screen read-only.
  • Pinning keeps only Pages.

Preview chrome
  • One row that never wraps, at the 240px minimum, the 300×198.75 default (300×168.75 image plus header) and the 720px expanded width: ellipsized title, status, Open page, More, Close preview.
  • Show actions and Operation history are in More.
  • Failure text is reachable through the status indicator, title tooltip and aria-live.
  • Resizes from four edges and four corners.
  • On narrow product layouts a Resources drawer selects the target while chat and preview stay reachable.
Capture and geometry
  • A never-shown Page starts with a 1920×1080 CSS-pixel viewport at normal page zoom. Preview bounds and layout zoom follow the preview size. A Page returned to the background keeps its last native bounds.
  • Desktop preview is the native Page with live rendering, including while dragged. Plain-browser previews use a separate sandboxed iframe, under browser embedding limits.
  • Only the visible preview subscribes to frames. Each frame carries resource ID, connection generation, sequence and capture time; frames from an old binding are rejected.
  • Delayed or failed capture is labelled Last frame, with its age; no image shows No frame.
  • Drag caches container bounds on pointer down and moves by transform on animation frames, without layout reads or state writes. Pointer up, cancel or lost capture writes one clamped position. Unmount, live-loss or a resource switch discards the drag.
  • Capture pauses during a drag. A capture begun before the pause is discarded, and only one capture is ever in flight.
  • Rapid target changes coalesce over about 200ms and render only the latest frame.

Ownership and concurrency

Descriptor
Resource ID, type, sanitized target, actual owner, lifecycle, connection generation, preview capability. Handles and leases stay in the host and are not restorable.
Association
Originating invocation, branch, child agent, sharing mode, keyed on stable branch identity or verifiable fork lineage. Forking does not duplicate external page state.
Identity
Distinct Pages with one URL stay distinct; rows for one actual Page merge. Titles and secret query values never establish ownership, and secret query parameters are not stored.
Child agents
Listed under the originating parent branch with their actual owner. Later work cannot rewrite provenance, and a shared group grants no access.
Branch writes
Ancestor resources show Referenced from. A browser write defaults to an independent Page, without claiming site or login isolation. Native windows and VMs need explicit transfer or another target.
Write leases
Exclude conflicts at the input scope. A second writer gets busy, with no queueing or preemption. A child's lease ends with it; the parent does not inherit it.
Events
Carry session, branch, resource, generation and monotonic sequence. Stale ones are discarded after branch change, reconnection or revocation.
Legacy records
Without provable branch ownership they sit in Unassigned, with no guessed migration.

Operating runs from validated adapter dispatch to receipt, confirmed cancellation or failure. Idle targets keep their connection without high-frequency capture; host applications are not scanned.

List and row appearance
  • Files, Activity and Resources stay the vertical navigation at the top of the right sidebar. No bordered card per resource.
  • Group headings reuse the left sidebar's SectionHeader: 14px secondary text, a 16px chevron after the title, count as trailing action; Enter or Space folds that group only.
  • Rows are about 44–48px: title, then type, state and child-agent name when needed. Long titles truncate; details show full title, sanitized origin and identity.
  • Operating and selection are distinct, with text as well as colour.
  • Webpage rows have three Lucide icon buttons: Preview in conversation, Open in tab, Close webpage (24px target, 14px glyph, PiP toolbar treatment).
Later review and learning
  • Existing receipts hold task, branch, resource, before and after observation, target, parameters, order, outcome and human corrections. Visible cues use the same source.
  • With user approval a later task may read selected sanitized excerpts to analyze targeting errors or propose reusable rules.
  • Record my next demonstration is a separate opt-in with explicit start, stop, scope, preview and deletion. Secret fields, passwords, secure input and credential-bearing URLs are never kept.
  • Images persist only after permission and redaction checks; otherwise only content-free metadata stays.
  • Task-local review, saved steps and model training are separate stages. Nothing trains or uploads automatically; proposed rules are validated on independent test targets.

Acceptance cases
  • One branch opens five pages: no extra top tabs, all listed, operations select the preview. Preview in conversation on a never-opened Page adds no tab and enters Fixed preview.
  • Two branches and their children run concurrently: provenance kept, no rebinding.
  • Inspecting A while the Agent operates B: A stays, B shows Operating, enabling automatic display returns to B, tab focus never moves.
  • Close preview, resizing and group collapse neither reload pages, stop VMs, grant control nor destroy targets.
  • Closing an active target, revocation, late frames, restart and disconnection have explicit states; unconfirmed stopping is not a confirmed pause.
  • Opening a tab fills the content area; undimmed content stays interactive and focus alone does not pause.
  • Markers never intercept input or draw from stale geometry.
  • Same-process windows, concurrent user input and two VMs verify conflict scopes independently. Successful capture does not establish background input.
