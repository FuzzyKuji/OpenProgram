作用域与全局保持同步

方向做法
作用域到全局setter 先更新自己的实例，面板同一拍重绘，再写穿到全局按 key 的 setter。钩子在全局 store 初始化时由 installScopeWriteThrough 安装，保持导入单向。
全局到作用域setComposerInputFor、setComposerSettings、setRunningTaskFor 调用 pushToSessionStore，WS 帧、旧桥接或标签转移都能到达活实例。
初始值实例首次渲染时从全局 map 取初值，刷新后重新挂载能显示已持久化的草稿。

没有镜像：全局 store 没有 composerInput、composerSettings、runningTask 或 contextPanelFor。聚焦会话的草稿就是 composerDrafts[activeChatKey]，用到时计算。需要比标签活得久的数据（localStorage、标签转移的传输格式、跨会话的侧栏视图）留在全局按 key 的 map。

为什么用实例而不是全局按 key 分片
做法例子取舍
每实例一个 store（采用）VS Code 编辑器组；Zustand 支持隔离最强。共享数据需要另一层。
一个全局 store，按 key，加作用域标记Redux 规范化、TanStack Query、Slack 式多频道界面调试和跨会话功能容易，但靠约定维持：读一次全局指针就退化。
物理隔离Chrome 渲染进程因运行不可信代码才值得；应用自己的分栏不值得付进程内存和 IPC 成本。

按 key 分片时每次读写都要给 key，给错或省略（等于聚焦会话）类型上都合法。实例由 provider 一次给定 key。一次按键也只通知该会话的订阅者。并行的 Record<sid, T> map 保留，转录行按视图存放，实例靠它们持久化。

全局单值造成的故障

组件渲染两次，读取的状态只有一份。两份显示同一个值，或者后写的赢。类型系统允许这样做，只在分栏且特定操作后才出现。

/context 徽标：全局布尔值会同时打开两个弹层。contextPanelFor: sid 指针能修复，但每个使用方仍要比较正确的 id。在作用域里它只是普通的 contextPanelOpen。

镜像，即聚焦会话按 key 条目的全局副本，更糟：每次写两份，每次切换要换，组件要判断是否绑定会话，窗口间转移还要重建它。

按会话

Record<sessionId, T> map。

字段内容
conversations侧栏每会话摘要（虽然按键存，但它是一份*列表*，见 C 类）
rowsByView每个视图（一个会话，或一个子代理的转录）的转录行，按视图和行 id 存；同一 id 在两个视图里是两行。通过 selectRow(viewKey, id) 读取，读出的行带上覆盖层。只经 apply-transcript-update.ts 写入：读取用 applyRead，服务端的实时行用编号的 transcript_update 变化和文字帧，只有本浏览器持有的行和覆盖层用 applyLocalChange。
messageOrder每视图的行 id 有序列表
overlaysByView、heldFramesByView本浏览器先于服务端显示在行上的字段，各自带着结束它的事件；以及等待所属行的文字帧
pendingProjectsByChat未发送会话选定的项目，按临时 chat key 存
runningTasks每会话运行任务；驱动各自 composer 的发送/停止按钮
trees每会话最新的实时 context 树
tokens每会话 token 用量
contextWindow每会话上下文窗口大小
heads每会话当前 DAG head（选中的分支尖端）
additionalWorkingDirsBySession每会话附加工作目录

composerSettingsBySession每会话工具开关/思考强度，持久化

pendingDecisions 是扁平 FIFO，每项带 sessionId（session-store/types.ts）；每个使用方都要过滤，作用域错了会吞掉或重复显示别的会话的问题。

旧运行时状态

runtimeState（lib/runtime-bridge/state.ts）是早于 React store 的模块级单例。WebSocket 帧进入运行时桥接，桥接更新它并写穿到 store；conv-store-mirror.ts 保持 store.conversations 权威。它是过渡层。

字段含义
currentSessionId旧的当前会话。chat-handlers.ts 和 conversations.ts 里以 session_id === runtimeState.currentSessionId 把关的帧，对非聚焦会话会被丢弃或错误路由。
conversations包含完整消息的按会话大 map，与 store 的摘要不同
isRunning一个全局标志

非分栏的消息渲染、会话切换、分支徽标刷新和大部分帧路由仍默认走它。分栏面板绕过它：#chatView 是单例，约十个桥接模块用硬编码 id 访问，所以分栏时 AppShell 把它隐藏，每个面板从 store 渲染 React 并自己发 load_session。

移除它需要什么
  1. chat-handlers.ts 和 conversations.ts 里每个 currentSessionId 判断都变成按 data.session_id 的 store 写入，后台帧才能落地。先要有焦点指针。
  2. runtimeState.conversations 没有按 key map 覆盖不了的读者，conv-store-mirror.ts 不再必要。
  3. isRunning 没有读者；runningTasks 已覆盖。
  4. #chatView 外壳移除，换成 PeerSessionPane 已证明可行的 React 路径。这是最重的一条。

错误移除判断会静默丢帧，所以每次移除都要配一次“帧仍到达其会话”的检查。
