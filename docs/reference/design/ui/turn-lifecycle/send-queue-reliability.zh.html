队列与插话

按键动作去向
回车、发送按钮插话当前这次执行，在支持的安全点
Cmd/Ctrl+回车排队上一轮结束后的一条后续消息
停止取消单独的控件；上面两个动作都不取消

没有常驻偏好：发送时按的键决定。目标由当前会话及其运行中的执行决定，绝不选择其他会话或子 Agent。

投递

方面规则
保留到匹配的已应用回执确认用户消息已持久化；仅进入安全点仍算应用中
命令携带只有消息、精确执行身份、版本、幂等键。不改权限、模型、工具或程序
发送前客户端保留不可变的信封
确认丢失投递未确认：该行保持可见，普通排空不能重发，确认重试复用信封
确认定时器每行一个；1.5 秒，传输失败后退避到 30 秒。明确回执清除
版本过期拒绝针对同一执行的新快照发一个新信封
目标在用户请求时绑定。版本重试只刷新版本，不能换成另一个执行
不支持或已结束条目保持排队；空闲对账按 FIFO 排空普通后续消息。执行结束时未投递的插话被拒绝，这些行可恢复排队
停止把在途指令保留为未发送草稿，即使尚未接纳。不确定的命令在明确回执前不可变；停止不能抹掉它，也不能允许普通发送
工具不因插话到来跳过已完成的工具批次
持有者过期不能授权迟到的输入写入。执行关闭时解决未投递命令，即使在等待效果对账

错误可见；传输失败后注入标记总是释放。参考：Codex 提示、App Server 插话（绑定预期轮次，不接受运行时覆盖）。OpenProgram 用自己的执行命令服务和安全点，没有第二个会话收件箱、消息代理或模型专属传输。

队列卡片

输入框上方停靠的一张浮起卡片。标题显示行数和有多少加入当前轮，并可折叠卡片。

行部件说明
标签插入当前轮（插话在途）、下一轮（等待）、未发送或待确认（失败后）
文本首行；点击展开完整消息和附件
动作，悬停或键盘聚焦时显示加入当前轮（不取消）、重试、编辑、投递确定时可移除
全部清除一次写入移除所有行，正在投递或编辑的除外，绝不排空将被移除的行
限制附件保持草稿行为；插话接受最多 4,096 个 Unicode 码点的文本

存储

数据位置
普通队列项、附件渲染进程内存
待确认的文本插话回执、已停止或结束的插话草稿同窗口 session storage；刷新后恢复且不重放聊天；尽力而为，不是第二份命令日志
已接受的命令服务端规范接受
已应用的输入持久化的用户消息

待确认的插话在解决前不能作为普通消息排空。读取或转录更新带来带有该插话命令 id 的行时，插话即确认；读取之后，未解决的命令用原身份确认。

历史

  • 普通后续消息在更新服务端镜像前从持久会话头解析前驱，包含上一回复、工具结果和已投递的插话。显式分支前驱不变。
  • 已取消和中断的轮次保留部分内容并显示终止状态，包括空回复。取消提示不推断是谁取消的。

函数重试确认

每次重试带一个请求身份，由确认或拒绝回传。接受定时器在派发时结束，不等函数完成。拒绝或断线发送只恢复对应的待处理卡片，原因只报一次。缺失的确认保持不确定，不自动重发。历史和界面校验仍然权威。

验收和审计覆盖
  • 排队两条后续消息，各自在上一轮结束后开始。
  • 工具运行时加入文本：同一执行和工具继续；指令进入之后的模型上下文。
  • 确认丢失：保留该行，重放同一命令且不重复投递。
  • 已结束、不可用和不支持的目标保留输入并报告状态。
  • 切换范围不能插话到别的对话。
