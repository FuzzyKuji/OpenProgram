WebSocket 命令生命周期

命令和断线流程

事件响应之后
JSON 无效记录脱敏诊断；发错误帧且不回显原文继续接收
未知动作operation_error(code=unknown_action)，回传有效的 request_id继续接收
处理器异常只记录动作、会话和类型；在同一连接返回 code=handler_error继续接收
传输断开把连接移出集合检查是否还有别的连接聚焦该会话
没有别的连接，且存在旧版跟进队列放入 _FOLLOW_UP_DISCONNECTED_web_follow_up 的等待方收到
等待方收到哨兵变成 None；真正的空字符串仍是 ""其 finally 删除队列

入口

入口行为边界
_websocket_handler（server_runtime/websocket_dispatch.py）隔离 JSON 解析和处理器异常；处理器失败返回 operation_error 并继续接收WebSocketDisconnect 和发送错误帧失败会结束连接；写连接不无限重试
_handle_ws_command未知动作返回 unknown_action；已注册处理器的异常传到循环传输响应只含受限的动作、会话、请求元数据和注册的错误类别
_web_follow_up（server_runtime/session_persistence.py）等待会话队列；最后观察者断开或取消时返回 None进程内状态；跨 worker 重启不持久恢复
停止、删除取消对象和哨兵都不算回答；持有者的 finally 清理队列分发器绝不按会话清理。获取资源的动作用自己的持有者 token 回滚，如 _release_run_reservation(session_id, msg_id)

信任和兼容

  • 客户端数据不可信。错误帧绝不回显负载、异常信息、路径、凭据或回溯；回溯只写本地日志。
  • 前端仍能消费旧服务端的 action_error。
  • 还有别的连接聚焦该会话时，关闭一个标签不取消问题。
  • follow_up_answer 的传输形状不变；字符串和真正的空字符串都有效。
取舍和排除
决定项目
采用命令级错误帧（Starlette：WebSocketDisconnect 结束连接，清理放 finally）；最后观察者断开时发哨兵；按持有者清理；来自 QuestionRegistry.cancel_session() 的“取消不是回答”；旧版队列可返回 None
拒绝任一标签断开就取消；分发器按会话删除预留；应用异常后关闭连接；把哨兵传给业务函数
范围外把旧版 set_ask_user 迁到 QuestionRegistry；改动 runtime.ask、ACP、频道提问、发送队列或运行预留协议；持久错误存储、确认和重连恢复

交互响应

时刻规则
连接写入成功后只清除捕获的草稿，并在所属对话里显示本地待确认用户消息。预留保留文字和附件直到确认。这不代表执行已开始。
服务端确认对齐本地身份，不重复
拒绝保留可恢复消息，不覆盖更新的草稿
无关工作资源投影和会话或侧栏工作不能延迟接受，也不能阻塞事件循环
关闭资源针对精确的页面和关联身份，保持代和序号顺序，不扫描无关输入。本地反馈与原生确认分开；失败或更新的代不能被旧的待处理动作掩盖
验收
入口场景断言
_websocket_handler第一个动作抛 KeyError，第二个是 ping同一连接先收到脱敏 operation_error，再收到 pong
_websocket_handler无效 JSON不回显该帧；处理下一帧
_web_follow_up 加断线唯一聚焦的连接断开等待方在测试期限内返回 None，不是 300 秒后；队列被删除
断线另一连接仍聚焦该会话不发哨兵；返回另一连接的回答
follow_up_answer空字符串返回 ""，不当作断线
