No standing preference: the key decides at send time. The active session and its running execution set the target; another session or sub-Agent is never picked.

Pending steering cannot drain as ordinary messages until resolved. A steer settles when a read or transcript update delivers a row carrying its command id; after a read, unresolved commands are confirmed with their original identity.

History

  • A normal follow-up resolves its predecessor from the durable session head before updating the server mirror, including the preceding reply, tool results and delivered steering. Explicit branch predecessors stay.
  • Cancelled and interrupted turns keep partial content and show terminal status, including empty replies. A cancellation notice does not infer who cancelled.

Function retry acknowledgement

Each retry carries a request identity echoed by its acknowledgement or rejection. The acceptance timer ends at dispatch, not when the function finishes. A rejection or disconnected send restores only that pending card and reports the cause once. Missing acknowledgements stay uncertain and are not resubmitted. History and surface validation stay authoritative.

Acceptance and audit coverage
  • Two queued follow-ups each start after the preceding turn ends.
  • Text added while a tool runs: same execution and tool continue; the instruction reaches later model context.
  • Lost acknowledgement: row retained, same command replayed without duplicate delivery.
  • Ended, unavailable and unsupported targets retain input and report state.
  • Scope switching cannot steer another conversation.
