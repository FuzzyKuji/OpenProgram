轮次占用

一个会话只允许一个进行中的轮次。运行时输入进入队列。停止是打断：占用在取消意图发出时释放，不等旧轮次线程结束。

停止

  1. 为规范执行发送 execution.cancel（use-chat-submit.ts 的 stopSession）。
  2. 用 Stop 覆盖层（stopOverlay）把进行中的回复画成 cancelled，保留已流出的文字。覆盖层盖在行上，从不改写行：服务端的行到达已结束状态，或服务端拒绝这次取消的命令 id 时，它就结束。
  3. setRunningTaskFor(sessionId, null, "always")：队列在 0ms 排空，发送可用。不因旧轮次收尾禁用发送。

如果运行任务上留着 cancelling: true 或用 drain: "never"，输入框会锁到 running_task_clear。Claude Code：运行时回车排队，Esc 打断后发送队列。Vercel AI SDK：stop 立即中止。

不变量

规则说明
每侧一个占用来源客户端：runningTasks，映射到输入框。服务端：_running_tasks 加规范驱动。行的 status 只渲染气泡，不控制输入框，反之亦然。行的状态只由服务端的 transcript_update 写；占用帧不写行
终态不可逆一旦 cancelled、completed、failed、error、interrupted 或 done，后续帧不能恢复运行样子。cancelling 是服务端内部状态，客户端当作已取消
占位不覆盖身份空的 { msg_id: "" } 预留只能写入空槽；msg_id 和 execution_id 才让停止能取消
只有本轮的终止帧释放占用嵌套的 display:"runtime" 结果只结束它的卡片。已取消轮次的迟到 running_task 不能复活槽位
停止不静默失败解析不到执行时服务端发错误帧，相当于 HTTP 路由的 404

与 Codex CLI（取消权在核心会话的运行轮次，UI 状态来自 TurnStarted、TurnCompleted、TurnAborted，协议没有 cancelling）和 Claude Code（QueryGuard 同帧转空闲，部分文字作为普通消息提交）一致。

在取消意图时释放

槽位是 _running_tasks；规范驱动持有当前尝试、协作取消事件和尝试代数。传输预留不占 run_control token，也不从 {msg_id}_reply 推导 id。cancel_execution 成功时：

  1. 把已接纳的 execution_id 对应到 session_id 和 msg_id。
  2. _finish_owned_run(session_id, msg_id) 移除传输槽。msg_id 不匹配时不做事，所以新预留安全，被取消轮次的 finally 也无害。
  3. 广播 running_task_clear，指明结束的轮次。

下一次 _try_reserve_run 不等旧驱动线程。只有与槽位执行匹配的 clear 才生效；停止并发送后的无范围 clear 已过期。

运行状态帧按 run_seq 排序

running_task、running_task_clear、run_state 和 session_loaded（run_active、run_task）都带它：服务端递增数（server._next_run_seq()，微秒墙钟时间，跨 worker 重启仍递增，在 JSON 里精确），在读取该帧运行状态之前取得。

帧客户端
乱序加载读到“运行中”，却在 clear 之后才发出，所以只应用比该会话上次更新的 run_seq（lib/chat/decisions/run-seq.ts 的 acceptRunFrame）
过期的加载仍确认恢复的 steer 回执，但不动槽位和队列
没有 run_seq（本地占位、聊天确认）照旧应用，由 clear 的身份匹配把关

迟到帧

帧规则
已取消 execution_id 的 running_task不能复活任务：由 run_seq 和待处理的取消把关
Stop 之后的文字和行变化不发送。_broadcast_chat_response 在停止后不再发文字帧，发布器丢弃已取消执行的行的非终态变化。终态 row_upsert 照常发出，并结束覆盖层
被拒绝的取消拒绝附带的 latest_snapshot 证明运行仍在继续时，覆盖层清除，运行占用恢复，之后的文字照常出现
已完成轮次 result 之后的 running_task只清掉输入框的运行任务。回复行的状态来自服务端的 transcript_update，客户端在这里不写行

0ms 规则：交互反馈。队列机制：队列与插话。

HTTP 中止

机制规则
iter_until_cancelled位于 providers/utils/cancelable_stream.py：在一个 __anext__ 未完成时最多每 250ms 轮询取消信号，取消后退出，让 async with 关闭流。Anthropic 和 OpenAI Completions 适配器使用它。
不用 wait_for不要对下一块 wait_for：超时会取消那次读取，杀死 httpx 和 OpenAI 的 SSE 迭代器。Grok 思考时常超过 250ms 没有分块，会结束成空回复。
finish_reason结束轮次。Grok 和 xAI 常在最后一个 token 后不关闭 SSE，所以用量只收 USAGE_DRAIN_S（1.5 秒），随后 EventDone。

四秒宽限

CANCEL_GRACE_S = 4.0（run_control/owners.py）只在持有者有子进程或会杀子进程的 terminate 钩子时适用。只有 token 的聊天持有者在取消意图后不等待。服务：runtime/execution/control/ 的 RuntimeControlService.request_cancel。
