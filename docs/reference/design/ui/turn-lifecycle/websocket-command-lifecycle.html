Trust and compatibility

  • Client payloads are untrusted. Error frames never echo payloads, exception messages, paths, credentials or tracebacks; tracebacks go only to the local logger.
  • The frontend still consumes an older server's action_error.
  • Closing one tab does not cancel the question while another connection focuses the session.
  • follow_up_answer's wire shape is unchanged; strings and real empty strings stay valid.
Choices and exclusions
DecisionItems
AdoptedCommand-level error frames (Starlette: WebSocketDisconnect ends the connection, cleanup in finally); a sentinel on last-observer disconnect; owner-scoped cleanup; "cancellation is not an answer" from QuestionRegistry.cancel_session(); a legacy queue that can return None
RejectedCancelling whenever any tab disconnects; dispatcher deleting reservations by session; closing the connection after an application exception; passing sentinels to business functions
Out of scopeMoving legacy set_ask_user into QuestionRegistry; changing runtime.ask, ACP, channel questions, the send queue or the run reservation protocol; persistent error storage, acknowledgement and reconnect recovery
