Turn occupancy

A session admits one live turn. Typing while it runs queues. Stop is an interrupt: occupancy is released on cancel intent, not when the old turn's thread dies.

Stop

  1. Send execution.cancel for the canonical execution (stopSession in use-chat-submit.ts).
  2. Draw the live reply as cancelled through a Stop overlay (stopOverlay), keeping streamed text. The overlay sits over the row and never writes it: it ends when the server's row reaches a settled status, or when the server rejects that cancel's command id.
  3. setRunningTaskFor(sessionId, null, "always"): the queue drains at 0ms and send is enabled. Send is never disabled for the old unwind.

cancelling: true on the running task or drain: "never" would lock the composer until running_task_clear. Claude Code: Enter while running queues, Esc interrupts then sends the queue. Vercel AI SDK: stop aborts now.

Release on cancel intent

The slot is _running_tasks; the canonical driver owns the active attempt, its cooperative cancel event and attempt generation. Transport reservations claim no run_control token and derive no id from {msg_id}_reply. When cancel_execution succeeds:

  1. Match the admitted execution_id to session_id and msg_id.
  2. _finish_owned_run(session_id, msg_id) removes the transport slot. It no-ops on a mismatched msg_id, so a newer reservation is safe and the cancelled turn's finally is harmless.
  3. Broadcast running_task_clear, naming the finished turn.

The next _try_reserve_run does not wait for the old driver thread. A clear is honored only when it matches the slot's execution; an unscoped clear after stop-and-send is stale.

Run-state frames are ordered by run_seq

running_task, running_task_clear, run_state and session_loaded (run_active, run_task) carry it: a server-wide increasing number (server._next_run_seq(), microsecond wall time, increasing across worker restarts and exact in JSON), taken before the frame's run state is read.

Four-second grace

CANCEL_GRACE_S = 4.0 (run_control/owners.py) applies when the owner has a subprocess or a terminate hook that kills a child. Token-only chat owners do not wait after cancel intent. Service: RuntimeControlService.request_cancel in runtime/execution/control/.
