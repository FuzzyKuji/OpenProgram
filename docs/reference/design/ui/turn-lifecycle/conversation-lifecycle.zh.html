对话生命周期

归属负责
转录每个视图的行，只由转录 reducer 根据读取、编号更新和有类型的本地变化写入；每个视图同时最多一个读取；分页、搜索目标、滚动锚点
执行单调游标和状态版本；当前任务和审批身份。快照恢复不模拟新的终止事件
输入框会话持有的草稿、附件、队列项和确认。导航或断线不清除未确认的输入
连接代定时器、待处理读取、分片缓冲。过期响应不能改变新连接或可见会话
服务端授权、执行、取消、审批。任何客户端优化都不能绕过

存储失败只降低持久化，不影响事件投递。本设计不包含新的执行运行时、远程服务、账号集成或删除历史数据。

转录读取

方面规则
归属每个会话和连接一个待处理的初始或刷新请求。导航复用；变更使其失效并保留一个使用最新选项的替换请求
响应每个响应回传请求 ID。过期、被替换和已关闭连接的响应被忽略
期限15 秒；会话内显示加载、断线或失败状态和重试按钮；缓存消息保持可见
不合并读取替换它所覆盖窗口里的服务端行。读取进行时，服务端暂存该视图的更新和文字帧，回复之后再发，所以读取不会撤销更新的进展。本地行（发送、函数占位、提示）和覆盖层在读取后保留；读取或更新带上某个本地行的 clientRequestId 时，这个本地行离开。没有第二个转录 store
无效游标围绕阅读锚点做一次无游标读取；失败可见可重试，自动翻页停止
显式重试保留分支头的无游标锚点读取；锚点不存在时有单独的“最新历史”动作
安全加载转换不重置指数重试延迟。读取重试绝不重复变更、提交、审批或取消

流式

  • 文本和思考帧合并成一次动画帧 store 更新，按偏移放进每个持有该行的视图。编号更新或读取先刷新待处理的文字。
  • 工具、步骤、引用、状态和终态行都以编号的 transcript_update 变化到达，和读取画出的行相同。
  • 文字帧的偏移超过行里已有的文字，说明丢了一帧；更新不接着视图的修订号，说明漏了一次。两种情况视图都在锚点读一次。
  • 连接关闭时先刷新已收到的文字，再清除每个轮次属于哪个会话的记录。
  • 渲染基础：有界历史窗口、按测量回收的行、工具输出懒加载、独立的跟随锁。

恢复读取

恢复读取使用只取快照模式：执行记录和事件游标来自同一个 SQLite 事务，不读事件正文，因为持久化的流可能超过 200 MB，而 Web 回放处理只消费快照。显式的事件历史客户端保持完整回放。

促成这一设计的基线
指标数值
原生刷新到转录出现11–14 秒
直接的初始历史请求0.18–0.20 秒
第一次历史请求之前处理 16 次恢复；一次刷新加载五次历史

重连路径在所选对话之前发送所有持久化游标，每个连接串行处理命令，回放快照进入实时更新路径并为终止执行再请求转录，游标存储在每帧同步持久化。这些是基线数据，不代表优化后的 App。

对话加载期间的资源

资源轮询与转录加载共用 worker。

项目规则
复用每个资源列表请求在所有可见资源间复用一张对话图、一个前驱索引以及缓存的来源和分支名结果；当前分支查询可用一份单独快照。这些只在该请求内存活
权威可见性、执行归属、控制对账和稳定分支引用选择仍然权威
效果受影响对话上同等查询从 5,741–5,760 ms 降到 124–147 ms（仅资源查询，不是页面加载）
