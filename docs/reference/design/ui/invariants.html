Cross-module UI invariants

Breaking a rule changes this list first, then the code. Each rule should have a pinning test under tests/unit/.

Rules 1 to 3. A new entry point that changes the set (config import, bulk operations, CLI writes) hooks the same broadcast; Settings may be in another tab.

RuleHolds through
1. The enabled set is the only model gatelist_enabled_models(): spec rows in the providers config. Disabled means no picker, no default, no chip
2. Enabled-set changes broadcastEvery consumer reacts, as drawn
3. Disabling the last used model forgets itNew conversations start on last_used_model in config.json; there is no default. Hiding would keep it serving background work and bring it back on re-enable
4. The frontend store can express clearedsetAgentSettings field: object replaces, null clears, undefined keeps. ?? alone cannot overwrite a stale value; any field the backend can report gone needs this
5. Backend-to-frontend frames go through the event busemit_ws_frame({"type": ..., "data": ...}); one server subscriber forwards to the sockets (event layer). _s._broadcast hides a frame from bus consumers (proactive, logging) and audit. Exempt, carrying session routing: _broadcast_envelope, _broadcast_chat_response
6. The three spawn entry points share one semanticsClean mode: spawn_caller makes the branch root's caller the opening turn, not ROOT. Change and test together
7. The chat sibling switcher appears only on real forks< N/M > sets group by fork point (predecessor, else caller; ROOT means none) and hold conversation turns only
8. Instant interaction feedbackInteraction feedback. Function runs pay about 1s of subprocess cold start, which must never feel like a dead click
9. Display order may change; data order may notThe attach pointer stays at the tail for head movement, yet the Spawned card renders before the reply it fed. Solved in the server projection (transcript/children.py), never in persisted order or head semantics
10. SSR boundary: no window at module scopeapps/web/lib/runtime-bridge/* may read window at module scope (session/chat-handlers.ts); a static import from a prerendered page breaks. New modules keep this or defer window access into function bodies
11. A transcript row draws what the server sentThe main chat, a split pane and an expanded sub-agent all draw through TranscriptRows. Each row dispatches on its rowKind with no default branch and takes its conversation from the row list, never from the focused one
