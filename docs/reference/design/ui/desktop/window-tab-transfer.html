Moving tabs between windows

A desktop tab can move to another OpenProgram window, or to a new window at the release point. When the move ends the tab exists in exactly one window; any failure leaves the source as it was.

The destination inserts before the source removes, so a live tab always exists.

Web pages keep their state

A web tab is an Electron WebContentsView. The coordinator moves that same object between windows and never calls loadURL, so redirects, sign-in, form values, scroll position, page memory and the DevTools target survive. It stays hidden until the destination reports new bounds.

Before reparenting: clear the agent action cue and control overlay, record each view's bounds and visibility, check the source still owns every view. A view in an active transfer is locked against a second transfer or an agent command.

Journals and recovery

  1. Before changing its tab store, each renderer writes a journal to window-keyed local storage (openprogram.tabTransferJournal:<windowId>): before and after layout, session state, file drafts, native-view bookkeeping.
  2. The main process records which roles opened a journal; the durable decision lists them as required.
  3. After a reload a renderer asks for pending decisions, applies committed or rolled-back, and finalizes its role.
  4. A window gone: another live window adopts the orphaned role.
  5. All required roles finalized: the decision is deleted.

Rollback

TriggerResult
Expiry, or destination or source failureRoll back
Escape, or a drag ending without a targetRoll back
A participating window destroyed or closingRoll back
Commit decision cannot be writtenRoll back
Already committedNever rolls back
StageRollback does
No journal opened yetDiscard the token, tell the source
Journal openedWrite rolled-back; destination undoes its insertion (2-second limit); every view returns to the source with original bounds and visibility; a torn-off window made for this move closes and its state is discarded
Source window goneThe moved views are closed, never left ownerless

Ordinary close rules do not apply: removing the source copy creates no close record, deletes no draft, and opens no fallback new tab before the destination acknowledges.

Routing after a move

Menu commands and agent web-tab commands go to the focused window only. Native-view messages are accepted only from the renderer whose window owns the view.
