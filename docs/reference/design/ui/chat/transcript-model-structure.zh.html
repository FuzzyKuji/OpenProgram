会话记录的行与归属

属于会话记录模型工程记录。目前已完成的内容：实现状态。

模型

在 .../transcript/schema.py 中定义一次。TypeScript 由它生成。

视图

键：session_id，或 <session_id>#sub-agent:<first job id>。同一对话的两个窗格共享一个视图。

  • turns：按序已加载的 Turn。顺序由服务端决定，客户端持有跨度。
  • window：{ head_id, revision, before, after, start, end, total }。与历史 hook 读取的名字相同，去掉 snapshot，加上 revision。以轮次计数。start 和 end 是轮次索引中的绝对位置，在 head 只前进时保持稳定。
  • 视图只有在服务端读取或携带窗口的聊天确认之后才有窗口。窗格绝不会把残留行误认为已加载的对话。

TranscriptView（服务端）

每视图一份，只有 id，没有正文：有序轮次、归属表（节点 id 到轮次、行和槽位）、带块 crc 的未结束行、子节点表、派生字段表、压缩槽位、目标验证锚点，以及 head_id（主视图）或 tip（子代理视图）之一。

部分规则
输入集合正好是会话记录显示的行：get_messages 的过滤（没有 display=root、rewound、structural 或隐藏的 context/*），再减去 execution_control 行及其 caller 后代闭包。带 assistant caller 的 role=tool 行按 aggregate_tool_messages 的方式折叠进父行。
链与失败链是 head 所在分支的分支顺序。被聚合折叠掉的 head 通过 _resolve_head 遍历解析；断裂的 predecessor 链回退到对同一输入集合的 predecessor 遍历。两者都是 legacy.py 中的具名情况。其他任何读取失败都返回可重试错误。

轮次成员（turn_index.py）。行按以下顺序分类，第一个匹配的决定结果：

  1. 附属行加入它所依附的行，绝不开启轮次：function=attach（仅 predecessor 或两条边都有）、运行时占位（type=status、display=runtime，且有 predecessor；重建的函数运行没有 predecessor，自己开启轮次）、工具行、caller 后代、带 covers_ids 的摘要。
  2. 压缩的 {id}_ui 和 {id}_card 行留在所在轮次内的确切位置。
  3. 插话（steering）和重启提示（trigger=restart）加入它们所在的轮次，被截断的回复和续接也一样。
  4. 以下开启轮次：可见的 user 行，包括 job_followup 和 display=runtime 提示；顶层函数运行；predecessor 不是当前轮次 user 行的 assistant 行（常驻代理的主动回复）；没有提示的 system 行。

spawn_branch_root 行绝不通过 caller 边被收进父轮次。caller 后代只匹配 _collect_exec_rows 的工具和叶子规则。

索引随 head 前进而扩展，在结构变化时重建。没有 socket 持有的视图放在容量 16 的 LRU 中。socket 持有的视图绝不淘汰。

存储的转录状态在索引保留而非重新读取的内容变化时前移：重挂，以及对摘要的元数据补丁，因为压缩行由摘要元数据画出。压缩在插入之后才写入 tokens_before、tokens_after 和 compacted_at。其他补丁只改行内容，每次读取都重新取。

所有非局部内容都从索引元数据计算，因此一个轮次可以单独投影：压缩槽位和 superseded_summary 来自摘要节点，spawned_from 来自 attach 节点，同级导航来自子节点表，目标标记来自对该会话执行的一次扫描，保存为 {assistant id: execution id} 并在新轮次出现时扩展。

轮次

{ id, rows }。id 是起始行的 id。放在第一个起始行之前的压缩行加入该轮次，但绝不成为它的 id，因此 id 稳定。

行

现有的 ChatMsg，相同的 camelCase 字段，在服务端构建。新增：

  • rowKind：user | assistant | function_run | system_text | system_event | compaction_card | agent_notice | received_message | spawned_root | sub_agent_step | external_reference | silent。dispatch() 的每个分支一个值，它没有默认分支。silent 覆盖 display=runtime 提示和内部目标轮次。
  • kind 和 slot 保持现有含义，不算新增：kind 是 compaction | snip | event，slot 是 card | event。system_event 行在那里携带子类型。compaction_card 行总是 kind: compaction、slot: card。只有 SystemEventRow 读取它们；覆盖读取 coveredBy。
  • status：pending | running | streaming | paused | cancelling | done | error | cancelled | interrupted，来自 status.py 中的一个映射。
  • steeringReplyId、continuedBy：由服务端盖上，因为机器人视图仍然绘制这些行。
  • continues：续接所合并的被截断回复的 id，最旧的在前。
  • attachCards、runtimeChildren、callRoots：名字不变。每个子项新增 blockId，即解析出的所属块，未配对时为 null。未配对的子项照样绘制，绝不丢失。
  • coveredBy：压缩 id。
  • user 行上的 origin：person | agent_delivery。
  • clientRequestId：metadata.client_request_id，在插话行上是 metadata.command_id。

块

按存储形状，加上 id 和 index。

  • 工具块：id = tool_call_id；没有 id 的旧工具块用 tool:N。
  • 文本和思考：id = <type>:<n>，其中 n 统计该类型的段数，一段是连续的同类型已存块。段的第一个块保持 <type>:<n>，同段后面的块是 <type>:<n>.<k>。流式 tap 把连续增量合并成一个块，所以它的块与最终分段的第一个块共用 id，未结束的步骤在最终写入重新分段时保持原位。
  • index 是在 blocks 中的存储位置。块总按 index 排序保存，所以块顺序绝不取决于到达顺序。
  • fullOutput 指向真实的行：<reply>_t_<tid>。

本地行与覆盖层（仅浏览器）

本地行是没有服务端副本的行：待发送、发送失败、乐观的函数占位、local_command 和无操作提示、压缩提示。它们不属于任何 Turn，并携带一个锚：

  • tail（发送和占位）：画在所有轮次之后，按创建顺序。来自别处的 turn_upsert 插在它们前面。由确认或带相同 clientRequestId 的服务端行移除。
  • afterRowId（提示）：紧跟在提示出现时的最后一行之后绘制。该行在窗口外时不绘制。

每个本地行都带 rowKind。待发送或发送失败是 user，乐观函数占位是 function_run，local_command 或无操作提示是 system_text，压缩提示是带 kind: compaction 的 system_event。带类型的本地追加要求这个字段，所以分发绝不会遇到没有它的行。

部分规则
覆盖层覆盖层是客户端在服务端发话之前改变服务端行显示内容的唯一方式。每视图：行 id、封闭的字段集（status、siblingIndex、siblingTotal、contextTree、chapterPinnedAt、reverted、turnFiles、goalVerification）、清除条件（until_terminal、until_field_matches、until_read、until_row_gone、until_command_rejected）和可选的回滚快照。
合并selectRow 合并行和覆盖层。读取和 upsert 让覆盖层保持到其条件成立。
Stop 覆盖层Stop 覆盖层是未结束行上的 status: cancelled。任何服务端终态都会清除它，所以后来的 cancelling 不能把已停止的气泡拉回思考状态；其取消命令被拒绝时也会清除（Stop）。

服务端行永不清除的仅帧字段：retryStatus、autoPreviewFiles。展开状态按视图保存，键为（行 id，块 id）。
