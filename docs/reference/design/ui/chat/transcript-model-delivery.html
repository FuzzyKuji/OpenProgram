Transcript delivery steps

Part of the transcript model record. Built so far: implementation status.

Delivery

Approval gate, before step 1

An old-versus-new comparison, drawn in the user's theme, covers every visible change below and needs a yes before step 1. Any later step that adds a new visible difference needs its own comparison and yes before it lands.

  1. A sub-agent drawn as a separate AttachCard at a page edge or when started by /task draws as the normal SubAgentStep at the same position. Manual and cross-session attaches keep AttachCard.
  2. A sub-agent, including a synchronous one, appears when it starts, shows running, opens into a live view and settles.
  3. Phantom empty rows, permanent Running steps and a user row marked running no longer appear.
  4. The user's own /spawn and /merge line stays visible.
  5. Steers and restart continuations are no longer drawn twice or lost at page boundaries.
  6. In the bot view, a steer sits before the reply it redirected instead of after it.
  7. A reader scrolled up stays put during background activity, and older pages stop landing after the newest rows.
  8. Nested call trees under a tool step survive a reload.
  9. Citations show while streaming.
  10. Open steps stay open and in place while a reply updates.
  11. A split pane shows the same rows as the main view and updates without focus.
  12. The expanded sub-agent view shows tools, thinking, terminal state and later turns.
  13. Copy and files on a restart-joined reply cover the whole reply; always-on sent files appear.
  14. A person's text starting with [task from stays their own message.
  15. Version arrows no longer count a compaction summary and cannot land on an attach row.
  16. A failed read shows a retry instead of a differently shaped transcript.
  17. Expanding a truncated tool result in a block works; late tool results appear on rows that had none.
  18. A reply whose final write failed settles when its execution ends.
  19. Text of a conversation holds briefly while that conversation is being read, then catches up.
  20. History loads in whole turns, so one load can bring a slightly different row count.
  21. A message the server refuses before accepting it shows the reason on its "Not sent" line, and no separate red reply appears under it.

Everything else keeps its position and look.
