Parking a queued row is not a send. Loading or failed attachments are rejected before queue creation, draft clearing and note publication; the existing note and its generation stay.

Follow operation lifetime

A note identifies a send; it is not permission to scroll forever. Every async completion, resize snap, welcome retry and animation callback first checks session, scroller key, generation and interaction epoch.

Note storage
  • Stored per (sessionId, scrollerKey), so main and peer in one session stay independent.
  • Never deleted on read. Completion and cancellation are recorded separately, with per-view applied generations; starting a latest request does not complete one.
  • Idle completed notes with no viewport are capped at 32; waiting notes are kept. Releasing a viewport prunes after the current turn, so a same-tick remount retains it.
  • turnSeed is the accepted optimistic turn, not the last row after ack.
  • A newest page nobody asked for (renewal, retry) becomes a note for each viewport with no follow lock.

Jump completion

  • While Jump runs, resize records the new target and does not pin.
  • At settle, or at the 700 ms watchdog, the current target is recomputed and one instant correction applied within 2 px; the reattachment slack is not used here.
  • Jump hides only after that, if the operation is still current. Reduced motion uses the same check.
  • Cancel stops browser motion as well as callbacks, and no cancelled operation corrects.

Saved per viewport in sessionStorage key chatScrollByKey: offset, bottom intent, timestamp, runtime identity. Leaving, hiding or unmounting records departure. Skipped under data-self-update-verification. The threshold is CHAT_READING_POSITION_TTL_MS.

Details
  • Latest restoration clears the history anchor and uses the cancellable latest-window loader. A user gesture cancels pending following; a saved pixel offset is not a latest anchor.
  • An empty transcript keeps latest intent: rows that commit before ResizeObserver delivery keep the follow state. Height growth is not a reading gesture.
  • The loader does not overwrite latest placement with stale pixels, and reloads schedule no second pixel restore: a cached offset can exceed the shorter latest page.
  • An unchanged position keeps its follow state across reload. A pending welcome send survives activation until its view is ready.
Legacy file-change summaries
  • Loaded only near the viewport, then kept in the session message store. A remounted card renders the result at once, including a confirmed empty one.
  • Errors stay retryable. Aborted or stale responses never update another session.
  • History preflight stays fresh and undo authorization stays server-side; a summary is a description, not permission to undo.

History windows

  • Older, newer and around replacement: each registered area captures its own anchor, top and height before the update, and restores after flushSync only if still registered for the same session and chatKey. Height caches use that area's key.
  • A registered area that lost registration is not restored. The unregistered #chatArea fallback applies only when nothing was registered at capture and the node is still the live main scroller; being connected is not enough.
  • Restoration skips a viewport holding a follow lock.
  • Rows shared by main and peer: each non-requesting pane keeps its anchor. If eviction removed it, the reader keeps the distance from the surviving end. A negative result (an expired snapshot renewed to the newest page) shows the end of the new window, not the top.

Selects when to request; never writes scrollTop. Serialization, cursor and generation validation, retry backoff, snapshot renewal, hidden-view suppression, recovery and disposal are separate.
