会话记录通信协议与模块

属于会话记录模型工程记录。目前已完成的内容：实现状态。

通信协议

在 websocket_dispatch.py 中按 socket 协商。history_version: 3 设置 _history_protocol = 3 和 _bounded_history = True。Web 在 list_sessions 和 load_session 上发送 3。ws_delivery.py 中的分片门和 load.py 中的分页门涵盖协议 3。版本 3 的回复不含图。

请求。 load_session 保留 history_before、history_after、history_around、history_latest，现在接受任意行 id，并新增 history_turn 用于单轮读取。history_snapshot 和 history_head 不存在。search_session 不再接受快照令牌。close_view { session_id, view } 是新增的。

回复。 全部在超过 128 KiB 时分片。

transcript_update { session_id, view, previous, revision, changes: [...] }
  turn_upsert   { turn, afterTurnId }
  row_upsert    { turnId, afterRowId, row }
  item_upsert   { turnId, rowId, list: blocks | attachCards | runtimeChildren | callRoots, item, index? }
  row_patch     { turnId, rowId, fields }

list: blocks 必须带 index。

变更的帧，对所有 socket 都是增量的。 chat_response stream_event 的 text 和 thinking 增加 row_id、item_id、item_index、offset。text_end 增加 row_id、item_id。旧客户端仍能看到 seq。

一个轮次的每个 chat_response 都带回复的 row_id，由该轮次的 naming_reply_row 包装加上。浏览器按这些 id 查找行，从不由一个 id 构造另一个。

ws_delivery.py。

  • 新帧种类 transcript，绝不替换或淘汰。溢出时移除该会话已排队的 transcript 帧并入队一个 critical transcript_gap；该会话后续的 transcript 帧被丢弃，直到这个 gap 离开队列。_evict_replaceable_for 把一个会话的 transcript 帧折叠成一个 gap，而不是移除。
  • _merge_adjacent 只在同一 item_id 按 offset 连续时合并流式文本。
  • 读取进行中时，在 QueuedWebSocket 上按会话暂存会写行的帧。
  • 协议 3 的过滤放在 _enqueue 内，用它已有的解析。

协议 3 socket 不接收 stream_event 的 tool_use 和 tool_result、tree_update 和 user_message；它们改变的内容由发布器以会话记录更新发送。

它们接收 text、thinking、text_end、retry、structured_output_retry，终态 chat_response 帧（只有运行级效果，不写行），chat_ack、running_task、running_task_clear、状态、context_stats、goal_update、execution.updated。斜杠命令 /spawn 和 /merge 的结果帧为其他 socket 保留；协议 3 的 reducer 不能把它们应用到行上。

跨部署保持打开的标签页不需要新机制：frontend_build 会重新加载它们。
