Chat quotes and message editing

Release the pointer after selecting message text to reveal the Add to chat action above the selection. The toolbar stays hidden during dragging, hides on a new pointer press or cancelled selection, and also supports completed keyboard selections. Add to chat appends the selection to the current draft. Selecting text is the only way to quote: the message action row has no Quote action. The selection toolbar uses a compact 28 px action with 3 px outer padding, 8 px corner radius, a subtle border and shadow, a rounded action target, and an opaque theme-aware popover background. Hover and pressed states mix solid theme colors, never replace the background with a translucent overlay. Keyboard focus has a visible outline. Quotes append Markdown blockquotes to that conversation's draft and focus its composer. Existing drafts and attachments remain intact; sending is explicit.

Historical user messages open an inline composer with the same text field, file mention picker, attachment processing and preview strip as the bottom composer. Existing attachments can be removed; images and documents can be picked, pasted or dropped. URLs remain editable text. Cancel discards only the edit. Save and resend creates a sibling branch through the existing edit route. Errors retain the edit and show a retryable message.

References: the user-supplied Codex selection screenshot establishes the selection action; no external product parity is claimed. Separate side-chat windows are outside this change.

Chat action icons

The selection action uses the shared animated-icons components. The upstream catalog has no Quote component, so QuoteIcon follows the existing Monitor and Pin fallback: the official Lucide glyph, the shared imperative start/stop interface, and the existing CopyIcon spring and translation. No SVG path or new motion style is authored. The whole button drives animation on pointer hover and keyboard focus; leaving or blurring resets it when neither interaction remains. Disabled controls and reduced-motion users receive static icons. Existing sizes, colors, surfaces, draft updates and session ownership remain unchanged.
