Sub-agent row

A spawned agent appears once in the turn: its step row in the execution timeline. Opening the row shows that agent's conversation. No separate card repeats it, as in Claude's "Ran an agent" row and Codex's sub-agent activity list.

Transcript load

load_sub_agent_transcript {session_id, job_id | head_id} replies sub_agent_transcript {view, head_id, turns, window} and leaves the session head alone.

  1. With only job_id: resolve the head from the Job's execution input.
  2. Follow the newest user or assistant child to the branch tip, which reaches later messages to the agent.
  3. Return user and assistant rows in branch order, not storage order: a reply placeholder can be written before its prompt.

The client replaces the agent's rows, keeps live rows the load did not include, and reloads when a Job of the agent reaches a terminal status.

Where the reply id comes from

A finished Job records its reply as head_id on the Job and its spawn card. The canonical driver reads it from TurnResult.assistant_msg_id. A turn that raised has no result and uses the reply id the Job was admitted with.

Each write reaches the caller's open chat as a transcript_update of that card; no stream event announces it.

The way back

On an agent's branch the sub-agent branch banner shows the agent's name and Back to main conversation, leading to the newest turn below the spawning reply. The reply itself would hide later turns. The Spawned-from card stays out while that branch is on screen.
