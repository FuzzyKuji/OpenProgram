Transcript wire protocol and modules

Part of the transcript model record. Built so far: implementation status.

Wire protocol

Negotiated per socket in websocket_dispatch.py. history_version: 3 sets _history_protocol = 3 and _bounded_history = True. The web sends 3 on list_sessions and load_session. The fragmentation gate in ws_delivery.py and the paging gate in load.py cover protocol 3. Version 3 replies are graph-free.

Requests. load_session keeps history_before, history_after, history_around, history_latest, now taking any row id, and adds history_turn for a one-turn read. history_snapshot and history_head are absent. search_session no longer takes a snapshot token. close_view { session_id, view } is new.

Replies. All fragment above 128 KiB.

index is required for list: blocks.

Changed frames, additive for all sockets. chat_response stream_event text and thinking gain row_id, item_id, item_index, offset. text_end gains row_id, item_id. Old clients still see seq.

Every chat_response of a turn carries the reply's row_id, stamped by the turn's naming_reply_row wrap. The browser looks rows up by these ids and never builds one id from another.

ws_delivery.py.

  • New frame kind transcript, never replaced or evicted. On overflow, that session's queued transcript frames are removed and one critical transcript_gap enqueued; further transcript frames for that session are dropped until the gap leaves the queue. _evict_replaceable_for collapses a session's transcript frames into one gap instead of removing them.
  • _merge_adjacent merges stream text only when the same item_id is contiguous by offset.
  • Per-session parking of row-writing frames on QueuedWebSocket while a read is in flight.
  • The protocol 3 filter inside _enqueue, using the parse it already does.

Protocol 3 sockets do not receive stream_event tool_use and tool_result, tree_update or user_message; the publisher sends what they change as transcript updates.

They receive text, thinking, text_end, retry, structured_output_retry, terminal chat_response frames (run-level effects only, they write no row), chat_ack, running_task, running_task_clear, branch_running_task and its clear (a turn on a branch that is not selected), status, context_stats, goal_update, execution.updated. Slash /spawn and /merge result frames stay for other sockets; protocol 3 reducers cannot apply them to a row.

A retry frame with restart means the response is sent again from its start. The stream tap cuts the row's blocks back to where that response began and writes the row, so the next text frames carry offsets into the shortened row.

Tabs left open across a deploy need no new mechanism: frontend_build reloads them.
