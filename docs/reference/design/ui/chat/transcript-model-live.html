Run-end status

event_effects gains one rule: when an execution reaches a terminal status and its anchor row is still open, it writes that terminal status to the row. The write goes through the store, so the row settles live and cold. A terminal store write that failed in finalize is thereby repaired when the execution ends, with no display-side fallback.

event_effects also writes the pause and the way back, on a lifecycle event whose snapshot is still the execution's current version:

  • Execution paused, row status None, pending, running or streaming: writes status: paused and pause_reason. continuation_contract_mismatch is excluded, because _project_failed_assistant already writes it as an error.
  • Execution running, row status paused: writes status: running and clears pause_reason.

The target is the anchor row, assistant_message_id, which for a function run is its pre-created node. Each write goes through the store, and the publisher sends it at once as a row_patch. reconcile_session_projection applies the same mapping at hydration, so live and cold agree. New text on a paused row is appended and leaves the status to this rule.

Stop

PartRule
PublisherText frames stay gated by _broadcast_chat_response, which keeps post-stop silence. In the publisher, while is_cancelled(session, execution_id=<row's execution>) holds, non-terminal changes to rows of that execution are dropped, since the terminal row covers them. Terminal row_upserts are never held. Background job rows in the same session keep updating.
Overlay and proofThe browser sets the Stop overlay with until_terminal, plus until_command_rejected naming the cancel's command id. A rejection whose latest_snapshot proves the execution still runs passes the checks in handleExecutionCommandUpdated (same session, not replaced by a newer execution); it sends overlay_command_rejected, which clears the overlay, and restores the run slot unless the slot already holds the turn at a newer version.
One sendA stop goes out once (lib/execution/cancel-execution.ts). The Worker takes it at the current version, so an old version is not a refusal. A stop of a turn that has ended answers already_terminal. "Stopped." follows the execution's cancelled frame.
Before the ackA Stop pressed before the ack sets the same overlay and sends the cancel as soon as the ack names the execution, with or without a version.
Row statusThe row then shows its server status, because the overlay never changed the row.
Other casesA rejection without that proof leaves the overlay until the terminal row. Text frames dropped under the overlay leave a gap, and the next frame's offset > length repairs it with one read at the view's anchor.

Foreign writes

PartRule
AbsorptionAbsorbed at the two existing points, the stale rebuild in _open and invalidate_cache. These report a foreign change and mark that view's open rows dirty, and nodes with seq above the view's maximum are resolved like new ids.
Rebuild rateThe publisher reads the cached index without a stale check and takes a foreign rebuild at most once per 2 s per session, so a running subprocess cannot cause an O(N) rebuild per tick. A mark inside that window defers the rebuild to the window's end and is never skipped, so a run's last foreign write always gets its rebuild.
Consistencymemory_index.rebuild fills fresh containers and swaps them under the lock, so a lock-free reader never sees a part-filled index. Cron children have no poller; their writes appear on the next read.

Head moves

CaseRule
Descendanthead_id in a meta.patch is compared with the old head. A descendant extends the index and sends nothing extra. Attach and notice writers use advance_head=False and no longer flip the head, so a spawn cannot reach this path.
Branch and structureA head that is not a descendant sends window_stale { head_id, reason: branch }, and every holder does one read at latest. window_stale { reason: structure } reads at the anchor, replaces in place and restores by message id. These reads run hydration, so session metadata refreshes too.

DAG panel

branches_changed { session_id } (replace class) goes out on attach writes, head moves and node deletes. The client runs its existing list_branches send. This is the only graph refresh trigger once reloads go.

Send

PartRule
IdentityA local row tagged clientRequestId. The chat action stores the same id as metadata.client_request_id on the user node, and function dispatch stores it on the pre-created function-run node, so a read or update names the send it belongs to.
Replacementchat_ack re-ids the local row to the server id, or removes it when the server's row already arrived. A turn_upsert or read carrying that clientRequestId replaces it even if it beats the ack, and a reconnect after a lost ack replaces the row settleSendsOnDisconnect marked Not sent. Function runs work the same; the placeholder goes at ack or upsert.
Pre-ack errorA pre-ack error marks only that local row, records the server's text on it as errorDetail and mints no _reply. The NotSent line under the failed bubble draws that text after "Not sent".
No local rowA rejection with no local row keeps its toast, and run_active keeps its requeue path.
SteerThe steer row carries the command id as clientRequestId. When a read or update delivers a row with that id, the reducer returns a settleSteers effect and the caller runs settleDeliveredSteer. This covers reads, which a frame cannot.

Sub-agent

PartRule
PlaceholderEvery spawn writes a placeholder attach row from on_accepted, so it carries job.id and tool_call_id and delivery=tool_result from the first write. The job carries attach_pointer_id, so every path that ends a job patches the card.
End writeThe end of a sync spawn patches the row, because append_message is idempotent on id; failure paths and a result with no head patch to errored. If the placeholder write fails the end write appends the full row.
Delivery and readsnotices.queue is already a no-op for wait=True jobs. The card is an ordinary store write the observer delivers as item_upsert. head_id is null during the run; opening the row reads by job_id through get_execution_input.
StartupStartup reconcile closes attach rows whose job is not active. A collapsed row loads nothing.
Expanded viewThe expanded view reads through the same reader under its view key, in branch order, without moving HEAD.
Tip rule and textIt has its own tip rule: a node.put whose predecessor is the view's tip, under the _branch_tip filter (user or assistant, not display=runtime, not function=attach), extends the view and emits turn_upsert. Text frames apply to whichever loaded views hold row_id, so job text cannot enter the parent.
