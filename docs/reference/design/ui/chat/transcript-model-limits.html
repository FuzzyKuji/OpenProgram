Transcript limits and enforcement

Part of the transcript model record. Built so far: implementation status.

Old data

Nothing stored is rewritten, replayed or migrated. Every shape is a named case in legacy.py with a fixture.

  • Attach rows linked by predecessor only or by both edges; anchored on a user row (sub_agent_step); manual or cross-session (external_reference, still AttachCard).
  • Rows with no blocks (backfill from tool_calls), no status, errors stored in content, no id (a stable key from timestamp and role replaces hist_<i>), extra as object or JSON string, readSpeaker, readNotice, pasted elements, chapter pins, gui_agent names.
  • Attach rows without tool_call_id: match attach.prompt to the agent or task tool input, then order among agent and task blocks of that reply. send_message consumes a card only with evidence. Still unmatched: blockId null, drawn as an unpaired card.
  • Code nodes without tool_call_id: same rule through caller edges.
  • Receipts on rows without origin: the existing header pattern, and the named sender session must exist in the store, so old delivered messages keep their look and a typed line naming no real session stays a user row.
  • Old steer rows, restart prompts and fallback blocks fold as they do now; steering already in blocks is not doubled.
  • Summaries with covers_ids stay compaction rows and stop counting as versions.
  • Old tool rows reached by provider id are served by the second match in tool_output.py.
  • A head folded away by aggregation (_resolve_head) and a broken predecessor chain (predecessor-walk fallback, logged).
  • A branch that continues past an attach row or other side row, left by a version arrow that once stood on one: the walk to a version's tip passes through it.
  • Running attach rows with no job id.

Turn grouping is computed at read time, so it applies to every old conversation with no write. Saved anchors stay valid because row ids do not change and any row id resolves. New metadata (tool_call_id on attach, origin, client_request_id) is ignored by old readers.

Enforcement

Types. schema.py generates wire-types.generated.ts, and a freshness test fails if they differ. TranscriptChange is a closed union with an exhaustive never check. Row.rowKind is a union, so dispatch has no default. Store writers are not on the public store type.

Contract tests. tests/unit/webui/test_transcript_contracts.py and apps/web/tests/chat/transcript/transcript-contract.test.mjs. No scan has an allowlist. Scans read source only, never build output (openprogram/interfaces/server/_frontend/, docs/_site/).

  • Only apply-transcript-update.ts writes rows.
  • No client code builds _reply or derives an id from another id.
  • No session_reload string in openprogram or apps.
  • No code in apps/web reads display, function or content to decide a row's type.
  • No file outside the transcript package folds attach, steer or restart rows. One named exception: joinedReply in restart-continuation.ts, which concatenates exactly the rows named by row.continues, all of its own turn.
  • No shift-based pairing in components/chat/messages.
  • No transcript row status literal lists outside status.py and row-status.ts. The scan covers interfaces/server/transcript/, ws_actions/session/, apps/web/components/chat/, apps/web/lib/chat/, apps/web/lib/session-store/ and apps/web/lib/runtime-bridge/session/. Execution lifecycle lists are another vocabulary and out of scope: use-ws.ts:351,393,426, event_effects.py:233,307, execution/dag.py:504.
  • legacy.py is the only module reading old record shapes. Two named exceptions: the second match in tool_output.py, which serves old tool rows by provider id (Old data), and stripLegacySpeakerLabel, which strips old channel labels from display text and decides no row type (Limits that remain).
  • No import from interfaces/server in runtime or state. tests/contracts/repository/test_runtime_layering.py does not scan this direction, so the transcript contracts do.
  • The observer does no projection or I/O.

Behaviour tests.

  • Page-edge sweep: every cut equals the unpaged read.
  • Live equals cold through production reducers and components, across stream, partial history, page edges, completion, late tree updates, errors, cancellation, reload, reconnect and a fresh chat.
  • Frames come from the real server emit path, never hand-written and never with an injected id.
  • Duplicate delivery changes nothing.
  • Interleaving property test: any order of writes, foreign writes, reads, page reads, view eviction, dropped frames and reconnects ends equal to a fresh read.
  • Interleaved text, tool, text and steer on the real publisher keep stored block order.
  • Unknown row and unknown item create nothing.
  • Reader window invariance under background updates.
  • Terminal status table.
  • Stop with no write after the flag clears still settles the row.
  • A second message to a running agent while it is expanded reaches the view.
  • Four cached conversations: a fifth closes one view on the server.
  • 300,000-node real server benchmark: first open, page read, evicted session, foreign-write rebuild, memory per view.

Process. Each step is built in its own worktree, rebased, merged once. Commits carry only their own paths. Affected tests and these contract tests only. Each read or live flip was checked against real shapes in the dev instance with a compare tool, and its mismatches were cleared before the flip landed.

Accepted behaviour

CaseAccepted result
Placeholder write failedNo live text; the terminal row appears when the turn ends.
Last text frame droppedThe terminal row heals it; no read runs.
Empty provider block between two same-type blocksRun numbering can shift at the final write; one open step closes, nothing else.
Power loss on the quiet pathThe tail of the reply in progress can be lost.
Cron children's writesThey appear on the next read of that session.
A conversation being read on one socketIts text holds on that socket until the read ends.
A page projecting under the view lockNon-text updates for that one session wait.
Collapsed sub-agent rowShows running state and no text preview.

Risks measured, not removed

  • A long autonomous turn is indivisible and can be many megabytes. Tool bodies keep the 32 KiB inline cap. Steps 0 and 5 measure it, and step 5 shows no regression before the flip.
  • Owner-map memory at 300,000 nodes is tens of MB per view, with shared strings and the LRU. Measured in step 0.
  • Golden fixtures cover named old shapes, and the compare tool covered the dev profile only, so a shape found only in stable data can surface later. An unknown shape draws as a plain row.
  • Offsets are UTF-16 units across Python and JS. A wrong computation becomes a repair read, not corruption; surrogate-pair fixtures cover it.
  • About six to seven weeks of work in the highest-traffic chat files while other sessions commit.
