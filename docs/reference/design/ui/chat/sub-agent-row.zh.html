子代理行

派生出的子代理在轮次里只出现一次：执行时间线里它的步骤行。展开这一行看到它自己的对话。没有另一张卡片重复显示，这和 Claude 的“Ran an agent”行、Codex 的子智能体活动列表一致。

帧路由

运行时桥（wsHandleChatResponse）同样忽略带 job_id 的帧。

项目规则
准入 id<job>_user、<job>_user_reply
后续 Jobjob_status.parent_msg_id 是上一个 <job>_user_reply，据此映射到子代理的第一个 Job
Store key<session_id>#sub-agent:<第一个 job id>。没有 Job id 的旧派生：分支头。
提示行回复流式输出前加入，取自派生卡片的 prompt 或 job_status.prompt_summary
行这个 key 是视图自己的：和会话共用的行 id（比如切到子代理分支时）是另一行。会话切在这条分支上、这条回复还没结束时，Job 的帧也写到会话自己那一行。
展开这一行load_sub_agent_transcript 经转录读取器、在这个 key 下，用 turn 和 window 回复子代理的整条分支：工具、思考、函数调用树、结束状态和后续轮次。读到分支末端，绝不移动 HEAD。

部分行为

步骤行幽灵图标、“子代理: 名称”、状态。运行中有取消（execution.cancel）。点标题在右栏打开这次调用的详情。
展开内容子代理的对话，最高 min(520px, 60vh)。收起的行不加载。运行中的子代理停在最新输出并跟随，直到读者向上滚动；已完成的停在任务处。
提示凸起的小卡片，标注任务或消息。去掉 [task from …] / [message from …] 回执行。点击前最多 3 行。
回复embedded 模式的 AssistantBubble：没有头部和操作栏
打开对话 ↗在主视图 checkout 到它最新的回复：已加载记录的分支末端（需要时点击时加载），否则取派生卡片的 head_id。对话运行中服务端回复 run_active，改为展开这一行。

加载记录

load_sub_agent_transcript {session_id, job_id | head_id} 返回 sub_agent_transcript {view, head_id, turns, window}，不移动 session 头。

  1. 只给 job_id 时：从 Job 的 execution input 解析分支头。
  2. 沿最新的 user 或 assistant 子节点走到分支末端，能读到后来发给子代理的消息。
  3. 按分支顺序（不是存储顺序）返回 user 和 assistant 行：回复占位行可能先于提示行写入。

客户端替换这个子代理的行，保留加载结果里没有的实时行，并在它的任一 Job 进入终态时重新加载。

回复 id 的来源

Job 完成时，把回复作为 head_id 记到 Job 和派生卡片上。canonical 驱动从 TurnResult.assistant_msg_id 读取。抛出异常的轮次没有结果，使用 Job 准入时的回复 id。

Attach 行

时机写入内容
Job 被接受由 on_accepted 写入：status=running、job_id、tool_call_id；agent 工具还带 delivery=tool_result。head_id 在结束前为 null。Job 用 attach_pointer_id 记住这一行的 id。每次写入都以这张卡片的 transcript_update 到达调用方打开的对话，不再有流事件宣告它。
派生返回对同一行打补丁。失败或没有 head 的结果补成 errored。
占位写入失败结束时追加完整的行。
Worker 启动Job 不存在或已结束的运行中行被关闭。

返回路径

在子代理分支上，子代理分支横幅显示名称和返回主对话，回到派生回复之下最新的轮次；回到派生回复本身会隐藏之后的轮次。当前显示这条分支时，“创建自”卡片不出现。
