聊天附件

消息里的每个文件都由同一种文本标记表示：

[attachment: notes.txt (txt, 18 KB, 4210 lines) @json "/abs/path/notes.txt"]

只由 openprogram/state/attachments.py 的 format_marker 写入，新增来源也调用它。网页端只由 parseAttachments 读取。可选的 @previewjson 指向保存的预览。旧写法 @ /abs/path 仍可读取。内容如何进入模型上下文：附件处理。

入站

来源字节模型输入聊天显示
网页图片：粘贴、拖入、选择会话工作目录 attachments/，会话内 SHA-256 去重，单文件 32 MB，单轮 64 MB图片内容和路径缩略图 chip，点击看原图
网页文档：PDF、代码、二进制同一存储；本地文件可留在原路径路径；工具按需读取可点击 chip，覆盖层查看
@ 提及、输入路径位置不变，零复制路径可点击 chip
Telegram、Discord、Slack、微信<state>/channels/<channel>/accounts/<account>/attachments/，20 MB，不去重4 MB 以内的图片作为图片内容，其余为路径缩略图 chip，隐藏标记

频道文字前加 [display name (id)]，标记放在后面。_one_line 去掉名称中的方括号，防止伪造前缀。没有文件名的粘贴图片按媒体类型补扩展名。

HTML 沙箱和压缩包
  • GET /api/file-page 只提供 .html 和 .htm，带 sandbox allow-scripts，没有 allow-same-origin。srcdoc 框架会继承应用的 script-src 'self'，靠脚本绘制的页面会变成空白。
  • 页面为不透明来源：无法访问应用及其存储，Origin: null 请求被拒绝，不能导航或打开窗口。相对路径资源在缩略图中缺失，因为严格 Cookie 不发送；在浏览器标签页中打开时有这些资源。
  • FileViewer 把 zip 或 tar 交给 ArchivePreview：左侧完整目录树，右侧用同一个 FileViewer 显示所选成员。不解压到磁盘。

方面规则

路由约定
GET /files/raw项目和相对路径，服务文件面板和中央标签页。始终拒绝绝对路径，保持这一不变量
GET /api/file-raw绝对路径，按 readable_roots 检查；nosniff、CSP sandbox，PDF 为浏览器查看器豁免
GET /api/file-read文本。根目录下的相对路径，或按 readable_roots 检查的绝对路径
GET /api/archive-list从 zip 中央目录或 tar 头读取条目，最多 5000 项，截断时标记
GET /api/archive-member单个成员，最大 32 MB，响应头同 /api/file-raw。名称只在压缩包索引中查找，../ 够不到任何东西
POST /api/file-reveal同样检查后在 Worker 的文件管理器中选中路径。从不打开或运行文件，所以卡片没有“用系统应用打开”

两个压缩包路由都接受绝对路径，或项目 id 加相对路径。FileViewer 只有一个 abs 开关，图片、PDF、Markdown、带行号代码和下载卡片的渲染都是同一实现。

暂缓

项目暂不做的原因何时做
用户附件的中央标签页覆盖层足够快速查看；按项目键控的标签页需要新处理。回复卡片已用标签页有人需要长时间阅读附件时
send_file 说明文字标记没有说明字段，回复文字已随文件一起某平台需要文字附在文件上时
出站工具允许列表send_file 是唯一出站入口，已检查根目录插件或 MCP 工具能触发投递时
短期签名令牌本地监听、同源防护、根目录检查网页 UI 离开 localhost 时首先要加
语法高亮带行号的 pre 够用；文档站的高亮只在构建时运行用户提出需要时

同样缺少：大图的多分辨率缩略图。

目标设计

任何来源的任何文件，在每个界面都通过同一个查看器打开。用户文件和 Agent 文件只差来源字段。

能力解决现状暂缓原因
一条附件记录（id、SHA-256、名称、MIME、位置、计数、来源、会话、消息）；文本只留 [attachment:<id>]重命名、去重、跨会话引用都变成查询全部信息在文本标记里需要改表和迁移历史；等跨会话引用成为实际需求
一个解析器，所有界面，包括终端内联图片（iTerm2、kitty，其他显示文件卡片）同一资源同一渲染决定网页已如此。TUI 没有附件概念，也不能粘贴图片与网页无关。同类项目说明实际收益有限
完全对称用户和 Agent 文件共用数据模型和 UI语法、解析器、chip、查看器已共用，只有回退不同部分完成；四个平台都能上传
输出为实时页面看着文档逐步形成canvas 写入带 id 的 Markdown 块，没有面板渲染线路格式已定。是最有价值的下一项；三个同类项目已实现

明确排除：全局内容寻址的 blob 存储。每个会话工作目录每轮都提交且可重放，大二进制留在 git 历史是接受的代价。

Canvas 文件内容

调用结果
set、append 带 content=""空字符串算内容；块保留空正文，get 返回空字符串
省略内容或为 null报错，文件不变
content 与 body 或 text 同时给出显式 content 优先，空也一样

八个同类实现对比
仓库进入上下文显示Agent 发文件查看、清理
claude-code（TUI）内联 base64；字节在 ~/.claude/image-cache/<session>/，0600。5 MB、2000 px，sharp 缩放，JPEG 质量 80/60/40/20。桥接的网页和移动端注入路径[Image #N] 带 OSC-8 链接到系统查看器。非图片：Read <path> (N lines)SendUserMessage 的 attachments: string[]；上传返回 file_uuid；30 MBTUI Markdown 和高亮。PDF 为文档块或逐页 JPEG。每次会话开始清理其他会话缓存；200 项路径 LRU
codex-cli（TUI）base64 input_image，包在 <image name path> 标签中。字节留在原处。2048 px，SHA-1 64 MB LRU。拒绝远程 URL[Image #N]，不可点击。Kitty 和 sixel 只用于吉祥物没有通用工具。图片生成打印 file:// 并声称已显示Markdown、syntect。file_opener 把引用改写成编辑器 URI
openclaw（网页、TUI）视觉模型收 base64；其他收 media://inbound/<id> 回执。存储 0700。图片 6 MB、音视频 16 MB、文档 100 MB。归一化 EXIF，重新编码 JPEG网页缩略图在新标签打开；卡片；音频播放器带状态徽标。TUI 只有标签MEDIA: 行和 message 工具。只有允许列表内的核心工具能发本地路径Markdown-it、DOMPurify。文档只为模型提取。两分钟 TTL
opencode（网页、TUI）base64 data URL 存 SQLite。@ 在提交时运行 read，注入两个合成纯文本 part。5 MB、2000 px、Lanczos3图片卡片带灯箱；非图片不可点击；@ 在文本中高亮没有；工具附件进入模型上下文GET /file/content；图片、音频、SVG、标签页、diff。随会话行删除
hermes-agent（频道）每轮路由：原生 base64 加路径提示，或 vision_analyze 文本。文档给路径，文本内联。无初始上限，被拒后压到 4 MBTelegram、Discord 原生；CLI、TUI、xterm 网页不可点击最完整：MEDIA:、send_message、先解析符号链接的根检查、按平台提示；提取 ![alt](url)Rich Markdown。24 小时 TTL
pi-mono（TUI）@file 内联并带 <file name> 标记。剪贴板写临时文件并插入路径。2000 px、4.5 MB，可关闭唯一真正的终端内联图片（Kitty、iTerm2），tmux 和 screen 下关闭；只渲染工具结果，不回显用户图片没有Markdown、diff；不支持 PDF，不清理临时图片
pi-ai（协议层）pi-mono 包的只读副本。模型未声明图片输入时移除图片块；工具结果中的图片拆成文本和合成用户消息无无无
weclaw（微信）图片被拦截保存，回复“Saved: filename”；Agent 看不到。语音用微信转写。无上限微信就是客户端隐式：裸绝对路径行或 ![](url) 被上传并替换为“Attachment sent”。根目录默认 ~/.weclaw/workspace，有扩展名允许列表Markdown 被剥成纯文本

发送文件的四种方式

设计使用者优点代价
工具参数claude-code、OpenProgram有类型，工具层检查文件存在占一次工具调用；说话和发文件分开
指令行openclaw、hermes随文字发送，无额外往返；按频道提示错误路径需要检查；提取不完整会泄露
隐式扫描weclaw无需学习，无提示成本提到路径就可能发送
无codex-cli、opencode、pi-mono、pi-ai无需实现模型只能贴路径

指令行和隐式方案都把路径限制在允许的根目录内，并先解析符号链接。

其他技巧

  • 输出为页面：openclaw 用 [embed ref=…] 嵌入 canvas 文档；Codex 把 ::codex-inline-vis{ 物化到沙箱查看器（2 MB、严格 CSP）；pi-mono 的 /share 把会话发布成私有 gist。
  • 签名令牌：openclaw 的 mediaTicket，v1.<payload>.<signature>，五分钟 TTL。
  • chip 作为编辑单元：claude-code 只有在 [Image #N] 留在文本中时才发送图片。
  • Hermes 把宿主缓存路径改写成容器路径。Codex 有 view_image。
