Activity panel

The right sidebar's Activity covers one conversation. What a run waits on is never a group: it is the row it concerns, with a red count on its glyph's corner. The one exception is Waiting for you, the reports left for the reader across conversations. Messages are never rows.

Overview

These groups, in this order. Waiting for you and Open work are not shown when empty, and only Waiting for you carries a count in its header. Hovering a group shows its SectionHeader chevron; clicking the header folds it (per-browser, lib/prefs/activity-view.ts).

Pairing an agent call with its sub-agent

The server reads calls from transcripts, not effects, whose metadata carries whole provider payloads. A Job records the reply that spawned it (spawn_caller) and its prompt.

  1. A call with the same caller and prompt started it; calls that did not fail pair first, since a failed call may share its prompt with the retry.
  2. If prompts do not line up, a caller left with one Job and one non-failed call pairs those.
  3. No Job: the call failed to start (result [agent error] … or outcome failed) or did not start.

The caller names the branch: a j_… reply is a sub-agent's, anything else the main agent's.

Pages

A row in the overview opens one page. Pages do not lead to other pages: what belongs to a row opens under it, in place, and stays open until it is closed. Activity at the top, Esc with focus in the panel, or Activity in the rail goes back, restoring the overview's scroll and focus.

The Agent time chart

One vertical time chart, newest on top, with a column for each level: Topics, Messages, Steps, Inside a step. Columns are 256 pixels wide. At the default width only Topics shows; scrolling right shows the next level, and a wide sidebar shows them side by side.

Every block is a card on hover and can be clicked. A block with more under it leads one column right. A block that is one call, one failure or a message with no steps opens in place: its input and result, or what was asked and replied, in the run list's words.

An opened block grows, the blocks below move down, and its bars in the columns to the left grow with it. A second click closes it. A call still running has nothing to open.

Clicking a block moves to its next column over 620 ms and the block keeps its place. A sideways swipe turns one column, like a page: the chart follows the hand for 48 pixels, then travels to the next column, and the rest of the swipe and its momentum move nothing. A shorter swipe goes back. Any other sideways scroll settles on a column edge 160 ms after it stops.

A column on its way in fades in as its blocks open, so its rows never show stacked. Blocks more than a screen above or two below the view are not drawn.

Topics

Each message the user sent has one topic, kept in topics.json beside the session's messages: topics in the order they first appeared, and which topic each message has. Nothing is written to the messages.

  • After each turn a background pass sorts what has no topic, on the same background model as chat titles. It sees the user's words only.
  • A short reply such as "continue" stays with the message before it and costs no call.
  • The first time an older chat's chart is opened, the same pass sorts its messages, 40 to a call. Until then they read Not sorted yet.
  • When a call fails or no model is available, messages stay unsorted and draw with the message before them. The next message tries again; opening the chart tries again after 10 minutes.

openprogram/host/processes/progress.py reads progress from output, most trusted first:

  1. ##progress 45/100 samples lines (the bash tool asks the model to print them for long loops)
  2. the OSC 9;4 terminal progress sequence
  3. tqdm and pip bars
  4. counters such as Epoch 3/10, step 120 of 1000, [45/100]

Once a more trusted source speaks, less trusted ones are ignored, so an inner per-batch bar never overwrites a sample count. Speed and time left are the bar's own, or measured since the count began. A redrawn bar takes one line of the 2,000-line limit, and the agent reading a background command gets each redraw once.
