Activity 面板

右侧栏的 Activity 只看一个对话。一次运行在等的事不单独成组，而是落在相关那一行，字形角上显示红色计数。唯一的例外是“等你处理”，即各对话留给读者的报告。消息不作为行。

总览

各组顺序固定。Agents 一直显示；其余各组为空时连同组头都不显示。只有等你处理的组头带计数。悬停组头显示 SectionHeader 的箭头，点击折叠（按浏览器保存，lib/prefs/activity-view.ts）。

agent 调用与子代理的配对

服务端从转录读调用，不读 effect，因为其元数据带着完整的 provider 载荷。Job 记录派生它的回复（spawn_caller）和提示词。

  1. 调用方和提示词相同的调用启动了它；未失败的调用优先配对，因为失败调用可能和重试共用提示词。
  2. 提示词对不上时，若某调用方只剩一个 Job 和一个未失败的调用，就配对这两者。
  3. 没有 Job：调用启动失败（结果为 [agent error] … 或结局为 failed）或未启动。

调用方决定分支：j_… 回复是子代理的，其余是主代理的。

页面

总览里的一行打开一页。页面不再通向别的页面：属于某行的内容在它下面原地展开，直到被收起。顶部的“运行记录”、焦点在面板内时按 Esc、或点侧栏轨道上的“运行记录”都会返回，并恢复总览的滚动位置和焦点。

页面像手机上那样移动，用的是 Launchpad 的弹簧；开启减少动效时直接切换。

每一块悬停都抬成卡片，都能点；被截断的标题或文字悬停时显示全文。下面还有内容的块往右移一列。只是一次调用、一次失败或没有步骤的消息的块原地展开：输入和结果，或者提问和回复，用运行列表里的写法。

展开的块变高，下面的块往下让，左边几列里它的色条跟着变长。再点一次收起。展开和收起是一段 240 毫秒的标准曲线，收起时内容留到块合上为止。还在运行的调用没有可展开的内容。

视野以读者去过的最深一列结尾，放得下时从话题开始。点开一块时，如果它的下一列已经在视野里，什么都不移动。列数少于层数时，视野一次移动一列：

动作发生什么

返回、Esc、在块上按左方向键退回一列；已在第一列时回到总览
左右滑动图表跟着手指走，最多一列。移动途中再滑也会从当前位置接住。
抬手已经滑过 48 像素或是一次甩动，就继续到手指前往的那一列；否则退回。两种情况都只有一次移动，抬手后的惯性不再移动任何东西。
滑过最后一列图表最多让出 44 像素，随落定一起回来
滑过第一列整个页面跟着走：这就是返回
横向转动的鼠标滚轮每一格移动一列
键盘焦点落到视野外的块它所在的列移进视野

一次移动只是各列轨道靠 transform 滑动一次：

  • 整列 240 毫秒，剩下的一段更短（不少于 120 毫秒），曲线是 --ease-standard；开启减少动效时直接切换。
  • 移动开始前，条目已经按终点排好。滑进来的列已经是最终尺寸；被点的块或视野顶上的块在屏幕上保持不动。
  • 比终点那一列更深的列不绘制，滑出途中也一样。
  • 滑动结束后没有任何东西再变高、淡入或落定。
  • 图表容器从不横向滚动，只上下滚动。离视野上方超过一屏、下方超过两屏的条目不绘制。

原因：这张图以前靠横向滚动翻列，每块的高度按滚动位置插值。三件事让移动不对劲：

  • 两段动画：高度在一列 256 像素的前 64 像素里就变完，过阻尼的弹簧还拖着长尾在滑，滑入的一列又按自己的曲线淡入。
  • 卡顿：每一帧都写所有块的 top 和 height、重设纵向滚动、改变哪些块绘制，等于每帧一次完整布局。
  • 半列：任何宽度下列都是 256 像素；不是滑动手势的横向滚动停下 160 毫秒后还要吸附到列边。
规则做法
高度由视野里最深的一列决定。父块盖住子块，所以各列同一高度是同一时间。
时间每块顶上写这一块最晚的时刻：话题和消息到分钟，步骤到秒。长时间空闲和换天是横跨各列的一行虚线：换天时每一列的时间列都写日期，长时间空闲在第一列注明空了多久。
颜色颜色只表示属于哪个话题，不表示结果好坏。每个话题按首次出现的顺序取一个主色，隔了很久回来的话题还是这个颜色。消息取主色下的不同色号，步骤和步骤里面继续往下延伸。没人发起的运行和还没分类的消息是灰色。失败和运行中写在文字里。
步骤连续调用同一个函数合成一行，每次调用在最后一列。失败的步骤单独一行，错误写在下面。子 Agent 自己的步骤在最后一列。最后一列的一组最多四行高，在自己的格子里滚动。
按钮只在运行中、暂停或等待的消息上。补充指令把按钮变成一个输入框，这一块高度不变。
数据activity/runs?chart=true 返回这一页，带每个事件的简短形式（输入截断，结果只在步骤失败时保留）和每次运行的话题。已结束的运行按修订缓存。

话题

用户发的每条消息属于一个话题，存在会话消息旁边的 topics.json 里：话题按首次出现的顺序排列，以及每条消息的话题。不往消息里写任何东西。

  • 每轮结束后，后台任务给还没有话题的消息分类，用和聊天标题相同的后台模型，只看用户说的话。
  • “继续”这样的短回复跟着上一条消息，不调用模型。
  • 旧会话第一次打开时间图时，同一个任务给它的消息分类，每次调用 40 条。在此之前显示“还没分类”。
  • 调用失败或没有可用模型时，消息保持未分类，画在上一条消息那里。下一条消息会再试，打开时间图过 10 分钟后也会再试。

  1. ##progress 45/100 samples 行（bash 工具要求模型在长循环里打印）
  2. OSC 9;4 终端进度序列
  3. tqdm 和 pip 进度条

更可信的来源出现后，较低的来源被忽略，内层每批进度条不会覆盖样本计数。速度和剩余时间取进度条自身的，或从开始计数起测量。重绘的进度条只占 2,000 行上限中的一行，读取后台命令的代理每次重绘只收到一次。
