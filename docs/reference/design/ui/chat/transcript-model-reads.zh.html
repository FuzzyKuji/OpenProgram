会话记录读取与客户端规则

属于会话记录模型工程记录。目前已完成的内容：实现状态。

客户端规则

规则行为
游标每个视图有一个游标。revision <= cursor 的 transcript_update 被忽略。previous == cursor 的被应用。其他情况在读者的锚点触发一次合并后的读取。没有窗口的视图收到的帧直接丢弃，不读取。完整窗口替换无条件把游标设为其修订号。页或单轮回复绝不移动游标。
修订号修订号来自一个进程级计数器，所以只增不减。从存储重建的视图从一个新编号开始，它下一帧的 previous 匹配不上任何游标，持有者读取一次。发布器在发布过程中重建的视图保留原修订号。worker 重启会杀掉 socket，新 socket 会读取。
条目或补丁未命中item_upsert 和 row_patch 携带 turnId。未持有该行且轮次不在窗口内：静默丢弃。未持有该行且轮次在窗口内：每轮最多一个在途读取，若返回后仍无该行则停止。绝不因未命中而创建行。
未结束行上的 upsertturn_upsert 和 row_upsert 绝不用更短的块替换未结束行上已持有的文本或思考块。终态行替换整行。
非最新窗口只有 after 为 null 时才追加 turn_upsert。否则只前进 total。
立即刷新reducer 在对某行应用任何条目或状态变化前先刷新该行的待写文本。
读取归属createSessionLoads 是唯一的读取归属，按视图为键，一个在途一个待发。完成的回复先应用，再发送待发读取，所以连串的失效无法饿死它。修复读取和翻页读取经过 exclusive：更新的读取替换正在等待的那个，被替换的以跳过结束；修复读取发现已有读取在途时并入其中。

文本帧。 给定 row_id、item_id、item_index、offset：

  • 未持有该行：丢弃，不读取。行的创建是带编号的变更，所以缺失的行由游标发现。
  • 行状态已落定，或该行上有 Stop 覆盖层：丢弃。
  • 条目不存在且 offset == 0：在 item_index 处创建。索引超过行最后一个块的帧在行旁等待，直到发布器的下一个变化带来它之前的块。
  • offset == length：应用。offset < length：裁掉重叠部分，应用其余。
  • offset > length：在视图锚点读取一次，该视图已有读取在途时不再读取。期间到达的帧被丢弃，因为它们处于读取结果之中或之前。

长度以 UTF-16 单位计，并包含该行待写的 rAF 文本。

暂存

部分规则
范围每次返回行的读取（首次打开、页、单轮、重连、携带窗口的聊天确认）都会在该 socket 上暂存该会话的写行帧，从捕获之前直到回复的最后一个分片入队。写行帧是 transcript_update、transcript_gap 和 stream_event。
终态帧终态 chat_response 帧（result、error、cancelled）只带运行级效果，不写行，所以不暂存。
开始与合并暂存在事件循环上同步开始，早于读取的第一次线程切换。暂存的连续文本会合并，所以普通流不会填满缓冲。
上限超过 256 个暂存帧时丢弃缓冲，并在回复后发送一个 transcript_gap。同一会话的嵌套读取计深度，降到零时刷新。断开连接时清空。
为什么足够先持久化后发送意味着捕获之前发出的每一帧都反映在读取结果里。暂存意味着捕获之后编号或发出的每一帧都在回复之后到达。因此文本总是处于读取结果之中或之后，偏移规则会把它裁齐。

首次打开

部分规则
请求与捕获带 history_version: 3 的 load_session。handle_load_session 照旧运行 reconcile_session_projection，把视图加入 socket 并开始暂存，在任何发布锁之外获取或构建 TranscriptView，然后在视图锁下捕获修订号 R 并投影最新的 6 轮，到实际字节达 128 KiB 为止。
顺序投影和捕获共用这把锁，所以编号 <= R 的帧在读取之前构建，> R 的在读取之后。
回复session_loaded 携带 turns、window 和现有元数据，graph: []。暂存帧跟在最后一个分片之后。

全新对话

部分规则
加入与确认不发送 load_session，因为会话 id 要到确认时才知道。聊天动作在发送的 socket 上加入视图并暂存。对未持有该视图的协议 3 socket，chat_ack 携带 first_read: { turns, window }，捕获方式与首次打开相同，然后暂存帧跟上。
内容轮次在确认前已持久化，所以 first_read 含有 user 行。回复占位和之后的一切都作为带编号的更新到达。
调用点适用于 _send_chat_ack、retry.py 和 turn_local_command.py。待发送的本地行按 clientRequestId 替换。

向前或向后翻页

部分规则
请求与回复同样的 load_session，带 history_before、history_after、history_around 或 history_latest，值可以是任意行 id。25 轮或 512 KiB。正文从存储新鲜读取。回复 session_history_page { id, turns, window, request_id, action }。
游标不再位于分支上的游标返回 cursor_not_on_branch，客户端做一次首次读取。保存在该行上的阅读位置同时作废，首次读取不会再请求它。只是前进的 head 不算不匹配。
放置客户端按 window.start 放置页，绝不放到末尾：既不相邻也不与已持有跨度重叠的页被丢弃。绘制前按消息 id 恢复。按整页淘汰。
锚点锚点只从服务端行保存，绝不从本地行保存。

重连

在锚点读取会话记录，然后恢复执行，只用快照。本地行和覆盖层保留。

分屏

帧交付给持有该视图的每个 socket，并不管焦点地应用。窗格在其视图没有窗口时读取。两个窗格通过同一个 TranscriptRows 绘制，会话范围取自行列表，而不是聚焦的会话。

视图生命周期

部分规则
关闭浏览器在淘汰对话或关闭窗格、展开的子代理时发送 close_view { session_id, view }。
上限一个 socket 最多持有 16 个视图。超过上限时，服务端丢弃该 socket 最近最少读取的视图并发送 view_closed；客户端移除该窗口，仍在显示它的窗格重新读取。
释放socket 停止时释放它的全部视图。四个对话的浏览器上限由 trimHistoryWindows 执行，正是它让 socket 保持在上限以内。

非 Web 消费方

消费方规则
事件路径CLI、ACP、频道、worker_turn 和 bound_reply 的 on_event 和 stream_event 不变。
CLI 和 rehearsalCLI（history_version 缺失）和 rehearsal 读取由 flat_rows.py 构建的 session_loaded.messages：id、role、content，整条分支，不分页。
HTTP 路由HTTP 命令路由（CommandReply，协议 1）得到相同字段，上限为最新 6 轮或 128 KiB，仍接受 history_before 和 history_after，因为 CommandReply 拒绝超过 4 MiB 的回复。
