规则行为
思考只有组里没有别的内容时才写“思考”或“思考中…”
名称桶里恰好一个不同目标时才写目标名。同一文件的重复调用只算一次。文件写 basename，搜索词加引号并截到 24 字符，抓取只写域名，命令从不写出。
数字英文一个用 "a"/"an"，更多用数字。中文始终用数字加量词（1 条命令、3 个文件、2 次）。
失败标签后跟柔和的红色“· N 个失败”。失败的调用计入它的桶，但不计入徽标。
运行中进行中调用的桶移到行尾，用现在时加“…”，闪光保留。调用结束后回到第一次出现的位置，恢复过去时。
宽度单行 28px。标签 min-width:0 加 CSS 省略号；失败提示、徽标、箭头 flex:none。没有字符预算。
悬停没有提示：这是记录内容，展开就能看到每次调用
文字text(en, zh)。中文过去时用了，现在时用正在：读取了 2 个文件，正在运行命令…

改动徽标

至少一个写文件调用成功，且每个成功的调用计数都已知时显示。求和，显示零（+16 −0），复用 .turn-files-diff 胶囊。

工具计数
apply_patch补丁正文的 + 和 - 行。精确。
editold_string 与 new_string 的行 diff，乘以替换次数。任一侧超过 2,000 行时用行数。
writeturnFiles 为 create：+lines(content) −0。为 modify 且本轮对该路径的写入都在这一组：取 turnFiles 的数字。否则未知，徽标等轮次结束。

turnFiles 出现之前，write 只有在本轮没有读过或改过该路径时才算“创建”。modify 则算“修改”。

每次调用携带什么
字段来源用途
toolblock分类；未覆盖的回落到 presentTool()，和时间线行一致
inputblock，完整 JSON路径、命令、搜索词、URL；old_string/new_string、content、补丁
result、is_error、outcomeblock成败；(N replacements)；Added、Updated、Deleted
运行中msg.tools[].status正在进行的调用
turnFilesassistant 消息，finalize 时取自变更日志整轮每个文件的 op、added、removed。没有 tool-call id，所以分组统计从参数推导，turnFiles 补缺。
不做轮次级摘要行
版本原因
确定性零成本，但重复文件卡片的总计和各组标题
模型生成每轮多一次标题模型路径的调用：耗 token、有延迟、只能在轮次结束后出现、内容再发一次，且多半和回复说的一样

必须把一轮折成一行的界面（消息缩略图、悬停预览）调用确定性聚合。
