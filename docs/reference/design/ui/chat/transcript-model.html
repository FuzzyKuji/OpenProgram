Transcript model

The server is the only code that decides what a transcript looks like. A package, transcript/, turns store nodes into Turns: a prompt plus everything it owns. Ownership is settled before any page is cut, so a page edge cannot separate a card from its reply.

A Row is the existing ChatMsg, built on the server with the same field names, so components keep drawing what they draw. Reads return whole turns fresh from the store at a numbered revision.

Later changes reach the browser in two forms only: text and thinking stay on the existing stream_event frame, and everything else is a numbered transcript_update built by the same projection functions that serve history. The CLI, ACP, channels, worker_turn and bound replies read the same projection as flat rows.

The browser does not fold, does not mint rows from misses and does not merge. It draws each row by the rowKind the server sent. Nothing is stored beyond the existing append-only log.

Every delivery step is built; Implementation status lists them.
