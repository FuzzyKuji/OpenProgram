会话记录模型

服务端是唯一决定会话记录长什么样的代码。一个包 transcript/ 把存储节点变成 Turn，也就是一条提示加上它拥有的一切。归属在切页之前就已确定，所以页边界不可能把卡片和它的回复分开。

Row 就是现有的 ChatMsg，在服务端构建，字段名不变，组件照旧绘制。读取按编号的修订号返回从存储新鲜读出的完整轮次。

之后的变化只以两种形式到达浏览器：文本和思考留在现有的 stream_event 帧上，其余一切都是带编号的 transcript_update，由提供历史的同一组投影函数构建。CLI、ACP、频道、worker_turn 和绑定回复以平铺行读取同一个投影。

浏览器不折叠，不因未命中而造行，也不合并。它按服务端发来的 rowKind 绘制每一行。除现有的只追加日志外不存储任何东西。

保持的不变量

不变量如何保持
DAG 含义日志保持只追加，seq 仍是唯一排序键，caller 与 predecessor 仍相互正交。显示折叠不改变 render_context、模型回放或 list_branches 的任何内容。
已存历史绝不改写每种旧形状都在显示时读取（旧数据）。
行身份消息 id、tool_call_id 和 card_id 保持稳定。锚点、测量高度、到达动画、导轨和保存的阅读位置继续工作。被替换的窗口在绘制前按消息 id 恢复。
滚动归属只有 useChatAreaStick 写跟随位置。只有 history-viewport 恢复锚点。加载器和 WebSocket 处理函数不滚动。
子代理隔离job_id 帧绝不进入对话。存储键仍是 <session_id>#sub-agent:<first job id>。折叠的行不加载任何内容。子代理会话记录按分支顺序排列。运行进行中 HEAD 绝不移动。
重连约定先读会话记录，再恢复执行，且只用快照。请求 id 关联、15 秒期限配可见重试并保留缓存行、忽略过期回复、run_seq 排序、重放未决问题和授权。重试状态只存在于实时。
合并保证快照和替换规则见会话记录更新归属。发送失败的行和本地行在加载后保留。读取与客户端规则和实时更新说明每项的机制。
上限服务端分页：首次读取 6 轮或 128 KiB，后续页 25 轮或 512 KiB，单个完整轮次总是允许。浏览器：6 页、8 MiB、四个缓存对话（MAX_CACHED_SESSIONS = 4）。页读取从不运行完整水合。验收是 300,000 节点的真实服务端基准，加上现有的 300,000 行浏览器测试，后者在步骤 5 改用轮次表述。
增量批处理每批一个动画帧。一行的待写文本先于该行的任何条目或终态变化刷新。
没有第二份存储没有新的运行时、数据库、事件日志或内存行源。
