派生字段当顶层行加入已持有轮次或成员的 predecessor 变化时，发布器对照已存表重算整个轮次的顺序、steeringReplyId、continuedBy 和 continues，并为每个变化的行发 row_patch。成员顺序的变化超出单次插入时发 turn_upsert。

运行结束状态

event_effects 增加一条规则：当执行到达终态而它的锚定行仍未结束时，把该终态写到行上。写入经过存储，所以实时和冷读都会落定。在 finalize 中失败的终态存储写入因此在执行结束时得到修复，不需要任何显示侧兜底。

event_effects 还在快照仍是该执行当前版本的生命周期事件上写入暂停及其恢复：

  • 执行 paused，行状态为 None、pending、running 或 streaming：写入 status: paused 和 pause_reason。continuation_contract_mismatch 被排除，因为 _project_failed_assistant 已把它写成错误。
  • 执行 running，行状态 paused：写入 status: running 并清除 pause_reason。

目标是锚定行 assistant_message_id，函数运行时就是它预先创建的节点。每次写入都经过存储，发布器立刻以 row_patch 发送。reconcile_session_projection 在水合时应用同样的映射，所以实时和冷读一致。暂停行上的新文本被追加，状态交给这条规则。

停止

部分规则
发布器文本帧仍由 _broadcast_chat_response 把关，它保持停止后的静默。在发布器中，当 is_cancelled(session, execution_id=<row's execution>) 成立时，该执行的行上的非终态变化被丢弃，因为终态行会覆盖它们。终态 row_upsert 绝不被扣留。同一会话的后台作业行继续更新。
覆盖层与证明浏览器设置带 until_terminal 的 Stop 覆盖层，加上指明取消命令 id 的 until_command_rejected。如果一次拒绝的 latest_snapshot 证明执行仍在运行，并通过 handleExecutionCommandUpdated 里的检查（同一会话、没有被更新的执行替换），就发出 overlay_command_rejected 清除覆盖层，并恢复运行槽，除非运行槽已以更新的版本持有这一轮。
只发一次停止只发一次（lib/execution/cancel-execution.ts）。Worker 按当前版本受理，旧版本不算拒绝。已结束的一轮返回 already_terminal。"Stopped." 跟随执行的已取消帧。
确认之前确认之前按下的 Stop 设置同样的覆盖层，确认一给出执行就发出取消，不论有没有版本。
行状态然后该行显示其服务端状态，因为覆盖层从未改变行。
其他情况没有该证明的拒绝让覆盖层留到终态行。覆盖层下丢弃的文本帧留下空缺，下一帧的 offset > length 在视图锚点读取一次来修复。

msg_id 指向变更

部分规则
状态status 经 status.py 取自树根：running、completed 映射为 done、error。其他根状态不发送。
未结束行与节拍running 树绝不改变视图已不再记录为未结束的行。节拍会合并。

外部写入

部分规则
吸收在现有两处吸收：_open 中的过期重建和 invalidate_cache。它们报告外部变化并把该视图的未结束行标脏，seq 高于视图最大值的节点按新 id 解析。
重建频率发布器不做过期检查地读取缓存索引，并对每个会话每 2 秒最多接受一次外部重建，所以运行中的子进程不会造成每节拍一次 O(N) 重建。窗口内的标记把重建推迟到窗口结束，绝不跳过，所以一次运行的最后一次外部写入总能得到重建。
一致性memory_index.rebuild 填充新容器并在锁下交换，所以无锁读者绝不会看到填到一半的索引。cron 子进程没有轮询者，它们的写入在下一次读取时出现。

HEAD 移动

情况规则
后代比较 meta.patch 中的 head_id 与旧 head。后代只扩展索引，不额外发送。attach 和提示的写入方使用 advance_head=False，不再翻转 head，所以 spawn 走不到这条路径。
分支与结构不是后代的 head 发送 window_stale { head_id, reason: branch }，每个持有者在最新处读取一次。window_stale { reason: structure } 在锚点读取，就地替换并按消息 id 恢复。这些读取会运行水合，所以会话元数据也会刷新。

DAG 面板

branches_changed { session_id }（replace 类）在 attach 写入、head 移动和节点删除时发出。客户端运行现有的 list_branches 发送。重新加载去掉后，这是图刷新的唯一触发。

发送

部分规则
身份一个带 clientRequestId 标记的本地行。聊天动作把同一个 id 作为 metadata.client_request_id 存到 user 节点上，函数分发把它存到预创建的函数运行节点上，所以读取或更新能指明它属于哪次发送。
替换chat_ack 把本地行改为服务端 id，服务端的行已经到达时则移除它。携带该 clientRequestId 的 turn_upsert 或读取即使抢在确认之前也会替换它，确认丢失后的重连会替换被 settleSendsOnDisconnect 标为 Not sent 的行。函数运行同理；占位在确认或 upsert 时移除。
确认前错误确认前的错误只标记那个本地行，把服务端文本作为 errorDetail 记录在上面，不造 _reply。失败气泡下的 NotSent 行在 "Not sent" 之后绘制该文本。
没有本地行没有本地行的拒绝保留 toast，run_active 保留其重排路径。
插话插话行把命令 id 作为 clientRequestId。当读取或更新交付带这个 id 的行时，reducer 返回 settleSteers 效果，调用方运行 settleDeliveredSteer。这也覆盖读取，帧做不到这一点。

子代理

部分规则
占位每次 spawn 都从 on_accepted 写一个占位 attach 行，所以它从第一次写入起就带有 job.id、tool_call_id 和 delivery=tool_result。作业携带 attach_pointer_id，所以结束作业的每条路径都会更新卡片。
结束写入同步 spawn 的结束写入是补丁该行，因为 append_message 对 id 幂等；失败路径和没有 head 的结果补丁为 errored。占位写入失败时，结束写入追加完整的行。
交付与读取notices.queue 对 wait=True 作业本来就是空操作。卡片是观察者以 item_upsert 交付的普通存储写入。运行期间 head_id 为 null；打开该行时通过 get_execution_input 按 job_id 读取。
启动启动对账关闭作业不活跃的 attach 行。折叠的行不加载任何内容。
展开视图展开视图以自己的视图键经同一读取器读取，按分支顺序，不移动 HEAD。
tip 规则与文本它有自己的 tip 规则：predecessor 是视图 tip、且通过 _branch_tip 过滤（user 或 assistant，非 display=runtime，非 function=attach）的 node.put 扩展视图并发出 turn_upsert。文本帧应用到持有 row_id 的已加载视图，所以作业文本不会进入父级。
