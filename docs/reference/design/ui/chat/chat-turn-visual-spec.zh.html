消息表面

没有头像，也没有发言人行。文本列与输入框左右边缘对齐。

表面外观行为
用户气泡靠右，随内容宽度，最多 75%（窄布局和分栏 88%）。16px 圆角，内边距 10px 16px，无边框。填充 --user-msg-bg（= --bg-input），--composer-shadow。悬停加深为 --composer-shadow-focus。内部代码块和折叠粘贴用 --bg-primary 内嵌。
助手回复平铺在页面上。各块之间统一 22px 的 --reply-gap；标题上方多半个间距，下方少三分之一。没有 token 或服务等级页脚。
排队行气泡表面，10px 圆角，位于输入框上方尚未发送的用户消息
发送中气泡 60% 不透明度未送达服务器的发送在气泡下一行说明。
编辑框占满整列，--bg-input，23px 圆角，输入框阴影，悬停和聚焦时加深保留的附件（可逐个移除）、新附件条、带 @ 文件提及的输入行。底行：回形针（ghost 圆形 icon-sm，“添加图片或文件”），然后取消（elevated sm）和保存并重发（primary sm）。Esc 取消，⌘/Ctrl+Enter 保存，可拖入文件。动作行隐藏。

有两个标记不是头像：多代理会话里非 main 的具名代理回复上方 18px 的身份行，以及手动函数运行的 ƒ 标记。

生命周期与归属

  • 流式、完成和恢复的消息使用同一套 ExecutionStrip、ThinkingStep、FunctionStep；完成后不切换为带框表格。
  • 没有有序块时，按存储顺序显示已存的思考和工具记录。不重建缺失的穿插，也不虚构工具记录。结果、错误、标识和完整输出引用保留。
  • Agent 回复发起的函数只属于该回复的时间线。只有用户发起的函数才是独立运行消息。

手动函数运行

表单和精确函数表达式是同一个 FunctionInvocation { name, kwargs } 的两种编辑器，共用一个转换器和一个 HTTP 提交器。两者都不创建用户气泡或 Agent 文字回合。

Please explain gui_agent(...)、`gui_agent(...)`不是完整表达式普通用户消息，交给 Agent

提交识别成功不调用 sendChatMessage，不写待发用户文本。附件、排队和系统决定绝不变成参数。占位、Project、频道、导航和回滚都在共用提交器里。

聊天公式

  • 完整的 $$、$、\[、\( 块在 marked 之前暂存，净化后还原为转义文本。MarkdownText 在绘制后排版；聊天区钉底路径对观察到的消息列调用 typesetMath。
  • 未闭合的流式公式等到下一次带闭合符的绘制。没有公式的文字和不完整的开头不排版。无效公式不抛错。

等待回复

空回复显示一行静态“思考中…”，带摘要行的扫光，没有 ›（代码雨风格下是绿色下落文字）。旋转的活动标记在侧栏对应行上。审批和终态不显示它；时间线、页脚和窗格标题不加标记。

自动重试

方面规则
位置回复最后一个工具组的句子之后，连接方式同“· N 个失败”。以文字结尾或尚无工具组时，单独一行收起行，前面没有点。
文字“服务器繁忙，3 秒后重试 2/5”、“网络断了，20 秒后再试”、“回复不完整，正在重试 2/3”
原因429：被限流。5xx 或过载：服务器繁忙。超时：请求超时。其他：连接中断。
颜色应对失败时橙色。“输出到上限，继续生成”保持行本身的颜色。等待时停止扫光。
秒数从收到通知起倒计时，等宽数字
展开后时间线以重试行结束（插头字形、系统色调、运行中），标题同一句话，失败用一行表示，如 ReadTimeout: …
事件attempt、max_attempts、reason、delay_ms、error（retry_error_text，最多 300 字符）。由 OpenAI 兼容和 Codex 适配器发送，retry-status.tsx 显示。
存续只存在于实时状态。下一段流式内容清除它，恢复后的回复与从未失败的一样。

失败的回复

  • 保留部分回答和有序轨迹。其后、消息动作之前有一条终态通知：本地化标题，技术细节按需以纯文本展开。不增加自动重试。
  • 部分块和失败详情是分开的字段。节点输出为模型上下文和非 Web 使用方保留错误文本；Web 映射器从有序文本块恢复回答。
  • 节点在最终失败事件前持久化详情、原因、可重试性和重试延迟，历史恢复同一通知。旧的错误输出可识别，不改写历史，也不在通知里重复回答。
  • 取消、审批、嵌套详情、重试和分支语义、Goal 报告不变。Provider 错误分类仍为权威；没有第二个错误存储。
验收
  • 公开回合输出文字和工具后失败：实时和冷历史都显示回答、轨迹和一条通知。
  • 空的和旧的失败回复保持可见。成功和取消的回复没有通知。详情在窄布局和暗色下可用。
  • 回归还覆盖浏览器权限继承和高层委派。绑定页面测试提供显式绑定，并期望同一观察失败三次后停止，带具体原因。

转录更新归属

  • 每一行都归服务端所有。读取画出一个窗口，编号的 transcript_update 变化让它保持最新，文字帧按偏移把文字加到块上。三者都由一个 reducer apply-transcript-update.ts 应用，所以实时画出的行就是重新加载画出的行。
  • 浏览器只添加服务端还没给出的东西。待处理的发送、函数占位或提示是有类型的本地行，读取或更新带上它的 clientRequestId 时离开。
  • 先于服务端显示的字段（停止、版本切换、章节固定、文件撤销、目标结果）是覆盖层，在约定事件发生时结束，从不改动下面的行。
  • 执行树补充所属回复：模型发起的函数的树是回复 callRoots 里的一项，函数运行的树是它那一行的字段。视图里没有的行，对应的树或帧不生成任何东西。
  • 漏掉一次更新或丢了一帧文字，视图在锚点读一次。流式过程中的读取不会循环，也不会缩短回复，因为服务端会暂存该视图的帧，直到读取的回复发出。分支移动或结构变化会重新读取。
  • 每个执行根保留持久化路径。重复调用保持独立；一个根在被文字隔开的各组中只消费一次。已完成函数留在摘要内；直接运行保持独立。

验收用生产 reducer 和组件回放录制的聊天，要求每个检查点实时与冷读取一致：流式、部分历史、完成、迟到的树、插话、错误、取消、重连和重载。

交互约定
  • 中间窗口的底部不是最新位置。主窗格和分栏共用跟随、自适应渲染和跳转。
  • 存在更新历史时和请求失败后仍可跳转；重复点击共用一个待处理意图。
  • 滚轮、指针和键盘在窗口变化前取消待处理的跳转或恢复。普通分页仍补偿插入的行。
  • 窗格拆除时保存最终锚点。重连后恢复加载，不沿用旧的重试延迟。
