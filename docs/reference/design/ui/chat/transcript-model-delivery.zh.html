会话记录交付步骤

属于会话记录模型工程记录。目前已完成的内容：实现状态。

交付

批准关口，在步骤 1 之前

一份用用户主题绘制的新旧对比，覆盖下面每一处可见变化，在步骤 1 之前需要得到同意。之后任何增加新可见差异的步骤，都需要在落地前有自己的对比和同意。

  1. 在页边界或由 /task 启动时画成独立 AttachCard 的子代理，在同一位置画成普通的 SubAgentStep。手动和跨会话的 attach 保持 AttachCard。
  2. 子代理（包括同步的）在启动时出现，显示运行中，能打开实时视图，并会落定。
  3. 不再出现幽灵空行、永久的 Running 步骤和被标记为运行中的 user 行。
  4. 用户自己的 /spawn 和 /merge 行保持可见。
  5. 插话和重启续接不再被画两次，也不再在页边界丢失。
  6. 在机器人视图中，插话位于它所改变方向的回复之前，而不是之后。
  7. 向上滚动的读者在后台活动时停留在原处，较旧的页不再落到最新行之后。
  8. 工具步骤下的嵌套调用树在重新加载后保留。
  9. 流式过程中显示引用。
  10. 回复更新时，打开的步骤保持打开并留在原位。
  11. 分屏显示与主视图相同的行，并在没有焦点时更新。
  12. 展开的子代理视图显示工具、思考、终态和之后的轮次。
  13. 重启合并的回复的复制和文件覆盖整个回复；常驻代理发送的文件会出现。
  14. 一个人打的以 [task from 开头的文字仍是他自己的消息。
  15. 版本箭头不再计入压缩摘要，也不会落到 attach 行上。
  16. 读取失败显示重试，而不是形状不同的会话记录。
  17. 在块中展开被截断的工具结果可以工作；迟到的工具结果会出现在原本没有它的行上。
  18. 最终写入失败的回复在执行结束时落定。
  19. 对话正在被读取时，它的文本短暂保持，然后追上。
  20. 历史按完整轮次加载，所以一次加载带来的行数可能略有不同。
  21. 服务端在接受前拒绝的消息，在其 "Not sent" 行上显示原因，下面不再出现单独的红色回复。

其他一切保持位置和外观。
