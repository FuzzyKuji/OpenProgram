Move projects while retaining history

Conversations live under the user directory, grouped by stable project id. No chat records are written into working folders.

~/.openprogram/
  projects/
    projects.json                    # registry / location / identity
    <project-id>/                    # project settings
  sessions/
    index.json                       # rebuildable listing
    locations.json                   # legacy compatibility
    projects/
      <project-id>/
        <session-id>/                # complete session Git repository
        .file-recovery/<session-id>/ # external rewind data
    <legacy-session-id>/             # existing default sessions
  memory/                            # memory store, unchanged
<working folder>/.openprogram/project.json  # versioned random identity token

Copied, original still thereSeparateRunOpening the copy registers a new project with a fresh token.
Copied then original deletedKeptRunOne candidate: treated as a move, also across drives. It cannot be told apart from a move.
Several copies foundKeptBlockedExplicit Locate.

Repair

MechanismRule
DiscoveryAt startup, project-list requests, file or execution access, Locate and opening a folder; never idle. Registered parents or their nearest surviving ancestor, up to 3 levels and 4,000 entries. Excludes home and its ancestors, hidden and dependency directories, directory symlinks. Incomplete or multiple matches do not relocate.
Opening a subfolderA folder with no token, whose nearest token ancestor belongs to a project missing from its recorded place, moves that project to the ancestor (reattach_enclosing_project). Home and its ancestors are never read.
Sibling movesWhen one project is found, other missing projects under the same old parent are tried under the new parent, and outer parents while names agree (follow_sibling_moves). Only where a project's own token is found: one Locate repairs a moved directory.
Where repair is offeredProject menu, Projects page and file tree, from lib/projects/project-location.ts. Identity differs at the recorded path, or a legacy record cannot be verified (a cloud-synced folder can change inode): one click confirms after showing the path. Locate opens the picker.
File tree refreshOpen folders re-list when the window regains focus, at most every 3 seconds, no size recount, through the same location check.
After migrationA waiting project opens when the retry reports every session done or deleted. A journal row whose workdir copy is gone but whose published directory holds the session metadata is done.
Identity, markers and relocation rules
  • Registered ids stay, including path-derived ones. New projects get UUIDs after checking canonical paths; collisions retry, never merge. Session ids are globally unique, names are display only. Location records carry path, revision and token.
  • Ordinary edits and location checks never write a marker. Registration and Locate create it atomically, refuse symlinked or malformed metadata, and do not overwrite another project's. Marker is identity, not authorization: permissions are revalidated at the new path.
  • Legacy records with a matching device/inode at the recorded path upgrade once; others need Locate once. Device/inode and native bookmarks are not used afterwards. Git remote equality is not proof.
  • Automatic relocation needs a matching token and one unambiguous location. Manual Locate allows a replacement after showing old and new paths. Both recheck revision, permissions and ownership at commit. Legacy placement repairs use a durable journal and show "Updating location" until complete.
Execution and references
  • History reads need no working folder. New tasks are blocked with no fallback to HOME, server cwd or session workdir. Running subprocesses are not retargeted; later file operations revalidate. Worktrees are checked separately.
  • Historical messages, authorization snapshots and rewind manifests are not rewritten. New file references are project id plus relative path; unavailable legacy paths stay unavailable. Rewind targeting a missing old location reports it and creates nothing.
  • Project location overrides stale work_dir. Additional directories and source_folders inside the old root are rebased by relative suffix and revalidated; external ones keep absolute paths and their own checks. Missing required directories block dependent operations with a repair option.
  • Memory text and history stay; permanently deleting a source conversation removes or marks its link, without creating a copy. Archived sources stay accessible.
Migration and deletion
  • Every session writer quiesces first: model tasks, fork children, jobs, checkpoints, attachment writers. Initial migration runs before execution; a reconnecting legacy source needs the same boundary, never a hidden move during reads.
  • All writers (CLI, worker, fork children, rewind) share an interprocess lock keyed by session id and re-read revision and location after acquiring it. On timeout, defer; never kill tasks or copy concurrently. Migration holds it exclusively. Mixed-version writes to one profile are unsupported; older processes stop through lifecycle management first.
  • Journal source, destination, identities, inventory. Copy to private staging, verify content and unchanged source, durably publish session and recovery data, atomically publish placement, then clean. Publication failure never allows source deletion. Resume without overwriting conflicts.
  • Messages, Git history, branches, recovery backups and stored attachments are verified together. Deletion is serialized with migration, with durable intent so recovery cannot resurrect. One authoritative writable location.
  • Indexes rebuild from both layouts; a temporarily unavailable migrating session is never pruned as empty. During migration: "Migrating conversations · Tasks start after completion."
Comparison with other tools
  • Adopted: application-owned storage as Claude Code, Codex and DeepSeek Harness have; grouping by project, with stable ids instead of path encodings; id separate from roots as in Codex and OpenCode; Locate from GitHub Desktop. OpenProgram keeps Git session repositories, branches and recovery instead of JSONL.
  • Not adopted: DeepSeek's immutable workspace path; platform bookmarks and events as required identity (Apple, Windows, inotify).
  • Evidence: Codex storage and cwd matching filter on recorded cwd; DeepSeek storage and workspace membership validate real paths against an immutable header cwd. The Claude Code native distribution embeds JavaScript selecting ~/.claude/projects/encoded-path/session-id.jsonl, from local inspection.
