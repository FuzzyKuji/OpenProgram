面板录制

Agent 用 computer_use_agent 的动作，把一个面板录成画面正好是该面板矩形的视频。没有给人用的菜单、按钮或快捷键。App 采集的是自己的页面，所以 macOS 不会来要“屏幕录制”权限，也不新增任何批准步骤。

Agent 调用什么

三个动作，挂在 browser 目标上：它已经连着 App，screenshot 也在这里。命名和限制跟 app 目标的 start_audio_recording、stop_audio_recording 一致。

computer_use_agent(target="browser", action="start_video_recording", args={"pane": "conversation"})
…
computer_use_agent(target="browser", action="stop_video_recording")

Recorded 12.4 seconds of tk3fa, 1600×1200 at up to 60 fps, saved to
~/.openprogram/computer-use/video/20261110-101500-conversation.mp4.
动作参数返回
start_video_recordingpane：录什么，见下表。max_duration：秒数，默认 60，最多 600。立即返回：面板、像素尺寸和时长上限。Agent 接着操作，录制同时进行。
stop_video_recordingdiscard：不保存，直接删除path、seconds、width、height、fps、bytes，以及 ended：不是这次调用结束时的原因
panes无应答窗口里当前可见的面板：id、类型、标题、尺寸
pane录的是
conversation本会话自己的面板（需在屏幕上可见）
panes 给出的 id屏幕上任何中间标签页或画布格子：会话、文件、应用、设置这类内置页面
window整个窗口。网页视图的位置是空白。
网页标签暂时拒绝

规则

方面规则
批准不新增
哪个窗口显示本会话的那个窗口；没有窗口显示时是主窗口
同时只有一个每个窗口同时一个录制。再次开始会被拒绝，并指出正在录的那个。
谁能停止开始它的那个会话
到达上限自动停止并保留文件；之后的停止调用返回它和原因
面板被关闭或隐藏同上：停止并保留文件
面板被调整大小视频保持开始时的尺寸，画面缩放以适应
失败Agent 读到什么
没有 App 窗口应答视频录制需要打开着窗口的 OpenProgram 桌面 App；打开后再调用。
会话不在屏幕上说明这一点，并列出在屏幕上的面板
面板不存在或没写错误里列出屏幕上的面板，和 panes 的结果一样
已经在录已在录制 tk3fa；先调用 stop_video_recording。
没有可停止的当前没有录制；先调用 start_video_recording。
max_duration 超出范围max_duration 必须在 0 到 600 秒之间
App 版本早于此功能提示更新桌面 App
采集、编码或写文件失败哪一步失败；不完整的文件被删除
文件不在 worker 所在的电脑上给出 App 报告的路径

worker 通过桌面链路发送 record_panes、record_start 和 record_stop；录制和写文件都在 App 里完成。代码：openprogram/programs/applications/browser/video.py、apps/web/lib/desktop/recording/pane-recorder.ts、apps/desktop/main/windows/pane-recording.js。

人看到什么

人只看到这圈描边：没有胶囊、计时或按钮。保留它是因为录制不经询问就开始，必须看得出来。录整个窗口时没有描边。

哪些算面板

界面由谁绘制怎么录
中间标签页：会话、文件、终端、审阅、应用，以及设置这类内置页面窗口的页面一路画面，裁到标签页内容
画布格子窗口的页面同上；裁剪范围跟着格子走
右侧栏：文件、活动、资源、详情面板窗口的页面同上
左侧栏、二级列表栏、设置页的一列窗口的页面同上
网页标签工具栏由窗口的页面绘制，网站由它自己的原生视图绘制之后：网站自己的 frame 作为一路画面
悬浮预览同网页标签同网页标签
整个窗口以上全部不裁剪的画面，把可见的网页视图贴进去
在网页上方展开的菜单；原生右键菜单各自的顶层视图；系统第一版不录
网页上的 Agent 光晕和指针每个页面一个透明窗口不采集

布局：中间画布、网页标签边界、Agent 控制覆盖层。

采集路线

路线实测帧率指针macOS 权限编码
推荐。自身画面流：用窗口自己的 frame 应答 getDisplayMedia，再 cropTo 面板完整和裁剪后都是 60 帧；网页标签的 frame 也是 60 帧由 Chromium 画进画面（轨道报告 cursor: motion）不需要内置：60 帧 H.264 MP4，带真实帧时间
循环调用 capturePage640×400 的面板约 115 帧；整窗并做 JPEG 编码时 59 帧没有不需要自己写编码；帧时间只能按循环估计
CDP Page.startScreencast约 93 帧，只能抓整个视口没有不需要自己写编码；要占用页面的调试器，Agent 控制也在用它
窗口采集：desktopCapturer，按矩形裁剪未测，因为一请求就会弹出系统提示真实指针屏幕录制，授予 App内置；原生菜单和网页视图也在同一幅画面里

在 Electron 45.2.1（Chromium 156）、2× 显示器、1280×800 窗口和一个小的移动元素上测得；真实页面在每条路线上都会更慢。

方面规则
谁能采集只有窗口的主页面，只能采集自己窗口的 frame，只在 worker 请求的录制进行期间。网页标签里的网站和现在一样被拒绝。
尺寸面板的 CSS 尺寸乘以显示缩放，取偶数。不设置的话画面流会按屏幕尺寸输出，所以要明确指定。
网页标签网站自己的 frame，交给窗口的页面；不需要拼接
为什么不用窗口采集它多一项系统权限，而且为工作流录制持有“屏幕录制”权限的身份并不是 App。它留给以后解决原生菜单。
为什么不用另外两条够快，但没有指针、没有帧时间，还要自己写编码。capturePage 继续做它现在做的事：静态截图。

文件

方面取值
格式MP4，H.264，8 Mbit/s，最高 60 帧，无声音。面板有变化才出帧，静止的面板帧很少。
GIF, WebM不直接录。需要时 Agent 用自己的工具从 MP4 转。
保存到状态目录下的 computer-use/video/，和音频录制并列；只留最新的 20 个
文件名日期、时间和调用时写的面板名
交给用户Agent 把它复制到工作目录，再调用 send_file

效果

效果做法
指针和点击标记Agent 的操作不会移动真实指针，它平时的指针画在另一个窗口里。用同一批动作事件把同样的指针画在被录的画面里。
自动放大到点击处导出时按文件旁保存的点击列表裁剪并缓动到每次点击
留白、背景、圆角边框导出时把视频放到一张底图上

这些都还没做。导出另写一个文件；原始录像不会被改动。

没有桌面 App 时

场景结果原因
在浏览器标签页里打开的 OpenProgram拒绝：需要桌面 App浏览器只有在人点击并回答它自己的提示后才共享标签页，且仅限 Chromium；Firefox、Safari 和手机根本不能裁到元素
通过扩展操作的用户自己的 Chrome 或 Edge第一版不做之后用 CDP screencast（实测约 93 帧），由 worker 编码
没有窗口的服务器拒绝：需要桌面 App没有东西在绘制这些面板
