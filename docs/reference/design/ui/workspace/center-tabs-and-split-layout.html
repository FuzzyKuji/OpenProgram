Center tabs, split panes and web-tab presentation

Renderer presentation and binding in apps/web. Cross-window transfer and main-process View geometry: see their own records.

Model

ConceptMeaning
TabChat, file or folder, terminal, web page or application page. Each keeps its own Back/Forward history.
GroupTabs shown side by side as one strip entry, laid out by a canvas. MAX_CENTER_TAB_GROUP_MEMBERS is unlimited. Created by groupTab; a preview expanded to split uses setSplitWebTab.
LeafA kind:"web" entry in the center-tabs store. Id w:<url>; a fork from nextPopupWebTabId is w:<url>:popup:…. Floating does not remove it.
PairingThe one first-class session-page relationship (pairedOwnerByTabId). A session may pair with many pages; closing either side clears it. Set when an Agent opens the page in the session, the user drags it into the session's split, or the user collapses it. Standalone pages have none, and no collapse action.
BindingAt most one active (tabId, ownerTabId) in the useWebTabPip singleton, plus previews per session. Not persisted. Rebinding keeps the old pairing.
HostWhere the page renders now: pane, chat preview or none. Derived by pipCoversCenter; components store no visibility.

A leaf has one native WebContentsView at a time. The preview is that real page, never a mask or screenshot; page tab and preview never show together.

Where one leaf is shown

end() clears only the binding; the leaf stays until closeTab. Owner or leaf closing calls it. Switching session is not a transition.

One conversation has one tab per window: see conversation tab identity.

How history is stored
  • pageHistory is the only store: page identity, session metadata, content route and file view, no nested histories, no input or messages. Session legacy history converts on first navigation.
  • Tab id is the instance, sessionId its current session. Collisions get a unique suffix; a slot whose target already belongs to another tab gets a unique identity.
  • Route sync reacts to pathname only; markSessionReady handles session ACK; navigation reacts to current-tab sessionId and draft changes.
  • Native browser URL history stays in browser controls. Web pages keep their own controls. Session history is app state, separate from browser History.
  • Window transfer checks prepared session history before and after the async ACK; a navigation change cancels a stale transfer, and rollback does not overwrite newer navigation.
  • Restoring a detail route first loads its exported host route, then replaces the URL before recording the visit. Duplicate activations share one navigation; a late host commit restores the latest target and is not a visit. Detail routes never reload the document on tab switch.
  • Provider selection derives from the route parameter. A late list response may pick a fallback only on the unqualified page; changing the detail does not reload the catalog.
  • center-tabs-store.ts composes store/ (state, commit helpers, actions) and navigation/ (pure helpers, selectors). No action module owns a second history.

The strip

CaseRule
New tab positionOpened from a tab (link, popup, conversation, file or page preview): right of it, in opening order (insertNextTo). Plus button, New chat, background Agent pages: at the end.
ControlsBack, Forward, New tab: 28px wide, 8px gap. An empty tab list takes no space. New tab has no left divider.
Closing the last tabAllowed. Window and strip stay, content blank, across routes and reloads, with no automatic draft. Session-owned hidden pages stay in Resources and are never the fallback. Close selects visible neighbors after normalizing split groups.
Press and releasePress uses the drag background and blur, changes no page. Release without drag activates by normal click; drag, Escape, cancel or lost focus consumes the click. Focus ring stays.
Drag appearanceTab and pane-label previews share background, backdrop-filter and shadow variables. Settings → General: transparency 0–100%, blur 0–40px, shadow 0–100%, live preview, Restore defaults. Defaults: 20%, 16px, saturation 1.2, 25% of the original shadow alpha. Text and icons stay opaque.
New window cueStays in the strip, above native page bounds: renderer content cannot stack over an Electron child view.
Drag a page onto ResourcesA single web tab attaches that exact Page to the visible conversation on release. Targets: the Resources navigation row, plus its body when open; never one combined rectangle. One border matching the target's outer bounds, no blur. Groups, drafts and other kinds are not sources or destinations.
Page attachment and drag settings detail
  • The server checks owner authorization, the session and the live window/tab/native-target identity from the registered desktop connection, then reuses BrowserResourceStore; no URL copy.
  • Failure reports an error and does not navigate, detach or fabricate a binding. Connection changes reject stale results. Cancelling sends nothing. Success opens Resources and keeps conversation, page identity, top tab and associations. It does not interrupt another execution's operation.
  • Preferences live in local storage, normalized; the pre-paint theme script applies them before hydration; storage events sync same-origin windows. Theme changes keep them. Invalid fields use defaults, numbers are clamped, zero disables that effect. Ordinary buttons and Resources outlines are unaffected. Dragging in the strip reorders; outside it transfers windows as before.
