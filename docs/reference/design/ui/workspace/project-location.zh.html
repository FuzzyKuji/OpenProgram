移动项目并保留历史

会话存放在用户目录下，按稳定的项目 ID 分组。工作文件夹里不写聊天记录。

~/.openprogram/
  projects/
    projects.json                    # registry / location / identity
    <project-id>/                    # project settings
  sessions/
    index.json                       # rebuildable listing
    locations.json                   # legacy compatibility
    projects/
      <project-id>/
        <session-id>/                # complete session Git repository
        .file-recovery/<session-id>/ # external rewind data
    <legacy-session-id>/             # existing default sessions
  memory/                            # memory store, unchanged
<working folder>/.openprogram/project.json  # versioned random identity token

文件夹发生变化时

情形历史新任务App 的处理
移动或改名，含关闭期间保留在新路径运行在限定搜索内找到 token 即更新位置。ID、标题、会话和归档状态不变，聊天文件不动。在搜索范围外：重新打开或 Locate 一次。
磁盘断开可读阻止留在侧栏。提示工作文件夹不可用，可读历史，重连后再运行任务。文件及引用它们的附件等待重连和身份校验。应用存储本身离线时历史也不可用。
已复制，原件还在各自独立可运行打开副本注册新项目，写入新 token。
复制后删除原件保留可运行只有一个候选：按移动处理，跨盘也一样。与移动无法区分。
发现多个副本保留阻止显式 Locate。
旧路径上换了文件夹保留阻止["The folder at this location has changed." “此位置的文件夹已变化。”定位原文件夹或确认替换。已注册给其他项目的位置绝不接管。
旧会话，源盘离线不可用阻止注册保留。提示旧会话尚未迁移，需重连原盘。绝不用空会话代替。

修复

机制规则
发现在启动、项目列表请求、文件或执行访问、Locate、打开文件夹时运行，空闲时不跑。在已注册父目录或最近存活祖先下，最多 3 层、4,000 项。排除主目录及其祖先、隐藏和依赖目录、目录软链。搜索不完整或多匹配时不改位置。
打开子文件夹无 token 的文件夹，若最近带 token 的祖先属于已不在记录位置的项目，项目移到该祖先（reattach_enclosing_project）。不读主目录及其祖先。
同级移动找到一个项目后，同一旧父目录下其他缺失项目在新父目录下尝试，名字一致时继续往外层（follow_sibling_moves）。只有找到项目自己的 token 才接受：一次 Locate 修好整个目录。
修复入口项目菜单、项目页和文件树，共用 lib/projects/project-location.ts。记录路径上身份不同，或旧记录无法校验（云同步文件夹 inode 会变）：显示路径后一键确认。Locate 打开选择器。
文件树刷新窗口重新聚焦时重列已展开文件夹，最多每 3 秒一次，不重算大小，走同一位置检查。
迁移之后重试报告所有会话完成或已删除时，等待中的项目开放。工作目录副本已无、发布目录有该会话元数据的日志行视为完成。
身份、标记与重定位规则
  • 已注册 ID 不变，含路径派生的。新项目在校验规范路径后生成 UUID；冲突重试，绝不合并。会话 ID 全局唯一，名字只作显示。位置记录含路径、版本和 token。
  • 普通编辑和位置检查不写标记。注册和 Locate 原子创建，拒绝软链或畸形元数据，不覆盖其他项目的标记。标记是身份而非授权，权限在新路径重新校验。
  • 记录路径上 device/inode 一致的旧记录升级一次，其余 Locate 一次。之后不用 device/inode 和原生书签。Git remote 相同不算证明。
  • 自动重定位要 token 匹配且位置唯一。手动 Locate 显示新旧路径后可替换。两者在提交时重查版本、权限和归属。旧布局修复走持久日志，完成前显示“正在更新位置”。
执行与引用
  • 读历史不需要工作文件夹。新任务被阻止，不回退到 HOME、服务端 cwd 或会话工作目录。运行中的子进程不改目标，后续文件操作重校验。worktree 单独检查。
  • 历史消息、授权快照和回退清单不改写。新文件引用用项目 ID 加相对路径；不可用的旧路径保持不可用。回退目标在旧位置已缺失时报告，不创建文件。
  • 项目位置优先于过期的 work_dir。旧根内的附加目录和 source_folders 按相对后缀重定基并校验；外部目录保持绝对路径，单独检查。缺失的必需目录阻止相关操作并提供修复。
  • 记忆文本和历史保留；永久删除来源会话时移除或标记其链接，不建副本。已归档来源仍可访问。
迁移与删除
  • 所有会话写入方先静止：模型任务、fork 子进程、作业、检查点、附件写入。初次迁移在执行开始前；重连的旧来源同样要此边界，读取时绝不暗中移动。
  • 所有写入方（CLI、worker、fork 子进程、回退）共用按会话 ID 的跨进程锁，拿到后重读版本和位置。超时则推迟，绝不杀任务或并发复制。迁移独占该锁。不支持多版本写同一 profile，旧进程先经生命周期管理停止。
  • 日志记录来源、目的地、身份和清单。复制到私有暂存，校验内容和来源未变，持久发布会话和恢复数据，原子发布位置，然后清理。发布失败绝不允许删除来源。恢复时不覆盖冲突。
  • 消息、Git 历史、分支、恢复备份和附件一并校验。删除与迁移串行，并持久记录意图，恢复时不会复活。只有一个权威可写位置。
  • 索引从两种布局重建；暂时不可用的迁移中会话绝不当作空会话清理。迁移中提示“正在迁移会话，完成后开始任务”。
与其他工具对比
  • 采用：Claude Code、Codex、DeepSeek Harness 的应用自有存储；按项目分组，但用稳定 ID 而非路径编码；ID 与根目录分离，同 Codex 和 OpenCode；Locate 来自 GitHub Desktop。OpenProgram 保留 Git 会话仓库、分支和恢复，不改 JSONL。
  • 不采用：DeepSeek 的不可变 workspace 路径；把平台书签和事件作为必需身份（Apple、Windows、inotify）。
  • 依据：Codex 存储和 cwd 匹配按记录的 cwd 过滤；DeepSeek 存储和 workspace 成员用不可变头部 cwd 校验真实路径。Claude Code 原生发行版内嵌的 JavaScript 选择 ~/.claude/projects/encoded-path/session-id.jsonl，来自本地检查。
