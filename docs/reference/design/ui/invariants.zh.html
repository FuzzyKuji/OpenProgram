第 1 至 3 条。改变集合的新入口（导入配置、批量操作、CLI 写配置）都挂同一个广播；设置页可能在另一个标签页。

规则靠什么成立
1. 启用集合是唯一的模型门控list_enabled_models()：providers 配置里的 spec 行。被禁用即无选择器、无默认、无 chip
2. 启用集合变化必须广播所有消费者响应，如图
3. 禁用上次使用的模型就是忘掉它新会话使用 config.json 的 last_used_model，没有默认模型。只隐藏的话，它会继续服务后台任务，重新启用时又回来
4. 前端 store 能表达“已清除”setAgentSettings 字段：对象替换，null 清除，undefined 保留。单靠 ?? 覆盖不掉旧值；后端可能报告“已没有”的字段都要这样
5. 后端到前端的帧走事件总线emit_ws_frame({"type": ..., "data": ...})；服务端唯一的订阅者转发给 socket（事件层）。_s._broadcast 对总线消费者（proactive、日志）和审计不可见。带会话路由、不在此列：_broadcast_envelope、_broadcast_chat_response
6. spawn 的三个入口语义一致clean 模式：spawn_caller 使分支根的 caller 指向开启它的那轮，不是 ROOT。一起改，一起测
7. 聊天兄弟切换器只在真实分叉上出现< N/M > 按分叉点分组（predecessor，否则 caller；ROOT 视为无），只含对话轮次
8. 交互即时反馈交互反馈。函数运行有约 1s 子进程冷启动，绝不能像点了没反应
9. 显示顺序可以调，数据顺序不可以attach 指针留在链尾供 head 移动，而 Spawned 卡片显示在它喂给的回复之前。在服务端投影（transcript/children.py）调序，不改落盘顺序和 head 语义
10. SSR 边界：模块作用域不碰 windowapps/web/lib/runtime-bridge/* 可能在模块作用域读 window（session/chat-handlers.ts），被预渲染页面静态 import 即失败。新模块遵守这条，或把 window 访问推迟到函数体内
11. 会话记录的行只画服务端发来的内容主对话、分屏窗格和展开的子代理都经 TranscriptRows 绘制。每一行按自己的 rowKind 分发，没有默认分支，并从所在行列表取得所属对话，从不取聚焦的对话
