页面加载性能

每个应用页面都加载共享界面。优化首屏代码、重复目录计算和 Provider 选择渲染，不改变认证、路由历史和模型能力。

不是端到端点击耗时。基准中十四种 DiceBear 样式全部进入首屏依赖（两个头像文件，gzip 约 270 KB），原生 Provider 列表请求耗时 1138 ms，Python profile 记录累计枚举 1.318 s。会话期间的资源计数包含三秒轮询，不是冷启动耗时。

设计

方面规则
头像可选样式用显式动态导入（React lazy）；默认 shapes 样式保持同步。合并进行中的加载，失败后可重试。卸载或配置变化后到达的结果被忽略。
SVG 缓存模块级重用，有上限（128 项，51.2 万字符）。上传和字母模式不生成 DiceBear SVG。
Provider 行React memo 配稳定回调；选择变化不重新生成未变的图标。
目录每次请求一份凭据存在快照，不跨请求，也不作为认证判断缓存。
设置读取成功的读取只在有效期内初始化 Provider 目录的首屏；配置操作使其失效。

必须保持

  • 不支持的 Provider 保持不支持。本地 Provider 身份、别名、账号存在性、CLI 回退、环境变量和云认证语义不变。
  • 指标不暴露凭据值。
  • 缓存过期、请求失败和加载占位都不把另一个 Provider 显示为已选路由。
  • 上传、字母、全部生成样式、Thumbs 背景和 SVG ID 隔离保留。
验收
  • 公共头像入口只加载默认样式；所选样式只加载一次；十四种都可选。
  • 相同头像在有界缓存内重用标记。
  • 目录列表测试证明每次请求枚举一次，下次请求立即反映变更。
  • 选择更新只渲染受影响行；预热后再次访问立即显示缓存行。
  • 对比生产入口字节和同机目录耗时与基准。
  • 在已安装的默认 App 中检查聊天、Agents、能力、通用和 Provider 导航。
