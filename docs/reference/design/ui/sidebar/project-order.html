Sidebar projects and conversations

The registry owns project membership. The projectGroups join applies the selected sort and pins; session ownership never changes.

Lists and order

ItemRule
PinnedA separate top-level list above Projects, same header typography and indentation, independent collapse. Each project appears once. Omitted when empty.
ProjectsHeader stays for filtering even when empty. Custom sections are peer lists and stay manageable when empty.
Project sortRecent activity (newest conversation), oldest activity, alphabetical, or manual once dragged. Independent of conversation order.
Conversation sortExplicit ascending or descending
VisibilityOnly projects with visible, non-archived conversations, pinned ones included. Archiving the last conversation hides the project; restoring one brings it back. Registration, selection, management, archive and stored order are untouched.
Stored order

A project ID array in the recents view preference, per browser, synchronized between windows by storage events. Unknown IDs are ignored, new projects follow the fallback sort, hidden projects keep their place when another moves. Invalid arrays fall back to the default. Storage failures keep the visible order for this window and announce that saving failed.

Dragging

Start
Pointer capture and a 6px movement threshold, no dependency
Motion
The group follows the pointer vertically, neighbours shift with the Favorite Programs spring (stiffness 600, damping 40). No insertion line or name preview. Reduced motion removes the spring.
Drop
Saves order and manual sort; section and pinned placement follow the destination. Sessions move with their project.
Cancel
Escape or a drop outside the list changes nothing
Keyboard
Alt+ArrowUp and Alt+ArrowDown keep focus and announce the result

Right-click and the options button open the same menu.

AlsoProject settings, new project conversation

Metadata

  • Updates validate supported fields, lengths and absolute existing directories, then replace the registry atomically under its lock, and notify all windows.
  • Editing never changes the main folder or membership; relocation is a project-settings operation. Moved folders: Project location.
  • Source folders are defaults when a chat has no explicit folder list; a deliberately empty list stays empty.
  • Filters use registry IDs, so renames do not break them.
  • Save failures keep the form and show the error.

Context menus
  • Desktop project and conversation menus use Electron Menu.popup. Coordinates are the invocation point in CSS pixels, scaled by renderer zoom; keyboard uses the focused control.
  • The Web fallback uses the same point with viewport collision handling, and also takes over when a native menu fails.
  • The bridge accepts bounded plain menu descriptions from the owning shell frame and returns only a selected action ID.
  • Cancellation, renderer navigation, unmount and window destruction close the request and clear transient feedback.
Project settings editor
  • Uses the application's Input and Textarea, with theme tokens and system font. Focused fields have a thin accent border and soft glow; the dialog has a restrained accent edge.
  • Icon choices show a persistent selected state and the header previews the choice.
  • Labels are 13px, fields use the shared 10px corner scale, content is left-aligned, and the body scrolls on narrow screens. Folder paths wrap without displacing remove controls.
  • Dialogs and overlays sit above narrow-screen sidebars, so the editor and its folder picker stay visible.
  • Reduced motion disables added transitions.
Acceptance
  • Dragging either way changes order only on drop, and reload keeps it.
  • Collapse, new-session buttons, membership and filters are unaffected.
  • Real menu entry, computed focus and selected styles, light and dark, reduced motion, cancellation and unchanged save payloads.
