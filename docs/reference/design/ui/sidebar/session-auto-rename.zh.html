会话自动重命名

会话菜单里“自动重命名”紧跟在“重命名”之后，让标题模型根据对话内容生成简短标题。侧栏原生菜单、侧栏网页菜单和对话菜单共用一个客户端动作 autoRenameSession。

情况结果
生成中显示进度；旧标题和内容保持可见；同一会话的重复点击合并
成功先保存再广播 session_updated；已加载的对话和所有客户端看到同一标题
失败保留旧标题；提示可重试
传输超时报告结果未确认，请用户刷新页面查看标题；不重放操作
期间会话被改名或删除生成后重新检查；丢弃过期结果
发起请求的连接断开已保存的标题不受影响
手动重命名不变；手动输入的标题不会被后台命名覆盖
生成的名字不锁定：清除 _user_titled，后台命名之后仍可改进
服务端路径
  • 不带标题的 rename_session（handle_rename_session）在工作线程里运行无工具的标题生成器，上下文与后台命名相同（build_title_context）。
  • 由一个被保留的后台任务持有调用，WebSocket 接收循环立即释放；任务完成后移除。
  • 没有验证过原生 JSON Schema 支持的模型走提示词回退，本地 schema 校验相同，同样不带工具。
  • 聊天历史提供文本；只有函数的对话提供调用标题和结果。
范围和验证

不改变操作系统权限、审批模式、首轮自动命名或其他应用。

验证公开的重命名命令在聊天和纯函数历史上的表现、失败、手动改名竞争、删除和持久化；菜单动作和断线反馈；再在 App 里确认侧栏动作能生成标题、更新侧栏和标签，并在完整刷新后保留。

实现状态

已实现：菜单、共用客户端动作、后台重命名处理。
