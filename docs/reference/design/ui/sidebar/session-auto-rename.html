Session auto rename

Auto rename sits directly after Rename in the session menu and asks the title model for a concise title from the conversation. The sidebar native menu, sidebar web menu and conversation menu share one client action, autoRenameSession.

CaseResult
RunningProgress shown; old title and content stay visible; in-flight clicks deduplicated per session
SuccessSaved before session_updated is broadcast; loaded conversation and all clients see the same title
FailureOld title stays; retryable message
Transport timeoutReports an unconfirmed result and asks to reload to check the title; the operation is not replayed
Conversation renamed or deleted meanwhileRechecked after generation; stale result discarded
Requesting socket lostA saved title stays
Manual RenameUnchanged; a typed title is locked against background titling
Generated nameDoes not lock: clears _user_titled, so background titling can still improve it
Server path
  • rename_session without a title (handle_rename_session) runs the no-tools title generator in a worker thread, from the branch context background titling uses (build_title_context).
  • A retained background task owns the call, so the WebSocket receive loop is released at once; the task is removed when it completes.
  • Providers without verified native JSON Schema support use the prompt fallback, with the same local schema validation and no tools.
  • Chat history supplies text; function-only conversations supply call title and result.
Scope and verification

No change to operating-system permissions, approval modes, automatic first-turn titling or other applications.

Verify the public rename commands for chat and function-only histories, failures, manual-name races, deletion and persistence; menu actions and disconnected feedback; then in the App that the sidebar action generates a title, updates the sidebar and tab, and survives a full reload.
