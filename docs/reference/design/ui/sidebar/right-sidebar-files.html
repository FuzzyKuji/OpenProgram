File tree and file management

The sidebar and the central Files page share one tree on @pierre/trees 1.0.0-beta.6. Pierre owns rows, hierarchy, selection, focus, virtual scrolling, sticky ancestors and keyboard navigation; OpenProgram owns filesystem state. Row height 30 pixels, density 1.

  1. PathBreadcrumb; copy button at the right end
  2. ToolsSearch, new file, new folder, refresh, sort, info
  3. SearchInput, opened on demand
  4. HeaderName, Size, Date Modified, Kind
  5. RowsName: remaining width, middle truncationSize 100 px, Date Modified 200 px, Kind 140 pxBelow 720 px: Name and Size only

Columns

AspectBehaviour
WidthA ResizeObserver measures the viewport and sets the Name width and visible columns; it disconnects on unmount. Rows never outgrow the panel and nothing scrolls sideways, as in Codex's tree, so Pierre's selection, focus ring and name editor draw whole without overrides.
HeaderStays visible during vertical scrolling and shares its column boundaries with the rows.
CellsPierre has no sortable columns. Three text parts through renderRowDecoration, styled with unsafeCSS; parts that do not fit are clipped. No table framework, no per-file metadata request.
Date Modifiedmtime in epoch seconds from the directory and search responses, shown in the current language and local timezone. Blank for missing timestamps and synthetic search ancestors.
KindFolder; uppercase extension plus file; File when there is no extension.
SortingDirectory headers toggle the per-project server sort preference, keeping folders-first and the hidden and ignored filters. Search keeps relevance order and its headers do nothing.
Deep foldersIndentation is capped inside Name, leaving room for the icon and filename and keeping columns aligned.
RenameInline rename keeps Pierre's decoration suppression.
Out of scopeColumn reordering, manual resizing, extra metadata fields, filesystem watchers.

Listing and search

AspectBehaviour
Listingproject_file_tree: lazy per directory, paginated, sorted on the server. Sort by name, type, modification time or size, with folders-first. Framework comparators keep backend order and never revert to alphabetical.
PaginationThe next page loads near the end of a directory's loaded entries, with no pagination button.
SearchBackend permission scope and pagination. Results use Pierre's hierarchy; highlight mode keeps directories.
MatchesThe backend decides fuzzy matches, shown by match markers and the native current-item selection. Literal queries use framework text highlighting.
RevealControllers expand and scroll; nothing depends on handwritten row DOM.

Visible folderBounded background statistics, in a shared queue running two jobs at once. States: cached, scanning, complete, partial, canceled, error. Search-excluded folders such as .cache and node_modules still have metadata and sizes.
In the listThe number alone, without ≈ or ≥.

Saved samples

AspectBehaviour
ReuseFinished samples survive view remounts and worker restarts and display without recursive I/O. At most 256, in the default profile state. Size sorting keeps the recent-complete-sample rule.
New scanOnly Refresh and Recalculate.
InvalidationA successful Files change removes affected ancestor and subtree samples from memory and disk and cancels affected active scans, including overlapping project roots.
KeyValidated absolute path. Device and inode must also match, so a rebound project or replaced directory cannot reuse another directory's bytes.
Incomplete scansStay incomplete and keep their skipped-entry record. Active scan tokens are never saved.
Stale samplesNested edits can outdate a sample; Details shows its time and completeness. No watcher, recursive freshness check, content read or new profile.
StorageThe existing atomic JSON writer: private temporary file, atomic replace. A corrupt or unavailable cache falls back to scanning.
Why not another store
OptionResult
Python sqlite3Durable transactions and concurrent connections, not needed for a bounded cache owned by one worker. No schema or dependency added.
Pierre tree, React queueKept for virtualization and the two visible-folder jobs. Neither supplies durable server-side samples.

Moving

AspectBehaviour
DragPierre's drag and drop onto a folder or the root; a hovered folder opens after 600 ms.
Carried out byThe tree shows the move at once; the same server rename as Cut and Paste does it, with draft protection and open-tab retargeting. A refused move re-lists the tree.
UndoEvery move shows a toast with Undo, which moves the entries back.
SkippedA move onto the same parent or into the moved folder itself.

Move to

A shadcn Command dialog that reads its input as a path. Goes through the same server rename and Undo toast; the chosen folder opens in the tree.

InputListed
NothingProject root, the five folders moved to most recently in this project, top-level folders.
folder/nameSubfolders of the part before the last slash, from project_file_tree, filtered by the rest, names starting with it first. Folders list first, so reading stops at the first file. One listing per level, so any project size works. Tab steps into the highlighted folder.
nameAlso project_file_search with type: "dir" for hits elsewhere; none past the search's snapshot limit.
A path naming no folderOffers to create it, missing parents included, and move into it.

The current folder and the moved folders are disabled.

Files from the desktop

AspectBehaviour
DestinationThe folder under the pointer, the folder of the file under it, or the project root. The tree outlines itself and a chip names the destination.
TransferThe browser reads the dropped files and streams each to POST /api/files/upload with a project-relative path. No local path is sent; nothing outside the project is opened.
FoldersArrive as their files, with missing parents created.
Existing nameNever replaced: the upload refuses it and a toast counts what was left unchanged.
Limit1 GiB per file.
ComposerThe drop stays in the tree and does not reach the attachment drop.

Refresh and errors

SituationBehaviour
Window regains focusRe-lists open folders, at most every three seconds, without recounting sizes.
Any refreshKeeps the selected path, expanded directories and loaded pages; old rows stay while it is pending.
Collapsed parentStays closed even if descendants were expanded; reopening restores them.
Directory or page failsAutomatic retries stop. The path and an explicit Retry show, never fictitious entries.
Project folder unavailableThe reason and the repair replace the listing: confirm the folder at the recorded place, or Locate. See project location.
Contracts keptWorkspace scope, cancellation, stale-response isolation, draft protection, server-side idempotent changes, metadata and size-cache permissions. The framework never touches file contents or decides permissions.
