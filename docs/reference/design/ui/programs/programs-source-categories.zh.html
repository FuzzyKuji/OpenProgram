Programs 源码分类

浏览器有 tools 和 applications 两个根，每个根下沿用已安装的源码层级。浏览器端不虚构分类路径。

行

行依据显示操作
tools已安装包下的目录下方 11 个用途目录只读目录
tools/<purpose>/<source>Python 源码和注册元数据一个可调用项：一行。多个：一个可展开的组。收藏和使用作用于可调用项
tools/<purpose>/<package>（含入口）registry.TOOL_PROGRAMS 中的包（tools/planning/goal）可展开：已注册入口和支持源码文件收藏和使用作用于入口
applicationsregistry.builtin_application_names()、program_directory.program_dirs()、catalog.records()、sources.owner_controlled_program_sources()每个应用一行，按名称排序；origin 为 builtin 或 installed；被跟踪时带 enabled；用户包带 load_state收藏和使用作用于入口；设置在 Applications 页或 openprogram programs enable|disable
applications/<name>/…目录路径下的注册入口，然后是顶层 Python 文件入口类型为 application；支持文件为源码行。harness clone 无子项，调用逻辑来自仓库分析。现有调用树和图

源码是用户包目录的已编目应用就是该包的行；位于其他应用目录内的，是带 part_of 的独立行。

单个实现文件是模块。有 provider、prompt、action、worker、共享状态或多个协作入口就是包，一个包可注册多个可调用项。公开名称不受位置影响。

应用函数调用

方面行为

应用发现与导入

  • 内置或用户目录只有带 __init__.py 或 application.json 才是应用。解析到根外的符号链接被跳过。已注册的嵌套入口通过其分类路径保持可见。
  • ~/.openprogram/programs/ 中的用户包从 openprogram.programs.tools.* 和 openprogram.programs.applications.* 导入内置 Program，从 openprogram.programs._authoring 导入辅助函数。openprogram.programs.Agents 和 openprogram.programs.workflow 不存在。
  • App 刷新在不同构建检出间保留有效的显式所有者 Programs 目录。配置的目录缺失时需要修复，绝不换成空的构建目录。显式迁移仍可用；首次安装可建立初始目录。

函数的直接回复和输入

手动运行的函数保留执行树，持久化的最终答案作为 Markdown 正文显示在树下，树折叠时也可见。这不增加模型调用或对话节点。摘要和接管说明保持可读，其他值显示为文本或 JSON，嵌套调用不变。选中的执行详情跟随状态更新，无需打开侧栏。

空函数表单按可见字段定高：折叠的 Advanced 部分只算摘要行。

备选方案与参考
参考模型本项目
OpenProgram 注册表普通和 agentic 函数在同一可调用面，带源码元数据保持一个运行时目录；只在管理界面加只读源码筛选
Hermes toolsets命名工具集表示选择，不表示归属工具配置与源码分类分开
Claude Code内部工具树未公开不照搬无法核实的一工具一文件夹假设
OpenAI Codex同时有 handler 文件和子模块同样按复杂度区分，不用 Rust 专有名称

不采用：每个可调用项一个目录、每份源码一个文件、仅前端分类、第二个分类注册表、旧导入路径的兼容副本、原始源码文件浏览、在 Programs 中重复 MCP 工具。

验收
  • 每份发布的工具源码恰在一个用途目录下，无旧顶层源码。
  • computer_use_agent 直接可见，逻辑路径为 tools/computer_use/computer_use_agent。
  • 内置浏览器是应用。每个应用都列在 applications/ 下。
  • 所有已注册可调用名称仍可用。
  • 打包后的 gui_agent 入口能开始桌面运行，无导入错误；应用包不导入已移除的命名空间。
  • 由 explorer 和注册表测试、导入冒烟、Programs UI 检查、TypeScript 编译和构建覆盖。
