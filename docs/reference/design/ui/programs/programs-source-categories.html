One implementation file is a module. Providers, prompts, actions, workers, shared state or several cooperating entries make a package, and one package may register several callables. Public callable names are unaffected by location.

Application discovery and import

  • A built-in or user directory is an application only with __init__.py or application.json. A symbolic link resolving outside its root is skipped. Registered nested entries stay visible through their category paths.
  • User packages in ~/.openprogram/programs/ import built-ins at openprogram.programs.tools.* and openprogram.programs.applications.*, and helpers from openprogram.programs._authoring. openprogram.programs.Agents and openprogram.programs.workflow do not exist.
  • App refresh keeps a valid explicit owner Programs catalog across build checkouts. A missing configured catalog needs repair and is never replaced by an empty build directory. Explicit relocation remains; first installation may establish the catalog.

Direct function replies and input

A manually run function keeps its execution tree, with its persisted final answer as a Markdown body below, visible even with the tree collapsed. This adds no model call or conversation node. Summaries and takeover instructions stay readable; other values show as text or JSON; nested calls are unchanged. The selected execution detail follows status updates without opening the sidebar.

Empty function forms size from visible fields: a closed Advanced section contributes only its summary row.

Rejected: every callable in a directory, every source in one file, frontend-only categories, a second category registry, compatibility copies at old import paths, raw source-file browsing, duplicating MCP tools in Programs.

Acceptance
  • Every shipped tool source lives under exactly one purpose directory, with no old top-level source.
  • computer_use_agent is directly visible, with logic path tools/computer_use/computer_use_agent.
  • The built-in browser is an application. Every application is listed under applications/.
  • All registered callable names remain available.
  • The packaged gui_agent entry begins a desktop run without an import error; application packages import no removed namespace.
  • Covered by explorer and registry tests, an import smoke test, the Programs UI check, TypeScript compile and build.
