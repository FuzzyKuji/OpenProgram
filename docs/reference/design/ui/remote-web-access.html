Remote Web access

Every HTTP, SSE and WebSocket request carries the per-start instance token, even on loopback. A valid token means the active profile's one owner. No relay, no accounts.

Invariants

  • Before authentication: no protected state, session data, file bytes, secret metadata, SSE event or WebSocket frame leaves, and no action runs.
  • A missing Origin never establishes trust. It is allowed only after valid Bearer authentication, or on a safe cookie request.
  • The token complements Host and Origin checks; cookies keep CSRF controls.
  • A non-loopback bind with incomplete origins fails before listening.
  • No route returns a stored secret, or the token after initial entry.

Startup failure and cleanup
  • The write follows the temp-file, os.replace and permission pattern of openprogram/extensions/mcp/token_storage.py.
  • Startup fails if the lock cannot be taken or the token file cannot be created and read back safely.
  • read_active_web_access() returns ActiveWebAccess only for a valid snapshot whose fingerprint matches the live token file.
  • On bind failure or shutdown, the process removes the token only while holding the lock with its own token in the file, and access.json only when the fingerprint is its own.
  • Stale unlocked files are replaced atomically by the next process.

  • The profile-specific name keeps simultaneous profile servers from overwriting each other's cookie: cookies are not port-scoped.
  • The cookie has no database row. It is recomputed from the token, so a restart invalidates it.
  • Except on bootstrap, any Authorization header selects the Bearer path: a bad one returns 401 and never falls back to a valid cookie.

Browser sign-in

The fragment never appears in an HTTP request, proxy log, Referer or route. apps/web/lib/net/auth/owner-auth-bootstrap.ts mounts the application only after the exchange and uses no Web Storage.

POST /api/auth/bootstrap contract
  • POST only, with a valid exact Origin and valid Host.
  • Content-Type: application/json, body at most 256 bytes, exactly {"token":"<43-character base64url>"}. Unknown keys, duplicate keys, bad base64url and other lengths are rejected.
  • Any Authorization header, a missing token or a wrong token: the same 401.
  • Success: 204 and the cookie. Always Cache-Control: no-store; the token is never in a response.

Sign-in link for another device

openprogram web auth-url --base-url https://agent.example.com
  1. Compare worker PID and port files, access.json and the listening process: send a fresh nonce to GET /api/auth/challenge and check the HMAC proof locally. The token is never sent to the probed port.
  2. Read the live token file and print one fragment URL to the terminal, never to application logs.

--base-url must be an effective origin frozen in access.json, with no path, query, fragment or user information. HTTP passes only for exact localhost on a loopback listener or an IP in the ranges under Plaintext HTTP.

Listener challenge and session check
  • Input: nonce of 32 bytes as 43-character base64url, optional revision of 40 lowercase hex that must equal the served revision.
  • Output: exactly 200 {"proof":"<43-character base64url>"}, where the proof is HMAC-SHA256(raw_token, "openprogram-web-challenge-v1\0" + nonce + "\0" + revision).
  • No credential is sent, and no token or diagnostics are returned.
  • GET /api/auth/session after sign-in: 204 means the cookie matches the live worker. On 401 the desktop shell exchanges a fresh in-memory token and repeats bootstrap instead of reconnecting with a stale cookie.

The Bearer allowance exists because the Node TUI reaches loopback by IP while presenting the canonical origin. Safe methods are GET, HEAD and OPTIONS, and change no state. Sec-Fetch-Site: cross-site is always rejected. CORS headers control reading a response and are not authentication.

How origins are computed
  • web.host and web.allowed_origins come from the active profile's <state-dir>/config.json. web.host defaults to 127.0.0.1 and is needed only for direct LAN or VPN access.
  • An entry is only scheme://host[:port], http or https. Invalid: wildcards, paths, queries, fragments, user information, opaque origins, malformed IPv6, unspecified and multicast literals (so 0.0.0.0 and ::).
  • DNS names are IDNA- and case-normalized, IPv6 is bracketed, default ports are removed.
  • effective_origins = configured origins + on a loopback listener, http://localhost:<port> and the literal actually bound. A non-loopback listener gets no implicit origin. A request's Host is never promoted into the set.
  • Host must be one valid authority: duplicate, comma-joined, user-information, unspecified and multicast forms are rejected.
  • request_origin = scheme + parsed Host, with ws as http and wss as https. This one comparison covers exact origin and DNS rebinding.

Acceptance behaviours
  1. Loopback HTTP, SSE and WebSocket without a credential fail.
  2. A correct Bearer token works without Origin; a wrong one gets the same 401 and does nothing.
  3. Bootstrap clears the fragment before other fetches, accepts only the bounded JSON, sends no token in URL, query or Referer, derives the specified cookie, rejects a body token with Authorization, then opens HTTP, SSE and WebSocket.
  4. Cookie unsafe HTTP and WebSocket reject missing, opaque, cross-site and unlisted origins before action or accept.
  5. Foreign, duplicate, comma-joined, unspecified and multicast Hosts are rejected on loopback, direct bind and proxy; HTTP/WS and HTTPS/WSS give the same origin pairs.
  6. Default loopback accepts only its implicit origins; another SSH local port is rejected until configured.
  7. A non-loopback bind without valid origins refuses startup; the listed HTTP ranges pass with warnings; unspecified, multicast, documentation, benchmarking, reserved and global literals are rejected for HTTP.
  8. Uvicorn proxy rewriting is off; forwarded scheme is honoured only from a raw loopback peer; forged X-Forwarded-For changes nothing; public bootstrap without HTTPS fails; direct WS and Caddy WSS give the expected origin.
  9. A second process for one state directory cannot change the live token or snapshot; bind failure removes only the failing process's files.
  10. Restart rotates the token and invalidates the old Bearer and cookie.
  11. A malformed Authorization header never falls back to a cookie.
  12. Static assets and /healthz contain no token, session, filesystem or credential data or diagnostics.
  13. Headers reject framing; protected responses are no-store; 401 advertises the Bearer realm.
  14. Docs read without authentication from prebuilt files in checkouts and packages, with no scan or build; Host still applies; unsafe methods and private APIs are excluded.
  15. Reveal returns 410 and 404; replace, preserve and delete follow the exact schemas; 8–11-character values use the fixed mask; masks are never accepted; frontend types have no reveal or full-secret field.
  16. nginx and Caddy carry authenticated HTTP, SSE and WebSocket over HTTPS with a loopback backend.
  17. Channel messages keep paired and gain no owner authority.
  18. Two profile servers on one hostname and different ports have distinct cookies and authenticate independently.
  19. The ownership probe checks PID, port and snapshot, sends only a fresh nonce, validates the versioned proof, optionally binds the revision, disables ambient HTTP proxies and never sends or logs the token. Foreign listeners and stale or mismatched snapshot, port, proof or revision are not the owner server.
