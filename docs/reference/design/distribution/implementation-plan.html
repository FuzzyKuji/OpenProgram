What verify-product-runtime.py checks
  • Launches a headless Chromium page; an artifact may record browser_probe as deferred only under --allow-deferred-browser.
  • Imports channel and search dependencies; checks Web assets.
  • Runs both built-in PDF extraction paths on a generated PDF; probes Rich rendering.
  • Requires installed OpenProgram metadata to equal the runtime manifest version.
  • Manifest schema 2 records each capability's present and verified, the product-manifest and lock hashes, exact distributions, platform and architecture.

Release acceptance

Each target is built on its native runner, on tag push v* or manual dispatch for an existing tag.

  1. Source, lockfile, Desktop and installer versions agree.
  2. Runtime archives are assembled, archived and verified per platform and architecture.
  3. Desktop jobs embed the same runtime, sign, and verify it before upload.
  4. CLI installer jobs verify checksum, extraction, capabilities, worker cold start, atomic current activation and launcher version.
  5. The publish job writes the release manifest and requires .github/release-notes/<tag>.md, in English, with the expected heading. It never overwrites a public release.
