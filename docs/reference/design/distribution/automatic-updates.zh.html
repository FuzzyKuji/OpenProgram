稳定版自动更新

更新是一个按清单校验过的完整稳定 GitHub Release。新提交不是更新。更新单位是整个产品：wheel、Web、Program、OCR、Browser 和模型都不单独更新。macOS App 和终端安装接收完整安装包；Windows 和 Linux App 接收已签名的封存版本。

从 Release 到平台

安装类型路径
managed_release上图路径。不可变标记优先
source_checkout明确的 Git ref：预检、检出、依赖与构建、探测、重启。不显示成稳定 Release
unknown稳定的错误，指向官方安装器或源码检出。不猜 PyPI、二进制或 Git 路径

openprogram upgrade 应用更新；--check 只读报告当前和最新版本；--dry-run 打印计划。pip_wheel 不是安装类型：开发者 wheel 只作构建输入。

调度

自动检查只负责发现。手动检查总是刷新。开发模式不自动检查。

时机下次检查
App 启动（打包版）30 秒后，或缓存算出的到期时间
成功后lastSuccessAt + 24 小时
失败后lastAttemptAt + 6 小时
唤醒或改设置清掉旧定时器，最多检查一次，重新排期
update-state.json

Schema 1。保存 automaticChecks、lastAttemptAt、lastSuccessAt 和最新已校验的发行版元数据。用临时文件加重命名写入；POSIX 设置权限，Windows 继承用户目录 ACL。

无效 JSON、未知 schema、未来时间戳、版本或架构不符、发行版缺失，都会规范化后重写。写入失败不得留下隐藏的内存设置变更。

信任边界

边界规则
GitHub 响应不可信。HTTPS、固定主机、最多 5 次重定向且每跳校验、大小上限、30 秒请求超时、60 秒下载空闲超时。要求 draft === false、prerelease === false、tag 为 vX.Y.Z、资产名和 manifest 基名唯一、GitHub 大小等于 manifest 字节数。
网络路径走 Chromium 网络栈，因此使用系统代理。API 返回 403、429、5xx 或无响应时，改用 releases/latest 重定向加 release-manifest.json。仍失败时，用可选的 update-source.json，只有带内置密钥的 Ed25519 签名才生效
渲染进程 IPC只暴露状态、检查、布尔设置、下载、打开发行版、订阅。不接受 URL、路径、哈希、仓库或命令。公开状态去掉资产名、URL 和 SHA-256。关窗口不中止任何操作
下载文件随机排他临时文件，处理短写，任何不符都删除。CLI 在新版本目录校验并拒绝归档路径穿越。启动器失败保留旧 current
安装器子进程固定仓库和版本。只放行 PATH、HOME、临时目录、语言、代理、XDG、OpenProgram 状态。不继承 provider 或 API 凭据，不继承归档或校验和覆盖项。--json 只输出一个 JSON 文档

失败

发生了什么结果
离线、超时、限流先回退到网页路径。自动检查：记录并退避 6 小时。手动检查：可重试的错误，并用平实的话说明原因。App 继续运行
Release 或清单无效下载前拒绝。不退回 wheel、源码归档、其他架构或旧版本。可保留最近的有效元数据
卡住、大小、哈希或 Windows 签名错误下载中断时重试，并通过 .part 文件续传，重启后也能继续。大小、哈希或签名不符时删除文件并恢复重试。未验证的文件绝不打开
CLI 归档、冷启动或启动器失败在最后切换前非零退出。旧版本保持选中（macOS 和 Linux 上是 current，Windows 上是启动器）
切换完成，worker 还是旧的命令明确说明并打印重启指令。不打断运行中的请求

版本库上的正式更新

从版本库运行的安装用签过名的 release 资源更新，并把所有者自己的提交重放到新 release 上。

项目规则
资产每个发行版都发布 version-<platform>.tar.zst、base-<platform>.tar.zst、toolchain-<platform>.tar.zst、repo.bundle、SHA256SUMS 和带 Ed25519 签名的 update-manifest.json，跳过若干版本的机器也能更新。客户端只下载缺少的部分：已有的 base 跳过，toolchain 只有在要构建 owner 提交时才下载。版本归档不含 venv 的链接和封印，因为它们带有构建机路径；解包时用构建自身的命令重建 venv，并在本机封存
获取不带参数的 openprogram upgrade 解析最新 release，在内存中校验 manifest、签名和校验和，再把本平台文件下载到 <runtime>/downloads/<release>，每个文件都按签名中的大小和哈希检查，下次运行时续传。--from <directory> 应用已经在本机的文件
校验解析清单前验签名，用清单验校验和，用校验和验本平台用到的资源。bundle 只把 refs/heads/release 向前移动，较旧的已签名 release 不能替换较新的。没有可信公钥的构建不接受任何 release
重放所有者的提交是 release..local，有压缩过的官方线就够。从旧到新在 work/official-<release> 里 cherry-pick。冲突的提交存到 unreplayable/<release>/，其余继续。release 已包含的提交跳过。候选基于 release 自身的版本构建，没动过的 Web 包直接克隆
失败构建或试运行失败时保存最新的提交并尝试其余的，最多重试 5 次，然后直接试未修改的 release。磁盘不足不丢弃提交。切换失败不重试。需要已安装外壳范围之外的 shell_compat 或 Python 小版本的 release 会等外壳更新，什么都不移动
