Developer ID distribution

From checkout to release

  1. A reviewed checkout builds an unsigned staging App: electron-builder --mac --dir, with identity: null.
  2. sign-macos-release.py signs Mach-O files and nested bundles inside out with one Developer ID, with hardened runtime and secure timestamp. Mach-O files inside packed .tar.gz and .zip resources are signed too.
  3. codesign --verify --deep --strict checks the whole signature.
  4. notarytool notarizes the App. stapler staples it. spctl --assess accepts it.
  5. ZIP and DMG are created. The DMG is signed, notarized and stapled.
  6. Packaged-runtime smoke, checksums, upload.

Any failed command aborts the release. The signer never disables Gatekeeper or changes certificate trust, and refuses to sign /Applications/OpenProgram.app.

Acceptance

  • The updater selects a signed DMG and validates its manifest digest.
  • Both architecture builds pass the packaged-runtime smoke tests.
  • Published size and SHA-256 match the release manifest.
