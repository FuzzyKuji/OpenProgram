Stable release automatic updates

An update is a complete stable GitHub Release verified against its manifest. New commits are not updates. The update unit is the whole product: wheel, Web, Programs, OCR, Browser and models are never updated separately. The macOS App and terminal installs take a whole package; Windows and Linux Apps take a signed sealed version.

Scheduling

Automatic checks only discover. Manual checks always refresh. Development mode does not check automatically.

update-state.json

Schema 1. Holds automaticChecks, lastAttemptAt, lastSuccessAt and the latest verified release metadata. Written with a temporary file and rename; POSIX sets the mode, Windows inherits the user-directory ACL.

Invalid JSON, unknown schemas, future timestamps, version or architecture mismatches and missing releases are normalized and rewritten. A write failure must not leave hidden in-memory setting changes.

Trust boundaries

BoundaryRule
GitHub responsesUntrusted. HTTPS, fixed hosts, at most 5 redirects validated per hop, size limit, 30 s request timeout, 60 s download idle timeout. Requires draft === false, prerelease === false, tag vX.Y.Z, unique asset names and manifest basenames, GitHub size equal to manifest bytes.
Network pathChromium's network stack, so the system proxy applies. On API 403, 429, 5xx or no answer: the releases/latest redirect plus release-manifest.json. If that fails too, an optional update-source.json, only with an Ed25519 signature from a built-in key
Renderer IPCExposes only state, check, boolean settings, download, open release, subscribe. Accepts no URL, path, hash, repository or command. Public state strips asset name, URL and SHA-256. Closing a window aborts nothing
Downloaded filesRandom exclusive temporary files, short writes handled, deleted on any mismatch. CLI verifies in a new version directory and rejects archive path traversal. A launcher failure keeps the old current
Installer child processPinned repository and version. Allowed environment only: PATH, HOME, temp, locale, proxy, XDG, OpenProgram state. No provider or API credentials, no archive or checksum overrides. --json emits one JSON document

Failures

What happenedResult
Offline, timeout, rate limitFalls back to the web route first. Automatic: record and back off 6 h. Manual: retryable error with a plain reason. The App keeps running
Invalid Release or manifestRejected before download. No fallback to a wheel, source archive, other architecture or older version. The last valid metadata may stay
Stall, size, hash or Windows signature errorA dropped download retries and resumes through its .part file, across restarts. A size, hash or signature mismatch deletes the file and restores retry. An unverified file is never opened
CLI archive, cold start or launcher failureNon-zero exit before the final switch. The previous version stays selected (current on macOS and Linux, launchers on Windows)
Switch done, worker still oldThe command says so and prints the restart instruction. Running requests are not interrupted

Official updates on a version store

An installation on the version store updates from signed release assets and replays the owner's own commits onto the release.

PartRule
AssetsEvery release publishes version-<platform>.tar.zst, base-<platform>.tar.zst, toolchain-<platform>.tar.zst, repo.bundle, SHA256SUMS and update-manifest.json with its Ed25519 signature, so a machine that skipped releases can still update. A client downloads only what it lacks: a base it already holds is skipped, and the toolchain is fetched only for owner commits to build. The version archive leaves out the venv's links and the seal, because they name the build machine; unpacking recreates the venv with the build's own command and seals the version here
FetchBare openprogram upgrade resolves the latest release, verifies manifest, signature and sums in memory, then downloads this platform's files to <runtime>/downloads/<release>, each held to its signed size and hash, resuming on the next run. --from <directory> applies files already on the computer
VerificationSignature before the manifest is parsed, sums against the manifest, each asset this platform uses against the sums. The bundle moves refs/heads/release forward only, so an older signed release cannot replace a newer one. A build with no trusted key accepts no release
ReplayThe owner's commits are release..local, so the squashed official line is enough. Oldest first, each is cherry-picked in work/official-<release>. A conflict is saved to unreplayable/<release>/ and the others continue. A commit the release already has is skipped. The candidate builds on the release's own version, so an untouched Web bundle is cloned
FailureA build or trial failure saves the newest commit and tries the rest, at most 5 retries before going straight to the unmodified release. Lack of disk drops nothing. A failed switch does not retry. A release needing a shell_compat or Python minor outside the installed shell waits for the shell update and moves nothing
