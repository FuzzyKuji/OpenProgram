Developer ID 分发

从检出到发布

  1. 经过审查的检出构建未签名的暂存 App：electron-builder --mac --dir，identity: null。
  2. sign-macos-release.py 用同一个 Developer ID 由内向外签 Mach-O 文件和嵌套 bundle，开启 hardened runtime 和安全时间戳。打包在 .tar.gz、.zip 资源里的 Mach-O 也会签。
  3. codesign --verify --deep --strict 校验完整签名。
  4. notarytool 公证 App，stapler 装订票据，spctl --assess 接受。
  5. 生成 ZIP 和 DMG；DMG 再签名、公证、装订。
  6. 打包运行时冒烟、校验和、上传。

任何一条命令失败都中止发布。签名脚本不关闭 Gatekeeper，不改证书信任，也拒绝签 /Applications/OpenProgram.app。

项规则
产物OpenProgram-<version>-mac-<arch>.dmg 和 .zip，架构 arm64 或 x64
更新器优先选带签名的文件名；旧发行版仍选 -unsigned.dmg
公证等待45 分钟。超时不会取消提交：脚本读取状态，只有 Accepted 才继续
本地签名专用钥匙串和已校验的 notarytool 配置
CI 签名退出时删除的临时钥匙串。Secrets：MAC_CSC_LINK、MAC_CSC_KEY_PASSWORD、APPLE_ID、APPLE_APP_SPECIFIC_PASSWORD、APPLE_TEAM_ID；变量 MAC_SIGNING_IDENTITY
缺凭据不产生正式产物
构建输出中只有公开的证书身份。密钥和凭据不进仓库
本地源码构建单独的开发身份。源码更新不得悄悄用它替换已安装的正式身份
薄 App 的 helper第二个签名 bundle，Contents/Resources/seed/helper/OpenProgram.app，标识符 ai.openprogram.runtime。它关闭库验证，因为 libpython 在 bundle 之外（entitlements.mac.helper.plist）；用 entitlements.mac.inherit.plist 签名的二进制也关闭，因为在用户机器上编译的包只有 ad-hoc 签名。隐私授权绑定它唯一的路径和签名，切换版本不影响授权。base 里的二进制在打包 seed 之前签名一次
WindowsAuthenticode，另行处理：Windows 支持

验收

  • 更新器选中已签名 DMG，并校验清单摘要。
  • 两种架构的构建都通过打包运行时冒烟。
  • 发布文件的大小和 SHA-256 与发布清单一致。
