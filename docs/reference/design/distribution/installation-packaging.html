Installation, packaging, release and upgrade

Official releases: v1.2.0 is the version this tree builds; v1.1.0 is the latest published. One complete product runtime per platform and architecture. The macOS App adds only the Electron shell to it and the CLI only launchers; Windows and Linux Apps are a thin shell plus a seed. Checks, downloads and platform handoff are in Automatic updates.

One version, one artifact set

A platform leg that fails leaves its files out and is named under "Not in this release"; publication stops only when the wheel or every macOS and Linux runtime is missing. Thin Apps need a trusted update signing key, because without one they could never update.

A leg whose artifact holds no installer or archive counts as failed and publishes nothing. When a planned package, a platform's update files or an installer's checksum file is missing, the publish job turns red after the release is public and names each one. Release workflow rules
  • Tag push v*, or manual dispatch of an existing tag; every checkout stays pinned to it.
  • Runtime archives first; Desktop and CLI installer jobs download the same-named archive.
  • Signing runs when its secrets exist. macOS: Apple secrets (Developer ID). Windows: WINDOWS_CSC_LINK, WINDOWS_CSC_KEY_PASSWORD. Without them macOS gets an ad-hoc signature, Windows must verify as NotSigned, and both take -unsigned names. No PyPI credentials.
  • Release uses the short-lived repository token. No Keychain, keyring or Credential Manager integration.
  • Notes come from .github/release-notes/vX.Y.Z.md, must be English (CJK rejected), lead with user-visible changes, and include a download table. Doc-only corrections update notes without moving the tag.
  • A public release is never overwritten; only a draft may be finished. The public latest entry is checked afterwards.
  • smoke-packaged-runtime.sh runs on system Bash 3.2; the deferred-browser flag is explicit, normal validation runs the complete browser check.

Desktop bundle

OpenProgram.app/Contents/
├── MacOS/OpenProgram         # Electron launcher
├── Frameworks/               # Electron Framework and helpers
└── Resources/
    ├── app.asar              # Electron main, preload
    └── runtime/
        ├── python/           # portable CPython + dependencies
        ├── bin/uv
        ├── wheel/            # build evidence
        ├── assets/playwright/
        └── runtime-manifest.json

CPython comes from python-build-standalone indexed by the pinned uv, never the build machine. The runtime manifest (schema 2) records OpenProgram, Python, uv, capability results, asset paths and the product manifest hash.

  1. Electron reads the in-App runtime manifest and verifies capabilities and required files.
  2. It starts the in-App Python worker by absolute path, with -I -B, ignoring PYTHONPATH, user site and system configuration.
  3. The launcher sets the bundled Playwright path.
  4. The worker reports status and capability hash at /healthz.
  5. Electron gets the authenticated URL from bundled Python and loads Web UI. A failure shows category, log location and repair action.
Prohibited at runtime
  • PATH lookups of openprogram, python, node, git.
  • The App or updater rewriting its own bundle. An AppImage update replaces the file beside it after verification.
  • First-use downloads of Python, Web, Browser, OCR or detector weights.
  • Reading apps/web/out, Program checkouts or development configuration from the repository.
  • npm build, pip resolution or git clone on user machines.
Icons
  • apps/desktop/build/AppIcon.icon is the Apple layered source: SVG layers on a 1024×1024 unmasked canvas, no pre-drawn frame.
  • icon.icns is the committed Electron input, keeping the accepted extent, contour, transparent corners and shadow.
  • The lavender cell and three discs stay centred, with no text or rasters. actool is unavailable on the build machine, so .icon is not compiled.
  • Gates cover layer structure, ICNS representations, 256 px contour, corners and round trip. Dock, Finder and Launchpad are checked only on the installed App.
Windows package
  • Per-user NSIS, selectable directory, asInvoker. Thin: the shell and a seed; x64 by default.
  • With a certificate, OpenProgram.exe and the installer must be Authenticode Valid. Without one both must be NotSigned and the installer takes the -unsigned.exe name.
  • Terminal uses Windows PowerShell and ConPTY. Chrome, Edge, Brave and Chromium profiles are discovered under normal paths. No ACL changes.
Linux package
  • executableName openprogram-desktop, installed under /opt/OpenProgram. The deb lists its libraries, including the t64 alternatives, and recommends bubblewrap; its desktop entry has a Recovery action.
  • electron-builder's deb post-install adds an AppArmor profile on systems that support it, so the Chromium sandbox works on Ubuntu 24.04; an AppImage has no such step.
  • Built on Ubuntu 22.04. Bundled Git needs glibc 2.34; the supported floor stays Ubuntu 22.04 (glibc 2.35).
  • An AppImage records $APPIMAGE so every relaunch and update uses the same file.

Programs

~/.openprogram/programs/
├── src/<program-id>/
├── manifests/<program-id>.json
└── environments/<runtime-id>/
    ├── releases/<generation>/
    └── current -> releases/<generation>

runtime-id covers at least CPython minor, architecture and dependency lock; Desktop and CLI on one platform share it. Install, upgrade and remove are one transaction:

  1. Resolve source and declarations into a temporary directory.
  2. Create a staging environment with in-App uv and CPython.
  3. Install dependencies from all enabled manifests; record exact versions and hashes.
  4. Import probes, registration checks, worker cold start.
  5. Atomically switch current. Failure deletes staging.

Programs fall outside release integrity, use separate environments, never overwrite openprogram, and are never installed by a wizard.

Local fixed App

The only stable local App is /Applications/OpenProgram.app, with a sibling development App (see dev instance). No App name carries a version, commit or task. Build Apps are never launched or kept.

Full install: npm --prefix apps/desktop run dist
  • Builds in a random temporary directory; validates bundle ID, version, main executable, embedded runtime.
  • Rejects a candidate older than the current App before touching App, worker or Launch Services. Version segments compare as arbitrary-precision integers; an unverifiable existing App fails, it is kept.
  • A user-level lock plus an atomic lock in Applications: concurrent runs fail before any change, and cleanup removes only locks held by this PID.
  • Unloads a launchd KeepAlive service, stops the lock-holding worker, staging on the Applications volume, then moves the old App into the transaction directory and activates the new one.
  • Reinstalls the service with the new embedded Python and -I -B; waits for /healthz; opens the App. Service arguments must not retain conda, checkout or deleted-App paths.
  • Failure restores old App, launchd service and run state. Success removes old App, wheel cache, staging, build and transaction directories.
  • Registers only the fixed path with Launch Services; on restore, best-effort re-registers and keeps the original failure status.
  • electron-builder ad-hoc signs components; a fixed local certificate signs the App and helpers; strict recursive verification follows.
Local App refresh: scripts/refresh-local-app.sh
  • Installs only refs/heads/stable. Without a stable branch, the checkout must contain local main and fetched origin/main.
  • Paths are resolved first, so slashes, dot components and symlink aliases share checks and lock. A genuinely custom App keeps its own source check.
  • Tracked, staged or non-ignored untracked changes refuse, before packaging, after it, and under the lock. HEAD changes during packaging rebuild; after the payload is frozen they abort.
  • Checkout, bundle, runtime manifest and bundled Python metadata must have one version, except that the source may be newer than the installed App, whose Electron and bundle metadata are then upgraded. A downgrade is refused.
  • Synchronizes main, preload, updater and runtime dependencies; never an app.asar over old modules. Rechecks source, wheel and App under the shared lock.
  • Extraction loses execute bits on unpacked node-pty files, so staging restores installed modes and forces spawn-helper executable. Symlinks are not followed.
  • Starts the embedded worker once; polls :18100/healthz for up to 120 s, with no repeat starts. Timeout reports endpoint and log.
  • After signature verification, reopens the App once even on failure, keeping the primary status; failures before that launch nothing. Cleanup errors never report success.

Thin signed shell

A thin App is the shell alone, in apps/desktop/shell/, plus a seed under Resources/seed. Windows and Linux Apps are thin. The macOS App stays embedded unless OPENPROGRAM_RELEASE_MAC_THIN is on.

First start

  1. Write .seeding, unpack with progress.
  2. Run install_seed.py with the base's Python: rename the build root in the version, rewrite the seal's file table, install the identity and tools, create repo/, write the pointer.
  3. Remove .seeding last, so an interrupted install starts over.

Acceptance

Runtime and macOS
  • Native runners, pinned commit and lock. --version, cold start, /healthz, /chat, hashed Web assets. Import and asset probes; excluded distributions absent.
  • DMG on clean arm64 and x64 with system Git only. Offline first start, worker, Web and Chromium probes. Python path and capability hash from the embedded runtime.
  • Two consecutive builds leave only the one App. Concurrent installers: one enters. A corrupt candidate or failed activation keeps the old App.
  • Bundle, runtime manifest, --version and Python metadata agree.
Windows, CLI, release
  • Windows: same ZIP as the CLI; manifest, Python, worker health and Web chat from the unpacked App; ConPTY presets; browser paths. Updater takes only the exact EXE. Before packaging, the tests in scripts/release/windows-contracts.txt; after it, smoke-windows-desktop.ps1 installs, launches to a healthy worker, makes one tool call and uninstalls keeping the data. The installed CLI also makes one tool call (smoke-tool-call.py).
  • CLI: both bootstraps with latest and pinned versions; no PyPI or clone; hashes match; old version starts after a failed upgrade.
  • Release: one version everywhere; every published asset passed its own leg; a build with no publisher signature carries -unsigned in its name.
  • Linux Desktop: scripts/release/smoke-linux-desktop.sh under Xvfb on clean Ubuntu 22.04 and 24.04 with Git removed: deb install, desktop entry, node-pty, first-run seed, restart after unpacking, worker health, /chat, the launcher, and the AppImage with APPIMAGE_EXTRACT_AND_RUN=1.
  • Docs, indexes and runtime errors contain no pip install openprogram or component-install steps.
