Publishing source to GitHub

GitHub carries main and nothing else. Its history never merges with the other lines, and nothing pulls GitHub's main back.

Branches

Locally there are exactly these three. A worktree branch is merged into dev and deleted, or deleted when abandoned. One worth keeping goes under refs/archive/, which no command lists as a branch and nothing pushes.

--no-pushStop after step 5
--tag vX.Y.ZStep 7; cannot be combined with --no-push
  1. Install the guards into the shared .git/hooks, so every worktree has them.
  2. Refuse a source not on dev. When main already holds the source's tree there is no new version; go to step 7.
  3. Scan added lines for live-looking credentials (GitHub tokens, Anthropic API keys, AWS access keys, private key blocks) and refuse on a hit. AWS's documented example key and one-line PEM strings in tests do not count.
  4. Refuse if scripts.docs_site.check --all fails on the source commit, read from a temporary checkout of it.
  5. Write the message: the summary, the number of local commits since the previous version, and a Local-Source: trailer.
  6. Create the commit with git commit-tree: the source's tree, the previous main as only parent (none for the first version). Move main and record the source in refs/publish/last, where the next version starts counting.
  7. Push main after checking GitHub's main is an earlier point of local main, so the push only fast-forwards.
  8. --tag vX.Y.Z also labels that commit on GitHub, which triggers Release. Before anything moves it refuses a tag that already exists, one that differs from the version in pyproject.toml or apps/desktop/package.json, and a source without .github/release-notes/vX.Y.Z.md starting with # OpenProgram X.Y.Z Release Notes. --dry-run runs these checks and shows the tag.

What a release builds

The Release workflow runs on the pushed tag. Every platform leg is independent.

A tag never moves, so a release can be rehearsed first. Publish main without --tag, then run gh workflow run release.yml -f tag=vX.Y.Z -f rehearse=true: every leg builds from main, the same checks run and nothing is published.

gh workflow run windows-install-smoke.yml -f tag=vX.Y.Z -f run_id=<rehearsal run> installs that run's Windows files on a Windows runner. When both pass, scripts/publish-github.sh --source refs/publish/last --tag vX.Y.Z tags the same commit; without --source, a promotion made in between would become a new, unrehearsed version.

The machine's global hooks (core.hooksPath) delegate both to the repository's .git/hooks, which is why the script installs them there.
