产品里有什么

部分规则
包含固定的 CPython（3.12.10）、固定的 uv（0.11.16）、固定的 Git、OpenProgram、预构建 Web、带 Node.js 的独立 Ink 包。能力列在 scripts/release/product-runtime.json：web providers mcp memory channels search tui.ink browser.playwright

一个版本，一组产物

pyproject.toml 是版本来源，Electron 元数据保留副本。标签、运行时清单、发布清单和健康端点必须与之相等，标签必须指向被构建的提交。标签不可变，修复用更高的补丁版本。

产物平台

不带版本号的 App 副本OpenProgram-<os>-<arch>.<ext>，供 releases/latest/download 链接使用。不进 manifest

开发者wheel 和 sdist，不是用户入口

arm64 和 x64 分开构建，没有 universal2。失败的平台任务不产出文件，并列在 "Not in this release" 下；只有 wheel 或全部 macOS 和 Linux 运行时缺失时才停止发布。薄壳 App 需要受信任的更新签名密钥，否则永远无法更新。

产物里没有安装包或归档的平台任务按失败处理，什么都不发布。计划内的包、某个平台的更新文件或安装包的校验文件缺失时，publish 任务在发行版公开之后变红，并逐个列出。开关或缺少密钥而略去的不算。

发布工作流规则
  • 推送标签 v*，或手动重跑已有标签；每个检出都固定在该标签。
  • 先构建运行时归档；Desktop 和 CLI 安装器任务下载同名归档。
  • 有对应 Secret 时才签名。macOS：Apple Secret（Developer ID）。Windows：WINDOWS_CSC_LINK、WINDOWS_CSC_KEY_PASSWORD。没有时 macOS 用 ad-hoc 签名，Windows 必须验证为 NotSigned，两者都使用 -unsigned 文件名。不需要 PyPI 凭据。
  • Release 用仓库提供的短期令牌。不集成 Keychain、keyring 或凭据管理器。
  • 说明来自 .github/release-notes/vX.Y.Z.md，必须是英文（拒绝中日韩字符），先写用户可见的变化并带下载表。只改文档的修正更新说明，不移动标签。
  • 公开发行版绝不覆盖，只能完成草稿。之后检查公开的 latest 入口。
  • smoke-packaged-runtime.sh 支持系统 Bash 3.2；延后浏览器的标志必须显式传入，正常验证运行完整浏览器检查。

版本默认最新稳定版，除非设置了 OPENPROGRAM_VERSION；只接受三段数字版本

安装做法

CPython 来自固定 uv 索引的 python-build-standalone，绝不取自构建机。运行时清单（schema 2）记录 OpenProgram、Python、uv、能力结果、资产路径和产品清单哈希。

  1. Electron 读取包内运行时清单，校验能力和必需文件。
  2. 按绝对路径启动包内 Python worker，带 -I -B，忽略 PYTHONPATH、用户 site 和系统配置。
  3. 启动器设置内置 Playwright 路径。
  4. worker 在 /healthz 报告状态和能力哈希。
  5. Electron 从内置 Python 取认证 URL 并加载 Web UI。失败时显示类别、日志位置和修复动作。
运行时禁止
  • 从 PATH 查找 openprogram、python、node、git。
  • App 或更新器改写自身 bundle。AppImage 更新在校验后替换它旁边的文件。
  • 首次使用时下载 Python、Web、Browser、OCR 或检测器权重。
  • 从仓库读取 apps/web/out、Program 检出或开发配置。
  • 在用户机器上运行 npm build、pip 依赖解析或 git clone。
图标
  • apps/desktop/build/AppIcon.icon 是 Apple 分层源：1024×1024 无遮罩画布上的 SVG 图层，不预画系统外框。
  • icon.icns 是提交在库的 Electron 输入，保留已验收的可见范围、轮廓、透明角和阴影。
  • 淡紫色单元和三个圆片居中，没有文字或位图。构建机没有 actool，所以不编译 .icon。
  • 关卡检查图层结构、ICNS 尺寸、256 px 轮廓、透明角和往返。Dock、Finder、Launchpad 只在已安装的 App 上检查。
Windows 包
  • 按用户 NSIS，可选目录，asInvoker。薄壳：外壳加 seed；默认 x64。
  • 有证书时，OpenProgram.exe 和安装包必须 Authenticode Valid。没有证书时两者必须 NotSigned，安装包使用 -unsigned.exe 文件名。
  • 终端用 Windows PowerShell 和 ConPTY。在常规路径发现 Chrome、Edge、Brave 和 Chromium 配置。不改 ACL。
Linux 安装包
  • executableName 是 openprogram-desktop，安装到 /opt/OpenProgram。deb 列出依赖库，包括 t64 备选，并推荐 bubblewrap；其桌面项带 Recovery 动作。
  • electron-builder 的 deb post-install 会在支持的系统上添加 AppArmor 规则，使 Chromium 沙箱能在 Ubuntu 24.04 上工作；AppImage 没有这一步。
  • 在 Ubuntu 22.04 上构建。内置 Git 需要 glibc 2.34；支持下限仍是 Ubuntu 22.04（glibc 2.35）。
  • AppImage 记录 $APPIMAGE，每次重新启动和更新都使用同一个文件。

Program

runtime-id 至少包含 CPython 次版本、架构和依赖锁；同一平台的 Desktop 和 CLI 共用。安装、升级、移除是同一事务：

  1. 解析来源和声明，写入临时目录。
  2. 用包内 uv 和 CPython 创建暂存环境。
  3. 按所有已启用清单安装依赖，记录确切版本和哈希。
  4. 导入探测、注册检查、worker 冷启动。
  5. 原子切换 current。失败删除暂存。

Program 不在发行版完整性范围内，使用独立环境，绝不覆盖 openprogram，也不由向导安装。

发生了什么结果
运行时文件或清单不符不启动 worker，给出重装说明
缺能力或资产阻止整个平台产物；没有缩减安装
旧检出或旧 App 覆盖当前 App在构建、停服务或写入前失败
旧的未签名 macOS 文件按文件名手动批准并核对 SHA-256
系统注入 Python 路径隔离启动时忽略
Program 依赖覆盖核心包拒绝激活环境
新运行时探测失败current 不变；不发布 Desktop 产物
版本不一致阻止构建或发布

本地固定 App

稳定版本地 App 只有 /Applications/OpenProgram.app，旁边是开发版 App（见开发实例）。App 名不含版本、提交或任务。构建中的 App 既不启动也不保留。

完整安装：npm --prefix apps/desktop run dist
  • 在随机临时目录构建；校验 bundle ID、版本、主程序、内嵌运行时。
  • 候选版本低于当前 App 时，在动 App、worker 或 Launch Services 之前拒绝。版本段按任意精度整数比较；现有 App 无法校验时失败并保留。
  • 用户级锁加 Applications 里的原子锁：并发运行在任何变更前失败，清理只删当前 PID 持有的锁。
  • 卸载 launchd KeepAlive 服务，停掉持锁 worker，先在 Applications 卷上暂存，再把旧 App 移入事务目录并激活新 App。
  • 用新的内嵌 Python 和 -I -B 重装服务，等待 /healthz，打开 App。服务参数不得残留 conda、检出或已删 App 的路径。
  • 失败恢复旧 App、launchd 服务和运行状态。成功后删除旧 App、wheel 缓存、暂存、构建和事务目录。
  • 只向 Launch Services 注册固定路径；恢复时尽力重新注册，并保留原失败状态。
  • electron-builder ad-hoc 签组件；固定本地证书签 App 和 helper；随后严格递归校验。
本地 App 刷新：scripts/refresh-local-app.sh
  • 只安装 refs/heads/stable。没有 stable 分支时，检出必须包含本地 main 和已拉取的 origin/main。
  • 先解析路径，斜杠、点路径和符号链接别名共用检查和锁。真正的自定义 App 保留自己的源码检查。
  • 已跟踪修改、已暂存改动或未忽略的新文件，在打包前、打包后和持锁时都会拒绝。打包期间 HEAD 变化则重建；载荷冻结后变化则中止。
  • 检出、bundle、运行时清单和内置 Python 元数据版本必须相同，只有源码可以比已安装 App 新，此时同时升级其 Electron 和 bundle 元数据。降级被拒绝。
  • 同步 main、preload、更新器和运行时依赖，不生成覆盖旧模块的 app.asar。在共用锁内复查源码、wheel 和 App。
  • 解压会丢失未打包 node-pty 文件的执行位，暂存时恢复已安装的权限，并强制 spawn-helper 可执行。不跟随符号链接。
  • 只启动一次内嵌 worker；轮询 :18100/healthz 最多 120 秒，不重复启动。超时报告端点和日志。
  • 签名校验通过后，即使失败也重开一次 App，并保留主要状态；此前失败则不启动。清理错误绝不报告成功。

签名薄壳

薄壳 App 只有 apps/desktop/shell/ 里的外壳，加上 Resources/seed 下的 seed。Windows 和 Linux App 是薄壳。macOS App 保持内嵌，除非打开 OPENPROGRAM_RELEASE_MAC_THIN。

模式启动时的依据
开发者<root>/developer.json
内嵌Resources/instance.json、Resources/runtime 或未打包的 App。原来的路径，没有变化
托管其余情况：壳读取 current，通过 start(context) 加载对应封存版本的 desktop/main.js

首次启动

  1. 写 .seeding，带进度解包。
  2. 用 base 的 Python 运行 install_seed.py：替换版本里的构建根路径，重写封存文件表，安装身份和工具，创建 repo/，写指针。
  3. 最后删除 .seeding，中断的安装会从头开始。
项目行为
seedbase.tar.zst、version.tar.zst、repo.bundle、launcher（macOS 上是签名的 helper bundle，隐私授权绑定的唯一身份）、shell-compat.json、只用标准库的 bootstrap/ 工具。命令行安装脚本用同一份 seed 的 .tar.gz 形式，scripts/release/build-release-seed.sh 构建两种形式
启动计数worker 经 launcher 启动，守护计数覆盖每一次启动；短促的认证命令用版本自己的 Python，不计数
桌面加载失败按壳版本记入 boot/<id>.desktop-failed，App 重新启动并回退。成功写 boot/<id>.desktop-ready
恢复页没有版本能加载；fallback 上 /healthz 失败 120 秒；App 菜单（Windows 和 Linux 上是 File）；macOS 和 Windows 启动时按住 Shift；Linux 上用 --recovery 和 deb 启动器动作
Gitbase 在 macOS、Windows 和 Linux 上带固定版本的 Git，排在 PATH 最前
外壳变化外壳版本变化时，刷新 shell-compat、Python 次版本和启动器；被占用的 Windows 启动器先改名移开
运行中的 workerworker 版本与 App 不同时重启，每次启动最多一次
macOS 位置从磁盘映像或下载文件夹打开的 App 会提示移到 Applications；共享文件夹不可写时移到 ~/Applications

验收

运行时和 macOS
  • 原生 runner、固定提交和锁。--version、冷启动、/healthz、/chat、带哈希的 Web 资产。导入和资产探测；排除的发行包不存在。
  • 在只有系统 Git 的干净 arm64 和 x64 上验收 DMG。离线完成首次启动、worker、Web 和 Chromium 探测。Python 路径和能力哈希来自内嵌运行时。
  • 连续两次构建后只有一个 App。并发安装只有一个进入。损坏的候选或激活失败保留旧 App。
  • bundle、运行时清单、--version 和 Python 元数据一致。
Windows、CLI、发布
  • Windows：与 CLI 相同的 ZIP；从解包的 App 校验清单、Python、worker 健康和 Web chat；ConPTY 预设；浏览器路径。更新器只选确切的 EXE。打包前运行 scripts/release/windows-contracts.txt 列出的测试；打包后 smoke-windows-desktop.ps1 安装、启动到 worker 健康、做一次工具调用，再卸载并保留数据。安装好的 CLI 也做一次工具调用（smoke-tool-call.py）。
  • CLI：两种引导脚本的最新版和固定版；不访问 PyPI 或克隆；哈希一致；升级失败后旧版本仍能启动。
  • Release：所有位置同一版本；每个发布资产都通过了各自的任务；没有发布者签名的构建在文件名中带 -unsigned。
  • Linux 桌面：在干净的 Ubuntu 22.04 和 24.04 上、移除 Git 后，用 Xvfb 运行 scripts/release/smoke-linux-desktop.sh：deb 安装、桌面项、node-pty、首次运行 seed、解包后重启、worker 健康、/chat、启动器，以及 APPIMAGE_EXTRACT_AND_RUN=1 的 AppImage。
  • 文档、索引和运行时错误里没有 pip install openprogram 或组件安装步骤。
