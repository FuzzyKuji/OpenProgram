工程规则

  • 平台行为放在 openprogram/host/_platform/（文件系统、锁、进程、进程归属、命令 Shell、终端、环境）或它选择的适配器里。
  • 优先能力检测。不支持的功能在入口失败，不在后期抛 NotImplementedError。
  • 对 POSIX 安全属性的弱化替代必须是明确记录的决定。
  • Windows CI 契约覆盖之前，修复不算完成。
  • POSIX 0600、0700 不是 Windows 要求：保留配置文件继承的 ACL，任何步骤都不移除继承或改写条目。原子替换和跨进程锁仍然必需。

W1：原生 CLI 和服务端

领域行为
源码安装器检出内 .venv、npm 锁文件、Web 和 Ink 构建、所选 extras、用户 PATH 上的 openprogram.cmd。-Minimal：只装 Python CLI 和服务端
启动器只有一个 openprogram.cmd：PowerShell 优先选同名 .ps1，而默认的 Restricted 策略会拒绝它，所以安装器会删除旧文件。PowerShell 脚本：带 BOM 的 UTF-8。批处理：不带 BOM 的 UTF-8，带 ASCII 代码页前导，关闭延迟展开，转义百分号，恢复调用方代码页，保留退出状态。安装器只对自身进程使用 powershell.exe -ExecutionPolicy Bypass -File；不改机器的执行策略或区域设置
Ink各系统都按能力判断。Windows Terminal 和 ConPTY 全屏运行；MinTTY 等恢复 stdio 后回退 Rich。分词器把控制字节和可打印片段分开；括号粘贴保持一个事件
MCP 令牌唯一临时文件加原子硬链接。读取时重新校验文件和祖先目录
进程PowerShell CIM，不用 WMIC。存活和创建时间来自只读原生查询；绝不用信号 0。信号到不了另一个进程，所以 worker stop 把 worker 的 PID 写进 worker.stop，worker 轮询到后按顺序关停；五秒没有回应就结束整棵进程树。--print 对 Ctrl-Break 和对 Ctrl-C 一样处理。那里阻塞的等待不会被信号唤醒，所以运行按最多半秒一次轮询等待，读 Worker 连接也一样
登录时启动 worker最小权限的按用户计划任务，每个 profile 一个，运行失败后重试。启动脚本自己设置 profile 和状态目录，因为任务不继承安装时那个 shell 的环境。装上后 worker 归它管：start 和 restart 按当前运行时重写启动脚本并启动任务；stop 先请求 worker 关停，再结束任务的这次运行，重试就不会把它带回来
文件日志共用跨进程锁。应用和回滚用不同的 guard 文件
文本与字节文本打开都写明 UTF-8，仓库契约计数的六处除外；openprogram/state 下每个文本模式的子进程也是。应用环境的 .pth 文件按区域编码写入，Python 的 site 模块在每个受支持的版本上都读这种编码。用 os.write 写入的描述符是二进制的，所以行尾是 LF，字节偏移保持准确
UTF-8 模式每个 launcher 和安装器都用 -X utf8 启动 Python：openprogram-launcher.exe、每个 openprogram.cmd、seed 安装器、命令行安装器的校验脚本，以及从这样的 Python 重启的 Worker。发布工作流不设 PYTHONUTF8。-I 会丢掉 PYTHONUTF8，所以模式作为参数传递。.pth 文件在这个模式下仍用区域编码。netstat、schtasks 和任务服务用的 PowerShell 按 OEM 代码页输出，所以它们的输出按字节读取，再用这个代码页解码
状态文件替换filesystem.replace_file 发布每个先写临时文件再重命名的文件：配置、凭据、定时任务、Agent 注册表、项目、检查点、更新记录。目标被另一个句柄、索引器或杀毒扫描占用时，它重试一秒。不加锁的配置读取以同样方式重试。有七处重命名保持直接调用，仓库契约逐一写明原因
对话文件夹重命名文件夹里有文件开着时，Windows 拒绝重命名这个文件夹。move_session_folder 重试一秒，然后抛出 SessionFolderBusy，文件夹留在原处。不会改用复制。见被占用的对话文件夹
影子仓库每条 Git 命令固定自己的设置：不转换行尾、文件名不加引号转义、开启长路径、不做提交签名。用户的 Git 配置影响不到它。恢复出的文件就是提交时的字节
检查点、备份、恢复没有基于描述符的操作时走路径回退：拒绝符号链接和联接点，重新校验父目录，二进制原子写
工作区审查分批读取 Git 元数据和对象；Git 调用次数不随变更文件增长
Shell 工具装了 Git Bash 就用它，否则先用 PowerShell 7，再用 Windows PowerShell；绝不用 cmd.exe。由一个函数决定：见命令 shell。系统提示写明正在用的那个和它的语法，不取 COMSPEC；沙箱开着时写的是 WSL 的 bash 和 Linux 路径，本机 shell 只用于获准离开沙箱的命令。每条命令是一个 Job Object，停止会结束整棵进程树。无窗口进程。Git Bash 的源码经临时环境变量传递；Python 子进程默认 UTF-8
PowerShell 命令UTF-16 源码放在一个 base64 参数里，不经过任何引号层。不加载 profile、非交互、文本输出，执行策略只对这个进程设为 Bypass：npm、pnpm 会解析到 .ps1 垫片，默认策略拒绝运行它；组策略仍然优先。输入、输出和管道都是 UTF-8；关闭进度记录。最后一个程序的退出码原样传出，PowerShell 自己只报 0 或 1
钩子config.json 里的钩子和命令工具用同一个 shell，不用 cmd.exe；事件以 UTF-8 从标准输入送入，不弹控制台窗口。程序以 2 退出仍然算拒绝
权限规则里的路径规则和调用按同一个解析后的名字比较：正反斜杠都行，去掉 \\?\ 和 \\.\ 前缀，短文件名展开，去掉结尾的点、空格和 ::$DATA。拒绝和询问规则不分大小写，覆盖文件的命名流，并按对话的工作目录解析相对路径；允许规则按完整路径和磁盘上保存的大小写比较。网络共享写成全程反斜杠的 \\server\share 或 //server/share；拒绝和询问规则也覆盖混用斜杠的写法
允许规则里的命令规则按 POSIX shell 读命令。命令可能在 PowerShell 里运行时，含 {、} 或 , 的命令不会被前缀或通配的允许规则放行，因为这些符号在 PowerShell 里的含义这种读法看不到。对这样的命令选“始终允许”，存下的是命令原文，只放行一字不差的同一条命令。拒绝和询问规则照常命中
SSH 环境Windows 的 OpenSSH 客户端不支持连接复用，每次调用各开一条连接。远端文本按 UTF-8 读取；客户端不弹控制台窗口
复制进工作树的链接.worktreeinclude 点名的链接指向目录时，重建为目录链接。没有创建链接的权限时，这个文件记为未复制
Program 发现直接查元数据，不为每次连接重建完整的导入到发行包映射
会话存储关闭取消定时器，在锁外等待进行中的写入，刷出最新快照。失败的写入保持脏状态。没有线程时同步保存
LF 编辑可匹配 CRLF 文件并保留行尾；重复匹配拒绝；混合行尾需要精确文本
自更新和 CI

日志读取可移植，但对话内控制器只有 macOS 版。对话的 prepare 和 retry 在创建状态前检查 host/_platform/environment.py 里的能力，并指向 CLI 和 Desktop 更新器。status 和 cancel 不受限。原生候选测试和激活尚未实现。

push 和 PR 检查会取代同分支的旧运行。安装验收和定时冒烟使用唯一分组。每个矩阵都包含两种架构。core 任务覆盖兼容层、检查点、备份、升级、安装器契约和计划任务；smoke 任务完成 PowerShell 完整安装，启动 worker，运行 doctor 后停止。

W2：发布安装器

原生 runner 构建 OpenProgram-<version>-runtime-windows-x86_64.zip 及其 SHA-256 文件；OPENPROGRAM_RELEASE_WINDOWS_ARM64 打开时构建 arm64。只有一个 runtime/ 根目录。Ink 启动探测成功后才记录 tui.ink。

  1. install.ps1（或取用它的 install.cmd）解析稳定版本，release manifest 没有本平台安装包时停止并说明，然后交给该不可变 tag 上的安装器。在 Windows 11 on Arm 上，没有 Arm 安装包的版本改装 x64 安装包，靠模拟运行，并说明这一点。
  2. 走这项回退时，先确认 tag 上的安装器自己能选 x64 安装包；做不到就在下载之前按名称拒绝这个版本。
  3. 检查磁盘空间，支持续传下载，校验 checksum 和每个 ZIP 条目；拒绝链接和重解析点。
  4. 在每运行时一把的排他锁下，校验能力，并在隔离暂存状态下冷启动 worker。
  5. 把通过校验的候选移入版本目录。
  6. 原子替换 .cmd 启动器，保留 openprogram.previous.cmd。

托管升级通过兼容层选择 Windows ZIP 和 tag 上的 PowerShell 安装器。经 iex 管道运行时失败只设置退出码并抛错，窗口不会关闭。

激活和解压细节
  • 各版本留在各自目录，保留上一份启动器。缓存的版本会重新校验。
  • 启动器先准备并做快照。替换失败时恢复；恢复也失败时，把原文件保留在报告的路径。
  • 写入前校验 ZIP 名称；文件经扩展长度路径流式写入，检查展开字节数和长度。检查和清理用同样的 API。不改长路径注册表值。
  • .NET 替换时传 NullString，否则 PowerShell 5 把 $null 绑定成无效的空路径。
  • 构建辅助脚本恢复工作区、工具链、下载和浏览器缓存环境，失败时也恢复。
  • doctor 以只读建议报告长路径和 Defender 状态。

W3：Desktop

领域行为
构建x64 按用户、assisted 的 NSIS，由薄壳和解包进 App 的 seed 组成（arm64 跟随 W2 的开关）。Release 任务要求 seed 在 App 内
发布门禁Windows 这一路先跑 Windows 契约测试（scripts/release/windows-contracts.txt），再安装刚构建的 App，启动到 Worker 健康，经它发一轮对话，然后卸载。这轮对话发给本机回环上的替身模型，它唯一的回复是调用命令工具执行 echo 你好; exit 3；文字和退出码都要回来。失败只把这个 App 留在发布之外，和 macOS、Linux 一样。Windows ZIP 安装在记 cli-verified 前跑同一轮
签名有 WINDOWS_CSC_LINK 和 WINDOWS_CSC_KEY_PASSWORD 时：OpenProgram.exe 和安装包 Authenticode 为 Valid，否则任务失败。没有时：两者都必须是 NotSigned，安装包改名为 -unsigned.exe
证书WINDOWS_CSC_LINK 是 PFX，可以是 base64 或 HTTPS 链接；WINDOWS_CSC_KEY_PASSWORD 是它的密码。两者都有时这一项改为签名构建。公共证书机构把代码签名密钥放在硬件或云服务里，可导出的 PFX 很少见；用云签名服务需要另写签名步骤
未签名安装包的提示浏览器可能提示该文件不常被下载。运行时出现Windows 已保护你的电脑，发布者未知；点更多信息 → 仍要运行继续，不会要求管理员权限。智能应用控制会直接阻止，无法放行。用新证书签名的文件在积累信誉前也可能遇到同样的警告
运行封存版本位于 %USERPROFILE%\.openprogram\runtime，首次启动时在进度页后从 seed 解包。seed 里的链接，文件夹变成 junction，文件变成第二个名字，因为符号链接需要特权。终端：Windows PowerShell，否则 COMSPEC，经 node-pty ConPTY。从常规路径导入浏览器
Worker 进程App 通过 openprogram-launcher.exe 以分离方式启动 Worker。没有控制台的 launcher 启动 Python 时不开控制台窗口，并把自己的输出句柄交给它，所以 Worker 写入 worker.log；从终端运行时共用该终端。参数从宽字符命令行按 UTF-8 读取
卸载卸载 App 时先请 Worker 停止，再移除它的登录任务；升级和重装两样都不做。状态文件夹原样保留：对话、设置和版本库。Worker 停不下来也不阻止卸载，原地运行的卸载程序自身不在被结束的进程之内
应用标识外壳在打开任何窗口前设置应用 ID ai.openprogram.desktop，即安装器写在开始菜单快捷方式上的那个。通知、任务栏按钮及其固定项都归属这个 ID
更新器通过 openprogram upgrade --json 接收封存版本。只有发行版需要更新的外壳时，才提供文件 OpenProgram-<version>-win-<arch>.exe 或 -unsigned.exe。运行中 App 自身的签名决定更新线：只有未签名构建的 App 才接受 NotSigned，并且要先通过大小和 SHA-256；已签名的 App 要求 Valid 且发布者相同。失败时删除候选。可见的用户交接：自动更新

本地刷新发布

windows-refresh-transaction.ps1 按顺序发布已校验的同级源和目标对，覆盖 App、CLI 运行时和启动器。加载脚本没有副作用。

事务契约
  • 路径不得重叠；拒绝驱动器相对路径和被重定向的祖先。使用扩展路径，不改 ACL 或机器设置。
  • 第一个目标的父目录里一把排他 OS 锁。载荷检查在锁内进行。
  • 四个回调：静默旧安装、校验已发布、静默失败的替换、恢复旧服务。每个都必须恰好返回布尔 true。
  • 刷盘的 JSON 日志记录每个源、目标和备份。按序发布，反序补偿。
  • 成功保留原件和回执，不删除运行时目录。关闭或回滚失败时保留日志并拒绝后续尝试。
  • 这是补偿式发布，不是崩溃原子的：恢复必须检查记录的路径，不能相信最后的标志。
  • 仍需构建：冻结检出、App 和 CLI 共用一个 wheel、停 worker 前校验、在默认 profile 和端口验证、与 CLI 和 Desktop 安装锁协调。

W4：命令沙箱

兼容层找到真实的 WSL2 发行版，校验 Bash 和 bubblewrap，探测命名空间，用 wslpath 转换路径。bubblewrap 提供与 Linux 相同的边界：只读根、可写工作区根、拒绝路径、PID/IPC/UTS 命名空间、私有临时目录，除非策略允许否则加网络命名空间。

sandbox.mode行为
off（默认）只在打开沙箱开关的对话中启用
auto探测成功后所有对话都启用；否则原生、无沙箱
workspace-write在入口报告缺少 WSL2 或 bubblewrap；只有 sandbox.unavailable_policy=refuse 时拒绝执行，否则在主机 shell 里运行

探测不改 ACL、所有权、权限、Defender 或 WSL 设置。AppContainer 需要按应用做能力和 ACL 工作。Job Object 能限 CPU 和进程，但没有文件系统和网络边界。

没有 WSL2 时，沙箱开关不可用，它的提示写 Sandbox unavailable: needs WSL2、缺什么和 wsl --install；doctor 也这样写。sandbox.unavailable_policy 在 Windows 上默认 warn，其他平台默认 refuse，所以命令在主机 shell 里运行，不会全部失败。

为什么这样设计

Claude Code（srt-win 加 WFP sublayer）和 Codex（windows-sandbox-rs，RestrictedToken 和 Elevated 两级）都做原生沙箱，MiniMax Code 内置了 srt-win。原生沙箱是 ACL、令牌和过滤规则组成的 Rust 或 C 子系统，所以暂时保留 WSL2，原生沙箱以后照 Codex 的 RestrictedToken 级别做。

大多数 Windows 机器没有 WSL2，默认 refuse 让这个开关等于“所有命令都失败”。原因写在开关上，它只和这个控件有关。

托盘里的后台 Worker

Assistant 和 Butler 让 Worker 在所有窗口关闭后继续运行，所以 App 把它显示在菜单栏（macOS）或通知区域（Windows、Linux），用系统原生菜单：

  • 一行状态，来自健康检查，每 10 秒刷新。
  • Open OpenProgram。
  • Stop background：像切换版本时那样停止 Worker，然后退出，因为 App 的窗口会再把它启动起来。

关闭窗口和 Quit 的行为不变，也不多问。图标是单色的 App 图标 apps/desktop/main/worker/tray/trayTemplate.png；没有这个文件就不创建托盘。

为什么这样设计

Claude Code 和 Codex 没有常驻进程，OpenCode 的 server 跟随 CLI。常驻的桌面助手 Alma 靠菜单栏或托盘常驻，OpenProgram 的常驻 Agent 也需要这样。每次退出都询问，会给日常动作加一个弹窗。原生菜单不是新面板，唯一的提示放在 Stop 这一项上。

卸载与版本库

<state>\runtime\users.json 记录哪些安装在使用版本库（versions/users.py）：{install_id, kind: app|cli, path}。每次 Worker 启动都登记它的安装，所以较早的安装在首次启动时登记。

App 的安装程序只在版本库里已经有版本时登记自己：首次启动把种子解包进空的 <state>\runtime，里面有别的文件就拒绝。写入时加锁，用 replace_file 发布。

卸载时从列表里去掉自己那一条；一条都不剩时，询问是否一并删除下载的运行时版本，写明大小；默认回答是“否”，静默卸载保留它们。对话、设置和凭据永远不删。

为什么这样设计
对比卸载时
Claude Code版本和用户数据分开放，不碰数据
Codex脚本只删自己的二进制
OpenCode交给包管理器

只有最后一个使用者才提供删除，是我们自己的做法：CLI、App 和 dev profile 可能共用一个版本库。这几 GB 能重新下载，所以可以提供删除；它是破坏性的，所以默认“否”。

发布方面的决定

事项决定
Windows 包失败发布里只缺这个包，Check every planned package 写明它，和 macOS、Linux 一样。Codex 以“构建并签名成功”为门禁，全有或全无；这里一个平台失败不挡住其他平台的修复版本
发布冒烟每个 Windows 分支安装自己的包，先把提示用管道传给 openprogram --print，再经替身模型跑一次工具调用（scripts/release/smoke-tool-call.py）；Windows 契约包括 PowerShell 规则测试和 --print 的 Ctrl-Break 停止
签名Azure Trusted Signing，和 Codex 一样：不用保管硬件证书，按月付费，SmartScreen 不再挡首次安装
Windows on Arm五个锁定的依赖有 arm64 wheel 之前，发 x64 包在模拟下运行；之后照 Codex 的安装器出原生包
对话内更新版本库的控制器：构建新版本、移动指针、保留上一版用于回滚，Windows 和其他平台一样。要退役的版本有文件被进程占用时留在原处，之后的一轮再移进 trash
为什么这样设计

Claude Code 把运行中的可执行文件改名为 .old.<时间戳>，下次启动时删除，因为它就地替换自己的二进制。

版本库从不这样做：每个版本有自己的文件夹，只移动指针。Windows 上含有打开文件的文件夹既不能移动也不能改名，所以保留策略把它留下、下一轮再试，效果正是改名给 Claude Code 带来的效果。
