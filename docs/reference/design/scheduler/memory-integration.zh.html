Memory 接口

任务类型行为
一次性带时区的 run_at，运行一次
周期五段 cron、用户签名、冻结的沙箱策略、非交互执行
监控按 cron 运行观察提示词；记录日志和状态，不保证跨渠道恰好一次通知

不做：Memory writer 推断任务、Memory 页显示 Commitments、服务隐式改 Memory、跨存储事务、外部令牌权限模型、已删记录的占位或转发、第二个执行器、项目管理、依赖、子任务。

一次运行的过程

  1. 用户 Web 界面、Agent 工具或外部 API 创建任务。
  2. 运行时签名提示词或命令、cwd、权限、沙箱和 MemoryRef。
  3. 常驻 worker 每分钟检查一次性和 cron 计划。
  4. 每次运行先按 workspace_id + memory_id 载入记忆的当前内容。
  5. 在冻结的非交互边界内执行，并写 Scheduler 日志和状态。
Tick 异常
  • @reboot tick 或普通 tick 的 Exception 以警告和完整 traceback 写入 stderr；守护进程在下一分钟继续，不重放。初次失败后，之后的 tick 用 reboot=False。
  • 常驻 worker：stderr 进全局 worker 日志。前台 scheduler-worker：终端。两者都不是任务执行日志。
  • run_once、KeyboardInterrupt、SystemExit 等 BaseException 保持立即失败。
  • scheduler-worker 及其别名 cron-worker，连同 --once 和 --list，绕过为 Ink TUI 启动准备的 stdio 重定向。

MemoryRef

字段规则失败
workspace_id当前 Memory 工作区的稳定 ID拒绝隐式跨工作区读取
memory_id创建和更新时解析到唯一 Topic 块；每次执行重读内容写入时：缺失、重复、跨工作区或格式错误被拒。执行前：任务失败，不回退旧快照。多个引用超限时，保留全部 ID 和 Topic 路径，只截断内容并标记。
写权限引用不授予权限。本地用户的提示词任务可用 memory_search、memory_get、memory_update，走现有引用检查、格式校验、派生视图和 Git 事务。Memory 事务失败不影响 Scheduler 状态

Agent 协议

阶段Agent边界
规划只有值得长期保留的任务才 memory_update.create_record，再把返回的 memory_id 作为 memory_refs 附上依次调用，非原子；任一失败都报告。临时提醒不需要 Memory。
执行读取原记录，再用 update_record 写状态、结果或下次需要的内容其他工具按对话权限模式。只有非用户设置的计划会被拒绝 Memory 生命周期工具。
收尾标记完成或关闭；没有保留价值时 delete_record。交互式 agent 可禁用或删除任务。旧 ID 返回 NOT_FOUND；仍引用它的任务下次失败，所以先移除任务。

已提交、仓库仍在且历史未改写时，删除的内容可从可达的 Git 历史恢复。memory_get 只查 HEAD，所以 API 查不到旧 ID。

旧 Commitments

记录变成
open，有日期当日本地 09:00 的已启用一次性任务
open，无日期暂停的一次性草稿，保留文字和来源，等用户设时间

Memory writer没有 record_commitments 工具和提示词。旧解析器只为迁移保留。

Scheduler 页面

  • 共用页头和主题 token；ManagePageHeader、ManageRow。搜索和主操作在 64px 顶栏同一行。
  • 页头下一排四个紧凑筛选，没有侧栏；窄时换行。任务行保留计划、状态和操作，按可见顺序编号。
  • 空状态：介绍和创建任务居中；三张建议卡在最宽 960px 的居中网格里，窄时单列，每张有标题、计划、提示词和使用。
  • 创建和使用打开现有表单，不创建任务；Escape 返回。
取舍
来源处理
定时任务产品参考独立页面、创建、搜索、一次性/周期/监控分类。不要重复大标题和大片留白。
现有 cron保留执行安全和 cron 兼容入口；改名 Scheduler，并入常驻 worker
Commitments、heartbeat不作为 Memory 类型；只保留迁移读取，没有标签页、状态字段或特殊 heartbeat
自动双写拒绝。由 agent 组合两个现有工具。

验收

  • 三个 Memory 工具能从 Scheduler 提示词 worker 执行，deny 和 ask 规则仍优先，脚本化运行更新 Topic 并产生 Memory Git 提交。
  • 回归覆盖初次和普通 tick、等待、超时睡眠、日志、CLI 入口和两种立即失败边界。
  • 容器宽 360、768、1440 px 无横向溢出；四个筛选都可达；加载、搜索和错误状态不变。
