CLI 和 TUI 配置界面

一份 schema 描述所有设置，每个界面只负责渲染。新增设置就是一个 SettingSpec，各处自动出现，不用按界面写代码。没有只能在 Web 改的设置。

界面访问 schema 的方式
openprogram config list、get KEY、set KEY VALUEget_settings、set_setting
openprogram setup 向导、openprogram portsget_settings、set_setting
TUI /config 面板现有 BackendClient 上的 WebSocket get_settings、set_setting
Web 页面REST /api/settings

代码：openprogram/state/settings.py、interfaces/server/ws_actions/settings.py、apps/cli/src/components/SettingsPanel.tsx。命令语法：CLI 命名约定。没有新传输或新进程。

规则行为
模式是动词openprogram web 启动 Web UI，裸 openprogram 启动聊天。没有 --tui、--web、--cli。
容器动词（programs、skills、plugins、sessions、channels、memory、worker、mcp、subagent）裸调用时打印子命令列表并以非零退出，统一走 _need_subcommand(parser)，因为各分发器自己调 print_help() 会走样
有真实默认动作的动词providers 列 pool，ports 显示端口，config 列设置
自文档每个 add_argument、add_parser 都有 help=；顶层 --help 带常用命令 epilog
setup首次运行流程；setup <section> 跳到某节，setup menu 打开选择器
config get、config set可脚本化，是文档的稳定目标；和面板编辑走同一条校验路径

Schema

@dataclass(frozen=True)
class SettingSpec:
    key: str             # 稳定 id，如 "ui.web_port"
    path: tuple[str, ...]  # config.json 中的点路径
    group: str           # "Ports"、"Memory" ...
    label: str
    widget: str          # "number"、"toggle"、"enum"、"text"、"json"
    apply: str           # "live" 或 "next_start"
    default: Any = None
    choices: Callable[[], list[str]] | None = None
    validate: Callable[[Any], str | None] | None = None  # 错误或 None
    help: str = ""
    secret: bool = False
    minimum: int | None = None
部分设计
SETTINGS有序列表，事实来源
get_settings()读一次 config.json，解析当前值，惰性计算 choices()，遮蔽密钥
set_setting(key, value)校验后，有专用写入函数就用（ui.* 用 set_ui_ports），否则走通用点路径写入。返回 {applied, value} 或 {error}
阻止的键点路径写入在每一层都拒绝 __proto__、constructor、prototype
位置~/.openprogram/config.json，经 profile 感知的 get_config_path()
动态键tools.disabled.<name> 开关工具，即时生效。providers.* 状态行只读
生效live：每次使用时重读。next_start：绑定时读一次（ui.web_port、memory.backend）。界面在编辑当下说明

TUI 面板

/config，也可从 Ctrl+K 面板进入：持续存在、编辑实时状态的编辑器，基于 Picker，分组、字段、编辑器三层。枚举字段复用 Picker，数字和文本用 LineInput。

区域行为
schema 分组Ports、Models、Memory、Search、Tools、Execution、Security、Voice 以及 SETTINGS 的其余分组，按注册顺序
动作行模型、thinking effort、权限模式、主题和 Claude 账户分别启动 /model、/effort、/permissions、/theme、/login，不重复实现
端口config set 通过 with_port_owner_note 附上占用者。面板只报告，不抢占
主题光标移动时预览，ESC 回滚；没有 Apply 步骤
Provider、channel显示状态和动作，绝不内联输入密钥；OAuth 不在文本框里重做
快捷键没有设置分组：TUI 没有快捷键配置文件

Ctrl+K 用同一个 Picker 渲染斜杠命令注册表（名称和描述）并带快捷键提示；/config、/model、/theme 在这里统一出现。不改变语法。
