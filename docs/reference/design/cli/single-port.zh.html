单端口架构

路径（按匹配顺序）worker 的提供方式缓存
/ws原生 WebSocket
/api/*原生路由
/files/raw、/docs/*静态挂载
/_next/staticapps/web/out/Immutable
/*out/ 里的文件；其余 GET 返回外壳 out/chat.htmlHTML no-cache

Electron 外壳加载同一来源。端口和冲突：Web UI 端口。稳定版 18100，开发版 18200。

不变量

  • 后端是唯一来源。没有代理、第二个服务器或构建时固定的端口。/ws 天然正确：就是页面加载的来源。
  • API 路由优先于静态。前端挂载最后注册。
  • Node 只在构建时需要。运行时只要 Python 和 worker。

为什么不用 Next 服务器

worker 旁边跑 Next 服务器的代价这里
/ws 代理目标在构建时固定；profile 环境不对的构建让所有客户端断开相对路径 /ws、/api/...；没有 rewrites()
worker 里要有回收端口、清孤儿、监视构建、监视父进程的代码worker 不启动 Node 进程
全客户端的 UI 运行时也要 Node静态导出

合并的代价很小：外壳通过 next/dynamic 以 ssr: false 加载，所有真实页面都是 "use client"，没有 middleware.ts、server action 或 next/image。FastAPI 设了 docs_url=None，不与文档挂载冲突。

前端导出

部分设计
apps/web/next.config.mjsoutput: "export"：next build 把 HTML、JS、CSS 写入 apps/web/out/
动态段会话、skill、provider 设置路径没有页面文件；没有 generateStaticParams 时静态导出会拒绝它们。SPA 回退返回外壳，客户端按 pathname 路由。真正干活的段保留一个占位的 generateStaticParams。
API route handler没有；这些路径由 worker 提供
提供openprogram/interfaces/server/frontend.py，在 create_app() 中最后挂载
构建门ensure_frontend_built：out/index.html 缺失或早于最新源码时，启动时跑一次 npm run build。打包版本自带 out/，从不调用 Node。

进程和端口

部分设计
入口operations/worker/runner.py 调用 interfaces.server.start_web 和 ensure_frontend_built
发现worker.port 文件是唯一事实来源
端口配置OPENPROGRAM_WEB_PORT 和 ui.web_port 设置这唯一的端口
Electronapps/desktop/main.js：WEB_PORT 取 OPENPROGRAM_WEB_PORT，否则取实例端口。启动地址、来源检查、导航守卫都用它

operations/worker/web.py 是不在调用路径上的双端口遗留代码，留待单独清理。它还提到一个已不存在的监视脚本。

取舍

  • 对合并后的来源没有 next dev 热更新。
  • 真正渲染内容的动态段，页面文件删除后会失去深链接。SPA 回退覆盖这种情况。
  • 拉取后 out/ 可能过期。启动门覆盖；git pull 后运行 openprogram restart。
验收标准
  1. openprogram（dev profile）只起一个监听端口；lsof 看不到 next-server。
  2. 首次加载 /chat、/s/<id>、/settings/providers/<id>、/skills/<name> 都能渲染；/ws 连上；/api/pick-folder 可用。
  3. 杀掉 worker，已加载页面显示断开；重启后重连。无孤儿进程。
  4. 没有 profile 环境的构建也能产出可用实例。
  5. 测试通过；桌面 App 重新打包并验证。
