Config write safety

config.json is one file mutated from several surfaces and processes. Without a lock over the whole read-modify-write, the later writer discards the earlier one.

from openprogram.state.config import update_config

def mutate(cfg):
    cfg["ui"]["web_port"] = 8101

result = update_config(mutate)          # returns the resulting config
update_config(mutate, expected_revision=revision)  # with a revision check

openprogram.state.config.update_config is the only correct way to change part of the config. Writes back with mode 0o600. The caller never holds a config dict across the lock boundary. read_config and write_config stay for read-only access and full replacement; a bare pair of them races.

LockCovers
_config_write_lock (threading.Lock)Worker threads: a TUI tool toggle and a web key save
config.json.lock, via _private_atomic_updateOther processes: openprogram config and openprogram setup against the worker

Neither is redundant. A private module lock cannot substitute: storage.py's _cache_lock protects only that module's cache.

Scope is write atomicity alone. Schema and validation belong to state.settings (redesign); the format stays JSON.
