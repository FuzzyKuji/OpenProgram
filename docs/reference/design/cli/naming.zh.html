CLI 命名约定

openprogram <noun> [<noun> ...] <verb> [<arg> ...]
部分规则
动词只有一个，在位置参数之前的最后，不夹在名词中间。一般现在时：list、status、add、remove、login、logout、set、get、discover、adopt、doctor、setup。
名词在前；多个名词逐层收窄命名空间。集合用复数（providers、profiles、models、channels）；只有绝不会有同级的东西才用单数。
参数在动词之后：openprogram providers login codex 里，codex 是 login 的目标。
标志双横线 kebab-case：--profile、--display-name、--max-poll-seconds

示例

命令状态形态
openprogram providers login <prov>现有单名词
openprogram providers list现有单名词
openprogram providers status <prov>现有单名词

不要这样写

命令原因
openprogram login动词在顶层，一有第二个登录目标就冲突
openprogram providerAuth logincamelCase；名词叠加是分开的词
openprogram list-providers把动词锁进名词。用 providers list
openprogram providers listing动词形式错误

何时加中间名词

只有父名词确实分成多个同级子组时才加。没有同级的中间名词是累赘。OpenClaw 保留 openclaw models auth login，因为 models 还有 aliases、list。OpenProgram 让 providers login 保持扁平，因为 providers 的直接动词都和凭据有关。

添加命令

  1. 选它所属的最深名词命名空间。与现有命令同级就复用。
  2. 选动词。优先用 CLI 里已有的。
  3. 接入：元数据和 argparse 在 openprogram/interfaces/cli/parser.py，逻辑放在 openprogram/interfaces/cli/commands/ 下的主题模块，顶层分发在 openprogram/interfaces/cli/application.py。
为什么这样定
  • 可发现：openprogram providers <TAB> 列出该命名空间的全部操作。
  • 可扩展：新领域作为同级名词加入，不会冲突。
  • 成熟 CLI 都收敛到这里：openclaw models auth login、openclaw models aliases add、gh auth login、gh repo create、docker container ls、docker image prune、kubectl get pods、kubectl delete service <name>。
