TUI 转录渲染

每个工具读作一行标题加一行量化摘要，输出折叠并给出准确的剩余行数，一个键展开全部，编辑显示带行号的 diff，轮次运行时输入的消息排在输入框上方可见，图片和 PDF 可按路径或粘贴附加，所有按键来自一张可覆盖的表。运行中提问：用户输入请求。

工具显示什么
所有工具状态字形用主题的工具颜色（◌ 运行、● 完成、✗ 出错），粗体工具名，括号里是它作用的参数，内容在 ⎿ 下。其他 provider 的名字（Bash、MultiEdit、TodoWrite、Task）映射到同一套渲染
bash输出折叠到 3 行，然后 … +N lines (ctrl+o to expand)；帧是预览时 N 取服务端给的完整输出行数。只隐藏一行时直接显示这一行
read、grep、glob、list一行：Read 52 lines、Found 8 files、Found 3 matches、No matches；内容只在展开时显示
edit、apply_patch、writeAdded X lines, removed Y lines 加 diff：绿色新增、红色删除、三行上下文，折叠段显示 ⋮，超过 12 行才折叠。行号在结果到达时读一次被编辑的文件得到；文件不在本机时不显示行号，不给错的
agentRunning…，然后 Done (2m 10s) 和回复开头；后台 agent 显示 Started in the background
todo_*最新一次 todo 调用画出 todos_update 帧里保存的清单：☒ 完成并划线，◼ 进行中加粗，☐ 待办
展开Ctrl+O 展开或折叠整个转录里的工具输出；折叠提示写当前生效的键
匹配结果按 tool_call_id 找到自己的调用，同名工具并发时结果落在正确的行；没有 id 的帧退回到同名最新的运行中调用
为什么这样设计
主题理由
按工具给摘要Claude Code 的工具渲染给量化摘要（Read N lines、Found N files、编辑的增删数和 diff）；Codex 在 └ 下印原始输出；opencode 把单行工具（读、搜索）和块工具（bash、编辑、task、todo）分开。摘要跟 Claude Code，因为模型拿到之后文件内容和文件列表对人是噪音；分法跟 opencode，混合运行每个工具两行。以前每个工具都印 6 行原文，编辑被淹没在文件内容里
折叠到三行并计数Claude Code 折叠到 3 行加 +N lines；Codex 保留头尾；Pi 显示 bash 的尾部。头部加准确总数能说清藏了多少；总数取服务端的预览元数据，只数预览会少算长输出
一个全局展开Claude Code 的 Ctrl+O 打开一个冻结的独立屏；Pi 原地切换 app.tools.expand。原地切换保持转录可滚动，不需要第二个屏和退出键，cell-grid 渲染器本来就整帧重绘
diff 来自编辑的参数Claude Code 用 old_string / new_string 生成 patch；Codex 用它应用的 patch。TUI 从调用里两者都有，不需要改服务端；参数里没有行号，所以读文件取，文件在别处（SSH 对话）时不显示
清单来自已保存的 todoClaude Code 用 TodoWrite 的参数画清单；我们的工具每次只改一项，所以清单取工具本来就广播的 todos_update 帧，TodoWrite 式调用仍按参数画

轮次运行时输入的消息

  ↳ also update the changelog
› and run the linter +2 lines
╭──────────────────────────────────────────────╮
│ >  waiting for response    enter edit · x remove │
╰──────────────────────────────────────────────╯
步骤行为
排队轮次运行时输入框照常接收输入；Enter 把消息连同附件放进队列，在输入框上方暗色显示，每条一行 ↳
选中输入框为空时按 ↑ 选中最新一条；↑ / ↓ 移动，Esc 回到输入框，其他键回到输入
编辑、删除Enter 或 e 把这条取回输入框（含附件），再按 Enter 排到队尾。x、Delete 或 Backspace 删除
发出分支空闲后（完成、失败或被停止），最早的一条作为下一轮发出，然后下一条。Esc 仍然停止轮次
为什么这样设计
主题理由
可见的行，而不是隐藏的缓冲Codex 把排队消息显示成暗色 ↳ 行，用一个键取回最后一条；Claude Code 按 ↑ 把全部拉回输入框；Pi 用 Alt+↑ 恢复；opencode 只显示条数。Grok Build 的队列面板用 ↑ 选中任意一条编辑或删除。行和选中方式跟 Grok Build，因为网页输入框的排队气泡也能逐条编辑、删除，两边一致
停止后照常发出Claude Code 停止后发出队列；Codex 和 Pi 放回输入框，因为它们的队列不能编辑。我们的队列停止前后都能改，所以照常发出，和网页输入框一致
一条一轮Claude Code 把排队的多条合成一条；这里每行各成一轮，删改一行不影响别的行，每个分支仍只有一个前台操作
在客户端排队每个分支只有一个前台操作，服务端会拒绝第二次发送；在 TUI 里等分支空闲再发，不需要改服务端

图片和 PDF

入口结果
粘贴或拖入路径粘贴的每个片段都是已存在的图片（png、jpg、gif、webp）或 PDF 时——包括带引号、\ 转义、file:// 和 ~ 的写法——插入 [Image #1] / [PDF #2] 而不是文字；其他情况保持文字
剪贴板图片Ctrl+V（Windows 上 Alt+V）或一次空粘贴，从剪贴板读图片：macOS 用 osascript，Linux 用 wl-paste 或 xclip，Windows 用 PowerShell
@path发出的 @path 指向图片或 PDF 时同样附加
发送文本里还在的占位符变成网页输入框的 [attachment: name (ext, N KB) @json "path"] 标记；删掉的占位符连同文件一起丢弃。图片带源路径按字节发送；PDF 只发路径，交给 pdf 工具。超过 5 MB 的图片和超过 32 MB 的文件被拒绝，并用一行说明原因
为什么这样设计
主题理由
占位符放在文字里Claude Code 和 Codex 都在图片位置显示 [Image #N]，删掉占位符就丢弃图片；终端没有附件条，文字是唯一能显示和删除附件的地方
粘贴时识别路径终端把拖入的文件交成它的路径。Claude Code 和 Codex 把这种粘贴变成附件；要求每个片段都是存在的可附加文件，提到路径的一句话仍是文字
网页输入框的标记服务端已经为带源路径的 Electron 上传保存、改写和渲染这个标记，TUI 不需要新协议，消息在网页聊天里显示也一样
不缩放网页输入框用 canvas 缩小大图；TUI 没有图像库，所以超过模型 5 MB 上限时拒绝，而不是发一个会失败的请求

// ~/.openprogram/keybindings.json（当前 profile 的状态目录）

  "app.toolsExpand": "ctrl+t",
  "app.commandPalette": "none",
  "queue.remove": ["d", "delete"]
}
部分设计
动作表每个可改的键都是一个只声明一次的动作，带作用范围（global、input、queue）、默认键和说明；处理函数问"这个动作是否匹配"，不直接判断原始按键
覆盖状态目录里 keybindings.json 的扁平对象 action → key | [keys] | "none"。用户绑定的键会从重叠范围内的默认动作上拿走
问题未知动作、读不懂的键、保留的动作或键（Ctrl+C）、用户自己把一个键绑给两个动作，启动时各在转录里出一行；文件其余部分照常生效，JSON 坏了就用默认
? 帮助空输入框按 ?（以及 /keybindings）打开快捷键列表，由同一张表和当前生效的键生成；输入框上的提示和折叠提示也用当前的键
为什么这样设计
主题理由
扁平的动作表Pi 的 keybindings.json 和 opencode 的 keybinds 是动作到键；Claude Code 按范围嵌套键到动作；Codex 在 config.toml 里按范围和动作嵌套；Grok Build 不能改键。扁平表最短，范围留在表里，用户不用写
警告而不是报错Codex 遇到冲突的键位拒绝启动；Claude Code 和 Pi 警告后继续。键位文件里的一个笔误不该让人进不了 TUI
Ctrl+C 保留Claude Code 保留 Ctrl+C 和 Ctrl+D，因为停止和双击退出依赖时间；这里 Ctrl+C 承担同样的停止和退出，所以固定
帮助来自表手写的列表会和处理函数脱节；从处理函数读的同一张表生成，两者永远一致，Claude Code 和 Codex 的快捷键面板也是这样

命令和交互

元素设计
命令注册表每个命令只声明一次（名称、标题、分类、快捷键、slash 名、是否可用）；驱动 Ctrl+K、slash 命令和页脚提示，注册表和处理函数不会脱节
提问提问和审批占用输入槽而不是弹窗；转录保持可滚动，esc 只有一个含义
危险操作选择器里的破坏性操作在行内确认：再按一次，行变红。没有嵌套确认层
选择器从 pickerKind 枚举逐个迁移到 ModalProvider 和 Form 组件
Spinner一条合成行，随宽度渐进取舍
Markdownmarked-terminal，按流式状态、文本和宽度对每个文本段 memoize；cell-grid 渲染器每帧重绘

保留 vendored hermes-ink 渲染器：已有鼠标跟踪和 ScrollBox，换 OpenTUI 没有收益。
