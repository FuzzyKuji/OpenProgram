TUI 转录渲染

工具调用折叠但不丢信息，Ctrl+O 显示全部，diff 结构化，Agent 忙时消息排队，快捷键可发现、可覆盖。运行中提问：用户输入请求。

元素设计
工具外壳每个工具一组渲染 hook（use-line、progress、result、error），共用一个外壳。圆点：排队暗、运行闪、完成绿、出错红。粗体工具名、括号内参数摘要、结果缩进在 ⎿ 下。两个字形，没有框
截断3 行，然后 … +N lines (ctrl+o to expand)。只隐藏一行时直接显示。超大输出先按字符预截断，估算剩余行数
摘要量化：Read 52 lines、Added 5 lines, removed 2 lines 加 diff、Found 8 files、Done (12 calls · 48k tokens · 2m 10s)
Ctrl+O独立 Screen：冻结消息列表，展开重渲染，页脚有退出提示。其中 Ctrl+E 显示全部不截断。可作全局键：流控用 Ctrl+S、Ctrl+Q
Spinner一条合成行，随宽度渐进取舍
忙时输入输入进入队列（暗色，在输入框上方），↑ 取回编辑，轮次之间发出
Diff自写：行号、增删着色、三行上下文；用于编辑结果和 /diff
Markdownmarked-terminal，按流式状态、文本和宽度对每个文本段 memoize；cell-grid 渲染器每帧重绘

信息密度学 Claude Code，下面的交互学 opencode。保留 vendored hermes-ink 渲染器：已有鼠标跟踪和 ScrollBox，换 OpenTUI 没有收益。

命令和交互

元素设计
命令注册表每个命令声明一次（name、title、category、keybind、slash-name、enabled），驱动快捷键、Ctrl+K、斜杠命令和页脚提示，注册表和 handler 不会走样
快捷键表默认值和描述声明一次，生成配置 schema。用户覆盖放在 ~/.openprogram。未知键报错；"none" 禁用。? 帮助来自同一张表
提问提问和审批占据输入槽而不是弹窗；转录仍可滚动，esc 只有一个含义
危险操作picker 的破坏性动作在行内确认：再按一次，行变红。没有嵌套确认层
Picker从 pickerKind 枚举逐个迁到 ModalProvider 和 Form 组件

服务端支持

改动原因
工具流事件带 call_id结果按 id 匹配，并发同名调用归属正确
load_session 回复带工具块/resume 恢复工具历史

两者都涉及 _event_parsing.py 和 dispatcher 事件发送，与事件总线工作共用。
