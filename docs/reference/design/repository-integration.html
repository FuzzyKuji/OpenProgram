Repository integration

The integration target is dev. main has an independent history and is written only by scripts/publish-github.sh (see Publishing source to GitHub).

Boundary

AreaRule
AuditEach branch at its committed head; uncommitted files stay in their worktrees
PreparationIn an isolated clean checkout
Branch deletionA separate operation
Stays authoritativeThe Agent and Context refactor; the official Anthropic API requirement

Merge decisions

The branch changeDecision
Is an ancestorAlready contained
Is duplicate or superseded, often patch-equivalent with a different commit idKeep the current implementation; record the branch ancestry only after comparing its unique patches
Is genuinely newNormal content merge
References removed APIsKeep the newer implementation
Updates dependenciesResolve together into one lockfile
Blanket remote overwrite, or blanket acceptance of historical filesRejected

Verification

ItemRequirement
Branch inventoryExact heads, containment, patch comparisons, reviews and remaining checks, in a private delivery ledger
AncestryEvery inventory head is an ancestor of the combined commit
Checks on that commitRepository contracts, affected public checks, dependency lock validation, Web tests, documentation checks
Existing failuresStay recorded as incomplete; never passing evidence
Conflicts or failed writesCandidate and original refs are preserved
