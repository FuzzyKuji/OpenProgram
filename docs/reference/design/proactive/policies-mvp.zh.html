三条模板规则

规则什么时候照抄车道、监视、冷却动作
DangerousCommandGuard在动作发生前拦截gate，tool.before，0Gate.ask
TestGapWatcher条件累积后提醒，又担心误报observer，model.response_completed，30 分钟Notify；设计上先 Prepare
UnvalidatedCompletionNudge纠正模型，不打扰用户observer，model.response_completed，15 分钟Inject

只有三条是有意的：主动系统死于误报，Clippy 和 UAC 弹窗都是如此。规则是要过代码评审的 Python 类，没有配置文件或 DSL。每条打磨好再加第四条。

DangerousCommandGuard

拦截放行
rm -rf 指向根、家目录、/*、.. 或系统目录rm -rf /tmp/x、rm -rf node_modules
git push --force 且提到 main、master、release、prod、production强推自己的分支
kubectl delete namespace 或 nskubectl delete pod x
terraform destroy、DROP DATABASE任何不确定的情况：宁可漏报，不要刷屏

关键词匹配的误报会让人习惯性确认，所以规则解析目标和分支。它只防手滑：威胁模型。

设计：作为风险标注并入现有的工具审批，同一命令只确认一次。

TestGapWatcher

项目说明
触发条件本轮改了文件、改了核心路径、没动测试文件
核心路径/auth/、/billing、/payment、/security；agent、conversation、jobs、permissions、providers、proactive 包
测试文件test_、_test、/tests/、spec.
检查时机只在收尾时，不是每次文件变更
设计：误报改注释、重命名、改配置、升依赖都会触发，所以先由只读 Prepare 任务核实缺口，有把握才提醒
设计：花费界面显示今天的次数、花费和未发出的提醒，并可关闭
设计：提醒带“帮我写测试”按钮

UnvalidatedCompletionNudge

项目说明
触发条件本轮改了文件且没有验证。跑测试和浏览器检查都算，否则前端工作会被误判：什么算验证
为什么用 Inject本仓库本来就要求自验，推模型一下比让用户确认便宜
设计推了仍不验证才通知用户；并要求模型确实声称完成
