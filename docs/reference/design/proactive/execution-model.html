Rules and how they run

class Policy:
    on: set[str]          # event types watched
    lane: "gate" | "observer"
    cooldown_s: float     # silence after acting
    name: str             # defaults to the class name

    def evaluate(self, event, state) -> Action | None: ...
    def dedup_key(self, event, state) -> str: ...   # what counts as "the same situation"

Both lanes: cooldown_s is checked against the event clock per dedup_key. A raising evaluate is logged and treated as no action.

Add a rule

  1. Write a class in openprogram/runtime/proactive/policies/ with on, lane and cooldown_s.
  2. Write evaluate.
  3. register_policy it (same name twice is ignored).

The engine, event stream and fold stay untouched. Interruption budgets and automatic breakers are out of scope; cooldown_s is the one knob. Mechanics of the gate: Event layer.

Implementation status

The engine, registry and three rules exist and are tested. install_proactive() and install_mvp_policies() are not called at worker start, so no rule runs in production.
