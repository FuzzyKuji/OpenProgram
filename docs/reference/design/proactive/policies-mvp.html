Three on purpose: proactive systems die of false positives, as Clippy and UAC prompts did. Rules are Python classes that pass code review, with no config file or DSL. Each is polished before a fourth is added.

DangerousCommandGuard

StopsLets through
rm -rf on root, home, /*, .., or system directoriesrm -rf /tmp/x, rm -rf node_modules
git push --force naming main, master, release, prod, productionForce-push to your own branch
kubectl delete namespace or nskubectl delete pod x
terraform destroy, DROP DATABASEAnything unsure: a miss beats a flood of prompts

Keyword matching produces false positives until people confirm by reflex, so the rule parses targets and branches. It catches slips only: Threat model.

Design: attach to the existing tool approval as a risk annotation, so one command gets one confirmation.
