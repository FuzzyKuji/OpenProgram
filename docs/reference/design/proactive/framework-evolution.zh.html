框架信号路由

子系统没有总线时接入总线后
EventBus未使用唯一枢纽：进程单例，统一 Event 格式，按类型订阅
WebUI 服务器每个信号用各自的 JSON 接到 _broadcast，UI 组件成了路由点普通订阅者，转发到前端 WebSocket
Agent 循环内部 AgentEvent 流；钩子返回值被丢弃保留该流，并在关键点发送；tool.before 可以否决
Dispatcheron_event 回调链通往 WebUI保留回调链，并发送 user.prompt_submitted 等事件
任务运行器直接广播 job_status发送 subagent.*；广播经 ws.frame
Auth事件设计正确，几乎没人订阅不变；桥接翻译 AuthEvent
Contexton_event 回调在回调中发送 context.*
Channels直接广播 channel_turn发送 channel.*；到前端的直连保留
Memory轮询，没有信号处理开始和结束时发送
文件变更没有信号文件工具发送 file.changed
插件钩子只能观察基于总线订阅，仍是插件 API

新消费者只需一次 subscribe(types=…)，不必对接五六种机制，其中有些时机原本根本没有信号。

  • tool.before 是工具拦截点，在审批包装之外，对子 Agent 同样生效。turn.stop 是另一个 gate。
  • 桥接是事件模型已经合理的子系统的接入方式：auth 内部完全不知道总线存在。
  • 接入事件源是增量的：总线收到副本，旧路径照常运行，每个源都能单独验证和回退。
  • WebUI 切换使用透传信封：广播帧逐字节不变，因此不需要影子比对，前端也察觉不到。
