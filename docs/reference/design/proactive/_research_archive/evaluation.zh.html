评估主动层

面向未来论文的研究方案，未实现。

贡献

贡献已有工作缺什么
C1git 即真相的事件溯源和把回放当策略测试：决策是事件流上的纯折叠Claude Code hooks、AgentSpec 即时拦截，没有事件溯源和离线回放
C2框架强制的打断预算和由驳回触发的熔断（执行模型 §5）hooks 是开环的：没有反馈和自我静音
C3惰性 L2 推断写回为派生事件（事件与状态 §4）让推断成为可复现结果的记录数据
  • 双通道（同步闸门、异步旁观）不是贡献：它沿用 admission webhook 与 controller 的模式。作为设计决策呈现，配 agent 特有的证据：实测 10 ms p99、失败关闭事故分析、闸门穿透子 agent 绕过。
  • PRL 是未发表的内部设计，只作附录动机，绝不作基线：评审无法核对，也从未实现。

实验

作者本人用两周只是个例：规则自己写、霍桑效应、20–50 个事件。

实验设计
大规模回放把数千条公开轨迹（SWE-bench、SWE-agent、OpenHands）映射到 Event schema。would-have-fired 至少两名标注者；报告精确率和 Cohen's kappa
召回独立标注的 should-have-fired 集；回放看不到漏报
真人部署8–12 名开发者，每人 1–2 周。按预期事件率推算达到统计功效所需会话数

基线

基线描述原因
prompt-only把三条规则意图写进系统提示，零运行时成本最关键：接受率相近则运行时层没有存在理由
no-proactive关闭这一层下限
gate-only只留闸门通道，约等于 Claude Code hooks隔离旁观和反馈的贡献

指标

指标衡量
TestGapWatcher（主要）被触发的模块真正补上测试的比例及其后续 bug 率
UnvalidatedCompletionNudge（主要）被接受的建议真正发现回归的比例
接受或驳回（辅助）混杂建议错误、时机、已知、习惯性关闭
熔断敏感性N∈{2,3,5} 的静音与漏介入曲线。说明为何用计数器而非期望效用：没有校准好的冷启动数据

配套评估

  • L1、L2 推断单独评估：路径前缀 → touched_modules（monorepo 易错）、claimed_completion 等各标注 100–200 例，分别报告准确率。
  • 规则精确率差时，区分状态错误和决策错误。
  • 消融：去掉熔断；全同步或全异步；只留 L1。测量精确率损失和增加的延迟。旁观放进同步路径增加的轮次延迟支持双通道。
  • L2 成本：每轮最多两次推断的金额和延迟，与 prompt-only 对比。

数据集发布

回放和标注作为数据集：机会分类、两名标注者、触发与不触发案例、should-have-fired 集。发布前应用脱敏 schema（威胁模型 §5：事件含密钥和私有代码）。发布 augmented 模式的 L2 缓存和模型指纹，复现的是标注集，不是推断过程。
