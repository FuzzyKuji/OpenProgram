分发

方式调用效果订阅者抛错
notifyemit / subscribe(handler, types=…)只观察；发送方从不等结果记录；其余订阅者照常运行
gateemit_gate(event, timeout_s=None) / subscribe_gate按注册顺序在发送方线程全部运行。任一理由即 allowed=False，理由累积。记录，按放行处理
transformemit_transform(event, value) / subscribe_transform每个接收上一个的值并返回下一个；None 保持原值跳过，输入继续传下去
  • gate 是 tool.before 和 turn.stop；唯一的 transform 是 tool.result，shell 钩子不能订阅。其余都是 notify：事件参考。
  • gate 要快：不调 LLM，不做慢 I/O。
  • 同一线程内对同一类型嵌套 emit_gate 会立即放行并警告。
  • timeout_s 是软总预算；超过后其余 gate 被跳过并警告。
  • tool.before 在 permission_mode 审批包装之外，bypass 和子 Agent 都逃不开。
  • notify 处理函数也在发送方线程运行；异步函数在有运行中事件循环时被调度到其上。

事件

@dataclass(frozen=True)
class Event:
    id: str
    ts: float
    type: str
    origin: str      # user / agent / tool / system / proactive
    payload: dict
    metadata: dict   # {"session": …, "turn": …, "lane": …}

make_event 填充 id、ts，并从 store 的 ContextVar 取 session 和 turn；显式传入的 metadata 键优先。session 和 turn 放在 metadata，因为它们是外部关联，对 auth、channels 等一半事件没有意义。框架没有 Turn 对象。

准入

只有真实消费者订阅时，一个类型才进入 EVENTS。新增类型只改发送点；新增载荷字段是安全的；改动已有字段可能破坏订阅者。

发送未注册类型时每种类型警告一次，绝不抛错。test_every_emitted_type_is_registered 覆盖所有 emit_safe 类型。

事件源类别接入方式
A：Agent 活动turn、工具、任务路径上的发送点；metadata 通常带 session 和 turn
B：系统状态，可能没有 Agent 在运行auth 保留自己的 subscribe/_emit，经 events/bridges.py 单向桥接。context、channels、memory 和 WebUI watcher 用 emit_safe 直接接入。

订阅者协议
Python gateNone 放行；字符串拒绝。tool.before：理由成为模型收到的错误工具结果。turn.stop：理由成为续跑提示，前缀 [hook]。
Shell，事件以 JSON 从 stdin 传入退出码 0 放行。2 拒绝，stderr 是理由。其他退出码或超时（默认 60 秒）放行并警告。
 
{"hooks": {"turn.stop": [{"command": "python check_done.py", "timeout": 30}]}}

config.json 顶层的 hooks 键。install_config_hooks() 把 gate 类注册为同步 shell gate，notify 类注册为后台运行器（守护线程，忽略退出码）。修改在 worker 下次重启时生效。

turn.stop 续跑循环
  • 每个完成的顶层对话轮次后，continue_stop_hook_turns 询问 gate。失败或取消的轮次不询问。
  • 被拒绝时再启动一轮普通轮次（dataclasses.replace、source="hook_continue"、INHERIT_PARENT），然后再问 gate。
  • 没有次数上限：第一次之后的询问里 stop_hook_active 都为真，钩子据此放行结束，与 Claude Code、Codex 相同。
  • Goal 轮次不走这条路径：goal() 自带完成判定，/goal clear 可以停止。
  • Head 移动仍由正常的 TurnWriter 路径负责。
