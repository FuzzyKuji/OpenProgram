One runtime, one session

CallEffect
create_runtime()Open session
runtime.exec()Send one request in it
runtime.close()Close session

No reset() or new_session(); a new session is a new create_runtime(). Two independent conversations need two runtime objects, which is rare.

Why one Runtime does not reuse sessions
  • CLI providers keep session state in the subprocess; reuse would hang a mutable current session id on the Runtime and invite concurrency races.
  • API providers are stateless; multiple sessions would be an upper-layer dict, no new capability.
  • ContextVar injection relies on a runtime bound to the current function tree.

The runtime is injected through a ContextVar

An Agent method without runtime= reads the _current_runtime ContextVar. An entry function with neither calls create_runtime(), and closes it at exit. A child inherits its parent's runtime.

RejectedWhy
Explicit runtime: Runtime in every signaturePlumbing unrelated to the function's logic, repeated at every nested call
Module-level singletonShared across threads and coroutines, so concurrent agents step on each other. A ContextVar is isolated per thread and coroutine.

Two Runtime classes would need two implementations per function, breaking “functions describe the task, providers describe the channel”. One conditional is the cost.

Retry lives in the runtime

exec() / async_exec() have max_retries, default 3 (OPENPROGRAM_MAX_RETRIES), for every provider. Providers only send and receive; retry, throttling and caching are runtime concerns.

  • One policy for network timeouts, rate limits and 5xx.
  • One failure format: Attempt N: ErrorType: msg.
  • TypeError, NotImplementedError and ImportError are not retried: a provider bug or missing subsystem does not go away, and burning the backoff schedule only delays the failure.

Two writes rather than one on completion: the visualizer shows a running call at once, and an exceptional exit still has a node for the error.

Embedding seams

The core runs inside hosts that are not OpenProgram (Embedding in your own stack). tests/component/runtime/test_standalone_embed.py executes the contract:

  • import openprogram and a full Runtime(call=...).exec() round trip do not pull in webui, FastAPI, Uvicorn or Textual.
  • With SessionStore(root_path=...) + session_scope(store, session_id) the run never consults openprogram.state.paths; with no store it persists nothing.
  • A standalone run starts with a principal drawn once per process and never stored, with the owner tier. It becomes the profile's owner when it is handed a profile runtime or sends a request to the profile's model. A run on a host-supplied call=, wherever the host creates it, reads no owner.json.
