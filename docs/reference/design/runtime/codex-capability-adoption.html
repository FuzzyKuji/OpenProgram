Adopted

SubsystemDecision and reason
openprogram permissions check, testRead-only explanation and self-test of permission rules with the original matcher. Enforcement unchanged.
Command network domainsOptional, macOS: authenticated local proxy plus Seatbelt. Default networking unchanged. Private destinations rejected. Linux and WSL refuse execution in domain mode.
execution.prevent_idle_sleepOff by default. One handle per active execution, released on completion, error or cancellation: an IOKit assertion on macOS, a system-required power request on Windows, a systemd-inhibit lock on idle and sleep on Linux. Display sleep is unaffected; on Linux a suspend the user asks for waits too. Read at the next execution. Failure to acquire logs a warning; the task continues. A resource lifecycle around dispatcher execution only.
bash sessionsSee execution below.
executionbash follows unified_exec's exec_command: it yields after yield_time_ms and a running command continues as a session that write_stdin polls, interrupts or types into (tty), with Codex's 64-session cap and LRU pruning. Sessions run on the existing managed-process supervisor, so they survive worker restarts. zsh forks and shell snapshots are not adopted. See command sessions.
networkBaseline shell sandbox has a network boolean; safe_http protects managed HTTP clients, not arbitrary command sockets. Per-command OS-enforced destination domains are missing. Retain optional macOS managed proxy; default network modes remain unchanged.
powerNo baseline power assertion or sleep inhibitor found in runtime, desktop or scripts. Separate opt-in runtime power assertion is an independent missing capability; no display wake or permanent power-setting changes.

Not added: context, patching, environment filtering, project instruction hierarchy, context-remaining tools. Existing implementations stay.

Overlaps, left unchanged

SubsystemDecision and reason

runtimeDurable execution, programmatic calls and cancellation already exist. A JavaScript/V8 runtime or different execution transport would overlap, not fill a missing product function.

memoryPersistent memory, archived sources and consolidation exist. Foreign memory formats and passive screen memory expand that existing system and are excluded under the no-overlap rule.
permissionsExisting rule enforcement, approval and model review remain unchanged. Only a separate read-only rule explanation/self-test CLI is retained.
sandboxExisting Seatbelt and bubblewrap/WSL enforcement overlaps these mechanisms. Native Windows and Landlock are alternate implementations, not adopted.
providersModel discovery, credential sources, proxy-aware HTTP, failover and transport already exist. OpenAI-specific payload compression and infinite retry policies are overlapping/provider-specific behavior; no replacement.
multiagentChild agents, message delivery, durable jobs and goals already exist. Do not add a second collaboration or goal subsystem.
mcpMCP tools/resources/auth and resource interfaces exist. Protocol revisions, MCP Apps and endpoint overrides extend overlapping integrations; not automatically migrated.
discoveryTool discovery, marketplace installs, plugin hooks and skills already exist. Recommendations, sharing and dependency convenience features overlap these systems; leave them unchanged.
interactionQuestions, owner responses, queued follow-ups and messaging exist. Async variants and mention UI are overlapping interaction behavior.
webWeb search, image viewing, browser tools and GUI control exist. Provider-specific external/full-CDP variants are not new standalone gaps.

desktopWorker supervision, chat, scheduled work and updates already exist. Transport/daemon variants remain unchanged.
diagnosticsUsage accounting, execution observation and health diagnostics exist. Plan-allowance history and internal Responses metadata are provider-specific or overlapping.
hooksExisting hook/gate system remains unchanged; no new compaction gate in this scoped migration.
guidanceAgent workspace instructions, time/environment context, rendering guidance and bundled document dependencies exist. Project-rule hierarchy and a context-capacity tool overlap these existing abilities and are removed from the candidate.
waitWaiting/polling/scheduling already exists; no duplicate sleep tool.

Acceptance

Through the public entries: CLI rule explanations and assertions, sandbox command restrictions, configuration and the real dispatcher lifecycle. Covers disabled defaults, cleanup on failure, independent concurrent assertions and unsupported platforms.

Sources and limits

Official Codex source: codex-rs/features/src/lib.rs, codex-rs/cli/src/main.rs, codex-rs/core/src/tools/handlers/mod.rs, codex-rs/utils/sleep-inhibitor. Covers public capability entry points of a pinned snapshot, not every Rust crate or closed service, and claims no parity with current Codex products.
