分支命名

分支名称跟随当前对话端点；显式分叉使用另一端点。Rewind 保留当前分支身份和名称，端点可以暂时停在已有兄弟分支的共享祖先上。主干没有合成的 main 名称，规则与其他分支相同。

谁优先

层级来源加锁自动命名可否覆盖
最高用户重命名（rename_branch、分支面板、/branch <名字>）或用户请求的 LLM 命名（auto_name_branch、/branch、TUI /branch rename）设置 name_locked否
spawn派生任务的标签，准入时就记在这次运行将写的回复（<job>_user_reply）上，所以运行期间代理列表和 Activity 就有名字；结束时只在分支还没名字时再写一次否写回检查通过时可以
自动到阈值时的后台 LLM 名称否可以
兜底head_msg_id 前 8 位十六进制否有存储名称即替换

名称受不受保护，取决于是不是用户要的，不取决于是不是 LLM 写的。

分支上的一轮

  1. finalize_turn后台轮次跳过，它们的分支结束后隐藏。
  2. carry_branch_entry有分支记录的分支，条目已随这一轮写下的每条消息移动（选中分支用 follow_line，其他分支用 carry_branch），并与新 tip 上已写的条目合并，所以一轮中途改名不丢计数。没有分支记录的线，由这里把条目从这一轮延伸的 tip 移到新 head，名称、锁和计数器跟着分支走。普通分叉点不动，分叉重新开始。Rewind 后继续发送则继承当前分支条目，即使已有兄弟分支也不丢失名称、锁和计数器。
  3. maybe_auto_name_branch已归档则停止；否则不论是否锁定都 turns + 1，已锁定的分支不起自动名字。
  4. turns 为 1、6、16、40后台线程：最后 6 条消息，最多 2000 字符，2 到 6 个词，上限 40 字符。
  5. 写回重读条目，已锁定或已归档则丢弃（写锁内在记录上再查一次锁）；否则写入并刷新 branches_list。

状态

branches: {
  <head_msg_id>: {
    name, created_at, updated_at,
    auto_named: bool,
    name_locked: bool,
    name_gen_count: int,
    turns: int,
  }
}

存在会话 meta.json，由 set_branch_name 合并写入，只改名称不会丢掉锁和计数器。所有写入者都在会话写锁内对盘上记录合并（分支记录）。写给分支已经越过的 tip（上一条回复，或这一轮自己的消息）的写入，落到分支现在 tip 上的记录。

显示位置内容
分支面板名称，否则短 id（graph/branches.py）
DAG 徽标名称，否则用户在该分支上问的文字，否则短 id（dag/render/labels/badges.ts）

对话内容放在 <branch> 标签内，并要求当作数据，消息无法借此改分支名。

边界

  • 标签仍保存在会话元数据和分支引用里，不另建命名注册表。
  • 分支命名不改变会话标题，也不改变 DAG 父边。
