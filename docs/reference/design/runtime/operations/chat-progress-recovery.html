Chat progress recovery

The dispatcher persists ordered thinking, text and tool blocks in extra.blocks on the owning assistant placeholder while generation runs. Session loading reads them the same way as completed turns.

CaseBehaviour
Stream tapAccepts only the owning session and message identity; nested runtime events keep their own storage
Text deltasCoalesce within adjacent blocks
Tool resultsUpdate their matching block
SuccessFinal persistence stays authoritative
ErrorMetadata merges with stored progress; blocks stay, with an error notice added
During a readstream_event and transcript_update frames for that session wait behind the read's reply and arrive in order, so a read captured earlier cannot undo an error. The error reaches the row as a transcript update; the terminal chat_response only ends the run
ReasoningOnly thinking events already shown live
