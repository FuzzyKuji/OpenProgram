Branch naming

A branch name follows its current conversation endpoint; an explicit fork uses another endpoint. Rewind preserves the current branch identity and name, even when its endpoint temporarily rests on a shared ancestor of an existing sibling. The trunk has no synthesized main name and follows the same rules.

Whether a name is protected depends on whether the user asked for it, not on whether an LLM wrote it.

One turn on a branch

  1. finalize_turnSkipped for background turns; their branches are hidden when they end.
  2. carry_branch_entryA recorded branch's entry has already moved with each message the turn wrote (follow_line for the selected branch, carry_branch for another), merged with any entry written at the new tip, so a rename mid-turn keeps the counter. For a line without a branch record, this moves the entry from the tip this turn extended to the new head, so name, lock and counter follow the branch. An ordinary fork point stays put; the fork starts fresh. Continuing after Rewind carries the current entry even when a sibling exists, preserving its name, lock and counter.
  3. maybe_auto_name_branchStops if archived. Otherwise turns + 1, locked or not; a locked branch gets no automatic label.
  4. turns in 1, 6, 16, 40Background thread: last 6 messages, at most 2000 characters, 2 to 6 words, capped at 40 characters.
  5. Write backRereads the entry and discards the label if it is now locked or archived (the lock is checked again on the record inside the write lock); otherwise stores it and refreshes branches_list.

State

branches: {
  <head_msg_id>: {
    name, created_at, updated_at,
    auto_named: bool,
    name_locked: bool,
    name_gen_count: int,
    turns: int,
  }
}

In session meta.json, written by set_branch_name, which merges so a name-only write keeps the lock and counters. Every writer merges on disk under the session write lock (branch records). A write addressed to a tip the branch has since moved past (the previous reply, or this turn's own message) goes to the branch's record at its tip now.

Boundaries

  • Labels remain in session metadata and branch references; no separate naming registry.
  • Branch naming changes neither the session title nor the DAG parent edges.
