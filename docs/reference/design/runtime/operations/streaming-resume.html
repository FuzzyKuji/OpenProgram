Reconnect

A session load returns the saved rows, then running_task for the live run:

{ "type": "running_task",
  "data": { "session_id", "msg_id", "func_name", "execution_id", "status_version",
            "started_at", "display_params", "partial_tree": null,
            "stream_events", "status", "reason_code", "run_seq" } }

Frames are per session; run_seq orders them so a late frame cannot revive a closed slot.

Rows and live trees arrive as numbered transcript_update changes: a function run's tree as a row_patch, a model-issued call's tree in its reply's callRoots. A reloaded tab reads first and then follows the updates; a missed update or a text frame past the row's text makes it read once more.

Worker restart

A new worker has nothing running, so startup reconciles every session, archived ones included, on a background thread. There is no age threshold.

NodeResult
runningBecomes interrupted
cancelling, owner deadBecomes cancelled
cancelling, owner aliveCancellation resumes
Has an open durable waitStays resumable
Execution still activeLeft to the execution

Continuing an execution after a restart is the job of openprogram/runtime/execution/restart.py, within execution.auto_resume_window_seconds.
