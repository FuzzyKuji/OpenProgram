文件变更、Review 与恢复

Undo、Revert、Rewind

撤销最新轮次撤销这一轮回退到这里
范围当前分支的最新轮次某一历史轮次源分支上所选检查点之后的后缀
文件所有文件通过预检后恢复后续没有同路径依赖且摘要一致时才恢复从日志投影目标状态，在持久意图下应用
对话HEAD 和全部消息不变不变创建并激活稳定的目标分支
分支不创建也不移动HEAD 不动源 ref 和 HEAD 不变；后续消息接在目标分支上
冲突任一路径不一致，整个操作被阻止不做自动反向合并任一不可恢复项都会阻止
之后追加撤销事务；卡片显示 Reverted；预检通过时可 Redo当前分支 Review 折叠该撤销；预检通过时可 Reapply预填原提示；显示对齐状态

轮次卡片显示适用的 Undo 或 Revert；用户检查点打开 Restore 面板。Redo 和 Reapply 是新事务，没有线性 redo 栈。对话记录不提供分支操作；Copy conversation 在对话的 ⋯ 菜单里。

事实来源

  1. 可信修改工具write、edit、apply_patch、经验证的适配器

    普通 Bash、外部写入：无回执，无轮次 Undo

  2. 修改日志提供本轮和当前分支 Review
  3. Git 工作区提供工作区 Review
  4. 历史规划器读取这三者和对话 DAG；只有日志能授权恢复
  5. 持久意图加锁、应用、校验，需要时再移动 HEAD

Bash 可以在沙箱或 worktree 中运行。Git 显示当前变更，但不证明它们属于哪一轮，也不授予 Undo。

Markdown 标题导航

键
取自可见的行内标题文本：保留 Unicode 字母和数字，转小写，去掉 _ 和 - 以外的标点，连续空白变成 -。为空时用 section。
重复
取第一个未使用的数字后缀，单次解析内唯一，也考虑与显式编号名的碰撞。每次渲染重置。
裸 fragment
百分号解码一次；只按标题键属性搜索来源文章，绝不拼入 CSS 选择器。无效或缺失时不滚动。
跨文件链接
经现有目标解析器和授权打开路径保留 fragment
段落请求
临时视图状态，不进入 CenterTab、标签历史、快照和窗口迁移载荷。包含唯一序号、物理标签 id、预期文档身份和 fragment。
段落请求细节
  • 项目文件打开使用解析后的实际目标 id，包括历史复用的标签。附件预览使用解析后的文件预览 id，而不是可能仍停在聊天的 activeId。
  • 被拒绝的自动打开不创建请求；已接受的无段落打开会清除旧请求。关闭或改指向使其失效。消费时比较序号，旧渲染不能移除新请求。
  • PersistentFilePanes 为每个文档身份保留一个物理 DocumentWindow。段落请求把活动别名选为首选宿主，绝不创建第二个 DocumentController。
  • 请求作为视图上下文经过 FileTabPane、DocumentWindow、FileViewer、TextViewer，保留授权。它把源码模式切到预览而不丢弃未保存字节，并等待该草稿或版本渲染完成。
  • 所选历史版本中的链接使用该版本的标题。附件路径保留只读标记和原会话。
情况要求的结果
Unicode、行内文本、重复标题、代码围栏键稳定且唯一；只有标题参与
两个已挂载文档有相同标题裸 fragment 只滚动来源文章
跨文件加载或重复同段请求加载期间保留；每个序号在渲染后滚动一次
历史复用 id 或聊天活动时的预览到达实际文件面板
两个别名、未保存草稿、源码模式、所选版本一个控制器和缓冲区；导航正确的别名和渲染版本
被拒绝的自动打开、无段落重开、关闭、改指向、重新加载不应用过期请求

PDF 阅读与批注

布局
文档标签在扁平工具栏之上；可移除的 180 px 左侧栏含缩略图和目录；连续页面。批注行按需出现；窄面板换行，不遮挡正文。
控件
翻页、适合宽度、适合页面、数字缩放、选择、文档内链接、搜索高亮。高 32 px，应用字体 13 px。只显示已实现的工具。
颜色
应用主题 token。参考：ink #202124、toolbar #27272a、canvas #151517、paper #ffffff、divider #414145、focus #4a90e2。
样式表
上游查看器 CSS 限定在 [data-pdf-reader] 内，含根变量，通用类名不会改变外壳
复制
合并排版换行；保留段落和标点；中日韩文本不插空格；保留普通连字符；去掉软连字符。只改剪贴板，只作用于文本层。可见的复选框可保留原换行。
批注
标准 PDF 高亮和自由文本批注，经 DocumentController 富编辑器租约、持久草稿和版本检查保存。草稿字节更新不重建查看器，也不丢撤销栈。历史和附件只读。
禁用
PDF 脚本和外部上传。不在范围内：原文编辑、OCR、页面增删、格式转换。

PDF 运行环境

解码器
PDF.js 6.3.289，模块和 worker 均取自 legacy/build，由同源 /document-assets/pdfjs/ 提供。清单记录版本和发行分支。保留本地 CMap、字体、WASM 和许可清单。
为何用 legacy
兼容代码必须同时在页面和 worker 中加载；只在页面打补丁修不了 worker。现代构建需要 Uint8Array.prototype.toHex。上游：浏览器支持。
外壳策略
connect-src 'self' blob: 让解码器通过 object URL 读取保留的版本。外部 HTTP 和 WebSocket 仍被阻止；blob 脚本、eval、object 和第三方 frame 仍关闭。
查看器参考
viewer 源码、PDF Expert 功能。不使用 EmbedPDF：第二个渲染引擎对阅读、高亮和批注没有帮助。

主题行为
默认构建App、runtime 和 Python 构建都不包含也不下载 Office 资源。PDF 独立。

失败继续使用之前选定的资源包；删除临时下载
安装之后当前 worker 无需重启即可提供，文档自动打开。关闭文档会停止它的请求；已请求的安装可继续完成。
旧资源包profile 资源仍可用；旧版本 App 内置资源不再选用。开发暂存是独立命令，普通构建忽略。
隔离独立来源，只允许资源树 GET 和 HEAD；不能访问主 API、鉴权或 WebSocket。两侧页面校验来源、实例、请求。宏默认关闭。没有独立来源的远程部署禁用编辑。

销毁固定的 mount 和 activate API，关闭时立即销毁待启动宿主。AbortSignal 在有界期限内取消可用性检查和激活。失败实例绝不挂到控制器。
不提供通用扩展注册表、自动更新、卸载控件、第三方上传

前进与后退

每个标签页有自己的页面历史：文件夹 A、子文件夹 B、文件 1、文件 2。后退后打开新位置会替换前进历史。文件夹恢复路径、展开和滚动；文件保持自动保存。

只有显式定位、搜索导航或恢复会移动视口；列表分页、后台刷新和大小更新不会。导航历史绝不与文件版本 History 混合、写磁盘或轮询。

版本生命周期

情况存储显示
一轮内多次修改保留最初的 before，更新 after。新版本提交后才替换记录。一个净变更
保存被中断待确认标记。不推断成功，不从磁盘编造 after。未完成，无法精确恢复；绝不显示“无变更”
已取消且确认未提交标记为 aborted无变更
清单损坏或不支持保留；不创建空历史，不覆盖明确错误。只有清单确实不存在才算无记录。
重新打开会话同一批持久记录；不依赖脚本输出或内存相同文件，可 Undo 或 Reapply
文件后来被修改不变阻止恢复，保留后续修改
保存顺序与发布
  1. 把每个 before 和 after 写成独立完整的文件；校验；fsync 版本目录。
  2. 发布清单。更新失败时已引用内容不变；失败的尝试绝不覆盖已发布版本。
  3. 只有明确取消失败的尝试后，重试才重新读取当前文件作为 before。成功的修改始终保留本轮最初的 before。
  • 普通文件快照在读取前后比较描述符元数据，在打开前和读取后比较路径元数据。
  • 设备号和 inode 必须一致；来自不同操作系统 API 的元数据绝不当作同类比较。任何变化都中止发布。
  • 存储的模式取自路径观测。
  • Windows 上的旧版迁移在刷新前以可写方式打开暂存文件，并保留源文件直到发布成功。

旧清单和 blob_ref 无需批量重写即可读取。丢失的历史不重建。系统崩溃和无视锁的外部程序可能需要手动恢复：保留证据，拒绝不确定的覆盖。

发布文档：write(file_path, source_path=...)
  • content 和 source_path 二选一。来源是有读权限的本地普通文件，上限 64 MiB。路径相同、目录、链接、过大或不可读的来源在修改前失败。
  • 目标保留写授权、读取基线和审批指纹。来源和目标指纹都参与审批等待，发布前再次校验。
  • 字节先写入目标目录的完整临时文件，再替换。失败时清理并保留目标。写原始字节，绝不做文本转换。
  • 建议锁只串行化配合的写入者。Windows 替换前关闭缺少删除共享的句柄并再次校验；没有操作系统级条件替换。
  • 先读：模型读原文件，再生成暂存版本。二进制读取返回类型和字节数。新文件无需先读。
  • 生成器都走这条路径；文本工具保留 write、edit、apply_patch，共用 prepare、commit、abort。CheckpointStore 持有状态；Review 和摘要是投影。
  • 不提供：Word 修订、PPT 可视差异、Office 语义差异、远程存储（声称可恢复前需要条件写入和可校验的版本 ID）、全盘扫描、轮询、插件注册表。
人工编辑、自动保存与编辑器生命周期
主题约定
共用路径人和模型的写入共用版本校验、完整文件发布和不可变的前后版本。project_file_write 幂等记录保存结果和指纹，不保存版本。
归属人工记录使用 actor=user；模型记录链接真实会话和轮次。不伪造聊天轮次；人工历史绝不变成侧栏会话。History 按文件聚合；轮次 Review 保留归属。
保留人工项目修改归项目，模型记录归会话。聚合索引引用版本，不复制。归档会话仍可读。永久删除会移除所属版本，缓存不得再显示；记忆来源显示“原会话已删除”或失去链接。项目文件和人工历史在聊天删除后仍在。移动的项目按当前位置恢复；离线时只读。旧历史分批回填；无法确认归属的显示不可用。
自动保存编辑器撤销处理即时修改。草稿先持久化；文件在短合并窗口后发布，绝不等待历史周期。每次发布校验读取版本；重试幂等；迟到响应不能覆盖更新的草稿。失败保留草稿和可重试错误，不关闭标签。
历史周期连续编辑间隔约五分钟。切换文档、结束编辑或恢复也会结束周期。重启读取记录，绝不读当前文件。
富编辑器与标签无关：视图隐藏时导出引擎继续存活，最新内容进入持久草稿后才释放。Office iframe 不因 React 重挂载或 DOM 移动而重建。关闭、重命名和恢复等待最终导出；失败保留编辑器和草稿。预览和编辑共用实例；历史实例不能写。重命名期间禁用编辑，成功后重新打开新路径。

修改日志

每轮一个清单，由 CheckpointStore（openprogram/state/store/snapshot/checkpoint/）管理。每个文件条目：

path、operation
create、modify、delete、rename
before、after
{kind: "regular", digest, blob_ref, mode, size} 或 {kind: "absent"}
status
prepared、committed 或 aborted，带 prepared_at、committed_at
stats、diff_state
增删行数、是否二进制；available、large、binary 或 timeout
recoverability
exact 或 unavailable，带 unavailable_reason
mutation_sequence
持久且单调；多轮折叠用它，而不是 DAG 顺序
不变量
  • prepared 在写入前持久化；确认 after 状态后才 committed。准备失败时修改工具在碰磁盘前停止。
  • absent 表示已确认不存在。读取基线失败记为 recoverability=unavailable，绝不记 absent。
  • unavailable 只用于已记录、因大小或类型策略省略内容的修改，不用于掩盖日志失败。
  • 同一轮同文件的修改折叠为最初 before 到最后 after 的净变更；重命名保留谱系。普通文件的前后都保留内容引用。
  • 路径在捕获、规划和应用时重新规范化；用已校验的句柄或 no-follow 原语检查父链、叶子 lstat、设备、inode 和链接数。
  • Revert、Restore、Reapply 也是事务；原记录不可变。当前分支只折叠活动谱系。
  • 每个提示定义 before_turn，assistant 完成定义 after_turn；界面明确显示恢复的边界。

三种 Review 范围

范围来源包含恢复
本轮某 origin 轮次已提交的变更集父轮变更集加所属子任务，各保留自己的 producer 轮次，去重，显示执行者Undo 或 Revert：闭包内都有精确回执，执行者已结束，摘要一致
当前分支活动谱系的日志投影所有轮次和显式 revert、rewind、reapply；不含兄弟分支和外部写入从具体轮次或检查点发起；没有一键分支 Undo

Rewind

一个计划，一个事务。WebSocket 的 phase 默认 plan；apply 需要 plan_hash 和 idempotency_key。计划状态：ready、unavailable、blocked、stale_plan、error。意图终态：committed、rolled_back、recovery_required、aborted。

阶段规则失败时
解析谱系从 HEAD 沿 predecessor 到目标非根用户轮次；子树只通过显式归属纳入不在活动分支上：拒绝
目标状态每个发起一轮的 prompt 有一个 checkpoint：.file-recovery/<session>/checkpoints/<user_msg_id>.json 记录每个被跟踪路径的状态，内容在共享的 blobs/<sha256>。没列出的路径取其后第一次编辑前记录的状态。没有 checkpoint 的 prompt（旧会话、运行中插入的消息）在读取时折叠 journal，不改写数据。捕获失败不阻塞工具，该路径记为 unavailable。没有可用备份的 prompt（evicted、journal_gap、no_checkpoint）对代码模式返回 unavailable，仅对话仍可用。
计划行每个目标和磁盘上的文件比较：restore、delete 或带原因的 skip，附 +A −D（单文件 1 MiB，总预算 3 秒）。Bash、手动、hunk Revert 和 Undo 的变化被覆盖恢复。规划不写任何东西，session 有 run 时也不跑崩溃恢复。按文件跳过，其余继续：other_session（目标状态读取之后，另一会话开始或完成过可信写入；读自 mutation-locks/last-writers/ 下各会话最新写入的按路径索引）、changed_since_edit（没有 checkpoint，文件已和 journal 不一致）、unsafe_path、parent_missing、no_backup、changed_while_reading。自有 job 运行中时以 job_running 阻止。
准备意图占住 run 槽位，把每个计划路径的当前内容存成 blob，journal 没见过的变化也能回滚；持久化计划 id、预期 HEAD、前后镜像、模式、跳过行；幂等在工作区锁内重建计划，hash 不同返回 stale_plan，零写入
应用工作区锁；持久化每个动作的状态；原子替换；摘要一致才删除只有摘要仍等于本事务写入的值才回滚；否则 recovery_required，保留外部内容
分支先建稳定的目标 ref，再用预期 head 的 compare-and-set 激活。首轮之前的目标使用持久 ROOT。按意图恢复文件；源分支和活动分支不变
收尾追加事务和导航事件；不标记旧节点；推进 writer epoch，旧任务无法写回启动时完成或回滚未结束的意图，绝不猜测

多文件恢复不是文件系统的单次原子操作。保证来自持久意图、回滚暂存、逐文件原子替换和重启恢复。数千文件的预检分页列出冲突；开始应用后只能完成或回滚。

过期返回 STALE_SNAPSHOT 或 STALE_CURSOR；客户端从第一页重新开始。

游标与工作区快照
  • 游标不透明，只对相同快照、归属、查询类型、筛选和排序有效。拒绝偏移量、路径锚点和跨项目 token。目录、搜索、Review 列表和差异的游标不能互换。
  • 快照保持候选顺序稳定。后续页绝不重新扫描。容量和 TTL 淘汰时报告过期。
  • 工作区快照按相对路径固定已暂存、未暂存、未跟踪以及重命名或删除的路径，钉住 HEAD 基线、index 内容、worktree 身份和新旧路径。差异由该内容对渲染，绝不用后来的 git diff。
  • 取后续页或差异前，重新读取状态向量、index 树和 no-follow 的 worktree 身份。任何变化都算过期。
  • 工作树一侧按 Git 的方式比较：当 text、eol 或 core.autocrlf 清理行尾时，先把 CRLF 转为 LF（auto 时仅当索引 blob 不含 CR），所以 LF blob 的 CRLF 检出只显示编辑过的行。
  • 按块还原时使用文件自身的行尾。
  • 快照内容共用 Review 配额；缺失或过期报告过期，绝不从 worktree 近似。
