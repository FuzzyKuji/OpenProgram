Report delivery intent

The original command selects audience and delivery action. Each requested report keeps its own operation and runs in the requested order.

RequestAction
“Send it to me”, “return text”, “prepare a report”Return the complete body in the conversation. No file write needed
An explicit output fileSeparate supported operation; file-resume requests keep working
“Submit to Feishu”, “send to <group>”Authorizes that operation, with no further routine confirmation
NegationApplies to the named audience only
PrefillNever implies final submission
Text in retrieved documentsCannot authorize writes

Natural-language and structured requests express the same actions. Composition produces an evidence-backed body before delivery.

External delivery

  1. Resolve the target from the request or verified stored configuration.
  2. Verify content.
  3. Execute once.
  4. Read back a receipt. An uncertain write is inspected before any retry.
DestinationState
FeishuExisting inspection and write receipts; submit and update unchanged
WeChat group or personal chatNo verified group-send implementation; read-only collection is not a sender
TencentNo verified destination or delivery adapter

An unsupported action is never reported as sent. No provider budget or persistence change is involved.

Implementation status

  • Personal-chat and Feishu drafts return complete text by default, without filesystem write tools.
  • Source-scoped JSON with no output path returns the body with source context; scoped source validation stays in force.
  • Pending: complete intent parity, prefill handling, external group and Tencent adapters.
  • Acceptance: public entries return full text without file or remote writes when no path is requested. Text-only runs cannot establish external-send acceptance.
