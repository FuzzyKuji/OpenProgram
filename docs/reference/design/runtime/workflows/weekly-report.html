Execution

  1. Classify the request.
  2. Draft, or inspect the form read-only and strictly validate the first-line state.
  3. Compose all new-entry fields, or the specified edit fields. JSON Schema with provider prompt fallback and Runtime format repair; unknown fields and missing required content are rejected.
  4. Write in the browser and observe success.

Fill failures and field binding
  • The first failure recorded by the guard is kept, including cancellation while waiting for its lock. A later native, parse or page-identity error cannot replace it.
  • After any write attempt, an ordinary error becomes a nonretryable UnknownWriteOutcomeError: no replay, no FILLED. Before a write it stays a browser-stage error with its cause. Cancellation and other BaseException signals propagate unchanged.
  • Contenteditable fields keep their native role and inner_text value source. Native or ARIA labels win. Otherwise only a complete native container binding to an exact known field counts: one visible leaf label and one editable control within twelve ancestors.
  • Diagnostic ancestor text and current names or values never identify fields. Ambiguous, truncated or redacted bindings stop before writing.

Original evidence

Requests, plans, drafts, checkpoints, assistant narratives, compaction summaries and generated memory notes never establish completed work. Default period: current ISO week in Asia/Shanghai.

Natural-request gate
  • A per-run wrapper around read_conversation keeps its name and schema. Only completed real reads qualify: the renderer repeats the same session, branch, range and budget, and its transcript must equal the visible receipt.
  • Defaults match the native tool: max_chars=0 uses the 1,000-character minimum, not the 60,000 default.
  • Native read errors keep their receipt and add no sources, including the textual error protocol.
  • Failed or cancelled tool receipts support only that failure or blocker; missing status stays unknown. Status comes from original persisted metadata.
  • Rows keep canonical session and node reference, timestamp, week, original text and visible quote.
  • Explicit user-supplied evidence keeps its scoped path. Inspection needs no composition. Name fields and intentionally empty fields need no evidence; partial edits need sources only for changed content.
Reporting period and current input
  • The period belongs to this report's audience, resolved from the whole request and independently checked against audience and local date. A period meant for another report does not apply; audiences may use different weeks.
  • Node dates decide source membership after resolution.
  • Current owner input keeps its actual timestamp. If it explicitly reports an earlier week it may support that period after verification; this does not widen historical retrieval.
  • Generated function narratives stay lookup-only by their persisted provenance.
Priming records and recomposition
  • Program-origin discovery and reads are persisted as code children of the report function through the nested-tool helpers and bound SessionNodeWriter, with source weekly_source_prime and original IDs, arguments, results, outcome, exposure and timestamps.
  • The event stream is consumed to its end before composition. No provider or LLM node is fabricated.
  • A bound writer with a missing parent or failed persistence stops composition; standalone read-only use keeps optional history.
  • A crash leaves the call unfinished. A new composition re-reads and revalidates; no old source capability is restored and exactly-once writes are not claimed.
  • A partial edit whose retained nonempty research content lacks mechanically valid bindings gets one bounded prime and one recomposition, preserving exactly the retained field set. Semantic rejection of valid references causes no retry. Inspection, clear-only, identity-only and structured materials force nothing.
  • Program-origin receipts stay separate from provider tool blocks. Titles and listed sessions prove nothing.

Content format

Work items and plans contain only supplied or verified facts, numbered when that helps. Form dimensions (implementation, experiment, result, baseline, writing) are optional suggestions: no five-item minimum, no empty headings.

  • Missing-source notices, placeholders and verification comments belong in diagnostics, not the body. Before verification or delivery, a narrow check refuses the standalone missing-record placeholder, including with a numbered dimension label; it never deletes or rewrites lines.
  • Real incomplete tasks, failed attempts and blockers stay reportable with their support.

Owner source across spawned programs

The personal entry runs in a spawned process and its request stays non-interactive. A separate immutable reference carries only the parent's canonical current owner message, captured from the admitted turn: session, message ID, exact input, principal, owner authority, store identity and owning execution.

The child resolves it only against the same execution, principal, session and store; all source checks still apply. Missing, foreign, assistant, replayed or other-store references provide nothing. No tool argument grants owner authority.

Acceptance

  • Public entries execute both conversation tools. Tencent collect returns current-week owner messages only; invalid material types give input errors.
  • Fill-only intent, pre-execution blocking, rejection of old frames and wrong pages, and real isolated DOM readback with zero submit events.
  • Composition from a real owned evidence gate with controlled provider replies: filler cannot reach a draft or write; supplied items survive; fabricated IDs, altered quotes, unsupported facts and wrong periods are rejected; a row added by a real read stays usable.
  • Controlled tests prove neither Feishu availability nor submission. A live write needs a success receipt on the same page.
