周报 Workflow

周报产出外部写入
personal飞书个人表单飞书，受现有闸门约束
personal_chat所有者发到微信群的三段式文本从不
group从微信读取其他成员周报并汇总从不
tencent每周五下午约 100 字的进展从不

包结构

weekly_report/
  workflow.py             唯一公共入口 weekly_report(task)
  steps/routing.py        只放 Agent 提示词
  reports/<report>/       各周报的角色、步骤和 README
  tests/<report>/
openprogram/programs/_authoring/reports/   共享的来源、输出、检查点、微信模块

只有根目录的 PROGRAM_ENTRIES 注册工具，Abilities 只显示一个入口。内部模块不列出。发现只支持一层分类目录，拒绝符号链接和重复项，仍需来源授权。授权的外部目录中的函数按所属目录得出 UI 路径。

路由

weekly_report 调用 Agent，根据完整语义、否定和上下文选择周报，绝不按关键词或冒号拆分。代码只校验目标枚举并原样转发请求：不摘要、不截断、不追加只出草稿的限制。

请求运行子流程收到
写我的个人周报，腾讯只是参考，不用小组周报只有个人周报完整请求
个人和腾讯都做，小组不用这两个同样的完整请求
全部都做全部，没有共同周期或恢复状态同样的完整请求
受众不明确personal_chat，不发送的发现草稿；绝不澄清完整请求
  • “组里的周报”是 personal_chat。group 指收集其他成员的周报。
  • 单个结果原样返回；多个结果加受众标签。失败的子流程显示 未完成：<error>，其余继续；全部失败时才抛出第一个异常。取消立即停止并附上已完成的结果。
  • 没有共同的周、检查点或完成状态；各子流程管自己的材料、输出和恢复。旧路由检查点不能恢复：通过 requests 传入子流程的恢复请求。
  • JSON {"requests": {"tencent": …}} 直接指定子流程；result_format: "structured" 返回 results 映射，不声称整体完成。
  • 各周报只解读自己的部分。腾讯把原文存入 user_request 供后续模型使用，材料只允许原文摘录。小组提取保留完整请求用于来源选择。

来源周和旧草稿

  • 执行周不一定是来源周。记忆候选保留说话者类型和来源日期。导入时间绝不把旧聊天标成本周。
  • 可信的所有者原始记录优先；同等来源在本周内按日期降序。
  • 后来的事实修正只替换冲突部分，独立进展保留。
  • 自动取材绝不把 Workflow 检查点或周报的 sources.json 当证据。带引用链的导出来源只用于审计。
  • 恢复拒绝已失效的检查点。旧草稿周次错误时保留文件和审计记录，使该次执行失效并检索真实证据。材料缺失时返回等待状态，不重发旧草稿。

腾讯内容

方面规则
包含本周的动作、发现、结果和当前问题；同周记录中的方法、对象和观察；实际做过的文献综述和复现
排除方向讨论、会议议程、行政事务、未来计划。引用决定或发现，不引用会议本身。不重复话题列表
不编造已完成、已验证、已提升等状态。有动作没结果就只写动作。相关外部材料不代表用户做过；论文结果和个人复现分开
格式始终以 本周进展： 开头，用编号的动作句。不写“未提供模型”之类的元信息、比喻或口号；未记录指标不等于没有数据
材料够用有记录的优化、提交和验证就够；模型列表和指标是可选细节
只在此时询问没有可用动作，或核心事实无法调和
补充搜索进展过于简略时，最多三个话题词，只搜同周记忆，合并去重后第二次选择。选择至多两次模型调用。结果和预算进检查点，恢复时不重复。每个上下文至多 30 条、18 KB
验证独立检查来源支撑和汇报范围

微信窗口读取

绑定唯一主窗口、PID 和进程启动身份，经 GUI Harness MacWindow / window_session。绝不打开、激活或置前窗口，不用全屏截图或剪贴板，不投递进程定向的键鼠事件。每次操作重新验证窗口和控件归属。

操作规则
输入群名只用原生 AXSearchField
选择群对匹配确切群名和 OCR 位置的控件 AXPress
翻页只用消息区内支持辅助功能翻页的控件；每次至多十二页，不声称历史完整
截图ScreenCaptureKit 的桌面无关窗口。图中标题验证前不持久化
消息需要页内日期和指定成员
不支持的操作可恢复状态；不切换到前台
没有辅助功能窗口（仅截图绑定）SEARCH_UNAVAILABLE；视觉读取器只读当前显示的对话，不搜索、不选择、不翻页
标题验证通过READY，window_controls 不可用，覆盖限于一个可见页
标题未验证CAPTURE_ONLY_GROUP_NOT_SHOWN 并说明原因；不持久化
后台动作被拒绝BACKGROUND_ACTION_UNAVAILABLE，绝不当作已执行
透明图、缺控件、窗口变化、并发使用各有原因和恢复参数。绝不让用户把窗口置前，也不把空捕获说成缺权限

取消或验证失败时也会归还临时截图。Apple 把 NSWindow.SharingType.none 标为旧常量，不用它推断捕获能力。

Agent 执行

Session 工具、结构化输出和超时
  • 新轮次从当前分支的发现状态恢复工具 schema，并与允许的工具取交集。其他 session 和兄弟分支不继承。审批恢复用现有检查点，不扩大权限。ContextVar 随轮次释放。
  • 只读 Agent 通过记忆搜索、目录查找和读文件解读小组请求，找到群和有序成员。用户提供的值优先。没有发送、写入、Shell、浏览器或递归周报工具。无法确定的字段保持缺失。
  • 结构化阶段用 response_format 加 prompt 回退：Runtime 校验 JSON，并在请求预算和超时内允许一次修正。格式错误是模型失败，保留原样重试参数，不算用户缺信息。
  • 工具轮由 max_iterations 约束；成功的工具轮不消耗失败预算，普通调用也不补充它。每轮检查取消和截止时间。
  • 个人字段：只读检索 Agent 返回六个具名字段，由 JSON Schema 校验。完整周报需要非空的本周工作和下周计划；部分编辑只返回请求的字段。来源验证仍决定哪些结构化输入可保存。结果不确定的外部写入不重放。
  • 记忆的 search、grep、get、browse 是只读安全工具，保留 memory.read 和显式的 deny、ask 规则。
  • 超时：模型请求继承 Runtime 部署超时（OPENPROGRAM_EXEC_TIMEOUT_S），没有 90 秒限制。腾讯后续模型阶段保持 180 秒。浏览器截止时间和结果不确定时不重试的规则不变。

实现状态

  • 路由、部分完成和恢复已在已安装的 App 中验证。
  • 真实微信消息读取未完成：对本机主窗口的调用返回全透明图。
  • Session 工具恢复、结构化修正和超时修复在验证中；早先验收暴露了小组模型格式失败和聊天调用缺失，整条流程还不能算正常。
  • 验收需要公共入口的请求保真测试、子流程上下文测试、调用图测试，以及通过普通聊天的本地 App 运行。直接调用函数的测试不能替代失败的聊天调用，阶段测试不能替代真实取材或外部提交。
