常驻 Agent

会话 DAG 按运行时发言身份隐藏内部检查提示及其回复、调用子树，旧记录同样适用。正式报告和普通用户消息继续显示；原始执行记录保留。

常驻是已保存 Agent（AgentSpec）的 always_on 部分；没有助手对象，也没有其他设置。使用该 Agent 的每个对话都是一个助手，有自己的 Goal、检查、未完成事项和报告。openprogram/runtime/conversation/always_on/ 只决定哪些对话唤醒、何时唤醒、唤醒做什么、报告发往哪里。

哪些对话会唤醒

所有者对话
未归档，且是 Web 聊天（source 为空或 web）、渠道对话或旧的主对话（source always_on）。agent 和导入的对话永不唤醒。
已加入
有唤醒状态、在 enabled_at 之后更新过，或刚切换到该 Agent（POST /api/sessions/{id}/agent 调用 join()）
首次唤醒
加入后一个间隔；没有间隔时为阶梯第一档（一小时）
停止某个对话
归档它。每条归档路径都会在 Goal 锁内暂停来源为 always_on、check_in、handoff 或 scheduled 的 Goal（chat.pause_always_on，原因 conversation_archived）。取消归档时恢复它，下次唤醒定在当下；没有可恢复的 Goal 时，已过期的唤醒从当下重新排。普通 Agent 和子 Agent 的对话不受影响。
重新开启
早于新 enabled_at 的 next_wake_at 从该时刻重新计算
旧的主对话
首次记录 enabled_at 时，_adopt_home() 从 <agent dir>/always_on/state.json 复制 applied_goal、last_check_in_at、last_wake、next_wake_at

调度器

ticker.py 随 worker 启动。每次 tick，对每个启用的 Agent：

  1. 补记缺失的 enabled_at。
  2. 列出对话（最多 500 个）。
  3. 结束更早 worker 遗留的检查。
  4. 加入新符合条件的对话。
  5. 唤醒已过 next_wake_at 的对话。

已禁用的 Agent：先以原因 always_on_off 暂停自动 Goal，再清除 enabled_at；锁被占用的 Goal 会让它保留，下一次 tick 重试。开启后的第一次 tick 恢复它们。两种方式同时停住的 Goal 等最后一次撤销。重启保留已保存的计划；每对话一把锁防止并发唤醒。

唤醒

wake(session_id, reason)，用于到期的对话或立即唤醒。记录结果和下次唤醒。第一个匹配的结果生效。未知或非所有者对话（包括试用对话，agent_trial）：WakeRefused。计时器在加入或唤醒前读取对话本身，所以早于该标记的索引行不起作用。

方面行为
Schema按名称给的列表带完整 schema，因为没有 tool_search

失败interrupted 且还没汇报的检查用 check_in.previous_check_in_at 恢复 last_check_in_at，第 9 步因此仍会看到它没看过的内容。除重启打断（boot 不同，或 Worker 停止时未完成）、被人取消的轮次和版本切换期间的拒绝外，每次都累加 check_in_failures；检查完成时静默清零。
失败通知第三次失败，或第一次出现 error_reason 为 auth、authz、blocked 时，在锁外发一条 approval 报告，check_in_failure_noticed 保证只发一次；发送失败的在下次失败时重试。error_retryable 决定措辞，账号类失败不带服务商原文，设了 wake_minutes 时不承诺放慢尝试。在该报告到期前，wake_step 回到 previous_wake_step，若用户消息已重置则保持更低的值；之后阶梯继续上升。
