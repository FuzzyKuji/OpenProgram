统一操作判定

审批清单和执行包装层使用同一判定。

情况规则
Owner 委托的 Agent shell 和托管进程使用接纳时的权限快照，不做一刀切的来源禁止
MCP 调用方、非 Owner 派生的 Agent保留该禁止；worktree 控制保留自己的限制
Bypass permissions跳过普通审批和 Auto 分类。不覆盖显式 ask、deny 规则或插件工具门。Sandbox 打开时命令仍在沙箱内。
非法模式值配置命令拒绝
拒绝说明原因和能力，不泄露机密
Web 答复规范等待命令被确认应用前，问题和所选答案都保留。投递结果未知时锁定选择并用同一命令标识重试；socket 发送本身不算完成。覆盖审批、提问、表单和讨论。

项规则

相对目标相对绑定的 worktree 解析；realpath 包含检查覆盖文件和父目录符号链接。共享文件安全助手对独立相对输入保持当前目录语义。

投递尽力而为，既不授权也不阻塞

模式解析

先取对话设置，再取项目默认，最后 Bypass permissions（DEFAULT_PERMISSION）。解析后的模式用于接纳和界面确认。各模式与判定一起定义。

权限的实时变更

方面规则
状态SessionStore 持有带版本的 permission_state 字典，含模式和 Owner 主体。原子比较并设置防止旧客户端覆盖新选择。没有并行的审批数据库或通用策略引擎。
设置命令WebSocket；认证 Owner，校验会话范围，返回权威模式和版本。冲突保持为错误。
生效点服务器确认时，与进行中的模型请求无关。之后每次普通审批检查都采用，包括同一批次的后续调用。单次调用在分派期间保持判定；已授权调用不中断。无需重启或下一条消息。
Web 和 App立即用已确认版本发送，只有版本未知时才先读。请求中的选择与已确认的模式分开显示；旧确认和水合快照不能替换新状态；传输错误保持可见。
未发送的草稿在本地存选择，不创建会话；首次提交时带上
模式变更时的待审批用统一判定重新评估。现已允许的，经规范等待答复命令解决并从检查点恢复。ask 规则、外发暂扣、沙箱提权和用户提问继续等待。
竞争与重启设置变更期间发布的等待，在旧运行时释放取消令牌后复查。启动恢复重新评估已持久化的变更。过期、取消或完成的工作不会复活。
派生 Agent可信派生接纳时，运行中的 Owner 父级把有效模式和规则写入子级不可变输入，绑定同一主体和确切的运行父级。交互式父级先解析最新确认模式；嵌套的非交互父级传递已冻结快照。已有输入不改写。子级保持非交互：无人批准的 ask 被拒绝；继承的 Bypass permissions 只跳过普通审批。
不接受实时覆盖独立定时任务、已配对频道、无关会话
Plan在工具边界强制，切入后已提议的写入也被阻止。工具目录保持稳定，中途切出不破坏续接。只能从选择器进入；exit_plan_mode 恢复之前的模式。
已存模式没有带版本状态时，可读取已有的 permission_mode
一次性批准自更新和无法表示精确规则的操作只提供单次允许；规范校验强制同一范围列表。答复经服务器确认才算数；重新加载后执行版本必须匹配；允许的范围由服务决定。

沙箱提权

在命令运行前请求，与 Codex 相同：bash 带 sandbox_permissions="require_escalated" 和理由。

方面规则
卡片在 Agent 安全点、任何副作用之前发布 bash:sandbox-escalation 清单；它覆盖普通 ask 本要问的内容
谁批准只有持 approval.request 的交互式本地 Owner。非 Bypass permissions 时，已配对频道、MCP 客户端、cron 和子代理不能提权。
解除可配置的限制；凭据过滤保留
绑定会话、执行、工具和工具调用；普通工具批准不能授权它
对话范围确切命令存在 Worker 内存中，从不写成权限规则，重启后再次询问
没有生效的沙箱请求被忽略
Bypass permissions无卡片直接离开沙箱
运行后才发现的拒绝访问标记，或 sandbox.network 关闭时的域名解析和网络不可达错误，绝不变成事后批准。结果指明应发起的请求。

已批准的文件写入

已批准的 edit、write 和 apply_patch 共用 file_state.write_checked。分派器和该模块在 Windows 上无需 Unix 专用模块即可导入。

方面规则
顺序检查已批准的内容和标识；不截断地打开；取排他锁；对已打开描述符求哈希；复查路径标识和解析后的目标；写入
锁现有兼容适配器（Unix 用 fcntl，Windows 用 msvcrt 字节锁），二进制模式；POSIX 保留 O_NOFOLLOW。移除链接检查或跳过加锁都不满足契约。
复查用元数据，不用第二个读句柄：Windows 字节锁可能拒绝同进程其他句柄的读取
链接拒绝符号链接和重解析项
批准时不存在的目标排他创建
路径回退写入前发现替换；不声称对每种并发祖先目录替换都有描述符级保护

失败与已知限制

  • 身份缺失、版本过期、非法模式、能力被拒、显式规则、分类器失败和沙箱拒绝彼此可区分。任何失败都不会悄悄变成 Owner 或 Bypass permissions。
  • 主机进程可见性可能使 ps、top、lsof 不可用。Docker socket 不会自动暴露。Linux 通配符屏蔽有限制。浏览器和远程网络有各自的控制。

与其他框架的对比
框架采用或改造边界
Claude Code权限模式、独立 Sandbox、Auto 分类身份和显式规则排在 Bypass permissions 之前。其权限有 deny、ask、allow 优先序，规则实时变更和逐审批评论；这里没有实现“先执行、后送反馈”的审批评论。
Codex CLI结构化违规、精确批准后重试。沙箱执行与审批策略分离。没有按工具的沙箱覆盖。其记住的批准是会话级，我们是项目级。域名策略、企业托管强制和远程审计导出在这里没有对应能力。
OpenClaw凭据过滤、后端拒绝、嵌套工具分类不自动选择 Docker
Hermes Agent硬规则先于 bypass、命令规范化、非交互拒绝规范化 NFKC、ANSI、NUL 和环境包装
OpenCode按工具和资源的规则权限不是 OS 隔离。V2 用最后匹配、项目级模式、同会话拒绝扩散和按子代理策略；我们是 deny 优先、精确操作授权、单一规范等待目标、子级接纳受父级约束。属有意差异。
pi-mono扩展拦截、非交互时按拒绝处理拒绝项目静默覆盖全局安全约束
AiderGit 恢复作为独立设施恢复不能替代凭据、网络或进程边界
Goose、WeClaw 适配器明确区分后端拒绝外部自动 Owner 批准，以及把可选隔离当作默认
