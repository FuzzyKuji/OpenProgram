统一系统访问

宿主能力边界，独立于模型工具审批、工作区权限规则、账号凭据和 provider 授权。读取状态绝不弹出系统提示。模型或远程客户端不能授予操作系统能力。

状态和 API

状态含义
granted指定执行者通过了最新检查
not_granted检查完成，macOS 表示没有
unknown检查失败、超时或无法证明身份。不算拒绝
unavailable缺少依赖或原生 API

接口作用
GET /api/system/access报告（schema 2）：平台、主机、执行身份、时间戳，每行含 id、类别、状态、详情、说明、请求方式、设置可用性、操作、恢复元数据
GET /api/system/access/waits未结束的等待，id 和 schema 相同
POST /api/system/access/setup仅限所有者和回环地址。请求所有已注册的原生 runtime 能力，返回一份合并报告
POST /api/system/access/{id}单行：重新检查，可选原生请求，返回新行。open_settings=true 只打开目标，绝不声称已授权

响应禁止缓存，不含机密。前两行保持旧的 screen_recording 和 accessibility 线路格式；旧回执按旧格式读取。未知 id 是客户端错误，什么也不打开。权限规则、Auto 模式、profile、Worker 和端口不受影响。

首次设置和操作

  1. Web 设置按产品领域显示注册表、每项用途，每次加载页面做一次只读检查。
  2. 用户选择“Set up all OpenProgram access”，或某行的“Request authorization”/“Open System Settings”。页面挂载、重连、轮询、历史回放和模型输出都不会发请求。
  3. 后端按执行者串行化原生请求，用指定 runtime 请求后重新检查。macOS 仍可能弹多个对话框，UI 逐项报告结果。
  4. 操作前 Worker 做一次新报告，只为缺失的必需能力创建持久的 system_access 等待。浏览器和 VM 操作跳过。
  5. 回到应用触发只读刷新。授权后等待经 Worker 对账解除，同一执行从检查点继续：没有伪造回答、重试或新执行。
轮次中报告
已确认授权的能力后续步骤不再报告；一次报告要启动进程，约 0.4 秒
有能力缺失每步都报告，授权后立刻看到
轮次中撤销授权桌面后端让该步失败并指出设置项，下一轮重新报告

身份和恢复

  • macOS 的检查和请求都经已签名的 runtime bundle ai.openprogram.runtime。源码检出可回落到开发解释器。已安装的 App 绝不注册裸 python3；匿名的 python3、node 和过期缓存路径都不是身份。
  • 读取状态、启动对账、重试和重复事件都不运行 tccutil，也不重置其他应用。
  • 经验证的过期回执可授权一次针对固定 OpenProgram bundle 身份的显式迁移；系统调用前写入的标记防止循环。其他情况（未验证代码、未知检查、要求未变、辅助功能迁移、其他应用）都走系统设置。
  • 产品不能预先授权从未作为目标的应用、从未选择的路径或已撤销的权限。绝不推断完全磁盘访问，也不把它当绕过手段请求。
  • Linux portal 和 Windows 完整性规则保持平台专属。浏览器和 VM 用自己的 provider 或 session 边界。

信任和并发

  • 只有执行主机上的本地所有者能请求或打开设置。回环和 Origin 检查必须通过，转发请求和远程客户端被拒绝。模型可以描述缺失的能力，不能调用设置接口。
  • 探测在新的有界进程中运行，每轮对账共用一份报告，不枚举屏幕内容。
  • 等待解除由执行 id、代次、检查点版本和取消状态把关。探测失败时等待保持打开；已终止或已取消的执行不能恢复。

验收
  • 报告、请求、设置、等待、标签和包声明都来自同一注册表，一致性测试在漂移时失败。
  • 重复报告、重连、回放和模型输出不产生提示。已授权行不产生请求。
  • 缺少桌面能力的 GUI 任务在规划前暂停，两项都授权后同一执行恰好恢复一次，不使用提问或审批 API。
  • unknown、unavailable、unsupported 和拒绝分开显示。可选项失败不影响安装或聊天的健康状态。
  • 已安装的 /Applications/OpenProgram.app 确认执行者身份、当前授权、设置动作，且没有 Python 或 Node 身份迁移。
  • 自动化：注册表、探测和请求路由、等待恢复、Web 渲染、不自动请求。
