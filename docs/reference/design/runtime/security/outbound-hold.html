Outbound hold

An email, chat message or comment reaches people who asked the Agent nothing. With the hold on, each such call waits as a draft the user approves, in every permission mode.

Which calls are held

mcp/adapter.py (sends_on_behalf) decides once per MCP tool, at registration, and stores _sends_on_behalf on the AgentTool. The raw name is split on punctuation and camelCase.

Where the hold applies

AspectBehaviour
OrderIn permission_decision, after deny rules, Plan's refusal and ask rules; before allow rules and the mode. See Permission decision and refusals.
Outcomeask with RULE_OUTBOUND_HOLD, whatever the mode and even with an allow rule. A turn that cannot approve gets NO_ONE_TO_APPROVE.
Which AgentThe turn's req.agent_id, main when absent. An unknown Agent does not hold. A turn with a profile_snapshot, such as a trial of an unsaved draft, also holds when the snapshot has the hold on; a snapshot never lifts a hold the saved Agent has.
Approvalone_shot_approval covers every sending tool, held or not: never "always", never an allow rule. Each message is approved alone.
The draftThe approval card's tool name and full arguments; approval._approval_detail does not truncate one-shot calls.
Deny with a noteThe note returns to the model as the tool result. Its next call is a new draft that asks again.

Configuration

hold_outbound, a top-level boolean in agent.json, set by the last checkbox on the Agent's Always-on tab and accepted by PATCH /api/agents/{id}. Only an explicit true turns it on; AgentSpec.hold_outbound defaults to false. Off, the call follows the conversation's mode and rules like any other tool. A one-time worker migration rewrites stored true values, which came from an earlier default, to false.
