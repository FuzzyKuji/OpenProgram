The decision path

permission_decision(tool, req, args) in openprogram/runtime/permissions/policy.py is the only function that decides whether a well-formed call runs. The first match ends it.

Check, in orderResult
1. Identity (identity.py, decide). Never fires for the owner's own turns: capability (decide_tool_authority), scope, page script in work a non-owner started; dangerous read paths in an always-on check-in; page scripts and destructive deletes in a handoff chain or an automatic Goal's turns, and in the sub-agents, nested programs and notice turns they startdeny: AUTHORITY_*, IDENTITY_SCOPE, IDENTITY_PAGE_SCRIPT, IDENTITY_CHECK_IN_READ, IDENTITY_OUTSIDE_TEXT
2. Owner deny ruledeny: RULE_DENY
3. Plan selected, tool marked unsafe_in plandeny: PLAN_MODE_DENY, so a saved bash(git:*) cannot break Plan's read-only promise
4. Owner ask ruleask: RULE_ASK
5. Agent with hold_outbound, sending toolask: RULE_OUTBOUND_HOLD, an implicit ask rule; see Outbound hold
6. Owner allow ruleallow: RULE_ALLOW
7. Bypass permissionsallow: MODE_UNRESTRICTED
8. Plan, tool is exit_plan_modeask: PLAN_EXIT
9. Call needs no decisionallow: SURFACE_GRANT, SESSION_POLL, APP_GRANT_FREE, SCHEDULED_MEMORY, SAFE_TOOL
10. Accept edits, safe edit inside the working directoriesallow: SAFE_EDIT
11. Autoallow: AUTO_APP_GRANT, when an earlier review held the same screen; otherwise model review: AUTO_CLASSIFY
12. Everything elseask: MODE_APPROVAL

Rules are empty by default and merge global, project and conversation (permissions/rule.py); deny beats ask beats allow, and source order matters only inside one behaviour.

Every ask goes through _ask_or_nobody: if can_approve(req) is false the outcome is deny with NO_ONE_TO_APPROVE. No card is published for a turn that would be refused at execution; APPROVAL_LOCAL_OWNER_REQUIRED remains a defensive assertion at resume.

Calls that are not well-formed, and Pages

A malformed call never reaches the decision. call_problem(name, args) in openprogram/programs/_authoring/prechecks.py combines guides.missing_required (GUIDE_REQUIRED) and prechecks.problem (INVALID_ARGUMENTS); permissions/approval.py calls it first:

CallerOn a problem
_permission_preflight, _interaction_manifestReturn None: no review, no card
_gated_executeOrdinary tool error: is_error=True, no denied flag, no mark_refused

Being in the wrapper, not the agent loop, it also covers Python-program inner tools and the MCP server.

Whether a turn may use Pages is surface_grant_applies(name, req, args), a separate question. runtime_attach.py captures the Page snapshot when the decision for list_pages is allow and surface_grant_applies holds, so a Program started under Bypass permissions still receives its Pages.

Refusal contract

permissions/refusal.py is the single producer. The model receives one line:

[blocked by <layer>] <what> did not run: <why>. To change this: <change>.
Refusal
layer, code, what (the call, in plain words), why (the reason, quoting the rule or naming the mode), change (where the owner changes this)
Refused
What tool code raises; wraps a Refusal and is built only through this module's constructors. _execute_bound in programs/_host/runtime.py, _gated_execute and the agent loop turn it into the standard result, so an AgentTool call never raises it. A plain Python call of a tool's implementation does.

denied: true, reason_code, layer, rule, mode, outcome: "not_started", execution_started: false. The existing tool row displays the text.
