权限判定与拒绝

Owner
authority_tier == "owner" 且 principal_id == owner_principal_id()。有没有人在看不属于判断条件。
可批准
can_approve(req)：Owner、speaker_kind == "owner"、interaction == "interactive"、能力 approval.request；或请求带 asks_through 的前台助手，在调用方的卡片上询问（Agent 协作）
Bypass permissions
存储和传输值为 bypass 的模式；默认模式

判定路径

openprogram/runtime/permissions/policy.py 中的 permission_decision(tool, req, args) 是决定格式正确的调用能否运行的唯一函数。第一个命中的检查结束判定。

按顺序检查结果
1. 身份（identity.py，decide）。对 Owner 自己的轮次永不触发：能力（decide_tool_authority）、范围、非 Owner 发起的工作中的页面脚本；常驻检查读危险路径；交接链或自动 Goal 轮次，以及它们启动的子 Agent、嵌套程序和通知轮次中的页面脚本和破坏性删除deny：AUTHORITY_*、IDENTITY_SCOPE、IDENTITY_PAGE_SCRIPT、IDENTITY_CHECK_IN_READ、IDENTITY_OUTSIDE_TEXT
2. Owner 的 deny 规则deny：RULE_DENY
3. 选中 Plan，且工具标记 unsafe_in plandeny：PLAN_MODE_DENY，保存的 bash(git:*) 也破不了 Plan 的只读承诺
4. Owner 的 ask 规则ask：RULE_ASK
5. 设置了 hold_outbound 的 Agent 调用发送工具ask：RULE_OUTBOUND_HOLD，隐式 ask 规则；见外发暂扣
6. Owner 的 allow 规则allow：RULE_ALLOW
7. Bypass permissionsallow：MODE_UNRESTRICTED
8. Plan，工具是 exit_plan_modeask：PLAN_EXIT
9. 无需判定的调用allow：SURFACE_GRANT、SESSION_POLL、APP_GRANT_FREE、SCHEDULED_MEMORY、SAFE_TOOL
10. Accept edits，工作目录内的安全编辑allow：SAFE_EDIT
11. Auto之前的审查已覆盖同一屏幕时 allow：AUTO_APP_GRANT；否则模型审查：AUTO_CLASSIFY
12. 其余ask：MODE_APPROVAL

会话分支共享当前文件。切换分支不增加工作区对齐权限关卡；只有显式 Rewind 请求恢复文件。

规则默认为空，合并全局、项目和执行所属分支（permissions/rule.py）；deny 优先于 ask 优先于 allow，来源顺序只影响同一行为内部。

所有 ask 都经过 _ask_or_nobody：can_approve(req) 为假时结果是 deny，代码 NO_ONE_TO_APPROVE；由其他 Agent 启动的助手则是 HELPER_CANNOT_ASK。不会为执行时必被拒绝的轮次发布卡片；APPROVAL_LOCAL_OWNER_REQUIRED 仍是恢复时的防御性断言。

格式错误的调用与 Pages

格式错误的调用不会到达判定。openprogram/programs/_authoring/prechecks.py 的 call_problem(name, args) 合并 guides.missing_required（GUIDE_REQUIRED）和 prechecks.problem（INVALID_ARGUMENTS）；permissions/approval.py 最先调用它：

调用方有问题时
_permission_preflight、_interaction_manifest返回 None：不审查、无卡片
_gated_execute普通工具错误：is_error=True，无 denied 标记，无 mark_refused

它放在包装层而非 agent 循环，因此也覆盖 Python 程序的内层工具和 MCP 服务器。

轮次能否使用 Pages 由 surface_grant_applies(name, req, args) 单独回答。浏览器目标的 tabs 动作判定为 allow 且 surface_grant_applies 成立时，runtime_attach.py 捕获 Page 快照，所以 Bypass permissions 下启动的 Program 也能拿到 Pages。

拒绝契约

permissions/refusal.py 是唯一生产者。模型收到一行：

[blocked by <layer>] <what> did not run: <why>. To change this: <change>.
Refusal
layer、code、what（用平实语言描述调用）、why（原因，引用规则或点名模式）、change（Owner 在哪里改）
Refused
工具代码抛出的异常；包裹 Refusal，只能经本模块的构造函数创建。programs/_host/runtime.py 的 _execute_bound、_gated_execute 和 agent 循环把它转成标准结果，所以 AgentTool 调用不会抛出它；直接用 Python 调用工具实现会抛出。
结果 details
denied: true、reason_code、layer、rule、mode、outcome: "not_started"、execution_started: false。现有工具行显示这段文字。
