Conversation

  • Every turn and every manual Program hangs off ROOT, not off the previous reply.
  • Calls inside a function are one flat, time-ordered column, however deep they nest.

Call threads

Thread items reserve no lane width. Closing a thread gives back its rows.

Branches talking

SceneRule
MergeOne node with several parents, in the base lane. Each peer tip feeds it with a thick line in the peer's colour.
send_messageReturns at once; neither branch blocks. The message lands at the end of the target branch. The answer comes back as a new user-tier turn labelled with the sender's name. Dotted lines appear only on hover.
SpawnA square on its caller's thread, at the moment it happened, with a name tag. Its own thread is one column further right and pushes later items down. No return line: the follow-up reply merges into the same anchor.

Branch-name badges

  • Collisions use measured pixel boxes, and every visible node counts as an obstacle.
  • Badges come only from active list_branches rows. A merged branch loses its badge; its name moves to the merge node's tooltip.

What counts as a branch tip

SessionStore.list_branches() in openprogram/state/store/session/session_store/branches.py returns only true leaves of the conversation predecessor graph, plus the head.

Sequential top-level Programs leave one tip, the last. Parallel siblings each stay a tip.

Retry and lanes

Top-level Programs under ROOT stay on the ROOT lane in time order. Only a persisted metadata.retry_of opens a fork lane. The Retry entry point writes it; build_session_graph() exposes it to layout.
