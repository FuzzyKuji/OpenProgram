DAG rendering specification

The implementation standard for drawing. Data semantics: Session DAG design. The figures in layout show the scenes (§6) and win over any text here.

Paths below: dag/ is apps/web/lib/runtime-bridge/dag/; styles/ is apps/web/app/styles/; chat/ is apps/web/components/chat/.

0. What to draw

LayerNodesAnswersCount
ConversationROOT, user, llm replies, spawn roots, merge, manually invoked top-level functionsThe session's shapeSingle digits to dozens
ExecutionTool calls and sub-callsWhat one turn didDozens per turn

The viewport lays out only the conversation layer. A turn's calls and agents are its call thread (§12). One chip is one reply and everything the model did until the next user message:

  • A runtime-notice reply (job_followup, process_exit) merges into its anchor, found by climbing predecessor past every followup. Its synthetic display=runtime user message is never painted; filter.py (bridge_hidden) re-parents the reply onto the notice's predecessor so it is never an orphan.
  • A restart's "continue the interrupted task" reply is stamped resumed and merges into the same anchor as the reply it continues.

Chat stream and call tree are unaffected: same data, three projections.

1. Position = (column, row)

Column = lane start + tier. Both axes step one unit (COL_W == ROW_H == 40), offset by PAD_X, PAD_Y.

Lane: which branch

EventNew branch rootAttachment
Retry or rewriteForked user or llm nodeShares predecessor with the replaced node
Spawnsource=agent_spawn user nodecaller = initiator, predecessor empty
MergeThe merge nodeBase branch lane; no new lane
  • Columns 0, 1, 2… by appearance, no gaps, no "trunk". A branch occupies its start column to its deepest visible chain node; the next starts one right.
  • A fork lane keeps one extra gap column, and tiers are zeroed per lane.
  • A fork lane mirrors the trunk: its first column is an empty spine where the dashed bridge lands; every turn steps one right and stubs off it. Capsules and relics take the bridge to the chip.
  • Thread items reserve no width: they take the nearest column right of the anchor that no line crosses at the insertion row, so threads on different rows share a column and two open threads never share a cell.

Tier and depth

NodeLayerColumn
ROOTconversationtier 0
userconversationtier 1
llm reply, mergeconversationtier 2
Thread item (call, spawn head)executionanchor's column +1; a nested open thread +1 more
  • Chain rows: a preorder walk of the structural parent tree; every visible node takes its own row.
  • A fork root sits on the row of its sibling, and every branch off one point shares that row. Each bridges to the branch immediately left, so the dash is straight and two units long.
  • Thread rows: from the anchor's next row, one per event; an open spawn's thread continues from its row. Later rows shift down: expansion is insertion, never overlay.
  • Cross-session spawns land as the target's own chain, lane 0.

7. Render pipeline

  1. passes/: merge-runs; collapse-runtime-pairs (legacy wrapper pairs); demote-decoration-cards (a card child is not a fork); fold-summaries; thread.
  2. layout/geometry.ts: lattice positions from the backend's lane, tier and depth, which the front end only consumes (openprogram/state/store/session/graph/layout/, tier in tier.py).
  3. render/edges.ts, render/nodes.ts, render/labels/badges.ts, then the canvas (interaction/view/canvas.ts, gestures.ts). render/seat.ts reads a drawn group's position back.

Orchestration: pipeline.ts. Payload: openprogram/state/store/session/graph/builder.py. Debug: python scripts/dag_dump.py <session_id> prints lane, tier, depth and an ASCII grid. A capture caches icons, tool presentation and text widths; attaching defers pane-size work a frame; applyView paints once a frame; a pan rewrites only translations. A repaint of 150 nodes takes about 5ms.

8. Fill means context coverage

A covered tile (is-covered, render/visibility.ts) is part of the next LLM call. The graph never derives context semantics: GET /api/sessions/{id}/context-range returns them, built from the functions the real render uses. enterExclusiveCoverageMode (dag/index.ts) fetches it.

The set is the active branch from head back to the latest summary, plus each covered turn's code nodes listed after their owner (_with_code_nodes, _coverage_nodes in openprogram/interfaces/server/routes/files/tree.py). Context ids with no drawn node are ignored.

The summary is an ordinary chain member, so branch ids are drawn ids and need no translation; only synthetic bridges are filtered (filter.py).

9. Compaction as one capsule

A summary stands for its range, so it draws as one chip with the archive icon, its covered count +N on the shoulder. metadata.covers_ids (context/persistence.py), passed through builder.py with covered turns' caller subtrees and missing ids dropped, drives shape, fold, count, ghosts and inspector. The front end does no seq arithmetic, which would catch dead forks.

ViewingCovered turnsCapsule
Carrying branch, foldedElided; capsule first on the trunkColoured, +N
Carrying branch, openGhosts: branch colour, dashed edge, no covered fillAfter its ghosts; no count
Other branchLive and rawAfter those turns, inert: no fold, count or fill
Superseded (superseded_summary)—Keeps its row, ghost grey, folds nothing

The carrying branch's chain contains the whole segment (compaction §3). Fold state is view-only (_summaryExpanded), starts folded, and sticks across branch switches. The slot never moves. Placements are clone rewrites in fold-summaries.ts; the stored row keeps its real predecessor. Grey is reserved for history no branch can carry.

10. Failed turns

status=error and off the HEAD chain (_isArchivedFailure): the same grey as a covered turn, the ! kept, inspector Failed turn · Recorded. Both conditions matter: status alone would grey the error you are looking at; off-HEAD alone would grey every sibling. The store writes status (execution control); a cancel stays cancelled.

12. The call thread

Everything a turn did is one time-ordered sequence. passes/thread.ts builds it; _threadOpen holds view state per anchor, never persisted, reset on session switch.

StateDrawing
FoldedOnly +N on the shoulder. No outline: anything shaped reads as a node
OpenA solid branch-colour line down the anchor's column, one stub and one real chip per event. Later rows move down; fold reclaims them
SpawnThe head is a call-thread chip with the sub-agent's character. The dispatch call (agent, send_message) folds into it unless no spawn opened. Internal turns merge in; its thread sits one column right. Recursive
ReturnNo line: the followup merges into the same anchor, so dispatch, work and return read top to bottom

13. Selection, deleting, minimap

One mouse, no tool modes; gestures are in the table above. Shift or ⌘ with click or drag adds and removes; a click on empty canvas clears. Code: interaction/selection/, interaction/view/gestures.ts, chat/dag/dag-tools.tsx.

  • Selection lights chips in place. The box is an accent outline over 8% accent. Re-applied each repaint, pruned to drawn nodes, dropped on session switch. It takes focus from the composer. Esc clears it, then leaves full screen.
  • Action bar, top left: N selected | ⌖ · Copy ID · Delete · ✕; afterwards Deleted N nodes | Undo for a few seconds.
  • Minimap (interaction/view/minimap.ts): dots on faint lines, an accent frame for the view, HEAD larger and ringed. Press or drag moves the camera; wheel zooms about the middle. Starts hidden; the choice is kept in the browser.
