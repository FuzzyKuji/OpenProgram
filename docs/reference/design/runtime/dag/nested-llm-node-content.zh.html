嵌套 LLM 节点内容

展开的 LLM 节点按执行顺序显示所有可显示内容。没有固定的 Reply 或 Reasoning 分区。流本身见 Agentic LLM 流式传输。

视图回答
执行树调用关系、并行分支、状态、时长、失败位置
节点内容一个 LLM 节点内有序的文字、推理和函数引用
折叠卡片名称、状态、时长、短预览
展开卡片、右侧详情同一组件 LlmNodeContent
  • 函数行在调用时出现，参数、进度、结果和错误都读自对应 DAG 节点。点击即在树中定位该节点。提前完成不会移动行。
  • 内部签名不是内容。
  • 所有可显示内容都能访问。大结果可以折叠或按需加载，但截断的预览绝不是唯一副本。

块协议

每个 LLM 节点在 execution_stream.v1 上按 attempt 维护有序 blocks。顺序由执行层通过 block_id 和 block_index 决定，与 WebSocket 到达时间无关。

类型字段含义
textblock_id、内容、状态流式 Markdown
reasoning_summary同 text，另加保留策略策略可不持久化
tool_refblock_id、tool_call_id、occurrence_id、ref_node_id，可选 group_id指向 DAG 节点；不内联结果
tool_arguments参数增量参数生成时的预览；终态显示以执行树为准
parallel_groupgroup_id、有序的 tool_ref id仅用于明确的并发批次
refusal、unsupported沿用按自身显示

工具身份

  • 一个限定的 occurrence_id 恰好一行。原始 tool_call_id 可在不同 provider 轮次重复；重复事件不新增行。缺少 occurrence 只接受旧记录。
  • DAG 工具节点同时保存两个 id；流发布 occurrence_id → ref_node_id。节点尚不可见时先发带稳定 id 的占位，再用同一 block_id 补全。不产生第二行，不虚构完成。

Attempt

事件结果
正常工具结果后的模型请求同一 attempt，继续追加块。turn_end 只表示一轮 provider 结束
传输或结构化输出失败start_attempt(reason=...)：显示边界；旧 attempt 保持折叠；新输出绝不接到未完成的 Markdown 上

并行调用

  • 组需要成员已知的真实并发批次。Python 调度器逐个执行调用，所以不发布 group_id；前端绝不根据相邻行推断分组。
  • 每个成员从第一个事件起带组 id；id 晚创建时为先前成员重新发布。
  • 顺序即调用顺序。完成只改变状态。

流式与滚动

  • 沿用聊天的 renderMarkdown、ThinkingStep、FunctionStep 呈现和安全策略。
  • 只更新活动块。未闭合的代码块、表格或链接不会让区域消失。
  • 大内容按块虚拟化或按需加载。
  • 在底部时跟随，向上滚动即停止。展开和语法高亮保持阅读位置。
  • Copy text 不同于 Copy full execution record，后者可含推理和工具参数。

刷新与失败

情况结果
刷新、owner 消失、worker 重启从 checkpoint、metadata.stream 和快照恢复相同的顺序、引用和终态。绝不调用模型
未完成的文字保留，并标记中断、取消或失败
未保存的推理显示“此内容未保存”，不显示空的成功态
旧记录由 metadata.blocks 构建单个 legacy attempt；无法解析的引用显示未解析并保留 tool_call_id

实时和持久快照保存完整块内容；只有兼容预览字段可被截断。

验收场景

模型输出 Markdown，并行调用两个函数，其中一个用 read_file 调用内部模型，外层模型继续。执行中断开并刷新。之后：

  • 块顺序、函数状态和层级与实时视图一致；工具状态来自持久化 DAG 节点。
  • 没有 Reply 或 Reasoning 标题栏。
  • 并行成员不按完成顺序重排。
  • 重试显示边界，不接到未完成的 Markdown 上。
  • tool_ref 与树节点一一对应，结果不重复。
