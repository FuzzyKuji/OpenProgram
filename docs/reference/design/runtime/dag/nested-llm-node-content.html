An expanded LLM node shows everything displayable in execution order. No fixed Reply or Reasoning sections. The stream itself: agentic LLM streaming.

Block protocol

Each LLM node keeps ordered blocks per attempt on execution_stream.v1. Execution sets the order through block_id and block_index; WebSocket arrival time does not.

Tool identity

  • One qualified occurrence_id is exactly one row. A raw tool_call_id may repeat across provider rounds; a duplicate event adds no row. A missing occurrence is accepted only for old records.
  • A DAG tool node stores both ids; the stream publishes occurrence_id → ref_node_id. If the node is not visible yet, a placeholder with a stable id comes first and the same block_id is filled in later. No second row, no fabricated completion.

Parallel calls

  • A group needs a real concurrent batch with known members. The Python dispatcher runs calls one by one, so it publishes no group_id; the frontend never infers a group from adjacent rows.
  • Every member carries the id from its first event; an id created late is re-published for earlier members.
  • Order is invocation order. Completion changes status only.

Streaming and scrolling

  • Reuse the chat's renderMarkdown, ThinkingStep and FunctionStep presentation and safety policy.
  • Update the active block only. Unclosed fences, tables or links never blank the region.
  • Virtualize or load large content by block.
  • Follow at the bottom; scrolling up stops it. Expansion and highlighting keep the reading position.
  • Copy text is not Copy full execution record, which may include reasoning and tool arguments.

Acceptance scenario

The model emits Markdown, calls two functions in parallel, one calls an inner model with read_file, the outer model continues. Disconnect and refresh during it. Afterwards:

  • Block order, function states and hierarchy match the live view; tool state comes from persistent DAG nodes.
  • No Reply or Reasoning header bars.
  • Parallel members are not reordered by completion.
  • Retries show boundaries without joining incomplete Markdown.
  • tool_ref and tree nodes match one to one, with no duplicated results.
