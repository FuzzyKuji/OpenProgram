分支协作

分支是一个 (session_id, head_id) 对，会话内和跨会话相同。分支本身不是特殊操作：checkout 移动 HEAD，下一个用户轮次自然成为兄弟节点。

方式入口写入内容DAG 中
消息：A 投递给 Bsend_message(message, to)在 B 的末端运行一轮；目标忙时进入收件箱排队点线 1 5，目标分支颜色，悬停显示；不影响泳道和深度
派发：B 替 A 做事并汇报agent(prompt, ...)子分支 B，以及 A 在发起节点处的 attach 指针spawn 边从任务节点到 B 的根；B 独立成道，从 A 最右列再右一列开始
合并：多条分支汇合/merge 或 WebSocket 动作 merge_branches每个 peer 一个 attach 指针、一个合并 assistant 节点、一个多父提交双环，图中唯一的汇合形状，落在 base 分支泳道；画汇合线，不画 attach 指针

线型、颜色和形状见 DAG 渲染第 3 节；场景 8（合并）、9（消息）、10（派发）。寻址、投递和限额见 Agent 协作。

合并

语法
/merge sid_a sid_b:head_b: message；peer 前加 * 表示 base
无 base
各 peer 平等，合并产生新末端
有 base
其余 peer 作为补充上下文，回复延续 base；相当于多 peer 的派发
省略 head_id
取该会话当前 HEAD
节点字段
合并节点role=assistant，综合各分支输出
attach 指针，每个 peer 一个function=attach、predecessor=target_head、attach.session_id、attach.head_id=peer 末端、attach.is_base、attach.merge_temp
提交commit_parents = [目标上一提交, *peer 提交 id]

attach 是嵌入原语：一条分支的内容以指针形式进入另一处。worktree 合并无关：由 worktree_merge 对文件做 git 快进。
