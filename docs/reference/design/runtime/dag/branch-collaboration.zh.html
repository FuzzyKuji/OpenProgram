分支协作

分支是一个 (session_id, head_id) 对，会话内和跨会话相同。分支本身不是特殊操作：checkout 移动 HEAD，下一个用户轮次自然成为兄弟节点。

方式入口写入内容DAG 中
消息：A 投递给 Bsend_message(message, to)在 B 的末端运行一轮；目标忙时进入收件箱排队点线 1 5，目标分支颜色，悬停显示；不影响泳道和深度
派发：B 替 A 做事并汇报agent(prompt, ...)子分支 B，以及 A 在发起节点处的 attach 指针spawn 边从任务节点到 B 的根；B 独立成道，从 A 最右列再右一列开始
合并：多条分支汇合/merge 或 WebSocket 动作 merge_branches每个 peer 一个 attach 指针、一个合并 assistant 节点、一个多父提交双环，图中唯一的汇合形状，落在 base 分支泳道；画汇合线，不画 attach 指针

线型、颜色和形状见 DAG 渲染第 3 节；场景 8（合并）、9（消息）、10（派发）。寻址、投递和限额见 Agent 协作。

切换、重新开始、回退

操作新建什么有分支在运行时
切换到已有分支什么都不建；视图和 head 移到那条分支的末端总是允许
从旧位置重新开始：编辑后重发、重试、在图里选中一条消息后发送在原分支旁新建一条分支，有自己的记录（新消息的 branch_identity）。两条都保留，都能运行。重试一条从没得到回复的提问时，改为重跑那条提问其他分支运行时可从任意位置开始；选中分支自己的轮次在跑时等待
回退什么都不建。就地撤回当前分支的尾部：分支 id、名字、设置和用量不变；末端退到所选提问之前，那条提问回到输入框那条分支在运行时拒绝；改动文件的回退在任一分支运行时拒绝

DAG 只追加，所以回退不删任何东西。它把撤回的节点列进会话元数据（rewind_hidden_nodes；旧末端在 rewind_hidden_heads），由 rewind_view.view_update 和 head 在同一次 compare-and-set 里写入。每个读取方都跳过它们：

  • 对话记录、消息读取和搜索；
  • 分支列表和版本计数，所以回退后发的消息延续这条分支，不多出一个版本；
  • 请求的上下文，它从末端往回走；
  • 压缩：总结了撤回轮次的摘要一起撤回，它之前的摘要重新生效（active_summary_for_chain 跳过图的 retracted 集合）；
  • 上下文提交时间线。

回退的撤销和重做把这些节点移出、移回列表。切换到被撤回的末端会被拒绝，并提示用撤销。以前的回退留下了额外分支的会话保持原样，不做迁移。文件恢复见 文件管理。

同类产品都把回退当成从当前这条线上去掉最近的轮次，而不是开一条新线。Claude Code 的 /rewind 就地截断对话，会话不变，提问还给输入框；分叉是另一个复制会话的命令。Codex 记一条带轮数的 ThreadRolledBack；这些轮次留在 rollout 文件里，离开历史，也不能作为分叉锚点。

撤回列表相当于 Codex 的回滚标记，另外保留了会话内的撤销，两家都没有。重新开始仍是单独的操作，所以回退不会让人丢掉原来的内容，撤回也不会多出一个版本。

属于某条分支的工作

在一条分支上开始的工作，在用户选中别的分支后仍作用于原分支：

  • Goal 记下它开始时所在的分支（branch_id）。它的签到和验证继续并读取那条分支；其他分支上的轮次既拿不到它的说明，也不计入它。此前保存的 Goal 跟随选中分支。
  • /merge 和 merge_branches 把回复写到开始时的分支（target_branch_id），只有那条分支仍被选中时才移动 head。
  • 为忙碌会话排队的 send_message 从它指向的那条分支的末端继续。
