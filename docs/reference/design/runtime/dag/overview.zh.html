会话 DAG 设计

箭头指向边的目标。每条用户消息、模型调用、函数或工具调用一个节点。聊天记录和调用树是这份按会话只追加记录的两个视图，任何历史调用都能按模型当时所见重新渲染。

ItemDetail
图的所有者每次 Agent 执行（所有权）
普通辅助函数不产生持久节点；语义操作仍完整记录
权限、取消、文件检查点留在发起执行，与图归属无关
继承的 Context不会把计算变成历史

模型选型

模型适合边界
扁平日志只追加，收集简单嵌套、祖先和读取需要额外关系
Span 树标识、父子调用、时序、状态、属性父子描述调用，不是对话前驱；无法表示备选后续
带时序的嵌套区间性能视图（Chrome Trace、Perfetto）时序无法说明回复属于哪条分支
会话 DAG（选用）调用、分支、读取同在一份记录需要边校验、索引和明确的渲染规则

一份记录要同时表达：嵌套调用、对话分支、每次 LLM 调用读取的确切节点。

边与不变量

ItemDetail
两种边有向、无环、相互正交
caller把顶层节点连到 ROOT
predecessor对话顺序和分叉，这是 caller 加 seq 给不出的。只存在这个顶层字段：没有 metadata 副本，没有旧读路径
写入（session_store/shared.py）错接的分支事后无法修复。没有真实 caller 的 ROOT 层 user 或 llm 节点必须有 predecessor，否则抛 PredecessorMissingError
合法例外首节点和显式根分叉（哨兵 "ROOT"）· ROOT 本身 · 派生根（predecessor=None，caller 为派生者）· ask_user 回答（input 非 None 的 user 节点）· 从会话开头覆盖的摘要节点（§8）
读取get_branch 和 list_branches 只走边，不回退 caller，不按 seq 拼接。缺 predecessor 的只能是派生根、ROOT、首节点、打开运行分支的 code 节点或上述摘要，否则抛 BrokenPredecessorChainError 并带节点 id

失败

ItemDetail
错误终态：节点写入 status=error，本轮提交，head 停在此处
取消同理，写 cancelled
重试普通分叉。失败线始终可达，又不在活动分支上，所以不进入重试的上下文，无需按 status 过滤
错误路径上的收尾是否运行
Git、项目和 shadow-git 提交，快照淘汰运行：时间线无空洞，重试有已提交的前驱
上下文提交回填、用量反馈、自动标题不运行：它们以有回复为前提

派生

根节点user 节点，带 caller、metadata.source、metadata.spawn_branch_root=True

上下文get_branch 停在根，从父分支渲染也不经 caller 下钻（上下文渲染）

目标 T新 user 节点：predecessor=M、caller=A、metadata.spawned_from_session=S。图不能画到别的会话，所以 T 的投影把 caller 放在 ROOT 并标 spawn_remote

完成通知

写回锚定在原因
Attach 指针调用轮次它是调用的记录
通知轮次（source="job_followup"）当前 HEAD，并推进它新轮次：N 个子 Agent 形成一条链，而不是一条消息被回答 N 次

Runner 让 TurnRequest.branch_from 保持 INHERIT_PARENT，从不回退 head。JobRunner._followup_lock 每个投递会话一把，串行化同时完成的子 Agent。

Head 与分支

ItemDetail
head_id活动分支尖。对话写入把它推进到真实节点，绝不指向占位符或摘要；悬空 head 渲染为空。带 caller 的节点不推进它
get_branch(session_id, head_id)从 head 沿 predecessor 走到终点
list_branches(session_id)可见的对话末端及保留的分支引用。Rewind 隐藏撤回的后缀，同时保留兄弟引用，包括停在共同祖先或 ROOT 上的引用。同一位置的引用由分支身份区分。内部执行行不创建对话末端
分支名会话元数据：分支引用的标签保存各自名称；branches 保留当前消息位置的兼容投影

上下文渲染

节点被渲染，当且仅当它最近的 ROOT 层祖先（沿 caller 向上）在 head_id 的 predecessor 链上，并且 frame 和 expose 规则允许。

ItemDetail
seq只用于排序
引擎解析 head、调用 render_context、把结果交给 render_dag_messages，自身不做过滤
读路径不写盘
ROOT从不展开：其 caller 子树会把所有兄弟分支带回来
派生根（metadata.spawn_branch_root）不经 caller 进入，所以 Goal 工作 Agent 读不到裁判。从派生分支内部渲染时仍可经主干看到
顶层聊天（frame −1）主干上每一轮完全可见
函数内部（frame = 其 seq）frame 前的历史加自身进度；其他函数内部按其 expose（默认 io）
带 metadata.tool_call_id 的 code 节点真实的 ToolCall/ToolResult 对，放入所属 llm 节点的 assistant 消息
不带的 code 节点文本对
聊天流顶层 user 和 llm 按 seq，嵌套折叠
调用树沿 caller 展开，循环兄弟折叠为 ×N

上下文组装

ItemDetail
一个组装器build_system_prompt(agent, *, channel, tools, additional_working_dirs, plan_mode)，供所有模型调用：身份、项目记忆、统一工具列表、技能
预算计的就是发送的字符串
变化默认不变，以获得 KV 缓存命中，并让聊天和函数背景一致。精简提示词是调用处的显式选择，接受未命中
函数内误用工具在用户轮开头给情境指引并限制递归深度，不改工具列表（自递归）
记录哈希变化时（开始、工具集变化、计划模式切换）：追加 role=code、name="context/system_prompt"、caller=ROOT、output 为全文的节点。渲染固定使用主干上最新的一个
context/* 名称保留并对聊天隐藏，context/summary 例外，它是真实对话内容
记忆预取当前 user 节点线上消息的前缀块，存为其 turn_context 元数据里的 memory_prefetch 一项（组合）。系统和工具段字节稳定
图片和文件节点内容，按引用保存；正文在附件目录，渲染时加载

压缩

ItemDetail
metadata.covers_ids用 id，因为兄弟分支的 seq 交错。WebUI 载荷把被覆盖轮次的 caller 子树也加入（渲染 §9）
下一个摘要吸收生效的那个，由 nodes.active_summary_for_chain 按链选出；图构建器按同样的选择折叠每个分支
完整规范压缩
旧工具结果从不老化：在压缩覆盖它那一轮之前，都按那一轮发出的样子渲染，所以两次压缩之间缓存前缀只增长
重放渲染只读存下的节点，同一张图任何时候渲染出相同字节；旧版本写下的 render_manifest 不再读取
溢出大节点在记录时溢出，一次且确定，绝不在渲染时
单一管线DAG 渲染是唯一上下文路径；出错时本轮明确失败

head_id、分支名会话字段
