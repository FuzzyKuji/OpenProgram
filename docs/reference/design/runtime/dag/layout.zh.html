字母代替真实圆形节点上的图标。泳道 0 为实心，其他泳道为描边。窄屏按“列,行”列出节点。

对话

  • 每一轮和每个手动 Program 都挂在 ROOT 下，不挂在上一条回复下。
  • 函数内部的调用是一列按时间排列的平铺节点，不论嵌套多深。

分支之间

场景规则
合并一个多父节点，位于基准泳道。每个对端分支尖端用对端颜色的粗线汇入。
send_message立即返回，两边都不阻塞。消息落在目标分支末尾。答复作为新的用户层轮次返回，并标出发送者名字。点线只在悬停时显示。
派出调用线程上的一个方块，位于发生时的位置，并带名字标签。它自己的线程再右移一列，把后面的项往下推。没有返回线：后续回复并入同一锚点。

节点状态与标记

状态画法
运行中节点自身的图标动起来，通向它的传送带上有珠子移动。没有占位节点。
出错红色 ! 标在节点右上缘；这一轮的其他节点不变。
已取消整个节点变淡，形状不变。
计数右上肩的数字：折叠了多少事件。不是节点。
↗跨会话派出，两侧都标：来源节点和目标分支根。

分支名徽标

  • 碰撞按实测像素盒判断，所有可见节点都算障碍。
  • 徽标只来自活跃的 list_branches 行。分支合并后徽标消失，名字转入合并节点的提示。

什么算分支端点

SessionStore.list_branches() 位于 openprogram/state/store/session/session_store/branches.py ，只返回对话前驱图的真实叶子，以及 head。

延续对话不延续
用户和回复节点；顶层 Program（caller 为空或 ROOT）；运行时调度的用户行内部执行子节点、其他运行时行、结构行和根行、 attach、context/*

依次运行的顶层 Program 只留最后一个端点；并行的同级各自是端点。

重试与泳道

ROOT 下的顶层 Program 按时间留在 ROOT 泳道。只有持久化的 metadata.retry_of 才打开分叉泳道。Retry 入口写入它； build_session_graph() 把它交给布局。
