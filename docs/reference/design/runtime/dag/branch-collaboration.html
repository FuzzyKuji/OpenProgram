Branch collaboration

A branch is a (session_id, head_id) pair, the same within a session and across sessions. Branching is not a special operation: checkout moves HEAD, and the next user turn becomes a sibling.

Messaging: A delivers into Bsend_message(message, to)A turn on B's tip; a busy target queues it in the inboxDotted 1 5 line, target branch colour, shown on hover; no effect on lanes or depth

Merge: branches converge/merge or WebSocket action merge_branchesOne attach pointer per peer, one merge assistant node, a multi-parent commitDouble ring, the only convergence shape, in the base branch's lane; convergence lines drawn, attach pointers not

Merge

Syntax
/merge sid_a sid_b:head_b: message; a * before a peer makes it the base
Without a base
Peers are equal; the merge produces a new tip
With a base
The other peers are supplemental context and the reply continues the base; the multi-peer form of dispatch
Omitted head_id
That session's current HEAD
NodeFields
Merge noderole=assistant, synthesized from each branch's output
Attach pointer, one per peerfunction=attach, predecessor=target_head, attach.session_id, attach.head_id=peer tip, attach.is_base, attach.merge_temp
Commitcommit_parents = [target prior commit, *peer commit ids]

Attach is the embedding primitive: one branch's content enters another point as a pointer. A worktree merge is unrelated: a git fast-forward of files, by worktree_merge.
