0. 画什么

层节点回答数量
对话层ROOT、user、llm 回复、派生根、merge、手动调用的顶层函数会话的形状个位数到几十
执行层工具调用及子调用这一轮做了什么单轮可达几十

视口只布局对话层。一轮的调用和 Agent 是它的调用线（§12）。一个圆片代表一条回复及模型直到下一条用户消息前所做的一切：

  • 运行时通知回复（job_followup、process_exit）并入其锚点，沿 predecessor 越过所有 followup 找到。合成的 display=runtime 用户消息不绘制；filter.py（bridge_hidden）把回复重挂到通知的前驱，避免孤立节点。
  • 重启产生的“继续被中断的任务”回复标记 resumed，并入它所接续回复的锚点。

聊天流和调用树不受影响：同一数据，三种投影。

1. 位置 = （列，行）

列 = 泳道起始 + tier。两轴同一单位（COL_W == ROW_H == 40），偏移 PAD_X、PAD_Y。

泳道：属于哪条分支

事件新分支根连接
重试或改写分叉出的 user 或 llm 节点与被替换节点共用 predecessor
派生source=agent_spawn 的 user 节点caller 为发起者，predecessor 为空
合并merge 节点基线分支泳道，不开新泳道
  • 按出现顺序编号 0、1、2…，无空缺，不分“主干”。分支占据从起始列到最深可见链节点；下一条紧接其右。
  • 分叉泳道多留一个间隔列，每条泳道的 tier 归零。
  • 分叉泳道与主干同构：第一列是空主干线，虚线桥落在上面，每轮右移一列并从主干线引出。胶囊和遗留节点的桥直接到圆片。
  • 调用线项不占泳道宽度：取锚点右侧、插入行上没有线穿过的最近一列，不同行的调用线可共用一列，两条打开的调用线不共用格子。

Tier 与深度

节点层列
ROOT对话tier 0
user对话tier 1
llm 回复、merge对话tier 2
调用线项（调用、派生头）执行锚点列 +1；嵌套打开的调用线再 +1
  • 链上的行：对结构父树前序遍历，每个可见节点独占一行。
  • 分叉根与其兄弟同行，同一分叉点的所有分支共用此行。每条分支桥接到紧邻左侧的分支，虚线水平且长两格。
  • 调用线的行：从锚点下一行起，每事件一行；打开的派生从其行继续。后面的行下移：展开是插入，绝不覆盖。
  • 跨会话派生作为目标会话自己的链，位于泳道 0。

9. 压缩显示为一个胶囊

摘要代表一个区间，所以画成一个带归档图标的圆片，肩部 +N 为覆盖数量。metadata.covers_ids（context/persistence.py）经 builder.py 加入被覆盖轮次的 caller 子树并去掉不存在的 id，驱动形状、折叠、计数、幽灵和检查器。前端不做 seq 运算，否则会把死分叉算进来。

承载分支的链包含整段（压缩 §3）。折叠状态只属于视图（_summaryExpanded），初始折叠，切换分支后保持。位置不变。摆放由 fold-summaries.ts 克隆改写，存储的行保留真实 predecessor。灰色只留给任何分支都不再承载的历史。

10. 失败的轮次

status=error 且不在 HEAD 链上（_isArchivedFailure）：与被覆盖轮次同样的灰，保留 !，检查器显示 Failed turn · Recorded。两个条件都要：只看 status 会把眼前的错误变灰，只看离开 HEAD 会把所有兄弟变灰。status 由存储写入（执行控制）；取消保持 cancelled。
