Tool toggles and toolsets

The Agent decides which tools a session may call. A session stores only intent, never an expanded list, so a new tool reaches every old session.

Who chooses

Agents → Capabilities → ProgramsScope: all, selected, named Access preset, or none. Plus disabled names and a web_search default.Agent profile, tools: {mode, allowed, preset, disabled, web_search}
Composer Web Search switchLayers web_search on or off over the Agent's setSession meta, web_search
/skill <name> with allowed-toolsNarrows the turn to the skill's allowlistSession meta, tools_override (list[str])

No composer Tools switch or per-chat preset. A chat without tools uses an Agent with Programs set to none. The chat action reads only web_search from a message, never tools or tools_profile.

Mechanics in programs/_host/runtime.py
PartBehaviour
apply_default_deferral()Runs once at import in programs/__init__.py and gives every entry its default tier. Idempotent. Entries registered later get theirs at registration.
split_tools_for_dispatch(tools)Partitions into (provider_tools, catalog) by tier and the loaded set
Loaded setA ContextVar seeded per session (install_loaded_deferred), extended from inside tool_search (mark_deferred_loaded)
freeze_turn_toolsCaptures deferred membership at each turn boundary. Only explicit discovery extends it within the turn.
Discoverytool_search adds allowed names to the loaded set and that turn's shared membership, so the next provider request carries real schemas. Schema as tool-result text alone is not enough for providers that accept only tools in the request array.
In-place mutationTool workers inherit ContextVar values; replacing a worker's value would not reach the provider coroutine
ExecutionUses the turn's resolved, permission-wrapped tools, not a new registry lookup. Without discovery the array is stable; discovery may change the cached prefix.
CheckpointsEach durable safe point records loaded_deferred_tools, which must belong to the resolved tool contract. Continuation validates the unchanged contract, then restores names without replaying searches. Older checkpoints restore an empty set. Tool-result text is never read as authorization or loading state.
Outside a turnrelease_turn_tools() reads the live loaded set
CatalogContext component deferred_catalog (_build_deferred_catalog in runtime/context/components.py), so the budgeted string is the one that ships. Empty when nothing is deferred.
_estimate_one_toolIn runtime/context/budget.py. Resident: description, parameters and a small wrapper. Deferred: bare name plus a newline. The two errors point in opposite directions, so test_budget.py checks each half against a real tokenized payload, within 15%.

Do not break

RuleWhy
Expansion is deterministicThe tool array is the root of the prompt cache prefix (models/providers/settings/cache_policy.py; first breakpoint at the last tool, Anthropic and Bedrock explicit mode). Any wobble misses the whole cache silently. No set() iteration or dict churn in agent_tools and _filter_agent_tools.
Never store the Agent's tools on a sessionThe list would freeze: tools added to DEFAULT_TOOLS later would never arrive. list[str] means only a /skill allowlist.
Never filter historyHistorical tool_use and tool_result render from messages regardless of context.tools. Breaking the pairing causes a provider 400.
Mid-turn array growth only through discoveryAnything else discards the cached prefix for the rest of the turn
Cost, cache and replay
QuestionAnswer
Do tools count as tokens?ContextCommit.total_tokens excludes the array (state/store/session/context_commit/types.py); the provider bills it. Invisible to the compaction budget, visible in input cost.
Cache?Any addition, removal or reorder misses the entire prompt cache.
Calls absent from the current array?They replay fine; the model just cannot issue that call this turn.
Commit replay?Unaffected: commits store no tool array.
