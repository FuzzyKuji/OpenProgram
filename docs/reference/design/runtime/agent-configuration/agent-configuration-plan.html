Fixed choices

  • The first production release covers saved and inline configurations, atomic persistence, shared resolution, optional memory and the editor. Manual per-call model selection does not need automatic selection.
  • AgentSpec is the only saved registry; AgentConfig is a typed value. Reuse Runtime.exec, MemoryBackend, Context Engine, capability catalogs and resource governance.
  • New saved and anonymous configurations default to memory off. Legacy profiles keep effective behaviour through explicit migration; no history or memory store moves silently.
  • Model selection occurs at invocation admission. Changing model mid-response or replaying side effects under a fallback is out of scope.
  • Single-base resolution; no named-Agent inheritance tree, mandatory role, autonomous creation of saved Agents, new worker or orchestration engine.

Migration, old clients and rollback

TopicRule
PreflightUnder the writer lock, read all saved records, the default pointer and effective legacy globals. Dry-run report of IDs, schema versions, unresolved references and semantic differences, without secrets or memory contents. Unknown schemas and corrupt records block that profile; never replaced with main.
NormalizeNo version means schema 1; becomes schema 2, revision 1. Unknown extension data goes to a migration backup; unsupported executable fields are rejected until understood. Old memory binding and behaviour stay; no switch to empty self spaces. Legacy global inheritance stays a named compatibility source until the user picks a mode.
WriteBack up the exact owned files and index with restrictive permissions first. Journal and restart-safe reconciliation for multi-file work. Commit a profile only after validation; an interrupted migration resumes idempotently. No external workspace, credential, session, DAG or learned-memory content changes.
PreconditionsNew writes require expected_revision. A temporary adapter compares a client's updated_at under the same lock, derives the revision and writes once. Neither given: 428; the UI keeps drafts and asks for reload. No last-write-wins.
Python callsNo-selector calls keep model, history, memory and output type. New keywords are keyword-only. Explicit agent_id/config defaults to clean history; explicit inherit obeys visibility rules. Conflicting aliases are validation errors. Durable start_from and to keep their meaning.
RollbackOnly with a reader that understands schema 2, or an explicit verified downgrade with writers stopped. Unsupported new fields prevent lossless downgrade. Restore a backup only before post-migration edits or after reconciling them. A legacy binary must not silently rewrite schema 2.
RolloutBackend dual-reader, updated clients, migration enablement, legacy-adapter retirement. Retirement needs updated first-party clients and a documented deprecation period.

P6: optional selection policy

Opt-in, runs before the resolver. A caller supplies a policy reference instead of agent_id/config (mutually exclusive). Candidates are saved Agent IDs or provider-qualified model references, never generated executable configuration. The policy declares its kind: a model choice keeps the caller's non-model fields; an Agent choice changes the base and follows normal history rules.

DecisionContract
EligibilityFilter unavailable provider, account or model, required modality, structured output or tool support, context limit, authority and remaining resource cap before ranking
RankingVersioned ordered deterministic rules over task tags, required capabilities and caller preferences; model-assisted ranking is a separately enabled later mode
No matchTyped no-eligible-candidate error, or an explicitly configured eligible fallback before inference; never broaden authority
TracePolicy version, eligible IDs, exclusions, chosen ID, rule identifier; no raw user content or unsupported cost and latency claims
StabilityPinned for retries and resume; a new invocation may select again; an active tool loop never switches
EvaluationFixtures for correctness, no-match, denied candidate, unknown price metadata and deterministic replay; measured quality, cost and latency on an approved corpus before claims
Example Agent-kind policy
  • Tag classify and structured output required: first eligible saved Agent with a selected small model.
  • Tag code-edit and tools required: a selected saved coding Agent.
  • Otherwise: a specified saved default Agent.

A model-kind policy returns only model references. Candidate IDs and thresholds are user-configured, not hardcoded rankings. Missing price or latency means unknown, not free or fast.
