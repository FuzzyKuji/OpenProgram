Configurable Agents

An Agent is a saved, reusable execution configuration. It is edited in eight sections (General, Programs, Skills, MCP, Memory, Context, Always-on, Advanced); saves are atomic and revision-checked. New Agents keep memory off.

  • The flat AgentSpec envelope stays. POST takes a name plus optional executable fields; id, revision and timestamps are server-assigned unless a valid explicit legacy ID is given.
  • AgentConfig has executable fields only. Export/import excludes server metadata and assigns a fresh identity. The package exports AgentConfig beside agent and llm; a provider-qualified model string normalizes to the provider/id object.
  • Active read modes need at least one authorized read space; read_write needs exactly one readable write target. Off leaves bindings inactive; the editor may keep them in its draft.
  • Unknown fields, invalid types and a field in both reset_fields and the changes are rejected before writing. Readiness is returned apart from stored configuration.

One resolver

The base comes from exactly one source, in order: explicit agent_id, explicit config (mutually exclusive with it), ambient Agent, system default. Session overrides apply only while on the same Agent identity; a switch inherits no model, prompt, tools or memory bindings. Authorized invocation overrides replace fields next; authority constraints apply last and revocations are rechecked at every effectful boundary.

Proposed Python API (not available yet)

Extends agent() and llm() with agent_id, config, overrides and history selection; no parallel executor. Validation and return types stay.

from openprogram import Agent

# Explicit history sharing; records stay in the same execution DAG.
agent(prompt, agent_id="reviewer", history="selected", context_nodes=[node_id])

class ExampleAgent(Agent):
    method_options = {
        'extract': {'tool': True},
        'classify': {'tool': True},
    }

    def extract(self, document):
        return agent(document, agent_id="my-agent",
                     overrides={"memory": {"mode": "off"}},
                     response_format=Result)

    def classify(self, document):
        return llm(document,
                   config=AgentConfig(model="provider:model", memory={"mode": "off"}),
                   response_format=Label)

_example_agent = ExampleAgent()
extract = _example_agent.extract
classify = _example_agent.classify

Spaces
self for a saved Agent is its own namespace and invalid for anonymous configs. Implemented: self, legacy_global. Target: a selected project or shared space, which allows anonymous memory use. write_space must be readable. Enabling a new Agent's memory defaults to self, with no copy of the old global store.
Off does not
Delete memory, disable session history or remove user-provided instruction files. Text already in messages cannot be unseen; start a clean context. Pending recalls are invalidated before entering a request. It is not a filesystem sandbox: if shell or file tools can read memory files, the UI shows that.
Failure
An optional backend failure shows degraded memory and continues; required=true fails before model execution. A write failure keeps the task result and reports separately.
Not offered
write_only. A backend without enforceable namespaces cannot enable scoped memory; prompts never simulate isolation.
Write eligibility
  • Every execution node carries a write-eligibility label, space reference and policy epoch. Session-end writers, compaction extraction, source export and scheduled reorganizers filter out off and read-only nodes.
  • Disabling writes blocks unsettled queued writes and prevents retroactive ingestion on re-enable. Committed memory stays.
  • Derived outputs and summaries carry the most restrictive eligibility of the context included. Splitting or switching Agents cannot relabel restricted data. Off propagates a no-write restriction but does not forbid an independently authorized read later.
  • A background write validates the original grant and current space policy at commit; revocation wins over the pin. Never retry with a broader space. External backends that cannot cancel are documented.
  • User-authored instructions and uploads stay inputs, even with personal facts; text outside recorded provenance is not claimed classifiable.

  • Clean means no inherited conversation messages, not no system or project policy.
  • Selected history is validated against the caller's visibility; DAG membership is not authorization. Execution history is kept by default; there is no incognito guarantee.
  • Workspace and project cwd are separate. A cwd is not an access boundary. Incompatible host or sandbox requests fail visibly.
  • Context length uses existing Context Engine limits; no second summarizer.

Capability scope and authority

Catalogs own definitions and credentials; Agent policies own references. Detail: Agent capability policies. Admission, usage, cancellation and quotas: resource governance.

  • A session or invocation may replace a preference but never expand an enforced ceiling. A delegation restriction survives an agent_id change. Rejected overrides are explained.
  • Provider-native search and other native actions are capability-gated; tools=[] alone is not a network restriction.
  • Accounts resolve through credential services; no raw keys in AgentSpec, snapshots, exports or examples. Anthropic connections use the official API and legitimately obtained API keys with API account billing.
  • Python already authorized by the host is not sandboxed by an allowlist; tools and nested agentic calls are checked at their public boundaries.

Atomic persistence

One canonical agent.json, atomic replacement. A small recovery journal covers create, default and delete across the index and resources; several os.replace calls are not a transaction. Startup reconciles unfinished intents before serving writes. Deleting an Agent never deletes shared memory, global credentials or external workspaces. Session and DAG references are enumerated through their store.

Configure an Agent

Configuration belongs to a conversation branch

A conversation shares its project and working directories. Each branch stores its own Agent, model and provider, effort, tool intent, search toggle, permission mode and rules, Plan, sandbox override and service tier.

A new branch copies its source's settings once, then changes alone. Switching restores the destination's settings, empty overrides included; Rewind, Undo and Redo keep them. A scheduled task's branch copies the selected branch with the task's Agent at its first run; later runs keep that record and take the task's Agent again.

Branch references own the settings; the session's top-level fields mirror the selected branch. A switch saves the source and restores the destination with the head in one commit. Old sessions seed a branch from their settings once; missing history is not reconstructed.

Admission freezes the turn's Agent, model, effort, Fast, tool intent, Sandbox, and permission mode and rules from its branch, the first of:

  1. the branch the request names;
  2. the record reserved for the run's message (a scheduled run's);
  3. the live same-session parent's branch;
  4. the record at the turn's starting message;
  5. the selected branch.

A chat, scheduled, background or headless turn on an unselected branch runs that branch's Agent and permission. A Job keeps what it was given, same-session children inherit their parent, and Trial Agents keep their snapshot.

An unfocused pane rereads its model settings when its branch or that branch's Agent changes. A model pick or Agent switch on a branch that is not selected leaves the live runtime alone and is not broadcast, so other panes and the sidebar keep the selected branch's model; the pane takes the model and its controls from the reply.

Every model settings read names the pane's branch, so after any broadcast a pane on a branch that is not selected reads back that branch's model, not the selected one's. A broadcast names no conversation, so no chip takes its model: each keeps what it shows until its own read lands.

The read also carries the branch's stored effort and web search toggle. A pane takes them unless one of its own writes is still on the way, so a setting changed from another window or the API reaches an open pane without a reload.
