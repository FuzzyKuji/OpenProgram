固定选择

  • 首个生产版本覆盖保存和内联配置、原子持久化、共享解析、可选记忆和编辑器。手动按调用选模型不依赖自动选择。
  • AgentSpec 是唯一保存的注册表；AgentConfig 是类型化值。复用 Runtime.exec、MemoryBackend、Context Engine、能力目录和资源治理。
  • 新的保存和匿名配置默认记忆关闭。旧配置通过显式迁移保持生效行为；不静默移动历史或记忆存储。
  • 模型选择发生在调用准入时。响应中途换模型或用备用模型重放副作用不在范围内。
  • 单基础解析；没有命名 Agent 继承树、强制角色、自动创建保存的 Agent、新 Worker 或编排引擎。

迁移、旧客户端与回滚

主题规则
预检在写锁下读取所有保存记录、默认指针和生效的旧全局设置。试运行报告 ID、schema 版本、未解析引用和语义差异，不含密钥或记忆内容。未知 schema 和损坏记录阻止该 profile 迁移；绝不替换成 main。
规范化没有版本视为 schema 1，变为 schema 2、修订 1。未知扩展数据进迁移备份；不支持的可执行字段在弄清前拒绝。旧记忆绑定和行为不变，不切换到空的 self 空间。旧全局继承保持为命名的兼容来源，直到用户选择模式。
写入先用严格权限备份确切的自有文件和索引。多文件工作用日志和重启安全的对账。校验通过才提交 profile；中断的迁移幂等恢复。不改外部工作区、凭据、会话、DAG 或已学习的记忆。
前置条件新写入需要 expected_revision。临时适配器在同一把锁下比较客户端的 updated_at，推导修订后写一次。两者都没有：428；UI 保留草稿并要求重新加载。不允许后写覆盖。
Python 调用不带选择器的调用保持模型、历史、记忆和输出类型。新参数仅限关键字。显式 agent_id/config 默认干净历史；显式继承遵守可见性规则。冲突的别名是校验错误。持久的 start_from 和 to 含义不变。
回滚只能用理解 schema 2 的读取器，或在写入方停止时做显式验证的降级。不支持的新字段使无损降级不可行。只在迁移后无编辑或已对账时恢复备份。旧二进制不得静默重写 schema 2。
上线顺序后端双读、更新客户端、启用迁移、退役旧适配器。退役需要一方客户端已更新并有公布的弃用期。

失败场景

ID操作必须成立
A01 A03创建只有名称的配置；用保存字段和等价内联字段调用 agent 与 llm不需要角色；匿名不持久化；除身份和来源外生效字段相同；llm 无 Program/MCP 循环；web_search=False 不发原生搜索，显式授权的 True 保留
A02两个进程从同一修订 PATCH 模型和工具；在替换前注入失败恰好一个 200、一个 409；文件为完整旧版或新版；没有混合字段；草稿保留
A04两个嵌套并行调用用不同模型和记忆；一个在 await 时取消请求用各自字段；finally 恢复调用方；取消传播
A05在记忆和 off/只读输出中放不同哨兵；强制召回、压缩和会话结束写入禁止的哨兵不进入请求或存储；派生摘要保留写限制
A05 A08暂停排队的召回或写入，撤销访问，放行，重启 Worker迟到的召回被丢弃；写入在提交时被拒；重试不能扩大授权
A06用 clean、inherit、selected 历史切换保存的 Agent；请求不可访问节点只有授权且选中的上下文；无隐式传递；推理前失败
A07selected=[]；被拒绝的显式工具；缺失必需 MCP；有无 Agent 选择的 llm 原生搜索发现和调用一致；预检成功前无副作用
A08 A12排队运行、编辑 Agent、恢复；触发下一次计划恢复用固定配置加当前撤销；新触发解析最新修订
A09带 self 和共享记忆、活动运行、外部 cwd 时复制、导出、导入、删除不复制记忆、历史、凭据或计划；共享和外部资源保留；活动中删除被拒
A10桌面和移动端、键盘操作所有分区；两个客户端保存冲突无草稿丢失、虚假成功、溢出或不可达标签；冲突提供重新加载或显式重新应用
A11迁移夹具：全局记忆继承、空允许、名称加类别、未分类条目、默认 Agent生效模型、能力、记忆和默认一致；重跑无操作

P3 还负责协作设计中的 C1–C10：实际的 execution_id/job_id 接口、完成后续和异步归档、消息耗尽后的授权输出读取、统一的历史可见性、结果限制、精确附着导航。只有 helper 或直接调用它的测试不算公开入口证据。

P6：可选选择策略

可选启用，在解析器之前运行。调用方提供策略引用，而不是 agent_id/config（互斥）。候选是保存的 Agent ID 或带 Provider 的模型引用，绝不是生成的可执行配置。策略声明自己的类型：模型选择保留调用方的非模型字段；Agent 选择改变基础并遵守正常历史规则。

决策契约
资格排序前过滤不可用的 Provider、账号或模型、所需模态、结构化输出或工具支持、上下文限制、权限和剩余资源额度
排序带版本、有序、确定性的规则，基于任务标签、所需能力和调用方偏好；模型辅助排序是之后单独启用的模式
无匹配类型化的无合格候选错误，或推理前显式配置的合格回退；绝不扩大权限
追踪策略版本、合格 ID、排除项、选中 ID、规则标识；不含原始用户内容或无依据的成本和延迟说法
稳定性重试和恢复时固定；新调用可重新选择；活动的工具循环绝不切换
评估覆盖正确性、无匹配、被拒候选、未知价格元数据和确定性重放的夹具；在批准的语料上测得质量、成本和延迟后才能声称
Agent 类型策略示例
  • 标签 classify 且需要结构化输出：第一个合格的、配置了选定小模型的保存 Agent。
  • 标签 code-edit 且需要工具：选定的保存编码 Agent。
  • 否则：指定的保存默认 Agent。

模型类型策略只返回模型引用。候选 ID 和阈值由用户配置，不是硬编码排名。缺失价格或延迟表示未知，不是免费或快速。

已知风险

风险处理
记忆内容出现在派生历史中通过上下文依赖和摘要传播写限制；测试跨 Agent 传递
插件无法强制命名空间隔离暴露不支持的就绪状态；阻止作用域绑定；不声称靠提示隔离
并发文件和默认索引生命周期带恢复和幂等的日志；变更权限集中在一个 manager
旧客户端覆盖新类型字段双读、条件写、显式错误；不静默降级
快照含个人指令现有执行存储 ACL 和保留策略；诊断显示哈希和引用，不显示提示文本
UI 超前于运行时功能就绪跟随已验证的后端支持；原型状态保持明确

没有阻塞 P0 的产品决策。确切的使用方路径和后端撤销支持在实现中确定，按上述失败关闭行为处理；做不到的后端保持不支持。
