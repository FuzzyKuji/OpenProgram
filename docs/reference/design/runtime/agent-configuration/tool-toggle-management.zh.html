工具开关和工具集

Agent 决定会话能调用哪些工具。会话只保存意图，绝不保存展开后的列表，所以新工具能进入所有旧会话。

谁来选

位置设置存储
Agents → 能力 → 程序范围：全部、指定、命名的访问预设或无。另有禁用名称和 web_search 默认值。Agent 配置，tools: {mode, allowed, preset, disabled, web_search}
输入框网页搜索开关在 Agent 工具集上叠加或去掉 web_search会话 meta，web_search
带 allowed-tools 的 /skill <name>把本轮收窄到技能的允许清单会话 meta，tools_override（list[str]）

输入框没有工具开关和按聊天的预设。不用工具的聊天使用程序设为无的 Agent。聊天动作只从消息读 web_search，不读 tools 或 tools_profile。

优先级

runtime/conversation/model_tools.py 的 resolve_tools(agent_profile, override, source)；override 由 session_config.py 的 tools_override_from_config(cfg) 产生。

可用不等于常驻

状态供应商工具数组目录中的名称可调用
常驻每轮完整 schema无是
延迟，已加载完整 schema无是
延迟，未加载无有tool_search 之后
禁用或隐藏无无否

目录只给名称，最多 80 个，其余显示数量，所以延迟工具再多也不会变大。

分组成员
常驻DEFAULT_TOOLS 减 DEFERRED_DEFAULT_TOOLS，加 tool_search 和 job_output。tool_search 永不延迟：它是唯一的加载入口。
DEFERRED_DEFAULT_TOOLS记忆工具、scheduler、exit_plan_mode（计划模式提示词会点名）、send_message、skill、save_routine。默认可用，体积大且少用。
其他已暴露工具full 中不属于 DEFAULT_TOOLS 的全部
应用入口延迟；应用在窗口中打开时常驻
显式网页搜索提升一份常驻副本，不用 tool_search 就能发送。共享注册表不变。
按名称给的工具列表列表里没有 tool_search 时，全部以常驻发送
programs/_host/runtime.py 的机制
部分行为
apply_default_deferral()在 programs/__init__.py 导入时运行一次，给每个条目默认层级。幂等。之后注册的条目在注册时获得层级。
split_tools_for_dispatch(tools)按层级和已加载集合分成 (provider_tools, catalog)
已加载集合按会话初始化的 ContextVar（install_loaded_deferred），由 tool_search 内部扩充（mark_deferred_loaded）
freeze_turn_tools在每个轮次边界记录延迟成员。轮内只有显式发现能扩充。
发现tool_search 把允许的名称加入已加载集合和本轮共享成员集合，下一次供应商请求带上真实 schema。只在工具结果里返回 schema 不够：有些供应商只接受请求数组里的工具。
原地修改工具 worker 继承 ContextVar 的值；替换 worker 的值到不了供应商协程
执行使用本轮已解析、带权限包装的工具，不重新查注册表。没有发现时数组稳定；发现可能改变缓存前缀。
检查点每个持久安全点记录 loaded_deferred_tools，名称必须属于已解析的工具约定。续跑先校验约定未变，再恢复名称，不重放搜索。旧检查点恢复空集合。工具结果文本绝不当作授权或加载状态。
轮次之外release_turn_tools() 读实时已加载集合
目录上下文组件 deferred_catalog（runtime/context/components.py 的 _build_deferred_catalog），预算的字符串就是发送的字符串。没有延迟工具时为空。
_estimate_one_tool在 runtime/context/budget.py。常驻：描述、参数和少量包装。延迟：名称加换行。两种误差方向相反，所以 test_budget.py 分别对照真实分词结果，误差 15% 内。

不能破坏

规则原因
展开是确定的工具数组是提示缓存前缀的根（models/providers/settings/cache_policy.py；第一个断点在最后一个工具，Anthropic 和 Bedrock 显式模式）。顺序抖动会悄悄错过整个缓存。agent_tools 和 _filter_agent_tools 里不得有 set() 迭代或字典扰动。
绝不把 Agent 的工具存到会话上列表会冻结：之后加入 DEFAULT_TOOLS 的工具永远到不了。list[str] 只表示 /skill 允许清单。
绝不过滤历史历史 tool_use 和 tool_result 从消息渲染，与 context.tools 无关。破坏配对会导致供应商 400。
轮内数组只因发现而增长其他方式会让本轮剩余部分丢失缓存前缀
成本、缓存和回放
问题答案
工具算 token 吗？ContextCommit.total_tokens 不含数组（state/store/session/context_commit/types.py），但供应商计费。压缩预算看不到，输入成本看得到。
缓存？任何增删或重排都会错过整个提示缓存。
历史里有、当前数组没有的调用？能正常回放，只是模型本轮不能再发起。
Commit 回放？不受影响：commit 不存工具数组。
其他项目的做法
项目存储避免过期的方式
opencode按会话的 tools: Record<name, boolean>每轮重新构建，再按意图过滤
claude-code--tools（"" 无，"default" 全部）、--allowedTools、--disallowedTools内置集合是常量；运行时取交集
pi-ai内置开关和扩展工具分开布尔意图；不影响实时加载扩展
hermes预设名称运行时展开（TOOLSETS 移植自它）

全都存意图，没有一个冻结展开后的列表。

边界和扩展

主题状态
供应商内置 web_searchCodex 和 OpenAI Responses 用内置 opts["web_search"]；其他未确认，所以保留工具名路径。确认后在 _overlay_web_search 切换。
没有 mode 的 allowed过滤 DEFAULT_TOOLS；selected 和预设按名称覆盖全部工具
数组的确切 token服务端数字，这里无法静态测量
新的意图维度在 Agent 配置加范围，或在 dict 意图加键。绝不回到存储列表。
