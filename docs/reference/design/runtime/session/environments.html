Environments

Where a conversation's commands and file tools run. A channel (WeChat, Telegram, …) only decides where messages are mirrored. Product page: Run conversations on another machine.

Turn binding

TurnBindings.bind sets the _current_environment ContextVar. current_environment() reads it first, then the current session's environment, then the default. get_active_backend() builds the backend from that and the current session. The tool runtime prompt names the SSH host or Docker image.

  • SSH: the worktree ContextVar is the remote folder, so the permission fence checks it too. remote_workdir runs pwd after cd (~ resolves on the host), cached per environment. Relative tool paths join with posixpath and never touch the host filesystem.
SSH command options 
ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new
    -o ControlMaster=auto -o ControlPath=<state>/ssh/%C -o ControlPersist=300
    <target> 'cd <dir> && <cmd>'
  • Connection sharing keeps each tool call to one round trip after the first.
  • %C hashes host, port and user, keeping the socket under the macOS sun_path limit. ControlMaster is skipped on Windows.
  • A leading ~ reaches the remote shell unquoted so it expands there.
Docker container lifecycle
  • One long-lived container per conversation, openprogram-<env>-<session> (characters outside [a-zA-Z0-9_.-] become -), started with docker run -d --init … tail -f /dev/null.
  • Working folder, project folder and additional working directories are bind-mounted at identical paths. The first mount is the starting folder.
  • A hash of image plus mounts is the openprogram.mounts label. Changed: remove and recreate. Matching: start a stopped container again. A per-process cache skips docker inspect after the first command.
  • Deleting the session removes its containers in a background thread. Without a session ID the backend uses one-shot docker run --rm.

Remote file tools

read, write, edit, apply_patch, glob, grep and list call remote_target(). SSH gets a RemoteFS and delegates to programs/tools/files/_remote.py, with the local tool's output format. Docker and local get None and stay local.

Implementation status

Implemented: local, SSH, Docker; registry, CLI, wizard step, settings page, WebSocket actions; first-message pinning; SSH file tools; per-session Docker containers.

Not implemented:

  • Per-project default environments
  • WSL and cloud environments
  • Password or interactive SSH sign-in
  • Checkpoint or undo for remote files; revert does not restore them
  • Moving an existing conversation to another environment
