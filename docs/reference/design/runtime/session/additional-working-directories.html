The main directory links through project_workdir_for; the fence side is in Sandbox architecture §3.5. A session with no stored list starts from its project's source folders.

Out of scope and extension points
  • CLAUDE.md and project settings are not loaded from additional directories. Permission rules follow the main project.
  • No per-directory read-only grading: once listed, a directory is a writable safe zone.
  • No global additional directories. Cross-session needs are served by projects.
  • Attributed entries: change only _as_str_list and check_path_safety; schemaless storage needs no migration.
  • MCP roots or multi-root IDE workspaces would use the same field as single source of truth.

Composer

  • Project chip, then one chip per additional directory and an icon-only add button (apps/web/components/chat/top-bar/chips/working-dir-chips.tsx).
  • Add and ✕ update local state optimistically; the working_dirs broadcast wins.
  • State is additionalWorkingDirsBySession in the session store, fed by session_loaded, the broadcast and optimistic updates. Not in ComposerSettings or localStorage: it is server data.
  • When list_projects reports path_missing for the session's project, the project chip turns to the orange warning palette with a Solar danger-triangle and offers “Locate folder…”.
