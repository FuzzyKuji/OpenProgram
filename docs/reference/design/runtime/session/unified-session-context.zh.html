统一 session 上下文

安装之后，同一个函数从命令行和 Web 运行应当行为一致。多项能力读取每轮的 session 上下文，调用方没建立时它们不报错，直接失效。

没有 session 时（_store=None）

能力失效点现象
docstring 进 promptrender.py 走不到函数说明到不了模型，Agent 退化成“What would you like to do”对话
DAG 持久化追加节点是空操作运行不进 session 历史
从 DAG 渲染历史_render_history_messages 返回 None每次 exec 看不到前面的步骤
ask_user 跟踪不写占位和完成节点提问不进历史
嵌套 called_by_call_id=None节点归属丢失

写法都是 store=_store.get(); if store is None: return。

上下文的组成

SessionDB (default_db / SessionStore)
  └─ ~/.openprogram/projects/<project-id>/chats/<session_id>/
SessionNodeWriter(db, session_id)      追加 / 更新 / 加载 DAG 节点
ContextVar，成对 set 和 reset：
  _store            SessionNodeWriter  深层代码写 DAG、渲染文档
  _current_turn_id                     文件备份归属哪条消息
  _current_runtime  create_runtime()   Agent 方法自动注入
  _call_id          Agent 包装器       called_by 归属

工作目录（文献综述、想法、论文等研究产出）和 session（对话 DAG）彼此独立，建立 session 不碰工作目录。

设计

一个上下文管理器 session_context 保证 set 和 reset 成对。什么都不传的调用方也拿到真实 session，并能取得它的 id。

r1 = run_research("survey agent reliability")        # None：新 session
r2 = run_research("now turn it into a paper",
                  session_id=r1.session_id)           # 同一 session，历史延续
r3 = run_research("unrelated: GUI agent benchmark")   # 独立 session
  • 一次调用不等于一个 session：连续性由调用方传 id 表达，和 openprogram --resume <id>、Web 客户端一致。
  • 清理归 session 管理（列举、删除），不归每次调用。
  • 阶段说明写在 docstring。上下文装好后，命令行运行不必把说明挪进 content，阶段函数不用改。
