操作流程

Session 目录
<state>/projects/<project_id>/chats/<session_id>/（未绑定时项目为 default）
元数据
id、agent_id、title、created_at、updated_at、source、status="idle" 等
调用磁盘上的 session注册表 _index帧
create_session建目录，写元数据新增一行，立即写入无；通过 list_sessions 发现
append_message日志追加节点行；元数据，对话链前进时包括 headupdated_at。用户消息：preview，超过 80 字符时取 77 字符 + "…"。5 秒内落盘。无；内容走单独的流式通道
update_session只写传入字段相同字段，不动 updated_at，立即写入session_updated，只含变化字段，前端增量更新
list_sessions不读复制行，去掉归档，过滤，按 updated_at 降序，按 offset 和 limit 分页sessions_list：注册表字段、preview、项目目录给的 project
delete_session持 session 锁销毁移除行并立即写入；清除位置，解绑项目session_deleted
set_archived元数据上的布尔值同一布尔值session_updated；未知 id 返回 False

注册表写入都经临时文件加 rename，退出时刷新。SIGKILL 后从日志重建，最多丢 5 秒的预览。commit_turn 在轮次边界保证字段持久。帧由 WebSocket handler 发出。

归档不删除、不移动、不追加，updated_at 不变，取消归档后回到原位（存储一致性）；get_messages 继续可用。

  2. 把 running 行重置为 idle；执行恢复是另一条路径。
  3. 清理未归档且超过一小时的行：

主项目绑定

主目录
项目的路径。对话放在应用状态目录下，按稳定的项目 id 组织，路径变化不影响绑定和仓库。附加目录始终可编辑。
草稿状态
保存在 pendingProjectsByChat[chatKey]，直到 chat_ack；这次发送 set_session_project 是幂等的
只含设置的仓库
创建前可能已存在且没有 id。handle_chat 判断 is_created（元数据 id 或历史）；create_session 把它移到项目位置并保留设置。
首轮之后
set_session_project 只接受当前项目，否则 project is frozen after the first turn（FROZEN_ERROR）。有 session id 时胶囊只读。
移到另一个项目修复缺失的目录
用户把聊天行拖到项目上，或用 Move to project文件夹在磁盘上被移动或改名后重新选择
动作move_session_to_project {session_id, project_id}relocate_project {session_id, project_id, path}
改变session 的项目。SessionStore.move_session，持 session 锁：丢弃缓存的仓库；把 projects/<old>/chats/<id> 和 .file-recovery/<id> 重命名到 projects/<new>/chats/；记录位置，重新绑定注册表，设置 meta.project_id；旧项目追加到 meta.project_history项目路径，不是绑定，所以冻结后仍合法。project_store.relocate_project 校验，改写路径，保留 id。
拒绝轮次运行中（RUNNING_ERROR）；目标已存在。同一项目：不变，不写节点。默认项目：每次 get_default_project 读取都把显示路径恢复为主目录，也没有项目 Git 仓库
回复session_moved {ok, from_project_id, project_id, node_id}、给所有客户端的 projects_changed、新的 projects_listproject_relocated {ok, old_path, path, node_id}、新的 projects_list

两种节点：role 为 code，caller 为 ROOT，predecessor 为 None；形状沿用 context/system_prompt；代码在 state/store/project/relocate_node.py。caller 让 head 不动。不放在对转录隐藏的 context/ 下：这是值得看到的用户动作。

之后效果
移动后的下一轮新项目的路径：project_workdir_for 每次重新解析
移动后的记忆project_layer.left_workspace_ids 把 project_history 映射为工作区，write_target 计入它们标记过的轮次，新项目的记忆只收之后的内容。主目录项目同理，目标是个人工作区。
移动后的设置模型和权限模式随元数据移动；项目默认设置（settings.json）来自新项目
目录缺失project_workdir_for 返回 None，绝不换成默认项目的主目录。项目缺失、被替换、等待中、迁移中或不可用时阻止新的绑定工作。session 仍可读，UI 收到位置状态和缺失路径。
自动跟随文件夹移动
机制规则
身份稳定 id；路径只是属性。Codex 把记录的 cwd 和最近轮次上下文匹配，DeepSeek 按不可变的 session 头 cwd 校验，都不跟踪任意文件夹移动。
原生身份启动、访问、卷重新连接、目录或祖先事件时，解析保存的书签或 inode，匹配则更新路径。不遍历 HOME。
应用拥有存放位置projects/<project-id>/chats/<session-id>/：重定位不移动聊天文件。旧副本经 journal 迁移。撤销恢复留在同级 .file-recovery/<session_id>/<turn>/。
不自动接管名称、Git remote、内容和遗留的 .openprogram/sessions 都不算证据
Locate folder展示预期旧路径和版本后可替换身份。目标已属于其他项目时拒绝，除非被定位的项目已缺失且没有对话：此时并入所有者，由选择器选中。
界面草稿选择器列出 path_missing 项目（点击进入定位流程）；/projects 显示警告和“Locate folder…”
不算空壳位置不可达或 journal 未结束的绑定 session

命名

只有一份实现 turn_runtime/titles.py：WS、函数形式、channel、CLI、spawn 都走 finalize_turn end → _maybe_auto_title。Channel 只多一个品牌 logo，显示在侧栏、聊天页和命令面板。

标记含义设置者
_user_titled用户输入的标题：永久锁定只有 rename：输入名称时设置，生成名称时清除
_auto_titled已有自动标题：不再截断。与锁分开，因为截断本来就要被取代。_maybe_auto_title，以及生成名称的 rename
_title_gen_count命中了 _RETITLE_AT_TURNS 的第几项_maybe_auto_title 内部
情况规则
时机第 1、6、16、40 次回复；首条用户消息是寒暄时再加 2、3。有 _user_titled 时不做。
第 1 次回复，立即_title_from_text(首条用户消息)：去标记，取首行，50 字符 + "…"；_auto_titled=True、_title_gen_count=1
然后，后台LLM 标题替换记下的标题，_title_gen_count=N+1，广播 session_updated。期间出现 _user_titled 或标题变化则放弃。
摘录build_title_context(get_branch(id))，1,000 字符内（2 × _MAX_INPUT_CHARS）。用户文本和每轮最终回复；不含工具记录、附件标记和 <think>。
寒暄问候、感谢、确认，或一两个字符如 hl。开场寒暄连同回复丢弃；之后的低内容消息丢弃，回复保留。全是寒暄时全部保留。
一定包含第一个实质轮次和最新轮次。其余由新到旧填充，… 标记缺口。
输入名称update_session(title, _user_titled=True)
Auto rename（标题为空）_llm_rename() → _user_titled=False、_auto_titled=True、_title_gen_count=max(1, N)。期间标题或锁变化：superseded，不写入。
