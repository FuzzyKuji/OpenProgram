附加工作目录

语义与 Claude Code 的 additionalWorkingDirectories 相同。

主目录附加目录
模型 cwd（system prompt、--cd、工具 ContextVar）项目路径不变
对话存储projects/<id>/chats/不变
acceptEdits 围栏白名单在内加入
告知模型工作目录“Also writable: /a, /b”
存放项目绑定SessionRunConfig，session 元数据
会话中修改首轮冻结；只能移动或修复随时，下一轮生效

主目录经 project_workdir_for 关联；围栏部分见沙箱架构 §3.5。没有已存列表的 session 从项目的源文件夹开始。

不做的事和扩展点
  • 不从附加目录加载 CLAUDE.md 和项目设置，权限规则只跟主项目。
  • 不分只读和读写：进入列表就是可写安全区。
  • 没有全局附加目录，跨 session 的需求用项目解决。
  • 条目要带属性时，只改 _as_str_list 和 check_path_safety；无 schema 存储不需要迁移。
  • 接入 MCP roots 或多根 IDE 工作区时，用同一字段作唯一来源。

数据路径

阶段代码行为
选择WorkingDirChips、POST /api/pick-folder最近项目，或原生选择器里的“Choose folder…”
发送set_working_dirs {session_id, dirs}完整列表。草稿还没有 id，列表随首个 chat 帧发送
校验并保存ws_actions/session/run_config.py 的 handle_set_working_dirs每项 expanduser() 后必须是目录；一项非法则整帧拒绝并说明原因。存展开后的路径，不存 realpath。广播 working_dirs
持久化save_session_run_configNone 表示不变，chat 帧不会清空列表
重新加载session_loaded.data.settings刷新或换客户端后恢复列表
每轮load_session_run_config → TurnRequest.additional_working_dirs
围栏runtime/permissions/identity.py 的 _path_is_safe → check_path_safety[current_worktree_path() or getcwd(), *dirs]
Promptruntime/context/components.py列表非空才有这一行

Dispatcher 每轮把真实 cwd 绑进 current_worktree_path，getcwd 只是兜底。

输入框

[my-project]  [foo ✕]  [bar ✕]  [＋]
  • 项目胶囊之后，每个附加目录一个胶囊，末尾是仅图标的添加按钮（apps/web/components/chat/top-bar/chips/working-dir-chips.tsx）。
  • 添加和 ✕ 先乐观更新本地状态，以 working_dirs 广播为准。
  • 状态是 session store 的 additionalWorkingDirsBySession，来自 session_loaded、广播和乐观更新。不进 ComposerSettings 或 localStorage：这是服务端数据。
  • list_projects 对该 session 的项目报告 path_missing 时，项目胶囊变为橙色警告样式并显示 Solar danger-triangle，菜单提供“Locate folder…”。

不变式

规则原因
只影响围栏和 prompt接到 cwd 或存储会破坏上表
围栏和 prompt 的 cwd 都来自 current_worktree_path()否则模型以为能写，围栏却拦，审批循环出现
整表替换幂等，没有“已添加”的边界情况，也没有部分写入
无 schema 的 session 元数据旧 session 读出空列表，无需迁移
整个 session 生命周期可编辑这是会话中放宽围栏的唯一方式
主项目缺失时解析为 None换成别的目录会给模型一个用户从没选过、看似合理的 cwd
