运行环境

对话的命令和文件工具在哪里运行。channel（微信、Telegram 等）只决定消息镜像到哪里。产品页：在另一台机器上运行对话。

类型后端命令形式工作文件夹本机沙箱
localLocalBackend本机子进程本机生效
sshSshBackend(target, workdir)ssh … <target> 'cd <dir> && <cmd>'远程绝对路径关闭；隔离靠远程账户
dockerDockerBackend(image, container, mounts)docker exec -i [-w cwd] <container> sh -c <cmd>本机路径，以相同路径挂载关闭；隔离靠容器

workdir绝对路径或以 ~ 开头

代码：openprogram/host/environments/__init__.py。写入都走 update_config（跨进程锁）。openprogram environments、安装向导和 WebSocket 动作 list_environments、save_environment、delete_environment、set_default_environment、test_environment 都是薄层。每次修改广播 environments 帧。

轮次绑定

TurnBindings.bind 设置 _current_environment ContextVar。current_environment() 先读它，再读当前 session 的环境，最后取默认。get_active_backend() 据此和当前 session 构造后端。工具运行时 prompt 写明 SSH 主机或 Docker 镜像。

  • SSH：worktree ContextVar 是远程文件夹，权限围栏也按它检查。remote_workdir 在 cd 后运行 pwd（~ 在远端解析），按环境缓存。相对工具路径用 posixpath 拼接，不碰本机文件系统。
SSH 命令选项 
ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new
    -o ControlMaster=auto -o ControlPath=<state>/ssh/%C -o ControlPersist=300
    <target> 'cd <dir> && <cmd>'
  • 连接共享让首次之后每次工具调用只需一个往返。
  • %C 对主机、端口、用户取哈希，socket 路径不超过 macOS sun_path 上限。Windows 跳过 ControlMaster。
  • 文件夹开头的 ~ 不加引号传到远程 shell，在那里展开。
Docker 容器生命周期
  • 每个对话一个长期容器 openprogram-<env>-<session>（[a-zA-Z0-9_.-] 以外的字符变为 -），用 docker run -d --init … tail -f /dev/null 启动。
  • 工作文件夹、项目文件夹和附加工作目录以相同路径绑定挂载，第一个挂载是起始文件夹。
  • 镜像加挂载的哈希存为 openprogram.mounts 标签。变了就删除重建，相同就重新启动已停止的容器。进程内缓存让首条命令后跳过 docker inspect。
  • 删除 session 时在后台线程删除其容器。没有 session ID 时用一次性的 docker run --rm。

远程文件工具

read、write、edit、apply_patch、glob、grep、list 调用 remote_target()。SSH 得到 RemoteFS，交给 programs/tools/files/_remote.py，输出格式与本地工具相同。Docker 和本机得到 None，走本地路径。

操作做法
stat一条 test 命令：存在、目录、大小
read_bytescat，上限 32 MiB
write_bytesmkdir -p，在同一文件夹写临时文件，再 mv 覆盖目标
退出码 255ssh 自身失败：ConnectionError，作为错误报告，不当文件内容
glob在远端 find，再用由 glob 转换的正则过滤。GNU -printf 取 mtime，BSD stat 兜底
grep有 rg 就用它，否则 grep -rE，用 head 截断
listShell 循环
读 PDF字节复制到本地临时文件，用本地读取器
先读后改按（session、主机、路径）记 sha256。覆盖文件的 write、edit、apply_patch 在未读过或已变化时拒绝
write 的 source_pathSSH 下拒绝：它会悄悄跨机器

胶囊显示和行为
环境始终显示。图标按类型（monitor、cpu、box），颜色是 worker 连接状态，文字是名称。草稿：环境列表和 Settings → Environments 链接。已有对话：其他环境置灰，并说明选择已固定
Channel始终显示。未绑定：聊天图形和“No channel”。已绑定：ChannelLogo 和账号 id，被挤压时只留 logo。channelHealth 是角上 6px 圆点：黄色降级，红色不可达。菜单每个有启用账号的应用一行，各有账号子菜单（已绑定的打勾），绑定时再有“Disconnect”，最后是“Manage channels”

胶囊是输入框设置 channel 的唯一位置。菜单和胶囊共用 channel-choices.ts，跟随输入框所在窗格（useBoundChat）。statusBadge 和 channelHealth 是独立的 store 切片。
