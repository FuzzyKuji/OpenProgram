存储一致性

数据模型见会话存储。

注册表时间与快照

updated_at 是最后一次内容追加的时间，不是最后一次元数据写入的时间。

操作合同
_persist_meta改名、置顶、已读、分支标记和 HEAD 不改变时间；追加才推进。
_index、list_sessions()读者拿到每行的点时副本；并发创建、更新、删除不撕裂字段，也不破坏迭代。
延迟 flush旧快照不能覆盖新快照；发布期间的更新保持 dirty，由下一次 flush 保存。

状态流

  1. 追加时生成一个时间值，同时写入会话元数据和注册表条目。
  2. 注册表更新持有状态锁；列表在锁内复制行，在锁外过滤和排序。
  3. 保存者取得写锁，在状态锁内捕获 JSON 并只清除已覆盖的 dirty，然后释放状态锁。
  4. 原子发布在状态锁之外执行。
  5. 并发更新重新标记 dirty，由定时器或退出 flush 发布。

失败与兼容

情况行为
写盘失败告警；内存继续服务；下一次更新或 flush 重试。
返回的行是副本，调用方修改不影响注册表。
创建保留显式传入的历史时间；重建不迁移 schema。
排序按 updated_at 降序，缺失视为 0；wire shape 不变。

Merged heads 原子更新

mark_merged(session_id, head_ids) 是集合并集。子 Agent 完成、task runner 和 Web 分支操作可能同时调用，每次更新都要保留。

属性要求
原子性读取、去重、追加和更新 idx.meta 在同一个 idx._lock 临界区内。
顺序保留既有顺序；新的非空、strip 后的 ID 按输入顺序追加。
幂等重复不新增；没有新值就不写盘。
持久化_persist_meta 在锁外执行；至少一个最终快照含完整并集。
范围与验收

只约束这次 read-modify-write：不引入 transaction API，不改分支命名、DAG 删除或索引 flush 协议。

  • 两个调用方并发写入不同 head：内存和重载后都含两者。
  • 空白和重复输入保持清理与幂等语义。
  • 持久化在 idx._lock 之外；异常和调用方行为不变。

Store 锁范围

一个会话的慢 I/O 不能阻塞其他会话。

资源锁要求
_locations、_sessions、LRU 顺序_lock只碰内存：不扫目录、不原子写、不 fsync、不递归删除。
单个会话的加载、重建、删除和失效每会话 RLock同一会话串行，不同会话并行；没有 transaction 层。
locations.json 发布_locations_write_lock在状态锁内捕获，释放后写入；旧快照不能覆盖新快照。
SessionMemoryIndex 持久化_persist_lock，然后 idx._lock保持锁序和 stale rebuild 语义；idx._lock 内不做 I/O。
范围与验收

文件格式、LRU 容量、删除语义、跨进程 stale 检测和 Windows 行为不变。

  • A 阻塞在 read_meta 或 list_history 时，B 的缓存读取在有界时间内完成。
  • A 的递归删除阻塞时，B 的读取不等待。
  • 并发首次加载只发布一个缓存对象；加载不会重新发布已删除的对象。
  • 两个会话并发更新位置后，重载的 locations.json 含两项。

缓存快照新鲜度

  1. 缓存重建和首次加载在读取历史与元数据之前获取磁盘指纹。
  2. 重建后的索引只记录这个指纹，绝不记录更新的指纹。
  3. 并发原子替换会改变指纹，下一次公共读取因此重建。
验收

两个真实 SessionStore 实例。写入发生在读者加载旧快照之后、标记同步之前；下一次 get_nodes 或 get_session 看到新值，缓存和首次加载路径都覆盖。取消重试保留原有时限，并读取实际的取消文件。

Windows 会话目录删除

显式删除、过期清理和容量清理共用一个平台适配器（openprogram/host/_platform/filesystem.py）。

失败处理
普通 Git 对象，只读属性清除属性，重试该次删除一次。
其他权限失败沿用调用方的尽力处理；不改 ACL，不跟随链接。
验收

公开的 reopen 和 delete_session 入口配只读 Git 对象；目录确实消失，而不只是从索引移除。必须原生 Windows CI。遵循 shutil 只读文件删除示例，回调兼容 Python 3.11。
