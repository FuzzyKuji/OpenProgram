Data model

On disk

<state>/projects/
├── projects.json                       project registry
├── <project_id>/                       `default` is the home project
│   ├── settings.json                   project defaults
│   ├── memory/                         the project's memory workspace
│   └── chats/
│       ├── <session_id>/
│       │   ├── main.jsonl              the session's log, written by the Worker
│       │   ├── agents/<pid>-<id>.jsonl log of another writing process
│       │   ├── functions/<id>.jsonl    one durable function's completed steps
│       │   ├── large_nodes/            bodies too large for a log line
│       │   ├── context/                persisted context artifacts
│       │   └── workdir/attachments/    uploaded files
│       └── .file-recovery/<session_id>/<turn>/   per-turn file undo
├── .chats-index.json                   registry (summary cache)
├── .chats-locations.json               durable session-id → directory map
├── .migration/                         migration journal and staging
├── .deleted/                           durable delete intents
├── .quarantine/                        log-less shells moved at startup
└── .locks/ .session-locks/             inter-process coordination
  • A session with no project lands under default/chats/. A store opened on another root (application runs, an embedding host) uses the same placement.
  • Moving renames the directory and records it in .chats-locations.json, the durable authority during migration or relocation.
  • A working folder is never the conversation directory. <project>/.openprogram/sessions/<id>/ is read only as a legacy migration source.
  • projects.json is published whole by rename. A change holds the registry lock for its read-modify-write; a lookup takes no lock and parses a published file once.

The session log

Each line is {"ts", "type", "data", "crc"}: nanosecond timestamp, CRC of the line. Lines are only appended.

Line typeRecords
node.put, node.patch, node.deleteA DAG node written, changed or removed
meta.patchTitle, settings and other session metadata
file.putA whole small document: jobs.json, notices.json, inbox.json, todos.json, open_work.json, always_on.json, always_on_reports.jsonl
turn.*Agent journal: snapshot, model decisions, tools started and their results
turn.rowsChanges to the run tables
function.*In functions/: a durable function's steps, requests and saved state
  • One writer per file: the Worker writes main.jsonl, any other process its own file under agents/.
  • Reading folds every file in timestamp order and skips a line whose crc fails, which only a stopped writer's last line can be.
  • A process keeps its fold and reads what was appended since. It refolds from the start if a known file was replaced or shrank, or a new line sorts before what it has.
  • Only realtime push fragments are not kept.

Run state

Executions, attempts, effects, waits and commands are folded from the same logs into plain Python tables in the Worker's memory, with their own transactions, undo and uniqueness rules. No database. A committed change is a turn.rows line.

ItemRole
~/.openprogram/active/<session>Marks unfinished runs; folded at startup. Others fold when first asked for. Deleting a conversation removes its marker, and startup drops one that names a deleted conversation
run_index.jsonlExecution → session
revisions.jsonlWorkflow versions and approvals, and global budgets
Idle sessionLeaves memory an hour after its last change, returns from its log
Function subprocessReads tables only. Steps go to its log under functions/; run-state changes (sub-agent start, Auto review verdict, pause, question) go to its parent via runtime/execution/worker_calls.py
Scheduled runA task's turn runs in a process of its own and writes that turn's rows to its own file under agents/. Sub-agents it starts go to the Worker through worker_calls.py, and the Worker runs them. The Worker reads the turn's rows again when the process ends
worker.lockHolder owns every run except a turn whose lease names another process (a scheduled run, ACP, MCP). No heartbeats; the OS releases it on exit
Job admissions, reservationsRun tables, in the session's log
usage.db settlementEvent commits first, reservation settles after. Startup settles any reservation whose event exists, so nothing counts twice

In progressNew Worker

An interruption is what the log shows when a turn has no final line, not a stored state. Planned upgrades wait for runs first.

A killed Worker never clears running, which would pin the chat at data-run-active="true". Registry load resets running to idle; reconcile_interrupted_runs() then turns a row still running into interrupted and cancelling into cancelled, separately from the node sweep, because a Worker killed between the status write and the placeholder leaves a running row with no running node.

Moving HEAD

_set_active_head (interfaces/server/server_runtime/session_persistence.py) coordinates an explicit checkout. SessionStore owns HEAD; _save_session does not write the mirror’s head or messages back.

  1. Atomically compare the source head, branch identity and settings, then save the source configuration and select the destination. The expected settings are read from disk in their stored form, so a record that has no agent_id yet (one first written by a model pin) still compares equal.
  2. Under the mirror lock, re-read current branch settings, head and messages. Branch references retain independent settings even at the same head.
  3. Drop the message cache.
  • Used by retry, edit, sibling checkout, deepest-leaf jump, branch checkout, branch delete, attach, rewind.
  • Refused while a run is in flight (_is_run_active): RUN_ACTIVE_ERROR, code: "run_active". Otherwise a reply lands on a branch the user left, or on a tail being deleted.

Cache and attachments

  • SessionStore holds lazy (SessionLog, SessionMemoryIndex) pairs in a bounded LRU cache. SessionLog owns the files; the index holds folded nodes, edges and active head.
  • Browser uploads are copied to workdir/attachments/ before dispatch, and markers keep the saved absolute path.
  • Channel files stay in <state>/channels/*/accounts/*/attachments, separately readable by the attachment path policy.
  • Only the exact shape <project>/.openprogram/sessions/<session_id>/workdir/attachments/<relative> may be rebased to that session's current directory (attachment UI, file reader, send_file). The result must stay under an allowed root, with no .. or symlink escape. Other old paths are never remapped.
