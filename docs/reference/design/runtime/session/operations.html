  2. Reset running rows to idle; execution recovery is separate.
  3. Clean up unarchived rows older than one hour:

A held conversation folder

Windows refuses to rename a folder while any file inside it is open. The Worker keeps none open between writes, so the holder is a reader in another process, an indexer, an antivirus scan, or a command running in the work folder. move_session_folder retries for one second, then raises SessionFolderBusy. A folder is never copied instead.

RenameWhen the folder stays held
Move to another projectsession_moved carries ok: false and the error; folder, recovery tree, binding and turns are unchanged. If the recovery tree is the held one, the conversation is renamed back first
Binding a draftset_session_project: the binding changes and the folder stays, recorded in the location map. First message: the create fails and the draft keeps its settings
Startup quarantineThe shell stays and the empty quarantine entry is removed
Publishing a migrated copyThe journal row is failed with the error; the source is untouched, and the next run publishes the verified copy

If the conversation cannot be renamed back either, the location map names its new folder so it stays readable, and the error names both folders. Moving it to the same project again finishes the move: the recovery tree joins the conversation, then the binding changes.

Archiving sets a field and deleting removes files in place; neither renames a folder. A conversation id never changes.
