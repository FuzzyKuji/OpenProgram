包结构

openprogram/runtime/内容
agent/一次模型调用：Agent 类及其使用 Context 的方式、agent() 和 llm()、工具循环（loop/：loop.py、driver.py 中的 LoopDriver、AgentSession、工具和事件类型、重试）以及 Runtime。这是 Agentic Programming 的代码。
conversation/建立在 Agent 上的对话和轮次：turn_runtime/ 运行一轮，chat.py 是 ChatAgent，production_driver/ 把一轮作为规范执行驱动，run_control/ 跟踪运行中的轮次；还有会话设置、收件箱、未完工作、回退和常驻 Agent。
jobs/后台运行：作业存储、运行池、resource_governance/（准入和限额）。
agent_registry/保存的 Agent 配置：有哪些，各自的模型、工具和工作区。
permissions/工具调用能做什么：policy（唯一决策）、identity（非所有者的限制）、refusal（拒绝文本的唯一来源）、审批、审计、authority（谁在请求）、attended 模式（无人值守时不提问）。
context/Context 类（model.py）和决定模型看到什么的一切：渲染、压缩、系统提示、session_db.py。
execution/暂停、取消和恢复的控制面：执行存储、修订、等待、检查点。
events/事件总线。
scheduler/、proactive/、commands/定时运行、主动策略、斜杠命令。

一个运行时，一个会话

调用作用
create_runtime()打开会话
runtime.exec()在其中发送一次请求
runtime.close()关闭会话

没有 reset() 或 new_session()；新会话就是再调用 create_runtime()。两段独立对话需要两个运行时对象，这种情况很少。

为什么一个 Runtime 不复用多个会话
  • CLI Provider 的会话状态在子进程里；复用要在 Runtime 上挂可变的当前会话 id，引入并发竞争。
  • API Provider 本身无状态；多会话只是上层的一个 dict，没有新能力。
  • ContextVar 注入依赖运行时绑定到当前函数树。

运行时通过 ContextVar 注入

没有 runtime= 的 Agent 方法读取 _current_runtime ContextVar。入口函数两者都没有时调用 create_runtime()，并在退出时关闭。子函数继承父函数的运行时。

未采用原因
每个签名显式写 runtime: Runtime与函数逻辑无关的传递代码，每层嵌套都要重复
模块级单例跨线程和协程共享，并发 Agent 互相干扰。ContextVar 按线程和协程隔离。

会话型与 API 型 Provider 共用一个抽象

作者看到的是 llm(...) / agent(...)，最终都到 runtime.exec。has_session 决定内部路径。

会话型 Provider（CLI）API Provider
对话记忆由子进程保存无；每次 exec 独立
上下文注入跳过 DAG 渲染；只发 docstring 和当前内容经 render_context + render_dag_messages 从 DAG 组装历史
render_range.subcalls无效限定注入历史的范围

两个 Runtime 类意味着每个函数两份实现，破坏“函数描述任务，Provider 描述通道”的分层。代价只是一个条件分支。

重试在运行时层

exec() / async_exec() 带 max_retries，默认 3（OPENPROGRAM_MAX_RETRIES），对所有 Provider 生效。Provider 只管收发；重试、限流、缓存都在运行时。

  • 网络超时、限流和 5xx 共用一个策略。
  • 统一的失败格式：Attempt N: ErrorType: msg。
  • TypeError、NotImplementedError 和 ImportError 不重试：Provider 的 bug 或缺失的子系统不会因重试消失，走完退避只会推迟失败。

DAG 写入

时机写入
进入 Agent 方法code 节点，status=running；_call_id 指向它
函数体内 runtime.exec()_call_id 下的 llm 节点，caller = _call_id
退出（return 或 except）回填同一 code 节点的输出和状态
expose="hidden"不写 code 节点；仍设幻影 _call_id，让内部 LLM 调用有帧可引用

写两次而不是完成时写一次：可视化能立刻显示运行中的调用，异常退出也有节点记录错误。

嵌入接缝

核心可运行在非 OpenProgram 的宿主中（嵌入你自己的技术栈）。tests/component/runtime/test_standalone_embed.py 执行该契约：

  • import openprogram 和完整的 Runtime(call=...).exec() 往返不引入 webui、FastAPI、Uvicorn 或 Textual。
  • 使用 SessionStore(root_path=...) + session_scope(store, session_id) 时，运行绝不查询 openprogram.state.paths；没有绑定存储时不持久化。
接缝核心默认平台注册
set_cancellation_check（openprogram.host.cancellation）空操作openprogram.runtime.conversation.run_control 在导入时注册精确的执行检查
set_session_id_providerNone；runtime.can_ask() 为 Falserun_control 提供活动会话 id
session_scope(store, id)未设置；不持久化调度器绑定每轮存储

钩子与 add_pre_invocation_hook 同型，保持单向依赖，同时由 run_control 检查精确的执行令牌。
