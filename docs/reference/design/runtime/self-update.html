In-conversation self-update

An Agent changes OpenProgram in a private worktree. The change becomes a sealed version, is tried on a copy of the data, and is switched to by the old version from outside the worker. Any failure returns to the version that was running. Official releases follow Automatic updates.

Rules

SubjectRule
WritingNever gated; only activation is checked
Running codeAlways a committed version
TurnsRefused at no point; during the switch they are held and run afterwards
Activation and rollbackDone by the old version's out-of-process controller. A changed updater applies from the next switch. A candidate's worker reports and never transitions an update that names it.
Rollback scopeCode only
What may changeAnything, with no protected-path list. Three fixed protocols are read by things that do not self-update: the pointer format, the <state>/self-updates/ files, the shell's main-process contract.

Validation
prepare requires an existing, linked, clean worktree with commits beyond local; errors return to the model. The candidate may be based on any ancestor of local; it is rebased, not refused.
Authorization
In default mode the owner's call runs without a card. Ask mode or an ask rule produces the ordinary card. A non-owner is refused by identity.
Acceptance
goal, assertions, verification_plan keep one acceptance-N check per assertion. self_update_observe is the verifier's only way to observe; in trial it targets the trial port.

Pointer

schema=1
generation=17
version=<id>
base=<base>
last_good=…              last_good_base=…
previous_good=…          previous_good_base=…
probation=u_7f3a9c       probation_deadline=1794134010
writer=controller

ASCII key=value lines, readable from C, batch, Python, Node and shell. Names and meanings are frozen. probation is empty when no switch is being verified.

  1. Take current.lock with exclusive create; break it past 10 s.
  2. Read current; on a generation mismatch release and fail.
  3. Write current.<pid>.tmp with generation + 1, fsync. Copy current to current.prev the same way; the write ending probation stores the committed pointer there, so a repair cannot bring back an expired probation.
  4. POSIX: rename, fsync the directory. Windows: MoveFileExW with MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH, retried 20 times at 50 ms on access or sharing errors.
  5. Release the lock. A lock that cannot be removed does not undo the move; it expires by age.
Implementations
versions/pointer.py, JavaScript in the shell, C in the launcher, bootstrap/versions.py. No symlinks, no junctions.
What a switch replaces
This one file, after the worker has stopped. versions/ and bases/ are never rewritten once sealed, so an interpreter or DLL that a process or a scanner still holds is never in the way of a switch; it only delays retention.
Writers
Controller, launcher guard, shell recovery page, bootstrap/versions.py, installer
Missing or unparsable
Rebuilt, never reseeded: from current.prev, else rebuild-pointer picks the newest version whose commit is reachable from local, writer=bootstrap.
Rollback conflict
Reread; version no longer the candidate means done. Still failing at the deadline: write pending-rollback, applied by the launcher.

Building

Run by the controller in versions/.staging-<update>/ from the task's worktree, or a temporary detached worktree for a kind without one.

Prepare

  1. Disk: a new base if needed, the version, the trial copy and 2 GB of margin; else abort with both sizes.
  2. Classify paths with delivery/activation.py.
  3. Base: reuse, or build-base.sh/.ps1 into bases/.staging-<id>, the recipe build-product-runtime.sh also calls. Unchanged pins are cloned. Needs network. A changed Python minor aborts: the launcher is compiled per minor.
  4. Venv, then the base renamed into place after verify-product-runtime.py passes.

Assemble

  1. git archive <commit> openprogram pyproject.toml into site-packages; generated dist-info.
  2. Frontend: cloned if no web, docs, tui component changed; else stage-release-assets with --node-modules <toolchain>. A changed lock runs npm ci --ignore-scripts.
  3. desktop/ from git archive of apps/desktop/main*.
  4. apps/desktop/shell/compat.json outside the shell's range aborts: “this change needs a new signed shell release”.

Seal

  1. compileall --invalidation-mode unchecked-hash.
  2. version.json, files.tsv, pristine.zip; fsync everything; rename to versions/<id>.

Activation

StepAction
quiescing 1Wait up to 10 minutes for no running task; checkpoint what runs with delivery/restart.py. Give up at 30 minutes.
2Probe the old version; store doctor rows and subsystems as reference. Only /healthz or identity failing aborts.
activating 3Write switching, enter_maintenance with a deadline. Owner messages and scheduled or always-on wakes go to self-updates/held/ (control/held_turns.py): “Switching versions; this runs as soon as that finishes.” The verifier source stays admitted.
4Checkpoint anything started since step 1.
5Journal {update, from, to, generation}; stop the worker without unloading its service definition.
6With a destructive trailer: snapshot every *.db, projects/, sessions/, functions/, memory/, active/, revisions.jsonl, run_index.jsonl, config.json to backups/pre-switch-<update>/.
7Compare-and-set the pointer: candidate, probation, deadline now + 600 s.
8Start through the launcher; up to 120 s for candidate identity, 30 minutes with migration progress.
verifying 9system_probe under the regression rule; subsystems against step 2.
10Turn check: a real turn, the owner's default model, one read tool call, the single admitted job. Provider or network error: inconclusive, no rollback. The candidate's own code failing: rollback.

12Probation 120 s: same worker pid, no subsystem regression. If desktop changed, relaunch the shell; main-ready and window-loaded within 30 s.

/api/diagnostics reports subsystems: scheduler, always-on, each channel, job runner, as running, deferred or failed. Every switch is a worker restart; the hot level exists only for user Programs.

Retention

Kept
current, last_good, previous_good; 5 most recent successful versions; each update's controller_version and candidate_version while non-terminal or queued; the version an open shell loaded (shell.json, live pid); versions whose boot/<id>.attempts was touched in 10 minutes; the frontend zips kept versions name
Deletion
Rename to trash/<id>, then delete. A read-only file, such as a Git object on Windows, is made writable and tried again. Unreferenced bases go the same way.
Left behind
A tree a running process holds, or a file that stays locked. The pass lists them in Plan.remaining, logs them, and the next pass tries again.
When
After succeeded and at worker start, never while the slot is held. Failed candidates after 7 days, work/<task> from aborted updates after 14.

Direct edits to a running version

At next start a files.tsv mismatch runs bootstrap/restore_version.py <version>. The owner is told once. Built-in applications are not hot-loaded when layout.managed(); developer checkouts keep hot loading.

  1. Compare hashes with pristine.zip and the frontend zip; only metadata differs: rewrite files.tsv, stop.
  2. Save changed and added files and a patch under unapplied/<stamp>/.
  3. Restore from the zips, removing added files except __pycache__.

Official updates

Discovery stays in update-service.js. Assets: version-<platform>.tar.zst, repo.bundle, SHA256SUMS, signed manifest, plus base- and toolchain- when changed.

  1. official/replay.py verifies assets and fetches the bundle into refs/heads/release.
  2. No user commits: unpack the prebuilt version, go to trial.
  3. User commits: in work/official-<version>, cherry-pick old_release..local oldest first. A conflict saves unreplayable/<release>/<sha>.patch and continues.
  4. Build, trial, activate with kind = official, one record per candidate, by control/official_update.py. No independent verifier. The old tip is saved under undone.
  5. A failed clean replay retries with user commits dropped newest first, at most 5 times, ending at the unmodified release.

A release needing a shell_compat outside the shell's range waits for the DMG or EXE shell update.

This machine (dev_stable)

The development instance is the trial and promotion is the switch. Both Apps run in the shell's embedded mode. See Development instance. The detached controller runs from a private copy (delivery/controller_bundle.py) and clears OPENPROGRAM_SESSION_ID.

Land

  1. Rebase the candidate onto dev.
  2. git merge --ff-only <sha> in the primary checkout, up to 10 tries. A rebase conflict or overlapping dirty file: aborted with the list.
  3. openprogram dev deploy <sha>.

Promote

  1. system_probe and browser probe on 18200.
  2. Wait up to 30 minutes for no stable tasks.
  3. If stable contains the commit, go to step 8. Else openprogram dev promote <sha>. On “only the commit the development instance serves”, redeploy, repeat step 4 once, promote again; a second refusal: aborted.
  4. Promote retries a failed refresh once. Still failing or unhealthy: git revert on dev, deploy, promote. rolled_back names the revert.

Deliver

  1. Deliver after stable restarts.

Undo here is git revert on dev. The trial engine and version layout run in tests with temporary HOME and ephemeral ports.
