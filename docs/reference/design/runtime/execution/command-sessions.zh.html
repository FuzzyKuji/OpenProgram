bash

bash(command, workdir, yield_time_ms, tty, description)

  1. prepare_command 解析 workdir（worktree、沙箱检查、远程 cd 防护）。
  2. session.run 检查会话上限，processes.start 在独立的 supervisor 下启动命令。
  3. collect 每 50 毫秒把输出读入 1 MiB 的首尾缓冲，直到命令结束或等待时间到。
  4. 已结束：Process exited with code N 加输出，记录移除。仍在运行：记录设 background=True，回复 Process running with session ID <id>。

write_stdin

write_stdin(session_id, chars, yield_time_ms) 在会话中查找（相同 session_id 或其范围内的执行）。

显示退出的回复会把记录标为 reported。

会话上限

每会话最多 64 个活跃会话。到达上限时，停止最近八个之外最久未用的会话并标为 reported，新回复会指明它。没有空闲超时。

退出通知

run_exit_notices 在 worker 中运行，每 2 秒扫描。

  1. unreported_exits()：background、未 reported、状态 exited 或 failed。stopped 的命令不发通知。
  2. 会话有运行中轮次或非终态执行时跳过，之后重试。
  3. 克隆最新的聊天请求，设 source="process_exit"、新的用户消息 id 和通知文本（命令、退出码、耗时、最后 2000 字符），以键 process_exit:<id> 准入。没有聊天执行时直接标记已报告，不发通知。
  4. 用户节点为 display="runtime"，记忆跳过它。

审批
write_stdin，空或 "\x03"无需决定（SESSION_POLL）；bash 已批准该命令
write_stdin，其他输入按模式处理，同 bash。在 Auto、MCP 和委托约束、危险允许规则中算高风险工具。
terminal_use input, interrupt, close任何标签页都按模式处理。卡片（TerminalApproval）显示标签页、目录、是否有命令运行、未完成的人工输入，以及拼写出控制字符的确切输入。
进程层
部分行为
group_guard，管道以 /dev/null 作 stdin 运行命令
group_guard，tty打开 pty 作为自身会话的控制终端，把进程组置前台，设 30×120，并泵送 master 与 supervisor 管道。进程组和会话里其他进程组（set -m 的作业、调用过 setpgid 的子进程）都空了以后停止读取，最晚在进程组结束两秒后：macOS 上 guard 持有终端时不会报告输出结束，而完全关闭的 pty 会丢弃未读输出
group_guard，信号忽略 SIGINT 和 SIGTERM，因此中断到达命令
Supervisorwrite 不加换行；interrupt 向进程组发 SIGINT（Windows：终止进程树）
ProcessStore记录 tty、sandboxed、background、reported、last_used。take() 返回未读输出和读取前丢弃的字节数。
tty 支持macOS 或 Linux 的本地后端

界面
Activity只列后台会话；第一次等待中的命令是活动工具调用
Resources运行中的后台会话列在 Terminal 组的 Background terminal；保留的输出在 xterm 中只读显示，带停止；随 3 秒的托管进程轮询刷新
工具行write_stdin：“等待输出”“中断命令”“输入”。terminal_use 输入：“在终端输入”。
