Next-step decisions

Code lists a fixed menu. The model answers with JSON naming one option. Only a validated answer runs; code stays in control. Source: openprogram/runtime/agent/decision.py.

An Agent method can be both a native tool for exec(tools=[...]) and a decision option. See tool calling.

Pure decision: decision.make

from openprogram import Agent, decision

class ExampleAgent(Agent):
    method_options = {"route_message": {"tool": True}}

    def route_message(self, msg: str) -> str:
        return decision.make("Pick a way to handle this message.", {
            "analyze":  analyze_sentiment,    # function: run, return its result
            "fallback": fallback_reply,
            "done":     "CONVERSATION_OVER",  # value: returned as-is
        })

The decision is the branch: the caller writes no if.

Work, then decide: agent(choices=)

from openprogram import Agent, agent

class ExampleAgent(Agent):
    method_options = {"handle_ticket": {"tool": True}}

    def handle_ticket(self, ticket: str) -> dict:
        return agent(
            f"Handle this ticket: {ticket}",
            toolset="default",        # the work: tools and reasoning
            choices={                 # the wrap-up: must pick one
                "refund":   issue_refund,
                "escalate": escalate_to_human,
                "close":    {"status": "closed"},
            },
        )

choices goes to Runtime.exec, which adds the menu and DECISION_FINISH_INSTRUCTION to the prompt and runs a normal turn. The last reply must be a {"call": ...} JSON, resolved by resolve_decision. decision.make is the same with no work before it.

A list works too. Each item: a callable, (callable, "description"), "name", ("name", "description") or ("name", "description", schema). A function's name comes from __name__.

Always the same structure, no branching: a single-option decision.make, or exec(response_format=...).

From reply to result

  1. render_options writes the menu: signature, description, arguments, one-line Call: JSON example. Only source="llm" arguments show.
  2. The model is called: runtime.exec(prompt + menu), or the turn agent was already sending.
  3. parse_args extracts and validates the JSON.
  4. On failure, one more pick (max_retries=1, 0 disables): runtime.exec sends the last reply, the error and the menu again. It lands in the DAG. Still invalid: DecisionError.
  5. resolve_decision runs the function or looks up the value.

DecisionError

Subclass of ValueError, carrying the last error type, message and reply head. except DecisionError catches only "the model never picked a valid option". The framework has no fallback; the caller decides.
