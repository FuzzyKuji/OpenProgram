Nested LLM streaming

Each llm() or runtime.exec(..., execution_kind="llm") inside an Agent method streams over execution_stream.v1, in-process or from a subprocess, with the same result on screen. The node's expanded layout is in Nested LLM node content.

Channels

CarrierHoldsLimit
execution_streamAttempts, blocks and text of one LLM node. Driven per frame.Never touches the assistant reply content
tree_updateTree structure, status and stream_preview from the checkpoint. Polled about every 1.2 s.A terminal status is a critical frame
Call.outputFinal output, written when the node closesStream state is a preview, never the final result

Only result, error and retry_result frames finalize chat bookkeeping. A nested stream frame never clears the parent run, overwrites reply text or refreshes branch metadata.

The browser store is a display replica keyed by session, execution and node, so parallel calls do not mix. subscribe_execution_stream answers from the live owner, else from the checkpoint.

Subprocess path

The child never opens a WebSocket. It puts frames on the existing event_queue; the parent checks schema version, known operation, session, execution, a generation not ahead of the launch record, and size, then forwards them. The parent never reallocates a revision or writes the child's checkpoint.

Not covered

  • Token-level audit logs or replayable delta recordings
  • Changes to top-level stream_event.text; full terminal-interface parity
  • Per-field highlights for structured output; image deltas
  • Cross-session stream subscriptions
  • Replacing tree_update
