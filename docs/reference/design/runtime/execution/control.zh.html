活动与控制

Activity 统计会话分支。在同一分支上再发消息不会增加 History 条目。

对象含义位置
会话分支会话中的一条路径；真正分叉才产生另一条一行计数的 Activity
执行一次任务运行，例如生成一条回复在分支详情中；其 id 是确切控制目标
托管进程工具启动的命令挂在其执行下，有自己的输出和停止控制

分支如何计数

示例计数详情
发消息，再说“继续”1两次执行在同一分支
从较早位置创建另一回复2各一行
同一分支后续执行失败1保留在详情中
两个分支共享较早消息2共享的执行可出现在两边详情，不加行

分支详情用短标题和执行计数；请求只出现在执行行。归属来自会话图和消息 id，压缩保留较早的关联。缺失的记录不会被猜成新分支。

显示哪种状态

情况分区含义
审批、问题、暂停或未解决的工具结果Needs attention新消息不会消除它
执行、子任务或所属进程在运行In progressAgent 回复结束不代表后台进程停止
已结束，无活动或待处理History失败和输出保留在详情
owner 已结束，只缺模型响应记录，无活动等待或非取消控制History显示“已结束 · 响应记录不完整”。旧的 Cancel 不使其可操作；只有子任务仍活动时才提供 Cancel。不表示成功。

状态取分支最新执行，并检查真实等待、活动后代和所属进程。已拒绝的等待显示 Declined，未决的显示 Waiting for your response；拒绝不会执行待处理操作。

首次加载、重连或游标重新同步时 Activity 不显示错误：只有当前会话已确认的请求失败才提示。读取失败时保留已保存记录并重试。

每个控制做什么

控制结果边界
Pause在下一个安全点停止当前动作可能先完成；不冻结任意代码行
Continue从已保存进度恢复同一执行仅在保存状态和能力允许时
Step运行一个声明的步骤后暂停工具动作或声明边界，不是源码行
Steer为尚未运行的工作添加指令已完成工作不变
Cancel结束该执行及其后代不能撤销已完成的外部操作；托管进程有自己的控制
Fork / Retry从允许的保存点创建独立子执行原历史保留。Agent 聊天子执行以暂停开始，需要 Continue；其他按调度器。

界面只提供该执行支持的控制。“accepted”表示已保存，“applied”表示已生效。终态协调赢得竞争时命令完成是幂等的：比较交换冲突后，服务只接受同一执行和结果版本上已应用的命令，保留已存回执，其他冲突继续上抛。

重启后保留什么

记录含义原因
检查点模型决定或工具结果之后的下一步Continue 从这里开始，不恢复冻结的线程
效果回执模型或工具请求是否完成及确认内容已确认工作不重复；不确定的外部操作先核实
尝试归属哪个 worker 可更新该执行旧 worker 不能覆盖替代者
情形恢复
运行中的 Agent 执行，Worker 消失启动时认领一次，用持久输入和最新续接记录激活原执行、修订、轮次和助手回复
中断的模型请求从已提交上下文重新生成；已完成工具跳过
尚无第一个模型响应在原期限内从准入输入重启
外部操作未解决不重复，保持需要核对。绝不伪造未提交回执。
手动暂停、取消中、已取消、已完成不自动继续
界面关闭或重连转录保留；worker 拥有的执行继续运行

Worker 中断不是助手失败：不追加错误回复，也不显示重启或恢复消息。真实的 provider 和工具失败照常显示。不需要专门保存或优雅退出。

自动继续窗口
execution.auto_resume_window_seconds默认 -1，无时间限制（空期限）。0 关闭自动重启。正数为时长。
起算有序关闭意图，或被放弃尝试的最后持久活动，不是下次启动。再次重启不延长；已有的有限意图升级后仍有限。
有序停止先在退出中的 runner 关闭调度和重启协调，再请求本进程拥有的那些轮协作暂停；定时对话在自己的进程里运行，不受影响。竞争的检查点版本在同一尝试和期限内最多重试三次。
尝试已结束启动恢复采用该轮日志记录的结局，并拒绝未完成的命令。没有记录结局时不发布检查点：运行变为 interrupted，未完成的暂停被拒绝。
自动恢复只有重启恢复拥有的暂停
保持显式用户暂停、取消、未答审批、未解决效果、过期检查点、不兼容运行时契约、没有重启意图的旧暂停记录
过期保留检查点供手动继续，绝不删除会话数据
自更新相同时长，从已完成更新的最后持久活动起算；期限和过期存于更新目录。恢复、契约修复规划和原会话后续都遵守。仍在运行的更新不被停止。维护模式仍控制准入和校验。
重启机制
  • provider 决定和完成的工具动作在普通执行中原子地发布检查点和效果回执。原执行 id、不可变输入、权限、预算和续接命令保持权威；排队的 Job 使用资源队列。
  • 重启意图是规范执行事件，与转换一起存储；固定的命令身份使重复启动幂等。没有第二个数据库、调度器、进程 owner 或权限路径。
  • 恢复归属记录确切继承的检查点；新效果之前的第二次中断保留它。
  • 新 Job 在准入时拥有稳定的用户和助手消息 id。暂停完成时按 Job 等待方保留的尝试和租约身份释放资源。
  • 启动时先分类被放弃的归属，再由 runner 应用此策略。仅 provider 或从未激活的聊天准入可在原活动期限内从不可变输入继续。

恢复同一轮次

方面规则
绑定还原相同的会话、轮次、回复、运行时和工具绑定，并在完成、挂起或出错时释放
浏览器页面能力仍绑定原 owner，绝不接受其他 owner 的 token。浏览器拒绝是显式工具错误，保留原因。
用尽迭代上限运行以未成功结束，保留文本和操作历史
已结束的等待只处理检查点仍为当前检查点的等待，旧答案不能恢复、失败或取消新等待。重复恢复是幂等的。
被拒绝的等待检查点保留已显示的文本、思考和工具调用；终态投影在保存后发布会话重新加载
待审批只有在权威执行更新指明同一会话内的消息时才显示在该消息旁。重连时请求规范回放。缺少证据时绝不把其他运行的决定挂到消息上。

函数版本

execution.code_change_policy 选择 keep_original（默认）或 use_latest；Continue 可按执行覆盖。相关函数和依赖的身份决定代码是否变化。策略变更是带版本围栏的命令，不会创建新调用。
持久函数记录源码和依赖身份、输入、已完成步骤和结果、下一个安全位置、可序列化状态、未决效果
边界同步 step、嵌套 workflow、命名 parallel。纯编排从已提交结果重建本地 JSON 状态。
存储现有执行事件、blob、检查点和效果账本
use_latest保留已完成结果及来源，校验其余部分。状态转换和步骤对应必须显式；含糊的修改保持暂停并列出差异。兼容的候选在新工作前成为保留版本。
绝不降级缺失源码、依赖不可用、状态不可序列化或边界不支持时，不能退回全新执行。不兼容的 use_latest 不退回 keep_original。重试是单独的新执行。
效果已完成效果被复用。没有确认结果的进行中步骤保持未解决，除非其协议证明安全。重复恢复和第二次崩溃不会重复已接受的效果。
嵌套嵌套调用保留父身份，并行分支保留各自进度
Agent 拥有的调用与手动调用共用机制。结果回到原工具调用位置；已存结果投递时不重新执行。手动调用更新原结果记录。
契约之外原生栈帧、异步编排、活动句柄和任意 Python 函数。外部步骤前拒绝 helper 内部导入和不透明的非标准库依赖。
步骤边界上的暂停
情形处理
在持久步骤检查边界之后、效果注册或调度准入之前接受的暂停通过待处理的 Pause 命令挂起函数
准入关闭冲突只有在该命令确实待处理时才转换；其他冲突保留错误
从未调度的计划意图在暂停前记录未开始回执
已调度的操作绝不归为未开始
取消优先

Continue 保留调用游标并复用已提交步骤。崩溃恢复使用最后的持久边界并隔离前 owner。函数子进程启动不持有全历史写事务，序列回填只属于添加该列的迁移。独立函数的进度帧指向现有 code 节点，完成时在可选的会话命名之前释放前台占用。

谁拥有运行状态

运行状态由每个会话的日志折叠成内存表，没有数据库文件。见会话存储。持有 worker.lock 的进程拥有它启动的运行。

函数子进程读取表，把变更交给父进程。定时任务的一轮，以及独立的 ACP、MCP 进程里的一轮，属于这些进程自己，这一轮的行写到它们自己的日志。定时任务启动的子 Agent 由 Worker 接纳并运行，只有 Worker 能认领排队的 Job。

尝试和围栏

情形规则
Owner激活的执行有一个当前尝试，由 worker.lock 持有者拥有，没有心跳
在别的进程里跑的一轮owner 租约记录该进程的 id 和启动时间
进程退出，锁被释放新 Worker 拿到锁后可关闭日志中仍开放的尝试，除非记录的进程还在运行；这时等该进程退出后读取这一轮的结局
有序停止、自更新检查点都不碰别的进程拥有的一轮
日志记录过某一轮的结束状态，后面的行又写成未结束启动时恢复记录的结束状态
每次 owner 写入（工具结果、安全点、等待、调整投递、结束）在事务内验证尝试未结束、代次为当前、执行仍指向它。未通过的 owner 停止。

失败的尝试把可读的错误文字留在尝试记录上，其中形似凭据的内容会被抹掉，最多 4000 字符。它不进快照和事件内容，只有 Activity 的单次运行事件读取它。因持有者丢失而关闭的尝试没有这段文字，旧记录读出来也是空。

控制面如何到达引擎

openprogram.runtime.execution 不导入任何引擎或 Program。需要解码的数据归它所有；要启动或询问引擎时，调用引擎在导入时注册到 execution/hooks.py 的钩子。

钩子注册方作用
agent_activatorconversation，必需构建激活尝试的生产 driver
recovery_turn_starterconversation，必需准入继续中断聊天的轮次
permission_wait_reconcilerconversation，必需恢复时重新运行权限审批等待
session_goalsconversation，必需重启协调用的会话 Goal owner 锁；Workflow Goal 的可恢复暂停
live_owner_signalsconversation，可选停止或杀死子进程和 exec 运行时
terminal_settlerconversation，可选结算聊天 Goal：用量、空闲计数、下一轮
job_recordsjobs，必需取消时查找、列出和结算 Job 记录
turn_request_fieldsjobs，必需存储的 Job 输入可携带的字段
job_runnerjobs，可选绑定执行存储的活动 runner

缺少必需钩子时抛 EngineNotRegistered（engine_not_registered），指明钩子和包，绝不静默跳过。缺少可选钩子本身就是答案：此进程没有该引擎。加载 conversations 时也加载 Jobs。

Workflow 问题

  • 运行中的 Python Workflow 提出的问题在当前进程内等待，绑定确切的执行、尝试和代次。它使用规范等待存储和问题界面，不做 Workflow 检查点，也不重启调用栈。
  • 答案回到原调用。浏览器刷新时重新加载待处理请求。
  • 只有活动的当前 owner 能创建或回答。取消、执行结束或失去进程 owner 会使其失效。Worker 重启不回放 Workflow。
  • 子进程通过现有队列桥接发布。意外错误上抛，不会变成未答结果。声明了等待前检查点的 Agent 工具问题保持持久续接。

用户决定面板和回执

问题、确认、表单和权限审批是输入框上方按会话划分的面板。终态回执留在会话中。
输入框保留草稿、附件、函数表单、焦点和发送或排队行为。新请求绝不占用它或移动焦点。
导航Back、Next 和折叠保留草稿，不发送
Skip拒绝整个问题请求
提交立即显示提交的答案和发送中状态
已应用已回答回执
投递未知重试保持相同的命令身份和答案
被拒或过期不能暗示批准
多个请求独立分键卡片，按会话和执行划分，包括分屏

卡片复用共享的问题渲染器、规范问题事件和执行命令。每张卡片拥有自己的答案字段、提交控件和投递状态。回执不是 Workflow 检查点；刷新重新加载待处理问题，不增加历史回执持久化。

标识符和安全规则
session_id会话范围和授权；绝不是控制目标
run_id归组相关的原始、分叉和重试执行
execution_id确切控制目标。Pause 和 Continue 保持不变；分叉或重试创建新的。
attempt_idworker 的一次激活
revision_id程序及其契约的不可变版本
command_id + expected_version防止重复操作并拒绝过期命令
  • 所有传输使用同一命令服务，在 owner 应用之前保存命令。界面状态不授权操作。
  • 取消优先于暂停、单步、继续和调整。只有当前 owner 发布进度或最终状态。
  • 已知模型错误和中止有响应记录。未知工具结果保持未解决，History 标签不会清除它们。
  • 分叉校验保存点、不可变修订和权限。程序、模型或工具契约变更保留独立审查。
  • Job 的 job_id 等于 execution_id。资源分配与执行状态分离。
  • 加载会话前读取当前存储的项目位置。读取和控制限于已授权的会话。重连使用已保存版本和事件位置，不产生重复任务。
  • 托管进程保留身份、归属和有界输出。重启恢复检查 supervisor，仅有保存的 PID 不构成发信号的许可。
