跨界面的长任务

所有界面都连接同一个 Worker（WorkerLock）、同一个会话存储和同一个事件总线。每个操作都经过 Worker，界面不保留未同步的本地状态。

需求机制状态
无人值守时不提问工具策略移除 ask_user_question已实现
运行中改变方向在循环检查点投递调整已实现
在任意界面回答问题同一问题注册表和等待存储；各界面渲染事件Web 和终端
在任意界面看到运行中的会话加载时发送运行状态和未决等待回放状态和等待，不回放中间增量

值守模式
效果denied_ask_tools 把 ask_user_question 并入策略 deny，无论函数请求哪个工具集。没有该工具就无法提问；不确定的输出留给之后的模型推理。
范围按会话保存在 Worker 内存中，无会话的调用方使用进程级默认值
默认无人值守：裸运行或后台运行没有人看着
Web输入框开关
终端界面/attended [on|off], /unattended
同步set_attended 动作；Worker 广播 attended_changed

调整

agent_loop 在轮次开始、一轮工具之后和后续之前调用 get_steering_messages。新指令在下一个检查点生效，当前步骤先完成。界面发送 execution.steer，命令先保存（控制操作）。

问题

QuestionRegistry 进程级、线程安全、只能认领一次，有事件层和队列两种传输，以及子进程桥接。任何界面的答案都回到同一注册表。加载会话时回放未决等待。

优雅停止

cancel_event 贯穿全程；子进程通过 process_runner.py 的 request_graceful_stop 停止。
