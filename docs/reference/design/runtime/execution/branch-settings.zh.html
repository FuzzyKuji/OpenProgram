分支设置

会话的每个分支用自己的设置和自己的状态运行，所以两个分支可以并行。

设置从哪里来

每个分支把设置存在自己的 branch_refs 记录里；会话顶层字段是选中分支的投影。resolve_branch_settings(session, branch) 返回每项设置的 values、sources 和 inherited（不设时跟随什么）。所有入口都经过它：网页、渠道、定时任务、always-on、Goal 和 --print。

没设的项回落到
模型、联网搜索、Fast分支 Agent 当前的值，再到产品默认
EffortAgent，再到项目，再到产品默认
权限模式、沙箱项目，再到产品默认
Agent默认 Agent

跟随 Agent

  • 新会话和切换 Agent 都不写模型，所以改了 Agent 的模型，下一轮就用新的。
  • 准入时把模型记进 turn_settings。Agent 让它和这条线上一轮不同时，用户消息带 model_change，页面显示一行说明，缓存断点报告记为 model_switch。
  • 换到窗口更小的模型时，先用旧模型压缩。
  • scripts/migrate_branch_follow_agent.py 清掉只是抄了 Agent 的模型和联网搜索开关。默认只演练，改动前先写备份。

写设置

  • POST /api/sessions/{id}/branch_settings 只存和 inherited 不同的部分；相同的值写成未设。reset_fields 也能恢复为继承。
  • 同一路径的 GET 和写入的回复都带解析后的值。
  • 发给已有会话的消息不带设置；新会话只带用户改过的控件。
为什么这样设计
决定跟随原因
跟随 AgentClaude Code 和 Hermes：没设就跟随上层。Codex：换模型时提示、换小窗口时压缩Agent 是用户维护的身份，改了它的模型，用它的对话都应跟着变
按字段回落Claude Code：模型和 effort 跟 Agent，权限跟环境权限是这个目录能做什么，属于项目边界；模型和 effort 是助手怎么工作。Codex 的统一层级会让项目覆盖 Agent 的模型，而这里的项目不设模型
后台入口读自己的分支Claude Code 把定时任务投递给归属方；OpenCode 触发时取会话的 Agent挂在别的分支上的定时命令原来用选中分支的权限，主线放宽它也跟着放宽
重试和编辑复制当前设置Codex、Pi、OpenCode取旧轮次的快照会把用户之后收紧的权限放宽回去；当前值就显示在控件上
只写差异Claude Code 的选择器选默认时什么都不写“在此分支设置”才表示用户真的设过

为什么这样设计
决定跟随原因
从历史取读取基线Claude Code 的 extractReadFilesFromMessages每个进程（Worker、CLI、定时任务）里都一样；分叉、回退和压缩不用额外记账
待办按分支Claude Code：每个执行上下文一份旁支写会话级的看板会覆盖主线的
Goal 绑定自己的分支Codex：每个 thread 一个 goal同样的原因；只有作用于整个会话的命令仍限定在选中分支
操作只占用自己的分支Codex：约束只落在被操作的 thread 上每个分支一个前台操作；多条分支共有的节点要它们都空闲
其他分支上的运行Claude Code 输入框旁每个任务一个标签；状态种类来自 Codex /side等审批会卡住工作，所以放在输入框旁。目前只发送了数据
