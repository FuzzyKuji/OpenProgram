Chat turn runtime

openprogram/runtime/conversation/turn_runtime/ is the execution path of a chat turn. Agent.run_turn and Agent.resume_turn own the public contract; process_user_turn and process_agent_continuation are entries that route through ChatAgent.

Head invariant

ModuleHead writes
turn_writer.pyWrites the head on user persist and failure, and supplies head_for_finalize, which finalize.py stamps. Applies advance_head, so a same-session spawned turn cannot move the head.
forced_tool.pyWrites its own head on the forced single-tool path
slash_actions.pyRestores the previous head after a /spawn or /merge

error_path.py picks the head after a failure and delegates the write to TurnWriter.record_failure. No other module originates a head_id.

Test seam

Tests patch _resolve_model, _load_agent_profile, _run_loop_blocking and process_user_turn on the package object.

  • __init__.py calls these as module globals, so a patch is seen at call time.
  • A sibling module never freezes one with a module-level import. loop_runner.py imports the package inside the function and calls _dispatcher._load_agent_profile(...).
  • A module outside the seam, such as finalize.py, takes the resolved profile and model as arguments.

Public surface

_wrap_agentic_runtime_block, dispatch_forced_tool_call, execute_continuation, execute_turn, process_agent_continuation, process_user_turn, trigger_compaction

Conventions
  • Heavy provider and context imports stay inside function bodies.
  • The split leaves the turn lifecycle, error taxonomy, persistence schema and event payloads as they are, and adds no async to the blocking path.
  • A completed turn's commit summary is the first nonempty trimmed prompt line, up to 60 characters, or turn when empty. Success, error and shadow-file commits share this rule. A failed session commit stays unacknowledged.
