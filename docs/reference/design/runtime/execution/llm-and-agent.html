Agent execution core

Lifecycle before and after the loop is all that differs. No per-function decorator is needed: Agent scopes ordinary methods itself. agent(), agent_async() and Agent.arun share the core.

Primitives

PrimitiveMeansPersistent sessionDAG
llm()One logical model request, with structured output and its repair budgetNo, current RuntimeOne LLM Call
agent()Model and tool loop for one task; final text or a validated structured valueNo, current RuntimeAgent Call holding LLM and Function Calls

run_agent_turn()Internal session lifecycle; not a Program primitiveYesIndependent Agent Call on a session branch

Workflow code calls the model only through roles. The contract is in Workflows; the Agent and Context owners are in Agent and Context contract.

No session_id, branch_from, advance_head, archive_when_done or run_in_background: persistence belongs to the execution environment. Saved Agent profiles go through Agent.from_spec, whose explicit overrides win.

Invariants

  • Only PROGRAM_ENTRIES register as tools; category directories do not.
  • Each role call is a child of its entry node, and every Program a Workflow calls appears in the DAG.
  • A direct Workflow does not attach to the prior assistant through predecessor.
  • App, Web and TUI of one profile share one worker.
