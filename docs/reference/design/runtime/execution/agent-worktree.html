Agent worktrees

An agent changes the user's real repository in an isolated directory, around git worktree add and remove. The shape follows Claude Code's EnterWorktreeTool and ExitWorktreeTool.

Tools

ToolParametersEffect
worktree_createsource_repo, branch_name, base_ref = HEAD, label, prCreates and binds as the session's active worktree
worktree_mergeworktree_id, strategy = ff-only, delete_branch = falseMerges into source_repo, removes the directory, keeps the branch
worktree_discardworktree_id, force = false, delete_branch = trueRemoves without merging; the record stays
worktree_keepworktree_idDetaches; directory and branch stay for the user
worktree_liststatus_filter, scope = sessionLists records

Create, merge and discard require approval. Tools return one text line, or [tool error] code: detail. The WebSocket offers list, get, merge, discard and keep (ws_actions/worktree.py). No switch tool: one active worktree per session, and several only through jobs.

Where tools run

The _current_worktree_path context variable (state/worktree/context.py) carries the path; no tool has a cwd argument. Each turn binds the session's active worktree (turn_context.py); worktree_create binds it for the rest of its own turn; a job with worktree_id binds its own.

ToolBehaviour
bashStarts at the worktree each time, in a fresh subprocess. cd .. can leave: a default location, not a sandbox. Hard isolation is the docker backend
edit, write, read (path_resolve.py)Relative paths resolve against the worktree. An absolute path outside gets an [outside worktree] warning and is not blocked
Runtime subprocess (--cd)Prefers the worktree over the session workdir

Choosing the repository

  1. The source_repo argument.
  2. The session's default workdir (the selected Project).
  3. git rev-parse --show-toplevel from the worker's cwd.

None found: source_repo_not_resolved. OpenProgram never runs git init for the user. A dirty source repository is fine: the worktree starts from base_ref. Function forms hold only parameters; the Project stays the source.

Isolation and commits

  • Neither source_repo nor the worktree may sit under <state>/projects, the session store: worktree_in_sessions_dir.
  • Discard leaves source_repo's HEAD and working tree untouched.
  • A kept branch is never deleted.
  • The agent commits through bash, so it writes the message. Nothing auto-commits.
  • File diffs are git's job; tool results enter context as usual.

Jobs and sessions

User takes overworktree_keep; later turns return to the source repositorykept

A job cancel discards its worktree with force=True (jobs/runner/projection.py). A completed job never auto-merges. Light jobs need no worktree. Worktree tools are synchronous git calls; git's own lock serialises concurrent adds.

From a pull request

pr accepts 123, #123 or a GitHub PR URL (state/worktree/pr_ref.py) and ignores branch_name and base_ref.

  1. gh pr view <n> --json headRefName,headRepositoryOwner,isCrossRepository.
  2. Fetch: same repository git fetch origin <headRefName>:<ref>; fork git fetch origin pull/<n>/head:<ref>, so no remote is registered.
  3. Normal git worktree add on branch op/wt/pr-<n>-<id6>; the throwaway ref is deleted.

.worktreeinclude

git worktree add checks out tracked files only, so .env and local overrides are missing. Patterns in source_repo/.worktreeinclude name untracked files to copy, right after the add, in create_worktree (include_sync.py), the one point every creation path shares.

PatternMeaning
#…, blankIgnored

No /Basename anywhere

Copy semantics
  • Candidates: git ls-files --others, without --exclude-standard, so ignored files appear.
  • An existing destination is left alone. Symlinks stay links. Permissions are preserved (shutil.copy2).
  • One failure does not stop the rest; both lists reach the record and the tool's return.
  • No file: no git calls.
  • Matching is fnmatch and pathlib: git has no include-filter plumbing, core.excludesFile injection is refused here, and pathspec is not a base dependency.

A missing base_ref passes through git's stderr.

Out of scope

Remote push (use bash), cherry-pick or rebase between worktrees, a conflict-resolution UI, worktrees across repositories, backup before discard, chroot or namespace sandboxing.
