The split follows risk: a user's tab holds sign-ins and running work. The model follows Codex's exec_command / write_stdin and Claude Code's background-task notice; Codex reaches the user's terminal only read-only, and Claude Code has Bash plus panel tools.

bash

bash(command, workdir, yield_time_ms, tty, description)

  1. prepare_command resolves workdir (worktree, sandbox checks, remote cd guard).
  2. session.run checks the session cap, and processes.start launches the command under a detached supervisor.
  3. collect reads output every 50 ms into a 1 MiB head and tail buffer until the command ends or the yield time passes.
  4. Ended: Process exited with code N plus output, and the record is removed. Running: the record gets background=True and the reply is Process running with session ID <id>.

Session cap

64 live sessions per conversation. At the cap, the least recently used session outside the eight most recent is stopped and marked reported, and the new reply names it. There is no idle timeout.

Exit notices

run_exit_notices runs in the worker and sweeps every 2 s.

  1. unreported_exits(): background, not reported, status exited or failed. A stopped command sends nothing.
  2. Skip while the conversation has a running turn or nonterminal execution; retried after it.
  3. Clone the newest chat request, set source="process_exit", a fresh user message id and the notice text (command, exit code, duration, last 2000 characters), and admit with key process_exit:<id>. No chat execution: marked reported without a notice.
  4. The user node is display="runtime", and memory skips it.
