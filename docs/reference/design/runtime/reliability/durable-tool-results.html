Normal screenshots and long text are kept in full; display and model input are managed separately. Payload size alone never turns a successful tool action into a failure. Available resources still apply.

Preview cap

  • The cap is the larger of the configured limit (default 30,000 characters) and the 2,000-character minimum, applied before deciding on truncation or a file.
  • A result within the cap is returned once, with no marker and no file.
  • Longer text keeps a non-overlapping head (70% by default) and tail, with a positive elided count. A zero-length tail adds no text.
  • The shared normalizer does this for registered functions and Agent methods.

Full-result files

  • A whole text is kept in the running conversation's directory, at tool_results/<sha256>.txt, named by its content. It is deleted and backed up with the conversation. Outside a conversation (a one-off CLI call) it goes to the profile state directory's tool_results/.
  • The same text is kept once; two different texts never share a name, whichever call or layer saved them. A raw provider call ID can repeat and plays no part in the name.
  • An existing file is reused, since its name says it holds that text. A new one is written to a temporary file and moved into place, so the path is returned only after the complete file is written.
  • Files written earlier under other names stay readable, without migration.

Failure signals

Each tool sets is_error on the existing ToolReturn from its own execution branch. The common normalizer never infers failure from text, so a success beginning Error: stays a success.

Pause before dispatch

  • A pause accepted between completed actions is consumed before the next provider or tool dispatch.
  • A planned operation that never started is recorded not_started and stays pending in the Agent resume cursor.
  • A live owner paused before its first effect resumes the original durable admission, with no synthetic model response.
  • A control command changing the execution version during result persistence retries only checkpoint publication under the same attempt fence. The external operation is not repeated.

Reading results at the delegation limit

  • read_conversation stays discoverable and reads an execution id at agent.max_messages. Reading creates no execution, branch or delivery and spends no allowance.
  • Session and ancestor ownership checks still apply, before any wait.
  • Exhausted chains still hide agent; send_message keeps its delivery-time guard. There is no separate cancellation tool.
