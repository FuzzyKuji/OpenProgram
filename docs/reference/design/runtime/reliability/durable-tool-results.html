Current design

Retain checkpoint metadata, reference counts, control-message budgets, content hashes and execution ownership checks. Complete assistant responses and tool results are stored as content-addressed blobs without the 64 KiB pending-message limit. Blob storage does not reject at 1 MiB; that value remains a display-page or producer-chunk target. This does not change model input policy.

Pause before dispatch

A pause accepted between completed actions is consumed before the next provider or tool dispatch. A planned operation that never started is recorded as not started and remains pending in the Agent resume cursor. A live owner paused before its first effect resumes the original durable admission without a synthetic model response. A control command changing the execution version during result persistence retries only checkpoint publication under the same attempt fence; it does not repeat the external operation.

Python execution outcomes

The execute_code public tool marks a nonzero Python exit or a timeout as an error while retaining stdout, stderr, and the observed exit code or timeout. Successful code remains successful. Local sandbox denials retain their existing structured metadata. This uses the existing ToolReturn result contract and does not add a retry, change backend selection, or repeat the subprocess. Acceptance calls the registered tool through AgentTool.execute with real successful, failing, and timed-out Python snippets; backend-specific timeout adapters retain partial output. Source verification and installed-App display acceptance are separate.

Read existing Agent results at the delegation limit

job_output remains discoverable and usable when the current collaboration chain reaches agent.max_messages. Reading an existing Job result creates no new execution, branch or delivery and consumes no delegation allowance. The existing session and ancestor ownership checks still guard result access; exhausted chains continue to hide agent, while send_message retains its delivery-time budget guard. Acceptance resolves the public available tool catalog at the configured limit, reads an owned completed Job through AgentTool.execute and refuses a foreign Job before waiting. No new cancellation tool is introduced. Independent reviews and the final combined gate bind implementation evidence separately.

Auxiliary provider outcomes

The registered image_analyze, image_generate and mixture_of_agents tools retain the success or failure status already determined by their local execution branches. A local outcome function returns the existing ToolReturn with an explicit is_error flag; registered AgentTool.execute receives that outcome. The public plain execute functions keep their original string results and signatures. Provider and model unavailability, invalid explicit model references, failed image-provider calls, image-save failures, all-reference failure and failed aggregation produce typed error results. A successful model answer remains successful even when its text begins with Error:. Partial reference failure retains the existing successful synthesis or single-reference behavior. Schemas, registered names, source modules, backend selection, paths, retry budgets, usage labels and cancellation semantics stay unchanged. The common normalizer does not infer failure from text. Acceptance exercises the actual registered wrappers with controlled official-provider transport responses and owned PNG input/output, then verifies unknown references, unavailable backends, sandbox denial before backend access and cancellation. Controlled provider replies verify local execution behavior; live credentials and remote model/image capabilities remain separate acceptance gates.

Canvas failure signals

Canvas registers an internal result callable that returns the existing ToolReturn protocol. Its plain Python execute callable keeps its signature and string returns. Existing explicit Canvas validation, path-policy, permission and missing-block failures carry is_error=true. Successful block bodies remain successful even when they begin with Error:. Result text does not determine failure. Schemas, aliases, path admission and cancellation retain their current behavior. Acceptance invokes the registered tool on owned files, confirms explicit failure flags and unchanged text, and checks successful Error:-prefixed data and plain-call compatibility. Independent specification and fresh quality review have passed. Final combined verification and installed-interface acceptance remain pending; the controlled checks do not use a real provider, App or terminal.

Unavailable question input

The registered ask_user_question tool returns a typed error for its existing invalid-question, unavailable-infrastructure and noninteractive-frontend branches. Each diagnostic retains its original text. The module still exports the same decorated AgentTool object, with the same registration name, schema, metadata and interaction manifest. Valid answers remain strings; decline and timeout handling retain their existing behavior. This does not answer a question automatically or change permission and approval policy. Public acceptance checks unavailable input and a controlled frontend answer through AgentTool.execute without sending a real user prompt.

Full-result artifact identity

A full-result file belongs to its existing session, execution and qualified occurrence. A raw provider call ID may repeat across rounds or sessions and is not a global file identity. Filenames contain a digest of existing ownership and use exclusive creation for distinct paths; direct calls without a scope also receive distinct paths. Re-saving one occurrence may produce another file but cannot overwrite content referenced by an earlier receipt. Return its path only after writing and closing the complete file. Existing receipts and legacy files remain readable without migration or rewriting. Preview limits, original output, error and cancellation semantics retain their existing behavior; no execution or retry manager is added.

Effective preview cap

The existing 2,000-character minimum applies before deciding whether a result needs truncation or a full-result file. A result that fits the effective cap is returned exactly once without an elision marker or a new artifact. Longer text retains the configured head and tail portions without overlap, with a positive omitted-character count; a zero-length tail contributes no text. The shared normalizer applies this rule to registered functions and Agent methods. Full-result identity, original content, typed errors and cancellation remain unchanged.
