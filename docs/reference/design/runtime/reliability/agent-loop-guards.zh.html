Agent 循环防护

卡在openprogram/runtime/agent/loop/ 中的防护起作用的位置结果
重复文字guards._RepeatedTextGuard流消费者，streaming.py丢弃这条回复，重新请求
重复工具轮次tool_loop_guard.ToolLoopGuard每个工具轮次之后，loop.py以一条提示结束本轮
写成文字的工具调用text_tool_calls.recover_text_tool_calls回复结束时，streaming.py写出的调用变成真的调用
反复失败的调用failure_policy 和工具执行器每次工具调用，tool_dispatch.py第三次相同的失败不再执行，用一条提示回应

正常的轮次不受影响。这里不限制输出长度、轮数或耗时。

重复文字

检查对象
提供了工具的回复；其文字的一段有界尾部
触发条件
尾部以同一段 32–1024 个字符的文字结尾，重复至少 8 次且总共至少 2 KB
抛出
RepetitiveOutputError
循环
关闭 provider 效果，保留所有已完成的工具结果，附一条用户提示让模型继续且不要重复，然后重新请求。消耗本轮共享的恢复额度。
额度用完
错误上抛且不可重试，Runtime.exec 因此不会在新会话里重放已完成的工具效果

重复工具轮次

ToolLoopGuard 统计连续多少个轮次的调用、参数和结果都相同。到 TOOL_LOOP_REPEATS（8）时，在下一次请求之前结束本轮，留下一条点名该调用的错误。用户的下一条消息让对话继续。

Stopped: the agent made the same tool call 8 times in a row and got the same result every time …
比较项方式
调用名称和参数，键按统一顺序（failure_policy.repeat_key）；忽略 bash 仅用于展示的 description
结果错误标记、文字和图片内容。关于运行本身的文字先归一化：elapsed 1.2s、Wall time、duration_seconds
计数清零结果变了；用户在本轮中途说的任何话（steering）
永远不算循环全是等待的轮次：工具名里有 sleep、wait、delay、pause 或 poll（clock__sleep、waitForCi），或参数只有一个时长

写成文字的工具调用

长对话深处，模型可能按聊天模板的样子把调用写进文字而不真的调用；什么都没执行，本轮结束，被要求继续时，它读到自己写的调用，又照样写下一个。

回复对应的请求提供了工具、回复结束时没有调用，text_tool_calls.read_written_calls 就从第一个形如调用的标签开始读取。

模型家族读取的形状
Hermes、Qwen<tool_call>{"name": …, "arguments": {…}}</tool_call>；参数是对象或 JSON 字符串
GLM<tool_call>name<arg_key>k</arg_key><arg_value>v</arg_value></tool_call>
Claude、MiniMax<invoke name="…"><parameter name="k">v</parameter></invoke>，单独出现或在 <function_calls>、<minimax:tool_call> 之内
DeepSeek DSML同样的 invoke，每个标签带 ｜DSML｜，一或两个任意宽度的竖线
情况结果
每个块都点名提供过的工具，参数可读块变成 ToolCall，回复以工具调用结束
调用之前的文字保留
调用之后的文字丢弃：那是编造的结果，真实结果随后到来
参数值是 JSON 就按 JSON 取，除非 DSML 标了 string="true"
未知工具、参数读不了、正文里提到标签回复保持原样

恢复在流消费者里、回复提交之前运行，上下文、持久记录和 UI 看到的都是真实调用。工具循环防护和文字调用恢复参照 magpie（yetone/magpie，MIT）。
