错误契约

影响请求、持久状态、后台任务或可恢复操作的失败都产生可观察的记录。内部重试不一定是 Toast，traceback、文件内容和凭据不进浏览器。

{
  "type": "operation_error",
  "data": {
    "error_id": "err_opaque_unique_id",
    "request_id": "client_request_id_or_null",
    "scope": "session | job | settings | channel | agent | transport | system",
    "code": "stable_machine_code",
    "message": "safe user-facing summary",
    "action": "safe_action_or_null",
    "session_id": "session_id_or_null",
    "operation_id": "action_job_execution_id_or_null",
    "retryable": false,
    "severity": "info | warning | error | fatal",
    "correlation_id": "opaque log lookup id",
    "occurred_at": "ISO-8601 UTC"
  }
}

可空字段写 null，不省略。

项含义
request_id客户端生成的关联值，不是授权或幂等凭据。成功和失败都回显并结束 pending。只回显非空、无控制字符、不超过 128 字符的值，否则 null。同一 action 的 session_id 同理。
error_id每次失败唯一。Toast 键为 scope + code + session_id + operation_id：5 秒内同键一次；每条记录都保留。
codeunknown_action：协议或版本不匹配，不可重试。handler_error：命令失败，保守地不可重试。后续操作用已注册代码。未知代码显示通用文字，绝不显示线上的 message 或 error。
UserErrorStore当前 profile 下按键存储的追加式记录日志（user_errors.py），按认证主体隔离：7 天，每主体 1,000 条。按 occurred_at、error_id 严格从新到旧分页。确认按主体和精确 ID 幂等关闭。提交后才发送；持久化失败不发送虚假的持久帧，以 state_recovery_required 关闭。
severityinfo：只进诊断。warning：局部降级状态。error：卡片和一次 Toast。fatal：持久阻塞状态，停止自动重试。
生命周期acknowledge_user_error 在请求连接上用同一 request_id 回复：先 user_error_acknowledged，再带显式 error_ids、scope、operation_id、occurred_at 的 operation_recovered。同主体的其他窗口收到同样的恢复；跨连接无顺序保证，请求连接失败不阻塞他人。重复确认会重发精确 ID 恢复。只有确认或实体删除才关闭；之后无关的成功不会关闭。
Job 失败job_status(status=errored) 是唯一线上事件，不再发 operation_error。那种帧只用于 Job 操作请求本身失败。
兼容新客户端读 operation_error 和旧的 action_error；服务器不重复发送。Web 资源和 Worker 是一个发布单元。actionErrorNotice 和 consumeActionError 别名统一成一条提示。
失败显示保存在不含
当前会话请求相关卡片或控件旁；一次 Toast会话错误记录，刷新后可见traceback、环境、未过滤的提供商响应
后台 Job会话列表标记；AttachCard 和 Jobs 显示摘要和可重试性Job完整子进程输出、文件内容
设置或管理保留最后已知状态并显示失败；绝不显示为空列表错误中心，直到确认凭据、令牌、机密路径
可恢复的降级无 Toast；相应界面显示降级状态结构化日志和指标重复提示
断线连接状态，恢复期间不重复报错恢复预算耗尽或有未确认操作时进错误中心每次重连一个 Toast
服务端
一个安全载荷构建器；WS 操作、频道和系统包装它，JobRunner 嵌入 job_status
前端
use-ws 只转发给一个错误存储；卡片、标记、Toast 从同一记录派生。每个后端路径迁移后删除兼容分支。
请求
成功和失败都结束 pending，按钮不会一直转

会话加载

初始成本取决于可见内容，而非历史长度。SessionDB 和 DAG 是唯一持久权威，线上传的是投影。

有界会话历史

方面规则
页完整的轮次：一条提示和它拥有的全部内容，包括调用后代。第一页 6 轮、目标 128 KiB；之后每页 25 轮、512 KiB（transcript/reader.py）。单个更大的轮次单独发送。
游标捕获的分支头加稳定的游标，分支上任何消息 id 都能找到它所在的轮次。游标不可用时返回明确的可重试错误，不进入重连循环。
副作用无：分页不修改历史或模型上下文，也不改变焦点、实时头、执行状态或提问重放
分片超过帧预算的历史和图响应按序分片、等待发送，分发前重组，并与之后的实时通知保持顺序。每连接：64 Mi UTF-16 码元、8 个未完成传输、1,024 个逻辑响应（history-fragments.ts）。缓冲随连接释放。
线上大小从 extra 去掉重复的提升字段。工具预览保留已授权的完整输出展开。
客户端按标识在前面插入旧行，不替换较新内容。请求捕获加载代次，重新加载、切换分支或更换 socket 后被忽略。滚动位置保持锚定。
重连加载最新一页；继续现有执行恢复
长会话图深度：带记忆的父链分类，然后迭代前序遍历；不用 Python 递归。父路径进入环的节点保持为独立根。分叉、重试、派生分支和调用子节点保持顺序和偏移。追问规范化只索引一次回复；泳道放置维护每泳道宽度和最大列，不再重扫。
线程消息聚合、分页准备和建图在事件循环外运行；等待发送留在循环上。快照和事件顺序不变。内存会话索引仍为权威；没有持久缓存或迁移。
限制完整 Graph 保留给分支和压缩控件。投影扫描捕获的会话；初始 Graph 和存储内存随会话增长。存储索引和懒加载图渲染是单独工作。
