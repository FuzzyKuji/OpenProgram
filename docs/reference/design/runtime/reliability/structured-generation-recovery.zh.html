结构化生成恢复

故障处理
结构化输出因长度截断从最后一个完整工具边界重新生成。绝不执行不完整的工具参数，绝不拼接不完整的 JSON。
流结束但没有终止事件（空或部分内容）与长度截断相同。部分内容绝不提交或执行。
无效 JSON 或 schema 值在同一额度内修复
重复输出（repetitive_output）检测时不设 token 或时长配额。只停止这次响应，保留已完成的工具轮次，消耗同一额度并给出原因。
瞬时传输错误由 provider 分类和 Retry-After 决定；使用单独的传输额度
取消、拒答、配置无效不自动重试
外部操作结果未知重复任何副作用前先对账

恢复记账

每次调用一个 RecoveryState（openprogram/models/providers/utils/recovery.py）。

额度默认消耗来源范围
失败额外 2 次；max_retries 为 0 或 1 时禁用长度、EOF、schema、重复整次调用累计
传输OPENPROGRAM_PROVIDER_STREAM_RETRIES（5）减 1流超过空闲上限没有事件，或在最终事件前断开；整个请求重新发送，已收到的部分作废。绝不占用修复次数按请求：请求成功后归还其重试
  • 成功的工具轮次不消耗额度。provider 调用次数只用于诊断，不是第二份额度。结构化输出调用预算（Runtime 的 max_retries 次请求）会把每次传输重试退回。
  • 该状态存在时，它是 AgentSession 唯一的重试依据：没有隐藏的本地上限，也不会重启已完成的工具。显式禁用重试始终有效。独立的 AgentSession 调用方保留自己的重试设置。
  • 每次重试通过现有结构化输出和执行流事件报告原因和尝试标识。重新生成指令要求完整值，并排除无效候选。已完成的工具结果留在上下文中。
  • 取消、调用方显式截止时间和不可重试的外部副作用始终优先。

耗尽错误到达 Runtime 持久化之前先暂停。保留原始原因和终止恢复阶段；标记为传输耗尽，Runtime 不能重启整次调用。

持久化

  • 实际请求、生效参数、停止原因、可得用量和重试都可区分。未知用量保持未知。
  • 错误路径保留元数据，不要求保留推理或敏感的部分文本。暂停不同于正在重试。
  • 重启和副作用对账由持久执行和副作用记录负责，没有并行调度器。
  • 报告阶段保留已解析范围、提供的材料、检索到的证据和已校验草稿。纯文本 resume_task 是重启请求，不是持久续跑。

浏览器工作流

故障行为验收
模仿工具调用的文本不作为证据；真实观察经公开工具边界取得未观察的声明之后不发生表单操作
重复模型输出见上表重复流可恢复，健康的长输出能完成，取消和耗尽仍是失败
固定阶段截止时间没有工作流级限制。单个浏览器操作仍有界；调用方取消、显式限制和重试记账有效。没有硬编码的 300/600 秒总截止时间
异常被转成成功文本类型化错误向上传播。即使 Python 正常返回，Function DAG 持久化和子进程 IPC 也保留失败的 ToolReturn 和 AgentToolResult。未知写入结果是不可重试的失败，再次写入前必须先观察。公开函数节点以错误结束；已完成的同级结果保留在诊断中
浏览器工具约定与 Desktop 注册
  • 各阶段只暴露 computer_use_agent，并且只接受它在内置浏览器里的浏览器目标；提示词描述 tabs、read、open 和阶段可做的四个操作。工具缺失、登录和权限失败都明确报告，绝不因此改用其他通道或写入。
  • 有来源窗口但未绑定 Page 时，tabs 清单保留该来源。没有已授权来源时，清单不回退到所有桌面窗口。
  • 在子进程中，Page 清单经父进程 webtab 桥获取，只接受来源窗口和该执行获授权的绑定。子进程用自己的注册表生成并消费 Page 令牌，令牌不跨注册表传递。
  • 通过 computer_use_agent 和页面恢复打开 URL 时，都经 Resources 创建后台 Page，不依赖前台聊天路由、已挂载的 Browser 面板或已有页面。窗口注册和原生 Page 目标可用性是两个失败阶段。
  • 直接 MCP 入口把失败的浏览器结果保留为 ToolReturn(is_error=True)；HTTP 分发成功不等于浏览器操作成功。
  • Desktop 桥在启动和重连时立即注册确切的窗口标识，早于等待保留视图或资源恢复，之后可幂等重复。恢复未完成不阻塞打开第一个页面。注册绝不选择其他窗口或扩大归属。
  • desktop_unavailable：worker 此刻无法使用已注册的 Desktop WebTab。它不同于模型模仿工具调用，也不同于页面的网络或内容错误。
  • 报告写入需要真实观察到的保存或提交，以及匹配的操作后观察和明确成功证据。明确失败或缺少确认都是未知且不可重试的结果。
  • 不在范围内：第二个调度器、从字符串推断持久检查点、绕过浏览器权限、新的持久报告状态机。

模型路由与组报告

  • 订阅 provider 在请求体和路由头中都保留显式模型 id。Grok 代理按 x-grok-model-override 路由；grok-build 只是空 id 的回退，别名保持别名。
  • 原生函数调用只来自 provider 的函数调用事件，绝不从文本解析。
  • read 工具把值为 null 的 offset 或 limit 视为未传，因为严格 schema 把可选字段变成必填可空字段。文本默认第 1 行、2000 行；PDF 默认第 1 页、20 页。没有全局去除 null。
  • provider 无法表达 schema 时，组报告解析可用基于提示词的 schema 校验。运行时错误是执行错误，不是成功的 BLOCKED 字符串。成员归属缺失时请求澄清，绝不编造作者。本地草稿不授权发消息或提交。
