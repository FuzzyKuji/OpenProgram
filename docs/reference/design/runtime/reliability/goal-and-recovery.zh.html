Goal 与重启恢复

恢复会话不等于重试它的工具：旧轮次可能以 interrupted 结束，而其操作仍是 outcome_unknown，新轮次先核对实际状态。用户行为见对话中的目标。

  • Web、TUI、ACP、后台 Job 和获授权的子任务共用一个对话执行层。
  • 没有第二个引擎，没有通用调度器，不承诺外部操作恰好一次。
Goal 步骤内容
保存目标原始目标、完成条件、权限范围、显式预算
通过聊天工作Agent 维护 Todo，使用现有工具和审批
轮次结束检查结算用量；继续、等待、暂停或验收
验收独立只读轮次确认每个条件；否则回到工作

没有默认轮次上限：轮次只用于诊断。create_goal、get_goal 和 update_goal 只读写目标。

自动恢复

运行意图与关闭
  • 持久的 run_intent 建立在现有的准入、命令和重启意图之上。请求保存后才向客户端确认。
  • run_intent 记录 work_id、原始输入和未消费消息、desired_state（run、paused、cancelled、done）、最新控制版本、权限范围、目标修订、执行宿主、父子链接、最后提交的进度和恢复策略。
  • 默认情况下，仍处于 run 的已授权工作无需重新打开会话即可继续。普通请求只继续到完成为止。后台工作保留原授权和并发配额；重启不授权新的子任务。
  • 关闭窗口或重新加载只是断开连接。“退出并停止所有任务”会持久化停止意图。
  • App 退出、升级、worker 崩溃和机器重启都不是暂停。优雅关闭停止准入并保存控制和检查点；强制关闭从最后一次提交恢复。
  • 客户端未确认的草稿不算已提交的请求。
  • execution.auto_resume_window_seconds：默认 -1（不过期），0 表示退出；现有的有限期限不延长。
  • 续跑时重新检查目录、宿主、模型和工具可用性、凭据、权限和预算。缺资源时显示明确的等待原因，绝不切换项目、账号或模型，也不扩大权限。
  • 原因未知的旧暂停记录保持暂停并附说明。

重启后的状态

重启前重启后必须保持
已接受、未调度的请求按输入顺序重新排队，准入一次按客户端请求 id 去重；迟到的重试不能覆盖停止
模型流中断保留已提交文本和工具结果，标记不完整输出，请求剩余部分不拼凑完整响应；新尝试可能产生额外费用
活动 Goal（工作中或轮次之间）加载目标、Todo、证据、预算、运行意图；继续工作或验收不跳过空闲的活动 Goal；5/5 只触发验收
用户暂停、结束或停止保持暂停或结束接受时即持久化；通知不能解除；“仍在停止”与意图分开
待审批或待回答恢复问题、摘要和范围；已提交的答案只消费一次重启不是批准；实现、参数或权限变化使旧批准失效
父 Agent 等待子任务恢复标识、输出、收件箱游标和等待关系；终态后父级继续重连存活子任务，绝不重建已完成的；用户暂停作用于范围内子任务，不影响独立任务
外部进程、终端、远程作业按主机、进程启动标识或句柄查询；存活则继续观察仅有 PID 不够；不确定则保持未知；不重新提交
浏览器、MCP、临时资源重连时验证身份；报告失效；仅在授权时新建表单、登录态、JS 内存和 REPL 变量不保证恢复；新标签页不能冒充旧对象
压缩或消息写入进行中使用最后提交的历史和摘要不完整的工具参数绝不执行；用当前权限；显示不可用依赖
结果已写、通知未送达重放投影和收件箱投递，不重跑版本防止 UI 回退；父级汇总不重复计费
用量回执缺失或只在流中按 provider 尝试对账，去重取不到的用量保持未知；停机不算活动时间

恢复承诺的是已保存状态、运行意图和可重建的执行，不是进程内存。未持久化的片段、已死 shell 的内存和丢失的回执如实报告，绝不隐藏。

选择恢复模式
情况模式
所有者存活只重连
确认死亡且有可验证检查点在同一执行下新建尝试
没有可靠检查点取得独占恢复权，用稳定修复键补齐缺失输出，旧轮次以 interrupted 结束，准入新轮次
  • 三者互斥，绑定同一持久决策、控制版本和续跑键。检查点必须覆盖已提交副作用，并满足权限、等待和安全点约定。
  • 旧执行者由租约和代际确认：租约不确定或存储不可读时不写修复；连接断开不证明死亡；拒绝旧代际的后续写入。可跟踪的存活进程被重连、等待或显式取消。
  • 修复可重复且无副作用。真实结果优先，不编造用量。迟到的可验证回执作为对账事件追加，并在后续上下文中替换占位内容。

规则内容
配对先按原始调用 id 匹配最近的调用，再转换 provider id。真实输出优先；重复输出取最后保存的真实记录；缺失结果用确定性的未知占位。

权限这一转换不授予权限，不能替代恢复决策。
不确定副作用的权限范围
  • 会话来源界定旧执行和被调用的 Job，不扩大到被调用会话的所有执行。
  • 只有实际的内置 read、grep、glob 和 list 函数算只读调查；名称、acceptEdits 和插件声明都不算。
  • 范围内其他操作都需要一次性批准，bypass、自动分类和允许规则都不能免除。批准绑定新调用和未知副作用集合；集合变化需重新批准，且不抹除任何记录。恢复状态不可读或损坏时拒绝执行。
  • Auto 或 bypass 下新的交互式所有者轮次，只在自己的执行子树内评估不确定副作用。
  • 嵌套 Runtime 仅在不可变准入证明这是所有者对话时才使用该边界：存储的 actor 是交互式所有者，经完整性校验的负载来源相同，且执行、会话和主体一致。
  • 提交到执行线程时携带 ContextVars，范围捕获检查的是同一次执行。Runtime 保持非交互，不能授予审批。
  • 证据不匹配时保留限制。此过滤器绝不解决或重放旧回执。显式 ask 或 deny、来源约束、计划模式和精确 Page 绑定仍然适用。

验收

主题规则
创建时保留目标，提取可验证需求，只在歧义影响范围时才询问。每个需求都有证据检查点。简单任务可不用 Todo；编辑 Todo 绝不移除需求。
进入 verifyingworker 提交候选，或必需 Todo 全部完成但未验证。普通轮次不运行判官。先检查修订、必需 Todo、子任务和相关未知副作用。完成文本不是事实。
审查独立只读轮次对每项需求返回 met、unmet 或 unknown 及证据。确定性需求读测试回执、文件版本和运行状态；语义需求用模型审查。测试遵循普通审批和预算。缺证据则回到工作。
提交仅限当前 goal_id、修订和已验证结果版本。重新检查证据和控制版本。受控产物用版本或摘要；外部事实保留时间和回执。
之后只代表验证时成立。不监控、不重开。人工豁免必须是带原因的显式修订。验收也可能出错。
无进展按结果和证据判断，不看工具次数。没有工具调用的自动轮次会让下一个提示带警告；连续第二次则以 stalled 停止（IDLE_ROUND_LIMIT 为 2）。
blocked同一真实阻塞在至少三个 Goal 轮次中重复，且没有独立工作
等待有存活句柄时等待，不做空转模型轮次。持久等待保存 work_id、修订、句柄、观察版本和消费键。通知仅在意图为 run、版本匹配且无当前执行时准入一次。对账以退避轮询。暂停、取消或修订使唤醒失效但保留结果。查询超时不代表操作已停止。

用量与费用

主题规则
归属goal_id、修订、turn_id 和 request_id 在分发前固定。暂停后的聊天没有旧归属。子 Agent 和验收请求继承归属；每张回执只算一次。重试是新尝试。
流累计用量推进每次尝试的水位。持久写入后才更新投影。临时失败用同一键重试。迟到回执仍归原 Goal。
显示token 和价格分开存；价格变化不改历史。估算、已知值和未知项分开显示：“已知 $0.42；另有 1 个请求用量未知。”
活动时间来自持久的开始和停止记录，不含暂停和停机。丢失的执行者保留最后心跳，显示下限和未知区间。迟到用量不重启计时。无法验证的显式时间限制会停止准入。
预算默认无限。设有硬费用预算时，未知价格或用量会暂停付费准入并说明原因。可计算时预留最大金额；否则不承诺防超支。账本重载后、恢复和验收前重新检查。
后台 JobGoal 身份在真实调用方准入时保存，启动时恢复。跨会话调用保留调用方来源，不建跨会话父级。Goal 和 Job 在 usage.db 共享开始和结算事务；回执保存 Job 预留，重启后可重建计量。未知 token 和费用分别预留；部分数据只记下限。过期未启动的预留不能分发；已启动的请求不释放。硬预算只接受审计过的限制、显式价格和服务等级。

会话中的 Goal

  • 只有显式激活的 Goal 才产生 UI。启动、运行、暂停和验收不加卡片；输入框只显示当前 Goal。

Claude Code 恢复、评估不自动重跑；小模型依据会话评估。仅核实官方约定。采用不盲目重跑和独立审查，但不在每轮评估
OpenCode 历史、用量未完成调用变为中断错误；用量在步骤结束记录采用可继续的历史和按请求计量；Todo 不决定完成
OpenClaw 修复匹配结果，合成缺失，处理重复采用投影修复，不覆盖记录；心跳不是 Goal
DeepSeek harness 收口、续跑独占写入后修复；区分未开始和未知；手动重新激活采用分层状态和幂等修复；不采用轮次上限和手动重新激活

参考源码固定在已检查的版本，其测试未运行。这里是本项目的选择，不代表保证相同。

Codex 的 App Server 文档和扩展源码在恢复时加载活动 Goal 并在空闲时继续。这不能说明能从任意退出或工具进程死亡中恢复，所以这里的续跑是自己的契约。

OpenCode 与 OpenClaw

OpenCode

方面行为
循环SessionPrompt.run 在非工具调用结束且无未处理调用时退出。每轮解析配置和工具，处理压缩和子任务。最后一步注入最大步数提示。
PlanPlan 是限制编辑的 Agent 配置，不是 Goal 状态。
TodoTodo：内容、状态、优先级，按会话存 SQLite，发布 todo.updated。todowrite 替换整个列表；子 Agent 默认禁用。只能作进度投影。

来源：prompt.ts、todo.ts、agent.ts、todowrite、agents

OpenClaw

方面行为
自动化作业id、name、enabled、schedule、会话目标、唤醒模式、类型化载荷、投递、失败告警、运行状态。载荷：系统事件、Agent 轮次、命令、脚本。目标：main、current、isolated、命名会话。执行和投递结果分开。
心跳系统监控，读取草稿或 HEARTBEAT.md，无到期事项时跳过模型。结构化任务：名称、间隔、提示。
承诺推断出的约定，含到期窗口、置信度、状态、尝试和投递范围。
这里的用途最适合作外部等待的参考：Goal 控制器可为未来时间或事件绑定自动化，事件到来时恢复。

来源：types.ts、heartbeat-runner.ts、commitments、自动化、心跳、任务
