Agent 协作：工具面

约定：Agent 协作。八个实现的对比：对比。

四个域

域是什么工具
计划：todo手工维护的计划。编辑不运行任何东西。todo_create、todo_update、todo_list
执行：job已接纳的记录，有 execution_id、状态和结果read_conversation(execution_id)、list_agents、close_agent；execution.cancel 是界面和 API 的命令
实体：agent运行中的对话分支。已存 AgentSpec 是由 agent 选择的独立配置。agent、list_agents、close_agent
通信：message继续分支或读取其历史send_message、read_conversation

这些域描述资源，不是互斥的命名空间。取消工作不归档分支，也不删除其配置。

后台分派返回 execution_id。details.job_id、attach.job_id 保留原名：把执行 ID 传给它们。不加 task_id 别名。

四种动作

动作调用效果返回
创建agent(prompt, description, …)新分支，以 description 命名；运行 prompt；接纳 Job前台：等待并返回最终结果。run_in_background=true：execution_id。
分派send_message(to="name", message=…)已有分支、对话或 Agent；接纳 Job；忙时排队execution_id
等待send_message(to="name", notify_when_idle=true)不投递；目标空闲时发一条通知现在的最新回复，或一个观察
查询list_agents、read_conversation、todo_list只读，不启动任何东西文本

前台创建经 run_agent_turn 和 runner.spawn_job(wait=True)：等待既不免除接纳和资源限制，也不去掉执行身份。

并发回执表示已投递或排队，不表示完成忙碌目标排队，不被打断
自动完成通知
  • 所有结束 job 的路径都经过 _update_attach_card：更新卡片，完成 archive_when_done，然后 notices.queue(job)。
  • 后台 Agent 完成、失败或被停止，或 send_message 的回复到达时，在发送方对话启动一个通知轮次，结果形状统一。发送方用 close_agent 关闭的 Agent 不再通知。
  • 轮次进行中的对话在前台轮次结束后收到；其间完成的都合在一条通知里。待发通知在 <caller-session-dir>/notices.json，重启不丢。
  • 通知落在投递会话的 HEAD 并推进它，结果形成一条串行链。派生的报告通过 attach 指针进入上下文；投递到已有分支的回复内联在通知里。
  • 不带消息的 send_message(to=…, notify_when_idle=true) 走同一队列，目标空闲后报告其最新回复。

对链的限制

设置，默认 0 表示不限计数超出时
agent.max_spawn_depth新分支的代数，默认 1。只有创建计数。1：worker 不能派生；2：再多一代。拒绝该创建并说明原因（"自己完成"）。跳数和消息预算有余时消息仍可用。
agent.max_messages整条链上的创建和 send_message，含 A、B 互发拒绝新投递。read_conversation 和 close_agent 不受影响。
agent.max_spawn_fanout每（会话，轮次）创建的 Agent 数。派生把计数传给子 Agent，父的不变，所以链计数器数不到兄弟。拒绝该调用，工具保留：工具列表在轮次开始时冻结。
 
openprogram config set agent.max_spawn_depth 2
openprogram config set agent.max_messages 8
openprogram config set agent.max_spawn_fanout 8

立即生效，存于 ~/.openprogram/config.json 的 agent 部分，也在设置 → Agent。

  • 完成通知重新绑定已完成 job 的消息计数，不增加。代数回到分派方的值：读结果不是创建，所以协调者可以开始下一批。
  • 接纳独立于此：max_jobs_per_session、max_queued_per_session、max_live_per_session；见资源治理。
  • 给自己发消息总被拒绝：to= 指向发起者当前分支是直接环路。

归档

分支留在会话 DAG 中。归档把 archived: true 写入分支的共享元数据，所有发送方都能看到。由 archive_agent(to="name") 或完成时的 agent(archive_when_done=true) 设置。

对已归档分支的调用结果
send_message(to=…)被共享地址解析器拒绝，发生在解析到分支顶端之后
list_agents 默认视图不列出
list_agents(scope="archived")列出
read_conversation(…)完整转录
agent(start_from="SID:MSG_ID")分叉出新分支。这是继续的唯一方式，没有取消归档。

场景

分派一批任务
  1. todo_create(subject=…)，用 blocked_by 标依赖。
  2. 对每项 agent(prompt, description, run_in_background=true)，立即返回 execution_id。
  3. list_agents() 看运行中的工作；read_conversation(execution_id) 取输出；用 close_agent 或界面停止。
  4. 完成通知到达调用方。
  5. todo_update(todo_id, status="completed")。
复用已有 Agent
  1. list_agents(scope="all")：按会话分组，带名称、可用的 to="SID:HEAD"、轮数、大致字数和末尾预览。
  2. 询问、通知或交给它工作都用 send_message(to="name", message=…)；它的回复以通知返回。
  3. 忙碌目标排队，不打断、不丢失，当前轮结束后运行。
查看旧对话
  1. list_agents(scope="all") 取地址和大小。
  2. read_conversation(session_id="SID:HEAD", start_turn=-10)：负数从末尾计。
  3. include_function_calls=false 只看文本；默认含工具、参数和结果。
  4. max_chars=60000 超限时丢弃靠后的轮次。已归档分支仍可读。

接口

接口约定
agent创建并运行分支，或用 to 分派。创建已存 AgentSpec 是另一操作。
read_conversation(execution_id)不等待，返回状态，结束后还返回回复
close_agent(target)停止本会话的执行及其后代，并归档其分支
execution.cancelWeb 界面通过控制端点提交执行 ID、预期状态版本和命令 ID
list_agents对话分支和运行中的工作，不管 AgentSpec 注册表

Attach 卡片

源会话 S 的消息 A 处的调用在 T 创建分支时，在 S 持久化 attach 节点，predecessor=A、extra.attach.session_id=T、extra.attach.head_id=H。流事件 data.session_id=S 选择接收对话；card_id 稳定。没有 attach.caller_session_id。

操作会话定位
加载或更新卡片S，来自 transcript 读取或 transcript_updateAttach 节点 ID
放到调用位置Spredecessor；实时 tool_call_id，旧数据按顺序回退
查看分支T = attach.session_idattach.head_id；后台分支运行时没有
状态或取消执行权限，与位置无关job_id；规范的 execution_id 和 status_version

映射器把卡片挂到 S 的调用方消息；AssistantBubble 区分同会话和外部卡片。跨会话目标不是 S 中的 DAG 节点：在 T 中解析 H，绝不在 S 中找 H 或移动卡片。
