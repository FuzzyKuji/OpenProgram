防止死循环

系统机制
本项目开启：并发 4、收件箱 50（淘汰最旧）、60 秒重复窗口、拒绝投递给自己。可选，默认关闭：深度、每链消息、每轮扇出。聊天轮次没有工具轮数上限。
Claude Code默认深度 3、并发 20，总派生量不限；fork 不能再 fork；队友不能派生队友。跨会话消息：按发送方限速、丢弃短时间内的相同消息、最多排队 50 条。
codex-cli深度（V1 为 1，V2 无）；并发全局 6、V2 每会话 4。无去重、计数、限速或环检测，兄弟可寻址时没有东西能阻止两个 agent 无限互派。
openclaw深度 1（到 5）；每 agent 5 个子（到 20）；并发 8 和 4；对话 5 轮（到 20）；转向 2 秒限速；公告重试 3 次；子 key 去重；工具循环检测，默认关闭。
opencode通过注入权限限制深度。同一工具相同参数连续 3 次时询问权限。步数默认不限。
hermes-agent深度 1（到 3）；并发 3；每子 50 次迭代；600 秒超时加心跳；全局暂停派生开关；叶子移除委派工具集。无去重或计数。
pi-mono扇出 8、并发 4、每任务输出 50KB。无深度、去重、限速或轮数上限；递归无界。
pi-ai没有工具循环
weclaw去重：微信 id 5 分钟、广播内名称。没有返回通道，因此无环。

我们取了什么

领域工具承载
计划todo_create、todo_update、todo_list清单；编辑不运行任何东西
执行read_conversation、close_agent一个 id、一个状态、保证返回、级联取消
实体agent、list_agents、send_messageagent 是会话图中的一条分支
通信send_message、read_conversation不建任务记录的消息；任意分支的记录
选择对照原因
工具名 agent、list_agents、send_messageClaude Code模型已经认识
计划用 todo_*与 Claude Code 不同它的 TaskList 是计划板；我们把运行中的工作和计划分开
寻址分支而非进程类似 codex-cli 路径、openclaw key(会话, head) 可唯一标识，无需 agent 表
任意 agent 可给任意 agent 发消息比 openclaw 宽松；类似 codex-cli V2、Claude Code消息不建任务、不会级联，最坏结果是没回应
一个消息工具：send_message 总是建 JobCodex send_input、Claude Code SendMessage返回、取消和级联属于 Job；一个工具免去在三种寻址方式间选择
每链消息预算；设置时取 8，含返回只有 openclaw 也计数仅靠深度挡不住已有 agent 互相委派。8 介于 openclaw 的 5 和 20 之间，因为我们还计入派生和派发。返回时重绑计数，一次往返花 1；代数恢复为派发方的值，协调者可派下一批。
设置时深度取 1，不取 3openclaw、codex-cli V1、hermes、opencode深度 3 适合有人看着的嵌套。我们的无人值守路径是 run_in_background=True。
每轮扇出；设置时取 8只有 openclaw 有真正的扇出上限派生不改父级计数，两个链计数器都看不到兄弟。openclaw 的 5 个活跃子 agent（1–20）是可借鉴的单位；hermes 的 3 和 pi-mono 的 8 是批量参数，而 agent 每次只建一个。8 是两倍线程池：填满、再排一批，第九个拒绝并指向已有八个。
不做转向限速和子 agent 硬超时openclaw 2 秒；hermes 600 秒openclaw 的限速保护会中止子轮次的 steer；我们排队，不打断。hermes 的超时是调用侧等待后放弃线程。job_output(timeout=) 就是这种等待，execution.cancel 还会终止运行时，并在 30 秒后强制进入终态。
按额度移除工具，二值其他系统无条件或按深度分层移除分层使 prompt 缓存失效
额外工具 close_agent、read_conversationCodex close_agent；Claude Code TaskStop一次调用停止并收起助手，不读原始会话文件也能读历史

每个数字的依据写在其常量旁。限额默认关闭，由 Job 池限制并发，深度由所有者决定。未完成项见实现状态。
