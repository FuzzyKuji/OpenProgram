Agent 协作

保存的 AgentSpec 是可复用配置（Agent 配置）。运行时分支是对话状态，可运行多个 Job；创建分支不创建 AgentSpec。隔离代码改动见worktree 工具。其他 Agent 的做法见对比。

工具

领域与工具作用
计划：todo_create、todo_update、todo_list记录打算做的事；不启动任何东西
执行：list_jobs、job_output观察已接受的工作，从排队到终态
对话：agent、list_agents、archive_agent创建、继续、寻址和归档分支
通信：send_message、read_conversation投递内容；读取历史

模型侧没有停止工具。UI 和 API 通过 execution.command 信封取消：action="execution.cancel"、command_id、execution_id、expected_version、空 payload（执行控制）。后台调用返回 execution_id，等于 Job.id，也就是 job_output(job_id=...) 的参数。

调用分支执行
agent(prompt=...)新建，起点由 start_from 决定准入 Job。前台返回回复；run_in_background=True 返回 execution_id。
agent(prompt=..., start_from="SID:MSG", description="review")一次调用从该节点分叉并命名同上
agent(prompt=..., to="review")已有；不新建 attach 指针准入 Job，运行或排队，返回 execution_id
send_message(message=..., to=...)已有直接投递创建 Job 并返回 delivery_id。目标忙时先得到收件箱回执，回执不等于准入。
send_message(to=..., message="", notify_when_idle=True)无不投递：目标空闲时立即返回最新回复，否则登记一次空闲监听
参数及规则
项规则
agent 签名prompt、description=""、agent_id=""、start_from="inherit"、run_in_background=False、to=""、archive_when_done=False
send_message 签名message、to、agent_id=""、notify_when_idle=False
start_frominherit（默认）：发起方历史。clean：新根。SID:MSG：该前驱。可以从已归档来源分叉，因为分叉不向其投递。

何时派生基础指令（runtime/context/guides/base.md）禁止派生，除非用户、AGENTS.md 或技能明确要求子 agent、委派或并行，与 Codex 的默认一致。单个任务由收到它的 agent 自己完成。
description给新分支命名
agent_id选择保存的配置，不是分支；不能扩大发起方权限
上下文clean 不带对话消息；其他模式只带所选且有权读取的历史。都不移除系统策略，也不隔离文件系统。
地址"SID:HEAD" 或无歧义的分支名，解析到分支当前末端。名称有歧义时报错并列出候选；目标不存在时报错，绝不新建。
直接投递给自己拒绝

分支

主题行为
list_agents(scope, limit, agent_id, source)session（默认）：本会话分支。all：所有会话，最近活跃在前，无预览。archived：本会话已归档分支。
每行内容会话：id、标题、agent、忙或空闲。分支：名称、to="SID:HEAD"、轮数、大小（— 3 turns, ~2k chars 或 <1k chars）、末端预览。
创建时命名取 description，否则取 prompt 前约 24 个字符
重命名第 1、6、16、40 轮由后台 LLM 重新命名；子代理分支和手动分叉走同一路径（分支命名）
派生名终身可作地址：重命名或结束后 to="scout" 仍到达当前末端，list_agents 标记为 (agent «scout»)

归档

向分支写入 archived: true，对同一存储的所有调用方生效。历史保留。没有取消归档；复用历史请新调用 agent(start_from="SID:MSG", ...)。

对已归档分支结果
普通 list_agents隐藏
scope="archived"显示，包括已合并的 head，解析到它自己的分支
新的 send_message 或 agent(to=...)拒绝
运行中的执行继续
已接受未开始的投递启动前重新检查；以明确原因拒绝
read_conversation、历史分叉由历史可见性决定；归档不授予权限
归档入口
入口规则
archive_agent(to, reason="")幂等。任何持有该工具的本地会话都可使用，不检查创建者：这是共享的本地信任边界。
agent(archive_when_done=True)只能用于创建分支的调用。同步：工具写入。异步：终态钩子写入。
先手动归档不取消 Job，终态处理不重新打开分支，钩子不改动。同步写入仍可能刷新时间戳。
持久化失败单独报告；成功的结果仍是成功
已合并分支合并和归档是两件事：已合并分支可离开活跃末端列表而未归档

结果

阶段行为
入队所有终态路径经过 JobRunner._update_attach_card：更新卡片、应用 archive_when_done、在投递会话的 notices.json 中排入一项。只含完成或出错的 wait=False Job。最近 500 个已结算 id 防止重复通知。
结算对终态 Job 调用 job_output 会结算其条目。空闲监听结算结束于该节点的 Job（notices.consume_reply）。
投递run_job_notices 每 2 秒扫描。有非后台执行或派发它的 agent 仍在运行时，会话算忙；其他后台 agent 不算。所有待处理条目合成一个通知轮次。
文本自动生成，不是用户消息。每个 Job：agent、结果、Job id、任务。派生：报告已在上下文中。投递到已有分支：内联回复（上限 20,000 字符）和地址。
失败同样回报并带原因，由发起方模型决定。不会自动重新提交。
位置合成用户轮次（source="job_followup"），不设 branch_from，因此推进投递会话的 HEAD。JobRunner._followup_lock 按会话串行：notice₁ → answer₁ → notice₂ → answer₂。

收件方用最终回复作答；再调用 send_message 会重复投递，回执中已说明。投递不保证目标模型遵从或回复。来自其他对话的消息会标明是另一个 agent 的输入，不是收件方的用户。

attach 指针和跨会话派生

派生写入 predecessor = caller_msg_id 的 attach 指针；子分支不会并入发起方。send_message 和 agent(to=...) 不写指针，回复保持内联。

发起方上下文得到的是报告而非全文：任务、最终回复和 read_conversation(session_id, head_id)。同步派生（delivery="tool_result"）只加地址。合并（is_base、merge_temp）和手动 attach 保留完整展开（上下文概览）。

S 中的调用节点 A 以 start_from="T:M" 派生时在 T 中运行。Job 记录 parent_session_id=T、parent_msg_id=M、caller_session_id=S、caller_msg_id=A。

操作身份
定位卡片存储消息的来源 session_id 加指针 id
加载结果extra.attach.session_id 和 extra.attach.head_id；绝不在来源 DAG 中查找
同会话边仅当来源和目标会话相同
跨会话外部附件卡片，保留来源位置和目标引用
标记来源节点 spawn_out。目标首个 agent_spawn 节点：caller=<来源节点>、metadata.spawned_from_session，投影为 spawn_remote。

创建和结束 attach 都不移动 S 或 T 的所选 HEAD。身份不一致时拒绝。见 DAG attach 渲染。

目标忙

发给运行中分支的消息不打断、不丢弃，排队。

情况行为
跨会话run_control.is_turn_running(target) 为真即忙。scope="session"。
同会话未完成 Job 的 target_branch_head_id、head_id 或 parent_msg_id 是末端即忙（inbox.branch_busy）。scope="branch"，之后继续该分支末端。
存入<session-repo>/inbox.json：正文、发送方 SID:HEAD、发送方 agent、链消息数、入队时间
取出轮次结束时（成功或出错，_drain_send_message_inbox）和 2 秒扫描，后者兜住取消或崩溃的轮次
顺序提交后才删除：崩溃可能重投，不会丢失
预算排队的一跳与直接投递同样消耗消息
已满50 条；丢弃最旧的，并给其发送方留系统通知
重复同一发送方 60 秒内对仍在排队的相同文本被拒绝，并告知发送方

限额

设置默认计数
agent.max_spawn_depth0（关闭）链上的代数；只有新建分支才加一
agent.max_messages0（关闭）链上的消息：派生、投递、派发和返回结果。投递传递发送方计数 + 1。
agent.max_spawn_fanout0（关闭）每个发起方 (session, turn) 新建的分支数

这些限制拓扑，不是 token、权限或准入。拓扑的 0 表示不限；资源限额不同，null 表示继承，数值必须为正。设置时取值的依据见对比。token、费用和运行时长见资源治理。

用尽时结果
新建分支，三项任一拒绝并说明原因；不产生分支或 Job
agent(to=B) 或 send_message(to=B)，消息用尽拒绝；深度和扇出单独用尽不阻止
消息用尽时的工具列表移除 agent；send_message 保留但拒绝
已接受的 Job、当前轮次、本地工具不取消
job_output、快照、execution.cancel在正常授权下可用；不消耗额度
计数如何变化
  • 派生消耗一条消息、一代和一个扇出名额。派发到已有分支只消耗消息，但仍准入 Job。
  • 通知轮次原样绑定完成 Job 的 chain_messages（多个 Job 共用通知时取最大值），并恢复 caller_chain_generations。读取结果不消耗。
  • 之后独立的用户轮次开始新的拓扑上下文。

执行资源

限额到达边界时
max_live_per_session、OPENPROGRAM_JOB_WORKERS（默认 4）已准入 Job 排队等待
max_queued_per_sessionquota.queue_full，通常可重试；不创建 Job
max_jobs_per_sessionquota.jobs_exhausted；终态 Job 不退还
token、费用、运行时长、空闲按资源治理的预留和取消规则
准入规则
计入Job.parent_session_id，即实际运行的会话：S→T 记在 T
经过准入所有 agent 调用，包括前台（spawn_job(wait=True)），以及 send_message 触发的轮次
目标忙时agent(to=...) 在收件箱等待前已持有 Job；消息可能只有回执
排队 Job启动时不再计数
拓扑限额为 0不关闭这些检查

取消

  • 沿 parent_job_id 传播：阻止未开始的后代，请求取消活动后代，确认退出前保持停止中。
  • 撤回排队工作不停止目标上的其他执行，并留下明确的投递结果。会话级 Stop 范围更大。
  • 终态 Job 仍可查询；取消是幂等的。取消请求不代表已退出（资源治理）。

结果大小

通用规整器把字符串限制在 30,000 字符（上下文紧张时更少），保留首尾，并可把完整 UTF-8 文本写到 <state_dir>/tool_results/，文件名不透明且独占，扩展名 .txt。只有写入成功才报告路径。

目标契约：job_output 和通知使用同一有界摘录，规范结果留在存储中；完整文本产物记录执行 id、所属会话和项目、媒体类型、字节长度和哈希，按结果的可见性读取，并随其执行保留。
