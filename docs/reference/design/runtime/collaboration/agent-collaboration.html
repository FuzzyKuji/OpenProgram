Agent collaboration

A saved AgentSpec is reusable configuration (Agent configuration). A runtime branch is conversation state and can run many Jobs; creating one creates no AgentSpec. To isolate code edits: worktree tools. How other agents do this: comparison.

The recipient answers in its final reply; a send_message back would deliver it twice, and the receipt says so. Delivery does not guarantee the target model obeys or replies. A message from another conversation is marked as another agent's input, not the recipient's user.

Attach pointers and cross-session spawns

A spawn writes an attach pointer with predecessor = caller_msg_id; the sub-branch never merges into the caller. send_message and agent(to=...) write none, so their replies stay inline.

The caller's context gets a report, not the transcript: task, final reply and read_conversation(session_id, head_id). A synchronous spawn (delivery="tool_result") adds only the address. Merges (is_base, merge_temp) and manual attaches keep the full expansion (context overview).

Caller node A in S with start_from="T:M" runs in T. The Job records parent_session_id=T, parent_msg_id=M, caller_session_id=S, caller_msg_id=A.

These shape topology; they are not tokens, permissions or admission. A topology 0 means no limit, unlike resource limits, where null means inherit and numbers must be positive. Why these numbers suit when set: comparison. Tokens, cost and runtime: resource governance.

How counts move
  • A spawn spends a message, a generation and a fan-out slot. Existing-branch dispatch spends a message only, but still admits a Job.
  • The notice turn binds the finished Job's chain_messages unchanged (the largest when several share a notice) and restores caller_chain_generations. Reading a result spends nothing.
  • A later independent user turn starts a new topology context.

Cancellation

  • Follows parent_job_id: prevents unstarted descendants, requests cancellation of active ones, stays stopping until exit is acknowledged.
  • Withdrawing queued work never stops another execution on the target and leaves an explicit delivery outcome. Session-wide Stop is broader.
  • A terminal Job stays queryable; cancellation is idempotent. A cancel request is not proof of exit (resource governance).

Result size

The generic normalizer caps strings at 30,000 characters (less under context pressure), keeps head and tail, and can write full UTF-8 text to <state_dir>/tool_results/ with an opaque, exclusive .txt name. The path is reported only after a successful write.

The target contract: one bounded excerpt for job_output and notices, the canonical result kept in the store, and a full-text artifact recording execution id, owning session and project, media type, byte length and hash, read under the result's visibility and retained with its execution.
