对话内自更新

Agent 在私有 worktree 中修改 OpenProgram。改动被构建成封存版本，在数据副本上试运行，由旧版本在 worker 之外切换过去。任何失败都回到原来运行的版本。正式发行版走自动更新。

规则

对象规则
写改动永不受限，只检查激活
运行的代码总是一个已提交的版本
对话任何时刻都不拒绝；切换期间到达的被保存，之后运行
激活和回退由旧版本的进程外控制器执行。改过的更新器从下一次切换生效。候选版本的 worker 只报告，绝不推进把自己当候选的更新。
回退范围只改代码
可以改什么什么都可以，没有受保护路径清单。有三样固定协议，读取方不经自更新改变：指针格式、<state>/self-updates/ 文件、shell 的主进程契约。

校验
prepare 要求 worktree 存在、已链接、干净、有 local 之外的提交；错误返回给模型。候选可基于 local 的任何祖先，由系统 rebase 而不是拒绝。
授权
默认模式下所有者的调用不弹卡片。询问模式或询问规则产生普通卡片。非所有者按身份拒绝。
验收
goal、assertions、verification_plan 保持每条断言一个 acceptance-N 检查。self_update_observe 是验收者唯一的观察方式；试运行时指向试运行端口。

ASCII key=value 行，C、批处理、Python、Node、shell 都能读。字段名和含义冻结。没有验证中的切换时 probation 为空。

  1. 独占创建 current.lock；超过 10 秒可打破。
  2. 读 current；generation 不符则释放并失败。
  3. 写 current.<pid>.tmp，generation + 1，fsync。同样方式把 current 复制到 current.prev；结束观察期的写入在那里存已提交的指针，修复不会带回过期的观察期。
  4. POSIX：rename，fsync 目录。Windows：MoveFileExW 配 MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH，访问或共享错误时每 50 毫秒重试，共 20 次。

versions/pointer.py、shell 的 JavaScript、launcher 的 C、bootstrap/versions.py。不用符号链接。

控制器、launcher 守卫、shell 恢复页、bootstrap/versions.py、安装器

构建

控制器在 versions/.staging-<update>/ 中进行，来源是任务的 worktree；没有 worktree 的 kind 用临时分离 worktree。

准备

  1. 磁盘：需要时的新 base、版本、试运行副本和 2 GB 余量；不足则中止并给出两个大小。
  2. 用 delivery/activation.py 分类路径。
  3. base：复用，或用 build-base.sh/.ps1 写入 bases/.staging-<id>，build-product-runtime.sh 调用同一配方。未变的层克隆。需要网络。Python 小版本变化则中止：launcher 按小版本编译。
  4. 创建 venv，verify-product-runtime.py 通过后把 base 改名到位。

组装

  1. git archive <commit> openprogram pyproject.toml 写入 site-packages；生成 dist-info。
  2. 前端：web、docs、tui 组件都没变则克隆；否则用 stage-release-assets 加 --node-modules <toolchain>。lock 变化时运行 npm ci --ignore-scripts。
  3. desktop/ 来自 apps/desktop/main* 的 git archive。
  4. apps/desktop/shell/compat.json 超出 shell 范围则中止：“this change needs a new signed shell release”。

封存

  1. compileall --invalidation-mode unchecked-hash。
  2. version.json、files.tsv、pristine.zip；全部 fsync；改名为 versions/<id>。
