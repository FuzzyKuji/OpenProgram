Programs 代码结构

Agent 能调用的一切都是 Program。

目录结构

openprogram/
├── runtime/agent/
│   ├── llm.py                  # llm()：一次模型调用
│   ├── agent_function.py       # agent()：模型工具调用循环
│   └── agent_class.py          # Agent：带方法的具名角色
└── programs/
    ├── __init__.py             # TOOLSETS、DEFAULT_TOOLS、agent_tools、apply_tool_policy
    ├── tools/                  # 始终提供给 Agent
    │   ├── files/  code/  web/  interaction/  knowledge/  jobs/
    │   ├── agents/  computer_use/  runtime/  system/
    │   └── planning/           # todo/  plan_mode/  open_work/  goal/
    ├── applications/           # 整体启用或停用
    │   ├── browser/            # 标签页、Page 与 web_use
    │   ├── meeting/            # 录制、转写并总结通话
    │   ├── workflow_recording/ # 演示录制器
    │   └── office_editor/      # ONLYOFFICE 文档编辑器
    ├── _authoring/             # Program 代码导入：application_client、
    │                           # json_parsing、reports/、helpers ...
    └── _host/                  # 加载和运行 Program；Program 代码不导入
        ├── runtime.py          # @function 与共享工具注册表
        ├── context.py          # ProgramContext，每个所有者一个
        ├── registry.py         # 内置、用户与 harness Program 的加载器
        └── packages.py  sources.py  execution.py  services.py  ui/ ...

~/.openprogram/programs/<name>/   # Python 包、应用、harness 克隆

每项能力只有一个实现和一个公开 import 路径。programs/ 下没有 functions/、workflows/ 或 packages/，旧路径也没有别名。

Program 的来源

来源内容加载
内置工具programs/tools/文件、shell、搜索、规划、询问用户、记忆、任务、网页、计算机操作始终加载，不能逐个停用。多数在导入时用 @function 注册；带 PROGRAM_ENTRIES 的包通过所有者为 tool:<name> 的 ProgramContext
内置应用programs/applications/browser、meeting、workflow_recording、office_editor，各自提供核心访问它所用的具名服务只在启用时加载（openprogram programs enable|disable <name> 或 Applications 页面）。context 所有者 application:<name>
用户 Program~/.openprogram/programs/列出 PROGRAM_ENTRIES 的包、带 application.json 的目录、openprogram programs install 记录的 harness 克隆走同样的 context。包规范：Workflow
可迁移包来源

项目内 Program 使用带 programs 范围的相对路径记录位置，绝不相对于聊天工作目录。一个外部安装绑定连接已安装 runtime 与源码 checkout。只有已授权的确切包名参与 Python 解析，不包括整个外部目录。拒绝和发布规则：Workflow 包合同。

基础原语与 Workflow

入口含义位置
llm()一次模型调用，结构化输出，不带工具循环runtime/agent/llm.py
agent()多轮模型工具调用循环runtime/agent/agent_function.py
Agent具名角色，其方法执行模型调用，可以作为工具提供runtime/agent/agent_class.py
goal()启动聊天 Goal。属于会话状态，不是原语programs/tools/planning/goal/

Workflow 是普通 Python，调用这些原语和其他 Program 来定义流程、状态与验收。凡是进行模型调用、调用其他 Workflow，或保存多阶段状态与完成检查的能力都是 Workflow，包装在角色里的单次模型调用也是。

Goal 以普通聊天轮次运行

方面规则
单一机制planning/goal/ 中的会话状态。每个成功的聊天轮次结束后，chat.py 决定是否为活动 Goal 再启动一轮。没有独立的 Goal 循环、裁判 Workflow 或嵌套工作 Agent。
Programs 表单goal(prompt) 只接收目标，在当前对话保存聊天 Goal；路由通过与 /goal 相同的控制启动第一轮。
聊天与 Agent/goal <目标> 和 create_goal 工具创建同一种 Goal。goal Program 从不作为工具提供给 Agent。
完成update_goal(status="complete") 或完成的 todo 计划只提交候选。verification.py 运行一次独立只读验证轮次后，Goal 才算达成。
限制没有轮数限制。连续两个自动轮次没有工具调用时以停滞状态停止。可选的 token、活动时间和费用限制是仅有的预算。
重启租约属于上一个 worker 的 Goal 以暂停状态恢复，并提供继续操作（restart.py）。

文件还是目录

形式适用示例
单个 .py一个公开入口和少量本地辅助函数，可以独立阅读tools/files/edit.py
同名包多个职责不同的模块、资源文件或会话适配器tools/planning/goal/、applications/browser/
内部目录，_ 开头只服务相邻代码的共享实现，不成为 Programs UI 节点programs/_authoring/、programs/_host/

是否拆分由文件数量和职责边界决定，不为统一形式。

调用方允许禁止

注册与 Programs UI

方面规则
注册_host/registry.py 加载内置工具、已启用的内置应用、用户 Program 和已记录的 harness。每个包通过自己的 ProgramContext 注册，按所有者保存（tool:<name>、application:<name>、包名、external:<package>）。卸载或重新加载时销毁它和它添加的一切。
Programs 树只映射源码目录。已注册入口可运行并显示 Use。展开同名包时从实际目录列出模块（goal/command.py），可以阅读，但不是额外的 Program。__init__.py 和 _ 目录不成为节点。
稳定契约移动源码不改变公开名称、参数 schema、权限、DAG 语义或会话状态格式。旧路径直接失败：没有别名，没有双重扫描。

不采用

  • 没有 @workflow 装饰器；分类由目录和元数据表达。
  • 没有 call_workflow(name)；Workflow 使用普通 Python import 和调用。
  • 没有带版本的新旧目录，也没有运行时二选一。

动态工具参数映射

规范 schema 区分键在调用时才确定的映射，和声明了字段的对象。

规范对象本地校验Provider 工具模式
匿名映射、Python dict 或 Mapping接受动态键；校验对象和声明的值类型保留映射 schema，非 strict
声明了字段（包括空集合）或显式 additionalProperties: false必填字段、类型、拒绝多余字段。从不放开。支持时用 strict
同时包含两类工具的请求每个调用按自己的 schema 校验按工具选模式；绝不在整个请求上关闭 strict
  • program.args 接受已注册 Program 的合法关键字参数，包括 task。可空映射保持 null 行为。
  • models/providers/schema/strict.py 拒绝把带动态键的 schema 变成 strict，开放映射因此不会变成空的封闭对象。
  • OpenAI strict 模式要求封闭对象：动态映射工具在 Responses、Codex 和 Chat Completions 上发送 strict: false，固定字段工具保持 strict。
  • Anthropic 同样按工具：映射工具保留普通 input schema，不带 strict 标记。
  • 固定的 execute_code schema 保持 strict。
