仓库集成

集成目标是 dev。main 的历史相互独立，只由 scripts/publish-github.sh 写入（见向 GitHub 发布源码）。

边界

方面规则
审计每条分支按已提交的头部；未提交文件留在各自的 worktree
准备在隔离的干净检出中
删除分支单独的操作
仍为权威Agent 与 Context 重构；官方 Anthropic API 要求

合并决策

分支改动决策
已是祖先已包含
重复或已被取代，常见补丁相同而提交 id 不同保留当前实现；比较其独有补丁后才记录分支祖先关系
确实是新内容正常内容合并
引用已删除的 API保留较新的实现
更新依赖一起解决到一个 lockfile
整体用远端覆盖，或整体接受历史文件拒绝

验证

项目要求
分支清单确切头部、包含关系、补丁比较、评审和剩余检查，记在私有交付台账
祖先关系清单中每个头部都是合并后提交的祖先
该提交上的检查仓库契约、受影响的公开检查、依赖锁校验、Web 测试、文档检查
已有失败保持记录为未完成，绝不算作通过证据
冲突或写入失败保留候选引用和原引用
