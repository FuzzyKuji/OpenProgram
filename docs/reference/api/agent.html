Agent and Context

EntryDoes
agent() / agent_async()Runs a model tool loop
AgentStores reusable configuration, scopes ordinary subclass methods
ContextSupplies named content and history selection
 
from openprogram import Agent, agent, agent_async

answer = agent("Summarize this text", tools=[])

class Researcher(Agent):
    instructions = "Return a short, factual answer."
    tools = []

    def prepare(self, question):
        """Remove surrounding whitespace."""
        return question.strip()

    def research(self, question):
        """Answer the prepared question."""
        return self(self.prepare(question))

researcher = Researcher(model="configured-model")
answer = researcher.research("A question")
# In async code: answer = await researcher.arun("A question")
# Or: answer = await agent_async("A question", tools=[])

All entries use the existing Runtime and Session DAG. Ordinary calls need no manual Context.

The class-and-method interface takes inspiration from NVIDIA-labs OO Agents. OpenProgram does not claim NOOA API compatibility.

Context

from openprogram import Agent, Context

context = Context(
    {"notes": "Use the project terminology."},
    providers={"current_topic": lambda current: "Agent context"},
)
researcher = Agent(context=context, tools=[])

The framework derives and binds Context automatically; this is optional. Content is separate from system instructions and tool authority.

Explicit session lifetime

To make several independent calls continue one session, pass an existing SessionNodeWriter.

from openprogram import Agent, Context
from openprogram.state.store import SessionStore, SessionNodeWriter

store = SessionStore(root_path="/var/lib/myapp/sessions")
store.create_session("research", agent_id="main")
writer = SessionNodeWriter(store, "research")
researcher = Agent(context=Context(store=writer), tools=[])
try:
    first = researcher("List the project requirements.")
    second = researcher("Review the requirements from the previous call.")
finally:
    store.close()
  • head_id selects an existing branch tip; None continues the current head.
  • The caller owns and closes the store. Execution scopes do not.
  • This supplies the event lifetime for NOOA-style repeated instance calls. The Agent still stores configuration; its default calls stay independent.

Method options

from openprogram import Agent
from openprogram.runtime.agent import llm

class ExampleAgent(Agent):
    method_options = {
        'f': {'tool': True},
    }

    def f(self, x: str) -> str:
        """One-line summary of what f does."""
        return llm([{"type": "text", "text": f"...{x}..."}])

_example_agent = ExampleAgent()
f = _example_agent.f

Signature and docstring supply names, types, defaults and summaries; method_options supplies the rest, with no decorator. Agent owns method execution and registration. Context resolves request content and visible history.

Runtime for a method

A method runs on its Agent's Runtime, or the caller's when the Agent has none: ExampleAgent(runtime=rt).f("x") runs f, its model requests and the Agent methods it calls on rt. Configure Runtimes where the program starts, not through method arguments. For two models in one workflow, give the second role its own Agent instance.

Older functions: runtime injection

Parameters named runtime, exec_runtime or review_runtime are filled when the caller passes none: from the current call chain, or for an entry-point call from create_runtime(), closed when the function returns. Several such parameters get the same runtime. They never appear in the tool schema or WebUI form. New methods do not declare them.

Introspection and safety
  • fn.spec: generated tool spec {"name", "description", "parameters"}. fn.execute(**kwargs) invokes with LLM-provided kwargs.
  • Re-entering itself more than 5 levels deep raises RecursionError; an injected situational prompt also steers the model away.
  • add_pre_invocation_hook / remove_pre_invocation_hook: hooks run at the top of every call and may raise CancelledError to abort it, as the WebUI stop button does.

Durable steps and code selection

from openprogram import Agent
from openprogram.runtime.agent.durable_steps import step

class ExampleAgent(Agent):
    method_options = {
        'report': {'tool': True, 'resumable': True},
    }

    def report(self, topic: str):
        research = step("research", collect_research, topic)
        return step("write", write_report, research)

_example_agent = ExampleAgent()
report = _example_agent.report

Execution is restored at explicit steps, not arbitrary Python stack frames. collect_research and write_report are ordinary source-defined functions.

ConstructRule
step(name, fn, *args, **kwargs)JSON-compatible inputs and results. A completed step returns its saved result without calling the action again. Repeated names are distinguished by occurrence; keep order and completed inputs stable.
workflow(name, fn, *args, **kwargs)Nested orchestration
parallel({"branch": (fn, args, kwargs)})Named workflows run concurrently, each with independent durable progress; waits for every branch before releasing ownership
execution.code_change_policyAfter a restart
keep_original (default)Retained source runs. After adopting B, a later restart keeps B even if the installed code is C.
use_latestCompleted results stay; the current function runs the remaining compatible steps

Authoring notes
  • Pass persistent state through JSON step inputs and results. Do not share mutable globals, closures or defaults between steps.
  • Import step dependencies at module scope. Source-defined Python helpers are retained recursively.
  • If B needs a different local state shape, write the conversion as pure orchestration over saved JSON before its remaining steps.
  • Manual calls resume the same execution and function record. Chat calls return their eventual result to the original pending tool call.
  • Restart-owned interruptions follow execution.auto_resume_window_seconds (default -1, no limit; 0 disables automatic restart).
  • The function run dialog distinguishes functions that declare this contract from ordinary ones, which need a new run after interruption.
