Which interface you get
  • Releases include a self-contained Node.js Ink interface on Windows, macOS and Linux. No separate Node.js install.
  • The check is real raw-input capability, not an OS list. Windows Terminal, PowerShell under ConPTY and modern integrated terminals get full screen. Without raw input: the Python Rich interface, with a message. Git Bash in MinTTY may land here; PowerShell in Windows Terminal, the recommended Windows setup, does not.
  • Full screen needs stdin and stdout to be terminals. Redirected or piped runs skip Ink before any ANSI frame and use line output; for automation use openprogram --print.
  • Both implementations connect to the local worker over WebSocket and share sessions with the Web UI.
  • The alternate screen restores the shell's contents on exit. Cursor and deletion work on whole Unicode grapheme clusters.
  • With --profile <name>, startup diagnostics go to ~/.openprogram-<name>/logs/ink-startup.log.
Compaction
  • /compact summarizes older complete turns with their visible tool results and keeps recent turns. It changes the next model context; original messages stay in the session. Token counts before and after are local estimates. A short history, failed summary or summary that saves nothing leaves the context unchanged.
  • Tool continuations can compact completed text results within one user message, with no command. Execution records are retained.
  • If that is not enough, older complete text-only execution history can be replaced in the next request by a task summary. All user messages and the latest assistant segment stay verbatim. Not eligible: incomplete tool groups, multimodal input, signed reasoning. Reused only within the current invocation, same model and unchanged prefix; the DAG stays the durable record.
  • Summary requests handle long text in bounded chunks, retry overflow with smaller chunks, and share a finite call and time budget. Failure leaves the history intact. If protected content alone exceeds the window, the request fails explicitly.

Channel messages whose user or assistant text is not a string are ignored for that field; existing background-session text is kept.
