命令效果

会进入哪个界面
  • 发行版在 Windows、macOS、Linux 上都带自包含的 Node.js Ink 界面，无需另装 Node.js。
  • 判断依据是终端实际的原始输入能力，不是操作系统白名单。Windows Terminal、ConPTY 下的 PowerShell 和现代集成终端得到全屏界面。没有原始输入时回退到 Python Rich 界面，并给出提示。MinTTY 里的 Git Bash 可能回退；Windows 上推荐的 Windows Terminal 里运行 PowerShell 不会。
  • 全屏要求 stdin 和 stdout 都是终端。重定向或管道调用在写出任何 ANSI 帧之前跳过 Ink，使用逐行输出；自动化用 openprogram --print。
  • 两种实现都通过 WebSocket 连接本地 Worker，并与 Web UI 共享会话。
  • 备用屏幕在退出时恢复 shell 内容。光标和删除按完整的 Unicode 字素簇处理。
  • 使用 --profile <name> 时，启动诊断写到 ~/.openprogram-<name>/logs/ink-startup.log。
压缩
  • /compact 总结较早的完整轮次及其可见工具结果，保留最近轮次。它改变下一次的模型上下文；原始消息仍在会话里。前后 token 数是本地估算。历史太短、总结失败或总结没省空间时，上下文不变。
  • 工具续跑可在同一条用户消息内压缩已完成的文本结果，无需命令。执行记录保留。
  • 仍不够时，较早的完整纯文本执行历史可在下一次请求中换成任务摘要。所有用户消息和最新的助手片段保持原文。不适用：未完成的工具组、多模态输入、带签名的推理。只在当前调用内、同一模型且前缀不变时复用；DAG 仍是持久记录。
  • 摘要请求按有界分块处理长文本，上下文溢出时用更小的分块重试，并共用有限的调用和时间预算。失败时历史不变。受保护内容本身就超出窗口时，请求明确失败。

频道消息的用户或助手文本不是字符串时，该字段被忽略；已有的后台会话文本保留。
