Bookmarks and History

  • The bar shows the direct contents of the Bookmarks bar; extras go in the double-chevron menu. All bookmarks opens the manager, with Other and Mobile bookmarks. Names, order and contents are unchanged. Nested menus open one level at a time and scroll within the window.
  • The manager has a folder tree, current-folder list, search, favicons and item menus. History groups by local date.
  • Favicons: saved icon, then the site's /favicon.ico, then a browser icon. No referrer or third-party service. Home shortcuts show /favicon.ico or the site's initial.
  • Homepage shortcut: Add, address, optional name. Cancel, Close, Escape, clicking outside or Add again clears it.
  • History and the persistent webtabs partition live in Electron's per-user data directory; chats, projects, Programs and worker configuration stay in ~/.openprogram/. Clearing browser data leaves those.
Icon cache

Decoded icons are shared across the bar, menus and tabs in each renderer. The cache is bounded, retries failed sources after five minutes and refreshes reused ones after thirty. Reopening a bookmark menu reuses its document. Closing the window releases it; restarting can reload through the browser cache.

Design: Built-in browser, Browser application

The Agent and a Browser pane

A visible built-in Browser pane in the same window attaches a bounded description of that exact tab before the first model response: title, origin, visible text, ARIA landmarks, and a browser-control tool. It works on either side or in picture-in-picture, without OS focus.

TargetingActions stay bound to the originating window and tab. DOM, ARIA, text and element references by default; one viewport screenshot only for a visual task or when structure fails. No OCR, object detection, iterative crops, component or vision memory, or workflow replay.
Your actionsClicking, scrolling, typing, navigating or closing does not pause the Agent. Agents may also operate OpenProgram's own interface. Pause with the task control by the composer.

Uploads and verification
  • upload with a fresh file-input ref and path, up to 50 MiB, selects a user-approved file. It always uses the normal permission gate. File read restrictions apply.
  • Observations expose filenames, not contents or paths. file_selected verifies selection only; check acceptance with a separate assertion. An uncertain upload is not repeated.
  • Verification uses assertion and a non-empty value; text is for typing or reporting a blocker.
  • Three consecutive failed actions or unmet assertions on one observation stop with the reason. A rejection stops without repeating. A blocker never counts as completion. Action counts measure Page mutations.

Shell metadata and the resource tool

On macOS zsh and compatible Bash 3.2 login shells, terminal_use(action="observe", ...) and resource(provider="terminal", action="observe", ...) return shell_integration:

FieldMeaning
statusstarting ready unavailable ended
mode reasonzsh-hooks or bash-debug; why unavailable
event_sequenceLatest accepted shell report
cwdDirectory in value with its sequence; null before a report
cycleForeground id, phase (running finished unknown), exit_code; null before the first command
  • start_cwd is the starting directory; the top-level exit_code is the terminal process. A cycle's code appears only after its foreground completion. command_complete stays null.
  • bash-preexec, custom DEBUG traps, prompt commands, readonly prompt configuration and incompatible tracing fall back to unavailable without touching your hooks. Missing or unavailable means unknown; reports grant no permission and can go stale.
  • resource(action="describe") returns providers and schemas. web and terminal keep their native identities and checks; observe returns generation, binding, input revision and output cursor.
  • Web release ends control and keeps the Page; close closes the observed tab, reports page_closed, and errors if unconfirmed. Terminal release leaves the process; close requests termination. Local Terminal operations need a live execution in the originating window and cannot bypass a sandbox.
  • Trusted Python: openprogram.host.resources.registry.register(...) for a ResourceProvider with a JSON Schema per operation and an adapter, which owns authorization and lifecycle. Duplicates are rejected and arguments validated. openprogram.host.resources.session.resource_use(kind, title, target) reports session usage inside a trusted runtime session and releases on exit. URL identities omit credentials, queries and fragments. Commands are never parsed into resources. Installed enabled applications register application.<id>.

Continuation rules
  • execution.auto_resume_window_seconds: -1 no limit (default), 0 off, positive is seconds. A deadline persists, is not extended by restarts, and existing ones survive upgrades; after it the task pauses for manual continue.
  • Tasks checkpoint at completed provider and tool boundaries. Continuation keeps task identity, permissions and resource admission and needs a compatible runtime contract. It restores durable checkpoints, not process memory. Confirmed tool results are reused; an unknown external result needs reconciliation.
  • Self-update continuation, replanning after a changed contract and follow-ups use the same setting, measured from the update's last activity. A running update is not stopped by it.
  • Conversations contain results of a requested update, but no update history, controls or recovery notices, and opening one starts no update polling.
  • Restoring a page does not start an Agent; a new task observes and checks permission as usual.
The browser tool after a restart
  • Listing pages waits up to 20 seconds for an App that is restarting, then reports desktop_unavailable and asks to retry. If the window is gone, other windows' pages are listed. With the App closed there is no wait: a page an Agent opens goes into a background browser with no window and none of the App's sign-ins.
  • An earlier session or page token leads back to the same tab with a fresh observation. The action is not repeated and closed pages are not reopened.
  • An unknown tab returns the current pages with fresh tokens.
  • A screenshot right after an action observes first, so it does not fail as stale.

Programs

Abilities → Programs has two roots. Tools: openprogram/programs/tools/ by category. Applications: built in from openprogram/programs/applications/, and installed in ~/.openprogram/programs/. Each expands to entries and source files; details show disabled state and, for your packages, load failure or not callable. A catalogued application in another's directory is listed alone, naming that directory. Opens on the first application, else the first tool.

Tree, selection and graph are kept when you leave. They are checked every five seconds while visible and on focus; unchanged files reuse analysis. A failed check keeps the last content.

Long conversations
  • History loads the latest page first and fetches nearby messages as you scroll, keeping position and streamed output. Failures retry automatically. Distant pages leave memory. Reopening restores the visible message if still on the branch.
  • Jump to latest in the main conversation and split panes appears while newer messages are unloaded. A failed jump stays retryable. Scrolling, clicking or a key cancels a pending jump or restoration. Closing a pane saves its position. Reconnecting skips old retry delays.
  • The DAG loads when opened. Markdown uses a bounded cache. Stored history and model context are unchanged.

Local App refresh preserves permissions of unpacked native dependencies and restores the node-pty helper's execute permission.
