Self-update rollback

Post-rollback diagnosis

AspectRule
JobOne read-only Job in the original session, created by the restored worker, with the approved model and profile. Reports a cause and corrections.
CannotEdit source, run shell commands, install or authorize. Original verdicts stand.
TimeAt most five minutes after rollback, shortened by an earlier approved deadline. Restart neither resets it nor repeats a terminal Job.
StopThe Job cancel action or self_update(action="cancel"). A new update supersedes it.
Cannot runUnavailable models or invalid evidence stop diagnosis without restricting the service.
Resultdiagnosis_result in self-update status --json, when one exists.

Post-rollback source repair

AspectRule
ApprovalInitial approval covers isolated repair and the listed required_tests. Default mode needs separate approval before another installation; explicitly approved bounded_auto permits later installations within its limits.
TriggerAn implementation or test diagnosis can start one read-only model Job proposing text edits.
ApplyingThe controller validates each edit, creates a new linked worktree and commit, and runs the frozen tests in a native sandbox with no network or App write access. Your worktree is unchanged.
ScopeThe original changed files, or bounded_auto's approved patterns. Files your candidate changed and the repair leaves alone stay as approved.
Never edited automaticallyProtected runtime, approval, installer, dependency and Git files. Invalid paths or non-unique old text stop repair.
TimeRepair and tests share at most ten minutes after rollback, shortened by an earlier deadline. A new update, cancellation or expiry stops them. Restart replays nothing.
CancelThe Job cancel action during the model; self_update(action="cancel", update_id=…) in the original conversation for tests. Failed worktrees and evidence stay for inspection.
Repair stateMeaning
candidate_readyNew commit and all configured tests passed
awaiting_testsNo required tests were configured; cannot be retried, start a new owner request with explicit tests
failedMissing or failed tests, or source drift
cancelled, expiredCancellation or expiry

None of these means installed. Requests from before these stages keep their old behavior and do not gain them.

Retry and iteration

AspectRule
retryself_update(action="retry", update_id, candidate_sha) from any of the owner's conversations. In a mode that asks, approval shows SHA, changed paths, tests and remaining budget. Git contents and test logs are rechecked afterward; a change invalidates submission.
bounded_autoNeeds a future total deadline, allowed path patterns and non-empty required_tests. Only requests with the frozen iteration authorization submit automatically; the mode field alone grants nothing.
AttemptsAt most three counting the first. Reserving a child consumes one, even if submission fails. Each child keeps goal, assertions, source baseline, model, profile and policy. Restart reuses the same child and deadline.
CancelStops the sequence, including pending approval, diagnosis, repair and tests. A child already activating or verifying finishes its transaction or safe rollback, and no further attempt follows. Unrelated Jobs are untouched.
StatusThe iteration section shows root, parent, attempt limits, deadline and submission status. submitted means handed to the external supervisor; the child still goes through packaging, system checks, a new verification Job, and commit or rollback.
