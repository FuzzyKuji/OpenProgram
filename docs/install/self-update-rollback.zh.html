回退后诊断

方面规则
Job恢复的 worker 在原会话创建一个只读 Job，使用批准的模型和 profile，报告原因和修正建议。
不能改源码、运行 shell、安装或授权。原结论保留。
时间最多回退后五分钟，原期限更早时取更早。重启不重新计时，也不重跑已结束的 Job。
停止Job 取消或 self_update(action="cancel")。新更新会取代它。
无法运行模型不可用或证据无效只停止诊断，不限制服务。
结果有结果时在 self-update status --json 的 diagnosis_result。

回退后源码修正

方面规则
批准首次批准包含隔离修正和所列 required_tests。默认模式再次安装前需另行批准；显式批准的 bounded_auto 允许在限制内再次安装。
触发implementation 或 test 诊断可触发一个只读模型 Job 提出文本编辑。
应用控制器逐项校验，新建 linked worktree 和 commit，在无网络、无 App 写权限的原生沙箱里运行冻结测试。你的 worktree 不变。
范围原改动文件，或 bounded_auto 批准的路径模式。你的候选已改而修正未动的文件保持批准时的状态。
不自动修改受保护的 runtime、审批、安装器、依赖和 Git 文件。无效路径或 old_text 不唯一会停止修正。
时间修正和测试共用回退后最多十分钟，原期限更早时取更早。新更新、取消或过期会停止它们。重启不重放。
取消模型运行时用 Job 取消，测试时在原会话用 self_update(action="cancel", update_id=…)。失败的 worktree 和证据保留供检查。
修正状态含义
candidate_ready新 commit 和全部已配置测试通过
awaiting_tests未配置必需测试；不能 retry，需 owner 发起带明确测试的新请求
failed测试缺失或失败，或源码漂移
cancelled、expired取消或过期

这些都不代表已安装。这些阶段之前的请求保持旧行为，不获得它们。

重试和迭代

方面规则
retryself_update(action="retry", update_id, candidate_sha)，可在 owner 的任一会话调用。询问模式下，审批显示 SHA、改动路径、测试和剩余预算。之后重新检查 Git 内容和测试日志，有变化则提交无效。
bounded_auto需要未来的总 deadline、允许路径模式和非空 required_tests。只有带冻结迭代授权的请求才自动提交；仅有 mode 字段不授予权限。
次数最多三次，含首次。预留 child 就消耗一次，提交失败也算。每个 child 保留目标、assertion、源码基线、模型、profile 和策略。重启复用同一 child 和期限。
取消停止序列，包括待批准操作、诊断、修正和测试。已在激活或验收的 child 完成事务或安全回退，不再有后续 attempt。无关 Job 不受影响。
状态iteration 部分显示 root、parent、attempt 限制、期限和提交状态。submitted 表示已交给外部 supervisor；child 仍要经过打包、系统检查、新验证 Job，以及 commit 或 rollback。
