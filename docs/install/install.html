What the installer does
  • The short script finds the latest stable GitHub Release, confirms it has a package for this system and runs the installer from that release's tag.
  • Prints the size, checks free space first, shows progress, and resumes an interrupted download on the next run.
  • macOS, Linux: installs under ~/.openprogram/runtime/cli/releases/<version>, creates ~/.local/bin/openprogram, and adds that directory to PATH with one marked line in the shell profile.
  • Windows: installs under %USERPROFILE%\.openprogram\runtime\cli\releases, creates %LOCALAPPDATA%\OpenProgram\bin\openprogram.cmd and adds it to the user PATH. The default script policy is left alone.
  • Serialized by a per-user lock. It resolves no product dependencies, clones no repository and builds no JavaScript.
  • Before switching current it verifies the architecture-matched manifest and bundled Ink TUI, then Web, providers, MCP, memory, channels, search, Ink and Chromium, then cold-starts the worker and checks health on an OS-assigned loopback port. Activation and failure.
  • openprogram doctor reports what is still missing, such as provider credentials.

Programs are added with openprogram programs install (Installing programs) and stored apart from the read-only runtime.

Developer additions

Editable Program sources, diagnostics, local frontend builds and replacement OCR or browser backends. Replacements are needed only for GUI perception paths using libraries the runtime omits, and do not change its manifest.

Windows development installer
  • Creates an isolated .venv, installs frontend workspaces from the npm lockfile, builds the browser UI and full Ink terminal UI, and installs the optional browser and Channel dependencies.
  • Installs missing Python and Node.js through winget.
  • Creates openprogram.cmd under %LOCALAPPDATA%\OpenProgram\bin and adds it to the user PATH, so a new PowerShell needs no activation.
  • Needs Node.js 22.12 or newer; Node.js 22 LTS is the validated major version. -Minimal installs only the Python CLI and server, with no frontend dependencies or build.
  • Installs editable CLI and server sources and the browser UI. Windows Desktop is packaged separately with the Desktop workspace's dist:win command.
  • Release and development installs include the Ink terminal UI, with the Python Rich interface as a capability fallback.
  • Windows sandboxing is optional: auto keeps native commands usable without WSL2 and bubblewrap; an explicit workspace-write policy requires that backend.
