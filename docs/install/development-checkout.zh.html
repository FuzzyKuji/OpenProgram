命令效果
openprogram dev deploy[ref] 默认 dev构建进 ~/.openprogram-dev/runtime；在 macOS 上还更新 /Applications/OpenProgram Dev.app。稳定版 App 照常运行。
openprogram dev open在默认浏览器以已登录状态打开。每次部署都会让浏览器重新登录；OpenProgram Dev 自己重新登录。
openprogram dev copy-models复制稳定版的 provider 设置、API key 和委托给 CLI 的登录。OAuth 登录要单独进行。
openprogram dev status两个实例各自运行什么，晋升会带来哪些提交
openprogram dev promote运行 scripts/refresh-local-app.sh，它只安装 refs/heads/stable，拒绝其他提交

Agent 在源码仓库的 worktree 里用 self_update(action="prepare") 做同样的事。这一轮结束后，脱离的控制器等稳定版 App 跑完运行中的任务，晋升这个提交，结果回到发起的对话。晋升失败时，在 dev 上落 revert 并晋升它。

完整规则：稳定版与开发版实例。架构和信任边界：正式版本自动更新。

源码 checkout 中的 openprogram upgrade

验证 Git 目标，仅在相关源文件变化时更新依赖和构建产物，probe 新 checkout，probe 成功后才重启 worker。openprogram update（--check、--force）是单独的遗留命令，目前会抛出 ImportError；更新只用 upgrade。

openprogram upgrade --check
openprogram upgrade --dry-run
openprogram upgrade

refresh-local-app.sh 做了什么
方面规则
构建退出 App 前重建 wheel 和 Desktop 资源，构建失败时什么都不变。
更新内容PATH 和内置 Python 安装、内置 Node 与 Ink 资源、App 图标。
探测重新生成能力清单和重启默认 worker 前，先探测完整内置 runtime。这也会升级旧清单；探测失败则终止刷新。
worker 解释器内置 Python 和 -I -B；已有 launchd 服务重新绑定到它，独立启动也用它。健康检查后脚本核对真实进程的可执行文件和参数：包版本一致不等于解释器一致。
检查点保持严格的工具合同，切换 Python 路径可能使实现指纹失效。
Node副本必须能脱离原安装运行，在改动 App 前检查。PATH 中的 Node 依赖相邻库时，把 OPENPROGRAM_NODE_BIN 设为独立可执行文件。
macOS 签名和正式发布
模式行为
本地迭代scripts/refresh-local-app.sh 使用固定的本地证书，不向 Apple 提交任何内容。签名状态保存在仓库外；不要为消除权限弹窗删除它。
正式发布Release 工作流在 v* 标签时运行，或手动指定已有不可变标签。用 Developer ID 签名 App 和原生组件，等待公证，附加并验证票据，运行打包 runtime 检查，再发布带校验和的产物。分支推送不触发。
  • 仓库 Secrets：MAC_CSC_LINK（加密 PKCS#12 的 base64）、MAC_CSC_KEY_PASSWORD、APPLE_ID、APPLE_APP_SPECIFIC_PASSWORD、APPLE_TEAM_ID。仓库变量：MAC_SIGNING_IDENTITY。只保存在 GitHub 设置中，不写入源码。CI 导入临时钥匙串，签名结束时删除。
  • 重建已审查的标签：Release → Run workflow 或 gh workflow run release.yml -f tag=vX.Y.Z。标签、包版本和发行说明必须一致。
  • 不要每次发布都重建证书或专用密码。过期或被撤销时，更新对应 Secret 后重试。
  • 申请编号在签名任务日志中。In Progress：Apple 未完成。Accepted：允许发布。其他状态停止发布。45 分钟等待超时不取消申请。
  • 用 xcrun notarytool info SUBMISSION_ID --keychain-profile PROFILE 和 xcrun notarytool log SUBMISSION_ID --keychain-profile PROFILE 查询。解决后重跑同一标签的失败工作流；新构建可能产生新的申请。
  • Developer ID App 身份不同，本地刷新拒绝覆盖它。切换模式可能需要重新同意 macOS 权限。Agent 的 bypass 设置不控制 macOS 权限。
