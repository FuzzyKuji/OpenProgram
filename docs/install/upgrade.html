Stable installations move only between published versions and never follow origin/main. State under ~/.openprogram is left unchanged. If the terminal command itself is broken, reinstall the latest version:

curl -fsSL https://openprogram.io/install | sh
irm https://openprogram.io/install.ps1 | iex
What the App updater does
  • macOS: picks the complete DMG for the architecture, downloads it to the location you choose, verifies byte count and SHA-256, and opens it. The shell and complete product runtime are replaced together. Unsigned packages: Open Anyway.
  • Windows, Linux: run openprogram upgrade in the version store and take the App file only when the release needs a newer shell.
  • Windows App file: verifies release metadata, file length and SHA-256. A signed App also requires a valid Authenticode signature from the same publisher; only an App built unsigned accepts an unsigned installer.
  • Downloads go through the system proxy and resume after a dropped connection. When GitHub's API refuses or does not answer, the App finds the release through GitHub's web pages.
When an App that manages versions can't start

A thin-shell App keeps its code as numbered versions under ~/.openprogram/runtime (%USERPROFILE%\.openprogram\runtime on Windows). First start unpacks the bundled code behind a progress page, about a minute.

macOS and Linux serialize upgrades. Version directories are kept, which is what makes rollback the same command. A running worker is not restarted.

Windows launcher replacement
  • One openprogram.cmd launcher is prepared before activation and replaced atomically. The previous one stays as openprogram.previous.cmd. Older openprogram.ps1 launchers are removed, because the default script policy would refuse them.
  • A validated runtime is retained for retry even when launcher activation fails.
Releases that carry a seed
  • When a release publishes OpenProgram-<version>-seed-<platform>-<arch>.tar.gz, install.sh and install.ps1 put it in the version store a thin App uses, <state>/runtime; openprogram runs the version current names.
  • openprogram versions list shows what is kept.
  • Without that asset, the plain runtime above is installed.
  • An interrupted install starts over on the next run. A run on an existing version store updates it through openprogram upgrade and reports what that did.

Official updates on a version-store installation

Takes a release as signed files and carries your own commits over. The Windows and Linux Apps update this way from v1.1.0. The macOS App and plain terminal installs use the routes above.

openprogram upgrade --check
openprogram upgrade
openprogram upgrade --from <directory>     # files already on this computer
Release fileContents

Signature, checksums and every file this platform needs are checked first. An unsigned or altered release changes nothing.
