聊天渠道

发给机器人的消息运行一轮 agent，回复回到同一个聊天。渠道运行在后台服务里，所以对话在 Web 和 TUI 里也实时可见。

平台接收方式登录实时进度收附件发文件
TelegramBot API 长轮询BotFather 的 bot token有图片、文档、语音、音频、视频、GIF图片、文档
Discorddiscord.py Gatewaybot token有有有
SlackSocket Mode（slack_sdk）bot token xoxb- 和 app token xapp-有有，files:read有，files:write
微信iLink 长轮询个人微信扫码无：不能编辑已发消息图片、语音、文件、视频图片、视频、文件

发行版和完整的源码开发安装都包含 Discord 和 Slack 依赖。

快速开始

需要一个 agent（openprogram agents add main）和可用的模型服务商。向导选择平台、登录、绑定 agent 并启动 worker。

  1. openprogram channels setup
  2. 给机器人发消息。第一条回复是配对码。
  3. openprogram channels access approve <channel> <code>

之后对话出现在会话列表里。

各平台准备

平台运行向导前
Telegram@BotFather，/newbot，复制 token。不需要 webhook 或公网 IP。
Discord在 Developer Portal 创建应用和 bot。在 Bot 页开启 Message Content Intent，否则网关拒绝连接。把 bot 邀请到服务器。
Slack在 api.slack.com/apps 创建并安装应用。开启 Socket Mode。bot token 权限：chat:write、app_mentions:read 和所订阅事件需要的 history 权限，如 im:history。app token 在 Basic Information → App-Level Tokens，带 connections:write。订阅 message 和 app_mention，适配器只处理这两种。两个 token 都必须有。
微信个人微信，不需要公众号。扫描终端二维码并确认。扫码人直接放行，无需配对码。凭证保留到出现 bot token invalid — relogin required。走腾讯 iLink 后端，其条款限个人使用。

命令

每个 --id 是一个 bot 登录，有自己的凭证和绑定。

openprogram channels list                              # 每个账号的状态
openprogram channels accounts add telegram --id work   # 建一个账号槽位
openprogram channels accounts login telegram --id work # 录入凭据（wechat 走扫码）
openprogram channels accounts rm telegram work         # 删账号 + 其绑定

openprogram channels bindings add main --channel telegram            # 兜底路由 → agent "main"
openprogram channels bindings add main --channel telegram \
    --account work --peer 123456 --peer-kind direct                  # 只路由一个 peer
openprogram channels bindings list
openprogram channels bindings rm <binding_id>
TUI 命令效果
/login <channel>注册并接到当前 agent
/attach <channel> <peer>把一个对端路由到当前会话
/detach、/connections撤销、列出

谁能和你的机器人说话

私聊使用配对。未列入的发送者的消息在到达 agent 前被丢弃，发送者收到八位配对码。批准只能通过本地 CLI 或 API，聊天里输入什么都不能批准任何人。没有关闭这道门的设置。

openprogram channels access list                       # 策略 + allowlist + 待批配对码
openprogram channels access approve telegram K7XQ2MVR  # 按配对码批准
openprogram channels access allow telegram 123456789   # 直接按 user id 加入 allowlist
openprogram channels access revoke telegram 123456789  # 移除一个发信人
  • 配对码一小时过期；被挡的发送者再次收到同一码，最多每分钟一次。
  • access allow 不用配对码直接加入已知的平台 ID。
  • 名单上的人都到达同一 agent 并代表你，记忆是整个实例一个工作区。只放你愿意把这台机器交给他的人。

批准的发送者能做什么

私聊轮次和 Web UI 工具相同，使用该聊天会话的模式和规则，所以默认 Bypass permissions 下可以不询问就在这台机器运行命令。审批作为聊天问题到达，用 /answer 回答。

openprogram channels accounts set wechat sender_access paired    # 或 owner，默认值（所有渠道）

paired 让账号上所有人在私聊和群里都只有回复和记忆。要独立记忆，对方运行自己的实例：

openprogram --profile alice

Profile

群聊

Telegram、Discord 和 Slack。微信 bot 只收私聊。

发送者回复记忆所有工具，代表你
绑定联系人或 full 访问是是是
chat 访问是是否
其他人无反应否否

其他人没有回复、配对码或错误，也不创建对话。新群名单为空。

openprogram channels accounts group-users add telegram 123456789 --access chat   # 只能回复和用记忆
openprogram channels accounts group-users add discord 80351110224678912 --access full  # 代表你运行
openprogram channels accounts group-users remove telegram 123456789
openprogram channels accounts group-users list telegram
openprogram channels accounts group-users add telegram 123456789 --access full --group -1001234567890
openprogram channels accounts group-users remove telegram 123456789 --group -1001234567890   # 群的名单还在，空了也一样
openprogram channels accounts group-users reset telegram --group -1001234567890              # 重新使用账号名单
  • 第一段：账号级名单。第二段：单个群的名单，替代账号的；remove 后群名单保留即使为空，reset 回到账号的。绑定联系人保留完全访问。Discord 帖子用父频道的名单，除非有自己的。
  • ID 是稳定的平台用户 ID：Telegram 和 Discord 是数字（开发者模式，复制用户 ID），Slack 以 U… 开头。worker 日志写出每个被忽略的发送者。下一条消息生效。
  • Settings > Channels 有账号级名单；单群名单只能用命令行。
  • require_mention 仍适用：名单上的人未提及时，消息只作为上下文等待。
  • chat 用户不能用 /new、/reset、/activation、/memory、/stop、/help。他们写的内容是之后代表你运行的轮次的上下文。
  • access revoke 只动允许名单；这些名单用 group-users remove。绑定联系人不能设为 chat：先撤销，这也结束其私聊。绑定列为 chat 的人会把他从名单移除。
  • 发送者输入什么都不能改这些名单。
从有 group_access 的版本升级

该设置已移除，存储值被忽略。之前在群里通过配对码批准的同事只有回复和记忆；他们在允许名单上，现在在群里代表你运行。升级前运行 openprogram channels access list，然后对每位同事执行 access revoke 和 group-users add <channel> <user id> --access chat。

渠道和环境

渠道决定消息镜像到哪里，对话的环境决定工具在哪里运行。来自渠道的对话用默认环境。

主题行为
渠道标签Web 和 App 输入框上方、环境标签旁：logo 和账号，或 No channel。圆点：黄色降级，红色不可达。打开后每个应用一行；选账号绑定或切换，Disconnect 停止，Manage channels 添加。
绑定微信账号你微信发给 bot 的消息到这里，不进单独对话。账号上每个聊天对象只归一个对话；在别处选择同一对象会移走，同账号其他对象的对话不受影响。没有已知对象的选择会占用整个账号。断开或切换后回到平常的对话。
绑定对话的回复每条助手回复都发出，不管谁启动的轮次：App 里输入、Goal 或提醒。只发回复：你输入的内容、工具进度和思考留在 App。常驻检查和定时任务改发报告，除非 Agent 的渠道设置已关闭。
审批暂停发送之前写的；批准后只发之后的
没有接收方未指定聊天的 Telegram、Discord、Slack 账号，回复留在 App
投递失败App 显示带渠道和错误类型的通知；回复已保存
账号状态设置的频道页，每个 bot 一行：运行中、已关闭、未登录、已退出登录（token 或登录已失效）、因错误停止、正在重连、没有响应或尚未启动。异常状态会写明该做什么，重新登录后 bot 自动启动。

谁说的

每条渠道消息都带发送者，私聊也是（main 会把对端放在一起）。Web、CLI、TUI 轮次没有。

{"speaker_kind":"human","speaker_id":"7391","speaker_display":"Ada","content":"预算定 5 万"}
{"speaker_kind":"human","speaker_id":"8022","speaker_display":"Bo","content":"改成 8 万"}
  • ID 在改名时不变，也能区分同名的人；记忆把事实记在说话人名下。
  • 显示名放成一行，最长 64 字符，方括号变圆括号。消息文本原样保留；在括号里打名字不能冒充。
  • Web 记录在气泡上方显示小字，如 WeChat · Ada；微信发送者没有昵称，ID 缩短为首尾各四位。

群聊行为

模式行为
always每条消息开始一轮
mention只有 @ 或回复 bot 才开始，提及被去掉。下一轮得到最近 50 条其他消息和发送者，Web 记录里在“earlier messages in the chat”开关后面。
ambient每条消息开始一轮，agent 决定是否用 chat_send 发言。对未提及消息的回复留在 Web 记录，标为“overheard”。没有输入状态或确认表情。提及的消息正常回答。每条消息一次模型调用。
openprogram channels accounts set telegram require_mention on       # 或 off（discord、slack 同样可用）
openprogram channels accounts set telegram group_sessions per-user  # 或 shared（仅 telegram）
  • require_mention 设默认：on 是 mention，off（默认）是 always。
  • 有完全访问的人用 /activation mention|always|ambient；单独使用显示当前模式。私聊不受限。
  • group_sessions（Telegram，需重启 worker）：shared（默认）或 per-user。
  • 群成员能接触 agent 的记忆。/memory read 禁止写入，/memory off 移除，/memory on（默认）跟随 agent 设置。私聊始终跟随 agent。
  • 其他 bot 的消息被忽略，重复投递只开始一轮。每个群每分钟最多 10 轮，其余作为之前的消息等待。

投递细节
  • 长回复填满占位后在新消息继续。占位无法编辑时改发新消息。
  • Slack 帖子和 Telegram 论坛话题里，占位、回复、文件、智能体自己发的消息和提问都留在原处；Telegram 话题里的“正在输入”也显示在该话题。同时发到频道的 Slack 帖子回复也算一条消息。
  • 编辑服务启动前发的 Telegram 消息不起作用。
  • ack_reaction on（微信除外）收到时加 👀；Slack 需要 reactions:write。
  • 长代码块在每条消息里都完整闭合，下一条接着打开。Discord 回复不会提醒任何人，包括 @everyone。Telegram 拒收的图片改为按文件发送。
  • 被限流时重试，有 Retry-After 就按它，最多三次，然后记录结构化错误。连接没建立时最多尝试四次；请求没到平台，不会重复送达。
  • 连接循环崩溃后指数退避重连，5 秒翻倍到 5 分钟。凭证失效保持停止，直到重新登录；被 API 拒绝的 Telegram token 也算。微信服务器出错时等待后重试，3 秒翻倍到 48 秒。
  • 服务每隔几秒检查账号：链接、登录、启用或禁用都无需重启。

一个对话同一时间只跑一轮，App 的轮次也算。另一轮在运行或等待回答时：

  • 聊天消息最多等 30 秒，之后机器人回复正忙，稍后再发一次即可。
  • ambient 模式下没提及机器人的群消息不回复，并入这个群的下一轮。
  • App 里发消息会被拒绝，和其他轮次运行时一样。
  • /new 和 /reset 遇到聊天软件发起的轮次时最多等 30 秒，之后机器人回复正忙。

同一个聊天的消息按到达顺序开启轮次，前一条的附件下载慢也一样。命令不排队。
