每次 Agent 方法调用都是会话对话 DAG 的一个节点，与用户消息和 LLM 调用并列。嵌套调用自动串起来：verify 调用 LLM 时，已经能看到 observe 和 click 的返回。

login_flow ✓ 8.8s
├── observe ✓ 3.1s → "found login form at (200, 300)"
├── click ✓ 2.5s → "clicked login button"
└── verify ✓ 3.2s → "dashboard confirmed"

选项控制
expose之后的调用能看到它的什么：io 输入输出（工具默认）、llm 它的 LLM 交互、full 全部（其他情况默认）、hidden 没有节点
render_range={"callers": N}函数自己能看到多少先前历史；0 完全隔离
render_range={"subcalls": N}长循环中它自身帧内的历史

编写函数的函数

编写和修复 Agent 方法是普通的 agent 工作，用文件编辑工具，遵循 agentic function API。没有 create() 或 fix() 框架调用。skill 就是规范：文件位置、装饰器元数据、docstring 与 content 的区分、校验清单和冒烟测试。Program 在写、跑、败、修中变好。

对话即 git DAG

每次交流是一个提交。分支是一等公民。

操作效果
分支从任意历史交流探索，保留原线索
附加把另一会话的上下文作为带标签的用户消息带入
合并把两个或更多分支合成一个汇总回复

涉及文件的分支在隔离的 git worktree 中运行：分叉的是底层仓库，而不是消息的副本。

多账户与密钥轮换

账户就是 profile：provider 的一组独立凭据。API key 类 provider 同样持有一个密钥列表。

openprogram providers login openai --account work
openprogram providers use openai work
openprogram providers use openai                     # 回到默认账户
openprogram providers list

Web（设置 → Providers）和 TUI（/login <provider>，在终端完成 OAuth、设备码、CLI 导入或粘贴密钥）有相同的面板。

密钥管理规则
添加粘贴，先校验再加入列表。可为每个命名
使用被调用的是当前密钥。通过环境变量或配置设置的密钥会迁入
轮换，可选，默认关失败的密钥冷却，下一个接替
冷却429 约 1 到 5 分钟，402 账单 24 小时，5xx 30 秒
策略in order、spread evenly、random、least used，可用 ↑ ↓ 调优先级
