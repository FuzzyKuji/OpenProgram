Daily use

Entry points

CommandOpens
openprogramTerminal chat
openprogram webBrowser at http://localhost:18100, signed in
openprogram --print "…"One question, one reply, exit
openprogram status, restart, stopThe background service: state, restart after code or config changes, stop

Both interfaces share one history, stored in ~/.openprogram/projects/<project-id>/chats/<session-id>/. Sessions with no project belong to the home project (id default, named after your home folder). Working folders hold project files, not conversation repositories.

Sessions

CommandEffect
openprogram sessions listEvery session across agents
openprogram --resume <session_id>Continue in the terminal
openprogram sessions resumeAnswer a session waiting for input
openprogram sessions attachRoute a channel user's messages (Telegram, Discord, Slack, WeChat) into a session
openprogram sessions detachBack to default routing
openprogram sessions aliasesList session and channel-user bindings

In the Web UI

History is a conversation DAG, like git commits and branches. Message actions appear on hover.

ActionOnEffect
CopyAnyCopies the content
RegenerateRepliesNew version of the reply
Pin as chapterRepliesLengthens, thickens and colours its tick on the left message rail, and keeps its action row shown. Unpin chapter removes it
Edit messageYoursChanges it and regenerates; files stay as they are
Rewind to hereYoursReturns the conversation, the files or both to before this message and refills the input; Undo rewind brings the conversation back
Fork from hereYoursNew conversation from this point; this one stays
ControlEffect
Previous and next arrows beside a messageSwitch versions after an edit or regenerate
Branch menu, top barList and switch branches
Select text, Add to chatQuote part of a message
Copy conversation, ⋯ at top rightNew conversation with the same history, running on its own
Right sidebarThe DAG: user messages, LLM calls, function calls. Scrolls with the chat; clicking a node scrolls to its message

Branches that touch files run in isolated git worktrees, so concurrent branches do not fight over one source tree.
