FAQ

Running

Port 18100 is in use 
openprogram ports                 # current port
openprogram ports --port 18110    # persistent, next start
lsof -ti:18100 | xargs kill       # free it from a leftover process, then restart

For one run: OPENPROGRAM_WEB_PORT.

The page opens, but providers, models and agents are empty

The page is not signed in: reached by typing the address, every list is empty, the Local chip is red and a notice says so. Nothing is missing. Run openprogram web. For another browser, openprogram web auth-url prints a sign-in link. Each service start makes a new sign-in, so open it through openprogram web again after a stop or restart.

The page from openprogram web will not load

Open http://localhost:18100. A release wheel contains the Web export; reinstall the exact release if it is missing. In a source checkout, run the development installer to rebuild it.

The service is down or behaves oddly 
openprogram status
openprogram restart
openprogram doctor
openprogram rescue     # diagnoses and prints the fix commands
Reading the logs 
openprogram logs list
openprogram logs tail            # last 50 lines of the worker log
openprogram logs tail -f
openprogram logs tail runtime    # worker, runtime or ink
Two OpenPrograms on one machine

Yes: profiles separate state and ports.

Providers

Provider not detected, or "No provider available" 
openprogram providers            # stored credentials
openprogram providers discover   # Claude Code, Codex, Gemini CLI and others
openprogram providers doctor     # expiry, refresh, cooldown, conflicts
openprogram setup                # re-run the wizard

A key in the environment must be imported: Key already in your environment. Restarting the service does not import it.

Several accounts or keys for one provider

Multiple accounts and key rotation. openprogram providers list marks the active one.

Data and updates

Where my data is

~/.openprogram/, or ~/.openprogram-<name>/ with --profile: config.json, projects/ (conversations and memory), logs/, usage.db (token usage). Full list.

Getting an earlier conversation back

openprogram sessions list, then openprogram --resume <session_id>, or the Web sidebar.

Why the release download is large

It includes managed Python and Playwright Chromium. It does not include PyTorch or EasyOCR. A normal install downloads no further product components.

Extending

An installed agent program does not show up

openprogram programs list, then restart OpenProgram or use Refresh on the Programs page. If it lists no entries, OPENPROGRAM_DEBUG_REGISTRY=1 openprogram programs list shows why. Directory contract.

Chrome or Edge browser extensions

Not supported. Store pages open as ordinary webpages: no install button, CRX download, browser import or extension manager. Electron/Chromium supports only part of the Chrome Extensions API, and OpenProgram maintains no fork or second browser runtime for it. The shipped Playwright Chromium is an automation backend: it hosts neither the Desktop Browser Pane nor extensions.

To extend OpenProgram itself: Plugins, Skills, MCP servers, Programs or agent tools.
