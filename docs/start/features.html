Why it works this way: Agentic Programming philosophy.

Automatic context

Every Agent method call is a node in the session's conversation DAG, with user messages and LLM calls. Nested calls thread themselves: when verify calls the LLM, it already sees what observe and click returned.

login_flow ✓ 8.8s
├── observe ✓ 3.1s → "found login form at (200, 300)"
├── click ✓ 2.5s → "clicked login button"
└── verify ✓ 3.2s → "dashboard confirmed"

OptionControls
exposeWhat later calls see of this one: io input and output (default for tools), llm its LLM exchanges, full everything (default otherwise), hidden no node
render_range={"callers": N}How much earlier history this function sees; 0 walls it off
render_range={"subcalls": N}Its own in-frame history in long loops

Functions that author functions

Writing and fixing Agent methods is ordinary agent work with file-editing tools, following the agentic function API. No create() or fix() framework calls exist. The skill is the spec: file location, decorator metadata, docstring versus content, a validation checklist and a smoke test. Programs improve through write, run, fail, fix.

Conversation as a git DAG

Every exchange is a commit. Branches are first-class.

OperationEffect
Branch offExplore from any past exchange, keeping the original thread
AttachBring context from another session in as a labelled user message
MergeCombine two or more branches into one aggregated reply

Branches that touch files run in isolated git worktrees: the fork is of the underlying repository, not a copy of messages.

Memory that writes itself

Paths, commands, tools and write guarantees: Memory.

DAG view

The right rail draws every node (user message, LLM call, code Call, attach) and edge. It scrolls with the chat, highlights the range in view, and clicking a node scrolls to its message. Rendering rules.

Multiple accounts and key rotation

An account is a profile: an independent credential set for a provider. API-key providers hold a list of keys the same way.

openprogram providers login openai --account work
openprogram providers use openai work
openprogram providers use openai                     # back to the default account
openprogram providers list

The same panel is in Web (Settings → Providers) and TUI (/login <provider>, which completes OAuth, device code, CLI import or key paste in the terminal).
