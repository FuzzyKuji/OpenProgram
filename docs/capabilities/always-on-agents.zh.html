常驻 Agent

使用常驻 Agent 的每个会话，在关注的事到点时醒来，推进常驻目标，空闲时用只读工具巡检新情况，只在值得时才来找你。

常驻是 Agent 配置的一部分。和这个 Agent 的每个会话都是一个独立的常驻助手，各有自己的目标、巡检和报告。想要两个互不相干的助手，就开两个会话。

开启

管家和内置职能 Agent 已经开启：在输入框的 Agent 按钮或 Agents 页面的卡片上开一个会话，告诉它要盯什么或接着做什么。你自己的 Agent：

  1. 在侧栏打开 Agents，选中它。
  2. 在常驻标签页勾选让使用此 Agent 的会话常驻。
  3. 可选：常驻目标、固定唤醒间隔，以及何时唤醒下的唤醒日子和安静时段。
  4. 保存修改。
  5. 和它对话：Agents 页面的新对话，或 Agent 按钮。
设置取值
常驻目标写要达成的结果（“让文档站没有死链”），不写例行动作（“每小时检查链接”）。要求满足后 Goal 结束；之后再看是巡检的事。
固定唤醒间隔5 到 10080 分钟。留空时 agent 自己安排唤醒。巡检关闭时，它不能安排巡检。草稿的试用对话不会被唤醒。
唤醒的日子定时唤醒发生在星期几，至少留一天。
安静时段每天的开始和结束，例如 22:00 到 08:00。结束早于开始表示跨午夜。

唤醒日子和安静时段按这台电脑的时钟和时区。默认任何时候都可以唤醒。立即唤醒、来自其他会话的消息和已在运行的 Goal 不受影响。

每次唤醒最多做一件事

情况结果
定时唤醒落在安静时段或非唤醒日不做事；下次唤醒移到安静时间结束
已有一轮或巡检在运行不做事；五分钟后再试
有尚未开始的常驻目标在会话中作为 Goal 启动
Goal 进行中或被你暂停不做事；Goal 自己继续，你的暂停保持
Agent 启动的 Goal 失败或被重启打断重新启动它，连续最多三次；有一轮成功完成就重新计数
Agent 启动的 Goal 的一轮被人停止、因其他原因停下，或重启次数用完发一条汇报请你决定，巡检继续
你启动的 Goal 失败、停滞或预算耗尽不重启也不汇报；巡检继续
没有 Goal，巡检开启巡检，除非没什么可查
其他不做事

没有常驻目标、没有未完成的待办或开放工作、上次巡检后也没有新消息时，定时巡检不调用模型直接跳过。失败或被重启打断、还没汇报的巡检不算上次巡检。

你没发过言的会话不会被巡检。agent 自己安排的巡检和立即唤醒总会运行。另一个 Goal 未结束时修改的目标，等它结束才启动；/goal clear 可立即切换。

固定时间的事（“每天 9 点总结收件箱”）请改用定时任务。

定时任务
  • 在后台运行，不进分支列表。每次运行都从头开始：只看任务和上一次的结果，不看会话内容。没有新内容就不打扰；有变化时在会话里发一条普通消息并通知。
  • 连续失败三次时告诉你一次。
  • 运行记录面板显示每个任务最近的结果和最近 20 次运行，每次都能原地展开看它做了什么。Agent 能看到任务并读取结果。

巡检

巡检查看记忆、会话的开放工作和会话本身里没收尾的事，并寻找新情况。过程不出现在会话里：你可以继续输入，侧栏位置不变。无论会话多长，巡检只读摘要和最新一段，需要时才往前翻，也绝不压缩会话。

每次巡检都能看到以前的报告，除非有变化不重复；选了渠道的 Agent 还能看到它其他会话的报告标题。网页、文件和以前的报告都只是数据，它不会照其中的指令做。

项目规则
工具只读：读取和搜索文件、网页搜索和抓取、读取会话和记忆、待办、开放工作和 Goal 的读取。你为对话或 Agent 关闭网页搜索后，检查也不会使用它。不能运行命令、改文件或调用 MCP server。~/.ssh、.env 这类凭据和配置，以及私有网络地址，一律拒绝。
只报告发现（默认）在报告里提议工作，由你决定
可自行开始目标可以把发现变成 Goal，或交给负责这类工作的会话。Goal 作为会话的普通轮次运行，使用正常工具和权限，但其中以及交接轮次里的页面脚本和破坏性删除会被拒绝；它会说明原因，由你自己操作。巡检不能等待批准：权限模式需要询问时，它改为在报告里提议这项工作
没有目标时进行巡检关闭后只为常驻目标唤醒
权限使用会话的模式和规则，但没人审批：需要审批的步骤被拒绝，改在报告里请求。它启动的 Goal 和其他 Goal 一样等你审批。
巡检失败时不算看过：下一次仍覆盖上次完成以来的全部内容，节奏不变。连续失败三次，或模型账号被拒绝时立刻，发一条报告告诉你；之后，没有固定唤醒间隔时，尝试间隔越来越长。被重启打断或被人停止的不计入。
巡检模型可在常驻标签页选更便宜的模型。默认用会话的模型。
每日预算每个 Agent 的美元额度。花完后定时巡检等到第二天；立即唤醒仍可运行。由巡检、交接或定时任务启动的 Goal 只能花当天剩余额度，费用计入当日合计，额度用完就不再启动。运行记录面板显示每次巡检的 token 和费用，以及当日合计。
设了预算时同一 Agent 的定时巡检一次只运行一个，其余巡检和自动轮次留下的 Goal 五分钟后重试。价格未知的模型触不到这个上限，运行记录面板会在它的巡检上注明。

报告

类型含义
发现你可能想知道的事
待决定需要你决定
已完成一项工作完成了

报告有标题、一到三句话的正文和可选链接，以 Agent 的消息出现，你的下一条消息可以直接回复。有一轮在运行时排在它之后。巡检没有可报告的内容时不在会话里留痕，运行记录面板仍显示结果。

App 里，消息只有正文和链接，网页链接显示为站点名；标题留在列表和通知里。聊天视图里，上方的时间行说明它为什么来：例行查看时发现、后台做完了、请你决定，或定时任务的名字。

位置行为
会话和未读圆点总是有；会话正在屏幕上时没有圆点。最小化或在后台的窗口不算在屏幕上
桌面 App 通知没有 App 窗口获得焦点时；点击打开会话。没有打开 App 时，电脑仍会弹出通知，除非会话正显示在浏览器里。按类型设置，默认开。
渠道按类型设置，默认开
侧栏的待处理带计数。等你决定：待决定的报告，直到你在该会话发言；交接、提醒或 Goal 继续运行都不算，关闭常驻也不会清空。新发现：发现和已完成的工作，直到你打开会话。也在每个运行记录面板顶部显示为等你处理。打开跳到会话。超过七天不再列出。

告诉它报告什么：直接在会话里说（“通过的构建不用告诉我”）。每条规则成为该 Agent 的报告偏好，之后的巡检和定时运行都遵守。只有你自己的轮次能添加，巡检和定时运行不能。运行记录面板列出它们可删除，每条报告也能停掉同类报告。

把报告发到渠道
  • 在同时把报告发到下勾选最多 10 个聊天渠道会话：Telegram、Slack、Discord 或微信。对这个 Agent 所有会话的报告生效。绑定了渠道的聊天不用勾选，报告也会发到那里，只发一次；渠道设置可同时关闭这两条路径。
  • 列表包含该 Agent 已有的渠道会话，以及用 peer 绑定的人和群：openprogram channels bindings add <agent> --channel telegram --account <id> --peer <id>。绑定到整个渠道或账号的 Agent 只列出和它说过话的人。
  • 每条报告在 App 保存后向每个选中的会话发一次。运行记录面板在报告下显示结果；发送失败（例如账号已退出）会显示在那里，报告保留。
  • 该渠道已有自己的会话时，报告也作为消息出现在那个会话里，所以直接在手机上回复就有上下文；在那里回复也算答复了这条待决定的报告。

把工作交给另一个会话

会话可以组队，一件事一个负责人。常驻会话的 agent 有 handoff 工具，按标题或 ID 给你的另一个会话发消息，也可以写 Agent 的名称（该 Agent 只有一个其他会话时）；对方可用任何 Agent。给每个会话清楚的标题和职责，并告诉负责规划的会话谁做什么。

环节行为
投递作为下一轮到达，以 📨 和发送方标题开头。有一轮在运行时等待，最多十分钟。
回复那一轮真正结束后答复作为新一轮返回，以 ↩️ 开头，中途停下等你审批的也一样。这一轮失败或被停止时，发送方收到的是这件事和原因。对方一直忙或在等待期间被归档时，消息退回为未送达。
转交接收方把工作再交给第三个会话时，最初的发送方会等第三方答复后接收方给出的答复，而不是它那句“我已经问了”。
聊天软件对 📨 的答复只发给发送方，不发到接收会话绑定的聊天软件。↩️ 那一轮的答复仍会发到发送方绑定的聊天软件。
权限每轮用各自会话的 Agent、模式和规则。Manual 模式下发送等待审批，Auto 模式下经过审核。
拒绝给自己发消息；给链上游正在等待的会话发消息；一条链超过四跳（包括经由该链启动的 Goal）；同一会话或同一条链每小时超过 20 条消息；发送方或接收方是子 Agent、导入或已归档的会话
重启链在服务重启后保留一天：跳数继续计算，还在等待忙碌会话的消息只投递一次，正在处理消息的会话完成后仍会回复；如果重启终止了这项工作，发送方会收到说明

运行记录面板

Activity 面板中的一行

在会话的运行记录面板里，主 agent 的行多一条常驻：是否有巡检在运行，以及安静时段之后的下次唤醒；agent 自己安排时附理由。

它的页面在运行列表上方有常驻一行：常驻目标、当前 Goal、唤醒计划、是否还在运行（上次何时唤醒、24 小时内的唤醒和失败次数，或早该发生却没发生的唤醒）、上次唤醒的结果和费用、今日巡检花费和报告偏好。报告是运行列表里的行。

立即唤醒现在运行一次，有回合在运行时 5 分钟后再试，也用来重试失败或被重启打断的巡检。Agent 给自己定好的后续巡检不受影响。

新建的常驻 Agent 空会话会列出三句可以对它说的话。点击只会填入输入框；输入框有内容后这些句子就消失。

使用常驻 Agent 的会话读起来像和机器人聊天：短段落各占一个气泡（最多四个，代码、表格和列表与前后文字留在一起），间隔 30 分钟或跨天后再显示时间。思考、工具步骤和消息按钮不绘制；Agent 说完一段后继续工作时显示三个点。

回复失败或没发完时，下方有一行说明；被重启打断的回复接着显示为同一条；网页来源只在最后一个气泡下显示一次。内容没有删除；旧会话同样如此，关闭常驻后恢复完整视图。

在 Telegram、Discord、Slack 和微信里，Agent 写得更短，用编号列表给出选项；表格写完后才发送，每行变成一行文字。

限制

主题限制
运行位置工作在这台电脑上，在会话的文件夹和沙箱里进行。worker 必须在运行。
停止关闭常驻或归档会话会停止唤醒，会话、报告、记忆和设置都会保留。
发送的内容通过已连接服务发出的内容遵循会话的权限模式。想逐条审阅，在常驻标签页末尾勾选发送前等我批准。巡检时无人可问，被拦下的消息会以草稿形式出现在报告里。
复制 Agent复制出来的 Agent 默认关闭常驻。
时间限制巡检超过 15 分钟会被停止，最近一次唤醒会写明原因。用立即唤醒重试。
报告和重启等待运行中一轮的报告在那一轮之后加入。服务重启后，一小时内的报告仍会加入，聊天应用的发送也会继续，所以聊天应用偶尔可能收到两次；更早的报告留在运行记录面板，没发完的发送显示为被重启中断。
你的浏览器检查、定时运行、自动 Goal 的轮次、交接或聊天应用消息，以及它们启动的工作，都不会占用你正在看的浏览器页面。它在你的工作后面打开自己的标签页，或使用从页面列表里点名的页面。
学习它靠记忆改进：在 Agent 的长期记忆标签页设为读写，纠正才会保存并使用。否则常驻标签页会提醒。你对汇报的回复会被学习，汇报本身不会；定时运行只有你在它的分支上继续对话时才会。
