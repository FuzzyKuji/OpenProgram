Weekly reports

Five packages in ~/.openprogram/programs, independently versioned; source checkouts do not include them. Shared helpers: openprogram.programs._authoring.reports.

EntryPurposeExternal writes
personal_weekly_report(task)Personal Feishu drafts, inspection, filling, submission, record updatesFilling changes fields without saving; submitting or updating needs an explicit request
personal_chat_weekly_report(task)Owner's three-section WeChat-group copy: progress, discussion topics, next-week plans, in ChineseLocal draft; never sends
group_weekly_report(task)Collect group reports, track missing members, prepare a summaryNever sends
tencent_weekly_report(task)About 100 Chinese characters of Tencent progress for a leaderLocal draft
weekly_report(task)Selects the requested Workflows and forwards the complete request; imports the other fourAs the child

Personal-chat and Feishu drafts return the full Markdown body by default, with no file write needed; returning text submits nothing. An explicit Markdown path keeps file delivery, and existing file-delivery resume requests still work.

weekly_report

Select it in Abilities. Natural language goes to a routing agent; JSON requests addresses children directly with no routing inference.

{
  "requests": {
    "personal": {
      "week": "2026-W37",
      "materials": [{"id": "p1", "week": "2026-W37", "text": "Experiments remain in progress; next week we will check the results."}]
    },
    "tencent": {
      "week": "2026-W37",
      "materials": [{"id": "t1", "week": "2026-W37", "text": "Tencent evaluation is still in progress. No final performance conclusion is available."}]
    }
  }
}

Materials are separate by audience. Personal and Tencent inputs need matching ISO weeks and unique source IDs. Thin evidence returns a request for input or review, never invented progress.

Tencent report

Select tencent_weekly_report and enter Prepare this week's Tencent weekly_report. Uses the current ISO week in Asia/Shanghai, targets 80–120 non-whitespace characters aiming for 100, intended for Friday afternoon. It creates no schedule and sends nothing; a scheduled run needs an exact time and material source configured separately.

OrderEvidence
Explicit materialsTake precedence
1. reports directoryOriginal current-week Tencent evidence; optional report_roots selects up to five directories
2. Other report sourcesConsidered next
3. Recent OpenProgram sessionsOriginal owner messages, keeping date and session/message reference. At most 20 sessions and the last 200 messages each.
4. Dated memoryGenerated notes are lookup candidates, not verified facts
ExcludedAssistant drafts, unattributed messages, other weeks, month/year-only dates, pending memory records, untrusted raw memory, test records
Other audiencesNeed source selection with exact quotes

A dated request or plan is a candidate, not proof. Combined context is at most 30 records and 18,000 UTF-8 bytes. Insufficient sources require clarification within that scope, which does not establish that no work exists elsewhere.

Output, timeouts and failures
  • Success returns the report body. Sources, character count and model calls stay in local drafts. "result_format": "structured" in the JSON task returns status, artifact paths and a recovery object; the router forwards explicit child options unchanged.
  • Generation and verification use low effort, 180 seconds per call and preserved retry budgets. Request interpretation inherits the deployment timeout. Every JSON stage declares a schema and reuses Runtime format repair.
  • Model failures produce no success draft and keep the typed failure and resume task, never treated as missing input.

Group report

Prepare the group report is enough: identity, roster, materials and author evidence come from memory, local records and the identified WeChat group. Supplied bodies are kept. No period given: the current ISO week, recorded as an assumption.

Personal Feishu report

Select personal_weekly_report and request Fill the personal Feishu weekly report without submitting. It checks records, prepares six fields, fills them and reads each back.

SituationFILLEDSUBMITTED
No record exists, fill requestedYesNo
Explicit submit request, no recordNoYes
Existing record or capped form, fill requestedBLOCKEDNo
Missing or ambiguous field, truncated value, uncertain writeNoNo

A submit request meeting an existing record returns its inspection result; changing it needs an explicit update request.
