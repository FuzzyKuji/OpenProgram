Agentic 工作流

Agentic 工作流在代码里叫 harness 或 agentic program，是一个包含 Agent 方法的 git 仓库，用 Agentic Programming 构建。发行版不捆绑任何工作流。安装后出现在聊天、Web UI 的 Programs 页和 openprogram programs run 里。

命令

命令效果
openprogram programs list所有 Program：工具、应用、你的包、harness。~/.openprogram/programs 里每个 Workflow 是一行 package，带入口和状态：loaded、error 或 pending（暂不可调用：还没有提交通过检查）。
openprogram programs install <owner>/<repo>任意 harness，git URL 或目录也行。克隆、安装声明的依赖、记录批准的来源。只限可变环境：源码检出或 CLI/服务器安装。打包的桌面 runtime 拒绝。
openprogram programs install <ref> --upgrade重装或升级
openprogram programs uninstall <name>把 harness 移到一边
openprogram programs run <name> -a key=value直接运行。--provider（默认自动检测）和 --model 覆盖模型。

Agent 写的工作流

适合稳定的多阶段结构、重复使用或需要可审查历史的任务；一次性任务不需要。没有专门工具，用文件工具和命令行：

  1. 把 ~/.openprogram/programs/<name>/ 建成 Git 仓库，写入角色、函数、PROGRAM_ENTRIES、README.md 和行为测试。
  2. openprogram programs check ~/.openprogram/programs/<name> 导入包，在系统沙箱里跑测试，通过后提交并把该提交记录为已检查。
  3. 失败时读报告、修复、再检查。

worker 几秒内加载通过检查的提交；入口无需重启就成为所有聊天里的工具并出现在 Programs 页。修改也一样。旧版本留在 Git 里。

命令行openprogram programs run paper_agent -a task="Survey recent work on agent memory"
Python普通可导入函数

表单只问任务信息，不问执行设置。文本润色从文本推断风格。浏览器后端和会话句柄保持内部。页码范围和输出位置是可选需求。明确的 Python 调用者保留支持的覆盖项。

模型选择

情况模型
从聊天运行内部调用继承本轮：单轮覆盖，然后会话选择，然后 agent 配置。也用于工具子进程。
直接运行工具内部调用需要明确的服务商和模型；不用全局检测或服务商默认值
函数体不调用模型没有配置也能运行
模型或凭证不可用函数体调用 Runtime 时失败，保留该模型的错误。无模型步骤仍运行，不换服务商。
浏览器工作流

选择后端时保留明确的初始 URL。官方 MCP 后端支持受保护的等待并传递快照失败。页面恢复限于当前窗口范围，不重放失败的操作。验证过的结果保留实际证据和观察目标。

周报

如果目录里有 weekly_report，把报告文本或要改的内容给它：提交本周周报、只更新下周计划、查看记录，或在指定路径起草本地草稿。

如何写入飞书
  • 读取配置的表单，写入前匹配姓名和年/周。没有记录时提交一次；已有可编辑记录时从提交历史打开并保存。部分更新保留未改字段。草稿和只读请求不提交。
  • 检查结果未知、登录失败和记录歧义时停止。提交上限本身不排除编辑已有记录。
  • 成功需要新的页面确认和持久化的值。结果不确定时报告，不重试。普通浏览器授权仍需要。用有界的浏览器步骤，不用 goal() 循环；不编造进展、指标或论文题目。
group_weekly_report

group_weekly_report(task) 准备未发送的草稿，检查后自己发送。

项目行为
证据从记忆、本地文件和微信收集范围、材料和作者
缺口缺字段不提问；未知作者和不可用来源会列出。缺少材料不等于没交
source: "supplied"限于提供的材料。完整结构化的仅提供材料检查不用模型
摘要有界的逐成员上下文、核对过的引用、明确的不确定性
文件reports/group-weekly/<week>/<unique-run>/ 或 output_dir
