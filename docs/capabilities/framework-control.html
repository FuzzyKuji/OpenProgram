WebSocket commands

framework(action="commands")
framework(action="command", operation="rename_session",
          arguments={"session_id": "EXACT_SESSION_ID", "title": "Research"})

Results hold response frames, after the command's own validation. Long-running work stays with the worker; read its execution or session state. File operations keep their request IDs, idempotency keys and revision checks.

A window, without screen automation

framework(action="interface")
framework(action="interface", operation="tabs.list",
          arguments={"window_id": "EXACT_WINDOW_ID", "arguments": []})

The catalogue declares tab, group, split, sidebar, resource view, appearance, bookmark and native Desktop commands with schemas.

  • Commands target one authenticated connected window. Missing or ambiguous windows fail explicitly, and a lost reply is not retried.
  • Native history, downloads, browser import and update controls use the existing Desktop functions. A browser window reports native-only capabilities as unavailable.
  • Window presentation needs a connected view; backend and installed application operations do not need a rendered frontend.
  • Unsaved file tabs must be saved or discarded before an automated close.
  • Web pages are created and closed with resource(provider="web", action="open"/"close"). Native Page presentation commands also need arguments.web_session_id from the current web observation, and keep the Page lease, session access and enabled-tool policy.
