Saving and model choice
  • Sections share one draft; Save writes all of it. Changing Agents or a destructive action offers Save, Discard or Cancel. A failed save keeps the draft.
  • If another editor saved first, compare before choosing. Keeping your draft does not overwrite the newer version; review and save again.
  • The model picker reads the provider catalog without changing another conversation. Last used model runs each conversation on your most recent model.
  • An unavailable model or unsupported effort stays visible until you change it. Missing required MCP servers stop execution before a model request.

Built-in Agents

Complete configurations saved as ordinary cards: edit, duplicate or delete them. The server installs those this instance has never had at startup; a deleted one is not recreated. One you have not changed picks up new versions on its own; one you have changed stays as you left it.

For chat, always-on off

AgentPurposeCapabilities
Assistant (default, id main)General; new conversations start on itEvery tool
DecisionSelect one of the supplied options with Agent.choose()One model turn, no tools, no automatic re-pick
Lightweight helperExtract, classify, format, summarize, predict next messagesNo tools
CoordinatorPlan dependencies, delegate authorized tasks, check resultsRead, search, Agent coordination
ExplorerSearch and read code, files and the web for another agent, and report what it foundRead, search, web; never writes

Decision, Lightweight helper and Coordinator have no prompt of their own; the task comes from the call and its Context. Memory, Skills and MCP start disabled. Pick a low-cost model for the helper and a strong reasoning model for the coordinator: names guarantee neither. Predicted messages are suggestions, not authorization; a planning-only request does not authorize delegated execution.

For work while you are away, always-on on

Butler is the general always-on Agent: every tool and read-write memory. Tell it what to watch or keep going; that conversation wakes when something is due, otherwise follows the check-in ladder, and reports only what is worth your attention.

Each has a prompt stating job, deliverable, what it never does, when it is done, how it works and its first task; only the tools it needs; memory on its own space. There is no fixed interval: each schedules its own wakes and follows the check-in ladder if it set none. No conversation, no wakes, no cost.

  • Producer and verifier are separate so the Agent that wrote a change never passes it.
  • Agents that handle mail or posts stop at a draft; their prompts forbid sending.
  • They cooperate by messaging each other by Agent name or conversation title: one conversation per Agent, each clearly titled; tell the planning conversation which does what.
From Python 
from openprogram import Agent
from openprogram.runtime.agent_registry import manager

helper = Agent.from_spec(manager.get("utility"))
result = helper("Extract the city from: the event is in Singapore.")

selector = Agent.from_spec(manager.get("decision"))
selected = selector.choose("Classify this message.", {"A": "Question", "B": "Statement"})
  • choose() returns the selected ID, uses the current Context and DAG, disables tools and web search and never re-asks. An invalid answer raises DecisionError. Model and reasoning are caller configuration. __call__() stays available.
  • create_builtin_agents() in openprogram.runtime.agent_registry.builtin_agents installs what was never installed, updates copies nobody has changed and leaves edited ones as they are. Assistant goes first, so it is the default on a fresh install. Server startup, setup and openprogram chat run it; registry reads never install.

Memory access

SettingMeaning
OffNo framework memory reads or writes
Read onlyReads, no extraction or new records
Read and writeThe write destination must be in the readable spaces
This AgentSeparate memory for the Agent
Shared legacy memoryThe pre-existing profile-wide store
Require memory to be availableUnavailable memory stops execution. Unset: execution continues and records the degradation.

New Agents start Off; configurations without a memory field keep legacy shared access. Background extraction and derived results preserve recorded write restrictions, so turning memory on does not ingest earlier restricted turns. Turning it off or deleting an Agent keeps stored memory. These settings do not govern file tools. The Memory page edits the shared store, not each Agent's space.

Open work

What counts as a commitment

What the Agent still owes you in a conversation after the task at hand: a reply it waits on, a promised check, an unanswered draft.

Open itemsDetail
Shown inIts instructions every turn, and the Activity panel
Changed byThe Agent, with the open_work tool. Ask it in chat to add, change or drop one, or mark one done in the panel.
Finished itemsThe latest 50 stay in history and leave the instructions

Not the task list, which plans the task at hand and ends with it. What another conversation should know belongs in memory.

Duplicate and delete

Duplicate copies the configuration under a new ID, not conversations or private memory. A self memory reference resolves to the new Agent's space; an explicit legacy shared reference stays shared. The default Agent cannot be deleted until another is made default.
