聊天 Goal

Goal 让目标在当前 agent 的普通轮次间保持有效，使用会话的工具、模型、权限和历史。没有嵌套的工作 agent。

开始与规划

输入 /goal <目标>，或使用能力 → Programs → Tools → planning → goal → Use，或直接要求 agent。Rich REPL 中 /goal 启动 canonical chat 并显示 execution ID。

环节规则
计划多步工作用 todo_create、todo_update、todo_list；简单目标不需要。新条目关联到 Goal 及其版本。每次待办变化和轮次结束时刷新进度；进度通知失败不会撤销待办。
候选agent 对照每项要求检查证据，再调用 update_goal(status="complete")。这只是提交。未完成的关联待办会阻止提交。待办全部完成也会触发验收，每个变更后的计划一次。
验收中评估原始目标和每项待办要求，只用受信任的内置检查工具，遵循常规权限。不能用 shell、写入或改 Goal；需要测试时作为证据不足退回工作 agent。
已达成需要逐项评估和证据引用。runtime 复核要求、用户控制、待办、未完成执行、未知影响和证据。暂停、编辑、取消、新指令或证据变化都会阻止过期的成功。失败的执行仍可恢复。

语义验收是独立的模型判断，不保证结果完美。完成只描述验收时的状态，不会启动持续监控。待办全部勾选不等于目标达成。

命令

命令作用
/goal读取当前状态
/goal pause保存暂停并请求取消当前执行
/goal resume用累计用量继续
/goal verify独立验收最近完成的工作，不直接标记达成
/goal edit <目标>保存新版本并暂停
/goal clear取消 Goal
/goal budget max_tokens=10000 max_elapsed_s=3600 max_cost_usd=2token、活动秒数和费用上限；0 移除上限
工具用途
create_goal、get_goal、update_goal短状态操作，不执行任务
blocked 状态同一个已验证阻碍在至少连续三个 Goal 轮次中重现，且没有其他独立工作时才能标记。runtime 强制轮次数，agent 负责确认是同一阻碍。
停止或暂停处理
预算耗尽用 /goal budget 提高或移除后恢复。等待时间不算活动时间。
执行失败或取消自动继续停止。常驻唤醒可能在一轮失败后重启 Agent 自己启动的 Goal；有人停止的那一轮不会重启。
连续两个空闲自动轮次（没有工具调用）Stalled。第一次会警告。任何工具调用或用户轮次清零，Resume 重新计数。
已暂停显示原因：轮次失败、Plan 模式、验收前提未满足、重启次数上限

Goal 没有轮次上限。徽章显示待办完成度，没有待办时省略，状态仍可见。上限可选，按累计用量计算。自动继续不扩大工具权限。

转录与详情
  • 验收轮次不渲染为回复。启动、运行、暂停和验收不增加转录卡片。Goal 结束时留一张紧凑卡片，点击打开其保存的结果、进度和用量，只读，新 Goal 开始后仍归属原 Goal。
  • 详情在刷新后保留目标、状态、用量和进度，并在用量旁显示上限，但不能编辑预算。
  • 在普通输入框补充指令，遵循其队列或转向模式。排队的消息先于下一次自动轮次，自动轮次最多等 15 秒。
  • 详情使用后端当前的操作资格。禁用的 Resume 或 Verify 说明未满足的前提。Refresh status 重试失败的读取，不丢草稿。End 总能停止 Goal 意图。未解决的操作显示标识、工具名、时间戳和状态。Inspect execution 打开那次执行，含待审批和待回答的问题。
重启与恢复
情形行为
worker 重启本身不暂停聊天 Goal：兼容的 checkpoint 按自动重启策略恢复，关闭期间完成的成功轮次保留持久的继续通知
阻止自动工作用户暂停、取消、预算耗尽和明确的重启上限。旧式可恢复暂停和缺少继续来源的 Goal 需要显式 Resume。通用外部事件唤醒仍是恢复限制。等待或未解决的执行不是完成证据。
Verify 需要已完成的工作、关联待办完成、预算可用、没有相关未解决工作。Goal 拥有的后台进程仍在运行或结果未知时阻止验收，无关资源不影响。暂停、取消、版本变化和重复请求无法绕过。
没有 owner 和活动后代的普通聊天的 Resume可关闭中断的帧并启动受限检查轮次，不重放旧工具调用。未知影响仍是未知，不声称外部操作已取消。
新准入有持久身份，准入和保存 Goal 之间崩溃不会产生重复轮次。不兼容的 checkpoint 用新聊天轮次；临时激活或凭证错误不授权这种回退。仅 provider 的中断后台 Job 保留不可变输入和资源准入。有未解决影响的子执行需要检查，不自动重放。
provider 请求中不完整的工具调用历史修复时不改写保存的记录：缺失的输出得到未知结果占位符，真实输出优先，重复输出合并，中断的文本保持标注，未配对的结果不发送但仍保存。这不证明失败，也不授权重试。
无 owner 的中断执行，结果未知下一个非检查工具结果前加一条通知，每次执行一次。不扣留、不重放。真正的内置 read、grep、glob、list 没有通知，同名自定义工具有。重启的聊天轮次同样适用。
计量
部分规则
活动时间跨重启保留已观察的工作，排除离线时间。worker 突然丢失后，最后的持久心跳是下界，最后一段显示为未知。迟到的回执不重启已暂停的计时器。明确的活动时间上限在未知段妨碍检查时阻止工作；移除上限可继续。没有默认时间或轮次上限。
聊天请求在发送前记录 Goal 身份、版本和价格。回执在暂停或编辑后仍更新原 Goal；替换 Goal 不转移费用。重复回执不重复计。已发起但无回执的请求是未知而非免费；详情同时显示已知小计和未知请求数。重启后可从账本重建，不重发请求。
旧总计与失败旧的游标总计在下一次归属请求时保留为遗留小计。计量失败显示未知。流式部分计数是累计下界；最终回执替换它。
后台 Job活动 Goal 准入的 Job 继承其身份，含后代和跨会话调用；目标会话中无关的 Goal 不计费。没有归属的 Job 保持未分配。Goal 和 Job 的预留在同一账务事务中开始和结算。缺少 token 或价格信息时保留相应预留敞口。
token 或费用上限在获取凭证和调用 provider 前预留保守敞口，统计并行请求，发送时再查。token 上限可降低输出上限。不支持的边界、未知价格或未定价层级不能绕过硬上限：Goal 暂停或报告耗尽。过期且未开始的预留不能发送；已发起的请求不会随时间变成免费。这些边界需要经过审计的 provider 适配器。
