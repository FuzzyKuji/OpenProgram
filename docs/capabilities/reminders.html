Reminders

Say it in plain words in any conversation. The reply states the exact firing time, for example "fires Fri 2026-10-23 17:00 CST (in 2.5 h)".

Asking to be reminded notifies; asking the agent to do something wakes it. Say which if it matters. To repeat work already done, with your corrections kept, save a routine.

Limits

  • Reminders run in this computer's worker. If it is down, a one-time reminder fires when it restarts. Keep it running with openprogram worker install.
  • A repeating task whose time passed less than 12 hours ago runs once when the worker restarts; an older time shows as a missed run. A task turned on or edited after that time does not run for it.
  • A task's agent run is skipped while its conversation is archived or its previous run is unfinished, including across a worker restart. Activity shows the skip. A waking reminder in an archived conversation only notifies.
  • Changing the time of a one-time task that already fired makes it fire again at the new time.
  • Focus and Do Not Disturb hold system notifications in Notification Center. The App's Notifications setting turns off its own too.
  • Only the owner, or an agent working for the owner, can set reminders, in scheduled and background turns as well as chat.
  • A scheduled agent run or command stops after 2 hours, counting time before a restart, and shows as a failed run.

Run your own command

Each firing is a reminder.fired event. A hooks entry in config.json gets it as JSON on standard input; hooks are read when the worker starts.

{"hooks": {"reminder.fired": [{"command": "python ~/bin/on_reminder.py", "timeout": 30}]}}

payload carries message, title, session_id, wake and fired_at. Event layer design
