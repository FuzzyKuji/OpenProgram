Self-update

An Agent can change OpenProgram itself: its tools, its interface, even the code that does the updating. Writing is never restricted; only going live is checked.

This page covers an installation that runs from sealed versions, under <state>/runtime. For a source checkout see Developer mode and Upgrade.

Windows is implemented but has not run on a Windows machine. A Windows trial has no OS sandbox: a temporary data directory, a separate port and a sanitized copy are its only isolation, and every Windows result says so.

How the Agent changes itself

Ask for the change in a conversation. The Agent uses one tool, self_update, not available in plan mode.

ActionEffect
begin(task)Opens a private copy of the code at work/<task> as the turn's working directory
prepare(task, goal, assertions)Hands committed work over for building, checking and switching
statusProgress and the queue. Default.
retry(update_id)Next attempt after a failure, at most three in one chain
cancel(update_id)Stops an update before the switch, or removes a queued one
versionsLists the versions kept
undo(target)Goes back

prepare needs a clean tree with commits beyond the running code; otherwise it says what is missing. A change based on an older commit is rebased.

CaseBehavior
Who switchesThe old version, from outside the worker. A new updater takes effect from the next switch.
Several requestsOne update runs at a time; others queue.

Versions

Each version is a sealed directory under versions/, and the file current says which runs. OpenProgram keeps the current version, the last good one, the one before it and recent ones. A version that ends abnormally twice on probation, or three times in ten minutes later, is replaced by the last good one, and the next start says so.

Your data

ChangeRule
Going backCode only; conversations, settings and files stay.
Schema and configAdditive only, so older versions can read your data. The trial enforces this.
Destructive migrationDeclared in its commit. Databases, conversations, memory and config.json are backed up at the switch, and the result names the backup:
 
openprogram versions restore-data <backup>
Editing a running version directly

Not refused. At the next start the launcher saves the changed files and a patch under unapplied/, restores the version, and says once how many files were set aside. The Agent can take that patch through the normal path.

Developer mode

<state>/runtime/developer.json, holding {"checkout", "python"}, runs from a source checkout: no pointer, trial or automatic return, and self_update activates nothing. Commit in the checkout and restart the worker.
