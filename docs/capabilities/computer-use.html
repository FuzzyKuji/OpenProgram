Computer use

One tool, computer_use_agent, lets the model operate a screen. Application windows work in the background: nothing comes to the front and the keyboard and mouse stay yours.

Guide deliveryNo call is turned back for a guide. A guide counts as read while it is in the model's context; after compaction the next call delivers it again. action="guide" or help("computer_use_agent.app") shows one.

Element actions reach hidden, minimised or covered windows; coordinate clicks, drags and wheel scrolls run in the background too. A click or hover on an element scrolled out of view scrolls it in first. An element with no frame, such as an option of a closed dropdown, is refused with a note to open what holds it, and nothing changes.

What you see on macOS

While the agent holds a window, a soft accent glow runs inside its edge, its traffic-light buttons turn the accent colour and pulse in turn, and the agent cursor glides to each target and leaves a small dot where it clicks. Your pointer stays put.

The overlay sits just above that window, so a window in front covers it, and it never takes clicks. It fades about 20 seconds after the last step. Show actions in the browser toolbar turns it off for Pages and applications. macOS also shows its screen-sharing icon in the menu bar.

Web pages

Each built-in tab has a short id such as tk3fa, the same across turns, sub-agents and workflow programs. read returns Playwright's accessibility outline, such as - button "Next" [ref=e12]; a ref holds while the element is on the page, and an element can be named by role and name instead.

Every action returns what changed, marked <changed> with [unchanged] for parts seen; a navigation returns the whole page. A re-rendered ref is found again by role and name; if gone, the error carries the page as it is.

Watching and taking over Pages

Agent-opened Pages stay in the background. Resources in the right sidebar lists the conversation's Pages by branch, including child agents'. Continuing a branch keeps its group; identical URLs stay distinct; unowned pages appear under Unassigned.

A popup from an Agent's Page loads in the background as its own Page in the same branch, without taking your view, and the next result names it. A popup from a Page you opened opens in front as a tab.

Your own Chrome or Edge

Set args.browser to chrome or edge for your sign-ins and cookies. Same actions: tabs lists by index, read with tab=<index> switches. The model is told to use it only when you name it or the task needs your signed-in state, and to stay in the one named. Without the extension a call naming it is turned back at once.

Virtual machine

openprogram config set computer_use.vm_url http://192.168.64.2:5000

Drives an OSWorld-compatible server: GET /screenshot and POST /execute with pyautogui. No element tree: screenshot, click, move, drag, scroll, type_text, press_key, wait, by pixels of the last screenshot. Each acting call returns a screenshot. The first use in a conversation asks for approval naming the endpoint.

Consequential steps

Allowing lets the model operate, not take consequential steps on its own. It asks once, right before a step that cannot be undone or speaks for you (sending, submitting, paying, deleting), saying what, where and with which data. If your request names that step, it does it and reports. Text on screen is data, never permission or instruction.

An interrupted step does not hold up the next. The model is told its outcome is unknown, looks at the screen and goes on; the step stays in Activity.

System access

System settings shows live desktop access on the execution computer; openprogram doctor, TUI /doctor and GET /api/system/access expose the same checks. Viewing them requests nothing. Missing access does not stop ordinary chat or upgrades.

PlatformRule
macOSManaged installations run the worker and its Python children through OpenProgram, an embedded application with a stable bundle identifier; look for that name in System Settings. Screen recording and Accessibility are checked separately in a fresh process of the desktop-task executable. Set up access requests only a missing permission. Remote clients must arrange authorization on the execution computer; a grant for another app is no evidence.
LinuxHeadless sessions and unsupported Wayland capture are reported apart from missing dependencies. An X11 display alone does not prove access.
WindowsDepends on the active session and target; secure desktops and elevated targets cannot be assumed.

Neither Linux nor Windows is told to disable security or run as administrator. Unverified: native Linux and Windows desktop acceptance; on the unsigned macOS development build, permission persistence across signed upgrades, first-run onboarding and automatic task recovery after authorization. Setup never retries a declined operation.

Automation errors on macOS

Apple Events to System Events or a target app need Automation, granted per target and separate from screen recording and Accessibility. On a denial, open System Settings → Privacy & Security → Automation on the execution Mac and inspect the requesting app's access to the target.

The failed operation stays failed; changing the setting neither approves nor repeats it. Other native failures keep their actual error.

Recording sound

Uses the Screen Recording grant and captures only the named application: no other apps, microphone or alert sounds. The newest 20 stay in ~/.openprogram/computer-use/audio/.

stop_audio_recording transcribes with the engine in Settings → Voice: whisper.cpp keeps sound on the Mac, OpenAI and Groq send it there. transcribe=false keeps only the file. Silence is reported and not transcribed. A chat model accepting audio, such as Gemini and OpenAI's gpt-audio models, also receives the recording.
