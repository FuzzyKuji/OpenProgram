查看和编辑 Memory

打开 History → Memory，选择主题。文档和 Core 来源记录在预览中打开，Edit 修改 Markdown。没有保存按钮。

项目行为
保存每次编辑进入此浏览器的草稿存储，并排队写入文件。写入串行，较早的响应不会覆盖更新的输入。
撤销Cmd+Z 或 Ctrl+Z。重做：Cmd+Shift+Z、Ctrl+Shift+Z 或 Ctrl+Y。App 保持打开时，自动保存不清除撤销历史。
冲突或拒绝草稿保留并显示错误。Review latest 在 History 中比较已保存文本和草稿；Replace latest with this draft 基于该版本重试。再次发生并发修改仍会被拒绝。

未通过检查的写入既不改文件，也不改历史。

History 从新到旧列出版本并显示本地时间，选中查看增删行。Restore this version 先记录当前状态，再把恢复作为新提交，因此可以反悔。恢复保留有效的来源引用，并拒绝破坏其他 Memory 文档的链接。

问题自动修复
写入模型不可用（登录被拒、套餐无权限、模型不存在、额度用尽）切换到默认 agent 的模型，再到最近使用的模型
编辑未通过格式检查退回就地修复最多三次，然后整轮重做一次
你或别的工具写的 Topic 文件按原样记住：能被搜到，也能被召回，标“added by person”或“outside file”代替来源。记忆从不改写别的工具写的文件；不是文本的文件在记忆页列一次，其余记忆照常
手写引用一条消息段落末尾加脚注，来源写 [关键词](/s/<会话>#<消息>)：会话 ID 在复制链接得到的链接末尾（只保留 /s/… 部分），消息 ID 是在上下文图里选中这条消息的节点后复制 ID 得到的内容。关闭记忆的对话不能引用。

格式检查

每个 Topic 段落以脚注结束，引用来源聊天消息：[keyword](/s/<session>#<message>)。Memory 不保存对话副本。

脚注结果
实质段落缺少脚注写入前报 INVALID_TOPIC_FORMAT；被拒绝的批次什么都不提交
新引用的消息在聊天中不存在，或不是人或助手的话（如工具结果）同上
定义重复，或段落移动、删除后遗留删除，不拒绝

后台写入在每改一个文件后运行同样的检查，并在本轮结束前修好。

点击脚注显示该消息及前后轮次，打开原会话跳转过去。会话已删除时显示 Original session deleted，记忆保留。归档隐藏会话，保留内容和链接，不会按时间或容量自动删除。
