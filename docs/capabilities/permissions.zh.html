工具权限

默认情况下，你发起的工作里每个格式正确的工具调用都直接执行，有人看着与否都一样。

项目说明
选择Web、App：输入框底部。终端：/permissions；Shift+Tab 按此顺序循环四个模式。
生效顺序当前分支自己的模式，其次项目默认模式（项目设置），最后 Bypass permissions。每一轮都用它，有人看着与否都一样。
Bypass permissions存储值是 bypass，--permission 和项目设置文件写的就是这个词。不覆盖显式 deny 或 ask 规则、暂存的消息、插件限制和身份限制。
Auto审查无法进行时拒绝该调用。
Manual首次操作某个应用时询问，可以在本对话内允许。
Plan会改动内容的工具同时对模型隐藏，允许和询问规则也放不过去。批准 exit_plan_mode 后回到之前选择的模式。
接受编辑旧模式。保存为它的对话继续使用，只在它是当前模式时作为第五行出现。

一次调用如何判定

  1. 谁在说话。 除所有者之外的人不论什么模式都受限。对你本人永远不触发。
  2. 你的规则。 默认为空。全局、项目和对话规则合并，deny 优先于 ask，再优先于 allow。deny 在所有模式下生效。Plan 的检查在 deny 之后、ask 和 allow 之前。
  3. 模式。

调用需要询问却没有人能回答时（定时任务、子 Agent、常驻轮次）会被拒绝，拒绝信息写明怎么放行。只有 Manual、Plan、Auto 回退或 ask 规则才会这样。

外部 MCP 客户端只能用 MCP 服务器暴露的工具

审批与提问

控件行为
工具审批卡片只显示当前操作，没有变更历史。同意和拒绝点击即提交。
拒绝并说明“拒绝”旁的说明按钮；按 Ctrl+Enter 发送。模型收到你的说明并照做。
拒绝任务继续：拒绝作为该工具的结果，操作不执行，模型被要求停下来问你。
提问卡片每个问题在控件上方。多问题和表单字段一起用提交回答提交，答案继续对应问题显示。跳过会告诉模型该问题没有回答。
先讨论写的话代替回答交给模型，模型在同一轮回应，卡片保留你写的内容。
主输入框仍用于普通消息。
允许此对话规则只保存到当前会话。目前 computer_use_agent 提供；规则按应用、虚拟机或你的浏览器命名，覆盖在里面做的一切，包括页面脚本。
始终允许提供时，把支持的确切操作规则保存到当前项目。只允许单次的请求不提供持久授权。
投递、等待和文件新鲜度
  • 服务端确认后才关闭；未确认时可重试同一答复。卡片显示已提交的答案、提交进度以及确认或重试状态。确认回执保留至刷新，待回答的请求重连后恢复。审批确认后卡片移除，工具行显示结果。
  • 人工审批默认没有时间限制。等待时保存进度并释放当前执行实例，重新打开 App 后恢复请求。
  • 恢复使用本轮保存的上下文，之后的记忆或日期更新不会使审批失效。工具、权限和工作目录仍重新检查。无法恢复时，对话说明操作没有运行。取消任务撤销审批。已过期的旧请求不会重新生效。
  • edit、write、apply_patch 记录审批时的文件状态，在执行前和写入前检查。已删除的文件不重建，内容变化时要先重新读取。任意命令不声明目标，所以这项检查不覆盖其副作用。
  • 同意和拒绝只答复当前请求，不创建项目规则。

任务运行中修改权限

修改对运行中的任务直接生效，无需停止；后端确认 Bypass permissions 后，同一条回复里的后续工具不再询问。

实时修改影响什么
  • 界面已知确认版本时立即发送，确认后才显示为有效。模型正在推理、输出或生成参数时同样生效。
  • 新模式进入后续模型请求，已在生成的文字不改写。已授权的工具保留授权。切到Plan阻止尚未获准的写入。
  • 不再需要的普通审批通过 execution 的持久等待自动处理，任务继续。显式 ask、提问、表单和 Sandbox 升级不因切换模式而回答。重复回答、取消、超时和恢复不会重复执行已完成的调用。
  • 只影响当前分支。显示该分支的其他窗口接收已确认的模式，分支或版本已过期的修改被拒绝。失败或断线的修改保持未确认：重新连接、检查模式后再试。未发送的草稿把模式存在本地，随首条消息发送。
工作使用的模式
认证 owner Agent 创建的子 Agent创建时继承父 Agent 有效的模式和显式规则，Manual 一路贯彻。保留自己的身份和非交互限制；显式 ask 仍阻止需要审批者的操作。之后的修改不改写已接纳的子 Agent。
没有父轮次的 owner 工作默认模式
定时任务所在对话的模式和 Sandbox 设置，以触发时为准。需要询问的调用被拒绝，所以要它自己完成就用 Bypass permissions 或允许规则。
绑定的聊天联系人、群里有完全访问的人聊天会话自己的模式和规则；审批发到聊天里，用 /answer 回答。聊天渠道

项目规则

History → Projects → 项目 → Settings → Permission Rules 里有拒绝、询问、允许三个列表。添加 ToolName 或 ToolName(pattern)；删除即撤销；修改就是先删后加。列表为空时，会话和全局规则仍可能生效。

保存与生效时机
  • 收到匹配当前项目的服务端确认后才清空输入。失败或未确认时保留输入并显示状态。成功后同步到该项目其他打开的视图。
  • 经认证的交互式 owner 会话在下一次操作时读取最新规则，包括运行中的修改。已获准的操作保留授权；审批等待仍需答复；已接纳的子 Agent 保留原策略。
  • 删除规则影响后续授权，不改变已执行的操作。
  • Windows 路径用正斜杠可避免转义歧义，如 read(C:/Users/me/project/**)。盘符路径里的普通反斜杠会保留。规则语法用 \\、\(、\) 转义自身字符。JSON 配置还要遵守 JSON 的反斜杠转义。
  • 同一个文件不管怎么写，路径规则都能匹配：正反斜杠、短文件名、指向该文件夹的链接。拒绝和询问规则不分大小写，也能匹配从工作目录出发的相对路径；允许规则按完整路径和磁盘上保存的大小写比较。网络共享写成 //server/share/**，或者粘贴时全程用反斜杠。
  • 命令在 PowerShell 里运行时，含 {、} 或 , 的命令只按原文精确匹配允许规则，也就是始终允许保存的那条。拒绝和询问规则照常读取。

拒绝信息

[blocked by <layer>] <what> did not run: <why>. To change this: <change>.
部分含义
<layer>identity、rule、mode、sandbox、hook 或 setting
工具结果还带 denied、reason_code、layer、rule、mode，outcome 为 not_started
AUTHORITY_TIER_MISSING请求缺少认证权限级别，Bypass permissions 解决不了。旧的已接纳执行要通过认证界面重新提交；新的聊天提交带身份。

缺参数或参数格式不对不算拒绝，作为普通工具错误返回给模型。

Sandbox

默认关闭，在输入框 Plus 菜单里按分支打开。修改影响后续轮次。

设置或情况效果
sandbox.modeauto：后端可用的地方都打开。workspace-write：强制使用。
网络sandbox.network 打开才有
写入只能写工作区；没有项目文件夹时工作区是 home 目录
始终只读shell 启动文件、.git/hooks、.git/config、编辑器任务目录、OpenProgram 状态目录；所以 ~/.zshrc、~/.ssh 和登录项碰不到

允许在沙箱外运行一次，凭证过滤仍有效

运行后被拦（包括域名解析失败）说明返回给 Agent，让它这样申请，而不是重试

将沙箱命令限制到公网域名

macOS：sandbox.network 设为 true，sandbox.network_domains 设为映射。

{"example.com":"allow","*.example.org":"allow","blocked.example.org":"deny"}
  • 精确域名和 *.example.org（任意深度子域，不含根域）。deny 优先。空映射拒绝全部，null 保留原网络开关。
  • 私有、本地、组播和保留 IP 始终拒绝，即使域名被允许。检查全部 DNS 答案，并直接连接已检查的地址。
  • 每条命令用带认证的本地代理，沙箱阻止直连，包括忽略代理设置的客户端。支持 80 端口 HTTP 和 443 端口 HTTPS CONNECT；客户端需支持常规 HTTP 代理设置。
  • 规则授权目标，不检查加密 HTTPS 的方法或内容。不支持 TLS 拦截、SOCKS/UDP、任意端口、本地网络或上游代理串联。不支持 chunked HTTP 上传和明文 HTTP Upgrade；HTTPS 隧道承载 HTTPS 和 WSS。
  • 命令结束或取消时关闭代理和连接。
  • Linux、Windows/WSL 拒绝已配置的域名策略，不会改成无限制。沙箱不可用时也拒绝，即使不可用策略是 warn。关闭 Sandbox 就关闭其限制。
  • 只作用于沙箱命令，不限制宿主的模型请求或其他工具传输。

Auto 审查

规则值
输入完整操作，包括 Shell 命令，上限 64 KiB。超限或分类器不可用时拒绝，不依据截断内容批准。
超时每个候选模型 30 秒
失效参数或实时权限策略变化。显式 deny 仍优先。
反复风险拒绝连续 3 次或累计 20 次，向认证的交互式 owner 提供对该确切操作的审批：只限一次，绑定原参数、工作目录、权限版本和文件状态。deny 规则和硬性限制仍有效。
计数按会话和权限版本。允许或批准重置连续次数；累计阈值后的批准也重置累计。分类器故障、无效回复和取消不计。持久身份避免恢复后重复计数，并发更新用执行数据库事务。
非交互任务收到拒绝，可继续其他允许的工作
失败上限风险拒绝不计入重复执行失败上限。宿主记录的结果在检查点恢复后保留。

中断的操作

控件或情况行为
停止中断等待中的模型和异步工具。执行程序退出后轮次结束，即使外部结果未知；未知结果留在 Activity。
暂停等当前操作到达可恢复的位置，并显示待处理的请求
新 owner 轮次，Bypass permissions 或 Auto不继承中断轮次的审批要求。旧结果保留为未知，不重放。显式 deny、ask 仍生效。
之前某步结果未知第一个非核查类工具结果的开头点名那一步，每次执行一次。不拦截，由模型决定核对什么。
恢复同一执行仍需核对结果或批准确切操作
屏幕步骤中断的 computer_use_agent 步骤告诉 agent 结果未知，它看一眼再继续，步骤留在 Activity。没到达应用就停下的（元素隐藏或消失）算未开始。

这些都不改变 macOS 权限，也不会让只读卷变成可写。

系统权限

macOS 权限和模式无关，模式不能授予它们。一个注册表包含屏幕录制、辅助功能、自动化、日历、提醒事项、文件读写、麦克风和摄像头。设置页、CLI/TUI doctor、GUI 前置检查、持久的系统权限等待和 HTTP 接口都读它。每行记录状态、被检查的身份、需要它的操作、平台能否申请。

状态含义
granted当前具名执行程序刚检查通过
not_granted确认缺少
unknown主机无法确认；不算拒绝
unavailable原生依赖缺失；不算拒绝
unsupported当前后端没有实现
操作效果
GET /api/system/access只做不弹窗的检查
设置 → 系统权限分组显示。初始化全部 OpenProgram 权限是首次设置的统一入口，返回一份报告；请求授权和打开系统设置按行使用。都要本机用户点击。
绝不弹窗重连、轮询、历史回放、模型输出、启动检查、普通重试
缺少权限只暂停声明它的操作；浏览器、虚拟机、无桌面和普通聊天不受影响
macOS 在更新后再次询问权限
  • App 和具名后台是签名应用，macOS 可能分别记录。同名条目（python3、node、缓存应用）不说明什么：已安装产品都通过签名 runtime bundle ai.openprogram.runtime 检查和申请，外层 App 不是第二个执行身份。
  • 自动化按目标应用，文件访问按所选路径。日历、提醒事项、麦克风、摄像头可能各需确认。未指定的应用或路径不能预先授权。
  • App 刷新、本地打包和对话自更新复用 ~/Library/Application Support/OpenProgram/local-signing 里的私有身份。清理时保留，其中是签名钥匙串。缺失或损坏时构建停止，不创建替代身份。
  • 首次从旧临时签名迁移可能要重新确认；旧开关可能显示开启但系统拒绝新签名。用请求授权。辅助功能和之前被拒绝的权限可能要去系统设置。
  • 记录的授权属于旧的已验证身份时，显式设置对这一项更新一次。启动和普通检查绝不重置 TCC、接受弹窗或修改其他应用。
  • 本地签名只用于本机开发构建；公开发布需要 Developer ID 签名和公证。
