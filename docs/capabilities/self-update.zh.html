自我更新

Agent 可以修改 OpenProgram 自身：工具、界面，甚至负责更新的代码。写改动不受限制，受检查的只是上线。

本页说的是从封存版本运行的安装方式，位于 <state>/runtime。源码 checkout 见开发者模式和升级。

Windows 已实现，但还没有在 Windows 机器上跑过。Windows 试运行没有操作系统沙箱，临时数据目录、独立端口和净化过的副本是仅有的隔离，每一份 Windows 结果都会说明。

Agent 如何修改自己

在对话里提出要改什么。Agent 使用一个工具 self_update，计划模式下不可用。

动作作用
begin(task)在 work/<task> 打开一份私有代码副本，作为本轮的工作目录
prepare(task, goal, assertions)把已提交的工作交出去构建、检查和切换
status进度和队列，默认动作
retry(update_id)失败后开始下一次尝试，一条链最多三次
cancel(update_id)在切换前停止更新，或移除排队中的请求
versions列出保留的版本
undo(target)回退

prepare 要求工作区干净，并且有运行中代码之外的提交，否则会说明缺什么。基于较旧提交的改动会自动 rebase。

prepare 之后

阶段做什么失败时
building从提交构建一个封存版本停止，worktree 保留
trial在你的数据副本上、用独立端口、不带凭据并用假模型运行，由独立的验收者检查断言。停止，线上没有改动
ready运行中的代码变了就 rebase 后重试，最多三次停止并列出冲突的文件
quiescing最多等 10 分钟的空闲时刻，然后给运行中的任务做检查点，30 分钟后放弃。停止，没有关闭任何东西
activating停止 worker，移动 current 指针，启动新版本回退
verifying探测，跑一轮真实的 Agent 对话，观察 120 秒回退
切换期间和之后
情况行为
谁来切换旧版本，在 worker 之外。新的更新器从下一次切换起生效。
多个请求同一时间只运行一个更新，其余排队。
切换期间的消息消息、定时任务和常驻唤醒被保存，显示 "Switching versions; this runs as soon as that finishes."，切换后立刻在起来的版本上运行。
新版本失败对话里说明原因，并启动只读诊断。
旧版本起不来以 needs_manual_recovery 结束，原因写在 <state>/runtime/recovery.log。

撤销

目标效果
仍保留的版本 id试运行该版本并切换过去，之后的提交会保存。
单个提交只还原这一个提交，走正常流程。有冲突时撤销停止并列出文件。
终端不经试运行，运行中的版本坏了也能用：
 
openprogram versions list
openprogram versions use <id>

版本

每个版本是 versions/ 下一个封存的目录，文件 current 说明运行哪个。OpenProgram 保留当前版本、上一个好版本、再前一个，以及最近的若干版本。一个版本在观察期内异常退出两次，或之后十分钟内异常退出三次，就换回上一个好版本，下次启动时会说明。

你的数据

改动规则
回退只改代码，对话、设置和文件不变。
数据结构和配置只能增量，旧版本才能读你的数据，试运行会强制检查。
破坏性迁移必须在提交里声明。切换时备份数据库、对话、记忆和 config.json，结果里写明备份位置：
 
openprogram versions restore-data <backup>
直接修改运行中的版本

不会被拒绝。下次启动时 launcher 把改过的文件和补丁存到 unapplied/，恢复版本，并告诉你一次有多少文件被放到一边。Agent 可以把这个补丁带进任务，走正常流程。

开发者模式

<state>/runtime/developer.json 写入 {"checkout", "python"} 后从源码 checkout 运行：没有指针、试运行和自动回退，self_update 不激活任何东西。在 checkout 里提交，然后重启 worker。
