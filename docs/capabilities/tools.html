Publish a generated document from the model
  • write(file_path="/absolute/final.docx", source_path="/absolute/staged.docx") publishes a separate temporary result, for Word, PowerPoint, PDF, images and other binaries. source_path and content are mutually exclusive; the source is a regular local file of at most 64 MiB. Existing targets must be read first; binary reads return metadata and set the same freshness check.
  • Records complete before/after bytes in the turn's file history, surviving reopen and restart. Undo and reapply refuse to overwrite conflicting later changes. New files can be undone. No Git repository needed. Local generators use this same interface.
  • A failed later history commit keeps the previously published version. An interrupted write is reported as unconfirmed and blocks exact recovery. Corrupt history blocks further recorded writes rather than being replaced. After a failed first attempt, reread before retrying. Versions follow the turn's retention.
  • Binary versions keep formatting and media; Review does not compare layout or show Word tracked changes. Shell commands overwriting the final file are not recorded, and unrecorded versions cannot be rebuilt from a card or output: write a separate result and publish it.
Manual edits and history
  • Project-file edits keep before/after bytes independently of conversations. Each successful write publishes at once. Changes from one editor group for at most five minutes; closing the group or an intervening outside change starts another version.
  • History lists retained versions and restores a selected one, creating a new entry after checking the current revision.
  • A failed save or an outside change keeps the draft for retry, export or explicit discard. Closing waits for pending changes; a failed save keeps the tab open.
  • History combines manual edits and confirmed model changes for the project-relative file. Model entries read retained bytes from the original session checkpoint, without a second archive. Restoring changes only this file.
  • Archived sessions keep their file history; permanent deletion makes their model versions unavailable; manual history is independent.
  • Older history indexes in bounded batches: Continue loading history. Incomplete or unverifiable history is labeled. Legacy paths appear only when project ownership can be established.
  • History follows the project when it moves and stays readable while its disk is disconnected; writing and restoring need an available location.
  • The document API accepts bounded binary content up to 64 MiB, which does not itself provide an editor for every format.
  • PDF, PSD and TIFF decoders accept at most 64 MiB, bound the rendered size, are local and load only when that format opens. Previewing a history version uses its retained bytes.
Office editing (ONLYOFFICE)
  • Built-in application office_editor, an optional local install shared by all Office formats; not in the default App or runtime. Disabled on Applications: the file offers only its download and nothing installs.
  • Without the component, Install or Cancel; nothing downloads until you choose. About 699 MiB, with resources, fonts, licenses and source materials. Files process locally.
  • The pinned archive and all resources are verified before a complete version is selected. Failures can retry and existing installs remain. On success the document opens without restarting. Cancel leaves the download, and Installation options lets you choose again.
  • Unavailable through remote application access. PDF viewing does not need it.
  • A centered status shows preparation and opening. Closing during startup cancels; a failure offers Retry.
  • Editing starts once the native editor is writable; autosaves. Tabs, split layouts and History keep the editor and its undo history. Closing waits for pending input; a failed write keeps the document for retry.
  • History previews are read-only and restoring creates a new version. No semantic Office redlines. The download stays when the editor cannot load.
Image editing limits

At most 64 MiB, 16 million pixels and 16,384 pixels per side. Changes save through the document history controller; Preview, History, tabs and routes keep undo and redo. Failed publication keeps the draft; closing waits for export. Exports rendered pixels, so embedded metadata may not survive.

Limits, notices and approval
  • Typing needs bash(..., tty=true) (pseudo-terminal, local backend on macOS or Linux). Without it stdin is closed, so a command waiting for input ends, and only the interrupt is accepted.
  • A call keeps up to 1 MiB of output: first and last halves when longer.
  • A background command ending unseen sends the conversation a notice turn with command, exit code and last output, after any running turn. A command you stop sends none.
  • Listed as Background terminal under Terminal in Resources, where you can watch and stop them, and in Activity. Record and output are deleted a day after it ends or its status became unknown.
  • At most 64 per conversation. Another stops the least recently used, never one of the eight most recent, and the result names it. Cancelling a turn stops a command in its first wait; background ones keep running.
  • Polling and interrupting are never asked about. Typing follows the permission mode, like bash.

workdir

Each bash call is a new shell: bash(command="npm test", workdir="apps/web"). A cd or export does not carry over. It does not change the worktree binding or the file tools' base, and it is not the Desktop terminal (that is terminal_use).

Path rules
  • Relative paths resolve from the bound worktree, or the host process directory when none. Absolute paths work. Literal: no ~, variables or expressions. Omit it for the existing default.
  • Missing, non-directory or denied directories fail without running; none is created and nothing falls back.
  • Selecting a directory grants nothing. Under a local sandbox policy it must satisfy the workspace's policy, including symlinks and extra authorized roots, and execution stays in that boundary. An unavailable configured sandbox is not bypassed.
  • SSH and Docker read it as a POSIX path on the backend. Relative remote paths need an absolute POSIX worktree binding. A guarded change prevents the command list from running if the directory is unavailable; Docker does not create it via -w. With a host sandbox policy, explicit remote workdirs are refused until backend-native authorization exists.
  • Results include the local starting cwd, or requested_cwd for remote paths. Not an ending directory or persistent state.
  • Tool-call notation; the Python export is an AgentTool, not a shell function.

The Web Search switch and backend selection
  • Per message. Providers with their own search (ChatGPT subscription, OpenAI Responses API, Anthropic) search through the provider: one "Searched the web" step per search with sources, a sources row on the answer, and no local web_search.
  • Other providers, Gemini included (its grounding cannot combine with function tools), get the local tool.
  • Off excludes both, even in automatic tool mode. On makes the schema available immediately, including when Tools is off, and still respects disabled tools and permissions. Tool profiles belong to each conversation and survive tab changes and refreshes.
  • Keys apply to the next call without restart. An unavailable saved default falls back; a named unavailable provider gives the reason and lists usable ones.
  • An unpinned search tries the saved default, then every other available web backend (arXiv only when named). When all fail with no key configured, the error points to Settings > Search.
  • DuckDuckGo reads its no-JavaScript page and returns about ten first-page hits; a bot challenge or unreadable page is an error, not an empty search.
  • combine="race" returns the first nonempty success; unrunnable providers are skipped, and if none runs the error lists each reason. combine="rrf" keeps results completed before the deadline. Total failure is an error, distinct from an empty search. Running requests finish under their transport timeouts.

The four domains: agent collaboration.

When a background agent finishes
  • The sender gets a notice turn marked automated, after any running turn; every agent finished meanwhile arrives in the same notice.
  • None if already read with job_output (which also waits for a send_message reply by delivery_id), handed back by notify_when_idle, or cancelled.
  • The notice carries the task and final reply, not the transcript; use read_conversation for the steps.
  • A message to a busy agent queues until it is free.
  • job_output works when the collaboration message allowance is exhausted and does not consume it. New deliveries still obey limits.
  • Cancel through execution controls: API execution.command with action="execution.cancel" and the current version. There is no job_stop.
