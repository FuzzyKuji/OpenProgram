工具调用

“选择”就是 Provider 消息里 ToolCall 与文本的区别；框架只解析并分支。循环：openprogram/runtime/agent/loop/loop.py 的 _run_loop。

入口

runtime.exec(content, tools=..., tool_choice=..., max_iterations=...)
参数作用
tools菜单：Agent 方法、{"spec":..., "execute":...} 字典，或带 .spec 和 .execute 的对象
toolset它和 tools 都不传：完整注册表，即默认开启工具。toolset="none" 或 tools=[]：只输出文本。工具体内嵌套的 exec 继承外层 tools= 列表（_current_tools contextvar）。
tools_source、tools_allow、tools_deny裁剪菜单
tool_choice"auto"（默认）、"required"、"none" 或 {"type": "function", "name": "X"}。由 Provider 映射（OpenAI、Anthropic、Gemini、Bedrock）。
parallel_tool_calls=False在支持的 Provider 上每轮只选一个
max_iterations轮数上限，实际为 max(1, max_iterations)。runtime.exec 默认 20；聊天回合没有上限。
choices强制的结构化收尾：下一步决策

执行所选函数

情况结果
找不到工具is_error 结果
validate_tool_arguments 失败is_error 结果
tool.execute 抛异常异常文本作为 is_error 结果
成功ToolResultMessage

错误返回给模型让它自行修正，不会中断循环。一轮内的多个选择由 _execute_tool_calls 依次执行。期间排队的用户消息等这一轮调用执行完，再进入下一次模型决策。

终止条件

条件结束方式
只有文本正常结束，文本即结果
stop_reason 为 error 或 aborted立即以错误或取消结束
轮数超过上限仅在设置了上限时
文本之后什么还会让循环继续

内层 while 也看 pending_messages，排队的用户消息会在纯文本回复后继续循环。退出后，get_follow_up_messages 可提供消息开启新一轮；否则运行结束并推送 AgentEventAgentEnd。

放进 tools 的 Agent 方法就是一个可选函数。若其函数体再调用 runtime.exec，会打开同一循环的新一层。
