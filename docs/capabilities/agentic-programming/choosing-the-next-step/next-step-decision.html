The model picks a function: it runs with parsed and injected arguments and its return value comes back. The model picks a value: that value comes back. The decision is the branch; there is no if.

Work first, decide last

from openprogram import Agent, agent

class ExampleAgent(Agent):
    method_options = {'handle_ticket': {'tool': True}}

    def handle_ticket(self, ticket: str) -> dict:
        """Read the ticket, look things up, then decide which flow to route to."""
        return agent(
            f"Handle this ticket: {ticket}",
            toolset="default",          # before: research with tools, run commands
            choices={                   # closing: the return must be one of these
                "refund":    issue_refund,
                "escalate":  escalate_to_human,
                "close":     {"status": "closed"},
            },
        )

Dict form: {name: handler}. List form: a callable, (callable, "description"), "name", ("name", "description") or ("name", "description", schema); a function's name is its __name__.

Tuples are reserved in handler position: a literal 2-tuple value is misread as (value, "description"). To always return one structure, use a single-option decision.make or exec(response_format=...).

Internal steps
  1. render_options emits each option's signature name(param: type, ...), description, per-parameter detail with options, and a one-line Call: JSON example with native placeholders (0, false, [], {}, "<str>") and nested shape. Only source="llm" parameters show.
  2. Model call. decision.make sends runtime.exec(prompt + menu); exec(choices=) splices the menu into its turn.
  3. parse_args checks the reply as in the table below and returns (chosen, kwargs): the function, or the name string.
  4. Retry on _ParseError: the previous reply, the reason and the re-rendered menu go back through runtime.exec, recorded in the DAG like any model call. When exhausted: DecisionError, with the last error kind, message and head of the reply. It subclasses ValueError; there is no built-in fallback.
  5. resolve_decision runs chosen(**kwargs), or looks up the value; a value option with a schema returns {"decision": name, **kwargs}.
