docstring 只保留摘要，不写 Args: 或 Returns:。下游需要的字段含义用 TypedDict 或 dataclass 返回类型表达。

默认值

方面默认
expose普通方法 "full"；显式工具 "io"（名称、输入、输出，内部 llm() 调用隐藏）
render_range.callersNone：本帧之前的节点不限。0 隔绝全部先前上下文。N：最近 N 个。
render_range.subcalls-1：本帧看到自己的全部进展。子调用内部由子调用的 expose 隐藏。N 用于限制长循环的提示词大小；0 隔绝本帧节点。
顶层聊天回合frame_entry_seq=-1：所有节点都在帧内，与其他帧同一路径
工具裸 runtime.exec：完整注册表。tools=[...]：指定菜单。toolset="none" 或 tools=[]：无工具。嵌套 exec 继承（_current_tools）。

docstring 与提示词

docstringllm(prompt)
范围整个函数一次模型调用；一个函数可有多次
读者人、决策菜单、工具 spec、元工具。作为 metadata.doc 携带，并渲染为描述性上下文。模型，作为权威指令
必须包含直接说明的一句话摘要，可写更多细节。不写“You are a helpful assistant”之类的套话，不角色扮演，不用比喻。指令、数据和确切的输出格式，即使 docstring 已写过
 
llm([{"type": "text", "text": (
    f"Classify the sentiment of the following text. Reply with exactly one "
    f"word: positive, negative, or neutral.\n\nText:\n{text}"
)}])

每项是字典，如 {"type": "text", "text": ...} 或 {"type": "image", "path": ...}。默认系统提示词来自环境运行时和 skills 块，不来自 docstring。

工具 spec 的描述回退顺序：description，然后 placeholder（写成“e.g. …”），最后只有名称和类型。render_options 只读 description 和 options。两者都不读 docstring 的 Args:，旧式 Args: 能运行，但在这里不起作用。

普通可调用对象

render_options、decision.make 和 choices= 接受。runtime.exec(tools=[...]) 只接受 Agent 方法、{"spec", "execute"} 字典或带 .spec 和 .execute 的对象，否则抛 TypeError。

工具注册和门控选项

name、description、toolset、unsafe_in、requires_approval、check_fn、available_if、defer：见函数调用设计。cache 和 cache_ttl 按名称和参数缓存。timeout 在 N 秒后停止函数体并返回错误结果。

尚不存在的字段

effects、permissions、idempotent、latency_hint 和 cost_hint 未实现：还没有使用方。门控已有上面的选项。
