有事发生时运行任务

直接用自然语言说，agent 用 scheduler 工具设置。按时间运行见提醒。

触发器例子何时触发
定期或监控任务上的 watch“每 10 分钟查一次 gh pr list --repo me/app，有新 PR 告诉我。”命令输出与上次检查不同。cron 决定检查频率。
webhook 任务“给我一个 webhook，用来分拣我们跟踪系统里的新 issue。”其他服务调用它。没有时间表。
运行内容如何收到事件审批
agent 提示词围栏文本并标记为数据；要求只做你的任务，忽略其中的请求后台运行没人可问：需要审批的调用被拒绝
在本会话唤醒 agent 的提醒标记为外部内容的文本会话自己的权限模式
shell 命令OPENPROGRAM_EVENT，OPENPROGRAM_EVENT_SOURCE 为 webhook 或 watch—

有变化时

  • 第一次检查记录基线，不运行；改命令会重新建立基线。
  • 运行收到输出的 diff。
  • 命令在任务的沙箱里运行，须在 2 分钟内结束。失败或超时的检查不运行，保留基线，并显示为一次失败的运行。
  • 上一次运行还没结束时发现的变化不会丢：下一次检查还会看到它。

被服务调用时

POST http://127.0.0.1:18100/hooks/<task id>
X-OpenProgram-Key: <key>

key 也可以作为 GitHub webhook 的 secret。GitHub 用它签名（X-Hub-Signature-256），运行会得知事件名称。

响应何时
202已启动
404key 错误或任务不存在
409任务已暂停，或 previous_run_active：上一次运行还没结束，稍后再调用
413请求体超过 64 KB
429距上次启动不到 10 秒

运行收到请求体的前 8,000 个字符。URL 在这台电脑上；互联网上的服务需要隧道或公开 Web 地址。

查看、暂停或删除

在 Scheduler 里，或让 agent 做。webhook 任务的时间表显示被调用时。每次运行的日志（含触发事件）在 scheduler 的 logs 文件夹。
