Local models

OpenProgram connects to a server you run. Downloads, GPU allocation and server lifecycle stay with that server.

Local OpenAI-compatible serverhttp://localhost:8000/v1
  1. Start the server and load a model with its own tools.
  2. Enable the provider and save its API Base URL.
  3. Click Fetch models and enable one.
  4. Select it in the chat composer.

localhost is the machine running the worker; for a remote worker, use an address reachable from it. A host and port alone get /v1; an explicit path is kept. Saving a new URL changes later discovery and inference for already enabled models.

SituationWhat to do or expect
Server requires a keyAdd it in the provider account panel. Without one, discovery, checks and inference omit Authorization; a cloud OpenAI key is never sent.
Several serversAdd custom provider: name, URL, Local server (API key optional). Ordinary custom cloud providers keep their credential requirements.
Check the serverConnectivity: a model listing confirms the endpoint; testing a named model also checks inference. Unavailable server, rejected key or invalid response report as failures.
No discoveryAdd model by id, with the exact identifier. It also updates an existing model's limits.
Token limitsEnter limits matching the deployment and its configured context size. Unknown limits default to 4,096 context and 1,024 output. A model's advertised training context does not count.

Local models use OpenAI Chat Completions, on the same streaming, cancellation and tool-call transport as other compatible providers. Tools, images, reasoning and strict JSON depend on the model and server. Enablement and limits persist in the standard configuration.
