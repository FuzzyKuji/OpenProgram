Worker overview

Control

Running openprogram starts a background worker if none is up. OPENPROGRAM_NO_AUTO_WORKER=1 makes the terminal UI only connect to an existing one.

CommandEffect
openprogram worker startStart in the background and return
openprogram worker runForeground, for debugging; Ctrl-C stops
openprogram worker status, openprogram statusRunning or not, PID, port, uptime; the top-level form also shows the log path and whether a service is installed
openprogram worker stop, openprogram stopStop. An installed service stays stopped until the next start or login
openprogram worker restart, openprogram restartStop and start fresh, after code or config changes
openprogram webStart in this terminal and open http://localhost:18100
 
$ openprogram status
openprogram: running (PID 82472, port 18100, up 48m)
  logs: ~/.openprogram/worker.log

Prefixes match: logs tail ink. Past 16 MB the worker log rotates at startup to worker.log.1, up to .3.

Login service

openprogram worker install starts the worker at login and restarts it after a crash; uninstall removes it.

PlatformServiceNote
macOSlaunchd, ~/Library/LaunchAgents/ai.openprogram.worker.pliststop unloads the job, so a crash restart does not bring it back
Linuxsystemd --userEach named profile gets its own unit
Windows source checkoutLeast-privilege per-user Task Scheduler entryOne task, OpenProgram Worker, serves all profiles

On macOS and Linux, start, stop and restart go through the service rather than creating a detached replacement. start and restart regenerate its plist or unit from the active CLI runtime, so an upgrade does not keep launching the old one.
