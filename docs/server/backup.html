Archives: ~/.openprogram/backups/<profile>-<timestamp>.tar.gz. Each command acts on the active profile only; under --profile alpha, ~/.openprogram-alpha/backups/, and a restore cannot cross profiles.

Store an opted-in archive like the credentials themselves. To move machines, logging in again is usually safer. backup-manifest.json lists only the categories actually included, redacted or excluded, plus never-backup rules under credential_policy, with no secret values.

Restore

  1. Running-process check. A live worker or Web server refuses the restore. Run openprogram stop first.
  2. Confirmation. Lists what will be overwritten and waits for y.
  3. Safety snapshot. Current state goes to <profile>-pre-restore-<timestamp>.tar.gz. If the archive has credentials, so does the snapshot, and the command says so.
  4. Replace only the entries in the archive. Caches and logs stay. A secret field a mixed file omits or redacts keeps this machine's value.
Archive and restore safety
  • POSIX applies mode 0600. Windows source checkouts keep the state directory's inherited NTFS ACL.
  • An archive is written to a unique temporary file, flushed and published atomically; POSIX also flushes the directory.
  • The whole archive is validated before any of it is visible: containment, member type, JSON shape of every registered secret file. Symlink, hardlink and traversal members are refused, and a rejected archive changes nothing.
  • Files publish through the owner-only atomic writer and each publish is journalled. A restore stopped by a crash or full disk is reversed at the start of the next restore.
  • POSIX uses descriptor-relative traversal. Windows has no dir_fd, so it validates containment and rejects symlinks, junctions and other reparse points before each path operation.
