How idle-sleep prevention behaves
  • Each execution reads the setting when its agent loop starts and holds a native power assertion until the loop finishes, fails or is cancelled, approval waits included. Running executions ignore a change.
  • Display sleep and explicit sleep still work; no permanent power setting changes.
  • Unsupported platforms or assertion failures log a warning and continue.
  • Independent background services and commands after the loop are not covered.

The last three stop a page you visit from opening a WebSocket to 127.0.0.1 and driving the agent, or re-resolving its own name to loopback. Stored API keys cannot be read back: the old reveal route answers 410.

openprogram config set web.allowed_origins '["https://agent.example.com"]'   # your own reverse proxy; next start

NO_PROXY bypasses still apply, with the full address check. openprogram rescue reports the resolved proxy and a missing SOCKS package.

What the proxy path checks
  • The client validates the target first and checks the proxy socket address. TLS still verifies the service hostname. Proxy authentication stays on the proxy connection. A failed proxy request does not fall back to direct.
  • Through a proxy, the proxy resolves the hostname. That is what makes fake-IP proxies such as Clash work: their local answers come from 198.18.0.0/15, which a direct connection refuses as NON_GLOBAL_ADDRESS.
  • Still refused: private, loopback and metadata IPs; local names (localhost, single-label hosts, .local, .lan, .internal and similar); hostnames whose local DNS answer is a real private address.
  • For a guarantee that the final resolution is checked too, configure an enforcing policy proxy.

Multiple instances

--profile <name> or OPENPROGRAM_PROFILE moves config, sessions and logs to ~/.openprogram-<name>/. Add a different OPENPROGRAM_WEB_PORT to run several at once.

openprogram --profile dev
OPENPROGRAM_PROFILE=dev openprogram status
