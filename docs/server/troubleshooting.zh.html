故障排查

现象处理
"No provider available"openprogram providers 列出已存凭据。openprogram providers discover 查找 Claude Code、Codex、Gemini CLI 登录和可接管的 env: 密钥。
未登录：openprogram providers login <provider>，或登录对应的外部 CLI。
密钥设在另一个 shell：接管它，见常见问题。
令牌过期：重新登录；openprogram providers doctor 检查过期、刷新和冲突。
"command not found: openprogram"重新运行安装脚本，再把 ~/.local/bin 加入 PATH（见下）
Web UI 端口被占用启动前 export OPENPROGRAM_WEB_PORT=8101，或用 openprogram ports --port 8101 持久化
Worker 无法启动，或端口不对openprogram doctor，再 openprogram rescue，后者会打印修复命令。提 issue 前先读输出
import openprogram 报 ModuleNotFoundError产品安装刻意使用私有 Python。源码 checkout 中运行 uv sync --locked，再 uv run --project /path/to/OpenProgram python ...，或激活其 .venv
 
curl -fsSL https://openprogram.io/install | sh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
openprogram doctor 检查什么

Python、Node 和 git；skill 和插件加载；provider 凭据；MCP 服务器；磁盘缓存；worker 是否监听 18100。

命令所用的 shell、是否在沙箱里，以及一条必须原样带回 UTF-8 文本和退出码的测试命令（失败只作提示，不拦截任何操作）。

Windows 上还有长路径配置和只读的 Defender 性能提示。它从不修改注册表、Defender 排除项或文件 ACL。

从源码开发
  • 用 uv sync --locked --extra dev 配置。外部 harness 开发：安装 Program。
  • 部分测试在裸 CI 上跳过，因为需要 $HOME 里配置好的 provider，所以有凭据的 Mac 跑得更多。搜索 pytest.mark.skipif。
