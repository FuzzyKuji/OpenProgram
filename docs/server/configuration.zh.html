阻止空闲睡眠的行为
  • 每次执行在 agent 循环开始时读取设置，并持有原生电源断言直到循环结束、失败或取消，审批等待也算在内。正在运行的执行不受改动影响。
  • 显示器睡眠和用户主动睡眠仍可用；不改变任何永久电源设置。
  • 不支持的平台或断言失败时记录警告并继续。
  • 不覆盖独立的后台服务和循环结束后的命令。

谁能访问服务器

层规则
绑定地址 web.host默认 127.0.0.1，仅本机。0.0.0.0 把需要登录的 UI 暴露给其他接口，且至少需要一个 web.allowed_origins 条目。不可信网络优先用同机反向代理加 HTTPS
登录每个 API 和 WebSocket 请求都需要登录链接设置的 owner cookie 或 bearer token，否则 401。公开的只有 /healthz、页面外壳、/docs，以及 /hooks/ 下由任务自身密钥保护的 Scheduler webhook
Host必须是有效 origin：绑定回环时为回环地址，加上 web.allowed_origins。否则 403
Sec-Fetch-Sitecross-site 得到 403
Origin，存在时必须与请求自身的 origin 一致，否则 403

后三项防止你访问的网页向 127.0.0.1 打开 WebSocket 驱动 agent，或把自己的域名重新解析到回环地址。已存储的 API key 无法读回：旧的 reveal 路由返回 410。

openprogram config set web.allowed_origins '["https://agent.example.com"]'   # 你自己的反向代理；下次启动生效

网络代理

目标路由
web_fetch、图片和附件下载、内置搜索（含 DuckDuckGo）、更新检查等固定公共服务、已审计清单内的 provider普通代理
自定义 origin：配置的 provider base URL、SearXNG、skill 或插件目录直连并做地址检查，或显式的强制策略代理
CLI provider外部 CLI 自己路由；继承 worker 环境
回环地址从不走代理
优先级普通代理来源
1security.outbound_url.policy_proxy，需要 owner 声明它会强制目标策略
2OPENPROGRAM_PROXY_URL：http://、https://、socks5://
3http_proxy、https_proxy、all_proxy 及大写形式，按 HTTPX 规则；适用时使用 macOS 和 Windows 系统代理

NO_PROXY 绕过仍然有效，并做完整地址检查。openprogram rescue 报告解析出的代理和缺失的 SOCKS 包。

代理路径检查什么
  • 客户端先校验目标，并检查代理 socket 地址。TLS 仍验证服务主机名。代理认证只留在代理连接上。代理请求失败不回退直连。
  • 走代理时由代理解析主机名，Clash 这类 fake-IP 代理因此可用：它们的本地应答来自 198.18.0.0/15，直连会以 NON_GLOBAL_ADDRESS 拒绝。
  • 仍被拒绝：私有、回环和元数据 IP；本地名称（localhost、单标签主机、.local、.lan、.internal 等）；本地 DNS 应答为真实私有地址的主机名。
  • 要保证最终解析也被检查，配置强制策略代理。

设置效果
